### work5 本地数据库副本（2026-10-21）

用户授权将远端开发库复制到本机，用于离线开发和自行造数。当前入口固定读取 `.local/database-local.json`，目标为 Docker `yaoming-smp-mysql` 的 `127.0.0.1:3306/ymsw_v2`；原有 `smp_local` 另行保留。Redis 逻辑库 10 与此前连接远端时使用的库 9 隔离。正常启动检查本地容器、应用账号及 MySQL 握手，不访问远端，不自动切库，不重复导入或初始化。

导入使用 InnoDB 一致性快照。原始远端导出、旧本地库备份、导入副本、记录数/字段/索引比对及 SHA-256 清单保存在 Git 忽略的 `.local/backups/remote-to-local-*`。存储过程中的远端 DEFINER 仅在导入副本中改为本地账号；远端库不执行 DDL/DML。密码只放 `.local/database-local.json`，不要提交到仓库。每次测试修改持久保存在本地 Docker 数据卷；再次同步需明确提出，以免覆盖自行创建的数据。

本次完成导入并比对 194 张表、107,337 条记录、2,988 个字段及 1,155 条索引列定义。启动后验证 system 的 MySQL 连接指向本机 3306，后端无远端 6033 连接；system/auth 健康检查、网关和门户代理均通过，浏览器已展示反应器业务页且未捕获控制台错误。未代填登录或执行业务增删改，不据此声明全部业务验收通过。

门户访问 `http://127.0.0.1:5581/login`，仍使用复制时远端已有的业务账号；旧 `smp_local` 的本地账号不会自动出现在新副本中。旧 `.local/dev.ps1` 和 `.local/README.legacy-20260914.md` 仅作历史记录，当前启动以 `.local/start-latest.ps1` 为准。数据库复制不包含数据库之外的附件文件、外部对象存储或真实设备服务；本机保留既有设备客户端/轮询禁用配置，相关联调另行准备。

以下原始命令适用于其他已配置环境，仍须先完成 Docker 守卫检查（若依赖 Docker）。

同日本机另遇数据库 TCP 连接成功但 MySQL 握手超时：直连物理网卡正常，经 Clash TUN 不通。在 Clash 的 TUN 设置中仅为实际开发库 IP 增加 `/32` 排除项并保存后，普通应用连接、system 数据源初始化及健康检查恢复。本机入口已增加真实 MySQL 握手预检；不要把 TUN 的 TCP 假阳性误判成数据库表结构或凭据错误。只读比对确认当前基线 189 表的 2,879 个字段均存在，未执行 DDL/初始化；该结果不覆盖类型、索引、约束、种子数据及全部业务接口验收。

## 1. 初始化本机工具路径并构建后端

从 PowerShell 执行；后续步骤在同一会话中运行。局部 Corepack 入口只写入 Git 忽略的 `.local-start-tools/`，避免全局 pnpm 11 被嵌套脚本误用。

```powershell
$ErrorActionPreference = 'Stop'
$devRoot = 'D:\Code\zhixianweilai\yaoming-cloud'
Set-Location $devRoot
$env:JAVA_HOME = 'D:\Programs\dragonwell-21.0.10.0.10+7-GA'
$env:COREPACK_HOME = 'D:\Programs\corepack'
$devTools = Join-Path $devRoot '.local-start-tools'
New-Item -ItemType Directory -Path $devTools -Force | Out-Null
& 'D:\Programs\nvm4w\nodejs\corepack.cmd' enable pnpm --install-directory $devTools
if ($LASTEXITCODE -ne 0) { throw 'Corepack 初始化失败' }
$env:Path = "$devTools;D:\Programs\nvm4w\nodejs;D:\Programs\Maven\bin;$env:JAVA_HOME\bin;$env:Path"
# 在前端目录确认 packageManager 实际选择的是 8.6.2。
Push-Location (Join-Path $devRoot 'futurefab-frontend')
try {
    pnpm --version
    if ($LASTEXITCODE -ne 0) { throw 'pnpm 不可用' }
} finally { Pop-Location }
mvn -pl futurefab-gateway,futurefab-auth,futurefab-modules/futurefab-system -am package '-DskipTests' -B -ntp
if ($LASTEXITCODE -ne 0) { throw '后端构建失败，停止启动' }
```

上述 Maven 命令实际执行结果为 `BUILD SUCCESS`、退出码 0；`-DskipTests` 表示未执行测试，不得报告单元测试通过。

## 2. 后台启动系统、认证、网关

三者分别监听 9201、9200、9090。门户请求经网关访问认证和系统服务，不能只启动 system。启动前检查端口；已占用时先核对进程身份并复用或协调，不自动停止他人进程。

```powershell
Set-Location $devRoot
$devServices = @(
    @{ Name = 'system';  Port = 9201; Jar = 'futurefab-modules/futurefab-system/target/futurefab-modules-system.jar' },
    @{ Name = 'auth';    Port = 9200; Jar = 'futurefab-auth/target/futurefab-auth.jar' },
    @{ Name = 'gateway'; Port = 9090; Jar = 'futurefab-gateway/target/futurefab-gateway.jar' }
)
# 全部检查通过后再启动，避免端口冲突造成只启动一部分服务。
foreach ($devService in $devServices) {
    if (Get-NetTCPConnection -State Listen -LocalPort $devService.Port -ErrorAction SilentlyContinue) {
        throw "端口 $($devService.Port) 已占用，请先核对进程"
    }
    if (-not (Test-Path (Join-Path $devRoot $devService.Jar))) { throw "缺少 $($devService.Jar)" }
}
foreach ($devService in $devServices) {
    $devProcess = Start-Process -FilePath "$env:JAVA_HOME\bin\java.exe" `
        -ArgumentList @('-jar', $devService.Jar, '--spring.profiles.active=dev') `
        -WorkingDirectory $devRoot -WindowStyle Hidden `
        -RedirectStandardOutput (Join-Path $devRoot ".local-start-$($devService.Name).out.log") `
        -RedirectStandardError (Join-Path $devRoot ".local-start-$($devService.Name).err.log") -PassThru
    Write-Output "$($devService.Name) PID=$($devProcess.Id)"
}
```

进程创建成功不代表服务就绪。查看三个 `.local-start-*.out.log` 的 `Started ...Application`，并执行下述 HTTP 检查；本次 system 首启约 40 秒。异常时同时查看对应 `.err.log`，不得只检查端口。

2026-10-20 反应器本机联调经用户确认，**仅 system 进程**额外传入 `--futurefab.observation.query.snapshot-ttl-seconds=300` 和 `--futurefab.observation.query.snapshot-max-ids=10000`。它们分别控制 M02 历史查询快照的缓存有效期和单快照观测版本 ID 上限，不是业务数据保留期限，也不是生产环境默认值；缺失时接口按契约拒绝创建快照。需要这组联调参数时，在上面循环的 system 分支追加参数，不向 auth/gateway 传入，也不为此发布 Nacos 配置。

新进程还需取得开发 Nacos 配置读取凭据：通过本机 `NACOS_USERNAME` / `NACOS_PASSWORD` 进程环境提供，不把凭据写入源码、文档或命令行参数。旧进程能运行不证明新进程已继承其环境；若 Nacos 配置读取返回 403，应先恢复合法配置读取权限，不用 `optional:` 或跳过导入来绕过。启动后仍需健康检查和真实历史查询证明参数生效。本轮生成的测试数据按用户要求保留，不因查询快照到期删除。

## 3. 构建共享资源并启动门户

2026-10-20 合并 `0c5df7de2` 后曾将开发默认代理目标改为线上后端。随后用户授权本机真实反应器联调，本次将既有 `scripts/portal-environment.ts` 的开发 `backendUrl` 明确恢复为 `http://127.0.0.1:9090`，并删除注释切换线上地址的歧义。未增加环境变量或 CLI 配置入口，`--host` 仍只改监听地址；生产构建清单由 `productionDeployment` 独立生成，API前缀仍为 `/prod-api`。代理配置修改后须重启门户并核对请求日志，源码修改本身不证明本机链路已联通。

```powershell
Set-Location (Join-Path $devRoot 'futurefab-frontend')
pnpm run build:shared
if ($LASTEXITCODE -ne 0) { throw '共享资源构建失败' }
pnpm exec tsx scripts/build-shared-libs.ts --check
if ($LASTEXITCODE -ne 0) { throw '共享资源核验失败' }
pnpm --filter '@futurefab/ui-sdk-language' run build
if ($LASTEXITCODE -ne 0) { throw '语言包构建失败' }
pnpm run routes:generate
if ($LASTEXITCODE -ne 0) { throw '路由生成失败' }
# 默认 5581 若已被现有门户占用，本次使用独立的 5582；不终止现有进程。
$devPortalPort = 5582
if (Get-NetTCPConnection -State Listen -LocalPort $devPortalPort -ErrorAction SilentlyContinue) {
    throw "门户端口 $devPortalPort 已占用，请先核对进程"
}
$devPortal = Start-Process -FilePath 'D:\Programs\nvm4w\nodejs\node.exe' `
    -ArgumentList @('D:\Programs\corepack\v1\pnpm\8.6.2\bin\pnpm.cjs', '--filter', '@futurefab/ui-portal', 'run', 'dev', '--host', '127.0.0.1', '--port', "$devPortalPort", '--strictPort') `
    -WorkingDirectory (Join-Path $devRoot 'futurefab-frontend') -WindowStyle Hidden `
    -RedirectStandardOutput (Join-Path $devRoot '.local-start-portal.out.log') `
    -RedirectStandardError (Join-Path $devRoot '.local-start-portal.err.log') -PassThru
Write-Output "portal PID=$($devPortal.Id), URL=http://127.0.0.1:$devPortalPort/"
```

保持该后台进程运行。若想使用默认端口，确认 5581 空闲后把 `$devPortalPort` 改为 5581，并同步调整验证 URL。门户浏览器请求前缀为 `/dev-api`，开发代理 target 为上述本机9090；本机后端启动范围仍为 system、auth、网关。共享库构建不可省略：本次缺少 `dist/index.dev.js` 时首页虽返回 HTTP 200，浏览器仍显示“页面加载失败”，补齐后登录页正常。

`build:shared` 当前只构建 `lib-smp-base`，不包含语言包或业务应用。语言源码已更新而语言包 `dist` 过旧时，任务页会显示 `feeding.taskSearch` 等键名；应重建 `@futurefab/ui-sdk-language`，不要添加重复翻译来修补旧产物。SDK 或业务源码更新后，也须按受影响范围重建实际包（如 `@futurefab/ui-sdk-smp-api`、`@futurefab/ui-app-smp-lab`），再刷新页面并核对浏览器加载的 `/unpkg/` 包 hash。构建退出码 0 不替代页面和业务接口验收；本地产物不提交。

## 4. 启动后的验证与停止

以下命令沿用历史实测步骤。执行 `/dev-api/code` 前先确认门户已加载本次本机代理配置；验证码200只证明当时配置的 target 可达，本机链路验收还须结合网关/目标服务请求日志核对，不能只凭前缀或页面地址判断。

```powershell
# 等待日志出现 Started / Vite ready 后执行。
& "$env:SystemRoot\System32\curl.exe" --fail --silent http://127.0.0.1:9200/actuator/health
if ($LASTEXITCODE -ne 0) { throw '认证服务健康检查失败' }
& "$env:SystemRoot\System32\curl.exe" --fail --silent http://127.0.0.1:9201/actuator/health
if ($LASTEXITCODE -ne 0) { throw '系统服务健康检查失败' }
$devHome = Invoke-WebRequest "http://127.0.0.1:$devPortalPort/" -UseBasicParsing -TimeoutSec 10
if ($devHome.StatusCode -ne 200) { throw '门户首页 HTTP 检查失败' }
$devCaptcha = Invoke-RestMethod "http://127.0.0.1:$devPortalPort/dev-api/code" -TimeoutSec 10
if ($devCaptcha.code -ne 200) { throw '门户至网关代理检查失败' }
# 仍须用浏览器打开门户，确认跳转 /login、登录表单可见且无资源加载错误。
```

2026-10-17 历史实测（早于上述代理变更，不代表当前默认配置）：后端打包、共享库构建/清单检查、路由生成均退出码 0；三个后端启动日志正常；auth/system 健康接口 HTTP 200 且 `status=UP`；网关 `/code` 和门户 `/dev-api/code` 均 HTTP 200、业务码 200；浏览器成功跳转 `/login`，登录表单可见且未捕获页面/控制台错误。验证仅覆盖启动、登录页展示和验证码代理；未提交账号登录、业务 CRUD、设备操作或数据库脚本，不能据此宣称业务/现场验收通过。

日志与 `.local-start-tools/` 只供本机使用，不提交。停止时按本次输出的 PID、端口拥有者及父子进程核对后，仅停止本次创建的进程；门户的 pnpm 父进程和 Vite 子进程须一起核对，禁止批量结束全部 Java/Node 进程。

## 5. 本文不证明什么

本文的历史启动实测与 §0 的 2026-10-21 本地副本验证应分别理解：最新记录覆盖启动、健康检查、数据库连接目标及浏览器页面展示。它不覆盖完整登录交互、业务 CRUD、状态变更、设备或外部系统联调，也不覆盖 `docs/开发基线/` 三份 SQL 的实际执行。按 AGENTS.md §13.2 判定，最新记录仅支持已检查链路的 `HTTP_VERIFIED` 和已展示页面的 `BROWSER_VERIFIED`；不得据此提高其他接口完成度或宣称“现场/生产验收通过”。
