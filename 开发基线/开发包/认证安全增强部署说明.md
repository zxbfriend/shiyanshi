## 2. 配置

秘密值由部署侧生成、保管和发布，仓库不提供真实值或通用默认密钥。

| 配置 | 服务 | 要求 |
| --- | --- | --- |
| futurefab.auth-security.hmac-key | gateway/auth/system | 至少32个UTF-8字节；相同环境共享，缺失或非法时认证安全请求503 |
| futurefab.auth-security.secure-cookie | gateway | 生产HTTPS保持true；纯HTTP本机开发需显式false，否则浏览器不会携Cookie |
| futurefab.auth-security.trusted-proxies | gateway/auth/system | 默认空，仅信任连接来源；需要代理时列精确数字IP并在边缘规范转发头，不支持CIDR |
| futurefab.auth.step-up.active-key-id | system | 当前HMAC密钥ID，默认v1，仅标识而非密钥 |
| futurefab.auth.step-up.keys.<keyId> | system | 独立操作绑定密钥，每个至少32个UTF-8字节；保留旧keyId直至在途/回执窗口结束 |
| futurefab.auth.step-up.challenge-seconds / proof-seconds | system | 默认各120秒；有效期不能由刷新或重签延长 |
| futurefab.auth.step-up.retention-hours | system | 默认24且不得小于24；本轮不新增自动删除业务审计/快照的任务 |

验证码/请求各预算配置以AuthenticationSecurityProperties为准，默认值为设计建议，生产需按共享出口人数核准。system的二次认证独立错误窗口默认15分钟、第6次冷却30分钟，操作者请求预算默认每分钟60次，分别可通过futurefab.auth.step-up.failure-window-seconds、failure-threshold、cooldown-seconds、requests-per-minute核准配置；这些不改变现有可配置的账号登录锁定规则。

同环境节点必须共享Redis逻辑库、对时。网关HttpOnly/SameSite Cookie只用于匿名预算及验证码归属，不当作用户身份；接口不能信任浏览器自行携带的“已认证”标志。操作凭证只从X-Operation-Proof取得，不接受Body覆盖。

## 3. 已知边界与验收

- AAD普通登录保留现有SAML链；现有旧成功入口尚未统一进入I02激活/登录快照，不能宣称已覆盖AAD登录历史反馈或单会话验证。
- AAD敏感操作重新认证需客户IdP核准。当前分支失败关闭，无本地密码降级，状态 `BLOCKED_EXTERNAL`；不能用普通SSO会话重用或构造authProof假装通过。
- 本地二次认证完成后仍重新读取当前角色权限和目标数据范围；提交前撤权不能依靠旧LoginUser缓存通过。与提交同时发生的授权变更仍沿现有事务隔离规则，不新增SYSTEM管理写动作或跨模块版本。
- 失败提示只在匿名认证边界统一，已有业务会话的401/403/409/423仍按原义处理。日志不得记录口令、验证码、挑战、操作凭证、SAML原包或密钥。
- 网络超时先查原请求回执，关闭策略窗口后只保留非敏感请求标识，不留初始口令或自动重发。取消和提交竞争以服务器真实回执为准。

离线校验：`python scripts/sync_auth_security_baseline.py`、`python scripts/test_auth_security_baseline.py`。它们仅检查或生成仓库文件，不连接MySQL；静态通过不代表SQL在目标库通过。

测试与构建记录在[实施计划](../../开发任务/07-实施计划/2026-11-01-authentication-security.md)。浏览器验收必须记录真实请求头/响应、错误日志和数据清理，附件不能含口令、验证码或凭证。
