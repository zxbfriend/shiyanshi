## 5. 超大 ID 全链路字符串检查（本轮专项）

背景：本库主键为 19 位雪花 ID（如 990000000000004507、1309095133135900672），超出 IEEE-754 双精度安全整数范围（2^53≈9.007e15）约两个数量级，任何环节按 number 解析都会静默丢精度。

| 链路环节 | 实测 | 结论 |
|----------|------|------|
| DB 列类型 | res_culture.culture_id / run_workflow_instance.workflow_id / run_workflow_step.step_instance_id / lab_integrated_reactor.integrated_id / dev_bench_reactor.model_id 等均为 bigint | 存储侧 19 位 |
| 后端 DTO | `StartCultureCommands` 全部记录字段为 String（cultureId/deviceId/occupancyId/workflowId/pageSessionId/expected*Version…）；候选 VO `CultureBalanceView`/`ExecutionSpecView.cultureId` 为 String | 传输侧 String |
| Jackson 序列化 | `JacksonConfig` 注册 `Long.class` 与 `Long.TYPE` → `ToStringSerializer`（即使实体用 Long 也序列化为字符串） | 双保险 |
| 实测响应 | candidates 响应 `"cultureId":"990000000000004507"`、`"deviceId":"990000000000004506"`、`"occupancyId":"990000000000004508"`——全部带引号字符串 | JSON 层字符串 |
| 前端类型 | `feeding/api.ts`（cultureId: string 等）、`sdk-smp-api/start-culture.ts` 全部 string；请求体一律字符串（本轮全部 curl 实测） | 前端 String |
| 前端数值化扫描 | 对 app-smp-lab 与 sdk-smp-api 扫描 `Number(*id)`/`parseInt(*id)`/`id + ` 拼接模式：无命中（ID 仅经 `String(...)` 归一化后比较） | 无精度回退路径 |

结论：超大 ID 全链路（DB→Java→JSON→TS→请求）均为字符串，无 number 化路径；本轮全部请求以字符串 ID 发出并被服务端正确接收。

#### 8.3.1 前次"正确的前置依赖语义"解释错误 — 本次纠正

前版报告称："W06/W07/W08 三页的候选查询均传 `subflowCode:"W03"`……这是**正确的前置依赖语义**，非接线错误；后端返回 400 是设计约束，不是缺陷。"
