## 4. 四类身份必须分开计数（口径先行）

本组接口最容易出错的地方是「一个数字 ID 同时是两种身份」。先立口径，逐口文档再引用。

| 身份 | 载体 | 产生 | 出现位置 | 关键事实 |
|---|---|---|---|---|
| **页面会话** | `pageSessionId` = `run_start_culture_session.session_id` | `POST /run/workflow-page-sessions`（`action=OPEN`）由服务端生成雪花 ID | SC-HTTP03、SC-HTTP04、SC-HTTP05、SC-HTTP02 的 `pageSessionId` 字段 | 一行代表一次「打开页面到关闭页面」；`object_version` 为会话版本，`sessionVersion`／`expectedSessionVersion` 都指向它 |
| **工作流** | `workflowId` = `run_workflow_instance.workflow_id` | 启动成功后由 `insertWorkflowInstance` 写入 | `/run/workflows/{id}`、`/run/workflows/{id}/steps/{stepId}`、`/run/workflows/{id}/operations`、`/run/workflows/{id}/cancel` | 一个成员一行；`run_workflow_step` 挂在它下面 |
| **批次** | `batchId` | 小试＝**会话 ID 本身**；W02／W03／W08＝**根工作流 ID** | `/run/workflow-batches/{batchId}` 及其 `/steps`、`/cancel`、`/waste/*`、`/actions` | 见下方「同一 ID 两身份」事实 |
| **请求** | `requestId` = `X-Request-Id` | 客户端每次写请求自带 | 守卫幂等键；`run_start_culture_receipt.request_id`；`/run/workflow-requests/{requestId}` | 六元组之一，不同身份的 `requestId` 不可互换 |

三条必须写死的口径：

1. **小试的 `batchId` 就是 `pageSessionId`。** `StartCultureApplicationService.start` 在 `:199` 写 `row.batchId = SMALL.equals(row.workflowKind) ? row.sessionId : null`。因此小试组「批次」与「页面会话」是**同一个数值**，但语义不同：前者用于批次读取/批次动作，后者用于会话恢复/回执/会话关闭。**不得把 `GET /run/workflow-batches/{batchId}` 与 `GET /run/workflows/start-culture/sessions/{pageSessionId}` 当同一接口的两种写法**，两者鉴权深度不同：前者 `write=false` 跳过 owner 校验，后者 `write=true` 强制 owner 校验。
2. **中试没有批次。** 同一行 `:199` 对 `PILOT` 显式写 `null`，`StartCultureSessionState.bind` 在 `:108` 反向校验「pilot batch forbidden」。所以中试的开始培养实例**不得**用批次口读写，只能用实例口 024／025／027。
3. **W02／W03／W08 的 `batchId` 是根工作流 ID，不是会话 ID。** 三者的冻结快照里 `batchRootWorkflowId` 与根 `workflow_id` 相等；批次成员各自仍有独立 `workflowId`。这与小试「批次 ID 等于会话 ID、成员是实例」在结构上不同源，跨类型传 ID 会命中各自的形状校验拒绝链（详见 `05-M07批次详情剩余三分支核验记录.md` §6.5）。

派生结论（只作计数口径，不作实现结论）：

- 本目录 `02-开始培养会话与W02批次五口.md` 中，`StartCultureSessionController` 的 3 个 handler 分别对应「页面会话写」「批次动作」「请求回执」三层，**不是三个批次接口**。
- 请求回执口读的是 `run_start_culture_receipt`（`StartCultureWorkflowMapper.xml:88` 的 `findReceipt`），**不读** `run_workflow_instance`，也不是「按 requestId 重放原请求」。它只回答「这个 requestId 是否已结算」，不返回原响应正文。
