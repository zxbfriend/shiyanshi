# M01 认证安全增强设计

日期：2026-11-01。归属：[M01详细设计](详细设计.md)。用户已授权按本方案开发；本地账号实现及分层验证见[实施计划](../../开发任务/07-实施计划/2026-11-01-authentication-security.md)，部署前置见[部署说明](../../开发基线/开发包/认证安全增强部署说明.md)。未执行目标SQL，HTTP、浏览器及AAD联调均为 `NOT_VERIFIED`。

## 1. 范围与决策

依据客户安全条款1.7、1.8、1.10、1.11及用户本轮确认，补齐验证码防暴力破解、敏感操作二次认证、登录安全反馈、认证失败提示。下文对这些事项的明确增补优先于M01主设计中旧的失败外壳、UI05/UI06、API07/API09及验证码单次消费描述；其余业务规则保持现行契约。

- 用户确认：二次认证仅覆盖管理员重置密码API07、密码策略修改API09。API09中有效期、提醒天数、初始密码和首次强制修改开关的任何变更均在范围内。角色和权限变更暂不增加二次认证。
- 本人改密API05继续验证旧密码，挑战改密API03继续使用合法登录挑战；不增加第二重弹窗。不新增自助找回密码、短信或邮件认证。
- 系统无互联网访问，互联网MFA条款不适用。敏感操作再次证明身份不等同于多因素认证。
- 初始密码、锁定次数、有效期已有配置能力，不作为本轮重做密码规则的理由；生产配置合规和运行验证独立验收。
- AAD已有SAML代码，本专题不把它描述成未开发，也不宣称已真实联调。AAD重新认证及公司设备限制依赖客户IdP能力，未验证时 `BLOCKED_EXTERNAL`。

选择沿用现有auth/system、Redis、MySQL及审计设施。未选择短信/邮件方案，因其引入客户通道依赖；未选择“几分钟内所有敏感操作免再验证”，因其不能绑定本次操作及目标。设计新增操作凭证和结果回执承载，不复用登录挑战、签批密码或扩大管理守卫注册表。

以下限流和票据时间为本方案建议值，尚非客户确认的安全阈值；生产投用前须核准。接口使用SEC前缀作为本专题认证辅助接口标识，不抢占既有M01-001～076编号，也不计入原76口骨架的完成数量。路由/DTO登记在本专题及模块接口目录，机器骨架目录仍代表原76口范围。

## 2. 验证码防暴力破解

### 2.1 入口与计数

`GET /code`（现有网关入口）与API01共用限流策略及Redis。下表为建议初值，按部署配置维护，禁止通用参数页直接关闭安全保护。

| 项目 | 建议值 | 规则 |
| --- | --- | --- |
| 图片验证码有效期 | 120秒 | 沿用现有值，不因刷新或错误延长 |
| 获取间隔 | 同一浏览器标识至少2秒 | 服务端生成随机匿名标识，HttpOnly、SameSite Cookie；生产HTTPS时Secure，不当作可信身份 |
| 获取窗口 | 标识每分钟20次；IP每分钟300次 | 任一超限429；IP用于共享出口总量保护，不直接锁定该IP全部账号 |
| 验证失败窗口 | 标识/规范化账号组合15分钟10次；IP每分钟300次 | 超限冷却5分钟；账号分量用服务端HMAC，不把用户名明文放Redis键；不能单靠匿名请求触发账号数据库锁定 |
| 活跃标识预算 | 按IP限制新匿名标识创建速率与存量 | 不能靠清Cookie无限绕过；不把攻击者可随意更换的clientId当唯一限流依据 |

获取次数包含刷新请求；校验失败计数不随获取新图清零，与账号口令失败计数独立。缺失标识走IP预算下的首次签发，不直接放行。各维度窗口和冷却以Redis服务端时间及原子脚本处理，键有TTL和有界容量，多个网关/auth实例共享。

IP只取受信反向代理规范化后的来源，边缘剥除客户端伪造的转发头；不信任任意X-Forwarded-For。公司共享出口可能产生误伤，投用前按人数压测校准IP预算，保留人工排查渠道，禁止全局解除限流来恢复单个用户。

### 2.2 原子消费及失败关闭

验证码存储包含答案摘要、所属匿名标识和到期时间。Redis脚本先验证所属标识，再原子读取、比较并删除；属于当前标识且尚有效的每张图最多一次猜测，错误也删除。标识不匹配不消费他人的验证码。答案只在服务端比较，不能返回响应或日志。

auth与网关只保留一个权威消费入口，禁止先在网关消费后在auth重复校验。服务间传递的验证码校验结果必须通过受控内部认证渠道绑定原登录requestId和请求摘要，不能信任浏览器传入的“已校验”标记。API01直接访问和旧入口均不能绕过。

Redis超时或不可用返回503 `AUTH_DEPENDENCY_UNAVAILABLE`，不继续验证账号密码或放行登录。已消费但响应丢失时重新获取图片，不恢复旧验证码。验证码错误不增加账号口令失败次数。验证码开关关闭时仍执行请求及口令尝试限流；本轮不擅自移除现有开关，生产是否开启另行核验。

响应：429 `AUTH_RATE_LIMITED`，`Retry-After`头与`retryAfterSeconds`整数一致，仅反映请求限流，不反映账号存在、锁定或剩余密码尝试数。验证码无效统一400 `CAPTCHA_INVALID`。前端倒计时只辅助展示，服务端始终复核。

## 3. 敏感操作二次认证

### 3.1 身份来源与交互

重置用户或保存密码策略时，先冻结用户已确认的目标、期望版本、业务requestId和载荷，再弹出二次认证。本地账号输入当前操作者密码；不输入目标用户密码，不发送初始密码作为身份凭据。验证成功后提交原API07/API09并携操作凭证。取消、切换目标或修改任一关键参数均撤销旧凭证并重新验证；表单内容只存在内存，关闭清除口令及凭证。

当前会话的认证方式由服务端登录来源确定，不能由浏览器指定或通过输入用户名切换。本地口令校验复用BCrypt及现有账号状态、凭据版本检查；二次认证错误采用独立的15分钟窗口，建议第6次失败冷却30分钟，计数绑定可信actorUserId且跨挑战、操作类型和会话共享，不能通过重建挑战、换浏览器或重新登录清零。验证请求按actor/验证requestId去重，依赖故障不计错；成功只清该操作者的二次认证错误窗口，不清其他窗口。冷却本轮仅阻断两类敏感操作，不清除已有登录/改密失败计数，不新增全账号锁定规则。

AAD会话发起与当前用户绑定的SAML重新认证：校验签名、Audience、Recipient、InResponseTo、有效期、一次性断言及认证时间，响应的稳定身份必须与当前账号映射一致。提出ForceAuthn要求不等于已证明IdP执行了重新认证；须核实AuthnInstant及客户支持行为。不能仅打开已有SSO会话就视为通过；不能降级为本地密码。回调通过后保持原业务会话及sessionVersion，不走普通新登录激活、不顶掉原会话，不计成功登录次数。

AAD配置或身份映射不支持重新认证时拒绝敏感操作并标 `BLOCKED_EXTERNAL`，不能给免验凭证。账号仅按邮件映射的既有实现需在联调前确认稳定IdP标识绑定，缺口只阻断AAD分支。

### 3.2 专题接口契约

下列接口已接本地账号真实链，AAD专用重新认证握手仍为目标契约且 `BLOCKED_EXTERNAL`。均需真实当前会话；actorUserId、sessionKey、登录来源均由服务端取得。操作凭证持久服务位于system；网关将/auth/step-up/**优先路由到system，其余/system/user/**沿既有路由，不通过固定内部来源Header冒充可信身份。

| 标识及外部路由 | 输入 | 输出及限制 |
| --- | --- | --- |
| SEC01 POST /auth/step-up/prepare | X-Request-Id=准备请求UUID；Body：operation=`PASSWORD_RESET`或`PASSWORD_POLICY_UPDATE`、businessRequestId、业务载荷 | data含challengeId、expiresAt、method=`LOCAL_PASSWORD`或`AAD`；AAD另返回站内发起地址，不返回任意跳转URL；先检查当前权限及目标范围 |
| SEC02 POST /auth/step-up/verify | X-Request-Id=验证请求UUID；Body：challengeId、currentPassword（仅本地） | 验证通过data={operationProof,expiresAt}；失败清口令、受限重试；AAD通过专用SAML回调完成同等流程，不接受浏览器自报认证成功 |
| SEC03 GET /system/user/sensitive-operation/result | Query：businessRequestId | 仅本人且原会话查询；data.status=`PENDING`/`APPLIED`/`EXPIRED`/`REJECTED`/`CANCELLED`，APPLIED携原API07/09结果；不存在或无范围统一404，不返回载荷、摘要或凭证 |
| SEC05 DELETE /auth/step-up/challenge | X-Request-Id=取消请求UUID；Body：challengeId、businessRequestId | 仅原用户/会话；system锁操作记录，PENDING/READY置CANCELLED并销毁Redis挑战及原始凭证，重复取消幂等；若APPLIED返回原成功结果，不能伪装撤销业务；正文非空，不在URL传票据 |
| SEC06 GET /auth/step-up/status | Query：businessRequestId | 仅原用户/会话；data.status=PENDING/READY/APPLIED/EXPIRED/REJECTED/CANCELLED；仅READY返回operationProof和expiresAt，APPLIED仅告知转SEC03查询原结果、不再发凭证。AAD回调后轮询用此口；Cache-Control:no-store；限流，不通过URL传凭证 |

准备挑战建议120秒，system记录challenge_expires_at；成功操作凭证建议120秒，从验证完成起算，不续期。至少256bit随机不可猜；数据库仅存token哈希，不存明文；挑战、操作凭证分用途、不能用作业务JWT。AAD通过回调后用SEC06取得凭证，URL不带凭证或密码；挑战只能完成一次。准备请求响应丢失可按原prepare requestId恢复同一挑战，不重新开始有效期；所有短时挑战关联信息和客户端取回路径均绑定原用户、会话、业务意图。

SEC01/02/05/06另受actor每分钟60次、IP每分钟300次的建议请求预算约束，多个节点共享；取票/结果响应不缓存。挑战或已READY凭证的原始值丢失，不从hash还原：经SEC01申请新的验证尝试，仍绑定同一业务意图，只有记录为PENDING/READY且未过对应期限时才允许；旧挑战被撤销，新挑战截止不超过原阶段剩余期限。验证完成锁操作记录、复核当前尝试及版本后替换proof_hash，旧凭证立即无效；新proof有效期不超过旧READY截止，不通过反复签发续期。APPLIED/REJECTED/CANCELLED/EXPIRED不再签发。新旧验证回调与提交同锁串行，提交先完成则后续只返回既有结果，不能重新签发第二次执行资格。

验证请求去重同时绑定actor、原会话、challengeId及验证输入：同一验证requestId更换挑战或口令返回409 REQUEST_CONFLICT，不按旧失败结果跳过新的验证输入。输入只保留服务端独立密钥HMAC用于短时去重，不保留明文或普通口令哈希，不写日志；缺密钥/去重存储不可用则失败关闭。原样重传只计一次失败，换新requestId仍进入actor累计窗口；明显重复冲突仍受请求预算限制。

取消或改动表单时先本地冻结提交并清理口令，通过SEC05请求撤销；取消响应未知时不宣称服务器已撤销，按SEC03核对。取消与提交竞争以同一操作记录锁串行裁决，取消先提交则业务写拒绝，业务先提交则显示真实成功。窗口直接关闭无法保证发出取消请求，凭证最多存活至期限且只能用于原意图；服务端过期拒绝，不依赖前端清理实现安全保证。

API07/API09增加必填`X-Operation-Proof`，保留各自Body的requestId、expectedCredentialVersion/expectedPolicyVersion权威规则，不新增跨模块managementRevision要求。现行密码族属于明确的Body版本例外，二次认证不能据此改造为普通管理守卫写。SEC01/02的X-Request-Id标识准备/验证本身，不代替正式业务requestId。

API07绑定规范载荷为目标userId、expectedCredentialVersion；API09绑定validDays、remindDays、expectedPolicyVersion、initPassword、initPasswordModify，严格区分省略与提供。未知字段拒绝，不做密码trim；客户端不能自行传payloadHash。system按固定字段序和类型规范化，使用独立部署密钥HMAC-SHA256计算摘要，覆盖operation、actor、session代次、businessRequestId及完整业务载荷。密码的普通SHA-256摘要不得用于绑定或日志，避免离线猜测。

### 3.3 事务、一次使用及结果恢复

system拥有操作凭证与结果回执；auth只编排认证，不直接写system私表。准备先持久化操作记录，认证成功通过受控内部调用把该记录置READY并绑定token哈希、操作者凭据版本、认证时刻及有效期。AAD远程握手不占用数据库事务。重复prepare/verify仅按各自请求与摘要恢复，不签发可用于新业务requestId的通用凭证。

正式写入顺序：校验当前身份/权限 → 锁该操作者businessRequestId对应操作记录 → 比较operation/原会话/载荷摘要 → 已APPLIED则返回既有结果 → 检查READY、token哈希、有效期和操作者凭据版本 → 按原API07/09顺序锁业务行并复核目标资格/期望版本 → 同事务写业务、脱敏成功审计、结果回执及APPLIED → 提交。所有新增路径均按操作记录→原业务锁顺序，不能反向取得锁；BCrypt和外部认证在持锁事务外执行，锁内复核版本。

- 一次使用指只能产生一次业务效果；并发同请求最多一次提交，重放返回原结果。成功重放仍需当前合法身份及原会话、原载荷与原token匹配，但无需凭证仍处于120秒有效期；过期不能阻止查询已提交结果。
- 业务回滚则操作记录不进入APPLIED；明确版本冲突等拒绝在回滚后独立记录REJECTED，使用state=READY且原proof_hash/载荷相符的CAS，不得覆盖其他并发请求已提交的APPLIED或CANCELLED；CAS未命中必须重读真实结果。记录失败也不能掩盖原拒绝。相同请求不得更换载荷；刷新版本或修改内容构成新操作，重新确认并二次认证。
- 传输超时先SEC03查询；SEC03将尚未生效的PENDING/READY合并返回PENDING，不暴露凭证状态；PENDING不证明失败，继续查询或以相同载荷、requestId、原凭证重试，不自动换键。依赖故障不标REJECTED，不伪造成功。查询在操作记录锁内确认当前状态：PENDING超challenge_expires_at、READY超proof_expires_at且未提交才显示EXPIRED；CANCELLED直接返回CANCELLED。已APPLIED优先返回成功，不能仅根据时钟判断失败。新操作需重新确认、生成新业务意图。
- 回执建议保留至少24小时，过期清理后旧凭证不能重新创建执行资格；重新认证必须新建操作意图。会话替换、退出、操作者改密、禁用后旧凭证不能执行；失去原会话只能重新登录后查询有权限的业务事实，不能复用凭证。
- API09现有“仅CAS、重试可能VERSION_CONFLICT”不足以恢复未知结果，本专题要求补持久化结果回执；不能用CAS成功率代替幂等。API07密码历史回执继续保留，与新增操作结果同事务一致。

### 3.4 权限和错误

API07沿用system:user:edit、目标可管理范围及受保护账号限制；API09沿用实时超级管理员检查。prepare时通过不代表提交时永久有权。角色/权限变更本轮无二次认证要求，但其原有鉴权继续生效。

缺凭证409 `STEP_UP_REQUIRED`；错误/过期/绑定不符统一409 `STEP_UP_INVALID`，不透露哈希或具体匹配项；二次口令错误400 `CREDENTIALS_INVALID`，提示“身份验证失败，请重试”；独立限流429 `AUTH_RATE_LIMITED`；会话失效401及权限403保持原义；AAD/DB/Redis依赖故障503 `AUTH_DEPENDENCY_UNAVAILABLE`。已明确的业务版本冲突沿原409处理，不能通过自动重新认证覆盖他人修改。

## 4. 登录安全反馈

### 4.1 事实与快照

只在业务会话成功激活时固定本次登录安全快照，包含previousSuccessAt、previousFailureAt及currentLoginAt。成功指真实业务会话激活，不包括INITIAL/EXPIRED挑战、提醒尚未跳过、解锁、JWT刷新、二次认证。AAD真实登录同样进入统一激活和审计链，不能旁路会话版本及快照。

对同一userId的成功激活与已知账号口令失败串行使用认证状态锁。成功事务先读取严格早于本次激活事件序号的成功/失败事件，再写本次成功事件、会话事实和快照；时间相同以不可变事件序号排序。失败审计须有请求幂等去重，窗口外旧记录不凭用户名重绑用户。账号不存在或验证码未通过的失败不写入某真实用户的“上次失败”，避免伪造关联。

登录快照为服务端持久化事实，不只存在Redis；同次激活重试、服务重启、刷新页面均读原快照。若快照事务失败不返回业务令牌；提交后缓存失败按原登录requestId恢复，不重复计数。没有可靠历史用NULL，不用本次时间或默认日期补齐。不得把当前sys_user.login_date覆盖后的值当作上次成功时间。

### 4.2 查询与展示

SEC04 `GET /system/user/profile/loginSecurity`：Bearer当前会话，无userId及业务写入。返回data={previousSuccessAt:string|null,previousFailureAt:string|null,currentLoginAt:string}；时刻为带偏移的ISO-8601，前端统一上海时区展示。响应`Cache-Control: no-store`，不返回失败原因、IP或他人信息。

UI在成功登录后首页显示“上次成功登录”“上次失败登录”，无记录显示“暂无记录”；首次已无历史时明确暂无，不显示“从未失败”的推断。附“如非本人操作，请联系管理员”。读取失败显示“登录安全信息暂不可用”与重试入口，不显示假空白，不使已登录业务流程自动退出。多标签共用该会话快照，下次真实新登录生成新快照；登录前不允许按用户名查询。

## 5. 认证失败提示与防枚举

### 5.1 对外映射

| 场景 | HTTP / errorCode | 固定用户提示 |
| --- | --- | --- |
| 匿名本地登录：不存在、错密码、停用、删除、账号锁定 | 400 / CREDENTIALS_INVALID | 登录失败，请检查登录信息或联系管理员 |
| 匿名AAD失败：无映射、无权、停用、断言无效或重新认证身份不一致 | 登录回跳仅给统一aad_authentication_failed；令牌交换400 / CREDENTIALS_INVALID | 登录失败，请联系管理员 |
| 验证码错误、过期、已用、归属不符 | 400 / CAPTCHA_INVALID | 验证码错误或已失效，请重新获取 |
| 请求或独立二次认证限流 | 429 / AUTH_RATE_LIMITED | 操作过于频繁，请稍后重试 |
| 认证依赖故障 | 503 / AUTH_DEPENDENCY_UNAVAILABLE | 登录服务暂不可用，请稍后重试 |

匿名登录对账号锁定不再返回423、剩余尝试数或锁定倒计时；这是对主设计旧UI01/API01外壳的显式覆盖。内部真实ACCOUNT_LOCKED/ACCOUNT_UNAVAILABLE原因保留用于计数和审计。已有会话的业务鉴权、解锁、本人改密及管理接口仍按各自401/403/423契约处理；不能把无权限、服务故障和版本冲突都伪装成密码错误。

对不存在、停用、删除、锁定等未正常校验口令的匿名分支执行等成本的虚拟BCrypt比较，哈希成本与真实策略一致；限流应先执行，避免形成计算放大。不得承诺网络耗时完全相等，验收检查可观测的显著分支差异。请求结构非法仍可400 INPUT_INVALID，但不得含用户是否存在信息。

AAD状态接口只报告启用与否；登录失败的URL、响应体、HTTP头不得携账号特定错误。服务器保留原始拒绝分类和requestId，前端不按内部错误细节拼接提示。代理、网关、auth、system失败映射须一致，旧登录入口同批核对，不能只改页面文字。

### 5.2 审计

记录事件时间、requestId、可信操作者/可关联用户、场景、操作类型、目标、结果和受控原因分类。口令、验证码、operationProof、challengeId、SAML原文、sessionKey、完整敏感载荷及其可离线猜测摘要禁止日志/URL/localStorage。未成功认证的账号信息按现有审计权限脱敏，客户端只得到统一提示及关联请求号。

二次认证事件独立归类，不增加login_count或用户上次失败登录时间。重置及政策修改的成功审计与业务和回执同事务，失败审计独立写；已有日志查询仅超级管理员可见的范围不扩大。

## 6. 存储与实施依赖

目标新增两类M01持久化承载，其字段见[数据库字段字典增补](数据库表结构与字段字典.md#认证安全增强目标承载2026-11-01)。现有sys_management_request仅用于冻结管理动作，不能塞入密码族或扩共享操作码绕过设计；Redis只承担短时挑战、验证码与限流，不独立承担成功回执。

本轮已实现本地账号源码并同步物理DDL、完整建表/核验及来源清单哈希；初始化种子不变，不执行目标数据库操作。静态同步不等于目标MySQL执行通过，存储运行状态 `NOT_VERIFIED`。既有库升级须单独审核授权，不重跑空库脚本或history/sql；源码不得先于存储/秘密配置部署。AAD普通登录旧成功入口尚未统一走I02/快照，不宣称已覆盖AAD登录安全反馈。

配置包括限流窗口/预算、挑战与凭证TTL、回执保留期、HMAC密钥标识、可信代理范围。密钥无源码默认值，经部署秘密配置提供；轮换保留在途验证所需旧keyId至回执窗口结束，禁止丢失密钥后放行。各节点必须同步时间。当前未发现的客户AAD能力只阻断AAD重新认证分支，不阻断本地账号设计。

## 7. 验收矩阵与交付口径

| 编号 | 验证内容 | 必须达到的结果 |
| --- | --- | --- |
| SEC-T01 | 同图并发猜测、错误后重用、跨标识消费、过期 | 最多一次有效比较；归属不符不消耗他人图；无绕过 |
| SEC-T02 | 刷新、清Cookie、伪造转发头、多实例、共享出口、Redis故障 | 预算共享且受限；合理共享出口可用；故障不放行 |
| SEC-T03 | 缺/伪造/过期凭证，换用户/载荷/版本/requestId/会话 | 两类写均拒绝；无任何部分业务更新 |
| SEC-T04 | 本地二次密码错及冷却、角色权限修改、本人改密 | 独立计数；角色权限不新增弹窗；本人改密保持旧验证 |
| SEC-T05 | 同凭证并发、业务回滚、提交后断网、回执过期 | 一次业务效果；成功结果可按原请求恢复；不自动换键 |
| SEC-T06 | prepare后撤权/禁用/换会话、目标越权、版本冲突 | 提交时重新拒绝；二次认证不提升权限 |
| SEC-T07 | AAD复用旧SSO、换身份、断言重放、客户IdP不可用 | 不能冒充重新认证；不替换业务会话；缺客户证据BLOCKED_EXTERNAL |
| SEC-T08 | 第一次登录、失败后成功、挑战后登录、刷新/重启/并发同毫秒 | 快照稳定，严格展示本次之前的事实；无历史保持NULL |
| SEC-T09 | 本地不存在/错误/停用/锁定、AAD各类失败 | 外部状态/码/结构统一；内部审计区分；无显著枚举差异 |
| SEC-T10 | 浏览器、网关/直连旧入口、日志及存储检查 | 无绕过；无敏感原文；记录真实请求/响应及清理情况 |

后端需覆盖Mapper字段映射、并发、回滚和幂等；前端覆盖取消清理、重复点击、未知结果恢复及统一提示。数据库在隔离目标版本MySQL验证约束，生产/共享库不得作为首次验证环境。用户可见变化必须浏览器验收，记录页面步骤、method/URL、请求头、脱敏payload/response、后端异常及数据清理；敏感口令/凭证不纳入验收附件。

分层报告：按本地账号源码、契约测试、SQL目标执行、HTTP、浏览器、AAD和现场分别登记，不以较低层结果代替较高层。实际用例数、原始退出码及全量失败见实施计划。建议阈值核准、AAD重新认证能力、现有AAD激活统一接线和部署分别登记，不以这些依赖虚构通过结果。
