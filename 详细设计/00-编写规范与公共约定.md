版本：1.0；日期：2026-09-08；状态：编写规范已整理，模块设计逐份评审。

当前属于九步计划的第 3 步。详细设计文件、线框图和 SQL 均为设计交付，不代表业务代码或数据库已经修改。每个业务模块以一份完整主文档组织，字段字典和较长 SQL 可放在配套文件，必须从主文档直接链接，不另建互相脱节的接口/页面文档体系。

## 1. 证据与版本

1. 业务依据依次为：最新用户确认 → 最新澄清决策 → 当前需求正文与原图 → 旧系统参考。旧设计草稿出现冲突时回到需求，不默认已定稿。
2. 数据库改造以当前 `sql/ymsw.sql` 和目标库只读结构为基线，参考 `cdp.sql`、`npp.sql`。文件快照不等于运行数据库；记录路径、日期和必要的哈希，保留用户已有修改。
3. 每项结论注明“需求已确认”“当前源码事实”“技术设计建议”或“外部依赖”。已有表/页面不等于已通过验收；不得从缺少源码推断其他仓库完全没有实现。
4. 每个模块维护 REQ、UI、DB、API、SEQ、CASE 标识映射和变更记录。技术建议进入评审，不冒充用户已确认。

## 2. 模块必备章节

| 章节 | 最低交付要求 |
| --- | --- |
| 范围与复用 | 需求来源、现状证据、改造点、排除项、依赖和代码影响 |
| 业务规则 | 角色、操作、前置条件、校验、审批、数据口径及副作用 |
| 状态与权限 | 定义表、Mermaid 状态流转图、转换规则、按钮/状态矩阵、非法转换 |
| 页面交互 | 布局原型/线框图、列表/表单字段、联动、按钮、反馈、退出和接口映射 |
| 数据库 | 完整表字段、字典值、逻辑 ER、索引、关联完整性、历史与迁移 |
| 接口 | 每个接口的全部输入输出字段、示例、错误码、权限、事务、幂等 |
| 调用时序 | 页面请求顺序、后端关键调用、异步/错误分支，使用 Mermaid 时序图 |
| 一致性与恢复 | 并发、重复提交、部分失败、过期/迟到事件、恢复及人工处理 |
| 运行与验收 | 日志、版本、性能容量、配置、上线回退、逐场景预期结果 |

模块不适用的章节写明理由，不空缺，不复制与模块无关的复杂机制。

## 3. 数据库设计统一要求

- 表级属性：物理名、中文名、用途、来源表、改造类型、引擎/字符集、主键生成方式、行生命周期、数据维护主体。
- 字段级属性：列名、中文名、类型/长度/精度、主键、可空、默认值、单位、完整枚举/字典值、来源和更新时机、关联表及字段。
- 字典字段写明字典名称、类型编码、存储值与显示含义、默认值、启停策略。固定技术枚举注明不是可自由配置业务字典；不能仅写“见某字典”。禁止擅自把 Y/N 与 0/1 混用。
- 不建立数据库外键约束。ER 图中的关联都是逻辑关系，标明基数和字段；新增/修改、批量、导入及后台任务共用关联校验。删除/停用如何影响引用和历史必须写明。
- 唯一约束不因取消外键而取消；解释组合索引字段顺序对应的查询/冲突控制。无必要不因风格重命名被广泛引用的现有列，确需改名必须给旧新映射和代码影响。
- 目标表必须列全部列，既有不变列也不能用省略号代替。关联模块表可以列为只读外部依赖，不重复宣称本模块负责其完整改造。
- 修改 SQL 包括前置检查、备份、DDL、数据回填、字典/配置初始化、核验和回退。未知目标库数据不猜测；阻断检查失败要停止而非清洗掉问题行。
- MySQL DDL 不能以普通业务事务回滚理解；脚本注明一次性执行、重复执行行为、部分失败后的恢复方法。敏感数据备份不得导入文档或输出到普通日志。

## 4. 接口与时间约定

- 全局内部主键以十进制字符串传给 JavaScript，避免 bigint 精度损失。数据库保持 bigint，不因前端传输变更为字符串。
- 时间戳采用带时区的 ISO 8601，业务日期 `YYYY-MM-DD`，业务时区 Asia/Shanghai；现有接口兼容差异单列。区间端点、到期比较符必须明确。
- 参数表包含位置（Path/Query/Header/Body）、类型、必填、默认、含义、单位、范围、示例。嵌套对象与数组展开到叶子字段；不写“返回用户对象”而省略属性。
- 接口必须区分现有、调整、新增、内部调用；保留现有 R/AjaxResult 外壳，模块明确嵌套层级。认证失败、业务校验和未知执行结果不能都用成功状态伪装。
- 创建/修改操作说明 requestId、幂等范围和寿命、重复同内容/不同内容如何处理；版本冲突说明刷新、保留输入和再次提交规则。
- 敏感参数不得在 URL、操作日志、异常堆栈或常规事件载荷中明文记录。

## 5. 页面设计统一要求

每个页面均提供结构图、字段表和完整交互。字段写控件、顺序、默认、必填、只读条件、校验提示、来源和关联 API；按钮写可见/禁用条件、确认文案、调用、成功刷新及错误行为。

必须覆盖加载中、空结果、无权限、失败重试、保存中、版本冲突、离开未保存、返回后筛选分页保留。密码等敏感输入退出立即清空；普通表单可以保留用户输入，但不能跨用户恢复。

线框图是交互评审依据，不表示视觉样式已经最终验收。先确认信息结构与流程，沿用当前 Vue/Element Plus 组件习惯；不借详细设计重新设计无关品牌或页面。

## 6. 状态、时序与计算

- 培养、检测、审批、任务、设备命令分别建模；状态图不代替转换条件表，接口时序不代替状态图。
- 转换表写原状态、触发者/事件、守卫条件、目标状态、事务内变化、事务外动作及失败结果。时间派生状态不一定需要落库，写清唯一计算口径。
- 计算模块写输入来源、量纲、精度、舍入、取数时点、公式版本和独立验算值。目标与实际、初始与当前分别命名。
- 设备模块增加接受/生效/回读区别、停止确认、执行锁、失联停止、重启对账和模拟/实机边界；不能从数据库提交成功推断物理动作成功。

- [ ] 迁移 SQL 无占位语句，前置检查和回退限制明确。
- [ ] 并发、重复提交、过期请求及恢复有可验证预期。
