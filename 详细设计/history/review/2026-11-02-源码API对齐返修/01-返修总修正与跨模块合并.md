## 2. 统一分类口径（本轮唯一有效定义）

> **落点说明**：本节目的表格与硬规则已由合并批**收入现行规范正文** [../../../00-编写规范与公共约定.md §9](../../../00-总纲与约定/00-编写规范与公共约定.md)（A—F 主分类、四属性、四计数维度、硬规则、契约落点要求）。本文件与《90-计数口径与分维度基准》保留为返修审计与底账证据，不再是口径的唯一来源——否则模块正文将反向依赖 `history/review/`，正是本轮缺陷一的另一种形态。

主分类**有且只有一个**：

- **A** 现行设计已完整记录，且与源码一致
- **B** 专题已完整契约，仅入口缺链接或定位不完整
- **C** 源码存在、现行契约缺失或仅零散提及，**本轮补齐**
- **D** 源码与设计存在实质差异（设计口径与源码口径并列写，不裁决、不改码、不升格）
- **E** 现行有效设计要求存在，但实现链缺失（需补开发）
- **F** 停用／被替代／延期／非本期／平台辅助，单列不进待开发

四个独立属性（不得塞进 A—F）：

- **接口性质**：公开HTTP / 受控内部HTTP / Java Port / Feign声明 / 后台消费者 / 非接口辅助
- **业务范围**：本期 / 延期 / 停用 / 范围待核
- **实现情况**：真实接线 / 部分接线 / 仅路由或拒绝桩 / 无实现
- **验证情况**：AGENTS.md §13.2 词表

硬规则：有 Spring 映射注解即 HTTP 接口（`@InnerAuth`、HMAC 验签、网关不暴露都只是访问边界）；内部业务用途≠非 HTTP；有编号≠A；无编号≠C；历史或辅助代码≠F；内部 Java 方法与 Mapper default 死桩**不是接口**，另册不计数（这正是上一轮 M05 把 D 用错的根因）；停用或被替代不得混入 E；前端在用不得留 F；实质差异必须记 D。
