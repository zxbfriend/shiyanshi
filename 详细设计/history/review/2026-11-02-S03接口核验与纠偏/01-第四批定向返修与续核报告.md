### 2.3 本轮发现并修正的扫描器实质缺陷（2 处）

**缺陷 1：参数列表右括号定位错误（影响 handler 身份键内容）**

- 现象：原实现用 `text.lastIndexOf(')')` 定位参数列表右括号。对「单行方法体」与「参数注解含嵌套括号」会切到更外层右括号，产生伪签名。
- 实例：`WorkflowBatchQueryController#detail` 原签名 = `StringbatchId){return`；`StatisticsController#cultureLabs` 原签名 = `java.util.List<String>cultureIds){return`；`DetWorkbenchController#markException` 原签名含 `.springframework.web.bind.annotation.RequestHeader(value="X-M05-Contract-Version",required=false)String`。
- 影响面：**42 条** handler 的 `paramSig` 为伪签名（占 1045 行的 4.0%）。
- 修正：改为从 `(` 起逐字符配平、记录 depth 首次回到 0 的位置作为右括号；配平过程屏蔽字符串/字符字面量；注解剥离改为支持嵌套括号与点号限定的 `stripParamAnnotations()`。
- 修正后：伪签名条目 **42 → 0**；`WorkflowBatchQueryController#detail` 签名 = `String`。

**缺陷 2：注解剥离不完整**

- 原正则 `/@[A-Za-z_$][\w$]*\s*(\([^()]*\))?/g` 无法处理嵌套实参，且残留 `.springframework...` 前缀。

### 3.3 本轮额外发现并修正的消费者漏检：Vue props 注入链

**现象**：M03 的 `ResProjectController#memberTree` / `#memberDetails` / `#saveMembers` 3 口被 v6 判为 `TEXT_ONLY`（「仅导入未调用」），但页面上确有真实调用。

1. 子组件内 `props.<prop>.<member>(` 记入 `PROP:<prop>` 桶；`const { api } = props` 解构后 `api.<member>(` 同理；
