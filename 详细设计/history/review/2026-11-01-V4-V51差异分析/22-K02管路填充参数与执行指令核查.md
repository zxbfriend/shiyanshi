# K02管路填充参数与既有执行指令核查

日期：2026-11-01；代码HEAD：`9aabe22594919a968d5ebc6fa95cdc245747c790`，同时读取当前工作区。用户授权核查已有附件与代码、记录具体缺口，暂不修改业务代码和客户原件。本记录不是新的业务裁决或执行方案。

## 1. 结论

新版已经明确：**小试开始培养第3步操作取样单元内的取样泵，净重g，速度数值g/min或Speed1—Speed10二选一，开始/停止可重复，允许跳过**。V5.1原文明确该驱动为既有功能，由药明方开发人员提供具体联调逻辑。因此不是业务含义未定，也不是需要用户再选择执行器。

旧附件有补料泵预填充、取样冲洗、普通取样、OPC/IOT补料等多个不同分支，不能仅凭名字相近认定某个旧接口就是新版取样管路填充。当前代码能够维护取样单元编号、展示它及记录跳过/模拟操作；**真实取样填充的参数、物理派发和结束结果链尚未接通**。

K02保留四类内部子项：实际设备寻址及既有入口、净重/速度字段对应、停止及结果对应、我方接线。不增加自动达量停止前置、强制档位标定、库存扣减、审批或恢复入口；不阻断允许跳过的开始培养独立路径。

## 3. 旧指令分别能证明什么

| 旧链 | 已有入口/动作 | 对本次K02的可用程度与限制 |
| --- | --- | --- |
| 补料连接预填充 | `workflow/filling?action=start_pumping` / `abort_pumping`；PUMP_LIQUID / ABORT_PUMPLING；回调`get-prefeeding-result` | 能说明旧系统存在预填充过程和回调关联；明确操作反应器补料泵，不能直接作为取样单元泵接口。 |
| 冲洗预填充 | `workflow/rinseprefilling?action=start` / `abort`；CLEAN_OUTSIDE / ABORT_CLEARING | 能说明冲洗链；不是已证实的新版净重填充。附件还指出结果误回调`get-disinfect-result`，不能把该错误照搬成新目标约定。 |
| 手动取样 | `manual/operation/bioreactor`下`start_sampling` / `abort_sampling`；`sampling_getinfo`；回调`get-sampling-result` | 是取样设备驱动的相关线索；尚不能证明该动作接受本次净重/档位、只做管路填充。普通取样会更新库存并可能写留样工序，不能未经依据将这些副作用带入开始培养。 |
| 手动冲洗/消毒 | `start_clearing` / `abort_clearing`、`start_disinfection` / `abort_disinfection` | 只说明对应原动作，不等于取样管路填充；不因可复用同一硬件就新增冲洗/消毒步骤。 |
| OPC/IOT补料V2 | `start-pumpingV2` / `abort-pumpingV2` → PumpingService | 证实Core以外另有旧OPC服务，但已查说明仍是补料；不能从它推断取样填充使用相同方法及参数。 |

**不指定其中任何一条为最终实现**。优先让现有OPC/原执行服务开发人员指出已在用的取样管路填充方法及一组真实请求/返回；如果已有独立方法直接复用，不要求客户新建统一网关，也不让操作人选择控制方。
