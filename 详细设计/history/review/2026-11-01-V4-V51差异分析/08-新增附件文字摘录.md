3. 算法与公式
四舍五入统一走 ConvertToTwoDecimalPlaces：Math.Round(x, 2)（.NET 默认中点舍入）。下文记为 Round2。
3.1 公共中间量
设离线 pH 为 \(c\)（自动=BGA cpH，手动=入参 OfflinePHValue），在线 PV 原始值为 \(p\)，当前 OFFSET 为 \(o\)，SP 为 \(s\)，deadband 低/高为 \(d_L, d_H\)。
a = Round2(c − p)   // 带符号差值：离线 − 在线
ΔpH = result = Round2(|c − p|)   // 绝对值，用于规则匹配
b = Round2(a / 2 + p)   // 中位目标 pH（约等于 (c+p)/2）
自动路径在进 PHCalibration 前会把 PV 先存成两位小数 OnlineData，因此自动的 a 实际是 Round2(c − Round2(p))。手动路径的 a 用 PV 原始值：Round2(c − p)。规则匹配的 ΔpH 两边都是 Round2(|c − p原始|)。
3.2 下发 OFFSET
校到离线值（自动 calType=5 / 手动 CalibratedToType=0）：
newOffset = Round2(a + o)
校到中位值（自动 calType=3 / 手动 CalibratedToType=1）：
newOffset = Round2(a / 2 + o)
物理含义：把在线读数往离线（或两者中点）拉，补偿量加在现有 OFFSET 上，而不是覆盖成绝对值 pH。
3.3 Deadband 门限
允许区间：  (s − dL) < 目标值 ≤ (s + dH)
场景目标值是否校验
自动 · 离线值—不校验，直接写 OFFSET
自动 · 中位值b校验，失败则不下发
手动第一次 · 离线值离线 cpH（c）校验
手动第一次 · 中位值b校验
手动二次确认 Sec—不校验，直接写 OFFSET
4. 自动校准逻辑
代码：Form1.RunAutopHTask → 规则匹配 →（需要校时）Form1.PHCalibration。
4.1 前置条件
1
取 CDP_Auto_Setting_Task_Info 中未删除、任务未结束（Status<5，Info.Status=1，EndTime>Now）的批次。
2
GetTaskMsg：当天该 BatchCode 在 CDP_Auto_Setting_Task_Msg 已有任意记录则 msgCount≥1，整天不再处理。
3
查 BGA：当天、已完成、最近 BGApHTimer 分钟内、SampleId 含批次号的最新一条 cpH。没有或为 0 → 记日志 Not Find Test Data，不写消息表，下一轮还可再试。
4
读 OPC：PV / SP / DB_HI / DB_LO。PV 为空则本轮跳过该罐。
4.2 规则匹配（由 ΔpH 决定）
阈值来自任务表：Rule1Param、Rule2Param2、Rule3Param2。操作码：1=不校准，3=中位值，5=离线值。
规则条件行为
Rule1
ΔpH ≤ Rule1Param
不写 OPC。记 Status=2，「偏差太小不校准」。
Rule2
Rule1Param < ΔpH ≤ Rule2Param2
按 Rule2Operation：1 不校；3/5 进入 PHCalibration。
Rule3
Rule2Param2 < ΔpH ≤ Rule3Param2
按 Rule3Operation，同上。
Rule4
ΔpH > Rule3Param2
不写 OPC。记 Status=2。代码用的是 Rule3 上沿，不是 Rule4Param。
表字段 Rule1Operation、Rule2Param1、Rule3Param1、Rule4Param 会被查出，但当前自动计算未使用。
4.3 PHCalibration 下发
再读一次 STD_OFFSET（nowSetVal）。
需要 nowSetVal 有值、result > 0、a 有值。
calType=5：val = Round2(a + o)，直接 Write。
calType=3：算 b，过 deadband 后 val = Round2(a/2 + o) 再 Write；不过则 Status=2，文案「校正值超出 deadband 范围」。
Rule2/3「命中」只表示 ΔpH 落在要校准的区间。中位值路径还要过 deadband。校验失败仍会写入当天消息表，因此自动当天不会再试。
5. 手动校准逻辑
接口定义：ISystemService，路径前缀 pHCalService/api/。
5.1 GetOnline
POST .../getOnline。按 LabDeviceName 拼 PV 标签，读实时 OPC，四舍五入两位后写入返回体 OnlinePHValue。入参里的在线值会被覆盖。SP / deadband 读点代码已注释，本接口不读库、不算 OFFSET。
5.2 StartPHCalibration（第一次，带门限）
必填：LabDeviceName、OfflinePHValue、OnlinePHValue、CalibratedToType。真正计算仍会重新读 OPC 在线值。
CalibratedToType = 0 离线值：deadband 判断对象是离线 cpH；通过则 val = a + o。
CalibratedToType = 1 中位值：deadband 判断对象是 b；通过则 val = a/2 + o。
失败：超出 deadband → 业务 Status=7 / 消息表 Status=3；写点失败 → 消息表 Status=3。
5.3 StartPHCalibrationSec（二次确认）
公式与第一次相同，但跳过 deadband，只要 OPC 读写成功就下发。用于界面提示超带宽后实验员仍确认执行。

8. 计算示例
8.1 自动命中 Rule2 但中位值超 deadband（FX048）
c  = 7.171          // BGA cpH
p  = 7.106352       // PV
ΔpH = Round2(|7.171 − 7.106352|) = 0.06     → Rule2（例如 0.05 < 0.06 ≤ 0.10）
OnlineData = 7.11
a  = Round2(7.171 − 7.11) = 0.06
b  = Round2(0.06/2 + 7.11) = 7.14
s  = 6.9, dL = dH = 0.2
区间 (6.7, 7.1]，7.14 > 7.10 → 不下发 OFFSET
8.2 手动二次确认写出中位 OFFSET
c  = 7.171
p  = 7.097774
a  = Round2(7.171 − 7.097774) = 0.07
o  = 0.019868
newOffset = Round2(0.07/2 + 0.019868) = 0.05
写入 V48-AIC-PH/FS_CTRL1/PH_COMP1/STD_OFFSET.CV = 0.05

代码没有真正解析 Type=3 的共享指向，而是用「先勾了谁就不重复计公共耗材」来近似共享：
