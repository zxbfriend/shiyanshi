## 1. 结论与交付标准

**补充前基线：详细设计已有较完整的业务规则、数据模型与接口基础，但尚未达到"逐接口可直接实现、可直接分派多人／多 AI 并行开发"的约定交付标准。** 补充前差距集中在以下三处；本轮结果以文末执行记录为准：

1. **错误码全集未收口**——M02 / M05 / M07 分散无单表，M06 / M09 已有错误码表，M04 §9.6 已包含 `CONFIGURATION_INCONSISTENT`；需要核对散落定义并建立统一入口。这直接决定前端统一错误解析能否落地（顶层 02 §8.1 要求 HTTP 状态与 code 一致、客户端统一解析外壳）。
2. **M07 设备命令缺 request/response 逐字段表**——`submitCommand/queryCommand` 概念齐（见 §2 与 `泵速执行与设备恢复契约.md:3`），但没有把命令身份/fence/速度选择与单位/生命周期查询态/停止证据收敛成一张可契约测试的字段表。
3. **主链时序图偏概要**——[统一主文档 §4](../../00-统一详细设计主文档.md) 已有 4 张端到端主线图，但**缺 `alt` 失败分支、事务边界内联、UNKNOWN-断线-重启-FENCE-幂等命中细化**，且"**培养七态 × 设备占用释放 × 运行事件**"当前无专门跨模块图。

以 M01 的**接口描述颗粒度**（字段级 + 幂等 + 冲突 + 版本）为尺子，补 M02–M09 各模块必要的调用时序与异常设计。**M01 是契约写法的参考基线，不是可照抄的模板、更不是各项全达标的实现**——其错误码本身也需收口，认证/管理双壳、SYSTEM 守卫、管理版本命名各有适用范围，不能机械推广到高頻采样、设备命令与事件通道。

交付须满足 5 项：

1. 每个纳入本期实现的接口明确**编号、方法与完整路径**（内部方法则明确拥有方与调用方式）、权限、**请求与响应逐字段**（类型/必填/取值域）、成功与失败样例、幂等键、版本控制、**事务边界**与错误处理。
2. 公共 DTO、错误外壳、通用规则允许引用，但**必须能直接定位到完整定义**；不得只写"同现有实现"或要求开发者自行补字段。
3. 关键调用链有**开发级时序图**：实际调用顺序、同步/异步、事务开启与提交、**事务外才做的调用**（如设备网关），以及适用的冲突、幂等、UNKNOWN、断线、重启恢复路径。
4. 生产方与消费方对字段、枚举、单位、版本、事件与错误语义**采用同一契约**。
5. 可分配任务包明确**修改范围、依赖契约版本、模拟输入输出、验收用例、集成责任**。

**验收目标：开发拿到任务包后，无须自行猜测接口字段、调用顺序、事务切分或失败处理；跨模块双方能按同一份契约独立实现并完成契约测试。** 文档里给了测试样例与断言，≠ 代码测试已执行/通过；实机验收与契约测试分别记录。

## 3. 任务执行原则

T0–T10 均为本轮对应范围的**必交项**；编号顺序表示依赖，不表示低编号优先做完才能碰其余。某接口或分支若判定不适用，须在该任务下**记录依据**，不得以"单人能写""可边写边补"降低交付要求。

其中 **T0–T3 是编码前置的硬契约**（枚举收口 / 错误码全集 / M07 命令字段 / 主链异常分支），**T4–T6 供多人并行开发对齐**，**T7–T10 是联调核对、一致性与任务包**——三档可并行推进，但 T0/T1/T2 的字段与码必须先落定，T3/T5 的异常分支图才有稳定基线。

已有内容做**引用与收敛**，不完整内容**补齐**，真正缺失内容**新增**；每张任务落盘后登记"实际文件 / 章节 / 契约版本 / 核查结果"。保留最新澄清决定、本期排除项与 M08 暂停，不开发业务代码、不执行迁移。
