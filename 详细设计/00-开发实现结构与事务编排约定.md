## 1. 现有工程适配结论

### 2026-10-11资源共锁的HTTP与后台双入口

本条为待实施技术合同，不宣称现有ManagementGuardExecutor支持后台调用。现有execute必须解析可信HTTP会话、校验WriteMeta，并提交管理版本/回执/审计；调度器不得伪造sessionKey、用户ID或调用GuardCallbackContext.open冒充合法管理写。

M01/公共拥有方（共享窗口由work2执行）提供同库资源事务入口：受信的M07调度器/执行器在事务开始时只锁既有sys_management_revision的SYSTEM行，再按[调用总设计](00-Controller与模块接口调用总设计.md)第5节统一全序取得业务根、设备及资源锁。后台身份来自受控Bean调用点和已核准执行器归属，携带sourceModule/sourceAction、持久任务或事件ID、executorId/assignmentEpoch（适用时）、资源集合与期望资源版本；不能由浏览器传参生成内部身份。不同后台用途分别登记白名单，不能用一个任意callback入口开放全部写能力。

后台只共享SYSTEM行的互斥锁，不执行管理版本CAS/递增，不产生用户管理回执，不进入HTTP GuardCallbackContext；依靠M07对象版本、fence、创建键和不可变run_event记录业务幂等与审计。HTTP写仍使用原管理守卫。两条入口取得同一SYSTEM行后均须遵守相同下层锁序；共享锁不是共享用户权限，不改变原授权判定。

拥有方锁读/占用转换Port加入调用方同一数据源事务，禁止REQUIRES_NEW、回调重新进入管理守卫或持锁RPC。先按资源稳定身份声明本次完整锁集合，必要的只读预解析不提供资格；事务内按全序重新核验，发现新增更早层级锁则回滚重来，不逆序补锁。事务内只持久化任务/占用/命令意图，设备调用在提交后执行，回写也走受信资源入口。外部结果UNKNOWN及租约超时不能自动释放物理占用。

实现准入：公共入口与M07真实占用建立/释放路径同批接入；测试覆盖无HTTP会话的合法后台调用、伪造/越用途拒绝、后台与HTTP竞争、回滚、版本不被后台无故递增、fence/UNKNOWN不被清除。只登记入口而没有生产消费者不得称共锁已实现，先依赖此能力的通讯删除/液瓶写仍不得翻wired。不得放宽GuardCallbackContext.open唯一生产调用点。

#### 2026-10-11技术合同第三轮：受控入口、来源与失败边界

待实现入口命名为ResourceTransactionExecutor，归M01/公共窗口；不是ManagementGuardExecutor.execute的后台重载。入口使用同数据源REQUIRED事务：已有事务则加入，无事务则创建；确认实际事务活跃后调用既有selectRevisionForUpdate锁SYSTEM行，无行视为依赖故障，不自行补行。它不调用increaseRevision、不插sys_management_request、不调用GuardCallbackContext.open。异常须使整组事务回滚，禁止捕获后继续提交；这些名称是目标登记，不表示生产类已经存在。

内部身份不得仅由传入的sourceModule/sourceAction字符串或可任意实现的标记接口证明。公共配置装配阶段把核准的具体调用Bean与固定用途绑定，形成仅向该Bean注入的能力句柄；普通Controller、未登记Bean和通用组件不能取得句柄。允许用途固定为M07资源抢占、命令回执应用、证据核准释放三类，每类再限制可调用Port及资源操作。注册表不可运行时随意追加；开关futurefab.resource-transaction.enabled缺失或false时不开放后台入口。启动核对用途、Bean、同数据源与事务管理器，冲突则拒绝启动该能力，不能退化成无锁调用。任务/事件ID、executorId及assignmentEpoch仍须读取本域持久事实核验，能力句柄不代替对象资格。

入口建立独立ResourceTransactionContext，包含固定调用来源/用途、任务或事件ID、已核验执行器归属、完整锁集合、SYSTEM锁已取得的事实和当前事务绑定；只在当前线程及该事务内有效，finally清理，不向异步线程透传，不接受HTTP反序列化。每个受影响Port在PKG-00逐方法登记HTTP_ONLY、BACKGROUND_ONLY或BOTH：HTTP_ONLY继续要求原守卫上下文；BACKGROUND_ONLY只接受上述用途和领域版本/fence；BOTH分别校验各自来源，不把“有任一事务”视为授权。仅后台需要的资源锁读/占用转换方法登记BOTH，用户/授权管理Port不得整体放开。P04纯查询另按M03来源合同校验，不强加HTTP管理写上下文。

事务与等待预算采用必填部署参数futurefab.resource-transaction.timeout-seconds、futurefab.resource-transaction.lock-wait-seconds（正整数，等待预算不大于事务预算）；无值不启用后台能力，不使用数据库默认值冒充已验收预算。同样的等待上界适用于HTTP资源写，实施时由公共拥有方提供连接级生效及恢复方案，不能改共享连接后遗漏恢复。SYSTEM/资源锁等待超时或死锁统一503 MANAGEMENT_BUSY并整组回滚；后台仅以原持久事件/任务身份有界退避重试，耗尽登记待恢复，不换身份、不释放UNKNOWN、不继续无锁执行。连接/提供方故障为503 DEPENDENCY_UNAVAILABLE；事实源响应成功但缺失/不完整为503 RESOURCE_FACTS_UNAVAILABLE。

共享SYSTEM锁区内禁止RPC、设备/文件IO、轮询和无界扫描；所有锁集合有界并先解析，写入数与预算登记在实施验收清单。性能验收必须给出真实部署预算、HTTP/后台混合负载下锁等待与持锁时长p95/p99、吞吐及超时回滚结果；本轮不虚构毫秒SLA或已通过性能验收。公共入口、上下文及最小真实消费者同批交付后才解除实现前置；具体部署参数和竞争验收未完成仍为BLOCKED_DEPLOY/NOT_VERIFIED，不把缺部署值误写为缺业务设计。

#### 2026-10-11第四轮：能力不可伪造及具名门禁

2026-10-11复审残余（代理检测手段）：唯一装配入口对工厂返回值及最终取得的三个消费者Bean分别使用Spring AopUtils.isAopProxy检查，并用引用全等核对工厂实例与最终Bean；任何代理、后处理器替换或无法取得唯一实例均拒绝启用对应能力，不以目标类相同放行。能力与消费者绑定在最终实例核验后完成，不允许先绑定原对象再由容器换成代理。该检测同实例三态运行用例一并交付，属于待实现门禁，不假称当前已有启动检查。

2026-10-11复审补正（消费者实例身份）：三类登记消费者仍可作为Spring Bean供调度器调用，但固定工厂返回的具体实例不得被Spring AOP/JDK/CGLIB代理包装；资源事务由ResourceTransactionExecutor承担，不在消费者上另挂事务代理。装配登记与调用核验使用同一实际实例引用，启动检测到代理即拒绝启用该能力，不按类名放行、不临时解包或重新绑定。若未来确需代理，须先修改此合同并增加代理身份测试。实施批须验证普通实例可用、代理实例拒绝、同类另一实例拒绝，不能仅以类名匹配证明身份绑定。

2026-10-11复审补正（扫描取证边界）：上述语法/类型扫描仅用于禁止性负控制，定位未经登记的构造、绑定、暴露及调用点，不以源码字符串或测试名称存在证明正向接线。正向交付必须验证实际装配实例、真实入口和持久化协作行为，运行权限/事务/回滚/用途拒绝用例；反射事实可证明形态与实例配置，但不能替代行为用例。该划界不放宽既有ManagementGuardedWriteArchTest的正向接线取证纪律。

能力句柄不是Spring Bean、不是可公开构造/反序列化的DTO，也不提供按类名、Bean名或purpose领取句柄的公开工厂。ResourceTransactionExecutor内部使用私有构造的不可变令牌，并以对象引用身份维护令牌→固定用途→实际消费Bean实例的绑定；调用时核验已登记的同一个令牌实例、用途、当前事务及持久任务/执行器事实，不能靠调用方自报类名鉴权。伪造同名类、字符串、令牌字段副本均无效。边界针对本应用受控代码和配置；不宣称能抵御任意JVM代码执行或反射越权。

装配唯一入口目标全名为com.futurefab.system.service.guard.ResourceTransactionConfiguration，能力创建/绑定方法只在公共实现包内可见、装配完成后关闭。该配置按固定工厂构造M07消费者并把非Bean、非公开网关对象注入其私有final字段，不通过全局容器注册能力/网关，消费者不得公开getter、转交句柄或接受Controller传入任务回调。目标消费者分别为com.futurefab.system.worker.m07.M07ResourceClaimWorker、M07CommandReceiptApplyWorker、M07ResourceReleaseWorker（分别对应抢占、命令回执应用、核准释放，后两类全名沿用同一包）。这些是本轮固定的目标名称，不是假称已有生产类；确需改名先同批更新名单，不能使用包级通配允许。

## 3. 每个HTTP入口的实现登记

模块《Controller请求调用时序设计》的每一行在对应开发任务开始前补齐以下实现记录；这是实现清单，不另造业务契约：

| 必填项 | 内容 |
| --- | --- |
| 契约ID/逻辑端口ID | 使用模块映射表已冻结ID |
| canonical路由 | 唯一目标HTTP method + path |
| 物理Controller | 现有或目标类名和方法名 |
| 应用端口 | 接口全名和方法签名；不得写Mapper方法代替 |
| 路由处置 | `REUSE`原样复用；`ADJUST`同路由改契约；`NEW`新增；`COMPAT`旧路由适配canonical；`DISABLE`明确停用 |
| 特殊序列 | 标准`CTRL-*`编号；若模块有开发级时序图，同时登记图名/序列号 |
| 表与跨模块Port | 本事务写表、只读表、调用的provider方法 |

同一method+path只能有一个canonical处理器。旧路由与目标路由同义时，优先保留一个canonical处理器；兼容入口只转换协议并调用同一应用端口。不能用现有路由数量与目标契约数量的大小关系推断已覆盖。

## 4. 可信请求上下文

Controller统一解析为不可由Body覆盖的`RequestContext`概念对象：`requestId`、`actorUserId`、`actorName`、`clientId`、`managementRevision`、`contractVersion`、来源IP和会话信息。`actorUserId/labScope/sceneCode/ownerModule`必须从会话、对象和服务端映射取得。

- 所有写入口按契约读取`X-Request-Id`；要求SYSTEM守卫的入口同时读取`X-Management-Revision`。
- Header缺失、格式错误或不支持的契约版本在进入应用端口前失败；但幂等键载荷冲突、对象版本冲突在应用事务内判断。
- Body中出现只读身份、版本或派生字段时按契约拒绝，不能悄悄覆盖。
- ID/版本在HTTP JSON中使用十进制字符串，Java内部使用`Long`或值对象；金额/重量/体积等精确数在JSON中使用规范十进制字符串，Java内部使用`BigDecimal`，禁止`double`参与hash或持久值计算。

## 5. 权限和异常映射

Controller上的权限注解只做功能权限第一道门；应用端口必须再次执行对象级范围、当前关系、状态和版本校验。查询先施加范围再分页，导出使用同一范围规则；内部Port不因无HTTP注解而跳过对象守卫。

现有全局异常处理器可以作为统一入口，但目标实现必须新增稳定领域错误载体并由它映射。应用层抛出的领域错误至少包含`errorCode/httpStatus/messageKey/issues/retryable`，响应统一带requestId。未知异常不得把异常消息或堆栈直接返回客户端；日志按requestId记录并脱敏。`AjaxResult/R/TableDataInfo`只存在于HTTP适配层，不能作为模块内或跨模块Port返回类型。

## 6. 事务编排

| 场景 | 事务拥有者 | 同事务内容 | 事务外内容 |
| --- | --- | --- | --- |
| 单模块写 | 拥有方`*CommandApplicationService` | 主表、子表、幂等回执、审计、outbox；按文档锁序和CAS | 文件、设备、邮件、短信、第三方HTTP |
| M01用户与M02用户实验室授权 | M01用户命令编排器；M02提供本地受控Port | 用户状态和授权替换按冻结锁序、同库`REQUIRED`；任一步失败整体回滚 | 通知、缓存失效消息 |
| M03候选提交M06审批 | M03先用本地事务固定候选；提交审批使用来源键幂等 | 每个模块只提交自己的主表/回执 | 模块拆分或网络调用时不得持M03锁；超时按来源键查单 |
| M03变更生效与M07屏障 | 当前单体由M03生效编排器开启`REQUIRED`，M07本地Port加入 | M03主值/候选/回执与M07未开始计算失效，固定锁序 | 若任一端远程化，功能先关闭，完成可靠编排/补偿设计后再启用 |
| M07设备动作 | M07命令应用服务 | 命令意图、资源守卫、outbox | 固定执行器调用设备；结果用新事务CAS回写 |
| M09通知投递 | M09投递worker | 领取/租约或结果回写各自短事务 | 邮件、短信、声光等实际发送 |
| M05报告/导出 | M05作业应用服务/worker | 作业、版本、证据引用及回执 | 文件渲染、对象存储；完成后短事务发布结果 |

写事务传播固定`REQUIRED`、`rollbackFor=Exception.class`。事务注解必须位于经Spring代理调用的public应用方法；禁止同类自调用期待开启新事务。查询预检不能代替写事务内重验。跨模块本地Port若加入同事务，必须在表拥有方方法内写表，调用方不得直接注入对方Mapper。

## 7. 后台worker统一状态机

所有outbox/job/command采用`PENDING -> PROCESSING -> SUCCEEDED/FAILED/UNKNOWN`的概念状态；具体表枚举以模块字段契约为准。领取使用`状态 + next_retry_at + lease_until + version`条件CAS并设置`worker_id/lease_token`；外部调用不持数据库连接。成功、明确失败、未知结果分别回写，UNKNOWN只能用原requestId/commandId向外部查单，不能换新键重发。租约过期允许接管，但旧worker回写必须因token/version不匹配失败。

每个worker实现清单必须登记：拥有模块、扫描表、批大小、租约、最大重试、退避、UNKNOWN恢复、死信/人工处置、指标和停机接续。未登记的表不得由通用定时器猜测推进。

## 8. 表到代码的映射规则

- 聚合根/主数据表：有Repository/Mapper，由应用命令服务维护。
- 子表/关系表：只能随聚合根保存，不单独暴露通用CRUD Controller。
- 不可变快照/历史/动作记录：只追加；纠正产生新版本或反向动作，不覆盖原证据。
- 回执/inbox/outbox/job/command：由应用服务或所属worker维护，不生成管理CRUD。
- JSON列：必须有schemaVersion和结构化Java DTO/值对象；Mapper使用明确TypeHandler或规范序列化器，不传任意`Map<String,Object>`跨模块。
- 每张表仍以《表结构与模块拥有方清单》的唯一写拥有方为准。工作流定义表`workflow_node/workflow_subflow/workflow_step/lab_workflow_node`归M04；M07只读定义并写`run_*`运行表。

## 9. 开发提交门槛

一个接口进入编码前，开发任务必须能回答：改哪个Controller方法、调用哪个应用端口、谁开事务、写哪些拥有方表、调用哪些跨模块Port、外部动作在哪个提交点之后、失败如何恢复。任一项为空即退回设计，不在代码中临时决定。

实现完成至少验证：正向、无权限、对象越权、格式错误、同键同体、同键异体、旧版本、并发CAS、依赖不可用、事务回滚、UNKNOWN恢复；涉及worker再验证双实例领取、租约接管和旧worker回写失败。

### 2026-10-18 当前依赖的数据源包装适配

当前 dynamic-datasource 4.5.0 的实际路由表值为 `ItemDataSource`。锁等待预算的装配核对可接受该公开包装，但须同时证明：包装为准确的 `ItemDataSource` 类型，`p6spy`、`seata` 均明确为 false，`getDataSource()` 与 `getRealDataSource()` 引用相同，且目标为 Druid。不得仅凭 `realDataSource` 为 Druid 就放行其他代理链，也不得通过反射解包。运行期仍在第一条会话语句之前核对事务绑定连接的 Druid holder；设置或恢复失败仍经所属池 `discardConnection(holder)` 废弃，原异常保留。该适配不改变事务资源键、锁顺序、预算必填性和未知包装的拒绝规则。

`ResourceLockWaitBudgetRoutingPoolContractTest` 使用真实 `ItemDataSource → Druid` 包装覆盖同一事务连接生效、恢复与恢复失败废弃，并对代理标志、未知标志及不同实际连接目标做负向验证。契约测试不代表目标数据库锁超时或现场验收通过；实际执行证据另行分层记录。
