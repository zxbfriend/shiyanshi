# 开发人员视角设计走查

日期：2026-09-17。范围：M01—M07、M09；M08排除。方法：以现有Spring/MyBatis工程结构为基线，从Controller入口向应用服务、事务、Mapper、跨模块Port、后台worker和目标DDL反向检查。本轮只修设计文档和SQL设计稿，不修改业务代码、不执行SQL。

## 1. 结论

走查前状态不是“拿到接口表即可直接编码”：逻辑端口和时序已经齐全，但缺少与现有类结构的统一落位规则；路由复用/兼容处置未形成开发门槛；异常映射、事务传播和worker领取规则分散；表拥有方清单仍有M04/M07双拥有方；M03一个CHECK存在NULL穿透。

本轮已将这些共性问题收口到[开发实现结构与事务编排约定](00-开发实现结构与事务编排约定.md)，修正唯一拥有方和M03约束，并把实现登记加入调用总设计。修订后，设计层P0阻塞为0，可以按模块准备开发任务；但代码、空库SQL执行、HTTP联调、浏览器和设备验收仍为NOT_RUN。开始编码须等待用户通知。

## 2. 现状证据与设计影响

| 观察 | 开发风险 | 本轮设计处置 |
| --- | --- | --- |
| 现有代码主要是`Controller -> I*Service -> ServiceImpl -> Mapper` | 若把逻辑Port误当新架构，会平行复制业务层 | 冻结为同一`futurefab-system`内的逻辑模块；优先复用，新增应用服务只做聚合编排 |
| 现有`ResCultureController`直接注入`ResCultureMapper` | 对象守卫、事务和测试边界可被绕过 | 目标入口禁止Controller直连Mapper；旧入口触及时按实现清单收口 |
| 部分Controller直接扫描Redis或编排多个Service | Controller承担业务聚合，权限和失败语义分散 | 在线状态、组合投影下沉查询应用服务；Controller只做协议适配 |
| 现有全局异常处理器把部分异常消息直接返回 | 无稳定业务错误码，可能泄露内部消息 | 冻结领域错误载体和统一映射；模块Port不返回HTTP包装 |
| 现有Service已大量使用`@Transactional` | 跨模块和自调用时容易误判事务已生效 | 冻结最外层应用命令服务、`REQUIRED`、受检异常回滚、禁止自调用和事务内外部I/O |
| 目标Controller映射使用逻辑端口ID | 开发无法仅凭ID判断复用现有方法还是新增路由 | 新增逐入口物理实现登记和`REUSE/ADJUST/NEW/COMPAT/DISABLE`五类处置 |
| 168张表包含主表、关系、快照、回执、outbox、job | 若按表生成CRUD会破坏聚合和证据不可变性 | 冻结五类表到代码映射；仅聚合根有业务写入口 |

## 4. 逐模块开发关注点

| 模块 | 开发人员首要落点 |
| --- | --- |
| M01 | 认证挑战与管理写入口分开；用户变更编排M02授权时遵守冻结锁序；角色/菜单/数据范围三层权限不能只靠注解 |
| M02 | 254个目标入口先做现有路由处置登记，避免重复Controller；设备配置写与设备外部动作分离；观测采集不是M08 |
| M03 | 现有培养Controller直连Mapper的入口不得复制；模式/初始重量统一走候选、政策、审批、生效和M07屏障 |
| M04 | 独占固定工作流定义表；模板版本、绑定、工程快照同事务；M07只能读核准定义 |
| M05 | 工作台命令不能沿用无requestId/version的旧直接Service调用；结果修订、签批、报告作业分别走命令、证据和job序列 |
| M06 | 审批只产生决定和交付，不直接更新M03/M07主表；交付worker按来源键幂等并处理UNKNOWN |
| M07 | 运行计算和设备执行分开；命令意图先提交，固定执行器事务外发送；资源守卫和租约必须可接管 |
| M09 | 业务事实由来源模块判定；规则匹配、收件人快照和投递归M09；通知失败不回滚来源业务 |

## 5. 开发启动时必须产出的首批工件

这些是代码阶段的正常第一批产物，不是新的需求澄清：

1. 按模块Controller映射表生成实现清单，逐行填写物理Controller/应用端口/路由处置；先做所选开发包，不要求一次性改完所有旧代码。
2. 建立共享请求上下文和领域错误映射的最小实现，随后业务Controller统一使用。
3. 为跨模块Port建立provider/consumer contract test；本地Bean调用也按超时/UNKNOWN语义测试，不能因同进程省略契约。
4. 以空库完整DDL生成实体/Mapper时按聚合分类，禁止为历史、回执、outbox、job表生成公开CRUD。
5. 每个开发包附事务测试和并发拒绝测试；涉及外部动作的包附“提交前不调用、回滚不调用、重复不重复副作用”的验证。
