# 在线离线统计需求核查与实现说明

核查日期：2026-10-18。读者：模块开发人员、组长与需求审核人。

## 一 核查结论

在线按时间、在线按培养、离线联合统计的主要页面和读取链已存在，不能认定需求已经全部验收通过。本次对照客户 V4.1 正文、在线／离线 Axure 原型、此前明确确认及 10 月 18 日最新回复，发现了代码偏差、来源接入缺口和验证缺口。用户在核查中明确要求修改的规则已进入本轮代码与回归测试；尚未确认的设备来源不作猜测。

最关键的剩余事项是：真实在线采集身份到培养反应器／控制器身份的映射尚未接通；仅被分享培养的用户可能无法从项目级联入口选到它；候选数量被截断；持续新增在线数据可能让已查快照无法出图；缺测断线和完整 12 万行浏览器性能仍需完善或验证。具体依据与限制见第五节。

基准提交为个人分支 `feature/data-statistics/online-offline` 的 `48a00feb3c1f8878dcb87b9b9dec91f1b9a592ba`。核查开始时工作区是 cloud，故只读提取个人提交，未自行切分支；随后用户工作区已回个人分支。本轮修正以该提交之上的工作区为准，不代表新的提交、推送或运行部署。

本报告只覆盖 V4.1 §2.4、§2.4.1、§2.4.2、§2.5 及对应统计原型，不把实验室看板、中试补料控制、检测签批业务或培养期间专用 21 列导出混入本轮验收。

## 四 本轮已处理的问题

1. 在线按时间的采样从“每段首条”改为“指定小时和分钟内首条”，不再用02:01代替02:00；恢复72档每20分钟。快照命名空间升级v9，旧v8查询不可继续混用。环境若显式设置 INTERVAL_EARLIEST，应改为 MINUTE_EARLIEST；没有自动发布Nacos。
2. 在线按时间不再因为不同采集通道把同一个设备拆成两张同名图；每个点仍保留原deviceKind、deviceId、channelCode。
3. 在线两模式的图数、曲线数、Y轴数按第二节最新确认修正。在线按培养全部拆分不再把同设备两个培养塞在一张图。
4. 离线按指标／全部拆分从“现有离线数据决定面板”改为“用户选择决定面板”，没有离线数据时仍保留图和在线辅助线。
5. 大辅助点数组不再用函数实参展开，避免调用栈溢出。新增20万辅助点回归；该修正不代表已完成真实12万行浏览器性能验收。

本轮未更改用户已有本地连接配置、Nacos导入工具、主题生成脚本及portal打包文件；没有提交、推送、合并、执行SQL、登录业务系统或操作设备。

## 五 剩余缺口和风险

### F01 真实在线来源与培养设备身份尚不一致

级别：P1。状态：BLOCKED_EXTERNAL。

统计按时间使用 BENCH_CONTROLLER／INTEGRATED_REACTOR 去匹配 lab_observation_receipt.device_kind/device_id，而现行 OBS 接收与处理白名单是 DETECTOR／FLOOR_SCALE／DOWNSTREAM_DEVICE。正常进入OBS的读数不能据此直接匹配培养控制器／反应器。当前培养过滤 A 只改变培养选择，不修复这条测量来源身份链。

小试还有两个ID域：按时间候选使用 lab_bench_reactor_controller.connection_id，培养当前主设备使用 lab_bench_reactor.reactor_id。它们即使碰巧数值相同也不是同一个身份。需要M02/M03提供并核验“来源设备＋通道→培养主设备／容器”的映射，不能改字段名或放宽白名单冒充接通。

直接影响：真实在线按时间统计及离线叠加可能查不到数据或没有可信设备标签。需要组长、M02采集和M03关联负责人审核，非用户凭页面判断即可消除。

### F02 12万结果行尚未完成整链路验收

级别：P1。状态：部分CONTRACT_TESTED，整链路NOT_VERIFIED。

原提交使用 list.push(...onlinePoints) 把大量点作为函数参数。只构造约100001条记录、200001个数值点，离线按指标分图就能复现 RangeError。现已修复，并保留了复现与回归证据。后台虽然允许最多120000结果行、默认1200000来源点，但仍一次读源、计算指纹、组装完整快照；前端也最终保留全量点，离线多图可能多次引用辅助点。

必须继续做：真实MySQL查询与执行计划、Redis吞吐和内存、HTTP分批及超时恢复、浏览器选择／滚动／绘图／导出、并发用户与临近30分钟过期。隔离缓存替身的约1秒不能作为生产容量指标。还需为大结果的选择请求和行请求检查默认20秒超时是否够用。

### F03 仅被分享培养的用户可能没有可达选择入口

级别：P1。状态：静态调用链确认，真实账号NOT_VERIFIED。

权限服务的可见培养集合包含培养级SHARE；但项目候选只按项目自身授权等来源查询，不从被分享培养反推父项目。页面必须选项目再选批次，培养选择器才启用。用户只拿到某培养／批次分享、没有父项目授权时，即使后端可读该培养，也可能无法从页面找到。

建议通过M03受权选择器展示可见培养及必要祖先导航，或允许直接选择有权培养；不得为解决入口而授予整项目或扩大查询权限。需有“仅培养分享”“仅批次分享”“过期分享”和“撤权后快照访问”账号用例。

### F04 指标候选和大量候选的完整性不足

级别：P2。状态：IMPLEMENTED范围不足。

在线候选来自所有未删除 dev_detector_item，没有按选中设备／通道的有效 lab_observation_mapping 过滤，离线专用项目也可能出现在在线下拉；线上实际有哪些指标仍需设备拥有方提供映射。该清单未冻结，不能在报告中编造固定在线指标列表。

实验室只请求第1页50条；项目／批次／培养最多500条，页面搜索只是搜索已加载候选，没有远程补查。超过这些数量时，用户有权限的对象可能不可见。设备候选超过500会显式拒绝，至少不会静默假称完整。建议远程搜索／分页候选，并保留授权过滤和明确上限提示。

### F05 缺测断线和大量点的可视化准确性仍需补强

级别：P2。状态：静态与纯函数复现。

当前先剔除坏质量、空值与无目标分钟数据，再把剩余点直接交给ECharts。connectNulls=false只有存在空值点时才形成断点；D0和D3两个有效点、中间无数据时，数组只有两点，仍会直接连线。不是“补了零”，但可能给人连续测量的错觉。

超过10000点的系列启用LTTB显示抽样。后端原点和CSV仍可保留，但显示抽样不保证每个峰值都出现；与现行“不能静默丢掉已选峰值”约束需要协调。建议按采样契约显式表达缺测段，并对大点数显示抽样给出可见说明与峰值保真验收，不能仅凭connectNulls选项宣布断点已实现。

### F06 持续新增在线读数可能使旧快照反复无法出图

级别：P2。状态：静态可确定的条件风险，HTTP未复现。

出图前会重新查询整个条件窗口并与原始全量指纹比较。按培养未填写截止时间时，采集持续新增读数，即使原快照内点没有被更正，也会令指纹变化并要求重新统计。分批图表最后一页也再次比较，大数据传输期间更容易遇到新增读数。

应区分“原结果被更正／作废”与“查询后新增数据”：前者必须拒绝旧数据，后者宜继续展示冻结快照并提示可刷新。实现方式需要冻结窗口上界或只校验冻结来源身份及版本，并保留撤权、作废和更正检查；不能简单删除来源校验。

### F07 导出和页面状态还有次要差异

级别：P2。状态：部分实现。

CSV直接导出已下载的chart.points，没有在点击导出时请求服务端重验来源及权限。若出图后数据被作废或权限改变，仍可导出旧的缓存数据；这与现行输出再检约束不完全一致。已下载数据无法从用户电脑收回，但应用仍应按约定校验新的导出动作。

修改任意筛选条件会立即清空当前列表／图，而原型描述是在点击“开始统计”成功取得新列表后替换。这是交互差异，不是数据计算错误，可作为后续体验优化。当前不把单独的数据视图或逐曲线样式编辑列为遗漏，因为用户已明确保留现有控件。

### F08 旧混合Mock不再命中新抽样规则

级别：P1测试数据阻塞。状态：BLOCKED_DATA。

generate_statistics_mixed_mock.py当前使用slot×15＋2分钟生成在线点，因此时刻为xx:02／17／32／47。它们均不在新五档的目标分钟上，直接沿用这批在线Mock会返回零个抽样点。此问题不应通过从相邻分钟补点解决，否则又违反本轮确认。

需独立准备符合目标分钟的在线测试数据，例如从00:00起每10分钟或更密集、且包含目标分钟的读数，再在获准的隔离测试库按需执行。保留一部分偏移分钟数据，作为应被跳过的反例。当前未修改真实读数、未重新生成或执行数据库脚本；部署前应同时处理抽样配置与测试数据，否则页面可能没有在线曲线。

## 六 当前代码怎样运行

前端路由：app-smp-data 的 online-statistics 与 offline-statistics，复用 statistics/index.vue。在线页面内部有按时间／按培养模式。请求由 sdk-smp-api/statistics.ts 发出。

调用链：页面筛选→SDK→网关 /system/data/statistics→StatisticsController→StatisticsApplicationService→M02/M03/M05只读Port及Adapter→所属Mapper/XML→抽样／命名／组行→Redis临时快照→勾选→图表／分批图表→chart-options.ts→ECharts。

| 接口相对后端路径 | 用途与关键保护 |
| --- | --- |
| GET /data/statistics/options | 指标候选；当前缺按设备在线来源过滤 |
| GET /data/statistics/devices | 有权实验室设备，培养模式与当前主设备取交集 |
| POST /data/statistics/queries | 三模式查询；X-Request-Id幂等；完整后返回数量 |
| GET /data/statistics/queries/{id} | 快照状态、计数、选择版本、D0、过期时间 |
| GET /data/statistics/queries/{id}/rows | 游标分批，每批1—2000行，界面无分页按钮 |
| PUT /data/statistics/queries/{id}/selection | ALL/NONE/SET_ROWS；版本CAS，每次最多500个行ID |
| POST /data/statistics/queries/{id}/charts | 完整已选点出图；重验权限和来源指纹 |
| POST /data/statistics/queries/{id}/chart-pages | 大图分批，游标绑定查询、选择版本、轴模式和票据 |

统一功能权限为 data:statistics:query；每次访问绑定原用户，重验实验室及培养范围。查询／选择只写用户临时Redis状态，不改变业务表，因此不需要照搬M07业务写的X-Management-Revision。

算法分工：StatisticsAlgorithms负责抽样、行组织、D0及相对天数；StatisticsSampleNaming只解析统计用途，不修改样品；StatisticsSnapshotStore负责1000行压缩块、行索引、元数据和选择CAS。快照默认30分钟，不能把它当永久统计归档。

## 七 数据表和关联路径

统计新增Mapper直接涉及15张不同业务表：M02侧9张、M03侧3张、M05侧3张；授权和采集前置还间接涉及下列额外表。下文是逻辑关联，不能据此认为全都有数据库外键。

### 在线读取

lab_observation_receipt.receipt_id → lab_observation.receipt_id → lab_observation_mapping.mapping_id；每条observation再取lab_observation_association中最大association_version的关联结果。

| 表 | 关联字段及用途 |
| --- | --- |
| lab_observation_receipt | 原始收件、真实来源device_kind/device_id/channel_code；不是当然的培养反应器身份 |
| lab_observation | receipt_id、mapping_id、item_id、observed_at、value、unit、quality、process_version；选有效且最新处理版本 |
| lab_observation_mapping | mapping_id→核准指标映射版本；item_id指向dev_detector_item，包含原码、单位、有效区间等 |
| lab_observation_association | observation_id→记录关联培养／项目／批次／实验室，取最大association_version；MATCHED或UNASSOCIATED，培养模式进一步限定culture_id |
| dev_detector_item | item_id、offline_stat_name、detect_class、unit；用于名称和统计指标定义 |
| lab_bench_reactor_controller | connection_id、controller_no；当前按时间小试候选及接收身份标签来源，需与培养设备ID域核准 |
| lab_integrated_reactor | integrated_id、device_no、lab_id；中试反应器候选与标签 |

采集前置的 res_observation_binding_revision 和 res_observation_binding_interval 由所属模块保存设备／通道到培养的关联依据，统计SQL当前不直接JOIN它们，而消费已生成的association。不能因此声称统计已完成传感器到反应器映射。

### 离线读取

det_sample.sample_id ← det_result.sample_id；样品current_result_id限定当前结果；det_result_revision按result_id＋object_version取得不可变内容。

| 表 | 关联字段及用途 |
| --- | --- |
| det_sample | culture_id可信归属，project_id、batch_id、lab_id，sample_no、second_id、day_number，current_result_id |
| det_result | result_id、sample_id、object_version、result_status、result_completeness、testing_end_time、del_flag |
| det_result_revision | result_id＋object_version，content_snapshot中的items、numericValue、unit、isVoided、itemOutcome、evidenceQuality |

M05提供方核对快照身份、版本、cultureId及结构；只选所需items，证据VERIFIED且VALUE、未单项作废的值才进入标准曲线。不直接从可变det_result_item读值覆盖版本快照。

在线和离线的“绑定”是：可信culture_id一致，按查询时间和选择集合并列展示。没有逐条在线点与离线样品的配对表，也没有按最近时间求平均或强行宽连接。自然轴用真实时间，相对轴共用该培养已选集合D0。不能把同一时间段误称为来自同一物理容器。

### 培养标签和当前设备过滤

| 表 | 关联字段及用途 |
| --- | --- |
| res_culture | culture_id，project_id、batch_id、lab_id；culture_code、start_completed_at；device_kind/device_id、container_id；对象／运行版本 |
| res_project | project_id→project_code，仅用于培养标签补充及所属模块选择器 |
| res_batch | batch_id→batch_code，同上 |
| lab_bench_reactor | reactor_id、controller_no、lab_id；M03小试当前培养主设备身份来源 |
| lab_culture_container | container_id、container_no、lab_id；有可信当前容器关联时补充标签 |

当前设备路径为 res_culture.device_kind/device_id→对应小试lab_bench_reactor或中试lab_integrated_reactor，container_id→lab_culture_container。若同一培养历史换过设备，该过滤仍表示“此培养当前绑定该设备”，不改写历史采集来源。样品能解析容器时优先保留解析结果；中试反应器阶段无编码时可显示核实的当前关联并标注时态。

### 权限与Redis

统计复用 SmpPermissionService 与 LabAuthorizationService。间接授权表包括 sys_user_lab、实验室负责人、项目／批次／培养成员及负责人表、相关审批人员范围；具体项目级与培养级分享由M03权限SQL确定，不新建一套统计权限表。

Redis v9按queryId保存1000行压缩块、完整行索引、轻量元数据、ALL/NONE＋例外集合、过期时间、来源指纹及图表传输票据。没有新增MySQL统计业务表；容器解析结果保存在用户快照里，不回写det_sample，也不写lab_observation_mapping。
