## 3. 候选→预检→创建的交付衔接

### 3.1 候选输出

候选读取应能提供：稳定cultureId及实际反应器身份、实验室归属、展示名称/培养编号/阶段、按场地排列所需信息、适用对象版本及本次类型资格。通气另提供具体MFC编号、气体、通路及实际配置来源；它们只读，不允许客户端以同名显示值替换另一通路。pH校准提供当前可选合格结果及其真实检测时间/身份，不用客户端提交的pH数值代替结果查询。

这些是交付所需语义，非新建同名物理字段要求；对应哪个现行读口/聚合DTO及版本来源仍须按第6节落实。不要求所有类型候选带全部BGA/MFC/泵信息，不让M08统计层拥有写资格判断。

### 3.2 输入及展开

沿现有ControlTaskInput的cultureId、taskType、timeRule、plannedAt、parameters、reason、clientRowId；具体可写字段白名单由[控制任务参数契约](控制任务参数与执行交付契约.md)第2节唯一维护，不扩任意JSON。实验室/反应器归属、资源及方案事实由服务端核实，不能接受浏览器伪造来源。预检只读，不冻结未来资格、不占设备；正式创建重新核权限、类型参数及本入口条件。

保存前二次移除的反应器/通路不进入生成集合。通气空流量与pH未选合格结果是原文明确的无生成行，不等同设备失败。取样按所选检测类型展开后，必须保留原选择行与各子任务的映射；不得丢失clientRowId，也不能仅靠培养ID匹配多子任务。子项关联用实际MFC/通路或检测类型稳定标识，不用数组位置或显示名猜测。

### 3.3 返回结果和事务边界

结果需可追溯“原输入行→实际生成单元→任务身份→适用审批身份/状态”，并区分已生成、原文允许的不生成、校验失败、明确写入失败和结果未知，附实际原因。具体映射沿现行响应外壳和错误码，不凭本专题新增一组业务状态；原BatchResultItem能否承载一行多任务须做字段级核对后冻结。

权限、版本、未知类型等结构/资格错误仍按现行契约校验，不能理解为允许静默跳过越权行。原文明确的空流量/未选合格结果不应被补液旧整批阻断语义抹掉。除此之外混合有效行/错误行的本地事务及返回规则，须核现有通用与专属合同后逐类登记，不能自行决定统一部分成功或统一全批失败，也不能让前端自行拆请求掩盖未定事务边界。

管理写复用同模块读口managementRevision、X-Request-Id及现行守卫；预检沿既有只读制式，不因POST新增写守卫。请求重放、载荷一致性和未知结果查询沿适用既有机制；FEEDING/SUGAR的addOnce、intentId、originalCreationRequestId不能未经契约核对套到其他自动生成或人工类型。多选不表示跨设备物理动作全有全无。

## 4. 详情、动作与执行记录复用

沿任务页面契约逐类型状态/按钮子集，不因任务有ERROR就统一给暂停、重试或忽略按钮；DO不加修改，取样异常沿原事件及取消复制专属入口。详情、日志、执行记录须读取实际任务类型、规格来源、审批、参数和命令/派发结果，不要求无泵控制任务填泵号或累计补量。

M07负责任务及审批衔接；M03提供培养及生效方案，M02提供资源/观测和原合法控制方适配，M05提供有效检测事实及既有检测派发采集，M06负责适用审批。不得跨模块直查内部表替代Port契约。原有ControlActionCommand按类型交参数；创建成功、审批通过、命令受理、回读及检测完成分别呈现事实，不能互相代替。

## 9. G07内部契约收口：展开、关联、预览与恢复

本节进一步确定M07专属目标载体，取代第3/6/8节中对应“展开位置/关联字段/预览待定”的早期状态。只细化现有ControlTaskInput、004/005及BatchResult语义，不新增客户规则，不改公共BatchResult字段或其他模块消费者。以下类型名为后续实施目标，尚未写入Java/SDK或接口机器登记。

### 9.1 唯一展开位置

**M07应用服务是唯一任务展开方**。004只读预检和005正式创建使用同一受控规范化/展开逻辑；前端仍提交实际选择和已存在的clientRowId，不预造任务ID、审批ID或generation身份，不调用两次创建去模拟拆分。该选择落实既有“服务端核实参数和来源”“每检测类型一任务”及M07拥有创建事务，属于内部编排设计，不改变用户选择方式。

- 单生成单元类型：一个原行保持一个生成单元。FEEDING/SUGAR原泵行及既有行为不改。
- 通气：沿现有ControlTaskInput中一行一个targetChannelNo及其通路；多通路按多输入行提交，服务端核对应真实通道。非空合法流量行各产生一个单元，空流量行不产生；前端形成参数行是表单组织，不代表前端生成任务。
- 取样：一个反应器原行可含selectedTypes集合，服务端按M04固定类型排序展开为多个单元；每单元按第8.2节投影为单类型七键结构。004只输出预览，005重新核实后展开并落任务，不消费004临时结果当授权。
- 已从页面移除的选择不在提交集合；选项/时间/来源变更后须按实际新载荷校验。恢复原请求不重新展开或读取最新模板来改写原结果。

### 9.2 专属子项关联字段

采用目标`ControlTaskUnitRef`，固定字段为`{clientRowId,cultureId,taskType,channelNo,detectionType}`。clientRowId是原输入行身份；cultureId/taskType必须与原行一致；channelNo仅通气有值，detectionType仅取样有值，其余显式null。通气gas/route仍属于经服务端核实的参数/资源来源，不用显示名代替通道身份。引用只在本次请求及原回执域内定位，不作为跨请求业务去重键，不产生次数限制。

同一原取样行的BGA和VICELL由detectionType区分；不同反应器同号MFC由cultureId及真实设备来源区分。服务端输出完整引用，客户端不得自造子项来改变生成集合。目标规格来源沿ControlTaskSpec.origin.creationRef和实际来源引用，不新增补料creationSource根键或把schema5解码成schema2。

目标结果行`ControlTaskCreationRowResult`固定：

| 字段 | 类型/语义 |
| --- | --- |
| clientRowId | 原输入行身份；每个提交行恰有一条行级结果，不依返回顺序猜关联 |
| units | `ControlTaskUnitResult[]`，完整对应本行实际展开单元，无单元时为空数组 |
| issues | 现行Issue数组；包括该原行不生成的原因或整行错误，不用假任务承载 |

`ControlTaskUnitResult`固定`{unitRef,status,objectId,approvalId,issues}`，后四字段沿现有BatchResultItem语义。APPLIED/PENDING仅表示任务/适用审批提交事实，不是设备完成；REJECTED/UNKNOWN仍按原批量结果定义，不新建任务状态。多子任务不共享一个objectId/approvalId，未产生的ID为null，不生成占位任务。

新类型使用M07创建专属结果投影，公共`BatchResult<T>`的batchRequestId/items及原FEEDING/SUGAR返回保持不变。创建专属回执须保存实际返回模型并可原样恢复，不能将新行结果强行反序列化成旧BatchResultItem。类型分派沿输入taskType及已有专属模型；混合输入的绑定/响应联合类型须在共享004/005登记时显式列出，不能无提示丢行或自行新增“只能同类型一批”的业务限制。

### 9.3 类型化预览

目标`ControlTaskPrecheckRow`为`{clientRowId,errors,warnings,units,issues}`，units为目标`ControlTaskUnitPreview[]`；外层TaskPrecheckResult形式沿原items。原补液PrecheckItem/TaskPreview保持原样，新类型不向targetGrams填pH/温度/流量。

`ControlTaskUnitPreview`固定`{unitRef,timeRule,plannedAt,parameters,evidenceRefs}`：parameters是控制任务参数契约第2节类型化参数投影，不另造无约束Map；evidenceRefs是实际服务端已取得的来源引用。plannedAt只表示本次预检快照，立即时间由正式创建服务端确定，不能把预检时刻当作执行证据。对于pH校准，读取的配对与目标预览沿已有phPair结构，由服务端事实提供；不得从预览反传targetPh取得下发资格。缺必需来源按原预检错误给出，不补0。

各类型预览的具体叶子沿既有字段树：pH校准的结果/目标模式及合法配对投影；pH调整目标及死区；搅拌rpm；温度℃；通气具体通道和L/min；取样单检测类型七键参数。单位、精度及白名单不在本节重复修改。预览不生成任务/审批/设备命令，不占用资源；正式创建仍重验。

### 9.4 无生成行与失败映射

| 实际情况 | 结果及处理 |
| --- | --- |
| 通气空流量、校准未选合格结果的原文允许不生成行 | 行结果units=[]，issues说明实际不生成原因；不伪造objectId/approvalId，不作为设备错误，也不以此阻断其他原文允许生成行 |
| 页面删除选择 | 不属于提交行；不输出虚构取消任务；恢复时不得擅自从原载荷删去 |
| 非法字段/精度、权限/版本或对象资格错误 | 沿既有错误外壳及对应行定位；不归类为“允许不生成”以绕过校验 |
| 实际生成集合准备/保存/本地审批关联失败 | 依现行人工创建的本地同批提交规则回滚，不留部分任务/候选/审批关联；不伪造各行APPLIED。明确拒绝与提交结果未知分别报告 |
| 所有行均为原文允许的不生成项 | 返回行级原因及空生成集合，不创建任务、审批或原调度项；不能调用取首个任务ID的既有领域事件逻辑 |
| HTTP超时或提交结果未知 | 保留原请求身份、载荷和关联，以原回执核对；不换键、不重新展开后自动补任务 |

事务解释依据任务页面契约“任何行失败整组不留部分任务”和JSON契约人工创建同库事务；这是原创建边界的落实，不是跨设备物理全有全无。适用顺序为：识别原文允许的不生成项→完整校验实际生成集合→按原本地事务提交。旧补液规则不因此被改成部分成功；新类型也不因有不生成项而跳过其他错误校验。混合输入沿相同已适用的本地提交边界登记，不额外设置批量上限或统一业务资格。

### 9.5 恢复复用和准确的存储余项

本期人工004/005扩展复用同一路由的原创建/恢复分支：正常回执窗口内沿原requestId、版本及完整原载荷重放；带originalCreationRequestId的过期核对沿原只读恢复资格、原创建者、原全集权限、载荷hash、404/409/503优先级。不得由浏览器提交intentId或子任务ID选择恢复子集。自动规则/灌注内部生成不经过本人工恢复分支，不外推addOnce为所有生成任务的统一业务门槛。

新类型创建的不可变回执需覆盖**原规范化输入及其全部行、展开单元、无生成行原因、每任务与审批身份、原返回结果**。比较原业务载荷，不用当前重新展开的集合判相同；恢复返回原结果，不把当前任务状态替换原提交状态。schema5的origin.creationRef指向实际创建事实，与任务/候选一致。

现有`M07_MANUAL_TASK_CREATED`事件结构以培养首个任务作为object_id，原恢复服务校验旧taskIds/creationSource。它不能直接覆盖“某培养只有不生成行”或“整批零任务”，也不能未分版本读取schema5。**本轮不擅自扩展该已固定事件JSON或新增平行表/事件**；实施前必须在共享JSON/事务契约明确新类型回执的持久承载、版本判别、零任务响应保留及读取校验，并同步机器登记/恢复消费者。正常管理回执可以保留零任务响应；过期且没有领域回执时按原404核对语义处理，不能据此证明从未提交，更不能自动补任务。

因此恢复语义与所需保存内容已明确，存储绑定仍是精确内部设计接线余项，不是缺客户业务决定，也不能报告为恢复已实现。
