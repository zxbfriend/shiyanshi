## 2. 运行边界

`futurefab-feeding-customer-adapter` 通过现 `GatewayInstallation` 安装，只有固定 OPC 查询与单泵设值路径。与 gateway/API 同坐标独立聚合，不继承业务 bootstrap，不读取业务数据库。缺部署配置立即拒绝，无默认适配器/模拟器。

- 只读：端点、来源版、反应器、实际点、原 Registration 和超时必须显式；URL 按原反应器值编码。HTTP 单次调用、不跟随重定向，1 MiB 响应上限，超时覆盖整个响应体。查询原响应先归档，再解析。
- 查询成功须同时 ResultCode200、IsSuccess=true、原 devId 匹配且原实际字段存在。900/true/Data0、200/false 等不能成为样本；不得用 pumpNset 代替 pumpN。全部原行和原时间文本保留，不自行选择“最新”或推断毫秒时间戳的资格。
- 原包没有合格质量、源序列和完整时间解释，故共享 Observation 返回 UNKNOWN、无合格 readings，并引用原字节归档。wrapper 时间是接收侧观察时间，不能替代设备发生时间。候选值只用于调试核对，不进入认可量或运行反馈判断。
- 正常 START/SET_SPEED 与原命令查询保持 BLOCKED_EXTERNAL/UNKNOWN。不会把 g/min 当 rpm，不采用旧常数换算，不把 HTTP 成功或 Code200 映射成 EXECUTED/实际首次开始。

发布包提供独立的离线配置预检入口 `CustomerOpcConfigurationCheckMain`。调用方必须显式声明 `READ_ONLY` 或 `PROTECTIVE_STOP`：前者允许 STOP 能力继续显示 `BLOCKED_EXTERNAL`，后者缺完整 STOP 批准包即非零失败。预检只加载配置、Registration 与批准原件并计算映射摘要，不打开客户端点，不输出端点、反应器、凭据或批准内容。其 `CONFIGURED_REQUIRES_RUNTIME_VALIDITY` 结果仍须在实际登记时核批准有效期，只属于软件配置检查，不能升级为接口、设备、健康或现场证据。

## 3. STOP 的受控批准

仅有“写入接口存在”不构成安全停止能力。独立停止安装批准必须同时冻结：

1. 完整原登记摘要及物理映射摘要，含来源版、端点、反应器、实际/设定点及调用超时；
2. 显式停止 rpm 设值、适用模式来源；
3. 独立读停通路能力来源；
4. 真实入口按原 identity/fence 仲裁、旧写/排队屏障能力来源；
5. 人工/备用写入口隔离能力来源；
6. 真实停止反馈语义及其批准来源、版本、有效区间。

这些内容来自受控部署文件；不得从请求体自报生成，也不能把本批配置测试当作物理能力实测。缺任一项即拒绝安全 STOP 写能力和新登记；没有示例批准文件或默认零值。本批只提供已核准配置的校验和协议转换，实际资料尚不满足现场投用。

外部请求交给 gateway 先锁定普通写，再由 Driver 向唯一核准点发单泵设值。停止源请求摘要归档，不生成新的 M07 命令 ID。普通 STOP 命令即使客户返回200也保留 UNKNOWN，因为没有原命令发生回执；独立 StopRequest 的 Code200 最多表示 ACCEPTED。其它码、矛盾字段、超时和异常均不能证明未执行或已停。正式 H02—H06 仍分别取得原设备/量/观察/资源证据。

已登记必要 STOP 不依赖业务数据库或通知。原归档写盘失败不能阻挡已核准停止请求，但不能形成可靠 ACK/完整证据；gateway 的原停止锁定/期限保持。新登记有效期与必要保护分开，后续新原因/重试不改变原期限。M07 解除 authority 尚待真实交接来源接线，当前安装器不授权释放。

## 4. 原始证据与 M07 接入

归档保存 HTTP 方法/地址、来源版、完整登记摘要、原请求摘要、请求体、响应码、原响应字节 Base64 和接收时间；文件以完整规范归档 SHA-256 命名并 force(true)。这不是新命令状态机或量账。不同来源不能用只含数值的摘要替代完整原包。

RUN-OBS-I01 是唯一执行样本入口。其 raw_readings v2 还要求原 commandId、阶段、实际 activeMilliseconds、labId、sourceInstanceId/BootId/EventId/Sequence、原时间文本/时区/精度、sourceRevision、设备/metric 对应关系和 normalization。当前客户文档、候选读数与本地监控日志不能自行补齐这些事实；缺实证时只保留原件，阻断样本资格转换。

observation_coverage 必须绑定原执行/段/fence/profile、可信覆盖起止、完整原 STOP 与原样本集合的摘要、缺口和持久连续性。日志健康或 HTTP 可达不能直接生成 COMPLETE；重启、丢包、时间不明、样本未入 M07 或未决命令未闭合都不得冒充完整观察。

## 5. 验证边界

已执行的测试分为严格响应解析、显式配置/批准改绑、本机 HTTP 请求/字节归档/超时/超大响应、离线预检真实 Java 子进程，以及独立模块编译/依赖检查。子进程用例覆盖只读通过、请求 STOP 但缺批准非零失败、完整 STOP 配置仅报告待运行时有效性，以及缺配置非零失败；并断言输出不包含测试端点和反应器。测试来源标 TEST，只存在 test 范围。
