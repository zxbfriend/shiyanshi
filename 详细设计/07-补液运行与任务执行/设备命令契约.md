## 1. 身份、版本与四层事实

ID、版本和fence均为十进制字符串；命令ID由M07预分配，不接受页面任意指定。小数为十进制字符串，时间为UTC毫秒ISO8601。未知属性拒绝。可信调用者必须是设备固定归属执行器；网关实际写入前校验归属、fence和配置版本，不能仅靠数据库CAS阻止旧执行器。

命令状态：PREPARED、INVOKING、ACCEPTED、EXECUTED、FAILED、UNKNOWN。INVOKING是网络调用前持久化的阶段，不是受理回执；ACCEPTED才表示设备网关已受理。查询态：NOT_SENT、ACCEPTED、RUNNING、STOPPED、FAILED、UNKNOWN、NOT_FOUND。NOT_FOUND仅为查无网关记录，不能证明从未物理执行。业务状态、命令状态、设备查询事实、结算状态分别保存。

M02-227改变控制器型号前须排除该连接的未决物理命令。按commandId的 `queryCommand` 不能回答“此连接有无UNKNOWN命令”；M07须提供按固定 `parameters.deviceRef={deviceKind:BENCH_CONTROLLER,deviceId:connectionId}` 的只读完整性判定，PREPARED/INVOKING/ACCEPTED/UNKNOWN均视为未终结。`run_command.resource_key` 是执行域资源，不得直接假定等于DeviceRef；精确身份投影、索引和历史覆盖证明应在提供方落码批同批完成。覆盖不完整或查询异常一律503，不返回安全空集。该DeviceRef的共享守卫键固定为 `BENCH_CONTROLLER:<connectionId>`，与命令行的主resource_key不是同一字段语义；新命令进入及M03新占用须先通过M07窄口锁同一 `run_resource_guard` 行，再写业务事实。守卫行首建、归属核验和多键字典序由M07封装，判定与新命令进入遵守M02[逐接口契约](../02-实验室与资源管理/工程资料维护与解析逐接口契约.md) §4.1。本段只冻结事实与共锁语义，不代表M07已实现该读口。

profile.stability的sampleCount/minSeconds/toleranceGrams、profile.stop的speedTolerance/speedUnit/minSeconds/sampleCount/postMonitorSeconds来自核准资料。无核准值保留null并阻断确认，不采用历史0.001、5秒、5条作为默认。

稳定参数逐项核准如下，与[统一方案F.3.1](../../接口文档/SMP小试二期与中试补料调度统一方案.md#f31-稳定判断参数明细及联合判定)一一对应：

| 参数 | 单位与判定 | 历史参考及证据边界 | 现场值 |
| --- | --- | --- | --- |
| `stability.toleranceGrams` | g；整个规定观察范围的最大值−最小值≤容差，等号通过数值条件 | 中试参考文档§17用地秤精度作阈值；§6.3的scale_precision=0.1仅为历史配置。未核准不自动令容差等于精度。 | 待确认/待核准，无默认 |
| `stability.sampleCount` | 条；有效去重样本数≥本值，停止确认同时满足stop.sampleCount，取较大要求 | §17取最近5条执行明细；尚未证明该数量可配置或能提供完整连续覆盖。 | 待确认/待核准，无默认 |
| `stability.minSeconds` | s；最后与最早实际采样时刻之差≥本值，停止确认同时满足stop.minSeconds，取较大要求 | §17的至少5秒是实际泵速低于阈值后的等待时间，不直接证明最近5条自身的跨度；不据此赋值5秒。 | 待确认/待核准，无默认 |

三项须同时满足，并核对同源、同配置/物料会话/单位/方向、有效质量/时间和完整覆盖；相邻差小、首尾相同、重复缓存或局部平稳均不足。不得忽略规定观察范围内的不利读数，不能用样本数乘轮询周期代替实际时间跨度。历史依据是[中试参考文档§17](../../接口文档/中试补液/补料调度程序逻辑.md#17-终止与完成逻辑)，文档已说明不等于原程序可配置性或现场参数已验证；小试ScalePrecision字段存在也不证明中试同源。历史Scale_Monitor_Time=120秒属于结束后续监，不替代本表或自动映射stop.postMonitorSeconds。称重稳定不代替真实停泵、计量、命令闭合和释放要求，也不代替抖动固定起点/J恢复判据。

`postMonitorSeconds`是停止确认/收尾所需的核准最低观察要求，不代替策略的抖动观察时长`intervalSeconds×jitter.observeFactor`；`postMonitorUntil`必须由已核准的真实覆盖证据支持，不能仅用当前时间或设定时长计算一个未来“已完成”结束点。抖动的观察时钟只从原实际`stoppedAt`开始。固定原起点/J下任一合格周期达到恢复判据，即判本次抖动已恢复；实际停料、最低安全观察、完整计量及其他门禁均满足时由调度立即续补，不额外等满策略抖动观察期。持续异常结论仍须有未恢复且覆盖到应判截止点的全部必需周期证据。

准入时应核对本设备的采样/存储/覆盖提供能力能支持这些时域要求。若已有覆盖结束点早于本次最低安全观察或最新恢复复核所需时点，只能按核准路径补采、补齐可追溯的覆盖证据；保留原停止和观察原件，不伪延长`postMonitorUntil`，不改变`stoppedAt`及首次停止确认期限。无法补齐时保持未完成/禁止恢复，不能凭孤立的后来缓存、GOOD或健康响应填补缺口。合法续段使用新段窗口，不以旧J判正常补料下降为反弹；尚未续段时保留保护并最终实时重验，详见[状态交接§5.1](任务状态调度与异常恢复.md#51-抖动停止观察与续段交接2026-10-21)。

STOP命令受理不等于STOP执行；已停止也不等于可释放所有资源。停止确认、稳定最终量、唯一结算、全部原命令闭合及所需停止后监控均满足后，按guard当前fence及H06释放；任务ERROR可保留待人工处理，不把ERROR_HANDLED当设备释放的必要前置。M03培养占用释放还需其独立屏障证明。PAUSED保留任务关系和按能力需要的资源，恢复新segment只补剩余量。

## 5. 原子性、错误和恢复

### 2026-10-13 暂停 STOP 接线约束

M07-008 的业务意图事务与物理派发分开。固定第四用途 `M07_COMMAND_INVOCATION` 仅由 `M07CommandInvocationWorker` 持有，按完整冻结 resourceClaims 的 ASCII 全序重验全部 assignment/guard 与命令摘要，CAS `PREPARED → INVOKING` 并持久化完整调用声明事件后提交。`M07TaskPauseDispatcher` 再在事务外调用 M02，真实回执由既有回执消费者在新事务核验并落库。

固定本机执行器来自必配 `m07.command-dispatch.executor-id`，不得从目标 assignment 行读出身份就自称该执行器。M02 CMD-I01/I02 仍须有生产提供方及真实传输认证。缺依赖在 HTTP 业务写前 503；不写假 PREPARED 充当可派发。HTTP 原意图重放可继续拾取 PREPARED，但 INVOKING/ACCEPTED/UNKNOWN/终态均不会再次 submit。`M07PreparedStopDispatchTask` 保留既有 Bean 名称，按持久 commandId 有界轮转恢复已提交 PREPARED 的普通任务 STOP/SET_SPEED（execution_id 非空、step_instance_id 为空），包含暂停恢复的原 SET_SPEED；单批上限 500，不扫描 UNKNOWN 或创建新命令；游标只影响公平性，不承担幂等。

恢复事务提交后，若同步派发因原上下文 ACK、续段双 ACK 或激活暂不可得而返回 503，命令保持原 PREPARED、原 commandId/requestId/payloadHash；既有扫描下轮仍调用 `M07TaskPauseDispatcher.dispatchPrepared`，重走 `M07ContinuationRegistrationGate.ensureActivated` 和原最终调用门禁。仅原 `PREPARED→INVOKING` CAS 胜者且 attempt_count=0 可首次物理调用；扫描不补 START、不把未知结果当未调用，也不绕过停止保护。扫描由 `futurefab.resource-transaction.enabled=true` 条件装配，调度配置沿用 `m07.command-recovery.worker.cron` 和 `.batch`。当前代码的既有 cron 缺省为每五分钟，不能据此声称满足设备保护或恢复响应时限；部署/隔离验证须显式配置并核对周期，现场未核准值仍待确认。独立监控及原停止期限不随重试重置。

`DeviceCommandReceipt.evidencePayload` 承载 §3 的完整 CommandEvidence JSON，不允许从几个最小叶子拼造读数或适配器身份。`evidence.payloadHash` 是去自身 payloadHash 字段后证据规范 JSON 的 SHA-256；与 `run_command.payload_hash` 的完整命令意图摘要独立核验，不比较两种摘要相等。空、异身份、异配置、非法时刻或摘要不符的回执不能推进成功，已尝试调用只能记 UNKNOWN、保留占用并按原命令核对。

到期的 ACCEPTED/UNKNOWN 由 `M07CommandQueryRecoveryWorkerTask` 有界扫描，`M07CommandQueryRecoveryExecutor` 从原命令不可变 `parameters.deviceRef`、commandId、deviceCommandId、fence 和 configurationRevision 组装 CMD-I02；查询在事务外，可信回执在新的受控资源事务内按版本应用。NOT_FOUND 只能保持 UNKNOWN 并安排下次核对；查询失败保留原态，二者都不得调用 submitCommand。该源码链仍依赖 M02 提供真实 `DeviceCommandPort` Bean 与固定执行器传输认证，未部署时属于 BLOCKED_EXTERNAL/BLOCKED_DEPLOY。

此链只完成暂停请求和命令生命周期，不等于最终安全暂停。完整核准 MeasurementPolicy、实际零速、稳定读数与停止后监控的消费者尚需落实；仅 STOP EXECUTED 不更新任务/执行为 PAUSED，不关闭超时计时，不释放资源。旧回执事件格式未由本批批量重写，现场/数据库/HTTP/浏览器验收另列。

1. 同事务持久化全资源claim、execution/segment和PREPARED命令。
2. 短事务将命令置INVOKING并提交；随后调用物理适配器，网络等待不持SYSTEM锁。
3. 回执在新事务核对身份／版本／hash，保存结果及事件。失败、超时或进程崩溃不能由页面重新生成任务补发。
4. 重启先隔离旧控制通路、列旧命令和资源，查询同commandId；UNKNOWN/NOT_FOUND保留占用。仅核准幂等绝对速度／STOP操作可按原键重传，一次性开始／体积脉冲未知时禁止重发。
5. SET_SPEED设定回读不是实际转速证明。CALIBRATION_INVALID停止并保留原因；业务准入错误见[错误码全集](错误码全集.md)，NCS监控是运行事实而非统一HTTP错误。

**持久状态和重试约束：**仅当前 START 为 PREPARED、attempt_count=0、invoked_at/resolved_at/result_evidence 为空、原执行 NOT_STARTED/NONE、全历史无首次开始事实、当前原段无运行/停止/计量事实且没有其他命令、分段或量账冲突时，才允许冻结撤回。两端持久撤回成功后，H06 在原 SYSTEM 事务内按业务→归属→完整资源→原命令锁序再验；任一 CAS/审计写失败，资源、段、task 和释放事件整笔回滚，外部墓碑保持保护并用同请求重放。

H06 将原准备段置 CLOSED，但 active_milliseconds 仍为已知零，stopped_at/end_readings/observation_coverage/raw_difference_grams/normalized_grams 均为空；原执行保持 NOT_STARTED/NONE。task 置 READY、current_execution_id 置空、reason 保留 DEVICE_STOP_CAPABILITY_UNVERIFIED，admitted 不改，object_version 递增。原 START 不改写 EXECUTED/FAILED/NOT_SENT，其退役由 `M07_START_NOT_SENT_WITHDRAWN` 和对应原 H06、双端最终释放 ACK 证明。

任务准备、首次日期门禁、实际 START Authority 与后续最终收尾都须识别这份完整退役证明。新 attempt_no 按原连续历史递增，核准必须绑定当前任务版本；不能借旧审批、旧登记 ACK 或旧基线启动。旧 CLOSED 空段只有原撤回证明完整时可作为未运行历史，不进入 FEED/SETTLE，也不能妨碍新尝试按自身真实停止、计量和完整观察释放。未证明退役的 PREPARED、任意 UNKNOWN、已有运行或计量事实继续阻断。

新原件、释放/outbox 的精确版本及字段见[数据库JSON与事务契约的启动前撤回协议](数据库JSON与事务契约.md#2026-10-24启动前未调用撤回与not_sent释放原件)，签名端点、持久墓碑和先后顺序见[独立补料监控契约第19节](独立补料监控进程与保护通道契约.md#19-启动前能力拒绝的持久撤回协议)。

### 2026-10-26 cloud工作流整组释放兼容

工作流后台释放复用原H06完整停止资格。辅助秤、控制器和泵各自的fence须来自同一原工作流执行冻结资源清单，原STOP只为该执行的实际停料作证；不能要求辅助资源fence机械等于泵fence，也不能借此跳过业务/全部步骤闭合、原命令、逐段完整覆盖及唯一PRIME计量核验。后台先锁原业务/执行，再固定完整资源清单及校验当前完整占用，后锁命令和量账，逐资源重验后原版本CAS释放；任一失败同事务回滚。任务执行仍使用原任务专用完整资源/命令摘要门禁，未改人工异常处理与安全释放分离的业务规则。

工作流收尾读取原段持久`observation_coverage`并交给共享停止组装件，不从样本条数、HTTP成功或零设定推断覆盖。只有v1采样而无受控覆盖生产者的路径仍未闭环，应列为软件缺口，不伪造COMPLETE或替换原任务v2资格。


2026-10-26 工作流v1停止覆盖生产链增补：M02核准观测角色/时间策略→完整规格冻结→正式DeviceReadingsPort→事务外真实读取→原业务/执行锁内持久样本→原STOP及完整原件覆盖CAS/LOCAL审计→共享停止组装→同事务PRIME与物料结算→H06释放资格。精确结构集中见[JSON契约](数据库JSON与事务契约.md#2026-10-26-工作流-v1-受控停止覆盖)。原段无覆盖、未知/冲突、缺口、迟到或坏质量均保持保护；不因新增生产者解除业务/步骤闭合、设备故障锁、原命令或完整资源校验。覆盖本身不代表实际停止，也不直接释放资源。


本次受控覆盖自动结算接入W07更换补料液的预填充。W07新PRIME_START在占用资源及登记执行前，必须取得核准 observationPolicy；缺少时明确 RESOURCE_FACTS_UNAVAILABLE，不允许以旧六字段profile启动该新链。历史执行的必要STOP仍按原身份处理。观测角色须与完整规格中的泵、秤、单位和M02配置版本对应，误配不得冻结为合法执行。PRIME_STOP在原守卫事务对当前OPEN段、原执行版本、worker及fence做STOPPING CAS，与原命令意图同事务；该状态仅表示停止请求，不等于实际停料。最终结算保留已经存在的停止原因，不把取消或异常覆盖成NORMAL。任务v2的首次开始、停止意图/期限、独立监控及H06条件保持原契约。
