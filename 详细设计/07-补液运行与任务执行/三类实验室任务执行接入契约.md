# M07 三类实验室任务执行接入契约

版本：INTEGRATION-20261010。与[共同边界](../00-总纲与约定/00-三类实验室设备接入与执行边界.md)、[设备命令契约](设备命令契约.md)、[泵速执行与设备恢复契约](泵速执行与设备恢复契约.md)共同使用。本文补充执行路径，不新增任务状态枚举或宣称现有骨架已实现。

## 1. 一期保留路径

一期原表结构全部保持一致，原GUI/Core继续承担已核准动作的执行和写入责任。新SMP先建立来源映射、任务/结果只读投影与对账；需要从新入口触发时，必须先逐动作明确唯一审批链、旧服务入口、幂等关联、回调与唯一写入方。未核准的动作不开放新入口。

| 旧链路 | 接入规则 |
| --- | --- |
| TaskQueue、Batch_OP及明细承载自动任务 | 保留旧任务身份与语义，不额外生成一套新调度去拾取同一动作；自动FEEDING实际拾取入口仍需现场核实 |
| ManualOPRec → Core start_pumping → 实际重量/结果回调 | 以来源实例和ManualOPRecID贯穿，不将HTTP受理显示为实际完成 |
| Core PumpIn/PumpOut更新CDP_Item_Serials.Quantity | 新系统不重复加减同一实际量；网页初始化等其他写入动作须独立登记责任 |

2026-10-11附录2复核（[GUI与Core分工](../../接口文档/GUICoreService.html)、[TaskQueue](../../接口文档/TaskQueue-自动取测与自动补料.html)、[一期手动补料](../../接口文档/手动补料Lab3021.html)、[一二期联动](../../接口文档/小试工作流/feeding-sampling-lab-linkage.html)）：

- 一期自动补料由网站写`CDP_Batch_OP`（OPID=2 FEEDING，Mode=3，Status=1）＋Sub（POSITION1—3）＋ParameterValue（计划时间、体积、速度）＋`CDP_TaskQueue`；Core执行后回调`POST api/pumping/auto-pumping-result`写`CDP_Batch_OP_Exec.ActualValue`。回调入口已证实，**Core拾取OPID=2的扫描条件与状态推进仍未见文档**（资料只详述OPID=1由TestOpsManager拾取），拾取入口保持BLOCKED_INPUT。
- 一期手动补料：网站先插`CDP_ManualOP_Rec`（OperationType 11/13/15/17=FM1/FM2/糖/FM3），以ManualOPRecID作`sourceid`调Core`start_pumping`；过程回调`get-pumped-weight`，结束回调`get-pumping-result`；Core以PumpIn/PumpOut直接改`CDP_Item_Serials.Quantity`，网站回调不改Quantity。据此一期补料期间重量/余量唯一写入方为Core（对应M07-EXT02一期部分）。
- 手动补料有4类，自动补料仅3个泵位，W04“第4泵”是否允许自动执行仍需确认（M07-W04-PUMP4）。

一次同步丢失或回调重复不能促使重做物理补料；按原身份补读与对账。原服务仍运行时，旧量只能作为兼容投影，不能同时安装M07接管基线并再次累计。只读映射/回执保存在新系统独立承载中，其物理字段另行冻结，不在旧表加控制列。

## 2. 二期、中试路径

目标为新M07统一业务生成、审批生效、调度、运行分段、异常恢复和计量账，M02复用经核准的协议服务。需要过渡时，按资源组保留一个旧执行方；同一任务不得同时进入旧表扫描器和新执行器。

二期已知旧路径是FixedFeedingTask等任务表及`StartFeeding`调用`/start-feeding`，但实际服务端实现仍待核实。中试已知版本由NPPScheduler/CoreService扫描任务，`/start-feeding`为空入口。两者名称相同不能据此复用启动判定。中试固定计划展开触发点仍待核实，不把新系统的生成时机写成旧系统事实。

2026-10-11附录2复核：

- 二期：自动补料在“补料任务队列”写`CDP_Batch_FixedFeedingTask`（Mode=1；SoureType 1协议/3人工/5子系统），手动补料同表Mode=3；执行时绑定地秤`DeviceStatus=2`、`CDP_Batch.IsFeeding=true`。网站`start-pumpingV2`经`PumpingService.StartFeeding`走OPC/IoT，不经Core。**到点拾取Mode=1任务的执行方未在资料中出现**。中试NPPScheduler扫描的正是同名表`CDP_Batch_FixedFeedingTask`且状态码（3/5/7/9/11/17/19/99）一致，推测二期可能由同类调度器执行，须客户确认后才可沿用中试证据，确认前维持BLOCKED_INPUT。
- 中试：[NPPScheduler](../../接口文档/中试补液/补料调度程序逻辑.md)每`coreservice_interval_time`=10s轮询`CDP_Batch`与待执行任务，准入、真实补料量、二/三段速度、闭环监控、停泵与结算均已成文；`POST /start-feeding`反编译确为空`BaseResponse`，INT-AC05前提已证实。自动补糖由调度器按当日Cedex结果计算后调用GUI`api/pumping/create-task`建任务。固定补料任务由用户在培养编辑页按PUMP1—8逐条录入或从培养协议模板复制（[批次培养详情](../../接口文档/中试补液/批次培养详情.md)§9.2/§10，前端证据）；后端是否另有展开逻辑未见，仍待确认。
- 旧调度直接拼接SQL访问MySQL、以WinForms承载、单实例Mutex；只作行为参照，不作新执行器结构依据。

新路径按现行任务生成规则，将M03生效培养方案及M04固定模板/策略版本展开为补料任务；补糖使用M05合格结果和M07已确认计算生成候选，按M06政策办理生效。每个计划发生项、候选版本、手工操作请求具备稳定来源身份，重复调度不重复生成。具体去重字段和已发布状态遵循现行任务契约，缺少物理承载须先补齐，不借代际适配另造状态机。

## 3. 统一执行与回执顺序

```text
方案/有效检测结果 → 候选与审批生效 → M07执行前校验
  → 固定设备组、参数和版本，持久化执行段与run_command
  → 提交本地事务 → M02 CMD-I01 → 已核准协议入口 → 设备
  → M02 CMD-I02/可信回执 → M07事件、状态、实际量与结算
```

执行前核对培养生命周期与占用、物料会话、目标量/单位、结果和方案版本、全部共享资源、有效配置/能力及当前执行权。固定资源组唯一执行器，不能仅以业务实例租约或任务锁证明物理独占。

M07分配commandId/requestId/fence，拥有唯一业务命令和计量账；M02转换协议、验证入口并返回证据。网络调用不置于跨模块数据库长事务中。受理、正在运行、已停止、已结算分别判断；命令返回成功不能直接关闭任务或释放资源。

## 4. 异常、恢复与实际量

| 场景 | 处理 |
| --- | --- |
| 下发前明确未发送 | 按原意图和现行恢复规则办理；不能借重试改参数 |
| 超时、断连、回执丢失、发送后本地写入失败 | 标为未知事实，保留资源；先查询原命令，不新建身份重发定量动作 |
| 检测失败、缺项、结果失效 | 阻断依赖该结果的计算/后续启动；运行段仍按已固定规格及现行安全规则处理 |
| 停泵指令已受理、零速但无停止反馈、重量不稳 | 保持停止核验/异常处置，不以0结算未知实际量，不宣告完成 |
| 暂停、重启、人工恢复 | 核对原命令和已发生量；恢复若获准仅生成对应剩余量的新段，保留原段证据，不重新全量执行 |
| 通知或展示同步失败 | 重试通知/投影，不能回滚物理事实或重复投料 |

现场必须具有核准的失联保护与停止方式；断网重连不自动恢复旧速度。人工处置也须记录权限、原因、证据及原命令关联，不通过修改数据库状态跳过物理对账。

## 5. 切换、验收与当前缺口

严格按[共同边界](../00-总纲与约定/00-三类实验室设备接入与执行边界.md)§6按资源组切换：阻止旧派发、处理未决动作和量、隔离旧控制入口，再启用新控制方。回退对称执行，不以数据库恢复抹除已投料事实；影子验证仅计算和比较，不连接第二个可写控制通道。

附录2记录的旧系统缺陷不得复刻进新实现或兼容映射：Core冲洗预填充误回调`get-disinfect-result`；终止任务前端传TaskQueueID而Core按BatchOPID匹配；中试补糖规则`<`与`≤`边界判定与符号相反（M04规则校验以现行契约为准）；培养编辑“+1”复制第6泵误用`n26++`；`GET /version`回显数据库服务器与库名；奥豪斯秤解析不校验稳定位。

交付一期动作/写入责任矩阵、二期/中试每条执行路径版本证据、任务到命令到实际量的追踪记录及共同矩阵INT-AC03—08/10—15。Core自动补料、二期服务端、中试计划展开、物理回执/停止能力等缺失项保持阻塞；一期桥接和新旧关联的物理接口/持久化未冻结前不得编码该路径。现有端口、任务骨架及模拟用例不能替代这些交付。
