# W07 当前补液页面接口接入

基线为 `b4318c84838969376e4c8cdac8eb156c2ef58f41`。本记录描述当前张新主 `replenishment.vue` 的实际接线；2026-10-23 的旧 Connection 页面记录保留为历史，不作为当前入口说明。

## 当前调用链

`feeding-workflow/index.vue → replenishment.vue → feeding-refill.ts → connection.ts → runWorkflowApi → RunWorkflowController → RunWorkflowApplicationApplicationServiceImpl`。

| 页面动作 | 接口 | 处理方式 |
| --- | --- | --- |
| 选择液瓶 | `GET /run/workflows/candidates`＋既有 M02 布局查询 | 精确匹配候选 feedingSlots 与 bottleId，沿用管理版本一致性检查，不凭 editable 代替 W07 资格 |
| 开始 | `POST /run/workflows`，subflowCode=`liquid_supply_feed_unit_small` | 每瓶一个实例；发送前持久化原请求，核对完整瓶集与培养集，保留 APPLIED/REJECTED/UNKNOWN/PENDING |
| 刷新及恢复 | `GET /run/workflows/{id}` | 保存每个已返回实例；详情失败不能重新启动。只读刷新不会重试写入 |
| 保存新瓶重量 | `POST /run/workflows/{id}/steps/{stepInstanceId}` | 使用冻结资源键、容量、步骤版本和管理版本；依次确认开始及换瓶步骤，不修改本地模拟余额 |
| 开始/停止预填充 | `POST /run/workflows/{id}/operations` | 仅消费真实 pumpRefs/allowedOperations；PRIME_START 使用 1–100 整数克及真实速度选择，STOP 不依赖可编辑参数 |
| 完成/跳过 | 步骤接口 COMPLETE/SKIP | 跳过只允许未开始的预填充并保留原因。未决命令、安全停止及资源释放检查继续由服务端执行 |
| 移除/取消 | `POST /run/workflows/{id}/cancel` | 移除对应瓶实例；整页取消逐个处理，只有服务端安全终态才清理本地恢复标识 |

接口方法以 SDK 当前代码为准。管理写均沿用原有 requestId、managementRevision 和对象/步骤版本，未自建另一套写协议。

## 保持的页面与状态约束

保留现有选择、原桶/新桶、复制、移除确认、预填充、取消和结果区域；CSS 与布局容器未改变。新增现有风格的状态提示和“刷新/核对原请求”入口，已发送或未知请求锁定输入；部分已确认的液瓶逐行锁定，其他未确认瓶保留用户输入。

已知实例及原请求按原用户和实验室保存。配置变化不隐藏已有批次的恢复入口；跨实验室迟到响应不会修改当前页面。结果未知时只允许原请求核对；不会清空原键后重新提交，也不会回退 Demo。

页面区分业务确认和设备执行。操作接口受理不生成实际运行状态、实际投料量或启动/停止时间；工作流完成由后端安全事实校验，不能当作设备现场验收。无回执字段时显示缺省，不生成客户端时间作为事实。

历史 W07 操作人快照曾采用 ActorContext 字段，详情采用 Person 字段，导致真实人员显示缺失。当前读取兼容历史字段，新写入只保存 userId、displayName、kind；不暴露或继续存储会话字段。
