## 1. 输入、范围及存储边界

沿已有目标ControlTaskInput：cultureId、taskType、timeRule、plannedAt、parameters、reason、clientRowId；ID/版本字符串、decimal精确十进制字符串、时间ISO offset，业务日上海。timeRule沿立即/定时既有值；立即由服务端保存当下计划时刻，定时取用户时刻；pH校准只立即。禁止以0克、虚假泵号或伪补液方案通过旧TaskInput校验。

五类人工控制任务不检查培养已选工作流、灌注/开始/自动控制完成，不以“进行中”筛选变相排除开始前合法培养；仍需真实培养、实验室/成员范围、当前设备、专属结果和原适用审批。DO无人工入口。培养内SAMPLING仍须完成开始培养，但不要求先启动自动控制；LoadSample为独立无培养来源，见[交接专题](LoadSample运行交付契约.md)。

ControlTaskSpec是既有目标名，其schema5只用于本类型参数与来源，原补液schema不改。保存采用既有task_spec JSON，以taskType选本节白名单，不接受任意对象。服务端固定原输入行、实际任务/审批及来源引用；不能将客户端提交的来源、实验室、设备版本作为权威。已有run_task.task_type仅16字符和旧限定值、plan_snapshot_id必填及旧补液解码器尚不能直接承接全部新类型；逐类型存储适配局部留Q-2-02，不能用伪方案或伪cultureId接线。

## 2. 类型参数白名单

| 类型 | parameters允许内容 | 创建及执行复核 |
| --- | --- | --- |
| PH_CALIBRATION | 原BGA resultId及精确版本/指标引用；目标动作由原四档规则及合法入口决定，不接客户端伪pH | 本培养、当前反应器当天未作废且有pH的合法结果；选中才生成。按检测时间配此前最近在线pH，无最大间隔，缺配对不下发 |
| PH_ADJUSTMENT | targetPh、deadbandPlus、deadbandMinus，沿M04原精度范围 | 死区均为非负偏差幅度，不是绝对边界或带负号下限；目标7、两侧0.1对应6.9—7.1。复核设备当前目标/死区和合法资源 |
| AGITATION_ADJUSTMENT | targetRpm | 正整数≤9999且>0，按设备真实能力写入，不增加BGA/补料连接统一条件 |
| TEMPERATURE_ADJUSTMENT | targetTemperatureC | 0<值<100℃，最多1位；复核设备能力，不另自造物理下限 |
| AERATION_ADJUSTMENT | targetChannelNo、原气体/通路引用、targetFlowLpm | 人工仅实际已配置Air；每非空通路一任务，>0、最多1位L/min并核型号量程，空值不生成，不截断或舍入放行 |
| SAMPLING | 原selectedTypes及各所选类型的M04 DetectionSpec叶子 | 按每培养×每检测类型展开，每子规格只含自身类型；BGA固定温度0<值≤40℃两位、DefaultValue可保存，执行解析Q-2-01；样品量1—9999µL整数 |

参数名沿已存在M04叶子/原控制任务引用，前后端精确绑定是实现待改；不扩展任意检测结果值、执行类别或权限字段。Vi-CELL样品/检测量及稀释，Cedex逐项目稀释、项目有效性和单位沿原M04/M05类型合同；不得把LoadSample本页15—40℃一位温度与1.0—20.0样品稀释迁到培养内任务。

## 3. 004/005及审批的实际生成集合

1. M07-003候选先核有权实验室/培养，按实际类型聚合资源和结果；读取返回本模块managementRevision。004预检只读，005写必须双头及对象版本。二者复用相同类型校验和唯一服务端展开器，保存前重验。
2. 原始行→unitRef→任务/适用审批及零任务回执沿[原专题§9—10](各类任务与批量新增交付契约.md)，一行多通路/检测类型不得丢映射。空流量、未选合格BGA按原文零任务；其他结构/权限错误整实际创建集本地回滚，不静默部分成功。
3. 每任务按实验室原设置决定审批；M06只消费原任务创建/修改/取消场景，不按新类型统一加审批。待审候选不覆盖生效任务，真正生效时任务、审计及适用审批关联同事务；物理下发不在创建事务。
4. 人工取样/补料间隔不足仅提示，用户确认可创建；其他资格不豁免。自动检测计划的M04-Q08等待后严格一小时冲突与批次实际间隔告警分别处理，不将提醒改成统一禁发规则。

## 4. 状态、执行与设备结果

任务列表、详情、日志和执行记录沿[任务页面契约](任务页面与接口契约.md)按类型已有状态/allowedActions投影；无补液计量的控制任务不获得补液暂停/继续/补差动作，DO仍不能修改。原任务代码、审批状态及设备事实分别展示，创建/审批通过均不表示已执行。

执行器在短事务锁目标任务并核版本、当前有效参数/资格、适用审批和已有执行事实；任务与执行审计同事务。提交后由原合法设备执行方调用，完成后另短事务核原任务/执行版本记录真实结果。不得持事务等HTTP/设备，也不以锁覆盖已发出未记录窗口；该窗口关联Q-1-07。

页面设备结果只分成功、失败、结果未确认。受理回执、客户端乐观状态、历史成功目标值均不替代本次物理结果。设备调用前不显示成功；超时不自动换请求ID重发。类型执行所需的原设备适配缺口复用K01/既有对接事项，不以新增能力令牌、投递表或对账流程填补。

pH原四档、自动到离线/中位deadband及日处理语义沿[原新增规则§3](十二月新增工作流与任务规则.md)。队列/详情触发仍按原AUTO执行类别，BGA结果页MANUAL入口允许超deadband二次确认；不能因人点击把所有AUTO变成MANUAL。缺BGA/在线配对是等待缺输入，不算当天已经处理。

## 5. D0、历史及当前差异

D0只消费[M03唯一分类§3](../03-项目与培养管理/培养运行变更页面与接口契约.md)：D0修改原拦截、方案来源未执行任务取消/新生成、人工日历任务不取消不平移、已执行事实保留，不能复制到仅改结束日。方案来源未执行任务按Q-3-02取消/重新生成，今天尚未到点及未来日期才新生成；取消与新增仍依原适用审批，不套旧改时间路径。

历史由M03统一双入口读取M07已有CultureRuntimePort目标方法readCultureHistory(cultureId,section,pageNum,pageSize)，section=feeding/tasks/workflows；只返回实际记录、原计划/实际时间和权限范围，不创建第二历史表。目标签名和普通完成两个Port新增方法仍是源码待改，依据[M03历史合同](../03-项目与培养管理/培养历史双入口与只读详情契约.md)。
