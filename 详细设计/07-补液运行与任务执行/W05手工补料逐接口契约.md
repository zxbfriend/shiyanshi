### 查询与最终保存

GET `/run/workflows/candidates?labId=...&subflowCode=manual_feed_small` 保留当前可信培养范围、补液节点选择与 W05 定义校验，并校验同实验室、同培养、同控制器的 W03 完成并应用。前端交集校验反应器的实际培养身份及进行中状态；写入在守卫事务内重验当前培养归属、RUNNING/DELAYED 生命周期及连接事实。候选不锁定未来资格，也不表示旧固定通道槽位校验已通过。

POST `/run/workflows` 沿用 `run:workflow:start`、Header/WriteMeta 双头和 M07-023 管理守卫。当前页面在最终保存时发送：

```json
{
  "subflowCode": "manual_feed_small",
  "labId": "1",
  "cultureIds": ["5"],
  "manualEntries": [{"cultureId": "5", "mediumId": "77", "feedGrams": "120.500001"}]
}
```

1 至 10 个不同培养，`cultureIds` 与登记行必须完全对应。`manualEntries` 与非空 `bottleIds` 互斥。所有 ID 保持字符串；实际克数为正数，最多 14 位整数、6 位小数，不自动取整或四舍五入。输入控件采用 string-mode，SDK 保留十进制文本，后端使用 BigDecimal 和 DECIMAL(20,6)。同名多料液不能猜 ID，前端拒绝歧义。

M07 经新增的 M02 `ManualFeedMediumPort.resolve(actorId, labId, mediumId)` 取得有效料液 ID、名称、糖浓度及糖补料标记快照；M02 再验实验室操作权限及未删除状态。该 Port 不读取瓶槽或泵。所有培养与料液先完成预检，再在同一 SYSTEM 守卫事务内按培养 ID 顺序创建工作流、两步完成审计记录、MANUAL_FEED 账和运行累计投影；整页原子提交，无部分成功。

独立登记快照为 `schemaVersion=2, registrationMode=INDEPENDENT`。账来源键为 `W05:{workflowId}:MANUAL:{cultureId}`，物料增量为 0，保存服务端操作人、时间、原请求、料液和实际克数及 SHA-256 内容摘要。无任务、设备命令或物料库存扣减。实例直接成为 COMPLETED/APPLIED，两步对应选择及登记的审计事实，不表示设备操作。

写入要求已有同培养、同实验室和同控制器的 W03 已完成且已应用的运行连接，不再为未连接培养建立账本行绕过前置。已有运行行按 labId＋objectVersion CAS 更新累计量和 last_ledger_id，绝不改连接、设备就绪或运行事实流；不据业务连接推断设备已联通。无需为此前置新增表或修改目标 DDL。

响应沿用 `batchRequestId` 和每培养 `{cultureId, workflowId, state:"APPLIED"}`。幂等回执保存整个实例集合，同用户、同原请求及相同规范载荷只返回原结果；不同载荷冲突，失败事务整体回滚。前端在发送前按用户＋实验室保存完整原意图；未知结果或回执不完整保留原请求、原版本、原数据，禁止修改和取消，完成按钮重放原请求。明确拒绝保留表单并要求刷新管理版本；未发送的普通草稿可本地取消。

成功后刷新候选，并 GET `/run/workflows/{id}` 读取服务端操作人、时间与完成状态。刷新失败仍保留已确认的完成结果，不能产生第二次登记；新一轮须显式点击现有“新建”入口。真实失败不回退 Demo。

## 候选与启动

旧固定通道启动也须核对 M07 完成连接事实。共享候选查询已核实上节连接前置，不能用 selectable 代替旧启动的槽位与固定通道校验。候选不锁未来资格。

POST `/run/workflows`，权限 `run:workflow:start`，Header/WriteMeta双头。Body为 `{subflowCode:"manual_feed_small",labId,cultureIds:[1..10个不同培养],bottleIds:[固定补料泵对应槽位ID]}`。服务器解析同实验室不同控制器、真实固定液体名称/泵通道，槽位全部归属所选培养且属于已完成W03冻结通道。最多40槽位（10控制器×4固定泵）；无跨实验室、重复或静默丢行。

M07应用服务在SYSTEM守卫事务内全量校验后按cultureId升序创建每培养一个实例及两步，冻结定义/来源配置。启动只保存流程审计，不记补量。原requestId与完整载荷重放返回原实例集合；未知结果保留原版本及载荷，不换键。所有ID为十进制字符串。

## 步骤与记录

GET `/run/workflows/{id}` 返回既有步骤、版本、冻结只读before及after。两步为step_1开始、step_2记录。NEXT只把PENDING置IN_PROGRESS；COMPLETE step_1后才能进入step_2。

POST `/run/workflows/{id}/steps/{stepId}` 使用既有workflow:operate、双头及expectedVersion。step_2 COMPLETE rows为 `{resourceKey,feedGrams}` 数组，必须完整对应启动冻结通道，feedGrams为>0的整数克，最多14位（既有DECIMAL(20,6)）；不接受mediumId/materialModelId/physicalItemKey/loadedGrams/primeGrams/speed等覆盖来源字段。表示操作者已完成的人工补充事实，不生成task、execution、command。

服务端锁workflow、step、runtime，重验M03当前归属/操作权限、连接身份及M02固定配置未漂移；先全量验证所有行，再每通道追加MANUAL_FEED账。source_kind=WORKFLOW、source_id=workflowId，source_event_key=`W05:{workflowId}:{stepId}:{resourceKey}`，material_delta_grams=0、material_session_id/execution_id=NULL。measurement_evidence保存schemaVersion、人工来源、冻结槽位/液体/配置、feedGrams、操作者、原请求及服务器时间；content_hash为完整规范化不可变账内容SHA256。

所有账、runtime.total_feed_grams CAS增量、步骤COMPLETED及实例COMPLETED/APPLIED、守卫回执/审计同事务。来源键唯一，事务失败全回滚；同键不同正文409，同正文回执重放不重复入账，旧版本409。每培养独立完成，批量启动不暗示批量结算。

## 取消与失败

未提交可用既有cancel口关闭实例；完成后拒绝取消/再次写入，不删除账或历史。仅W05进入无物理副作用的取消分支，不调用设备或资源释放命令。前端只清本实例草稿。没有取消已提交账的入口，纠错沿既有追加更正规则。

400：重复/格式/非整数/来源字段覆盖/行不全；403：功能或数据范围不足；404：不存在或不可见；409：版本、状态、连接/配置变更；503：来源不可读。所有拒绝均不产生补量。依赖缺失明确显示，不回退Mock。

前端在启动及每次写入后重读当前详情/revision；未知结果锁定本次意图，允许以原requestId/版本/载荷重放。刷新丢失未保存草稿不伪造恢复成功，可按原实例ID读审计/终态。菜单实验室入口保留labId。
