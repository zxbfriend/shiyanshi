# 反应器生产过程时间线接口契约

版本：M07-PROCESS-20261019-V1。

## 1. 范围与归属

本契约服务于“实验室工作台 → 反应器详情 → 生产过程”，按单个培养展示工作流、已执行补料、已执行补糖和离线检测事实，并提供节点详情。

这是 M07 对本模块运行历史的只读查询，不恢复延期的 M08 综合工作台、统计读模型、导出或跨培养分析。M07 负责查询编排和统一排序；M03 提供培养基本信息与对象可见范围；M05 仅通过只读 Port 提供检测事实。M07 不得直接访问 M03、M05 Mapper 或内部表。

首版不包含物料记录、趋势图、统计指标、生产结束或设备实时曲线。缺少真实事实时返回空集合或明确的来源状态，不生成演示节点。

## 2. 浏览器接口

### 2.1 查询生产过程

- 编号：`M07-036`
- 方法与路径：`GET /run/cultures/{cultureId}/production-process`
- 权限：`run:workflow:query`
- 对象范围：调用人必须能读取该培养及其所属实验室；权限通过但对象不可见时统一按对象不可见处理，不泄漏培养是否存在。
- 查询参数：
  - `cursor`：可选，上一页返回的不透明游标；不得由客户端解析或拼接。
  - `limit`：可选，默认 `100`，范围 `1—500`。
- 一致性：只读查询不要求管理版本 Header；响应返回各节点真实 `sourceVersion`，不承诺跨 M03、M05、M07 的全局快照一致性。

响应业务体：

```json
{
  "culture": {
    "cultureId": "123",
    "cultureCode": "C-001",
    "reactorName": "R01",
    "startTime": "2026-10-19T00:00:00Z"
  },
  "nodes": [],
  "nextCursor": null,
  "sources": [
    { "source": "M03", "state": "AVAILABLE", "reasonCode": null },
    { "source": "M07", "state": "AVAILABLE", "reasonCode": null },
    { "source": "M05", "state": "AVAILABLE", "reasonCode": null }
  ]
}
```

`sources.state` 取 `AVAILABLE/PARTIAL/UNAVAILABLE`。M03 培养身份或可见范围不可取得时整个请求失败；M07 本地查询失败时整个请求失败；M05 暂时不可用时允许返回 M07 节点，但必须把 M05 标为 `UNAVAILABLE` 并给出稳定 `reasonCode`，页面显示“检测数据暂不可用”，不得伪装成“没有检测”。

`sources.reasonCode` 当前稳定值：`SOURCE_RECORD_INCOMPLETE` 表示来源中存在缺少稳定标识、版本、发生时间或登记模式的记录，来源状态为 `PARTIAL` 且这些记录不进入正常节点集合；`DEPENDENCY_UNAVAILABLE` 表示可降级来源暂不可用，当前仅适用于 M05，来源状态为 `UNAVAILABLE`。`AVAILABLE` 时该字段为 `null`。

### 2.2 节点公共字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| nodeId | string | `ownerModule:sourceId:sourceVersion` 的服务端稳定编码；仅用于读取和前端 key |
| ownerModule | `M05/M07` | 事实拥有方 |
| sourceId | string | 原事实稳定主键 |
| sourceVersion | long | 原事实对象版本；无显式版本的不可变步骤取父实例版本 |
| kind | `WORKFLOW/FEEDING/SUGAR_FEEDING/DETECTION` | 节点类型 |
| source | `WORKFLOW/MANUAL/AUTO` | 原型中的 W/M/A；按第 4 节映射，禁止根据创建人名称猜测 |
| title | string | 节点主标题 |
| subtitle | string/null | 二级流程名、检测类型等辅助文字 |
| status | string | 原事实状态 |
| occurredAt | instant | 排序与 Dn 分组时刻 |
| startedAt | instant/null | 真实开始时刻 |
| endedAt | instant/null | 真实结束时刻 |
| operator | object/null | `{userId, displayName}`；显示名来自事实快照或合规身份投影 |
| payload | object | 与 `kind` 对应的类型化详情，禁止任意键值替代主契约 |

`DX.Y` 为页面视图序号，不保存入库。`X` 由 `occurredAt` 相对培养真实 `startTime` 按上海业务日计算，D0 为开始日；`Y` 为同一天按第 5 节排序后的 1 基序号。

页面按反应器详情已加载的培养周期生成完整 `D0`～`D(周期-1)` 日行，再把节点放入对应日期；某日没有节点时仍保留自然日期并显示“暂无操作”，不得只根据已有节点省略空白培养日。

2026-10-20 按用户确认的反应器生产过程参考图恢复布局：上方横排展示实验室已配置的工作流程，下方“生产”区域按培养日排列横条；每行左侧显示 `Dn` 和自然日期，右侧以淡蓝箭头节点显示 `DX.Y`、标题及 W/M/A 来源标记。生产区域内部滚动，移除原设备图片及培养摘要侧栏。节点详情、来源不可用提示和游标分页保持原接口语义；无真实记录时不生成示例节点。

## 3. 类型化详情

### 3.1 WORKFLOW

`payload` 包含 `workflowId/subflowCode/subflowName/definitionHash/steps`。每个步骤包含 `stepInstanceId/stepCode/stepName/stepOrder/state/startedAt/endedAt/operator/formRows/completionEvidence`。表单和完成证据只投影定义快照允许展示的字段，不把设备密钥、通信参数或原始内部 JSON 透传浏览器。

### 3.2 FEEDING

`payload` 包含 `taskId/taskSourceKind/pumpName/mediumName/targetGrams/actualGrams/unit/reason`。仅 `business_state=EXECUTED` 的任务进入时间线；`occurredAt=ended_at`，若已执行事实损坏且 `ended_at` 为空则来源标 `PARTIAL`，该任务不进入正常节点集合。

### 3.3 SUGAR_FEEDING

除 FEEDING 字段外，包含 `preSugarConcentration/postSugarConcentration/concentrationUnit`。浓度只取任务关联的最新有效 `SETTLE` 冻结计算快照：输入快照的 `glucoseBeforeGl` 为补糖前浓度，输出快照的 `glucoseAfterGl` 为补糖后浓度。任一值未知返回 `null` 及对应 `missingReasonCode`，不得用 `0` 替代。原因码取 `SETTLEMENT_CALCULATION_MISSING/SUGAR_CONCENTRATIONS_MISSING/PRE_SUGAR_CONCENTRATION_MISSING/POST_SUGAR_CONCENTRATION_MISSING`；两值齐全时为 `null`。

### 3.4 DETECTION

`payload` 包含 `sampleId/sampleNo/detectClass/detectType/detectMode/samplePosition/temperature/cellType/dilutionFactor/items/resultStatus/resultCompleteness/deviceCompletion`。`items` 来自 M05 样品检测项和当前核准主结果；OSMO 无附加录入项时返回空数组，不补造字段。开始、结束时刻优先使用 M05 的可信实际时刻；未核验历史才回退到旧投影时刻，并在 payload 标明 `timeEvidenceState=UNVERIFIED`。

## 4. 数据来源与映射

| 节点 | 权威事实 | 纳入条件 | W/M/A 映射 |
| --- | --- | --- | --- |
| 工作流 | M07 `run_workflow_instance`、`run_workflow_step` 的当前只读投影 | `culture_id` 精确匹配；实例状态不限，取消状态按真实状态展示 | 固定 `WORKFLOW` |
| 补料 | M07 `run_task`、TaskSpec、结算投影 | `task_type=FEEDING AND business_state=EXECUTED` | `source_kind IN (USER,COPY,ERROR_SUPPLEMENT)` 为 `MANUAL`；`PLAN_FIXED/PLAN_RULE` 为 `AUTO` |
| 补糖 | M07 `run_task`、TaskSpec、计算及测量快照 | `task_type=SUGAR AND business_state=EXECUTED` | 同补料 |
| 检测 | M05 检测历史只读 Port | `culture_id` 精确匹配，未删除、未清空，当前结果不为 `cancelled/voided` | `detect_mode=manual` 为 `MANUAL`，其余已登记自动模式为 `AUTO` |

2026-11-04 用户确认：新建 `W06` 取样单元液体补充记录按启动时核实的培养归属分别保存并进入对应培养时间线；历史记录缺少可靠培养归属时不得根据当前绑定关系推断。取消补料、取消补糖及跨天取消任务不展示，符合原型“成功记录进入生产过程”的口径。实现与运行验收以实际结果为准。

培养开始时间、培养编号、反应器显示信息由 M03 培养只读 Port 返回。工作流标题优先取 `definition_snapshot` 的固定显示名；任务的泵、培养基与单位取 `task_spec` 及执行时快照；不得回查当前主数据覆盖历史名称。

## 5. 排序、分页与去重

1. 主排序：`occurredAt ASC`。
2. 同一时刻：`WORKFLOW < FEEDING < SUGAR_FEEDING < DETECTION`。
3. 最终稳定排序：`ownerModule ASC, sourceId ASC`。
4. 游标编码完整排序键；翻页期间新事实只允许出现在后续刷新，不得导致已返回节点重复。
5. 聚合层按 `(ownerModule, sourceId, sourceVersion)` 去重；同一 `sourceId` 出现更高版本时返回高版本，不合并两个版本的 payload。

## 6. 分层与实现边界

目标链路：

```text
ProductionProcessController
  -> ProductionProcessQueryApplicationService
     -> M03CultureTimelineContextPort
     -> M07ProductionProcessRepository
     -> M05DetectionTimelinePort
  -> ProductionProcessView
```

- Controller 只接收参数、鉴权并映射统一响应。
- 应用查询服务校验培养范围、合并来源、稳定排序和游标。
- M07 Repository 只读 M07 表；M03/M05 只能通过 Port。
- 不新增时间线持久化表，不复制 M05 检测结果到 M07。
- 节点详情随列表返回；首版不增加按节点任意 ID 查询接口，避免绕过培养对象范围。

## 7. 错误与验收

| 场景 | 结果 |
| --- | --- |
| `cultureId` 非法、`limit` 越界、游标损坏 | 400，统一参数错误外壳 |
| 缺 `run:workflow:query` | 403 |
| 培养不存在或对象不可见 | 404 等价外壳 |
| M03/M07 权威事实不可用 | 503 `RESOURCE_FACTS_UNAVAILABLE` |
| M05 暂时不可用 | 200，M05 source=`UNAVAILABLE`，M07 节点仍可读 |

契约测试至少覆盖：D0/Dn 边界、同刻稳定排序、游标无重复、W06 排除、取消任务排除、仅 EXECUTED 任务纳入、M05 部分不可用、对象越权、未知浓度不补零、快照名称不被当前主数据覆盖。
