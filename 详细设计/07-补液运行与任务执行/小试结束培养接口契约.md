# 小试二期结束细胞培养后端接口契约（V4.2，2026-10-26）

## 2026-11-07 现行澄清适用口径

依据正式决策记录末尾S04客户答复及后续补充。本节与下文正文同步；仅为设计，不证明代码或设备已验证。

- **Q-3-06**：原提前取消申请跨计划结束日获批后继续按原取消申请生效，最终为已取消；审计actualEndedAt采用该申请内记录的结束时间，审批时间另记。此为本场景对旧“最终服务器时刻作为实际结束”的明确例外。终态及原占用释放仍在审批通过且原安全/版本条件满足后的实际应用事务中提交，应用/释放时间不回写为申请内业务结束时间；正常结束等其它场景不受此例外扩展。

本专题只适用于新 SMP 的小试二期。依据客户 V4.2 §3.4.7.2、结束培养原型，以及本轮用户确认：只保留“所有”筛选；Row 取台式反应器设置中的场地；正常结束检查方案其他已选环节有真实操作记录，未选开始培养不拦截；执行/暂停补液须先原入口处理，执行取测不拦截（原生5/6/36/103/125）。设备暂用明确标记的模拟回执，真实停机回读协议待现场接入。前端页面和交互本轮不改。

## 2026-11-04 终态与释放规则

成功完成工作流中的结束培养才写终态并同步释放原控制器占用：当前为 `RUNNING` 且当前上海业务日等于生效计划结束日，结果为 `FINISHED`；结束延期先按原生第7问主动改计划并生效，不能直接沿旧计划结束；`RUNNING` 且早于计划结束日时为 `CANCELLED`。日期按上海业务日判断；开始延期须按对应计划修正规则办理，不由结束入口直接消除延期。单纯到期、延期、原因保存或审批通过都不表示结束完成。

正常完成、确认跳过、异常免审和审批后自动应用均在最终提交前核验安全事实，再原子保存工作流完成、培养终态/实际结束时间与原占用 `RELEASED`。无安全证明时保持原状态/占用，不新增“终态但待释放”。当前模拟边界下 `SKIP` 与 `COMPLETE` 使用同一安全核验，不把跳过当成真实设备已归零；已有 `RELEASE_PENDING` 仅保留原身份核验后的恢复清理，不执行自动数据回填。本节覆盖2026-10-26的先终态后释放规则，旧测试记录只作为当时证据。

## 流程及状态

| 场景 | 页面步骤 | 提交时的业务结果 |
| --- | --- | --- |
| 进行中且当前为生效计划结束日 | 开始→完成培养→关闭设备 | 可多控制器；第3步“完成”或确认“跳过并完成”时全量安全校验，整批保存 `FINISHED`、完成事实及原占用释放。第2步仅推进步骤，不提前写终态。 |
| 进行中且早于计划结束日，免审批 | 开始→完成培养 | 仅单控制器；原因必填。最终保存前核验安全及仍为进行中提前，成功时保存 `CANCELLED` 并同步释放原占用。跨日或延期导致分支变化时拒绝并重选正常结束；安全校验未通过时不写终态。异常流程不进入关闭设备页。 |
| 进行中且早于计划结束日，需审批 | 开始→完成培养 | 仅单控制器；原因必填。送审、拒绝均不改变培养与占用。获批后等待安全收尾，最终完成时按当前生效计划/状态核定结果；待审跨计划结束日仍按第44问显示延期，不把申请当完成，并同步释放原占用。异常流程不进入关闭设备页。 |

审批保留原申请身份、原因与证据；Q-3-06提前取消申请跨计划结束日仍沿原取消申请处理，获批并满足安全/版本及原占用条件后最终CANCELLED，actualEndedAt取申请内记录时间，审批/实际应用/释放时刻分别留痕。其他正常结束仍核当前合法计划，不借此绕过延期修正规则。

取消仅适用于送审或最终保存之前：二次确认后关闭本次未保存尝试，下次从第1步开始。已送审申请的撤回仍待团队确认，不通过取消入口实施。

2026-10-27 用户确认正常第3步的设备来源：从当前小试控制器配置读取 MFC 数量及泵通道；控制回路固定为 DO、pH、Vessel Temp、Agitator。原型注释中的“集成反应器”不作为小试设备查询来源。现有实现通过 `BenchControllerRuntimePort` 按控制器身份读取并冻结归零目标，所有目标为 `OUT=0`、`MAN`，模拟执行不代表真实设备已归零。

正常结束时间的保存时点存在原文冲突：需求正文第2步仅写点击“完成”进入第3步，第3步取消要求不保存当前数据；原型同时写“走到步骤3就是记录了结束时间之后”和“整个步骤完成后，需要记录结束培养时间”。2026-10-27 用户再次确认：第2步只记录步骤确认，第3步点击“完成”或确认“跳过并完成”时才统一保存培养状态和结束时间；第3步取消后培养保持进行中。结束时间使用最终确认时的服务器时间，记录到时分秒。

## 工作流定义与分支（2026-10-27）

需求规定正常三步、异常两步，不要求数据库必须保存两套子流程定义。现有环境的 `end_cell_culture_small` 三步定义可以复用：正常运行全部三步，异常仅运行前两步，不创建或自动完成第三步。数据库的子流程ID、步骤ID、说明和图示保持原来源，不新增、改名或覆盖共享定义。

M07 经现有 M04 只读接口解析定义。已有独立正常／异常定义时继续使用；仅在对应独立定义返回 `NOT_FOUND` 时读取同实验室适用的公共定义。重复定义、依赖故障或配置不完整不转用另一套配置掩盖错误。公共定义须属于小试、`end_culture` 目录、不可重复，完整三步按顺序使用 `step_1/step_2/step_3` 或 `START/COMPLETE_CULTURE/SHUTDOWN_DEVICE`；不支持混排或从任意三步流程猜测语义。培养仍须选择定义所属目录。

实例的 `subflow_id/subflow_code/definition_hash` 保留实际 M04 来源。运行步骤使用业务步骤码，`definition_step_id` 保留原步骤ID。`selection_snapshot.finishType` 冻结正常／异常分支。小试的 `definition_snapshot` 在既有字段外增加 `sourceDefinition`，保存 M04 返回的完整定义及真实 hash/version；`steps` 保存本次实际运行的两步或三步，说明和图示从来源复制。该扩展只用于小试结束，不改变 W01 等其他流程的快照白名单。异常分支保留完整来源用于追溯，但不向页面显示未执行的关机步骤。

启动、批次操作、审批消费和停稳释放同时核验流程编码、冻结分支、工作流种类与模拟标记；不接管仅有旧编码、没有这些冻结来源的历史实例。现有两套独立定义及其已生成实例继续支持。此改动不修改 M04 端口、工作流管理页面、初始化脚本或运行库定义。

## HTTP 接口

2026-10-27 用户确认离线指标并列规则：同一培养、同一指标有多份有效结果的检测完成时间并列最新时，返回 `state=AMBIGUOUS`，保留指标名称和检测完成时间，`value/unit/resultStatus/resultId/sourceVersion/sampleNo` 为空，`reason` 提示“同一检测完成时间有多份有效结果，暂不展示单一数值”。不以上传时间、审核状态或结果ID打破并列；完成时间不同时仍取最新有效结果。沿用当前培养关联设备和反应器阶段样品的范围，不修改检测记录。

所有写接口要求 `X-Request-Id` 和从本模块读接口顶层取得的 `X-Management-Revision`，遵守现有管理守卫的幂等、版本与权限规则。ID 和版本均以十进制字符串传输。

从指定控制器进入时，候选读口携带 `cultureId`、`deviceId`：先按培养定向读取并核验实验室与访问权限，再校验当前控制器绑定；绑定变化时拒绝。未指定培养时保持实验室候选列表语义。

| 作用 | Method / path | 输入或输出要点 |
| --- | --- | --- |
| Row 选项 | `GET /run/workflows/room-options?labId=…&subflowCode=end_cell_culture_small` | 仅从当前有权候选控制器对应的台式反应器场地取值与名称。 |
| 候选卡片 | `GET /run/workflows/candidates?labId=…&subflowCode=end_cell_culture_small&relationFilter=ALL` | 可选 `venueId`；返回控制器、培养日、计划结束日、`finishType`、在线/离线指标、准入及不可选原因。不接受“与我相关”。 |
| 启动 | `POST /run/workflows` | `subflowCode=end_cell_culture_small`、`labId`、`cultureIds`；正常分支多个培养可同批启动，提前异常只能单台。冻结原培养、控制器、占用和工作流定义。 |

| 审批决定 | M06 现有决定交付入口（内部消费者） | 只应用原候选、原版本及原审批决定；重复交付返回原回执。通过仅允许后续安全完成，最终应用同步保存培养终态与原占用释放；拒绝时培养状态不变。 |

最后两个接口供没有设备回读协议时的后端联调使用，不代表系统读到了真实停稳信号，也不要求现有前端新增页面或修改交互。真实设备接入后须用核准的回读证据替代人工模拟确认，完成现场联调后才可宣称物理停机已验证。

**2026-11-03 前端例外范围订正**：上句「不要求现有前端新增页面或修改交互」的主语是上表末两行（模拟人工停稳状态、模拟人工停稳确认），仅覆盖这两口。上表前四口（批次详情、整页推进/最终完成/取消/移除、异常原因及送审/免审完成、常用异常结束原因）**没有逐口的「不要求前端」表述**，其页面用途与逐口前端范围属未核；本专题头部「前端页面和交互本轮不改」是 2026-10-26 的本轮开发范围声明（与[接口目录与契约定位.md](接口目录与契约定位.md)的「只开发中试W01与结束培养后端，前端设计/交互不改」同类），不得读成上述四口永久不需要前端，也不得由零页面引用反推这四口已停用。

审批决定自动应用还依赖公共后台资源事务执行器：现有小试审批消费者复用 `M07_PILOT_END_CULTURE_APPLY`，执行器的装配要求 `futurefab.resource-transaction.enabled=true` 及有效的事务和锁等待预算。2026-10-27 对本机两个 Nacos 配置文件及 system 启动参数的只读检查未发现这组配置；由于环境变量等其他来源未核实、运行实例未开放装配查询，实际运行状态仍待确认。缺少执行器时审批回投为 `BLOCKED_DEPLOY`，不能仅凭审批服务和单元测试宣称自动应用可用。公共事务配置由对应负责人评估，不能为此擅自启用其他后台消费者。

`abnormalEnd` 只返回原因、候选ID及版本、审批ID、审批状态和应用状态，不向页面暴露完整内部审批政策快照。步骤同时返回操作人ID、开始/结束时间及是否跳过。审批通过后，流程操作结束时间取审批决定时间，培养实际结束通常取最终安全保存时刻；Q-3-06提前取消跨期例外取申请内记录时间，审批、应用与释放各记真实时刻。

2026-11-04覆盖旧免审批规则：免审不创建审批单，但原因保存本身不证明培养完成。最终完成前按本节V5.1分类核验任务和相关未决设备动作，不以所有活动任务数为0一律拦截，成功时同事务保存原因/完成事实、培养终态与实际结束时间、原占用释放。任何占用或步骤版本冲突均回滚，重复请求沿用原回执。

2026-11-04覆盖旧跳过规则：正常“跳过并完成”沿当前明确标记的模拟边界执行与“完成”相同的安全校验，成功时同步保存培养实际结束时间和原占用释放；失败时不能显示已结束。“完成”与“跳过”分别保留第三步 `COMPLETED`/`SKIPPED` 和模拟回执，不把模拟确认当成真实归零或停稳证据；真实设备仍需独立接入与验收。

常用原因由管理员通过既有“系统管理／字典管理”统一维护：字典类型编码固定为 `bench_end_culture_reason`，建议名称“小试异常结束常用原因”；字典标签是可选择的原因文本，排序、启停沿用 M01。M07 经 `FormCandidateFactsPort` 读取，不直接访问 M01 表、不读取用户历史原因，不新增维护页面。选择后仍用既有 `reason` 文本提交，可手动填写；保存的是当次文本，不因字典日后改名而改历史原因。未配置项时列表为空，不生成默认原因；读取失败返回 `FACTS_UNAVAILABLE`，不伪装空列表。2026-10-26只读核验：运行库未配置该字典及正式选项，真实HTTP返回空列表；需管理员维护正式内容，自由填写原因不依赖选项初始化。

正常批次中已移除的成员不再参与余下成员的状态推进。若该已取消成员的操作权限已撤销，批次读接口也不回显其卡片；仍选中的任何成员权限不足则拒绝整批操作。已移除成员后来重新绑定设备不影响剩余选择，历史卡片仍取原冻结事实。

## 模块数据边界与验证

- M03 拥有 `res_culture` 和 `res_culture_occupancy` 状态写入；新结束流程同事务终态并释放，历史 `RELEASE_PENDING` 仍占唯一活动槽位。
- M07 拥有 `run_workflow_instance`、`run_workflow_step`、`run_event`；冻结流程定义及步骤，记录审批回执和模拟停稳确认。M06 拥有审批政策、申请和决定；M02 提供控制器、台式反应器 Row 与指标来源；M04 提供流程定义。
- M01 拥有常用原因的 `sys_dict_type`、`sys_dict_data`，复用字典维护与读取，不新增表或修改建库脚本。M03 正常收尾的 `completeNormally`、`skipNormally` 均在安全核验后同步释放；`releaseAfterManualStop` 仅保留原历史终态/占用及 M07 原流程证明的恢复清理。
