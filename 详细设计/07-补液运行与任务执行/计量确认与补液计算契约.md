## 1. 单位、读数和账本

重量/累计/任务目标统一Decimal g，浓度g/L，公式体积L=g/1000；业务体积按已确认密度1换算。来源mL/μL仅在具体物料量纲经核准后用1mL=1g、1000μL=1g。原值、单位、观测时刻、receivedAt、设备/通道、quality、sequence、configurationRevision、方向、净重策略、精度及归一化值一并记录。数据库十进制最多6位g、10位g/L，显示层舍入不覆盖计算输入。

初始培养重量取M03的合并字段；初始量的g/kg展示按规格≤15 L使用g、>15 L使用kg，累计补液/累计取测始终g。反应器量程不是培养液量，液袋模型容量不是本次实际装载量。

小试当前净量=初始培养重量+全部已认可培养补入g−全部已认可取测g。中试当前净量取反应器秤归一化净值，不能再减取测账本。小试计算字段写入责任需EXT02核准writerMode=SMP/PLC；两者不可同时写同一权威投影。PLC与理论值可并列对照，不静默取较大或最新一个。

## 2. 残糖与乳酸确认

入口按14原文默认当天，列表按检测完成时刻倒序、ID倒序，当前培养Cedex检测项itemCode前三位为GLC的完整指标行；GLUCOSE_LACTATE模式增加前三位LAC的完整行，不按名称分类、主记录计数或合并同前缀。查询可看历史已确认值，确认仅本业务日检测数据。本期显式使用M05调用规则：允许tested/uploaded/signed/reviewed，必须VERIFIED、未删除/整项未作废、itemOutcome=VALUE、有效数值与可换算g/L。该词表以[自动检测与跨模块结果契约](../05-检测与数据签批/自动检测与跨模块结果契约.md)4.1为权威（2026-10-07 INT-13更正：此前此处使用了M05域外的终态词，只翻正措辞，不放宽准入）。PARTIAL仅正常且本次所需指标齐全的项允许人工确认，错误项不允许。此处明确覆盖M05通用默认uploaded以上，不能要求结果必须审核后才允许原文的残糖确认。

状态词表分层口径（2026-10-07 INT-19登记；只定词表归属，不放宽也不加严任何准入条件）：本节出现的三类词各司其职，禁止互相顶替。

- `resultStatus`＝**结果级状态**。取值域以基线`det_result.result_status`为准（`idle/stored/pending/testing/tested/uploaded/signed/reviewed/voided/timeout/exception/cancelled`），该域内**不存在VERIFIED一族的取值**，因此上段“必须VERIFIED”在词表上不得解作结果级状态。
- `itemOutcome`＝**检测项级产出状态**。取值域`VALUE/ERROR/NO_MEASUREMENT/UNKNOWN`（基线`ck_m05_rx_outcome`）。其中`VALUE`是“该项有可用检测值”的**准入词**，既不表示结果正常或异常，也不承载签批可信度；它不是任何质量词或状态词的别名。
- `evidenceQuality`＝**版本快照层证据质量**（`ResultSnapshot`顶层键，基线无`evidence_quality`列）。VERIFIED/UNVERIFIED一族表达“该版本内容是否由当时事件真实产生”，事后补写的BASELINE恒为UNVERIFIED。

另需区分：基线在`det_result`上还有**结果级签批链状态**`sign_chain_state`（`VERIFIED/UNVERIFIED/CONFLICT`，`ck_m05_sign_chain`），它是基线中唯一以`VERIFIED`为域值的列。据此，“必须VERIFIED”的词表归属只可能是`sign_chain_state`或快照层`evidenceQuality`，两者都不是`itemOutcome`的近义词；残余问题由“词表口径不一致”收敛为一句可执行的业务裁决：**M07准入是否施加`sign_chain_state='VERIFIED'`，以及是否同时要求`active_sign_id`非空**。按基线`ck_m05_sign_ptr_state`，`sign_chain_state='VERIFIED'`与`tested/uploaded`同时成立是**合法**的——该约束末支明确允许`result_status NOT IN ('signed','reviewed','voided')`配`active_sign_id`、`active_review_id`、`active_void_id`三者全NULL；真正排除`tested/uploaded`的前提是**`VERIFIED`且`active_sign_id`非空**（此时只允许`signed`或`reviewed`）。所以单施`sign_chain_state='VERIFIED'`并不作废本段“允许tested/uploaded”的允许面，也不与末句冲突；只有连带要求`active_sign_id`非空才会与末句“不能要求结果必须审核后才允许原文的残糖确认”冲突。若不施加该门，则应改按快照层`evidenceQuality`口径或删除该门。

`confirmation.source_snapshot`的`status`叶子按本口径**只承载来源结果级状态**（M05来源取`resultStatus`域值，手工来源显示『已检测（手工登记）』）；VERIFIED一族属证据质量/签批链层，不得写入该叶，也不得混入`itemOutcome`判断。该叶的取数实现仍属M07-019解析器工作，本口径不产生任何运行行为变化。

GLC与LAC分别选择、分别60秒，培养＋上海业务日期＋analyteKind各有一把确认守卫。因此选GLC不会锁死LAC；同一类同时只能有一个COUNTDOWN且本日最多一个生效CONFIRMED。选择其他同前缀项目也不能绕过每日唯一。对GLUCOSE_LACTATE必须两类同日都完成确认后才能提供完整自动计算输入；可以来自不同Cedex结果，保存两个独立源版本/时间，禁止拼成一个虚假检测样品。

## 3. 计算快照

CalculationInput固定schemaVersion、algorithmVersion、purpose、cultureId、businessDate、planSnapshotId/version/hash、initialGrams、weightBasis、basisGrams、physicalBeforeGrams、volumeEvidence、glucoseConfirmationId、lactateConfirmationId、previousSettlementId、glucoseBeforeGl、lactateConfirmedGl、mediumSnapshot、taskParameters、measurementPolicy、evaluationStamp。

basisGrams用于目标补糖量，CURRENT取本次执行前当前量，INITIAL取初始量；physicalBeforeGrams记录真实/理论当前培养量，保留两个字段，不把“依据=初始”误呈现为实际秤读数。目标预览、动态生成判定、实际执行前计算各自建快照并标purpose=PREVIEW/GENERATE/EXECUTE/SETTLE；预览不生成执行事实。实际混合使用执行前后培养液体积和实际入量，目标量使用配置的计算依据，两个用途不能用同名“罐重”混淆。

计算输出固定targetGrams或null、actualGrams或null、glucoseAfterGl或null、sugarMassBeforeG/AfterG或null、completionPct或null、formulaCode、dimensionSteps、issues、inputHash。中间“目标补糖量”按已有决策不增独立任务列，从快照公式可重演；界面可展示中间推导值及单位。所有缺值传null和原因，不用0代替未知。

## 4. 公式

设初始合并量I(g)，按依据选定B(g)，实际任务前净体积Vb(L)，任务后Va(L)，补入液体实际体积F(L)，当前糖G(g/L)，确认乳酸Lac(g/L)，培养基糖Cf(g/L)。

| 公式编号 | 用途 | 公式及条件 |
| --- | --- | --- |
| M07-F01 | 数值补料/定量补糖 | targetGrams=inputGrams，>0整数 |
| M07-F02 | 百分比补料 | targetGrams=I×percent/100，0<percent<100，最多3位小数 |
| M07-F03 | 按规则补糖-残糖 | targetGrams=(targetGl−G)×(B/1000)/Cf×1000；Cf>0 |
| M07-F04 | 按规则补糖-残糖乳酸 | 同F03，浓度差再减Lac；需要有效本日两类确认 |
| M07-F05 | 含糖补液后实际混合 | Gafter=(G×Vb+F×Cf)/Va；小试Va=Vb+F，中试Va来自新鲜净重 |
| M07-F06 | 非糖补料未勾选计入料液带糖 | Gafter=G×Vb/Va；不能误加当前培养基未知糖量 |
| M07-F07 | 残糖量 | sugarMassG=实际净体积L×相应实际/理论糖浓度g/L |
| M07-F08 | 完成度与误差 | completionPct=actualGrams/targetGrams×100；deficitPct=(target−actual)/target×100 |
| M07-F09 | 糖耗 | 昨天最后已结算糖浓度−今天确认糖浓度，单位g/L，允许真实负数；缺任一项不写伪0 |
| M07-F10 | 袋余量 | 首次液袋采用型号容量作为理论起始量，更换后采用本次认可补充净重，减去各自session累计认可消耗g；与下限同单位严格小于标红 |

“补料时计算补料引起的糖浓度变化”对非糖补料决定是否计入料液带糖：false仍按F06体积稀释，true按F05混合；糖补料仍按原F05。每次使用真实认可体积，不把未勾选解释为保持旧浓度（第130问）。原图未计算糖耗显示0仅为兼容展示点，返回value=null、hasValue=false；曲线提示无数据，不把展示0参加统计或补液计算。

F03/F04先按LT/LE判断糖下限，再计算目标；差值≤0记录NOT_NEEDED，不生成零或负任务。按设备核准精度步长HALF_UP量化最终目标，一次舍入，存未量化值和量化结果；NCS061比较的是核准单位的最终待泵入量，阈值缺失THRESHOLD_UNVERIFIED，不报“过小”。不修改客户已确认公式以追求一次补入后精确达到targetGl：F03计算的量与F05混合后浓度可不同。

算例：I=140g，10%→14g。B=2000g，G=3g/L，目标7g/L，Cf=400g/L→20g；同条件Lac=1→15g。20g真实入罐、小试Vb=2L时Gafter=(3×2+0.02×400)/2.02=6.9306930693g/L，不写成7；残糖总量14g。无糖补料20g则6/2.02=2.9702970297g/L。目标50g暂停分段20+30g→100%完成度。

4. 逐段核对历史 CLOSED 段及其唯一账来源、培养/物料归属、金额与摘要。`execution.confirmed_grams` 必须等于历史已认可段量之和；本段只追加一次差量，不能直接信任 CLOSED 标记或现有累计值。先插唯一账，再 CAS 更新 `runtime.total_feed_grams/last_ledger_id` 与 `material.consumed_grams`，最后写停止、关闭段、更新暂停状态及审计；任何失败须整体回滚。禁止 `INSERT IGNORE` 后仍累加，禁止先投影后尝试去重。OPEN 段已经存在同来源账属于事实不一致，不能自动再次投影；成功后的重放不再累计。
5. 首批自动培养投影仅启用已核准 `writer_mode=SMP`。PLC/UNKNOWN 未有核准的专用投影规则时保持等待，不将其改为 SMP，不抹掉原 STOP 命令或已有停止/采样证据；这些路径不获得可恢复暂停或资源释放资格。所有安全停止、隔离和保护职责继续保留。

`sample.raw_readings.activeMilliseconds` 的本批内部生产/消费口径固定为**当前 segment 的实际活跃累计毫秒数**，沿原版本字段，不解释为整次执行累计或采样接收间隔。新样本不能低于同段已持久值；原身份重放仍按原 hash 返回。同段来源或时长缺失、回退、溢出均阻断相关认可，后台不能用零填补。执行累计等于各历史已认可 CLOSED 段活跃时长加当前段实际活跃时长；确认暂停后的等待不计入，新段启动前不以墙钟差值推算，重启不重置累计。可信生产者必须覆盖暂停请求至实际停泵的活跃时长，不能拿“请求停止时”计数代替实际停止计数。

起读数须为完整 GOOD/g 读数，与终读数的设备、指标、实验室、来源版本、归一化模式/方向/精度/profile 一致，并按原开始时刻验证新鲜度；终读数时刻保留为 `end_readings.capturedAt`，物理 `stoppedAt` 仍取原 STOP 的真实停止时刻。本段认可不核准新的目标、恢复剩余量或供料公式，不解除 40g/35g 等待确认政策，不改变原首次开始日期、安全观察或资源释放条件。

### 2026-10-21：正常终点收尾与异常原量冻结

正常控制达到终点只准备原执行 STOP，不直接结算。`M07NormalStopFinalizer` 由已持久样本的同一事务和原补偿扫描共同唤起；两入口先按运行态、任务、执行、全部段的顺序锁定原身份，再核全部原命令、受控完整观察覆盖和最终起终读数。`STOPPING`、STOP 回执或当前时刻已过观察截止都不能单独确认完成。任务或执行任一 `NEEDS_RECONCILIATION` 仍阻断。

### 2026-10-21：明确核准的最终允差与实际反应器重量

最终认可范围由核准 `finalPolicy` 表达：下界为原冻结任务目标量乘明确批准的 `minimumFinalPercentOfTarget / 100`，上界同理使用 `maximumFinalPercentOfTarget`。这是核准参数的计算表达，不提供默认百分数，也不将异常后补料的 5% 自动当作最终允差。全程精确十进制；超出 `DECIMAL(20,6)` 的有效精度或范围时阻断，不自行选择舍入方式。

结算政策只供原 `STOPPING + OPEN + NONE` 最终化或 `STOPPED + CLOSED + PROVISIONAL` 原段首次认可使用，不能为仍运行的执行生成停止结算资格。实际停止、全范围观察、原命令闭合和唯一量账仍由原最终化/认可链核验。

明确 `calculateGlucoseChange=false` 时不造物理后量；为 true 时，必须在原冻结设备和完整资源中明确标定反应器实际称量流，并从原已提交、经过计量/时间资格核验的 GOOD 样本取得实际净重。读数须不早于原完整停止观察终点且在核准时效内，实际值与明确净量换算一致。供料秤不能通过更换 metric 名称充当反应器秤；预测重量、任务目标、补入量以及缺失时的零值均不能代替该读数。较晚坏质量或冲突读数不能通过挑选较早 GOOD 读数规避。

未核准的计量含义、实际活跃来源、校准窗口或观察连续性继续阻断相应自动路径；配置文件存在、journal 存在、健康回执以及时间到期均不代表校准或观察覆盖已完成。

## 同袋恢复供料生产输入（2026-10-23）

恢复不得把 `M07SupplyAdmissionPolicy.Input=null` 当成永久软件占位，也不得凭账本余量或首启核准直接放行。`TaskResumeIntentService` 在事务外取得本次 M02 固定 `asOf` 读数；`M07ResumeWriteBundle → M07ResumePreparationReader → M07ResumePreparationPolicy` 在锁定原执行、分段、资源、命令及当前物料后，将该批读数交给 `M07ApprovedResumeSupplyAuthority`。同一事务复核来源、原冻结规格、计量角色、质量、单位、归一化、预填充时序及当前新鲜度，再由原 `M07SupplyAdmissionPolicy` 比较 W−R。过程中不调用设备、不建立第二套量账、不以最终认可量代替当前液袋整体重量。

同袋恢复复用 `m07.approved-fixed-preparation.entries` 原有受控文件及原始字节 SHA-256 钉扎。来源 `schemaVersion=1` 仍可首启，但没有恢复供料核准；`schemaVersion=2` 必须显式给出 `sameContainerResume`：

| 字段 | 含义与限制 |
|---|---|
| `amountBasis` | `ORIGINAL_TARGET` 为原目标 T；`NOMINAL_REMAINING` 为 T−已认可累计量。必须逐来源明确核准，不默认选择；本实现不自行增加裕量。 |
| `comparison` | `AT_LEAST` 对应 ≥；`STRICTLY_MORE` 对应 >。必须明确核准，保留等于边界的差异。 |
| `amountBasisReference` | 可追溯的恢复比较依据，不得用首启名称隐式授权恢复。 |
| `approval` | 原 Proof 的 reference/revision/hash；必须完整且随原钉扎文件核验。 |

该软件输入只提供承载能力，不表示客户已选定比较口径。未确认项仍待确认；隔离测试必须标记 TEST 并显式提供测试核准，不成为生产默认值。来源文件到期、schema1、缺字段、当前来源不匹配或本次合格读数缺失均阻断。

同袋身份必须仍是原来源中的 sessionId、resourceKey、physicalItemKey，当前及上一段物料会话相同；复用原已核准 R 和预填充原件，使用当前锁定物料版本重新构造准入身份。唯一 FEED 账导致的会话版本增长不自动认定换袋，但物料身份改变不能借用原袋核准；换袋恢复仍需该新袋明确的预填充、残余量及比较核准输入，不能借此路径放行。
