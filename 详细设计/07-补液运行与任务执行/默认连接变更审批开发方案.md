## 范围与拥有方

控制器是否占用以 M03 有效占用事实为准。未指定培养且空闲时使用实验室默认连接并直接保存、无需原因；占用时反应器详情操作有效占用培养。明确操作草稿时，其固定泵属于该草稿，草稿关联不自动占用控制器。培养已设置固定泵时读取培养配置；未设置时带入实验室默认连接，首次保存写入该培养配置。培养侧修改不能回写实验室默认连接，也不能修改工艺模板。控制器、培养、实验室及相关占用的身份和版本必须在服务端重新核验。

空闲且未指定培养时，外置泵字段置灰且不可修改；其余可编辑字段保存至实验室泵默认连接。现有通道泵实例配置关联字段保持原值，也不能当作设备物理连接的证明。首次固定泵保存必须支持培养尚无完整补液方案的场景，不得编造补料或补糖规则。

## 培养固定泵事实

现有 FEEDING 参数槽位与快照要求真实补液流程节点，普通方案保存也会产生生效快照；因此它们既不能承载未勾选补液时的固定泵保存，也不能单独证明用户在默认连接入口保存过固定泵。由 M03 持有独立培养固定泵事实，以培养、实验室、控制器及稳定通道身份约束配置，并区分生效版本与待审核候选。只有保存生效后才产生可供 W03 使用的固定泵已保存事实；仅读取实验室默认值、提交候选或审核中均不视为已保存。

固定泵版本须保留实际提交的泵位与资源身份，并关联并发版本、操作者和请求回执；审批候选不可覆盖现行生效版本。未勾选补液时不创建补液节点或虚构计算规则；已有生效补液方案时，固定泵生效与保留其他规则的培养方案更新应在同一事务内一致完成。无生效方案时不能伪称已配置补液规则。草稿需核对培养自己的控制器关联；预约和运行还须核对有效占用身份和版本，变更或事实不可得时拒绝。具体表结构、审批决定和回执见 M03 固定泵连接事实字段契约。

占用培养的默认连接修改对应审批场景 `M06_SC026`（培养执行操作／设备信息／默认连接，来源 M07）。该场景在审批目录中为 OWNER_GATED，目录存在不代表已经支持发起、生效或撤回。培养补液方案及其快照由 M03 持有，M07 应通过 M03 拥有的内部契约完成候选读取、校验和生效，禁止直接操作 M03 内部 Mapper。`M06_SC048` 是补液方案候选场景，其现有入口要求精确工艺模板版本，不可借用来接收本弹窗的任意修改。

## 候选与审批

- 页面以稳定通道编号读取当前有效培养方案，候选仅包含固定泵对应的培养基、耗材、泵速策略和外置泵选择，以及必填原因；补料计算规则、补糖规则及其他未编辑字段取当前生效方案，不能由页面重建或覆盖。
- 培养尚无已保存的固定泵版本时，即使用户沿用当前显示的配置，首次点击保存仍须提交候选并按 SC026 策略处理；已有保存版本且配置未变化时不重复提交。审批通过并生效后才视为已保存，W03 的“已设置”还要求补糖计算配置完整。
- 服务端重验培养与计划版本、补液方案槽位版本和原生效快照、有效占用及物理泵通道集合；按编号校验完整性、主数据引用和型号能力。来源版本变化、对象不可见、占用变更或有未决候选时拒绝，不能回退到实验室默认配置。
- 创建不可变候选时固定变更前后内容、原因、原生效身份、来源与校验摘要，并从可信会话取得操作人。候选内容是培养自己的修改，不能伪装为原工艺模板版本；不改变模板及既有历史快照。
- SC026 的审批来源、候选引用和快照正文的 `ownerModule` 均为 `M07`，目标为 `CULTURE`；M03 仍是固定泵版本及事实的写拥有方，M07 通过内部契约获取和校验事实。每次变更使用新建的不可变 revision ID 作为 `candidateId`，该候选的 `candidateVersion` 固定为字符串 `"1"`；重试沿用原身份与内容，培养、计划、占用和状态版本分别核验，不能用候选版本替代。候选摘要使用 M03 候选信封摘要，不使用通道内容摘要冒充。
- 提交候选时，在同一守卫事务及一致性锁下读取真实变更前事实、核验并冻结变更后通道内容，生成审批审阅所需的前后快照并与该候选身份持久关联。前值按培养固定泵生效版本、培养生效 FEEDING 方案、实验室默认连接依次选择，仅在上一级明确不存在时选择下一级；存在但无法核验时拒绝，不能降级。真实方案须固定并核验快照、槽位、代次、应用回执和完整包；使用默认连接时固定其原始内容和来源身份，不能在审核时重读当前值。读取不到完整可信前值时拒绝送审。审阅快照中的培养、实验室、项目、批次、目标版本及候选身份须与真实申请和候选一致，原因使用实际提交值；展示名称取当时可信资源快照，缺失不得编造。快照与候选由 M03 同事务保存，M06 签审和应用时核对同一原件。
- M07 查询当前实验室对 SC026 的真实审批策略；需要审批时同事务建立候选和审批关联，现行方案保持不变。免审批时也必须经过同等身份、权限、引用和安全屏障核验，并由拥有方同事务生效；政策或必要事实不可用时明确拒绝，不伪造审批结果。
- 审核中再次进入时只读展示原候选和原因，按原审批权限提供撤回；撤回、拒绝不能改变现行方案。审批通过后使用可信决定投递，重新校验版本、占用和执行安全条件，经 M03 拥有方更新培养生效方案；任一条件失败不得部分生效。
- 写请求沿用管理守卫的请求 ID、管理版本和幂等回执；相同请求结果未知时保留原载荷、版本和请求 ID 恢复，不以新请求覆盖。审批前后和生效审计须关联同一候选身份。

## 已设置状态与验证

连接补料单元的“已设置”需要两个独立事实：本培养默认连接已成功保存，以及本培养已勾选补液并配置必要计算规则。读取当前控制器默认连接、创建候选或发起审批均不能冒充保存成功；审批通过但未生效也不能冒充成功。固定泵保存事实须由拥有方持久化或以可验证的现有事实证明，不能靠前端猜测；读取使用 M03 固定泵版本及其真实生效原件。

2026-11-06 用户明确：“已设置”不额外要求补液方案生效。W03 通过 M03 `W03ConfigurationStatusPort` 批量读取并核验当前培养的固定泵保存原件/回执、补液勾选及 `res_culture_feeding_config` 五项已保存规则；`planConfigured` 及“方案已设置”筛选使用这一展示事实。用户确认设备初始化后通道编号正常不可修改，该展示判断不附加当前通道映射比对，正常按泵号读取数据功能保持不变。存在审核中的新候选时，已核验的旧生效版本继续提供展示状态，不能把候选当成已保存。执行用 `selectable` 和实际提交准入仍独立核验既有开始完成、生效 FEEDING 方案、占用和设备条件；不改卡片样式、标签或旧默认连接写入口。v2 审批和政策直存分别核验真实批准或免审原件，不用草稿 v1 校验或空审批号代替。

实现应覆盖占用状态切换、跨培养访问、重复提交、管理版本冲突、候选与现行方案并发变化、审批通过／拒绝／撤回、免审批、设备与任务安全屏障及回滚。缺少设备或现场参数时只报告源码与契约验证，不能宣称设备联调通过。真实 HTTP 与浏览器验收独立记录。
