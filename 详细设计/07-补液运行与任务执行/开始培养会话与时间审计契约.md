## 6. 状态、取消与刷新重开

### 6.1 第4步是唯一业务保存点

两类流程均仅在第4步点击“完成”、校验通过且本地事务成功提交后，保存初始量、细胞类型/前缀、中试告警配置及完整开始培养记录。第2/3步“下一步”和第4步确认勾选不是保存按钮；表单仅保留于当前页面内存，不写服务器草稿表，也不写 localStorage/sessionStorage/IndexedDB 或持久化 Pinia。最终 COMPLETE 携带全量业务表单及证据引用，服务端重新校验，失败整单不保存。

正常同一页面会话内可前后切换步骤，保留当前内存输入；修改前序输入使后序校验/确认失效，需要重新校验。刷新、关闭后重进、明确取消都会丢弃未提交输入；两类流程均没有恢复至第2/3/4步的业务入口。旧原型“小试取消保留历史步骤”的保存点规则由本次确认取代。

历史设计曾在未完成阶段持久化运行实例及 FIRST_WORKFLOW_STARTED；按用户最新确认，小试和中试开始培养未完成时不持久化该流程及 FIRST，首次开始事实和完成事实在最终保存事务内处理。重新进入时系统核对并安全关闭本人旧流程；真实设备命令及其回执不能伪造或凭数据库回滚撤销。当前 cloud 代码不会关闭旧会话，系统安全收尾目标仍需实现与验证；本条不改变其他工作流的审计或设备安全要求。

沿用工作流 state=OPEN/IN_PROGRESS/COMPLETED/CANCELLED/NEEDS_RECONCILIATION，以及步骤 PENDING/IN_PROGRESS/COMPLETED/SKIPPED/CANCELLED/UNKNOWN；不增加培养状态。interaction_state仅ACTIVE/CANCEL_REQUESTED/CLOSED，新增page_session_id、cancel_request_id；不再为开始培养新增SUSPENDED、resume_step_code或RESUME动作。

| 事件 | 工作流/交互态 | 步骤与用户可做事项 |
| --- | --- | --- |
| START提交成功 | IN_PROGRESS / ACTIVE | 第1步通过，第2步进入；绑定本次pageSessionId |
| 同会话下一步 | IN_PROGRESS / ACTIVE | 当前步通过/跳过，保留最小校验摘要；业务表单仍仅在页面内存 |
| 未完成时取消或刷新重开，已安全闭合 | CANCELLED / CLOSED | 旧步骤只作审计；旧会话失效，页面回第1步，新尝试重新填写 |
| 取消或刷新时有在途动作 | IN_PROGRESS / CANCEL_REQUESTED | 页面回第1步，提示旧操作安全收尾中；不能开始新动作 |
| 停止/重启结果未知 | NEEDS_RECONCILIATION / CANCEL_REQUESTED | 保留占用及命令证据，只允许查询、停止及对账 |
| 旧动作安全对账完成 | CANCELLED / CLOSED | 关闭旧尝试，可按当前当天准入从第1步新建；不是恢复旧步骤 |
| 第4步完成事务成功 | COMPLETED / CLOSED，application_state=APPLIED | 保存完整业务数据；之后刷新显示已完成只读记录，不重复创建 |

正常未提交阶段application_state=NONE。数据库提交失败全部业务写回滚；物理动作不会回滚。结果未知先查原完成requestId，禁止未查清就取消已提交成功的流程或重建一次。

### 6.2 取消、刷新与页面会话

| 场景 | 保留 | 丢弃/失效 | 下次入口 |
| --- | --- | --- | --- |
| 第1步尚未START，刷新/取消 | 无培养运行实例；保留第1步页面会话时间审计 | 设备选择、页面输入 | 第1步 |
| 小试或中试第2/3/4步未完成，取消 | 启动/操作审计和真实设备证据 | 全部未提交表单、配置意图和本会话校验；无中间保存点 | 旧尝试安全关闭后，从第1步新建 |
| 小试或中试第2/3/4步未完成，刷新/重新进入 | 同上；原实例仅用于查询和安全关闭 | 所有未提交输入、当前步骤和勾选不回填 | 立即显示第1步，旧尝试未闭合前禁止新的START |
| 刷新时第4步完成请求在途 | 原请求号、原实例及实际提交结果 | 不自动重发为新请求，不先认定取消 | 查询后：已完成则只读；未完成且原请求被关闭则第1步；未知则等待对账 |
| 完成已成功后刷新 | 全部已保存数据和原完成回执 | 无 | 已完成记录只读，不重新开始培养 |
| 完成与刷新重开/取消竞争 | 实例版本锁决定一个赢家 | 输方无业务副作用 | 完成赢则只读；取消赢则旧会话完成请求拒绝 |

前端每次进入向导先按保存的控制标识调用SC-HTTP04查询原请求、M07-024/SC-HTTP01查询原尝试。已完成则直接只读，不创建多余页面会话；尚未完成时显示第1步空表单，并通过SC-HTTP03 OPEN登记新页面会话，由服务端生成pageSessionId及第1步开始时间。新会话可以记录等待收尾的时间，但旧尝试未关闭前不得START。普通接口重查、轮询、读取managementRevision不属于页面刷新，不丢当前内存输入；浏览器刷新、组件销毁后重新进入才按本节重开。

sessionStorage只保存labId、workflowKind、requestId、实例/组ID、pageSessionId等控制标识，不保存表单、原业务请求正文或可恢复步骤数据。任何OPEN/START/COMPLETE发出前先记录其requestId，防止响应丢失后无法查询；重复OPEN使用原requestId，不生成多个审计会话。无控制标识时按有权范围查活动尝试，不借刷新自动取消其他用户/其他标签页；先阻断并走有权取消入口。服务端绑定actor、lab及会话，客户端ID不是授权凭证。

SC-HTTP04查询只返回请求身份、状态、关联对象和最终回执，不返回未完成表单。明确APPLIED后读取原结果；REJECTED允许用户在同一有效会话明确修正后用新请求；PENDING/UNKNOWN必须查询或对账。NOT_FOUND只表示当前未查到，不证明迟到的原请求不会执行，不能据此重发业务动作。刷新后已丢原正文，仅可查回执/关闭旧会话，不以空表单冒充原正文重放。**2026-11-03 现状订正：本段是按语义状态给出的客户端处置规则；当前实现只产出 `UNKNOWN`（查不到回执行，含 `reasonCode=ORIGINAL_REQUEST_NOT_SETTLED`）与 `APPLIED` 两态，`REJECTED`／`PENDING` 尚无实现产出，`NOT_FOUND` 在本口是拒绝码而非状态取值。因此本段规则描述的是语义约定，不是当前可读到的状态全集。**

关闭旧会话与旧START绑定必须共用会话锁：未绑定时SC-HTTP03 CLOSE原子关闭并使迟到START失效；已绑定时CLOSE返回SESSION_BOUND和有权可见的实例/组引用，随后单实例用027、批量用SC-HTTP02 CANCEL，reasonCode=PAGE_REFRESH。若原完成并发成功，则关闭/取消返回已完成回执；若关闭/取消赢，则旧会话的步骤/COMPLETE全部拒绝。不能把NOT_FOUND变成成功关闭凭证。旧动作未知时会话先失效、物理资源仍保持占用，安全闭合后才允许新START。

GET无副作用，不依赖beforeunload/sendBeacon一定送达；真实刷新发生在浏览器，服务端只能以收到受管关闭/取消事务的时刻判定竞争结果，不伪称能撤销此前已提交完成。所有正常写动作必带pageSessionId，安全STOP/取消恢复依据原operationId与当前合法安全用途执行，不因业务会话失效而失去停止通道。

历史实现中，小试组取消或刷新按整组收尾，全部安全后batchState=CANCELLED，不再DISSOLVED后拆成单台续做；重新开始可重新选择设备批量，并通过restartedFrom关联旧审计。按最新确认，重新进入时系统核对并安全关闭本人旧流程，未完成开始培养不产生此次 FIRST；M03占用及真实设备状态仍按各自安全规则处理，不将数据库取消等同于设备动作撤销。系统安全收尾目标仍需实现与验证。

页面从头开始不等于重新进行人工接种或设备动作：展示已发生动作的只读提示，避免重复操作；填充仍可在满足安全条件后显式跳过。需要重新排期走M03现有合法流程，不自动调整旧实例deadlineAt，也不放宽当天完成限制。

#### 6.2.1 步骤动作与退回规则

| 动作 | 允许位置与条件 | 状态及证据变化 |
| --- | --- | --- |
| START | OPEN页面会话、第1步，尚无绑定；同日准入通过 | 绑定固定实例/组；关闭第1步访问、打开第2步；不得对已绑定会话再造实例 |
| VALIDATE_NEXT | 当前第2/3步，或已绑定尝试退回后的第1步；后者只核验冻结成员，不再调用START | 先全量校验再关闭当前访问/打开下一步；缺字段不推进；第4步禁止此动作 |
| BACK | 第2→1、第3→2、第4→3；不得跳步；全组无未决填充/重启等物理操作 | 当前访问以BACK结束，目标步新visitNo；目标步IN_PROGRESS，后续步PENDING，原访问历史保留 |
| SKIP | 仅小试当前第3步且物理安全闭合 | 登记本访问skipIntent；等正常NEXT/组推进时将该步记SKIPPED并结束计时，不提前跳至第4步 |
| CONFIRM | 仅当前第4步；类型须属于该kind，证据新鲜 | 保存最小确认审计引用，不结束步骤或保存业务表单；组内确认仅更新对应成员版本及组版本，不切换共享访问 |
| COMPLETE | 仅当前第4步，各前序本轮校验有效；显式用户点击 | 全量输入/证据重验，原子保存；失败不结束第4步 |
| CANCEL | 任一未完成位置 | 关闭当前业务访问、使会话失效，物理安全收尾独立完成；最终CANCELLED |

BACK不撤销已发生的泵/重启动作。若存在未决物理操作先留在当前步查询/停止；不得回退再发同一动作。返回前序使目标步及其后所有validationHash、skipIntent、确认谓词绑定失效，重新前进必须重新校验/显式选择跳过；真实操作历史仅用于安全核对，不作为新一轮自动确认。中间请求使用当前visitNo、expectedStepVersion及本次payloadHash，最终提交逐步核对同会话最新有效摘要与定义/来源版本；仅前端修改后未重新校验的表单不能COMPLETE。

### 6.3 到日截止与在途请求

- 截止时未完成的实例保留原步骤和审计，派生 deadlineReached=true、blockReason=START_DAY_EXPIRED、候选mode=READ_ONLY、allowedActions仅查询/取消/安全停止/对账；不将业务工作流标为COMPLETED，不把培养直接取消或删除。两类未完成记录均仅供审计与安全收尾，次日不能继续或从头补做。
- M07负责截止检查及可恢复的安全收尾：写口与执行器派发前双重检查，避免午夜前排队的START/RESTART午夜后才执行。已调用/未知的设备动作按原命令身份停止、查询和对账；安全STOP与监控不能被日期门禁禁用；用户失权仍拒绝其手动写，由已登记固定安全用途的M07执行器继续收尾，不使用过期用户身份或前端伪造SYSTEM。安全证据不足继续保留资源及UNKNOWN，不因跨天释放占用。截止扫描迟到不构成宽限期，写口/派发守卫独立生效。
- 新的COMPLETE以锁后、最终生效写入前的服务端权威时间判定，并在所有待提交写入后、COMMIT前的最后数据库日期守卫再次比较deadlineAt；排队/事务跨零点且最终守卫已过期则整组业务提交回滚。不得采用客户端点击时间、请求到达时间或回填前一天时间。完成记录、事件与回执共用第8节第5步取得的完成时间，末尾守卫只复核截止、不重写已生成事件；页面回包晚到不是新的完成动作。
- 若当天已经真实完成并持久提交，仅HTTP回包或查询发生在次日，允许有权用户读取原完成回执；幂等重放先识别已提交的原回执，不再次写入。当天尚未完成的旧请求次日重发仍拒绝；真实设备回执晚到只能补操作证据，不能据此补写START_COMPLETED。
- M03按完整工作流完成事实判定状态；无完整完成在次日过期，已有其他完整流程且已选开始培养仍未完成则延期，未选开始培养不查开始延期；过期释放主容器预约不证明设备已停；不因禁止续做自动清延期，也不通过改变培养状态解除本实例日期门禁。

### 6.4 每个步骤的开始和结束时间

业务保存与时间审计分开：两类四步都必须记录startedAt、endedAt、endReason、actorId、pageSessionId/attemptId、visitNo。时间由服务端在步骤转换事务中取得，数据库UTC、精度毫秒，页面按Asia/Shanghai展示。客户端时间只可作辅助线索，不能覆盖权威时间；第4步成功前不保存业务表单的规则不变。

| 步骤 | 开始时间 | 结束时间 |
| --- | --- | --- |
| 第1步 START | 页面会话OPEN在服务端受理时；尚未选培养时先记会话审计 | 选择设备并成功提交START时；同事务建立实例并关联本次会话第1步记录 |
| 第2步 INOCULATION | 第1步成功结束并进入第2步时 | 校验通过并实际进入第3步时；校验失败不结束 |
| 第3步 SAMPLE_PRIME / ONLINE_ALARM_CONFIRM | 第2步成功结束并进入第3步时 | 校验/安全条件通过后进入第4步时；小试跳过标SKIPPED。组内单行跳过不提前结束该行步骤，统一组推进时记录结束 |
| 第4步 DEVICE_CONFIRM / OPC_CONFIRM | 第3步成功结束并进入第4步时 | 仅点击完成且事务成功时结束，使用最终completedAt；勾选确认、OPC恢复或提交失败均不算完成 |

一次成功的下一步转换使用同一服务端时间关闭当前步并打开下一步；小试批量同一转换内所有成员使用同一时间，逐设备命令时间另记。分别记录startedBy和endedBy；系统中断使用可信服务身份。已有actor_user_id只作兼容投影，不能覆盖两端身份或统一为最后提交人。

同一会话返回前一步必须经BACK命令记录：关闭当前访问endReason=BACK，前一步新建visitNo+1的访问记录；不覆盖上次开始/结束时间。返回第1步仅查看原冻结成员；要更换设备/培养必须取消原尝试后重新选择，不能原地替换实例归属。修改前序输入后重新进入后序同样新增访问并重新确认，不复用旧确认。访问记录才是时间历史权威。run_workflow_step.started_at投影为该实例此步骤首次进入时间；当前访问仍进行中或未确认结束时ended_at=null，已结束时投影最近一次访问的结束时间，同时返回currentVisitNo和endReason；不得以旧ended_at展示重入后的当前步已结束。概览跨度不是有效操作时长，耗时按已闭合访问段分别展示。

取消或刷新使当前未结束访问终止，endReason分别CANCELLED、PAGE_REFRESH；没有开始的步骤两时间保持null，已结束步骤时间不改。若服务端只在刷新后收到关闭旧会话请求，endedAt记录服务器确认中断的时间，endTimeBasis=DETECTED_INTERRUPTION，并显示“中断确认时间”，不得冒充精确刷新/关页时刻。未取得结束/中断事实时endedAt为null、显示未确认，不能填最后心跳、零值或第4步完成时间。正常转换使用endTimeBasis=SERVER_TRANSITION；中断检测时间不表示泵已停止，safeClosedAt单独记。

时间键固定为(pageSessionId,stepCode,visitNo)，三者均非空；不把可空workflowId放进唯一键。第1步尚无培养时归页面会话，START后各实例通过关联表引用同一会话访问；小试批量共用步骤转换访问，实例的started_at/ended_at是该引用的投影，不重复造多条第1步访问。命令实际开始/结束仍按设备各自记录。visitNo由服务端在会话锁下递增；开始有requestId，结束有独立endRequestId，重复请求不多建访问。

批量中部分成员跳过、部分完成填充时，不能把共享访问统一标为SKIPPED。共享第3步访问以NEXT结束，实例关联记录分别保存memberOutcome=COMPLETED/SKIPPED及证据引用；实例详情将跳过成员的结束原因投影为SKIPPED，其余为NEXT，起止时间均引用共享访问。中试和其他步骤不接受SKIPPED。步骤当前态仍按本轮访问与成员结果投影，BACK作废本轮结果但保留历史关联。

结束原因枚举：NEXT、COMPLETED、SKIPPED、BACK、CANCELLED、PAGE_REFRESH、DEADLINE_EXPIRED；缺少实际结束/中断事实则endReason/endedAt均null。步骤访问状态由是否闭合派生，不将BACK等原因塞入现有步骤state枚举。时间条件、元数据与必填/可空约束须在SC-01中同批落字典和DDL。跨零点由截止事务首次确认中断时记DEADLINE_EXPIRED/DETECTED_INTERRUPTION，不回填成精确00:00结束。

刷新新建新pageSessionId/attemptId，从第1步重新计时；旧尝试包括各步时间保留于操作历史，不回填新尝试。已完成请求回包丢失时只读取原记录，不重复结束第4步或改写任一时间。重复NEXT/BACK/CANCEL/COMPLETE请求通过requestId和步骤版本去重，不多建访问、不重写endedAt。截止前后、刷新与完成并发仍按实例/组守卫决定唯一结果。
