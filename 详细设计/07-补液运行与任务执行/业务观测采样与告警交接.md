## 2. 收件与来源身份补齐
内部RUN-OBS-I01 appendExecutionSample接收原sample DTO及采样来源证据，必须匹配已有execution/segment的设备、配置、adapter身份和fence；source_sequence≤128固定为适配器规范采样身份的SHA256十六进制，输入身份包含adapterInstanceId/sourceBootId/sourceEventId/设备通道/执行ID。旧稳定序列不重编码；启用新模式的run_execution.execution_spec采用schemaVersion=2，保留原ExecutionSpec全部字段和resourceClaims，新增sampleIdentityVersion:2并纳入spec_hash。仅新执行写该版本，旧schema1不补键，禁止在同一执行中混用键规则。

2026-10-15 经用户明确确认允许调整冻结载体：`ExecutionSampleCommand` 显式携带 `executionId、segmentId、sourceSequence、observedAt、stage、quality、payloadHash、samplePayload`。其中 `sourceSequence` 为64位小写SHA-256文本，不再使用无法表达v2身份的 `long`；四个原本不可派生的目标表必填列由调用方显式提供。`sample_id/received_at` 由服务端生成，`sample_hash` 从已重算一致的 `payloadHash` 解码，`raw_readings` 由通过固定v2 schema校验的 `samplePayload` 原文落账。该调整不改变 `ExecutionSamplePort#appendExecutionSample` 方法签名，但属于共享DTO契约变更，提供方、调用方和门禁必须同批更新。

sample.raw_readings 新增schemaVersion=2模式，保留v1全部叶子，增加：
sourceEvidence={identityVersion:2,sourceInstanceId,sourceBootId,sourceEventId,packetHash:64hex,rawPayloadRef:受保护引用,configurationRevision,sourceSequenceText:null|string,ownerModule:M07,readings:[{index:int,channelCode,sourceRevision,sourceObservedText,sourceTimezone:null|string,sourcePrecision,sourceRef:null|SourceRef}]}。
readings证据数组按原readings下标完整一一对应，长度/索引严格校验；来源详情不自动向浏览器输出。新模式不是允许向schema1塞未知键。旧数据双读v1/v2，v1缺失证据显示UNKNOWN，不补造boot/event。新写仅在消费者支持v2、执行规格固定v2后启用；不改变其他JSON列的schema。

同(execution_id,source_sequence)同hash返回原sampleId，异hash不能覆盖原样本；在run_event追加SAMPLE_CONFLICT（object_kind=EXECUTION，新增允许值）及受保护冲突原包引用，source_event_key取冲突身份+hash的规范SHA256，长度≤128。冲突使该采样失去可信准入，安全动作按核准故障策略执行，不等M09响应。合法样本/业务判定事件同事务保存；ACK丢失以原身份查询/重发，不生成新的执行。

数据库或证据落盘失败不能成功ACK；适配器持久待发，失去及时可信观测按原fail-safe处理。无法保证落盘/停止能力的设备路径不启用，不因本包文档完成而开放。原样本DATETIME(3)精度不扩大本轮DDL，原始精度保存在v2证据；亚毫秒先后不得仅靠截断后的observed_at推断，按核准sourceSequence和证据处理，时序不明则UNKNOWN。

发送器取payload.m09Event交给M09 INT01。M09 sourceModule=M07，sourceEventId=run_event.event_id，sourceObject={module:M07,kind:OBSERVATION_MONITOR,id:conditionKey64hex,version:sequence,hash:证据hash}，sourceVersion/sourceSequence=sequence。原run_event可靠发布状态和恢复规则保持；M09 Fact/QuantityRef/CommandEvidence仍是既有v1，外层run_event payload v2不要求M09接受新Event schema。

评价锁monitor，校验phase/ownerEpoch/持久输入身份；重复采样或重复缺测时间槽不多加连续次数。同condition跨进程重启保持sequence。持久化evaluationVersion、consecutiveCount、lastSlotKey、lastSampleRef及最后评价水位，不使用Redis丢失后从0开始的计数充当持续告警依据。核准profile或阶段证据缺失UNKNOWN，不凭字段名发停泵指令。

M02仅生产非运行通用条件，M07负责已绑定运行/连接会话条件；交接phase时固定ownerEpoch，旧生产者迟到输入拒绝推进当前监控。当前物理执行安全循环只依赖M07核准策略，不被M02/M09/M08网络回执阻塞。非运行监控ON/TEMP_OFF/LONG_OFF与执行安全停止仍分离。

## 5. 迁移与验收
已有sample v1只读保留、不批量伪造新来源字段、不重算历史泵量。v2先双读验证，再对新执行启用；执行中的旧版本保持原identity规则直至结束。回退先停止启用新执行，不能在v2执行未结算/命令UNKNOWN时降级到不认识该证据的程序。

验收覆盖：同键同hash、异hash保留；adapter重启/序列重置；旧fence；DB失败和ACK丢失；亚毫秒时序；v1/v2双读；跨模块真实来源权限；monitor重启恢复与重复时间槽；M08停机期间曲线/台账可查；M09失败不影响安全动作。所有用例仍待执行，见[联合迁移核对](../history/review/00-业务观测独立交付与迁移核对.md)。

### STOP-H08：历史段迟到样本与冲突隔离（2026-10-21）

本批单元和 MyBatis 映射验证覆盖原段保留、关闭后幂等、冲突原包、原身份失败关闭、原执行待对账及不改新归属。实际 MySQL 回滚/并发、监控来源生产、完整对账动作及 A/B 现场交接仍须分别验收。

| event_type | result 固定字段 | source_event_key |
|---|---|---|
| MONITOR_EVIDENCE_RECEIVED | schemaVersion:1、registrationHash、registrationId、完整 identity、完整 JournalFact entry、pageSource、sourceStorageHealthy、coverageState:UNKNOWN | `M07:MONITOR_EVIDENCE_RECEIVED:`＋`SHA256(registrationHash+"\|"+position)` |

| MONITOR_SAMPLE_EXCLUDED | schemaVersion:1、registrationHash、entryHash、reason（仅 BEFORE_SEGMENT_INVOKED、PREVIOUS_SEGMENT_BEFORE_CONTINUATION_INVOKED 或 PREVIOUS_EXECUTION_BEFORE_START_INVOKED）、exclusionBasisHash、originalInvocation（字段见数据库JSON契约） | `M07:MONITOR_SAMPLE_EXCLUDED:`＋同上位置身份摘要 |

payload_hash 仍覆盖整个规范信封。RECEIVED 只证明 M07 事务收到原件；PROJECTED 只证明唯一采样 Port 返回 APPENDED/DUPLICATE 且无冲突；EXCLUDED 只证明该原观察不在本段运行时域。三者均不证明物理停止、原段连续观察完成或资源可释放。缺资格生产者、sourceEventId/时区精度/归一化/实际运行时长时，原件可收而样本投影保持 BLOCKED_METADATA；原文保留，可在资格补齐后按原位置重放，不补造 sourceSequence。数据库失败不返回成功 cursor，停止保护不依赖业务收件成功。

每次已验签分页收件（包括空页）在原事务内按 registration 原 journal position 从旧到新扫描最多100条待投影原件；这是单次处理上限，不是设备参数或允许漏包数。原件游标和采样资格分离：STOP 等命令尚未形成合格回执时可以继续保存原件，但最旧未决观察原则上阻断后续样本推进；仅本契约明确列出的首启前、前命令和窄续段调用前未决分类可继续检查后包，旧包仍不投影，避免先写后包导致旧 activeMilliseconds 永久回退。原回执到达后用同一资格生产者、同一唯一采样 Port 再验原身份、命令、阶段、时间、计数和全部原读数；不改历史计数、阶段或源序列。旧数据已经被后样本越过时保持阻断/对账，不能补造旧计数来填覆盖。

上述重投影限于可追加样本的原段。锁定原 context 已为 `CLOSED` 时，仍核验原覆盖身份/fence、原命令来源、分页链及完整原件，持久化原件后返回真实收件游标和 `ORIGINAL_SEGMENT_CLOSED`，不再查询原调用或待投影队列。已关闭段不能追加样本；暂停后的停止观察进度由 `M07StopMonitorProgressProducer` 直接读取同一 `MONITOR_EVIDENCE_RECEIVED` 原件，独立执行 `qualifyStopObservation`，不依赖 PROJECTED 回执。该优化不停止独立监控、不改变认可量，也不解除资源、恢复或停止确认门禁。

启动前原包排除依据中的两种摘要分别核验：命令 `payload_hash` 必须等于原登记的 `commandPayloadHash`；`resultEvidence.payloadHash` 则是结果证据删除自身 `payloadHash` 字段后的规范 JSON SHA256，必须重算并与结果自身声明值比较。二者不能混比，也不能把命令摘要复制到结果中替代完整性校验。排除事实 `originalInvocation.commandResultHash` 仍记录完整原结果（含自身摘要）的规范 SHA256，用于后续重验及冲突检测。原命令身份、实际调用时刻、回执身份和双 ACK 条件全部保留。

EXCLUDED 仅记录已经证明处于本段起始调用之前的原观察，不删除原件、不写有效样本或补观察覆盖。须完整验证原登记和双ACK，绑定初段原 START 或续段原 SET_SPEED 的实际已执行命令、payloadHash、结果证据及原 invokedAt；同包全部读数身份、GOOD质量和原时刻合格，observedAt 加核准时钟误差及 receivedAt 均严格早于 invokedAt 才可排除。命令 UNKNOWN、缺ACK、跨调用边界、来源未知或缺读数均不可排除。排除依据和原件绑定摘要持久化，依据改变不能借旧排除标记跳过。CLOSED 原段仍仅保留原件，排除事实不重开原段、不改量账。

续段准备时，独立监控可先收到设备仍属于前段的原观察。仅当 `ownership=MISMATCH`、`observedIdentity` 完整等于原 `ContinuationRequest.previousIdentity`，且该请求、双 ACK、已执行原 SET_SPEED 及其 requestId/hash 全部一致时，允许记录 `PREVIOUS_SEGMENT_BEFORE_CONTINUATION_INVOKED`。外层观察时刻和全部读数加核准时钟误差，以及全部 receivedAt，都必须严格早于新段原 invokedAt；跨越或等于边界、坏质量、UNKNOWN、其他执行/段/fence/资源仍阻断。原 MISMATCH 不改为 MATCH，该排除不贡献有效样本、运行时长、停止覆盖或量账；后续 MATCH 原观察仍须经过正式资格生产者及唯一采样 Port。原前段身份、前段登记 ID 和完整 continuationHash 一并纳入排除依据；依据缺失或变化不复用旧排除，不改历史原件。

2026-10-24 新执行接管前原包排除：新执行登记后、原 START 实际调用前，设备可能仍报告已释放的上一执行身份。仅在全部原资源的前一 fence（恰为新 fence−1）指向同一个历史释放原件，原登记、认可结算、资源释放、外部 gateway/monitor 双 ACK 经原交接投影完整核验，且双 ACK 不晚于新登记时刻时，才允许使用该历史身份。原、新执行必须不同，设备、控制器、适配器、配置、主资源和完整资源集合必须一致，每项 fence 恰递增 1。`ownership=MISMATCH` 且 observedIdentity 完整等于该已释放身份，外层 observedAt、全部 GOOD 读数加核准时钟误差和全部 receivedAt 均严格早于新 START 原 invokedAt，才记录 `PREVIOUS_EXECUTION_BEFORE_START_INVOKED`。原件即使迟到仍完整保留；不能改成 MATCH，不贡献样本、运行时间、覆盖或量账。新 START 必须具有已执行原结果、新登记与双 ACK，未知结果、未释放或缺 ACK、等于/跨越调用边界、坏质量及其他身份继续保护阻断。

### 异常业务状态、可信量和设备释放的交接（2026-10-21用户确认）
