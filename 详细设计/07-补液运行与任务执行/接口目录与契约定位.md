## 2026-11-05 培养固定泵来源只读入口

`GET /run/cultures/{cultureId}/pump-connection-source` 要求 `resource:culture:query`；M03 来源口另按可信操作者核验培养对象与实验室查看范围。返回真实来源：已核验保存原件与回执的 `SAVED_REVISION` 附 `savedChannels`、`saved=true`；`FEEDING_PLAN` 附 `feedingPlan`，或 `DEVICE_DEFAULT` 附 `defaultChannels`，后两者 `saved=false`。设备默认的培养基、耗材和泵速策略以 `value` / `MISSING` 或 `UNVERIFIED` 原样返回；页面按当前统一主数据的 ID 匹配名称，仅供展示，查不到时显示空值，不代表服务端已核验或固定泵已保存。培养、设备、版本、通道及占用身份以十进制字符串返回。活动候选或生效回执不可核验时拒绝读取，不退回默认值、不伪造保存成功；不改变固定泵或审批状态。仅为源码与契约，实际 HTTP 和浏览器验收状态另计。

`PUT /run/cultures/{cultureId}/pump-connection/draft` 要求 `resource:culture:edit`，接收 `X-Request-Id` 和该模块读取口获得的 `X-Management-Revision`。正文为 `expectedCultureVersion`、`expectedPlanVersion`、可空 `expectedStateVersion`、可空 `expectedEffectiveRevisionId`、可空 `reason` 及完整 `channels`；逐项包含 `channelId`、`pumpNo`、`mediumId`、`consumableId`、`speedKind`、`speedCode`、`strategyId`、`sourceTemplateId`、`sourceVersionId`、`externalPumpId`，细节由 M03 固定泵契约和拥有方校验。培养 ID 只取路径；权限、培养及实验室范围、并发、幂等、审计和唯一事务均由 M03 端口执行，不嵌套管理守卫。仅支持草稿且没有生效补液方案，不操作设备、不创建补液方案或审批；返回 `revisionId` 与 `replayed`，响应顶层管理版本由实际守卫提交回填。请求不允许提交可信名称、快照或决定回执。

来源读口的 `effectiveRevisionId` 仅在 `SAVED_REVISION` 时是已核验的正整数十进制字符串，其他来源为 null；再次草稿保存须将它原样作为 `expectedEffectiveRevisionId`，与同一读取结果的 `stateVersion` 及管理版本一起提交，不能从候选或快照猜测。

### 设备运维对象范围的授权口径（2026-10-12 用户确认，来源等级【已确认】）

本段原写「复用设备运维授权」，与[物理接口与骨架字段设计.md](物理接口与骨架字段设计.md)第 4 节「不再使用『复用设备运维授权』作为不可实现描述」**自相矛盾**，本轮按已确认口径统一修正：

**移交权限须同时满足三条**，缺一即拒绝整组移交：

1. **有执行器移交功能权限**（`run:executorAssignment:transfer`）——允许进行该动作；
