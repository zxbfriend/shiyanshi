# 独立补料监控进程与保护通道契约

> FEED-SAFETY-V1；Java 17 软件协议。关联统一方案 CL-03、CL-04、PAR-05～PAR-10、PAR-14。本文件定义软件边界和验证方法，不代表客户参数已核准、设备能力已验证或现场已启用。

## 1. 模块与职责

| 模块 | 职责 | 禁止承担的职责 |
|---|---|---|
| `futurefab-api-feeding-safety` | 版本化事实、严格 JSON、规范摘要、内部签名和有界 HTTP 客户端 | 不包含任务状态机、量账、设备默认参数、Spring 或数据库客户端 |
| `futurefab-feeding-monitor` | 独立进程保存活动保护副本，核验原始读取身份/质量/时效，监督控制进度和首反馈，提出 STOP、保留原始证据 | 不发 START/SET_SPEED，不计算认可补液量，不凭健康恢复解除保护，不自行授权网关注册/释放 |
| `futurefab-feeding-gateway` | M02 独立实际写入入口；受控登记、独立读取、停止锁定与正常命令仲裁，持久化原请求/原锚点并返回事实 | 不根据监控请求生成虚构 M07 commandId，不把 STOP 接收状态当物理停料证明 |
| M07 业务执行侧 | 冻结原执行/原命令、取得受控登记回执、提供真实进度/首启来源，归并停止、量、观察、未决命令和释放证明 | 不以调用时间替代设备发生时间，不以 HTTP 健康或 M09 通知回执替代物理停止/业务收尾 |

三模块使用相同版本坐标，仅通过 reactor 聚合，不继承根 POM 的业务 bootstrap 依赖，不读取 system 开发配置。现 P2 监控启动器显式要求 `monitor.maximum-active-bindings=1`；这是单执行隔离验证范围，不代表多设备吞吐、全站周期或现场容灾已通过。

## 2. 身份、批准与严格输入

- `ProtectionIdentity` 固定 executionId、segmentId、normalControllerId、adapterInstanceId、configurationRevision、deviceRef、primaryResourceKey、fence、specHash 和完整 resourceClaims。所有业务 ID、配置版本及 fence 使用十进制字符串；无通道设备的 channelCode 显式为 null，不能补成 `"-"`。
- `MonitorProfile` 固定 profileId/revision、批准来源和全部显式时间参数：pollInterval、requestTimeout、maximumClockSkew、maximumSampleAge、maximumControlGap、firstFeedbackTimeout、stopConfirmationTimeout，以及 requiredMetricCodes。缺失、零值或负值不能获得新执行资格。已有停止意图不得因新配置缺失而重置原期限。
- `ReadStopAuthorization` 固定批准的 pathId、完整资源集合、有效区间和来源。HMAC 只证明通路身份和载荷完整性，不能代替能力批准。
- 监控启动配置绑定完整 profile 摘要、完整读取/停止授权摘要及时钟批准摘要。登记全量值必须吻合；注册、恢复连通或健康成功均不能自行生成能力批准。
- JSON 为封闭 schema 1：拒绝未知字段、重复键、尾随文档/标量、数字/字符串隐式转换、整数版本溢出和未知枚举。Instant 保留全部精度；集合复制为不可变值，不能在签名或持久化后改变资源集。
- 规范 JSON 使用字典序对象键、声明顺序数组、显式 null、UTF-8 和 ISO 时间/Duration。摘要不包含其自身签名或摘要字段的递归输入。protectionKey 对完整保护身份计算，其中 resourceClaims 按 resourceKey 排序；原事实/请求摘要覆盖完整规范载荷。

## 3. 路由与身份权限

统一前缀 `/feeding-safety/v1`，POST；身份来自部署配置的独立 clientId/key，不由 body 选择。不同角色/通路不能共用密钥，避免持有 MONITOR 通路密钥的一方签名冒充 M07。

| 接收进程 / 路由 | 调用身份 | 输入 / 输出 | 意义 |
|---|---|---|---|
| 网关 `/register` | M07 | Registration / RegistrationReceipt | M07 先完成受控网关登记 |
| 网关 `/verify-registration` | MONITOR | 原 Registration / 匹配的 RegistrationReceipt | 只核验已有持久登记，不新增或改绑 |
| 监控 `/register` | M07 | Registration / RegistrationReceipt | 本地副本持久化且匹配网关原登记后返回 durable=true；两处 ACK 缺一不得 START |
| 监控 `/progress` | M07 | ProgressUpdate / ProgressReceipt | 原身份、递增序列及来源事实；不是健康心跳。倒退/未来时间不能重置期限 |
| 监控 `/actual-start` | M07 | FirstStartUpdate / FirstStartReceipt | 原 firstStartCommandId、真实发生时刻及来源；重复幂等，冲突保留原件并保护 |
| 网关 `/read` | 配置允许的 MONITOR/M07 | ReadRequest / Observation | 独立读取；须匹配完整当前身份，UNKNOWN/MISMATCH 不能确认原对象可控制 |
| 网关 `/stop` | 配置允许的 MONITOR/M07 | StopRequest / StopReceipt | 稳定保护键和不可变请求键；返回原首次意图/期限及原载荷摘要 |
| 网关 `/release` | M07 | ReleaseRequest / ReleaseReceipt | 网关核验受控交接及自身原命令事实 |
| 网关 `/verify-release` | MONITOR | 原 ReleaseRequest / 匹配的 ReleaseReceipt | 只核验已发生的 M07 网关交接，不授权解除 |
| 监控 `/release` | M07 | ReleaseRequest / ReleaseReceipt | 原身份/摘要匹配网关持久 ACK 后，才持久解除活动保护 |
| 监控 `/evidence` | M07 | EvidencePullRequest / EvidencePage | 只导出原 registration 的可验证原件；收件 ACK 不代表样本合格或观察完整 |

请求头为 X-Feeding-Client、X-Feeding-Timestamp、X-Feeding-Nonce、X-Feeding-Signature。请求/回执分别使用 FEED-SAFETY-V1-REQUEST / FEED-SAFETY-V1-RESPONSE 域；签名绑定 clientId、POST、精确路由、完整时间、nonce 和 body SHA-256。监控拒绝重放 nonce 及重复认证头。客户端不跟随重定向，单次请求以显式超时覆盖整个响应体，上限 1 MiB；未知结果保留原请求身份，不自动换键。远端必须 HTTPS；当前进程入站仅监听显式 loopback，跨主机部署还需核准 TLS 入口。

## 4. 可靠副本与停止锚点

1. ProtectionJournal 使用排他文件锁、规范载荷、链式校验和、追加及 force(true)，先持久再发成功登记回执；不是第二套业务状态机或量账。
2. 重启重放可验证前缀。末尾损坏不能抹掉此前可靠活动；未知/被修改记录不能猜成设备绑定。损坏或存储满时阻断新增登记，原可验证活动继续独立读停，观察连续性标为不完整。
3. 当前日志文件有 64 MiB 软件容量上限；达到上限阻断新可靠写入并保持保护，不自动删除或伪造完整观察。实际容量、保留周期和维护流程仍需按 PAR-14 核准。
4. 首次 STOP 尽量先写本地停止意图。已登记对象发生磁盘写失败时，必要且经独立身份核验的 STOP 不等待本地落盘；持久化/观察缺口保留。M02 入口仍须自行持久锁定并核验当前 owner。
5. 未知回执重试原不可变请求。追加原因在前一请求已匹配可信入口回执后形成新 requestKey，保持同一 protectionKey 和网关原 firstRequestedAt/confirmationDeadline；不能重写原请求摘要或重新计时。
6. 原期限为 null 时保持未知，不能用新原因/重试补造核准期限。首份入口回执中的期限不得晚于本地原期限，也不得晚于入口原 firstRequestedAt 加同一核准 stopConfirmationTimeout；更早的首次意图不能携带延期后的窗口。已有可信锚点此后必须原样重放。LOCKED、ACCEPTED、UNKNOWN 均不等于物理 STOPPED；REJECTED 或身份/摘要不匹配不能作为可信停止接收证明。
7. 停止后按核准时长继续监控并保存原始 Observation，不以泵速零、单次稳定值、等待时间已到或 ACK 合成 M07 收尾；完整覆盖、可信计量及命令闭合后才可释放。时长缺失或覆盖有缺口不得套用旧120秒等默认值。期限到达保留期限事实，不抹掉迟到反馈或绕过释放要求。

## 5. 时间、首次开始及监控范围

- 首次开始原件与接收时间原子保存为 FirstStartObservation。同事实重复幂等；不同原命令、时刻或来源的事实保留原件和冲突，不覆盖原首次开始。
- 可信事实证明首次开始达到或越过冻结 firstStartDeadline 时，保留事实并请求 TASK_START_DATE_VIOLATION 保护。登记时间、预填充 START、一般 progress 和 HTTP 调用时间都不能替代补料首次实际开始。
- 超出接收侧核准时间误差的未来事实保留为不可信/冲突并按 START_UNCONFIRMED 保护，不能先宣称日期违规。重启沿用原接收时间，不因时钟前移自动将其转为可信事实。
- 首反馈期限从可信实际开始事实计算。独立进程已接第16节的显式指标角色与运行反馈核准文件，合格原始反馈和资格证明均可靠落盘后，才记为本段首次反馈；GOOD、零速、单独非零值或较新的 Observation 外壳时间不能代替核准的运行语义。原样本早于实际开始、超过期限才取得资格、身份/单位/boot不符或未落盘，均不确认。达到期限仍无原证明时按 EXECUTION_PROGRESS_STALLED 保护。控制进度期限仍独立从原登记或最近有来源的控制里程碑计算，健康成功不推进里程碑；原始数据缺失/坏质量使用原 NCS013 语义。
- 新核准文件允许requiredMetricCodes显式绑定主泵、供料秤或其他已授权资源，按原device/单位/boot逐项核验，不把地秤WEIGHT改成主泵数据。此接线只确认原读数身份及首反馈语义，不计算补入量、袋可用量、预填充量或认可账；这些量保护及M07跨设备raw投影仍须各自完整的方向、基准、终点和资格生产链，不能因指标可读取而启用未覆盖策略。
- 观察缺口使用 MONITOR_UNAVAILABLE 保护事实；原始数据不可用与进程不可用分别保留。读取超时或返回 UNKNOWN 时，监控保留不确定性，将原完整 identity/fence 的必要 STOP 交给已核准的独立停止入口再次校验，不复用旧 MATCH 冒充当前控制权。明确 MISMATCH 后隔离旧绑定，连后续读取超时也不能发送旧 STOP；需新的完整 MATCH 才解除该身份隔离。隔离事实随原 Observation 持久重放，不能向新 owner 控制。
- 在途执行发生调度退出、业务数据库故障、超量、数据超时或冻结时，独立监控沿核准判据保留异常事实并经仍可用路径STOP；M07负责将其归并业务ERROR，物理状态无法确认则独立保留UNKNOWN。业务数据库不可写时不得伪报ERROR已落库，可靠副本及原发生时刻/首次期限保留，恢复后按原件归并。普通STOP在核准确认等待期内且无其他异常时只待确认，不因等待本身报故障。

## 6. 解除分支

`ReleaseBasis=STOP_CONFIRMED`：M07 明确物理停止、可信计量及唯一账/对账闭合、核准停后监控时长和完整观察、无未决命令、无未归属变化及资源交接；notSentEvidence 必须为空。布尔值只是交接外壳，网关受控 authority 仍须核对来源与原记录。ERROR只要完成这些安全收尾条件即可释放设备，不等待人工异常处理或ERROR_HANDLED；量未知/未认可、对账未完及缺观察证据仍不合格。

`ReleaseBasis=NOT_SENT`：stopConfirmed 为 false，其余适用交接条件明确成立，携原始未调用反证 notSentEvidence。网关从自身原命令记录证明未发出且无 UNKNOWN；监控不能自报未调用，不能虚填 stopConfirmed=true。

M07 先取得网关交接，再请求监控验证同一请求。仅 ReleaseReceipt.released=true、完整身份及 releaseRequestHash 全匹配时，监控才写解除。原完整 ReleaseReceipt 持久保留；成功响应丢失后，同一请求在当前进程和重启后均返回原回执，异包重放拒绝，不能复活登记。恢复连通、午夜、M09 已通知、STOP ACCEPTED 或单独资源释放均不能替代此步骤。

上述解除的是原设备占用与该原保护登记，不解除ERROR任务的故障锁或同培养队列阻断。不同培养通过自身准入及新的claim/登记后可使用真正可用资源；如设备级隔离或能力故障仍存在，不得准入。异常处理生成的补料子任务必须重新claim，不继承已释放的原fence。ERROR安全收尾与人工业务处理分离的实现范围见第10/15节，不能仅凭新增规则声称旧软件已支持。

## 7. 验证与未启用边界

证据分为：协议/摘要测试；副本损坏、重启、进度、首启、多原因等单元测试；loopback HTTP 权限/签名测试；真实两个 JVM 的生产 Main 与**仅 test 源码中的** M02 Installation/Driver。双进程测试能验证进程分离、停止保护及原锚点重放，不能替代设备联调、业务数据库断连整链、跨主机部署或现场保护验收。

投用前仍需：M07 活动/里程碑/首启生产者和双登记门禁联调证据；监控原始证据回交 M07 收尾闭环；真实 M02 适配器与写入屏障/独立读停能力；客户参数、时钟质量、连续观察、容量和逐设备启用清单。缺项保持 BLOCKED_EXTERNAL/BLOCKED_DEPLOY/NOT_VERIFIED，不补默认现场阈值。

客户 OPC 的已确认协议解析、原包归档及条件化 STOP 安装边界见[客户 OPC 适配与原始证据接入契约](客户OPC适配与原始证据接入契约.md)。该适配器仍返回未核准观测，普通启动和自动运行资格保持阻断，不能据已有源码解除上述投用条件。

## 8. 原始证据分页与 M07 唯一收件

`EvidencePullRequest` 固定 `{schemaVersion:1,registrationId,identity,afterCursor,afterHash,maxEntries}`。初始 cursor 为字符串 `"0"`、hash 为 64 个零；每页 1—100 条上限由调用方明确给出。`EvidencePage` 固定 `{schemaVersion:1,registrationId,identity,afterCursor,afterHash,nextCursor,nextHash,hasMore,storageHealthy,entries,source}`；source.hash 覆盖完整规范 page，计算时只排除 source 自身。

每个 `JournalFact` 固定 `{position,previousHash,entryHash,kind,body,bodyHash,originalPosition,originalPreviousHash,originalEntryHash}`：

- position/previousHash/entryHash 是**该 registration 独立导出链**，从 1 连续递增；entryHash 覆盖规范 JournalFact、排除 entryHash 自身。另一执行的原件不会出现在页中。
- originalPosition/originalPreviousHash/originalEntryHash 保留全局日志原位置和原链证明。过滤后的原位置可以跳号，不将其宣称为连续全局日志。原 entry hash 算法为 `SHA256(originalPreviousHash+"\n"+kind+"\n"+Base64(UTF8(body)))`；bodyHash 绑定完整原文。
- cursor/hash 必须匹配原导出前缀；不接受跳页、异 hash 续页、伪造身份或未知登记。日志损坏只导出可验证前缀并置 storageHealthy=false，不能补造连续观察。
- 页体软件上限 786432 字节，保留 1 MiB 通路余量；单条原件超出上限则明确失败，不截断 body、不跳过原件、不推进 cursor。该值是报文防护上限，不是设备参数。
- 原件导出使用日志快照，JSON/摘要计算在日志锁外；STOP 不等待导出、网络收件或业务数据库。

M07 网络编排必须先在事务外验签取得整页，再调用 `M07IndependentMonitorEvidenceIngestion.ingest`。该事务沿原 runtime→execution→segment 锁序核对已持久执行、specHash、原段 fence、原命令适配器/配置；expected Registration 来自受控登记来源，不能使用浏览器自报对象。原件先进入 `LOCAL/MONITOR_EVIDENCE_RECEIVED`，重复原位置/原 hash 幂等，异包拒绝；存储失败不返回成功游标。没有新表、没有第二份量账，不把 LOCAL 原件自动交给 M09。

只有显式本地 `M07MonitorSampleQualificationProvider` 提供原 commandId、阶段、实际 activeMilliseconds、实际采样时刻、运行时长和指标/时间资格来源以及完整 raw v2 后，才调用唯一 `ExecutionSamplePort.appendExecutionSample`。provider 不得在事务内进行远程调用，也不得用接收时间、轮询次数或健康状态推算实际运行时长；无实现/无元数据返回 BLOCKED_METADATA，坏资格返回 QUALIFICATION_INVALID，原件保留。

本批投影仅支持 OPEN 原段、主泵原设备读数、原值/单位原样转入 raw v2；多读数外壳 observedAt 取各实际采样时刻的最早值，保留各自全精度 observedAt/receivedAt，不用 Observation 外壳时间覆盖。质量不得升级；设备、配置、fence、原 commandId、阶段、来源 boot/sequence 和完整摘要逐项相符。raw v2 的 sourceEventId、原始时区/精度、sourceRevision、规范化和 sourceSequence 规范身份仍必须来自受控资格生产者，不在收件器补默认值。跨设备量值和转换未接线时保持阻断。

Port 仅在 APPENDED/DUPLICATE 且无冲突时生成 `LOCAL/MONITOR_SAMPLE_PROJECTED` 回执；冲突/隔离返回 SAMPLE_NOT_ACCEPTED，数据库失败回滚原事务。每次收件包括空页均从既有 run_event 按原位置从旧到新扫描最多100条未投影观察；最旧未决观察原则上阻断后续样本推进，仅下述首启前原包、正式采样契约的 `PREVIOUS_COMMAND_OBSERVATION_PENDING` 及文末2026-10-26已确认的窄续段 `CONTINUATION_PRECALL_OBSERVATION_PENDING` 可继续检查后包，原件接收和运输游标仍独立保存。命令回执或资格补齐后自动重验原件并沿唯一 Port 投影，不能改旧 activeMilliseconds/阶段/源序列来通过门禁；已投影原件不会重复调用采样 Port。CLOSED 原段只保留此通道原件，不改已关闭量账。

首次START附近可能出现“全部原始读数已采集、Observation外壳稍后封装”的完整原包。仅当原首段登记及双ACK、首条且唯一START的EXECUTED原件/摘要/调用时刻已核验，无早前物理命令或当前未知物理命令，全部GOOD读数的observedAt及receivedAt加核准时钟误差均严格早于该START调用，并通过核准指标resourceKey/deviceRef、单位、boot/sequence和时间资格，且原实际泵速及本段有效运行计数均为0，才将该包分类为 `FIRST_START_PRECALL_OBSERVATION_PENDING`，继续检查后续独立合格原包。该分类不写排除或投影回执、不产生样本、不计量、不授予运行或覆盖资格；原件仍完整保留，每次重放重验。不得以设备种类拼接资源身份。缺双ACK/命令结果、跨调用边界、迟到的receivedAt、坏质量或非零运行事实均不得采用此分支。它不改变 `BEFORE_SEGMENT_INVOKED` 的外壳与原件时间判据，也不改变停止覆盖对实际停止锚点之后原件的逐条核验。

只有完整原登记/双ACK和准确原起始 START（续段 SET_SPEED）的 EXECUTED 结果证据、payloadHash、invokedAt 均已核对，且整个 GOOD 原包完整身份相同、observedAt 加核准时钟误差及 receivedAt 均严格早于原调用时刻，才追加 `LOCAL/MONITOR_SAMPLE_EXCLUDED / BEFORE_SEGMENT_INVOKED`，避免明确不属于运行时域的旧包长期占据队头。排除仍保留完整原件，绝不成为样本或覆盖；UNKNOWN、跨边界和来源不完整保持阻断。排除依据随原登记、双ACK及原命令结果摘要持久，并在后续扫描重新核对，不据旧排除事实绕过变化。事件字段及处理边界见[数据库JSON与事务契约](数据库JSON与事务契约.md)和[业务观测采样与告警交接](业务观测采样与告警交接.md)。

新执行接管已释放资源时，原 START 调用前仍属于上一执行的 GOOD 原观察，只有前 owner 全部原资源已完成安全释放及外部双 ACK、新旧 fence 恰递增 1、完整旧身份吻合、全部原时刻严格早于新 START 调用，才可留原件并记录 `PREVIOUS_EXECUTION_BEFORE_START_INVOKED`。原释放、结算及双 ACK 原件参与排除依据并逐次重验；跨边界、未知或缺证仍保护阻断，数据库失败回滚收件。该规则不改观察身份、不产生有效样本或停止覆盖，精确字段见上述数据库 JSON 契约。

原始页完整、storageHealthy=true、样本已入账都**不产生 COMPLETE observation_coverage**。本服务始终返回 OBSERVATION_COVERAGE_UNQUALIFIED；仍需原 STOP、实际观察区间、原样本集合与 hash、所有缺口及身份来源经过 M07 停止证据装配，才能形成其唯一覆盖结论。当前测试覆盖签名分页、两个真实 JVM 重启重放及受控收件/投影，不能据此标记真实业务 DB 故障整链或现场停后观察通过。

## 9. 普通 START 的双登记持久门禁

`M07TaskPauseDispatcher.dispatchPrepared` 在进入原 `M07CommandInvocationWorker` 之前调用 `M07MonitorRegistrationGate`。仅普通任务的原 `PREPARED START` 进入登记握手；工作流步骤沿其原独立契约，STOP、SET_SPEED 与原命令查询不依赖本门禁。缺少登记提供方、明确配置、网络回执或持久双 ACK 时，普通 START 保持 PREPARED，并按依赖不可用阻断；不得将请求已送出、readiness 文本或单侧 ACK 当作登记完成。

握手分成两个短事务及其间的事务外网络调用：

1. `M07MonitorRegistrationStore.prepare` 锁原 runtime、task、任务执行历史、当前 execution/segment 及原 START，重核当前 EXECUTING、准入状态、完整 frozen spec、资源集合、owner/fence、适配器、配置、命令原摘要与当前 OPEN 段。只有内部 `M07MonitorRegistrationProvider` 提供明确的 profile、时钟资格、独立读停批准及两端实例身份后，才持久 `LOCAL/MONITOR_REGISTRATION_REQUESTED`。
2. registrationId 由原 commandId 与原命令摘要稳定派生；计划日来自原 task，首次开始截止为该计划日之后的 Asia/Shanghai 零点。登记时刻不是实际开始时刻。已有任务首启事实只能引用原持久事实及来源，不能由预填充、调用时间或提供方自报代替。重试读取同一原登记；到期批准不通过换键或重写登记续期。
3. `M07IndependentMonitorClient.register` 在所有 M07 事务外依次请求网关 `/register`、监控 `/register`。两份回执必须同 registrationId、完整 registrationHash、明确核准实例且 durable=true。部分成功或响应丢失保留原请求，按原身份重放。
4. `acknowledge` 在第二个短事务重新取得同一原执行/段/命令，确认网络期间身份和状态没有改变，再持久 `LOCAL/MONITOR_REGISTRATION_ACKNOWLEDGED`。原 `M07FixedTaskStartGate` 在最终调用事务中再次读取并验证这两份持久回执；此后仍须通过原日期、能力、策略、资源与实际调用入口检查。登记本身不产生开始权限或 STARTED 状态。

`futurefab.m07.independent-monitor.enabled=true` 才创建网络客户端。`gateway`、`monitor` 两通路分别必填 `endpoint/client-id/instance-id/key-file/request-timeout/maximum-clock-skew`，统一前缀为 `futurefab.m07.independent-monitor.`。key-file 必须是明确绝对路径的受保护文件；两通路密钥、endpoint、实例身份须独立，不提供默认设备参数、地址、凭据或超时预算。未启用配置时不创建网络客户端；必要 STOP 和原查询仍保持原路径。

当前已完成协议/持久事件的隔离测试、Dispatcher/最终门禁接线测试及 system 客户端至生产网关 HTTP 服务、独立监控 Main 的 loopback 联调。已提供显式部署文件及固定 SHA-256 的核准配置加载器，按设备/适配器/配置/资源集合、冻结 measurementProfileId/revision 与有效时间全误差区间绑定；文件存在和 TEST 配置仍不构成真实 profile 批准。自动进度/首启发布及证据拉取的生产调度接线见第11节；完整释放事件后的软件交接见第10节。真实核准配置、普通 START 的数据库并发、设备入口与现场资格仍按各自验证层记录，不得据隔离软件测试提升为已通过。

## 10. 本地释放到独立保护解除的可靠交接

本节目标规则包含正常结算及ERROR安全收尾两类来源。ERROR的设备释放不等待人工处理；但业务状态、完成度或单个STOP回执均不是安全收尾证明。当前已实现的结算来源链与本次必须新增/调整的ERROR来源分开登记，旧来源限制不能作为继续等待人工处理的业务规则。

ERROR最终释放中的“无未决命令/全命令闭合”按[设备命令H06](设备命令契约.md#2026-10-21-h06-停止后资源释放资格)核验，包括核准证据证明已隔离且不可能再物理作用的旧命令；原UNKNOWN历史仍保留。仅本地停止锁、新fence或SMP入口撤权不能替代客户侧在途处置证据。实际量、归属和观察仍须完整，不能凭隔离推导历史补量；该资格不用于放宽暂停续段。

既有 `M07MonitorReleaseHandoffTask` 只扫描已提交的 `LOCAL/M07_RESOURCE_RELEASED`，与本地 H06 释放事务分离。其已实现范围为完整 TASK 执行的 STOP_CONFIRMED 分支：object 为原 EXECUTION/最终执行版本；source key 绑定原 `M07_EXECUTION_SETTLED` eventId；result 精确包含 schemaVersion、ownerKind、ownerId、executionId、sourceEventId、sourceEventHash、segmentId、executionSpecHash、stopEvidenceHash、coverageHash、releasedResources、releaseEvidenceByResource。完整资源集合、各原 fence、释放后 guard 版本及各资源原九键释放证据必须保存，不能只凭 FREE 或 `stopEvidenceRefPresent=true` 组装外部证明。

既有结算交接器将原释放事件与原完整 Registration、两端原持久登记 ACK、原 `M07_EXECUTION_SETTLED` 逐项绑定。原执行/段/specHash、培养/实验室、STOP/coverage 摘要、原 STOP 命令引用及全部资源 fence 必须相同。普通结算保留 SYSTEM 来源；人工原量认可后的结算只接受 USER 与 confirmedBy 精确一致、handlingId 和明确结算政策齐全的正式分支。PROVISIONAL量未认可、旧 result=null、工作流或缺 NOT_SENT 原始未调用反证，仍不能借此结算路径补造释放证明；任务显示ERROR_HANDLED也不代替完整来源。

登记查找以该原最终结算的executionId/segmentId为准，必须恰有一份原请求及匹配双ACK。初始段读取`MONITOR_REGISTRATION_REQUESTED/ACKNOWLEDGED`，续段读取`MONITOR_CONTINUATION_REQUESTED/ACKNOWLEDGED`中的nextRegistration和原continuationHash；不得按execution任选首次或最新记录。续段双ACK仍核验原恢复命令、版本、摘要、两端实例及PREPARED/MONITOR_READY语义，回执时间不得晚于原释放。最终释放只消费已完成停止、观察、认可量和完整资源释放的H06原件；它不产生续段激活或普通写许可。缺原件、歧义、异段或摘要不一致保持WAITING_RELEASE_PROOF。

ERROR目标分支沿原唯一`M07_EXECUTION_SETTLED`事件承载安全收尾，不另建事件或量账：受控M07事务在可信计量认可、原SETTLE及适用投影完成后，允许任务ERROR、执行STOPPED、计量CONFIRMED；原异常原因、STOP/coverage、全部段唯一认可账及对账、calculation来源、全命令闭合、完整资源/fence及当前归属仍须精确绑定，随后由同一H06及可靠释放交接消费。此自动来源保留SYSTEM身份，不要求人工confirmedBy/handlingId，也不借正常最终允差合格把异常改成成功；人工更正来源继续按其原权限及来源核验。目标业务规则已确认，固定schema如需扩展，须在实施批版本化登记并同步生产方/消费者白名单，不改旧JSON或历史hash。当前候选SQL及释放资格仍仅接受EXECUTED/ERROR_HANDLED/CANCELLED，另有SETTLED原件要求；必须扩展这两层对ERROR安全收尾的支持，不能仅新增事件便宣称已完成。

完整来源先在短事务冻结为 `MONITOR_RELEASE_HANDOFF` PENDING 行，原请求包含原 registration/identity、原 H06 来源摘要和明确 STOP_CONFIRMED 交接证明。外部调用在事务外按网关 `/release` →监控 `/release` 顺序执行。两端均须 released=true 且原身份、releaseRequestHash 完全相同；之后短事务追加 `LOCAL/MONITOR_RELEASE_ACKNOWLEDGED` 并按 eventId、尝试次数及原 payload_hash 将 PENDING/RETRY 改为 PUBLISHED。这里的 PUBLISHED 仅表示两端持久交接 ACK 已归档，不表示 M09 通知送达。

网络超时、部分成功、响应丢失、异包回执或本地 ACK 落库失败均重试同一原完整请求，不更新原 authorizedAt，不生成替代 registration，不改变原 FREE 事件或原 fence。独立监控继续保护，网关按自身当前身份核验；旧绑定的重放不得控制新 owner。必要 STOP 不等待本交接器。已生成交接子行的原来源不再进入来源扫描，未闭合子行由单独有界重试扫描处理。

启用需同时满足原资源事务开关和 `futurefab.m07.independent-monitor.release.enabled=true`，并明确设置同前缀的 `batch-size`、ISO Duration `retry-delay` 及 `cron`。cron 缺失为禁用值 `-`，没有默认扫描/重试预算或现场参数。当前隔离测试覆盖来源严格校验、人工来源、原请求重放、双 ACK 身份/摘要、本地写失败、CAS 失败及调度接线；实际数据库回滚/并发、实际独立端口交接和现场能力仍按对应验证层记录，不能因本地 outbox 代码存在标记已投用。

## 11. 已提交控制事实与原始页的自动交接

`M07MonitorActivityTask` 是事务外有界入口，按顺序尝试来源入队、证据拉取请求入队和已有请求发送；前一步不可用不阻断后续已有请求的重试。启用必须同时满足资源事务开关及 `futurefab.m07.independent-monitor.activity.enabled=true`，并明确提供该前缀的 `batch-size`（1—500）、`page-size`（1—100）、正 ISO Duration `retry-delay/poll-delay` 和 `cron`；cron 未配置为 `-`，网络超时仍使用第9节分别配置的两个通路预算，没有新增现场默认值。

- 控制进度只消费原 `LOCAL/EXECUTION_CONTROL_EVALUATED` 的合格 schemaVersion=2。完整原 event hash、SYSTEM 用途、execution/segment/spec/fence/adapter/config、原 sampleId/hash、sourceCommandId/sourceSequence、明确控制政策以及原 registration 和双 ACK ID/hash 必须相符。`ProgressUpdate.occurredAt` 取原 `controlledAt` 的纳秒值，`observedAt` 单独保留于来源；控制评估是控制器里程碑，不能当成物理运行反馈。序号使用原 eventId；同登记的前序控制事件尚未持久 ACK 时，后序不越过。旧 schema1 不自动升级为受控来源。
- 实际首启只消费原 `M07_ACTUAL_FIRST_START_RECORDED` 或完整身份的 `M07_ACTUAL_FIRST_START_STOP_REQUIRED`。必须将 incoming 原件经正式首启 codec 规范化后，与该原 execution 的 `first_start_evidence` 精确匹配，再核原 START 与登记关联。发生时刻来自原 `occurredAt.reportedAt/actualOccurredAt`，保留纳秒；接收时刻、事件落库时刻、当前日期不得替代它。迟到但权威的跨日事实仍交接；冲突 incoming、隔离身份、缺 specHash 或缺双 ACK 保留待交接，不将它当权威首启发送。proof 的版本 `1` 指原首启证据 schema1，完整原始来源引用及核准信息仍保留在不可变来源快照中。
- 证据轮询只从原持久登记及双 ACK 发起，同一登记至多一个 PENDING/RETRY 页请求。游标/hash 只取该登记上次持久原始页 ACK；初始值仅为其导出链的 `0/64零`。原请求固定完整 registration、原双 ACK、afterCursor/hash、maxEntries，失败不换键、不跳页。HTTP 返回后先走第8节唯一 ingestion 事务，再追加本地页 ACK 并 CAS 发布原请求；三者失败整组回滚。页 ACK 完整保留原请求、整页、实际投影数量与 blockers，后续资格补齐可重放原页。

三个专用 outbox 类型分别为 `MONITOR_PROGRESS_HANDOFF`、`MONITOR_FIRST_START_HANDOFF`、`MONITOR_EVIDENCE_POLL`，复用 PENDING/RETRY/PUBLISHED，不新增表、任务状态机或量账。网络只在事务外；`LOCAL/MONITOR_ACTIVITY_ACKNOWLEDGED` 与发布 CAS 同事务，原事件 ID、尝试次数及 payload_hash 必须一致。首启必须 accepted=true、conflict=false、durable=true；进度必须原序号/hash 和 durable=true。监控端对完全相同的进度重放幂等，不刷新其原发生时刻；同序异包仍拒绝。

页的 PUBLISHED 仅证明整页原始证据已收到，缺元数据仍是 BLOCKED_METADATA，coverage 始终 UNKNOWN。storageHealthy、完整游标链、健康成功或本地页数均不证明实际采样覆盖；闭段原件先保留，必须有受控分类来源才能区分真实迟到旧段采样与闭段后的持续保护读取，不按每个新 poll 自动触发 H08，也不据原件收到自动消除异常。当前软件证据为隔离行为测试与专用 SQL 验证；真实采样资格、连续覆盖、部署和现场能力仍须分别核准。

监控端可对已验证、只追加的本地日志维护按原登记身份隔离的导出索引，后续轮询只解析新增原件，不重复解析和计算既有前缀。索引仅复用原始字节及确定的导出摘要链；每次请求仍校验完整身份、原游标/hash及页上限，`storageHealthy`读取当前日志状态。续段原件在前后登记中的归属保持原协议，重启必须从原日志重新校验并重建逐字一致的导出结果；损坏尾、摘要错误不得被缓存掩盖。导出解析和摘要计算不得持有独立追加/停止所用的日志锁。该索引不形成采样资格、覆盖、实际停料、进度或量账，不刷新任何原安全期限。

## 12. 暂停后续段的连续保护交接

续段使用原 `ContinuationRequest`，绑定 previousRegistrationId/完整旧 identity、新 nextRegistration、原恢复命令 ID/requestId/payloadHash、原停止命令及停止、观察覆盖、已认可分段和恢复资格 Proof。同执行、spec、完整资源/fence、控制器、适配器与配置保持一致，segmentId/registrationId 必须不同；冻结监控 profile、计划日、首启截止及原实际首次开始事实不变。它不是新 START、资源释放或健康恢复后的重新登记。

`nextRegistration.source` 保留本段 `M07:CONTINUATION:<commandId>` 资格原件摘要；首段配置核准 source 通过每层原资格事件、前段完整登记及双 ACK 追溯，不要求二者字符串相同，也不将首段 source 写入续段。M07 的采样资格与执行 Authority 共用此追溯，核对不可替换的 profile、clockQualification、readStopAuthorization 和冻结身份。追溯只确认批准来源，不替代续段双 ACK、上下文 ACK、ACTIVATED、实际首反馈或最终正常写门禁。

监控 `/prepare-continuation` 仅允许 M07 身份：

1. 先经独立 MONITOR 通道向网关 `/verify-continuation` 核对原请求 hash、next registration、durable 和 PREPARED。若本地尚无交接原件，历史 MONITOR_READY/ACTIVATED 不能补造本地已接管事实；旧登记、可信原首启和显式批准必须仍能精确核验。
2. 追加并 force 原 `CONTINUATION` 后，在同一监控互斥区内建立新段活动并退旧段活动；过程中不释放资源、不重写旧 STOP 的首次意图/期限/原因。新段持久化失败时继续旧段保护。新段注册容量沿用原活动槽位，不产生保护空窗或同时控制两个身份。
3. 随后用独立 MONITOR 凭据向网关 `/confirm-continuation` 证明新副本已持久，核对原请求 hash 后持久 `CONTINUATION_READY`，返回本监控实例的 MONITOR_READY 回执。M07 后续仍须单独 activate，并在原命令实际调用入口复核当前权限；阶段回执仅是已发生的历史交接事实，不代表当前允许普通写。
4. 丢失确认或本地回执时，按原请求重放；已接管新段不回退旧段、不重建 registrationId、不刷新原时间。持久 MONITOR_READY 回执可跨进程重启原样返回，异包拒绝。重启观察缺口继续触发保护，不能因历史交接 ACK 自动解锁普通写。

新段首反馈窗口从 nextRegistration.registeredAt 计算，并等待该新段自己的合格实际反馈；不能以任务原 actualFirstStart 已存在跳过恢复后的反馈等待。全任务首次开始日期事实仍沿用原件，不在恢复时重新判成新任务首启。当前第5节的反馈资格缺口仍适用，未有明确反馈语义时不得宣称恢复已实际运行。

日志新增两种精确类型：`CONTINUATION` 的 body 是完整原 ContinuationRequest，`CONTINUATION_READY` 的 body 是完整原 ContinuationReceipt。旧、新 registration 的独立导出链均包含同一原 CONTINUATION 及其原全局日志证明；新链从该交接原件起步，不合成 REGISTER。旧链可见同执行新段交接，不包含其他执行原件；各自 cursor/hash 独立，不能沿用旧段游标。原停止证据继续可按旧 registration 拉取。

本节软件验证包含：持久化失败、错误/历史网关回执、冲突首启、丢 ACK 重启、原请求幂等、新段反馈期限与旧/新导出链单元测试；真实签名 GatewayHttpServer 与独立生产 MonitorMain JVM 的交接和强杀重启；原两个生产 Main JVM 的故障保护回归。测试 driver/authority 仅位于 test 源码；没有真实设备、现场批准、业务库断连整链或部署验收。M07 续段 outbox/实际调用门禁及新段自动活动来源应按各自实现证据登记，不因本节监控交接通过而视为全部完成。

## 13. V4.1抖动、返水、堵塞与量保护的接线约束（2026-10-21）

规则权威为客户V4.1-1013 §1.6.7及[泵速执行与设备恢复契约§4](泵速执行与设备恢复契约.md#4-读数窗口与监控)，正常抖动同窗口公式沿M04 Q09。本节统一已确认规则与实现约束；当前软件状态按第15节分项记录，不将M07侧接线等同独立进程完整监控已具备。不新增另一套量账、任务状态机或现场默认参数。

- 二/三段策略终点E限99—100%，最多1位小数；FIXED沿其单独核准的终点，不借用策略终点或测试参数。累计实际量≥T×E/100触发停止；超量NCS009为累计实际量>T×(1+p/100)，等号不触发严格超量。终点与超量分别计算，已发正常STOP或正在抖动观察不能屏蔽超量。原T、E、认可历史量和原计量来源必须冻结且匹配执行身份；不知道目标量/来源时不能从袋重量或健康字段猜测。
- 抖动从CALIBRATION起，HIGH/LOW继续；Δj=interval×jitter.checkFactor，阈值=max(precision×jitter.scaleFactor，窗口开始理论每秒流量×Δj×jitter.factor)。实际增量和理论增量必须同窗口。触发后以内部JITTER_OBSERVATION_REQUIRED立即提出原身份停止，初次不报NCS030，只有实际停料证据成立才开始观察期；回执接收、零设定或线程定时器不得代替实际停止事实。
- 返水从HIGH起，LOW继续、不用于CALIBRATION；Δb=interval×jitter.checkFactor，检查系数与抖动相同已由V4.1明确，不另设独立可写值。实际增量<0且≤precision×backflow.factor触发NCS032，保留负值，不能取绝对值。
- 堵塞从HIGH起，LOW继续、不用于CALIBRATION；Δc=interval×clog.checkFactor。理论窗口量>2×precision且实际量<理论量×clog.factor才触发NCS031，任一等号均不满足对应严格条件。阶段/速率/物料session/暂停恢复改变时截断重建；停后稳定重量不能当运行堵塞。
- 抖动观察时长由显式interval×jitter.observeFactor形成，按interval周期复核。用户已确认固定触发窗口起点与原J：当前合格读数相对该起点的方向归一化增量≤原J即本次抖动恢复，不重置起点、不按零速或观察跨度重算J。原供料秤1000g/J10g、当前993g表示7g≤10g，其他安全门禁齐备即由调度续段，不额外等完整抖动观察期。恢复后建立新运行窗口，正常重量下降不再套旧J。仅全期持续未恢复、到期仍超原J且覆盖合格才报NCS030；缺资格不伪报持续异常。可信采样边界/覆盖、精度、时钟、profile及恢复资格仍须核准，不能用零设定、GOOD或health响应填补。
- 多原因与首次停止意图/期限须持久且跨进程一致。独立监控仅STOP/留证；调度在本次恢复及原实际停止、最低安全观察、计量、完整新段交接等全部条件成立后立即恢复。若其他门禁阻断，继续保护并在最终派发前重验实时事实，不以早期恢复记录覆盖新异常，也不额外建立强制重观察流程。人工暂停/取消/现场锁及其他原因不因抖动消失而解除。迟到正常结果也不能覆盖保护原因。

数量/方向/精度/实际活跃/阶段与窗口元数据必须由核准来源提供，不把现profile的metricCode列表当完整计算资格。第8/11节原始页PUBLISHED、日志连续、样本投影成功均不等于物理观察COMPLETE，也不等于独立STOP已归并到M07停止意图/STOPPING；该回交已接下述受控消费者，仍须分别核验其原来源、数据库事务和现场能力；不得合成USER_PAUSE或EXECUTED。

当前文档已对齐上述规则。Java判定、实际生产调用、SQL原子性、HTTP/独立进程及逐设备现场验证分别登记在现有开发计划；本节不因本轮文档修订新增通过数。已确认的固定观察基准与原J须固化为原件；缺合格量来源、覆盖或设备核准参数时，相应自动运行/恢复保持阻断，必要保护与原件归档继续。运行中缺窗口资格、过时缺可比边界或gap按MONITOR_UNAVAILABLE保护，只有可证明初期跨度不足才等待。M07判定原件使用MONITOR_ANOMALY_EVALUATED，登记于JSON契约；独立日志、该LOCAL事件与M09送达不是同一证据层。


## 14. 独立停止原件的业务归并

显式启用 `m07.independent-stop.enabled=true` 后，`M07IndependentStopTask` 以必填 cron、batch-size（1—500）有界扫描 LOCAL 原始 STOP_REQUEST/STOP_RECEIPT；不要求先出现合格样本。扫描失败保留原件并继续其他来源，后续周期按原身份重试；同一来源已有严格匹配的 MONITOR_STOP_RECONCILED 才跳过。网络派发在资源事务提交后沿既有 dispatcher；已有必要STOP/查证不依赖告警或新增恢复资格。

消费者通过既有 M07ExecutionControlWorker 的密封 M07_EXECUTION_CONTROL 入口锁原 runtime→task→execution→segments及资源/命令，核原 registration和双ACK、完整spec/claims/fence/worker/adapter/config，再归并停止意图与STOPPING。schema及幂等标记见[JSON契约](数据库JSON与事务契约.md#2026-10-21抖动观察结论与独立stop归并原件)。原始未知START不伪造成功，必要STOP仍可从已调用原命令产生；从未调用且无有效原命令时仅保留保护并等待来源，不伪造完成。

`m07.command-recovery.recheck-seconds` 必须已有显式部署值，用于原命令查证调度，绝不作为物理停止确认时限。首次意图和nullable deadline由原监控事实与现有stop_intent合并，已有明确期限不延长；来源缺失仍阻断相关归并，但不抹去独立进程已持久的保护。旧段、已换owner/fence或完整资源不符不得控制新占用。物理停料、原量认可、观察/未决命令闭合与资源释放继续沿H01—H08各自核验。

原停止归并调用链已完成隔离 Java 反例验证及专用Mapper/事务隔离MySQL验证，范围和日志按开发计划单列；全系统与整链验证不由这些定向结果替代，不以本节登记或LOCAL marker证明实际设备停止。抖动观察已接原最终化，但本次“合格即恢复、其余门禁齐备立即调度”的政策仍须重新核验判定器及SYSTEM完整续段链；恢复事实不单独授予开泵权，人工锁及其他原因不得被清除。

当前段保护身份查询同时识别原START登记与原SET_SPEED continuation登记，返回真实请求/双ACK身份及事件类型；不得将旧段ACK移到新段。gateway丢ACK后的同原请求先进阶段回执只证明历史阶段已到达，不授权当前普通写；恢复进度及实际派发仍须独立ACTIVATED原件与当前停止屏障重验。观察和必要STOP可在MONITOR_READY接管后继续，不等待普通运行激活。

## 16. 指标角色与首反馈核准上下文（2026-10-21）

这是独立进程内部的封闭schema1文件，不修改Registration、MonitorProfile、原CommandParameters或raw v2，不改变旧规范摘要。部署必须明确提供成对的`feedback.config-file`绝对路径和`feedback.config-sha256`；摘要固定完整UTF-8文件原字节，不排除任何字段，也不由进程自动生成批准。文件上限256 KiB；重复键、未知字段、尾随内容、隐式数字转换、版本溢出及缺失字段拒绝。

文件精确字段为`{schemaVersion:1,monitorProfileHash,binding,validFrom,validUntil,metrics,runningFeedback,source}`。binding为`{normalControllerId,adapterInstanceId,configurationRevision,primaryResourceKey,deviceRef,resourceKeys}`，完整resourceKeys唯一且排序，逐项属于原resourceClaims及readStopAuthorization；monitorProfileHash匹配完整原profile。有效区间覆盖核验时刻、原registeredAt和原样本observedAt。每个metrics项为`{role,resourceKey,deviceRef,metricCode,unit,sourceBootId}`，完整metric集合与requiredMetricCodes相同，必须显式含FEEDING_MASS角色；角色还包括ACTUAL_SPEED、ACTUAL_RUNNING_STATE、REACTOR_WEIGHT、SEGMENT_ACTIVE_MILLISECONDS。角色仅声明读取语义，不自行取得物料会话、方向、累计量、活跃时长或观察完整性资格。

runningFeedback为`{metricCode,kind,lower,upper,lowerInclusive,upperInclusive,allowedValues}`，必须指向被控主设备的实际反馈。NUMERIC_RANGE只用于ACTUAL_SPEED，明确十进制上下限与边界且排除零；ENUM_VALUES只用于ACTUAL_RUNNING_STATE，明确允许的原数值编码，数值上下限为null、边界false。不能因GOOD或任意非零而推断运行。若同时绑定主设备实际速度，零/负速度或开始前的旧速度样本不能被“运行”状态码覆盖；正速度也不能绕过原核准谓词。所有所需读数仍必须满足原设备、单位、boot、GOOD质量和时间资格。

首段锚点取可信actualFirstStart；续段取nextRegistration.registeredAt，原任务首启事实不被覆盖。资格评估时刻取独立读取返回后的本进程时钟，绝不把请求发送时刻当作采样上界；原observedAt/receivedAt完整保留。合格首反馈必须发生在本段锚点之后，并在原firstFeedbackTimeout内完成资格确认和可靠落盘。原Observation与命名EVIDENCE均持久后才生效；其结构见[JSON契约](数据库JSON与事务契约.md#2026-10-21独立监控首反馈原件)。

重启只按同一核准文件hash及历史qualifiedAt重新核验原Observation，保留首反馈原件，不制造新运行事实；进程中断仍是观察缺口。缺失或不可加载的反馈核准不会删除已有可靠活动：Main在原通路/存储配置有效时保留旧活动读停，记录FEEDBACK_APPROVAL_UNAVAILABLE并阻断新登记；结构不完整的启动配置仍须修正。更换文件、缺原Observation、异身份或不合格证明均不能阻止后续原STOP请求/回执及首次期限重放。它不解除保护锁，不确认物理STOP，也不等于M07采样/观察COMPLETE。

本批验证包括核准摘要/严格解析、跨设备/单位/boot、零速和旧反馈冲突、有效期、读返回时钟、首反馈持久失败、续段隔离和重启原件；真实生产Main子进程通过签名loopback Gateway读取显式TEST秤，跨首反馈期限并强杀重启，另验证核准摘要损坏后仍维持原停止锚点。测试设备/参数/异常资格Installation仅在test源码中；没有真实设备或现场核准结果。独立异常上下文生产者和M07跨设备投影的缺口仍按第15节分别推进。

正常终点、异常停止与人工暂停后的进度含义都是持续处理原 STOP 的真实独立观察，不能伪装为仍在调速。统一使用 `M07_STOP_OBSERVATION_PROGRESS`，每次必须有新的合格 OBSERVATION 原件、同登记/资源/fence 和已执行 STOP 的实际反馈。来源分别绑定原人工暂停事件、原控制 `STOP_PREPARED`，或原 `MONITOR_STOP_RECONCILED` 及其配对的独立请求/回执；不能只凭 STOPPING 字符串续报进度。正常终点后控制已停止调速，也仍应交接合格停后观察，避免把正常停止观察误判为调度停滞。完整字段、原件校验及有界幂等键见[JSON契约](数据库JSON与事务契约.md#2026-10-21独立监控活动与证据轮询专用-outbox)。

PAUSED 还必须具有原认可暂停交接事件；已关闭计量段不再插入执行采样或量账。上下文 command 使用原 STOP 的 payload/result 摘要与实际执行时间，phase 为 STOPPING 或已有事实证明的 PAUSED，commandedGramsPerMinute 为停止意图的 0；数量基准、历史认可量、原 T/E/p 和监控参数保持原值。该 0 不是实际停料或完整观察证明。异常原因保留，观察进度不改变业务正常/异常结果、不自动恢复、不释放资源。

独立监控原控制进度期限继续执行，不因暂停/停止字符串关闭或放宽。观察原件缺失、源时间陈旧、实际速度非零、闭段后活跃计数变化、业务库失联或交接失败时不生成替代心跳，已有独立保护继续执行。人工暂停首个确认期限从原段双 ACK 登记的核准 `profile.stopConfirmationTimeout` 取得，并在原管理锁内复核原身份；正常/异常停止同样保留其原已核准期限，稳定窗口与停后观察窗口不能代替该期限，重试及后续观察不得重置首时刻/已有期限。未部署原登记能力时必要 STOP 保留，但未知期限仍不能取得完整收尾资格。

停止覆盖遍历原始连续日志时，`STOP_CONFIRMATION_DEADLINE_REACHED` 是保留的期限事实，不是坏样本，也不是实际停料证明。仅在其外层原件与完整登记身份、摘要、可靠覆盖和发生时间均核验通过后，才可按以下规则解释：严格解析内嵌 `StopReceipt`；核对原网关实例的 `STOP_INGRESS` 来源、回执请求摘要和非 `REJECTED` 状态；按原 registrationHash/requestKey 取得已收到的 `STOP_REQUEST`，核对完整身份、保护键、原请求正文摘要、原件顺序和全部原因。回执不得推迟原请求的首次时刻或已知期限，其期限必须明确、不超过原核准停止确认预算，且该证据的 recordedAt 已达到该期限。原请求原因必须已归并到同执行、同段的 M07 停止意图；M07 已知的更早首次意图和更早期限继续保留，不由该证据重置。

合格的期限事实保留在停止覆盖的原始来源链中；它不增加 `qualifiedSamples`、不延长真实覆盖时间、不清除异常，不授权恢复或资源释放。缺原请求、未归并原因、未知期限、其他登记/网关、未来或篡改证据仍阻断覆盖。期限已到与停止后观察能否完整成立分开判断：后续真实合格采样仍可完成安全收尾，业务异常及原期限历史保留。暂停/停止收尾扫描若因资格、原件或事务冲突失败，记录 WARN、executionId、segmentId 和原始异常原因，并继续其他候选；不能静默吞掉失败或改写证据以完成收尾。

独立进程将上下文按版本/前摘要保存在单独的可靠事实副本中，重启按原件重放；业务库不可用时继续使用已有可靠原件进行必要保护。副本损坏、回退、分叉、缺明确角色/原命令/窗口锚点时不得新准入或冒充正常；已有活动不因批准文件失效而丢弃保护。相同段的原T/E、基准、会话、历史量及参数不得由后续上下文改写。后续段必须重新绑定其真实基准/会话和原登记，不把旧段读数重新归属。

续段初始上下文复用同一版本化协议和可靠发送机制，来源为原`MONITOR_CONTINUATION_REQUESTED`及其完整`MONITOR_CONTINUATION_ELIGIBLE`原件。前段完整上下文版本链和每版精确LOCAL持久ACK必须可重放；新段单独从revision=1开始，不能借旧段ACK。生产时按runtime→task→execution→segments→commands→material→唯一认可账的原锁序复核归属，认可来源键沿`M07:SEGMENT_RECOGNIZED:<executionId>:<segmentId>`。合法换瓶续段绑定已锁定新段的物料会话、基准及资格原件，保留原执行spec和原历史量；不得强制新瓶会话等于首段会话，也不得把恢复命令的剩余量当作原T。原T/E/p及核准指标和时间资格继承同一执行已确认上下文；恢复资格Proof不冒充profile批准来源。

### 18.1 真实监控窗口的确认（2026-10-24）

用户确认配置周期是最小跨度；以最新合格读数为终点，选同阶段、原命令/速度、物料会话内不晚于“终点−周期”的最近真实起点。按实际跨度τ计算理论补量、J及堵塞阈值，逐点保留并验证原样本和核准最大gap，不插值、不改时间或跨边界拼接。停后抖动复核在基础周期已达到后使用真实合格样本，原起点/J不变；持续异常必须有到原期限或其后的真实覆盖，保持profile最低观察要求。

## 19. 启动前能力拒绝的持久撤回协议

本协议仅适用于已登记原请求、但停料能力明确拒绝且完整事实证明从未开泵的原尝试。不能将 NOT_FOUND、超时、未签名拒绝、一般配置错误或 UNKNOWN 转为 NOT_SENT。协议沿用原认证签名、响应签名、时钟质量、请求大小限制及精确身份，不增加普通启动/调速入口。

| 数据对象 | schemaVersion=1 固定字段 |
| --- | --- |
| NotSentWithdrawalRequest | `schemaVersion,registration,capabilityEvidence,requestedAt,source` |
| NotSentWithdrawalReceipt | `schemaVersion,registrationId,identity,withdrawalHash,endpointId,completedAt,withdrawn,noInvocation,source` |
| NotSentWithdrawalFact | `schemaVersion,request,receipt` |

registration 为原完整 Registration；capabilityEvidence 为原 typed 停料能力拒绝 JSON 字符串，其 registrationId/identity/registrationHash 必须与原请求一致。source 为原命令身份、版本及 payloadHash 的 Proof；withdrawalHash 为完整规范请求摘要。withdrawn 和 noInvocation 必须为 true；completedAt 是实际完成持久撤回的时刻，不能推算或补造。M07 冻结同一请求重试，保留原拒绝发生时刻，不用后来批准结果改写旧失败尝试。

1. M07 在原事务保存请求后，事务外以 M07 凭证调用网关 `/withdraw-not-sent`。网关只接受自身可靠日志中同原登记的明确能力拒绝，检查没有任何普通命令调用/意图（包括 UNKNOWN）、保护停止、进度、续段或冲突占用；记录并持久化 `NOT_SENT_WITHDRAWAL` 后返回收据。重复请求仅返回同收据，冲突摘要拒绝。
