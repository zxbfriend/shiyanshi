## 外壳与验收

HTTP失败的code与状态一致；字段定位只含当前有权对象。认证失败、管理请求失败和领域异步结果分别解析。400/409保留非敏感草稿，401清敏感身份，403/404隐藏无权对象。任何结果未知的写请求先查原身份，不自动生成新UUID。每个接口的错误集合由本表及其明确引用的生产方定义组成，不要求所有接口返回所有码。

样例构造：选择本表HTTP码，errorCode为精确码名，code为同一HTTP整数，requestId为原请求ID；其余外壳字段严格采用所属接口既有定义。运行事件使用其reasonCode/issues，不套HTTP外壳。测试须覆盖同键重放、同键异载荷、无权、旧版本和依赖故障。

## FEED-20261020：原因码扩展与复用规则

本节为小试二期/中试补料、补糖任务的正式设计登记；**新增20项语义原因码，不分配新NCS数字码，不新增HTTP顶层错误码或业务状态**。这是契约登记，不是源码已实现证明；`FutureFabReasonCode`、生产方/消费方白名单、SDK与界面翻译、事件处理及契约用例须在实施批同步，完成前不开放依赖分支。客户源码、客户文档、本轮业务确认、SMP设计与接口/现场验证分别留证，不能用本表反推客户系统已有这些码。

### 1. 现有码复用及HTTP边界

| 分类 | 复用及处理 |

### 3. 判定、恢复和验证约束

1. 正常等待、证据待确认、已达故障阈值分别处理；不能给每个准入阻断都自动生成设备报警。告警ruleKey映射/通知配置另按M09登记，不自动新增规则或默认阈值。
2. 错误码不替代状态机。调度唯一正常启动/调速；独立补料监控交付证据并仅请求核准停止；M02落实实际入口仲裁和原始协议事实；M07唯一归并业务状态与计量；M09只投递。正常结束与故障并发时保留全部原因，不能仅按已达目标归并成功。
3. 操作响应的 `Issue.retryable=false` 表示不能自动重试物理动作；条件改善后的重新预检、只读查证及已有核准同键STOP重传不受此标志禁止。不得用新请求ID绕过未知、日期、版本或锁定。
4. 开始/停止/计量证据须关联原task、execution/segment、command、归属/fence、配置/profile版本与实际发生/接收时刻，沿既有来源引用保存；当前承载缺项需版本化补齐，不向固定JSON任意添键，不改历史hash。
5. 首次开始日期的完整规则及判定矩阵见[任务状态与恢复](任务状态调度与异常恢复.md#feed-20261020首次开始日期与原因判定)；正常跨午夜、合法续段不产生日期故障。停止确认期限与任务执行超时独立；物理停料、量确认、观察结束、业务结束和释放各自核验。
6. 验收至少覆盖20项触发/解除、HTTP与业务原因分层、多个原因合并、未知原身份查证、晚到证据、午夜边界、重启后期限保持、通知失败不阻塞停止。静态文档登记不等于这些运行用例通过。

## 2026-10-21：抖动观察内部原因及窗口失效映射

`JITTER_OBSERVATION_REQUIRED` 是同窗口抖动判定触发的内部STOP原因，承载于原段stop_intent及`MONITOR_ANOMALY_EVALUATED.change.after.reasons`。它不是新增HTTP码、NCS数字码或`FutureFabReasonCode`的第21项新增语义原因，也不等同持续抖动告警NCS030。请求STOP、实际停料、本次抖动恢复与持续未恢复分别留证；首次停止期限不因进入观察、追加原因或重试重置。

| 事实 | 复用码/内部结果与处理 |
| --- | --- |
| 初始抖动超过原同窗口阈值J | `JITTER_OBSERVATION_REQUIRED`；立即请求原身份停止，先确认真实停料再观察，不直接报NCS030。 |
| 任一合格停后观察周期，相对固定触发起点的方向归一化增量≤原J | 本次抖动已恢复；原1000g/J10g、当前993g即7g≤10g。其余安全门禁齐备后由调度立即续段，不额外等待完整抖动观察期；恢复后新建运行窗，正常下降不套旧J。内部RECOVERY_ELIGIBLE名称不增加再次等待要求，也不单独授予开泵权。 |
| 完整观察期持续未恢复，到期仍超原J且全覆盖合格 | 复用NCS030；资格未知不能伪报“持续抖动已证实”，也不能恢复。不为已合格恢复的本次抖动补报到期持续异常。 |
| 本次已恢复，但其他安全门禁阻断续段 | 保留实际阻断原因及保护，在最终派发前核验实时事实；不能沿用早期记录绕过新异常或失效证据，不额外设置正常必经的重观察/等待期，不重置原STOP期限。 |
| 运行期超量、堵塞、返水 | 分别复用NCS009、NCS031、NCS032；按各自阶段及严格/含等号边界判定，并发时保留全部原因。 |
| 必需窗口资格缺失、过时仍无可比边界、窗口gap或质量/身份失效 | 复用MONITOR_UNAVAILABLE并保留精确blocker；运行保护停止，不能套NCS030/031/032猜故障种类。该码在此表达必需监控判定能力失去资格，不宣称监控进程已离线。 |
| 可证明仅处于新阶段/原命令窗口初期，跨度尚不足 | 内部`WINDOW_INCOMPLETE`表示等待，非新增共享错误；其他已核准保护继续运行。不得把重启丢历史或长期缺边界始终当初期不足。 |
