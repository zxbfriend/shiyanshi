# 开始培养接口与完成事务契约

> 2026-11-07 最新规则覆盖下方与之冲突的中间写入及会话恢复口径。`POST /run/start-culture/completions` 是小试、中试最终保存入口，要求 `run:workflow:start` 和 `run:workflow:operate`，使用 `X-Request-Id`、`X-Management-Revision`。请求包含 `workflowKind`、`labId`、`definitionVersion`、`entryBusinessDate` 和完整 `members`；每个成员包含目标培养/设备/占用及版本、`expectedDeviceVersion`、包含 `expectedWeightRevision` 的 `typedPayload`、预填跳过或模拟选择、模拟确认项。十进制值仍按原字符串传输。
>
> 保存先重新校验全部成员权限、业务日期、培养/计划/占用/重量/设备和定义版本、在线告警及设备安全条件。小试整批在同一事务内写完成记录、首次运行与开始完成事实、业务结果、审计和回执；任一失败全部回滚。各培养按编号排序锁定，完成唯一槽与培养版本共同阻止后提交覆盖已有结果。2026-11-08用户确认重新进入时系统应核对并安全关闭本人旧流程；当前 cloud 代码不提供该旧会话关闭能力，仍需实现与验证，不能将数据库状态视为设备停止证据。
>
> 未知结果使用原用户和原请求号查 `GET /run/workflow-requests/{requestId}`；查无回执为 UNKNOWN。页面仍保留原完整请求时可按原请求号、原版本和原内容重试；刷新仅保留请求编号以回查，不保留业务输入。最终保存通过现有受管写机制审计实际操作者，同键异载荷拒绝。

## 7. 数据与接口契约

### 7.1 类型化数据

所有 ID/版本沿现有正十进制字符串协议，decimal 以十进制字符串传输，时间为 ISO offset 时间，存 UTC 并按上海时间算业务日；不可用 JS 浮点隐式换算。ActorContext 从服务端取得，WriteMeta 的 requestId 及管理修订只从现有统一请求头绑定，表中“WriteMeta”不表示允许 Body 覆盖；禁止同键异载荷。以下模型字段为增量设计，开发必须更新 DTO/SDK/机器台账。

新口使用专题编号 SC-HTTP01/02/03/04，不占用已有 M07-001～035 数字；后续机器台账登记为新增 planned/disabled/unwired 后才能接线。**2026-11-03 现状订正：本句是 2026-10-17 的登记前置条件，当前源码中 SC-HTTP01～04 已有 Controller 路由、应用服务方法体与 SDK 封装（`StartCultureSessionController`、`WorkflowBatchQueryController`、`RunWorkflowController#startCultureSession`，SDK 见 `sdk-smp-api/src/start-culture.ts`），该「unwired 后才能接线」的前置已不是当前状态；机器台账本身的登记口径不在本专题维护范围。本订正不表示这些口已验收通过：目标数据库、HTTP、浏览器与设备联调均未验证。** 查询复用 run:workflow:query，创建复用 run:workflow:start，步骤/命令/取消/组动作复用 run:workflow:operate，重启沿 run:service:restart；涉及已选培养的口均叠加实验室及培养成员范围；未绑定培养的页面OPEN/CLOSE只核验实验室、功能权限和会话owner，不要求不存在的cultureId。查询旧批量组必须对完整成员集合有权，不泄露失权成员。

通用错误复用 INPUT_INVALID、NOT_FOUND、PERMISSION_DENIED、STATE_CONFLICT、VERSION_CONFLICT、REQUEST_CONFLICT、DEPENDENCY_UNAVAILABLE；新增专题 reasonCode（待登记）包括 NOT_START_DATE、START_DAY_EXPIRED、START_ALREADY_COMPLETED、PAGE_SESSION_INVALIDATED、SESSION_BOUND、FIRST_FACT_PENDING、OBSERVATION_STALE、DEVICE_NOT_READY、PHYSICAL_RESULT_UNKNOWN、SOURCE_CONFIG_CHANGED；原START_POLICY_UNCONFIRMED/INITIAL_INPUT_CONFLICT不再用作阻断已确认首启告警及实际初始量保存的业务原因。400/403/404/409/503 服从现有映射；批量同一错误响应内带 perTargetIssues，但不能在失败响应中留下部分生效。403/404 边界遵循现有不泄露策略。

所有查询口和写回执返回与本次对象范围一致的顶层managementRevision及对象版本。候选读取与最终保存均使用对应业务范围的真实版本，不跨模块借用或硬编码。最终保存前校验培养、计划、占用、重量、M09配置等相关当前版本及完整表单；FIRST与完成事实在最终事务中处理，不在未完成的START阶段提前改变版本。普通重查revision不重载页面/不清内存表单；明确409与未知结果分开，未知优先查原请求。

请求回执复用既有幂等基础，若当前基础缺请求身份查询则SC-01扩展，不新建重复业务框架。最低登记键=(actorId,labId,requestId)，保存请求kind、页面会话、hash、状态与关联对象，不存第4步前的完整表单；同键异载荷拒绝，APPLIED只有真实提交成功才能返回，正常步骤APPLIED仅指该次阶段转换成功，不等于开始培养完成。请求PENDING/UNKNOWN不得靠TTL推断成功/失败或清除物理资源。

## 8. 完成事务、事件与幂等

目标采用当前同一 Spring/MyBatis 数据库事务，不把设备请求放在数据库事务内。M07 专用 StartCultureCompletionService 编排，M03/M09 提供方要求已有受管事务及合法调用用途；任一提供方失败抛出异常，所有本地生效写回滚。

1. 事务外取得可信观测和必要远端状态；没有核准 profile/服务身份/权限时拒绝。目标分层锁序（本轮实现保留SYSTEM全局串行锁，具体见第15节）预锁 SYSTEM → lab → 所有 M03 培养/变更守卫及占用（按培养 ID） → M07 页面会话 → runtime/批量组/实例/步骤访问（各类按稳定ID） → 完整设备资源稳定键 → 配置/候选/交付回执。OPEN/CLOSE尚未绑定培养时只取SYSTEM→lab→页面会话子序；发现已绑定只返回引用，不持会话锁反取培养。其他路径先按只读引用定位，再按完整锁序重验。所有参与路径同序，不持M09锁反向获取M03，不将候选锁提前到M07 runtime之前。
2. 验当前仍在合法的开始业务日、WriteMeta、权限、完整成员集、定义/完整表单摘要/培养/计划/占用版本、唯一完成槽、无未决命令；最终观测仍新鲜、同配置且满足确认谓词。按用户最新确认，开始培养不要求未完成阶段先产生 FIRST_WORKFLOW_STARTED；首次开始事实与完成事实在最终保存事务内处理，不能提前伪造已完成事实。其余流程的 FIRST 规则不由此改变。
3. COMPLETE按真实本次提交集合核对表单、确认与物理证据；小试异常未勾选不视为已确认或自动完成，不以旧“原组每台必须全部确认”强制勾选；不新增整批/部分完成选择题或批量拆分恢复入口。对实际提交集合先完成M03及中试M09校验再原子保存，不从旧实例恢复表单，不把已确认初始量/首启告警规则再次设为政策未决。既有身份、范围和版本校验保留。
4. M03 apply 初始化主值及来源，原子调用现有 M07 输入变更失效能力（来源键 completionId，沿用版本屏障，不造 candidateId）；仅中试M09 applyInitial保存有效培养配置及允许的模板/候选；已有集合原样确认不伪造修改修订。已冻结日初、已执行快照、每日额度不改。
5. M07 将第2/3步业务表单及第4步确认的完整快照在本事务首次写入；在日期守卫核准后取得本次统一的服务端 completedAt，保存不可变 completion 记录，将最终步骤/实例标记完成；在同事务追加每培养一条原生 START_COMPLETED RuntimeFact，occurredAt使用同一completedAt。expectedCultureVersion 使用第 4 步返回的真实当前版本，plan/occupancy 沿锁内基线；不伪造旧版本。
6. M03 SC-M03-I04 在同事务核验 M07 刚写入的真实完成记录与原事件，收件并应用，保存 start_completed_at/运行水位/回执。跨 owner 通过 Port 可看到同事务源记录，不跨 Mapper。必须 APPLIED 才成功；BLOCKED/UNKNOWN/仅 RECEIVED 导致整个完成事务回滚。原源事件证明校验仍限制本次明确的固定两类开始流程。
7. 先保存M07长效回执、management audit及outbox，完成时间仍取第5步已冻结的completedAt，不改原事件及摘要；全部本地写入后、COMMIT前以数据库权威当前时间执行最后日期守卫，失败整组回滚。此后不再插入业务写或远端调用，只有事务成功才返回200。数据库时间检查须取实际当前时间，不使用事务开始时缓存的时间；若最后校验通过而COMMIT应答稍晚，归属仍按已核准completedAt，不能以网络回包时间反写业务日期。批量所有成员同时可见；事务内较早写出的 COMPLETED 不会提前对外可见。原有通知按既有契约投递；不新增独立外部监控同步流程。

START_COMPLETED.occurredAt 取第5步日期守卫核准的当天本地完成时刻，且事务末尾日期复核仍须通过，不取点击时间、人工接种推测时间或异步投递时间；操作者来自最终提交身份，步骤各自保留原操作者。重复完成查询原 completionId，既不改首次时间，也不增重量版本、不发第二告警周期。事务提交后 HTTP 断线，按原 requestId 查长效回执；不知道结果时不使用新键重建流程。

按用户最新确认，小试和中试开始培养的 FIRST_WORKFLOW_STARTED 与 START_COMPLETED 在最终完成保存事务内处理；未完成时取消不产生这次开始事实，也不改变培养状态。旧的“START 阶段先产生 FIRST”描述不再适用于开始培养，W03 等其他来源不因此改变。START_COMPLETED必须来自当天有效完成，写真实开始培养完成时间并作为完整流程完成事实由M03判RUNNING；已真实完成的事实迟到投递/重放不自动清除 START/END 延期或恢复 RUNNING，也不允许次日新造完成事实；延期恢复遵循M03本轮按原因修正相应计划的契约，不自动改实际时间。开始完成不自动执行补液/自动控制、不生成测量结果、不释放主设备占用。

本次不新增独立外部在线监控同步接口、externalSyncState流程或外部ACK作为培养完成前置。按原有本地配置及既有设备采集/服务链落实；已有服务状态资料进入开发核对，不反推另一套客户系统对接需求。真实设备或接口未联调保持NOT_VERIFIED。

## 9. 物理操作与恢复

1. 命令意图在短事务中绑定培养/实例/步骤、完整资源集及 fence、profile/方向、requestId/hash，保存 PREPARED 和审计；事务提交后才派发。
2. 固定执行器凭既有受控用途重验并 CAS 获得调用权；ACCEPTED 只表示受理，EXECUTED 按真实协议解释。UNKNOWN 查询原 commandId，禁止换键重复 START/RESTART。
3. 新事务应用回执与观测；安全停止需可信停止/稳定读数等核准证据，不能只看停止 API 成功。单资源只有一个 owner，不能另启界面计时器驱动泵。
4. 取消时先固化 cancelIntent，禁止新 START；如果原 START 未派发，以可证明的未调用状态关闭；若已调用或未知，走核准 STOP/查询/人工对账。STOP 未知仍占用；租约到期、页面关闭、取消成功文案均不能释放资源。
5. 服务重启等不可逆外部行为保留原回执。恢复只恢复工作流记录与核验，不自动重做人工接种、泵动作或重启。
