# 取样取消复制与原调度事件交付契约

本专题为S02的G05、G06现行专属设计补充，限定小试取样取消并复制及小试原调度事件处理。业务依据为V5.1 B5462—5467、B7978—8027及有效澄清；条款定位见[覆盖表第42—44节](../00-V5.1阶段设计覆盖表.md)。不替代模块既有管理守卫、权限、审批和响应契约。本文定义交付所需语义，不表示已实现DTO、路由、数据库结构或外部协议；接口编号和物理字段须与现行接口目录维护方协调登记，不能据本文编造外部方法。

## 2. G05：取样取消并复制

### 2.1 输入与读取

| 交付项 | 专属语义及取得方式 |
| --- | --- |
| 源任务身份 | 当前实验室、有权培养下的小试取样测样任务；服务端重新读取类型、执行状态及归属，只有执行出错状态适用。不得相信页面传来的状态 |
| 写元数据 | 沿当前模块制式传入requestId、同模块读取的managementRevision及适用对象版本；用户身份由认证上下文取得。不发明新权限编码 |
| 复制参数 | 从源任务合法类型参数读取培养、反应器、检测选择及原执行时间；按现行SAMPLING规格映射，不能装进补料字段。新任务有独立身份 |
| 审批条件 | 读取原有实验室适用配置，按原有审批流程处理；不新增审批种类或免审批分支 |
| 原调度关联 | 必须取得源任务对应的原调度项/Batch_OP等实际身份；不能仅凭显示编号猜测关联。精确映射列入第4节 |

### 2.2 动作及交付结果

1. 校验上述输入及源任务执行出错资格；不放宽通用取消接口，不把普通补液复制的重新选时间规则带入。
2. 实现原文“原任务标取消、从调度队列删除”，保留历史任务和结果。调度删除由原合法执行链落实；不能用本地状态修改冒充原调度已删除。
3. 复制产生新任务：当天取消并复制保留原计划时刻，即使已经过去；隔天操作必须由用户重新确定执行时间，不自动改为当前时刻（第26/126问）；沿本类型校验和适用审批处理，取得新任务及其调度关联。需要审批时遵循原有审批生效规则，不因复制直接绕过审批调度。
4. 原文要求的耗材处理交由原业务链执行；创建附件的耗材计算可作来源，但不能据此自行定义取消时退回、预留或孔位释放算法。

交付结果须能区分：源任务标取消事实、原队列删除事实、新任务身份/原计划时间/实际审批状态、耗材处置的已知事实及原执行方回执。此清单是接口验收所需信息，不强制新增同名响应字段或状态枚举。受理、完成、明确失败、结果未知不得混报为成功；复制完成不代表设备执行成功。

### 2.3 中间失败及重试边界

远程取消、耗材动作和新建不能宣称由一个本地事务保证原子完成。若取消已完成而新建失败，应保留真实源任务/调度事实及失败原因，不伪称复制完成、不自行恢复原任务。若外部动作结果未知，沿既有幂等与结果查询机制核实原次请求，不自动换键重发造成重复任务。具体可查询回执和恢复落点须由第4节协议证据落实；不新增人员恢复审批或业务次数规则。对源状态变化、无权限及版本冲突沿现行错误处理返回，不新设统一门槛。

## 3. G06：小试原调度事件处理

### 3.1 查询交付

来源限定原调度事件，页面按当前有权实验室读取。排除条件是`EventType=10 AND Status IN (9,11)`，不是隐藏所有类型的9/11。列表按开始时间倒序分页，提供模式、类型、状态、培养信息/反应器模糊条件、开始时间及1H/3H/24H/3D/7D/15D快捷范围；展示模式、类型、消息、培养、开始/结束时间和状态。字段名称、时区及分页外壳沿现行契约；底层枚举不得猜测。第146问Excel导出复用相同权限、筛选和排除条件下全部查询结果与列表字段，不限当前页，不扩大为全实验室原始表。

详情交付培养、反应器、错误消息/时间/代码以及处理人、处理时间、根本原因、处理内容、后续动作。已处理记录只读。原事件身份及处理记录绑定必须由真实接口或模型证明；不能将OperateUnitID同名视作唯一主键或一对一关系。

### 3.2 写入语义和字段对照

| 需求语义 | 附件证据及交付约束 |
| --- | --- |
| 允许处理的事件 | 仅EventType=10且Status=0；提交时重新校验，页面按钮可见不代替服务端校验 |
| 根本原因 | RootCause；选项来自原适用字典，编码/文本保存方式待原接口证明 |
| 处理内容 | 需求HandingContent对应附件HandlingContent，登记拼写映射，不新建两套列 |
| 后续动作 | 需求HandingResult对应附件HandlingResult；本页Retry=1、Continue=3，不能外推其他来源枚举 |
| 人和时间 | HandlingUserID、HandlingTime等由实际认证和处理链留痕，不能信任页面伪造的操作者 |
| 关联与回执 | 原事件、处理记录、实际重试/继续的关联及结果须可核对；处理记录保存不等于设备动作完成 |

实际重试/继续仍交原唯一控制方；M07不直接写旧表触发、不改成M09告警处理、不用run_event替代原事件。处理后Status的具体值及写入者缺证，不擅定为1。重复提交、并发已处理或结果未知按既有版本/幂等与原方回执核实，不再次盲发；若原方不提供相应能力，登记技术缺口，不伪造成功。该要求是交付一致性约束，不新增业务状态、自动关单或审批步骤。

## 5. 后续验收清单（本轮未运行）

| 场景 | 应核对的结果 |
| --- | --- |
| 非取样或非ERROR源任务、越权、版本变化 | 不执行取消复制；沿现行错误外壳，原任务不被错误改写 |
| 合法复制、需审批/免审批 | 原取消和队列事实可核、新身份和原时间可核、审批按配置；无历史结果删除 |
| 取消未知、取消后创建失败、重复同次请求 | 如实返回和留痕；无假成功、无盲目重复队列或自行恢复原任务 |
| 耗材处理 | 与原执行链及实际用量配置一致，不以预估等同实际处置 |
| 事件查询及详情 | 实验室隔离、组合隐藏条件、时段/排序/分页正确，已处理只读 |
| 处理事件及并发重复 | 仅Type10/Status0；动作1/3和字典映射正确；处理记录及原执行回执可关联 |
| 原方不可用或结果未知 | 不以本地记录成功等同重试/继续已完成，不自造处理后Status |
