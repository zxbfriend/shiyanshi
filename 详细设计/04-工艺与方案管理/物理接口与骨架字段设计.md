# M04 物理接口与骨架字段设计

版本：DD-20260918-PHY-01。本文冻结 M04 模板接口及实验室工作流清空接口尚缺的物理类名、方法、DTO/VO和Mapper适用性。业务字段、事务、权限和错误以主设计、接口目录、调用时序及错误码全集为准；本文不表示代码已实现。

## 1. 文件归属

- 模板接口 M04-API01—16：`ProcessTemplateController` → `IProcessTemplateApplicationService` → `ProcessTemplateApplicationServiceImpl`。
- DTO/VO位于`com.futurefab.system.domain.dto.process`和`com.futurefab.system.domain.vo.process`；禁止Entity、Map、Object直接成为canonical协议。
- 模板本地持久化按职责拆为`ProcessTemplateMapper`、`ProcessTemplateVersionMapper`、`ProcessTemplateBindingMapper`、`ProcessTemplateVersionModelMapper`；不得合并为跨模块万能Mapper。
- API13—16只编排M01/M02读取Port，API01只形成当前用户创建上下文，均为`NOT_APPLICABLE`，不得为了三层外观创建空Mapper。
- M04-API17—21沿用清单已登记的Workflow/LabWorkflow物理接口；API22补齐差异保存Mapper，API23补齐`clearWorkflows/clearLabWorkflows`，均使用现有`LabWorkflowNodeMapper`。

## 4. DTO边界

- Path、Query和Body在Controller层合并成单一DTO；API02/03/04包含路径ID，不能用`NoBody`掩盖路径输入。
- API05的五键固定为`TemplateBindingPreviewCommand`；API06—08分别使用创建、编辑、复制Command，不合并成带大量可空字段的SaveDTO。
- API13—16虽然只读，POST仅为复杂条件传输，DTO后缀使用`Query`且服务端不得产生本地写入。
- API23仅接受空JSON和公共写元数据；`LabWorkflowClearCommand`禁止`cultureIds`、`force`或客户端labId，labId只取路径。
- 骨架生成前本表17条接口不得再出现`TBD-MISSING`、未解释`null`或`TARGET:`建议名。

## 2026-10-24 免审候选激活与固定包解释

`TemplateApprovalContext.directDecision` 携带 M06 当前同步回调原件；DIRECT 必须由 DirectParameterDecisionPort.requireCurrent 验证，并精确核对申请人、请求、培养、实验室、管理版本、候选、包摘要、政策版本和决定时刻。DIRECT 的 approvalId / approvalResult 均为 null，不能冒充 APPROVED；原审批分支保持原完整核验。

`GenerationPackagePort.decodeForDirectCandidate(DirectCandidatePackageQuery)->TemplatePackage` 为同原候选槽位的固定 FEEDING/SAMPLING 包专用只读入口。请求只有 packageQuery 与 evidence 两字段，必须核验当前 M06 原件及培养/槽位；FEEDING还须原候选ID/包摘要一致。旧后台 decodeForGeneration 的原资源事务限制保留；两个入口共用原 schema2/3、来源、完整字段和 canonical hash 解码，未实现的新接口默认拒绝，不读取 latest 或授予设备运行资格。
