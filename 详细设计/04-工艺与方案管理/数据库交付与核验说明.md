# M04 数据库交付与核验说明

日期：2026-09-10；状态：核心结构与迁移步骤设计稿，未连接或执行数据库。入口：[主设计](详细设计.md)、[五表字段字典](数据库模型与版本字段字典.md)、[内容存储契约](模板内容存储契约.md)。

本包新增五张模板核心表67列，复用四张工作流表45列而不改其DDL；不修改原sql/ymsw.sql，不导入旧库实际数据，不增加培养快照或第二套管理回执。MySQL目标8.0.16及以上，实际小版本、权限、字符集与驱动配置必须在隔离环境验证。

前后核验脚本创建和删除本脚本专用临时用途存储过程；它们不是纯SELECT文件，但不会修改业务行。过程同名已存在时默认报错，先核实前次失败现场及SHOW CREATE PROCEDURE，再处理，不自动DROP未知同名对象。禁止使用客户端“忽略错误继续”、mysql --force或选中后半段绕过前置。任何SQL错误后停止，不将后续SELECT打印出来的结果当成功依据。

01/02使用当前显式选中的数据库，不内嵌猜测库名。执行前记录所选环境、数据库名、脚本hash、实际MySQL版本和备份编号。01设置的会话变量与数据库绑定，02不允许换连接/换库后继续。无数据库选中、依赖未部署或目标对象存在都按失败处理。M01尚未交付到目标库时先完成其部署与验收，不能删掉依赖检查让M04单独投用。

03可以在后续独立连接做基础核验，但应在一致性维护窗口或受控读快照中运行，避免跨多条检查观察到不同事务版本。脚本计数通过之后仍须把全部列名、类型、NULL/默认、字符集、生成表达式、主键/唯一键/索引顺序与05逐项比较；不能只凭67这个数量宣布结构相同。

## 2. 约束与代码责任

| 约束层 | 本包落实 | 不替代的检查 |
| --- | --- | --- |
| 身份/占名 | 五表主键；template_kind+live_name唯一；Q10禁用仍占名、删除后NULL释放 | 应用保持名称与当前版本name_snapshot同步；不同类型具体名称长度仍按内容规则 |
| 不可变版本 | (template_id,version_no)唯一；模式/版本正值与前驱是否为空CHECK；基础JSON对象类型 | 前驱归属/完整绑定/内容hash/六类叶子验证；版本不可变由应用写入口及数据库账户授权落实 |
| 固定绑定 | (parent_version_id,slot_key)唯一，来源及沿用索引，JSON对象类型CHECK | SELECT/RELOAD/RETAIN资格、固定实验室、允许的局部修改、槽位与规则一一对应 |
| 型号投影 | 复合主键、顺序唯一、反向查询索引 | M02真实共享型号身份及能力，不能把台式connection_id写入modelId |
| 核准导入 | 来源系统/表/键唯一，目标和批次索引 | 旧枚举、单位、资源ID、历史参数及作者时刻证据，不以唯一映射就认定业务合法 |

SQL层共24条CHECK是基础约束，不完整复制模板校验器。特别是JSON字段合法、父版本固定树完整、哈希真实、正常创建审计必填、已删除正常操作的操作者/时间必填、资源可用和工程单位都还需要受控服务/导入验证。旧导入允许未知历史作者/时间为NULL，因此不能用全表NOT NULL把旧事实伪造出来。

新增prc_template的current_version_id、按类型/删除/创建时间、按类型/删除/修改时间三个辅助索引，为主设计默认排序与当前指针核验服务；其他核心索引沿字段字典。保留名称键的utf8mb4_0900_ai_ci比较，kind/code/slot/hash/request等使用ASCII二进制比较，不借数据库排序规则进行资源名称关联。查询计划须按实际数据量核验，不承诺未测的吞吐或响应时间。

正常应用数据库账号对版本/绑定/型号投影采用读/插权限，身份表按需更新；批量升级/修复需独立受控账号及审计。权限落实必须核实当前连接账号已有数据库级/全局授权，MySQL权限叠加不能用一次表级GRANT抵消上层宽授权。已有共享账号若必须拥有其他表更新权，应以独立最小权限连接或受控写服务部署方案收口；未完成前不能宣称数据库已防止版本篡改。本文件不对未知账号执行GRANT/REVOKE。

## 3. 备份、部分失败与回退

1. 安装前保留目标库经核验可恢复的备份/恢复演练记录、相关四表与M01依赖的SHOW CREATE、应用包及配置版本。备份内容留在受控位置，不写入本说明或普通操作日志。
2. 五表原先不存在，本次安装不修改已有工作流/培养/资源表；02创建第N表失败时，已建表可能仍存在，因为DDL隐式提交。立即停止，不以ROLLBACK已执行为成功恢复。
3. 同连接且尚未启动任何M04写入时，可以核查安装现场、显式设置`@m04_confirm_empty_rollback = 1`后运行04。过程先数完所有已存在目标表再DROP；存在非表对象、外键引用或任意数据即停止。只删除本次固定白名单目标表，绝不删除M01/M02/M03及工作流表。
4. 数行和DROP之间不能仅靠普通事务排除写入，因此整个回退窗口必须停用全部M04业务写入/导入/后台消费者；没有证明停写，不执行04。会话丢失或安装来源不明时04拒绝，不另设“强制忽略检查”参数。
5. 曾经开放业务写入或导入旧数据后，04不再适用，即使人为清空后看起来无行也不能使用。应保留新数据与来源，采用经过演练的前向修复或一致性恢复方案，同时处理M03使用快照、审计及回执；禁止逐个DROP表当数据回退。
6. 旧应用回滚还涉及新写Header、权限收口及流程清空入口，数据库空表回退不保证应用兼容。回到旧包前核对消费者已停止且不会把历史固定参数重建为当前模板值。

## 4. 旧数据核准，不自动填充历史

当前源文件是结构/样例基线，不是已核准导入清单。CDP/NPP同名表分别识别；禁止直接INSERT SELECT把旧ID、状态或ConfigId写入新结构。旧数据导入应先取得每项可审查的证据：

| 核准项 | 要求 |
| --- | --- |
| 范围与身份 | 明确源系统/表/原主键及主子行范围，生成新稳定ID；不同来源同数字不能合并；来源键必须唯一 |
| 类型与枚举 | 确认六类归属、IsTwoStep/Status/比较符/模式等每个值含义；不按“非零即真”猜测 |
| 参数 | 六类完整本体和固定嵌套树按当前schema 1及公式版本验证；不能只存旧子模板ID等待运行时解析 |
| 资源与单位 | 实验室、型号、检测项目、培养基/耗材、实例量程与单位逐项映射；缺证据NULL或拒绝依赖，不编造型号能力 |
| 历史 | 没有当时策略值时不能把策略当前内容当历史；未知作者/原保存时刻保留NULL，recorded_at/imported_at记录真实导入时刻 |
| 唯一与启停 | 未删除同类名称冲突需核准解决，不自动改名、覆盖或删除；导入状态必须有业务依据和完整校验，不自动启用 |
| 核准证据 | source_hash覆盖原主行及所需子行，导入前重验；reviewed_by_user_id/reviewed_at/evidence_ref必须可追溯 |

特别阻断：NPP三段高速占比旧默认85不符合本期60—80，不能截成80；NPP固定泵只有ConfigId而没有当时策略参数，不能补造原培养快照；CDP旧定时PH校准任务不导入本期模板或恢复排除的任务入口。

完整核准后应通过与正常保存同一类型校验/固定绑定/投影构造的受控导入工具，在一个事务中写身份、版本、绑定、型号投影及prc_template_import_map，保留旧来源只读。工具未实现、真实核准行未提供，因此本包没有虚假的自动回填SQL、演示默认数据或INSERT IGNORE。该限制不妨碍审阅/测试五表空结构，但禁止宣称已完成旧业务数据迁移。
