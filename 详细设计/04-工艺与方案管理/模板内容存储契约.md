## 1. 内容、版本及输入的分工

### 2026-10-24 RULE 执行时固定包解析

`GenerationPackagePort.decodeForExecution(ExecutionPackageQuery)` 仅为原任务 `M07_RESOURCE_CLAIM` 的 SYSTEM 真实事务提供严格固定包解码，包装请求携带原 taskId 及完整 `GenerationPackageQuery`。沿用 schema、来源、摘要和字段验证，不生成包、不重写包、不核准当前设备能力。原 `decodeForGeneration` 继续限定生成用途；`decodeForDirectCandidate` 继续限定受守卫的 HTTP DIRECT 候选事务。三者不能互借上下文或同时拼接 HTTP/后台身份；未安装执行解码能力默认拒绝。M03 负责确认生效槽位和 APPLIED 原件，M07 负责 EXECUTE 计算及原批准目标比较。

下面每个类型的根对象是prc_template_version.content_json的完整内容；kind、schema版本、名称快照、来源、作者和时间由核心表列承担，不再在根对象重复一份。SAMPLING/PUMP_SPEED本批content_schema_version均为1，calculation_profile为M04_CALC_V1；版本组合必须受服务端支持，不允许客户端自由指定解析器。

| 数据 | 存储/生成位置 | 写入约束 |
| --- | --- | --- |
| 模板名称、启用/删除状态 | prc_template及版本name_snapshot | 沿Q10名称键规则，名称不是引用身份；启停/删除不修改content_json |
| 本体输入 | 下文类型化content_json | 所有字段明确白名单，服务端从合法DTO构造，不直接存浏览器原始对象 |
| 未选分支 | 显式null | 不用空对象、0、空字符串代替；已选分支必须具备全部所需字段 |
| 派生数值 | 固定公式版本计算；展示值走只读输出/查询投影 | 不作为可写内容保存，不能接收客户端伪造派生结果 |
| Cedex历史项目显示信息 | itemSnapshot子对象 | 服务端读取资源事实并固定；客户端不填写、不覆盖；历史查看不联接当前名称替换 |
| 实际控制器、检测仪、泵、秤、目标量及执行状态 | M03/M05/M07相应使用/任务事实 | 不进入本批模板本体，不在模板保存时解析DEFAULT温度或进行设备操作 |
| 嵌套到父模板的完整有效参数 | prc_template_binding.effective_parameters_json | 使用同一来源类型的内容结构，按effective_schema_version=1解释；允许的局部修改重验，不能只存来源ID |

本批两个类型自身无模板嵌套槽位，因此保存其独立版本时binding集合为空；它们作为其他模板的子来源时，父版本保存完整有效参数及来源版本。schema升级只建立新内容版本，不原地转换旧行；旧版本必须由对应解析器解释，无法解释时报版本不支持并阻止使用，不降级猜测。

### 1.1 数值与空值编码

| 记号 | JSON编码及技术容量 | 约束 |
| --- | --- | --- |
| ID | 非空十进制字符串，对应正bigint | 无正号/指数/小数；由服务端校验身份，不使用名称匹配 |
| I32 | JSON整数，−2147483648至2147483647 | 所有字段再施加业务范围；无明确业务上限的正整数使用此技术容量，不能将其误报为设备支持上限 |
| DEC(p,s) | 普通十进制字符串，总精度p、最多s位小数 | 不允许NaN/Infinity/科学计数法/单位文本；输入超精度报错，不自动四舍五入后保存 |
| STRING(n) | JSON字符串，最多n个Unicode字符 | 是否允许空/NULL按各字段定义；快照忠实保留合法资源显示值 |
| NULL | JSON null | 与属性缺失不同：下文要求存在的键缺失时报告必填错误 |

数值存储/内容hash使用规范字符串：去多余整数前导0和小数末尾0，零统一为"0"。例如"99.00"规范为"99"，但不因规范化接受超出原允许小数位的输入。页面格式化两位小数只是展示，不能改变存储精度。计算用十进制/精确整数，不用二进制浮点累积。

I32容量是本次存储类型决定，跨字段乘法使用至少64位或任意精度中间量并先检查容量，不以各输入均合法推断结果不溢出。特别是Vi-CELL派生检测量的容量与原样品量1—9999范围分开；不得把派生量强制压回样品量范围。

## 2. SAMPLING schema 1

### 2.1 完整字段树

根对象固定为applicableLabId、selectedTypes、detectionMode、bga、vicell、osmo、cedex七个键，无其他可写属性。selectedTypes采用固定排序BGA、VICELL、OSMO、CEDEX，是选择集合而非执行顺序。只有选中类型才有对象，其他三个/四个类型键必须显式为null；不得根据默认样品量自动推定已选类型。

| 完整路径 | 类型/空值 | 范围、来源及写入规则 |
| --- | --- | --- |
| applicableLabId | ID，必有 | M02实验室身份；直接与嵌套使用均受Q03限制，保存时核验当前允许的实验室 |
| selectedTypes[] | 固定枚举字符串，至少1个 | BGA/VICELL/OSMO/CEDEX，无重复；映射既有资源detect_class的BGA/Vicell/OSMO/Cedex，不能将API规范大小写直接当成现存字典值 |
| detectionMode | AUTO/MANUAL | 沿既有手动/自动语义；模板中只有配置，不生成任务/告警 |
| bga | 对象或null | 选BGA为对象，未选为null；对象仅含sampleVolumeUl、temperature、stability |
| bga.sampleVolumeUl | I32 | 1—9999µL；初始表单默认120，保存时必传 |
| bga.temperature.mode | DEFAULT/FIXED | DEFAULT可保存，不自动解释为读取设定/实测值；执行来源冲突见Q-2-01；FIXED采用本值 |
| bga.temperature.valueC | DEC(4,2)或null | FIXED时0<值≤40℃，DEFAULT时必须null |
| bga.stability.mode | NONE/FIXED | NONE为无稳定要求，不等于默认温度模式 |
| bga.stability.toleranceC | DEC(4,2)或null | FIXED时0<值<100℃，最多2位，表示±幅度；NONE必须null |

| vicell.sampleVolumeUl | I32 | 1—9999µL，初始600 |
| vicell.dilutionFactor | I32 | ≥1，初始1；设备实际倍数范围由M05/M07消费能力复核，不默认任意倍数可执行 |

| cedex.items[] | 非空数组 | 保存具体项目集合，按itemId去重；内容hash按ID数值升序，不储存未来自动扩张的分组选择规则 |
| cedex.items[].itemId | ID | 逻辑关联dev_detector_item.item_id，不是item_code，也不是lab_detector_item_config的设备ID |
| cedex.items[].dilutionNumerator | I32，固定1 | 序列化为1；前端只读，其他值拒绝 |
| cedex.items[].dilutionDenominator | I32 | ≥1，初始1；1/n为Cedex参数，不套Vi-CELL样品量乘法 |

### 2.2 资源关系和历史处理

项目主数据与开关来源已对齐[M02检测与资源配置](../02-实验室与资源管理/检测与资源配置详细设计.md)：dev_detector_item关联同类型lab_detector，再按(detector_id,item_id)读取lab_detector_item_config；enabled='0'开启、'1'关闭，同类型有效项目没有配置行时默认开启。不能只inner join已有开关行导致默认开启项目消失。已有配置行的enabled为NULL或非法值时属于待核验，不能按缺行默认规则放行。对无效类型、已删除项目或其他实验室项目不能因“缺行默认开启”放行。

模板候选与保存检查使用M02提供的实验室资源结果，不能直接绕过其授权读取别的实验室。若按多台Cedex设备形成候选集合，单个项目可选不代表全部所选项目能由某一台设备一起执行；实际设备选择、项目组合能力和是否拆任务由M05确定。本契约不把一个候选集合声明成运行就绪证明。

独立模板编辑/新选项目按当前有效资源核验，并在新版本中形成本次快照；旧内容行不更新。父模板沿用已存子内容且仅修改合法数值时，保留原项目ID与原快照；不能顺手从当前项目表刷新旧嵌套历史。新增/更换项目必须经该编辑入口允许并重新核验，在新父版本中固定新项目事实；不可用更新同名项目替换旧ID。来源实验室改变必须走Q03的跨实验室新身份与重验路径。

同一个项目的显示名称、分组变化不会自动扩大所选集合。来源项目缺少可解释的旧快照时保留证据缺口，不用今天的名称/单位伪造当时记录；核准导入与正常新保存分开处理。

## 3. PUMP_SPEED schema 1

### 3.1 完整字段树

根对象固定strategyType、labType、calibration、high、low、monitor六个键。二段式calibration=null，三段式为完整对象；high和low必有且无运行状态字段。所有百分数保存数值本身，例如"50"代表50%，计算流量时除以100；不是0.5倍的输入，也不是额定转速百分比。

| 完整路径 | 类型/空值 | 二段式 | 三段式 |
| --- | --- | --- | --- |
| strategyType | TWO_STAGE/THREE_STAGE | TWO_STAGE | THREE_STAGE；无连续式枚举 |
| labType | PILOT/SMALL/COMMON | 必填中试/小试/通用 | 同左；通用不授予权限 |
| calibration | 对象或null | 必须null | 必须对象且仅含以下两键 |
| calibration.seconds | I32 | 不存在子字段 | 120—300秒 |
| calibration.allocationPct | I32 | 不存在子字段 | 6—20，目标量占比% |
| high.ratePctPerMin | DEC(4,1) | 1—100且整数 | 2—50且整数；单位目标量%/min |
| high.allocationPct | I32 | 50—90% | 60—80% |
| low.ratePctPerMin | DEC(4,1) | 1—100且整数 | 0.5—20，最多一位小数；均严格小于高速 |
| low.allocationPct | I32或null | 必须null，低速占比由终点减高速占比计算 | 必填2—15%；三段占比严格相加等于100 |
| monitor.intervalSeconds | I32 | 1—60秒 | 同左 |
| monitor.overAmountPct | DEC(4,2) | 0<值<100% | 同左 |
| monitor.timeoutGraceSeconds | I32 | >0秒 | 同左；不是理论总时长 |
| monitor.endpointPct | DEC(4,1) | 99—100%，最多一位小数 | 同左 |
| monitor.jitter.checkFactor | I32 | 1—5 | 同左，检查窗口=基础间隔×系数 |
| monitor.jitter.factor | I32 | 2—10 | 同左 |
| monitor.jitter.observeFactor | I32 | >0 | 同左，观察时长=基础间隔×系数 |
| monitor.jitter.scaleFactor | I32 | >0 | 同左，与实际秤精度相乘 |
| monitor.backflow.factor | I32 | ≤−1 | 同左；不用原图正数占位提示 |
| monitor.clog.checkFactor | I32 | >0 | 同左 |
| monitor.clog.factor | DEC(2,1) | 0—1闭区间，最多一位小数 | 同左 |

monitor只含七个普通字段/分组：intervalSeconds、overAmountPct、timeoutGraceSeconds、endpointPct、jitter、backflow、clog；jitter含四键，backflow仅factor，clog含两键。返水检查系数是jitter.checkFactor派生值，不另存一份允许漂移的字段。技术精度DEC(4,1)允许表达100但不放宽二段/三段的整数业务限制；例如三段低速"0.5"有效，高速"2.5"拒绝。

### 3.2 页面字段与存储路径映射

| 主设计逻辑名 | 本体存储路径/生成位置 |
| --- | --- |
| calibrationSeconds、calibrationAllocationPct | calibration.seconds、calibration.allocationPct |
| highRatePctPerMin、highAllocationPct | high.ratePctPerMin、high.allocationPct |
| lowRatePctPerMin、lowAllocationPct | low.ratePctPerMin；三段输入占比low.allocationPct，二段占比只读派生 |
| monitorIntervalSeconds、overAmountPct、timeoutGraceSeconds、endpointPct | monitor.intervalSeconds/overAmountPct/timeoutGraceSeconds/endpointPct |
| jitterCheckFactor、jitterFactor、jitterObserveFactor、jitterScaleFactor | monitor.jitter.checkFactor/factor/observeFactor/scaleFactor |
| backflowFactor、backflowCheckFactor | monitor.backflow.factor；检查系数由monitor.jitter.checkFactor生成 |
| clogCheckFactor、clogFactor | monitor.clog.checkFactor/factor |
| calibrationRatePctPerMin、highDurationMin、lowDurationMin、theoreticalDurationMin | 固定公式版本只读计算，不写可变内容值；总时长展示投影写version.duration_display_min |

理论时长比较保留精确分数或等价精确计算，不把两位小数展示值用于超时判定。比如calibration占比10%、运行180秒，其理论速度是10/3%/min，不能先截成3.33再倒算校准时间。所有求和完成后才对展示分钟HALF_UP两位；无法整除的中间结果不逐步舍入。

Q09正常抖动计算固定为同窗口：配置最小周期Δj=intervalSeconds×jitter.checkFactor。2026-10-24用户确认，运行时采用同阶段、同原命令及速度、同物料会话的真实合格起止读数；实际跨度τ≥Δj，threshold=max(精度×jitter.scaleFactor，窗口开始理论每秒流量×τ×jitter.factor)。以最新读数为终点，取不晚于“终点−Δj”的最近真实起点，完整核验窗口内来源/质量/序号及核准最大gap，不插值或重标时间。返水、堵塞沿各自配置周期采用同一真实窗口口径，堵塞理论量按其实际τ计算。模板字段、范围及无默认值要求不变，运行/停后观察及原J留证由M07与独立监控契约负责；本次确认不代表现场参数或能力核准。

正常停泵和超量比较沿已确认的≥终点、>超量边界；三段100%占比理论总时长与endpointPct<100的提前停泵独立，不能按二段式公式改写三段低速输入占比。

### 3.3 二段式完整存储示例

所有监控值仅用于结构和数值验算，不是新建表单默认工艺参数。

```json
{
  "strategyType": "TWO_STAGE",
  "labType": "COMMON",
  "calibration": null,
  "high": {"ratePctPerMin": "50", "allocationPct": 80},
  "low": {"ratePctPerMin": "10", "allocationPct": null},
  "monitor": {
    "intervalSeconds": 2,
    "overAmountPct": "5",
    "timeoutGraceSeconds": 30,
    "endpointPct": "99.5",
    "jitter": {"checkFactor": 3, "factor": 2, "observeFactor": 3, "scaleFactor": 2},
    "backflow": {"factor": -2},
    "clog": {"checkFactor": 3, "factor": "0.5"}
  }
}
```

## 5. 保存与读取校验顺序

1. 公共身份/功能权限、M01管理版本/幂等及本模板object_version先校验；本批不决定最终角色功能码。
2. 按template_kind选择唯一类型DTO；拒绝未知键、错误JSON类型、缺失必有键、超精度、非法空值和本期不支持枚举。
3. 取样核验selectedTypes与四对象完全对应、项目身份/开关、DEFAULT/FIXED互斥及样品量；泵速核验二/三段分支、范围、低速小于高速、三段占比和监控参数。
4. 服务端读取/保留合法来源快照，计算派生输出、适配和查询投影；将本体/绑定的规范内容纳入核心hash。未保存的新来源与已保存来源沿用分别执行Q01—Q03资格检查。
5. 新版本、父绑定有效内容、当前指针、审计和回执同事务；保存成功不证明任何设备参数已生效。
6. 读取历史按原schema与calculation_profile解析；对正常读取中发现的hash/模式错误记录核查并阻止依赖消费，不能自动“修复”旧JSON。无权对象先判权再返回诊断，不泄露来源详情。

## 7. Config与灌注共用结构

以下为第二批字段树草案，字段位置已展开，Q11量程校验时点已确认，PID工程约束及型号精确来源尚未闭合，不能据此发布运行算法。CONFIG/PERFUSION的content_schema_version目标为1，calculation_profile=M04_CALC_V1；未完成的工程约束不以schema编号冒充已验证。

本节延续ID、I32及十进制字符串编码。未明确输入精度的工程数暂以DEC(20,6)作为存储容量，明确一位/两位小数的字段仍执行原精度；六位不是设备允许精度，也不表示可自动舍入未知设备参数。单位、符号、物理上下限和量程对应未核准时保持依赖未就绪，不能给未知值补0。所有新增存储路径是设计字段，不是现有接口。

### 7.1 型号引用与稳定通道

| 路径/结构 | 类型与完整叶子 | 规则 |
| --- | --- | --- |
| reactorType | INTEGRATED_REACTOR/BENCH_REACTOR | 与既有类型逻辑一致，不用实例ID替代型号 |
| models[] | 非空有序数组，每项仅modelKind、modelId | modelKind=INTEGRATED_MODEL/BENCH_CONTROLLER_MODEL；modelId为ID；同类型且去重，依reactorType选择来源 |
| models[].modelKind | STRING(32)，固定判别码 | 工艺包保留 INTEGRATED_MODEL／BENCH_CONTROLLER_MODEL；型号引用统一 `dev_reactor_model`，分别匹配其 reactor_type 为 INTEGRATED_REACTOR／BENCH_CONTROLLER，不误用台式容器型号 |
| models[].modelId | ID | 对应统一型号表 `dev_reactor_model.model_id`，按类型及有效性核验，不按名称猜测身份 |
| MFC通道身份 | channelNo:I32，1…M | 本版本型号兼容通道集合内稳定编号；MFC1等显示码由编号派生，不以数组位置关联 |
| 泵通道身份 | pumpNo:I32，1…N | PUMP1等显示码派生；不把外置泵实体ID与固定泵编号混为一谈 |

型号集合投影到prc_template_version_model，display_order取明确数组次序；保存前重新核验泵数、MFC数及温度/重量/压力能力一致，灌注还要求规格一致。Config不增加规格一致条件。集合变化使通道/回路失效时保留编辑输入并阻止提交，不静默删行或重挂。

### 7.2 输出映射与旧版MAP2

MAP2为恰好两条输出，按outputNo排序，保留于pH及旧schema的读取。2026-11-06原生第152问补清：Config的pH行选Nothing时该行未使用，免填左右映射范围、不绑定输出；不新增最少有效输出限制，初始化OUT及控制模式保留。此豁免不迁移到灌注。十二月Config DO改为三个固定槽位；可全选Nothing，Nothing免映射范围，有效输出沿既有端点/资源校验。旧schema包及摘要不原地改写；新保存的字段变更须同步版本化序列化、校验与消费契约，不能仍用MAP2截成两个DO输出。

| 每项叶子 | 类型 | 校验 |
| --- | --- | --- |
| outputNo | I32 | 1或2，集合恰为{1,2} |
| source.kind | MFC/PUMP | DO仅两条Air/O2 MFC；pH固定一条CO2 MFC和一条功能名称为“加碱”的PUMP |
| source.channelNo | I32 | source.kind=MFC取channelNo，PUMP取pumpNo；按判别码校验对应集合，不跨表碰数字 |
| source.route | HEAD_SPACE/SPARGER_1/SPARGER_2或null | MFC来源必填；泵来源必须为null。DO两输出的气体类型+通路组合不得完全相同 |
| inputStart、inputEnd | DEC(20,6) | 两者不同，保留方向；0→−100合法结构，不强制升序 |
| outputStart、outputEnd | DEC(20,6) | 两者不同，保留方向；两个端点都要满足有证据的输出量程 |

Config未使用槽位仍保留outputNo，source及四个范围叶子均为null；不新增Nothing枚举，不用0伪造范围。有实际输出的source对象仍仅kind/channelNo/route三键，route仅MFC来源可写。该空行编码与三DO目标一起走既有版本化序列化发布，旧包按原schema读取且摘要不重写；灌注MAP2不因此改变。以下“两输出”只描述旧schema MAP2读取；新增Config DO三个槽位须按前述规则版本化处理，不套本段数量。旧版DO选择两条完整Air/O2 MFC，pH选择一条完整CO2 MFC和一条功能名称为“加碱”的完整泵；DO两输出气体类型+通路不得完全相同。DO输入范围为非负整数，pH输入范围为可带负号的整数；两个输入区间将端点取min/max后比较，允许端点相接，不允许正长度交集。两个输出端点均为整数且须落在关联MFC或泵的额定量程内。

例：输入区间[−100,0]和[0,100]可相接；[−100,0]与[−1,100]重叠1个单位，拒绝。输出量程0—100时0→80可通过范围项，0→101不能通过；灌注应用时按已确认Q11对照培养固定的有效Config及目标设备能力，不擅自新增量程输入框。

反应器型号泵/MFC最大量程按原生第38问为正数、最多2位、≤9999.99；M04消费该资源事实时不以整数解析截断。该确认不改变Config手填输出范围或目标参数的原精度；前述额定范围与现场真实能力仍各自核验。

### 7.3 PID_SET

PID_SET固定五键do、ph、vesselTemp、jacketTemp、vesselPressure。每个非null对象只含gain、reset、rate三项DEC(20,6)，全部必填；不存自由表达式或函数。do/ph/vesselTemp必有对象，jacketTemp/vesselPressure可为null；设备无对应能力时可选项必须null。不存在agitator PID行，不能凭控制回路有Agitator就新增一组PID。

三个数值的工程单位、符号、物理范围和实际允许精度仍待资源PID契约；有限数和存储容量检查不等于PID合法性完整验证。当前不能宣称负增益或负时间常数有效。初次带入需全部所选型号有相同合法来源，否则由允许的页面输入供校验；保存后读取本模板版本，不从当前资源重新覆盖。后续明确工程规则必须同步到本节和版本兼容策略，不能悄悄把已存旧值按新单位解释。

## 11. 自动控制与补液的规则公共结构

第三批补齐AUTO_CONTROL/FEEDING字段树草案，schema目标均为1、calculation_profile=M04_CALC_V1；继承第1节数值编码与第7节型号判别规则。页面显示字段全部有存储或只读生成落点，但规格/型号映射、资源证据接口和运行恢复仍有明确依赖，不能据此宣称整个模块已具备编码/执行条件。

### 11.1 行身份、日期与时间

每个规则对象必含ruleId（规范小写UUID字符串，36字符）与displayOrder（I32≥0）。同模板全部规则ruleId唯一，displayOrder在所属规则数组内唯一、用于展示排序；数组规范化按displayOrder，执行时间另算，不能用排序号当执行时间。修改保留原ruleId，新增生成新ID；复制模板为所有行重建ID并重新映射取样槽位，来源版本和合法有效参数沿Q01/Q02固定。客户端不能借沿用不存在的规则ID获取旧绑定资格。

dayIndex/arrivalDay/startDay/endDay都是I32日序号，0≤日序号<cultureDays；起止区间含两端且startDay≤endDay。HH:mm:ss是长度8的24小时字符串，00:00:00—23:59:59，无时区后缀；解释时采用Asia/Shanghai业务日，不能将D1理解为保存后经过24小时。时间缺失不得填00:00:00默认掩盖。

### 11.2 自动控制DetectionSpec

| 对象叶子 | 类型/空值 | 规则 |
| --- | --- | --- |
| configured | boolean | 定时取样必须true，其余可false |
| waitMinutes | I32或null | true时≥0，表单默认0；false时null |
| baseType | RULE_TIME/TASK_COMPLETED_AT/PREDICTED_AT或null | true时由槽位类型固定，不能自由替换；false时null |
| slotKey | STRING(128)或null | true时服务端按ruleId和用途生成；false时null且无绑定行 |

定时取样slotKey=rule/{ruleId}/scheduled，baseType=RULE_TIME；完成检测=rule/{ruleId}/completion、TASK_COMPLETED_AT；温度预测检测=rule/{ruleId}/predicted、PREDICTED_AT。每个true槽位与一条SAMPLING绑定一一对应，parent_rule_id=ruleId、effective_schema_version=1，完整有效内容采用第2节七键SAMPLING结构。false却提交非空等待/基准/槽位或遗留绑定行，整体拒绝，不默默生成隐藏检测。

AUTO_CONTROL原文允许修改带入检测字段，因此可编辑已允许的类型、样品量、温度/稳定模式、倍数、项目与方式，并按同实验室可用资源和SAMPLING叶子规则重验；不套灌注“只读参数/来源类型子集”的限制。不能修改来源固定实验室来跨实验室使用，不能回写来源版本。全部生效取样绑定的实验室约束与父本体求交，无交集拒绝。

等待基准只保存语义枚举，不提前存任务完成时间或预测时间。定时取样可静态计算业务相对时刻=dayIndex×86400+timeSeconds+waitMinutes×60；使用宽整数计算防溢出，保留跨日结果。同培养检测类型相交且时间差<3600秒冲突，恰好3600秒允许。运行再按M05合格任务集合重验。按用户要求，后续代码常量/核心判定必须注释60分钟业务原因及边界，不能仅在文档说明。

### 11.3 有边界数值区间WINDOW

WINDOW固定lower、upper两对象，每侧仅operator、value。operator为LT/LE/NA；NA时value=null，其他情况下必填十进制字符串。lower表达value < 或≤ 观测值，upper表达观测值 < 或≤ value；双侧非NA还要求lower.value<upper.value。至少一侧非NA，禁止双NA充当有效条件。各规则具体单位、数值范围见后表。

与灌注pCO2不同，本处lower是“下值与观测值”的方向，不能复用灌注比较方向相反的表达式。日期交集与触发数值集合交集同时存在才按对应规则判冲突；端点开闭参与集合运算，不能只比较阈值文本或只检查是否完全重复。
