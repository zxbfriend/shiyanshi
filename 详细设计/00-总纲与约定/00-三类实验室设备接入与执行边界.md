# 小试一期、小试二期与中试设备接入和执行边界

版本：INTEGRATION-20261010。性质：当前设计补充，由《02-详细设计》引用；模块专题定义具体交接。本次仅完善设计，不表示接口已实现、设备已核准或现场验收通过。

## 1. 适用范围与审查结论

原模块分工方向成立，但不足以直接交给开发：缺少旧库写入责任、来源身份、设备代际与协议分离、命令所有权、结果关联、切换与恢复、逐设备验收条件。本补充将这些规则落实到 M01—M09。

用户已明确：小试一期保留原系统，所有表结构与原系统一致。该约束优先于原文中将所有场景概括为新系统空库建设的表述：新 SMP 仍从独立空库建设，一期现存数据库及原服务不运行新库建表脚本，不迁改其结构。保留原服务不等于开放全部旧页面或恢复新系统已排除的业务功能。

二期、中试按“新系统承担目标业务执行、可复用经验证的现场通信服务”的目标补充。现有执行器是否作为过渡路径、某一台设备何时切换，以设备组的接入登记和切换验收为准；不因本文发布自动停用旧服务。新旧执行器不能同时拥有同一设备组的控制权。

### 1.1 接入维度

| 维度 | 说明 | 拥有方 |
| --- | --- | --- |

## 2. 模块分工

核心专题：M02[设备适配](../02-实验室与资源管理/三类实验室设备适配契约.md)、M05[检测接入](../05-检测与数据签批/三类实验室检测接入契约.md)、M07[任务执行接入](../07-补液运行与任务执行/三类实验室任务执行接入契约.md)。M01—M09各自主设计均登记本次职责；当前开发总入口为[02-详细设计](../../02-详细设计.md)。

| 模块 | 必须补齐 | 不得跨越的边界 |
| --- | --- | --- |
| M01 | 用户/服务身份分离、操作权限、凭据保护、审计和接入页面导航 | 不托管业务任务，不把旧账号或客户端自报身份视为新系统授权 |
| M02 | 设备/泵位/秤/物料映射、有效通信配置、能力核准、CMD-I01/I02提供方、协议适配、非执行观测 | 不创建第二套补液任务或结算账；不绕过执行权直接下发 |
| M03 | 培养/批次身份映射、方案与生命周期权威、培养设备占用和运行屏障 | 不以相同显示编号直接关联旧培养，不自行判定泵已停 |
| M04 | 适用代际与能力约束、固定模板/工程/策略版本 | 不决定现场服务路由，不用模板保存动作开泵 |
| M05 | 检测派发、逐样品回执、结果接收与版本、位置释放、有效结果交接 | 不将检测命令全部挤入补液 DeviceCommandPort；不让结果返回直接开泵 |
| M06 | 当前路径的审批政策、候选/hash与决定幂等交付 | 不为同一动作并行启用新旧两套生效链；审批通过不等于执行完成 |
| M07 | 执行路径选择、一期兼容、二期/中试调度、命令意图、执行分段、停止与结算、切换恢复 | 不直接读写 M02/M05 Mapper，不复制一期实际量再次入账 |
| M08 | 将来只读消费带来源的结果 | 延期不阻塞任何接入或业务观测，无设备控制权限 |

## 3. 唯一写入责任与一期保留

一期对接必须先按操作列出“谁创建、谁更新状态、谁改库存、谁接收回调”。旧数据库由原应用/Core按既有职责写入，新系统所属模块通过兼容应用服务调用或读取，不能让多个模块各自直接操作旧业务表。原服务必须继续写旧库的行为不因新系统同步投影而改变。

| 数据 | 一期保留路径 | 新执行路径 |
| --- | --- | --- |
| 任务/手动操作 | 原 TaskQueue/Batch_OP/ManualOP/相关原对象为权威，新系统保存来源引用和只读投影 | M07拥有任务、候选、执行与命令 |
| 培养和资源身份 | M03/M02各自维护映射；旧事实保留旧来源 | 分别由M03/M02拥有 |
| 实际补量和物料量 | 原Core/原业务服务按操作的既有责任更新；M07观察，不再次产生新增补量 | M07计量账唯一结算；M02物料投影按受控交接更新 |
| 检测结果 | 保留旧来源与版本，经M05兼容接收；不默认具有新签批资格 | M05结果版本与签批链 |

源键至少能区分系统实例、对象种类、对象ID、源版本/事件身份。旧 BatchID、BatchOPID、TaskQueueID、ManualOPRecID、BatchTaskID不能互换。没有可信源事件ID时，需要适配协议固定去重键及证明；接收时间或当前最新行不作为唯一关联依据。

一期所有原表结构保持不变，扩展映射/回执存储只能放在新系统独立承载中；物理设计未冻结前禁止编造默认映射。同步采用各自本地事务与可靠事件/对账，不假设跨旧库、新库和设备存在一个原子事务。

一期原服务活跃写入的培养，不安装用于接管的 M07 legacy-handover 基线。该基线适用于真正停止旧写链、核准截止水位后的接续；观察投影与接管计量必须区分。

## 4. 两种执行序列

### 4.1 一期保留序列

```text
操作入口 → M01身份/所属模块权限 → M03培养与M02资源映射
  → M07检查该动作属于保留路径及既有审批生效事实
  → M02通信适配调用原Core已核准操作，或原系统按原任务表调度
  → 原Core/原业务服务执行、更新原库
  → 可信回调或只读采集进入M07/M05
  → 去重、关联原对象、更新观察投影与事件
```

自动补料的具体旧调度入口未核实时，新系统只展示已验证事实，不另造“写表后一定执行”的承诺。没有实现新旧审批映射的动作不得通过新页面发起；原保留应用继续按其已核准流程运行，不自动替换为免审。

### 4.2 新执行序列

```text
M03生效方案 / 人工候选 → M06决定 → M07准入、排队、锁资源、固定执行规格
  → M07同事务持久化execution/segment/run_command意图
  → 提交事务 → M02 CMD-I01派发到固定执行器/协议适配器
  → 设备回执/采样 → M07核验原身份与版本
  → 可信停止＋稳定重量 → 唯一结算 → 释放资源 → M09事件
```

补液业务命令身份、状态与结算由M07拥有。M02返回传输/设备事实，可以保留适配器侧投递证据，但不能复制一套独立推进的补液命令业务状态机，不能直接写M07的run_*表。现有 DeviceCommandPort 提供方仍为M02，M07产生commandId/requestId/fence；不更换签名以绕过实施登记。

设备服务可以是Windows现场进程；业务模块边界与进程部署不是同一维度。设备运行中的称重、停止和失联保护必须由固定执行控制链承担，不依赖浏览器连接，也不使用普通定时任务无条件重试物理动作。

## 5. 连接、回执和异常的共同规则

- 配置保存、配置应用、通信在线、具备执行资格分别判定；desired/applied版本一致仍需真实设备身份、模式、通道与合格新鲜读数。
- 代际不能代替协议：二期/中试均可因型号使用不同通道。通信表现有设备种类白名单不因本文自动扩展，控制器和泵沿其工程/专属接入契约办理。
- 执行前固定设备、物料会话、能力及配置版本；运行时结构性改绑定被阻断。共享泵、秤、管路和控制器需作为完整资源组核验。
- ACCEPTED仅表示受理；失败与UNKNOWN分别记录。超时、空响应、网关NOT_FOUND不能证明未执行。先查原命令；没有可核准查单能力时保持隔离，不自动再开始。
- 只有核准幂等的绝对速度/停止操作可按原键重传；查询不得暗中重下单。断网时停止是否能送达必须实测，现场watchdog不能用软件声明代替。
- 已发生的物理量不因取消、回滚、切换程序而撤销。实际量未知不能结算为0；通知失败不回滚执行事实。
- 检测执行终结、结果齐全、指标可计算分别判断；部分失败、无值、迟到和源更正由M05保存原始证据并按版本交接。
- 外部故障缺输入记BLOCKED_INPUT，缺现场环境记BLOCKED_EXTERNAL；这些是交付标签，不增加HTTP业务错误码。实际接口复用所属模块已登记错误码，不能把UNKNOWN转换为普通可重试失败。

## 6. 切换与回退

按共享物理资源组切换，流程为：停止旧侧新增派发 → 等待/处理活跃、暂停、UNKNOWN及未结算任务 → 核准旧库截止水位和实际量 → 证明旧控制通道已隔离 → 固定新归属与版本 → 校验配置/读数 → 启用新派发。任一项不满足即保持原控制方或隔离，不双控。

影子验证只读同一输入并比较计算/预期命令，不能连接第二条可写控制通道。回退同样先处理新侧未决动作、量和截止水位；新侧已经发生的物理动作不能靠恢复旧数据库快照消除。不存在“自动退回旧系统再执行同一任务”的策略。

## 8. 完整性与验收矩阵

| 编号 | 用例 | 预期 |
| --- | --- | --- |
| INT-AC01 | 旧新库有相同主键或重复显示编号 | 按完整来源身份区分，无法唯一则阻断 |
| INT-AC02 | IP在线但泵位/秤/料液绑定错误或配置未应用 | 不启动；实机核准记录精确设备组 |
| INT-AC03 | 一期结果回调重复、乱序或同步中断 | 原库状态不被倒写；不重复加量/扣量；可按原身份对账 |
| INT-AC04 | 二期/start-feeding返回成功但无开始证据 | 不显示已执行；核实原服务，不改走另一通道补发 |
| INT-AC05 | 中试空启动接口 | 不作为启动成功依据，接入版本和真实扫描机制有证据 |
| INT-AC06 | 同请求重复/异载荷/并发审批或启动 | 同身份一次生效，异载荷冲突，不重复物理动作 |
| INT-AC07 | 下发前后分别断电、断网、回执丢失 | 查询原命令；UNKNOWN保持占用；核准停止能力生效 |
| INT-AC08 | 旧执行器复活、租约超时或另一业务实例争抢 | 物理入口拒绝第二控制方，不只证明DB锁成功 |
| INT-AC09 | 部分检测失败、结果缺项、位置复用后的迟到包 | 无值不填0，不误关联，不凭超时释放位置 |
| INT-AC10 | 执行中修改方案/物料/设备配置，暂停后继续 | 固定原执行参数；新段只执行认可剩余量 |
| INT-AC11 | 停泵受理但实际仍动，最终重量不稳定 | 不结算、不释放、不声明任务完成 |
| INT-AC12 | 切换/回退前存在未知动作或未结算量 | 切换阻断；无双控、重放和重复累计 |
| INT-AC13 | 通知故障、重复源事件、恢复乱序 | 停泵/账本不回滚，告警不重复开周期 |
| INT-AC14 | 一期结构对比与一期回归 | 原表结构保持一致，原Core/网页读写及回调兼容 |
| INT-AC15 | 非授权用户或未认证服务伪造回调/命令 | 拒绝业务更新，保留安全审计，不泄露凭据 |

所有用例当前NOT_VERIFIED。文档链接和静态一致性通过不替代契约测试、HTTP、数据库、设备及现场验收。
