## 3. JSON结构、不变量与索引

### 2026-10-11规则保存与实例应用分离

用户确认保存型号规则不自动应用到实例。管理员显式选择目标仪器并确认后，由M02唯一写入实例applied_rule_revision/applied_rule_snapshot；M05只消费实例已应用快照，不读型号最新规则替代。每台应用独立回执、版本及审计；批量选择不得静默跳过失败仪器或报告全部成功。忙碌实例拒绝本次应用，保留原版本；不安排结束后自动更新。

忙碌包括待执行/待检、执行/检测中、未回收结果及活动/UNKNOWN请求；缺事实也拒绝应用。应用事务在管理守卫、实验室、设备锁顺序下重验身份、核准适配能力、型号修订和上述事实。型号保存与实例应用是两个动作，不能用数据库保存冒称物理设备已更新；设备侧必须应用的参数仍要取得真实ACK，UNKNOWN保留旧运行版本且阻断相关动作。

本条区分纯服务器规则（工作台容量/遮挡/暂存删除判定）与需要实际设备参数变更的配置：前者在服务端合法事务提交即成为实例规则版本，不强加无协议依据的设备命令/ACK；后者按已核准适配契约等待真实ACK，未知不放行。未回收结果走原设备结果查询、补收、冲突核对及受控终结证据恢复，不以超时、修改规则或删通讯记录清除占用；恢复完毕后管理员重新主动应用，不自动更新。

完整实例快照采用独立信封：schemaVersion、modelId、profileRevision、legacyScalars、ruleProfile。legacyScalars冻结寻址/容量等主数据标量，ruleProfile逐项复制该核准修订的扩展JSON，不把旧标量重复写进型号rule_profile。标量字段、枚举和核准适配标识必须在M02/M05字段字典逐叶登记并共同契约测试；完整装配只来自同一持锁版本，缺项不猜默认值。profileRevision须等于applied_rule_revision，modelId须匹配实例归属。

本条关闭“是否自动生效”的业务裁决，不冒称G-6生产者已存在。实例应用HTTP编号/DTO/功能码/审计、快照逐叶字典及ACK接入须在M02拥有方实施批完成；不在本设计批预建操作码或翻wired。旧快照无法按核准schema解析时失败关闭，不自动转成最新规则。

rule_profile只接受受控schemaVersion=1及动态规则枚举；inputProfile采用接口设计的受控字段约束。保存时应用做结构、范围、组合与适配能力校验；MySQL JSON类型仅保证JSON语法，不保证业务结构正确。规则发布在实例无活动/未知请求且适配能力核准后生效；仅数据库保存不是设备已应用。

item_bindings数组元素目标为{sampleId,resultId,columnNo,channelNo,occupancyGeneration,expectedItems:[{itemId,itemCode,unit,dilutionNumerator,dilutionDenominator}],acceptance:NOT_ATTEMPTED/ACCEPTED/REJECTED/UNKNOWN,deviceRequestRef或null}。发送前固定身份与期望集合，之后只按带证据的事件更新接受事实，不能改变集合、位置或规则。每个真实调用的request_id保持唯一；不同调用不可共享一个设备请求ID来伪装幂等。

当前device_status仍沿accepted/rejected/unknown；混合接受时整体unknown并由item_bindings表达逐样品事实，响应可为PARTIAL。PREPARED先写device_status=unknown、local_status=committed表示本地意图已提交，不代表设备已调用；start_time记录该调用意图开始时点，真实设备时点在事件证据中保留。若实施时确认原字段被外部统计解释为网络开始，须同步消费者或增加精确时点，不能静默改变报表含义。调用未知不写rolled_back伪装未执行。

拟增索引：det_sample(detector_id,occupancy_state,column_no,channel_no)、det_sample(current_dispatch_id)、det_sample(created_user_id,queue_status,create_time)、det_dispatch_log(client_request_id)、det_dispatch_log(detector_id,dispatch_lifecycle,create_time)。只提出访问路径，实施前用实际MySQL执行计划评估，不能凭设计声称性能达标。不为client_request_id加唯一约束，一次HTTP批量可包含多个真实调用。

设备行锁下保证：同设备/列/位置至多一个未RELEASED当前占位；新占位代次递增；同HTTP提交多位置可共享该次设备版本，但同位置不能共享新旧代次；UNKNOWN阻断相应重占。重复回调事件不增加新占位，不把旧代次状态写入新样品。批删跳过项不变，可删项与回执提交后queue_revision递增一次，各成功样品object_version递增。

不新增位置表的代价是同设备操作短时串行；锁内不做设备网络调用。未来确有多设备高并发需求可以另做分区，但不能先放松该锁而仍声称空位互斥。日志是发送身份与审计事实，清理策略不能删掉仍用于回传/恢复的映射。

## 4. 写入与恢复责任

| 事件 | 原子本地变更 |
| --- | --- |
| 保存新暂存 | 新sampleId、created_user_id、DRAFT及代次，固定适用项目/稀释；device queue_revision递增 |
| 修改本人合法暂存 | 条件更新object_version及白名单，不修改created_user_id或代次 |
| 发送预占 | RESERVED、操作者/请求时点、调用日志PREPARED、身份/规则快照一起提交；已发送历史不被覆盖 |
| 派发工作者取得调用 | 条件PREPARED→INVOKING后才网络调用；崩溃后的INVOKING按UNKNOWN查证，不无条件再发 |
| 完全确定拒绝/从未调用 | 记录证明，释放工作名额；可留DRAFT待人工重试，历史调用仍保留，不清请求证据 |
| 接受/开始/完成 | 核验原sampleId/代次后更新RUNNING/COMPLETED、现业务状态及版本；完成不是左侧自动删行 |
| 调用/设备未知 | UNKNOWN并保留位置与调用；不能回到MANUAL未发送集合 |
| 左侧移除完成样品 | RELEASED与clear_flag=1，不改det_result、不改样品del_flag；版本与审计递增 |
| 删除从未发送草稿 | RELEASED、clear_flag=1、del_flag=2；不得联动删除其他结果 |

离线或满载在调用前形成draft_source=OFFLINE_UNSENT/CAPACITY_UNSENT；重新发送仍由用户发起。PREPARED恢复可继续执行已授权且能证明尚未网络调用的同一意图；INVOKING/UNKNOWN必须先核实。这与禁止自动发送未发送草稿是两条不同路径，不用离线告警扫描所有stored/pending自动重发。

## 5. 迁移、核验与回退设计要求

1. 迁移前核对实际五表DDL与M02既有增量是否执行，尤其single_send_limit；备份待映射数据、活动调用和设备位置，报告未知/重叠占位，不把测试默认数据当生产来源。
2. 按版本前置检查添加20列与选定索引；本版SQL设计稿已生成，已有/半迁移结构必须停下核对，不盲目重跑，尚未执行。nullable新事实先保留NULL，object_version/queue_revision起点只表示本地版本，不代表历史身份已核准。
3. 按可信业务记录映射规则、操作者、调用和占位；create_by仅可在明确一对一且未复用账号的身份核准后映射，不能运行时按同名用户猜userId。日志只有sample_nos时不得凭业务编号覆盖旧/新样品关联。
4. 有未核准活动设备保持不可新发且可授权查看历史，不批量置FREE/COMPLETED。维护窗口对设备事实核准后接入统一守卫，再发布规则快照和新版接口。
5. 核验同位置当前占位唯一、待检测/检测中有调用身份、每个新项目稀释在约束内、规则snapshot与修订一致、未发送午夜集合无调用证据、签批历史仍可读；形成逐条不一致报告。
6. 回退业务前停止新派发并处理活动/未知请求。规则启用后旧程序无法理解占位与动态锁，不能直接切回旧程序继续发送；可进入只读模式保留新增列和日志，待所有活动归档并证明兼容后再决定结构回退。禁止为了回退删除仍有关联的调用映射。

本轮已同步M02的01—06及字段字典，并新增旧库07补丁/08未启用回退；M05运行三表包见[数据库交付说明](发送规则数据库交付说明.md)。其余结果/签批增量仍待合并，不改原sql/ymsw.sql。
