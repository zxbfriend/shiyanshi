# M05 审阅收尾接口与验收补充

2026-09-11。补充现行受控更正、发送接收、结果与报告契约；SQL 26—30 接续 25 号完整基线。现场能力见现场能力核准矩阵；通用归档与压测见跨模块收尾目录。

## 样品时间与当前结果

det_sample.current_result_id 是可空的当前派发结果投影指针。只有 sampleId＋样品代次＋dispatchId＋设备真实任务身份的绑定证据唯一确定当次结果，才允许在样品守卫内安装指针。不能按 MAX(result_id)、最新 create_time 或最早完成时间猜当前结果。多子样品映射仍未核准时保留 NULL 并输出 timeEvidenceIssues；查询展示各结果原始时间，不拼成一次虚假检测。

安装/切换指针与当次派发绑定原子完成；同一代次同一任务重复接收不改变指针。旧派发迟到只能更新其合法原结果的接收证据，不能回写样品当前状态/开始完成时间。时间投影只取指针指向的有效当次结果和真实设备事件；未提供开始事实时为空，不使用调用成功时刻。历史 det_sample 原时间不批量清空或填造；新 API 返回 currentResultId、timeEvidenceStatus=VERIFIED/UNKNOWN/AMBIGUOUS、timeEvidenceIssues[]，历史未经核准时不作为自动执行输入。

det_result_revision.source_id 改为 NOT NULL，迁移前有 NULL 即停，人工核对来源后另行受控修复；本增量不猜值。结果读取继续使用受控更正的现行版本解析器：current_correction_id→新 revision/schemaVersion=2 的完整结果与签审元数据。M07/M09 消费端必须支持 schema 2，并在新计算/动作前确认当前引用仍有效；旧缓存不自动转成新依据，既有物理事实不倒退。

## 兼容边界

single 请求有效条数恒为1。Cedex Bio 的 singleSendLimit=24 保留其原配置字段及展示来源，读接口同时返回 effectiveRequestLimit=1；不得把旧值覆盖为1或因此准许一次发送24个。发送配置静态约束按 sendMode 分类校验，不能把单发存量值错误套成列容量。

det_approval_assignee、det_ccpd_upload_log 仅作为历史查询来源；新签批/报告/CCPD审计写入既有新设计的不可变动作、报告与版本对象，不双写旧表。历史记录与附件仍保留。当前模板旧字段字典/SQL为版本化基线，30号为最新目标。

M03 成员、培养与方案来源的接口已形成设计，运行实现与现场接入仍是准入条件。UNAVAILABLE 与真实无人必须区分；不以接口文档存在宣称已接入。Q09双人受控更正、Q10整批全部日期导出及预览、Q11长期保留沿既有已确认文档。

## 故障点与验收

| 用例 | 场景 | 必须断言 |
| --- | --- | --- |
| CLOSE-M05-01 | 两实例同时生成同培养/计划/样品代次自动检测 | 唯一生成键命中同一对象，样品号与位置只占一次 |
| CLOSE-M05-02 | 意图提交后宕机；设备接收后响应丢失；事件入库后消费前宕机 | 依次恢复原意图、查原命令、重放原事件；不盲发、不漏接、不重复释放 |
| CLOSE-M05-03 | 当前派发B运行中收到A的完成包；同编号旧设备任务重现 | B指针/状态/时间不变，A按证据归属，不按文本编号合并 |
| CLOSE-M05-04 | 当次有两个子样品而无主结果证据 | 指针NULL、时间证据AMBIGUOUS，不能以排序选一条 |
| CLOSE-M05-05 | single传2条；Cedex源配置24 | 服务端拒绝2条，原24保留，有效上限展示1 |
| CLOSE-M05-06 | 更正后旧消费者请求新计算；归档结果再导出/重试CCPD | schema不兼容阻断，新消费者读现行版；历史包与唯一键不重复产生 |
| CLOSE-M05-07 | 整批报告在列表仅本人、近7天、当前页条件下发起 | 预览与导出均为有权批次全日期；无权批次失败，版本快照固定 |
| CLOSE-M05-08 | 旧更正人离职或历史签批身份缺失 | 新双人更正保留旧事实，不冒用身份，不以撤签重写历史 |
