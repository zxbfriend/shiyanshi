## 1. 签批记录与日志

UI04项目和上样日期必选，日期含今天共15个自然日为默认（today-14至today）；全部时间范围为Asia/Shanghai的左闭右开区间。项目按当前用户参与时间倒排，批次随项目联动；项目标签按10章文本模糊查询，不能照搬UI02字典单选。样品/培养关键词共同模糊，人员关键词在送检人、当前有效签名人/审核人中OR，再与所有权限及其他条件AND。默认固定送检人ID=当前用户，输入显式人员词后替换默认本人条件，不能把两条件隐式叠加成永远查不到他人。设备编码和检测类型保留截图筛选。状态选ALL/UPLOADED/SIGNED/REVIEWED，默认ALL，ALL包含有权且未删除的作废记录。

按上样时间DESC、resultId DESC分页；pageNum>=1、pageSize=10/20/50/100，默认10。详情先查父对象权限再取项/日志；列表返回样品ID、类型、状态、设备编号、固定送检人、上样/完成时间、当前有效签名/审核显示名和审核时间。撤销后当前列清空，旧人/旧时间保留在历史；不能从全体历史中的最大时间猜当前有效动作。UNVERIFIED历史显示“历史签批依据未核验”，不生成新签名快照冒充当时事实。

日志统一投影ActionLog={actionId,resultId,targetResultItemId,operationCode,occurredAt,actor:{kind,userId,displayName},reason,beforeStatus,afterStatus,beforeVersion,afterVersion,relatedActionId,isRevoked,evidenceQuality}。顺序occurredAt DESC、actionId DESC；保留上传/撤回、改ID、异常、整结果作废恢复（旧单项字段仅保留可证历史，不提供新单项操作）、签名审核撤销以及打印导出记录。源表不同必须带sourceKind，不能凭重复的数值主键合并。旧重载action_type只呈现原始事实及未核验标识，不推断成新精确动作。打印记录中的操作时间是系统任务时间，不能显示成设备物理打印完成时间。

沿用GET /detect/approval-record/page、/{resultId}/detail、/{resultId}/logs及GET /detect/audit-log/page；功能码detect:approvalRecord:query、detect:auditLog:query。全局日志查询同样必须有对象范围；历史分享只读、可打印/导出，不赋予任何写入权。错误沿M01公共封装，ID/版本字符串；禁止把权限过滤放到前端。

## 1.1 2026-10-13：M05-064 专用审计查询

`GET /detect/audit-log/page` 绑定 `M05AuditLogQuery`：`labId/projectId/batchId/cultureId/resultId` 为可选正整数字符串，`sampleKeyword/operationCode/actorKeyword` 为可选字符串（首尾去空，最长100字），`beginTime/endTime` 为合法日期或带时区 ISO 时间，`pageNum/pageSize` 为整数。动作精确匹配；样品号及历史操作人显示名按字面子串匹配，不将输入当 SQL 通配符。

缺省近15个上海自然日，含当天；日期型 endTime 包含该日（转次日00:00），精确时间型 endTime 为排他端点。输入先按 Asia/Shanghai 解释，再转换为 UTC DATETIME 查询边界，遵循独立建库的 UTC 会话基线。默认 pageNum=1/pageSize=10，pageSize 1—100；反向/非法日期与分页拒绝为 INPUT_INVALID。

复用 `detect:auditLog:query`，候选来源为 `det_result_sign_record UNION ALL det_print_export_log`，仅接受关联结果的日志；暂存阶段合法 result_id=NULL 日志不属于本查询范围。通过 M05 真实绑定与 M03 历史范围核验后再计数、分页，顺序为操作时间、日志 ID、sourceKind 倒序。跨源同数值 ID 不合并；不借结果项联表重复计数；逻辑删除的历史结果保留范围核验。

成功外壳为 `{code,msg,requestId,data:{rows,total,pageNum,pageSize}}`，不再使用旧接口顶层 rows/total；行沿用 ActionLog/DetApprovalLogVo，包括 sourceKind。旧 `DetApprovalRecordQuery` 的隐式送检人/状态条件不带入本查询。前端需显式适配，当前批次不改页面或 SDK。

当前实现对缺失/损坏历史派发绑定返回 RESULT_PROJECTION_UNAVAILABLE，不以空列表掩盖证据缺口。被新代次替换的旧结果尚待不可变历史归属读取扩展；无关结果的证据缺口也可能使宽范围查询不可用，属于后续 B3/B10 的明确限制，不宣称完整历史审计验收。长日期范围的扫描性能及真实 MySQL 时区配置尚待验证。

业务样品分组沿主设计UI03身份键，不单独按可修改sampleNo或cultureCode合并；不可关联培养的结果不得编造培养sheet。导出前必须输出预览scopeSummary、实际结果数/版本、扩展检测类型、排除项原因；确认后集合冻结。原文“任一检测类型结果状态合格”是批次内样品入选谓词，不是勾选卡片；签名才使用显式卡片集合。文件任务不能把当前页勾选、分页或日期筛选偷偷带入导出，CULTURE/DATE只改变分sheet方式。范围内无权记录始终不进入文件；预览显示无权项数量也须避免泄露未授权对象。数据量超部署配置阈值在预览阶段提示缩小到合法培养范围，不能悄悄截断。异步任务最大结果数/字节数/超时为技术部署参数，缺配置拒绝超大任务，普通可支持范围必须在部署验收记录中公布。

POST /detect/report-jobs/preview 输入{purpose:PRINT|PDF_EXPORT|XLSX_EXPORT,scope:SINGLE_RESULT|BATCH,exportMode?,resultId?,expectedObjectVersion?,projectId?,batchId?,cultureId?,templateProfile}；SINGLE_RESULT仅用于工作台，BATCH按上表必填，拒绝卡片集合及隐藏日期限制。输出精确集合摘要及5分钟确认令牌。POST /detect/report-jobs 输入{confirmationToken,printerId?}，头X-Request-Id、X-Management-Revision，输出{jobId,state,manifestHash}。GET /detect/report-jobs/{jobId}返回状态/原因；GET /detect/report-jobs/{jobId}/file在已具备有效文件且重新验证全部冻结对象当前阅读/导出权限后返回文件。未知job同无权响应，不泄露路径。原/sign-console/print、/export和/workbench/result/{id}/print转同服务；新版不能直接接受客户端fileName/filePath写“打印成功”。UI03“打印”按原文是PDF文件，不因按钮名称自动发物理打印命令；工作台明确选择打印机才用PRINT。沿原打印/导出功能码及对象读取权限校验；同用户+请求ID不同payload冲突。

冻结顺序：M01管理守卫→实验室升序→设备升序→样品升序→结果升序；锁内复核权限、版本、状态，确保每一结果当前版本快照存在，保存完整manifest/selection、模板与映射版本、操作日志截止集合及任务。释放事务后渲染，不能一边查最新值一边逐页生成。长文件任务不长期持数据库锁。撤销签名发生在冻结后不回写已冻文件，但下载重新鉴权；文件标注生成时刻及版本，截至该时刻的真实状态。

功能码明确复用：签名台批次PDF/Excel为detect:sign:export（现Controller的print/export均用此码）并校验detect:sign:query和用途范围；工作台物理打印沿detect:workbench:edit及query；历史详情PDF/打印使用detect:sign:export及对应detect:record:query或detect:approvalRecord:query，不能要求历史分享获得结果编辑权。任务查询/下载只允许原发起者或有该对象/用途审计权限的服务，重新执行相同功能及对象范围校验；仅传purpose不能提权。打印机还需M02当前可用及实验室范围匹配，无可用打印机不影响PDF下载。

权限冻结：`GET /detect/report-jobs/{jobId}`和`GET /detect/report-jobs/{jobId}/file`不是独立的无权限查询；服务端读取任务中固定的purpose/scope，并重新执行创建该任务时的功能码和对象读取范围。BATCH PDF/XLSX要求`detect:sign:export`＋`detect:sign:query`，SINGLE_RESULT工作台PRINT要求`detect:workbench:edit`＋`detect:workbench:query`，历史详情要求`detect:sign:export`＋对应查询权限；原发起者身份只是一项必要条件，不替代功能权限。

## 3. 原模板逐项映射

### 2026-10-11复审补正：非HTTP工具的可信请求上下文

保持下文进程内工具、不新增HTTP路由的接入方案。现有SEC-I01会校验requestId与RequestMetadataContext一致，SEC-I02会再次调用SEC-I01；因此非HTTP工具不得直接调用两Port而忽略上下文，也不得伪造Servlet请求或跳过实时身份校验。唯一新增上下文建立入口固定为目标com.futurefab.system.service.impl.port.m01.TrustedAdminToolAuthenticationAdapter，由work2公共窗口与M05真实核准工具同批交付；这是待实现入口，不表示当前public setter已经受到架构门禁约束。

适配器先验证真实Bearer的签名、到期及可信会话关联，不接受工具自报requestId/sessionKey/actorUserId/authzVersion；验证失败零签名、零发布。随后只在当前同步调用线程、无既存RequestMetadataContext时生成服务端UUID requestId并建立作用域，以该ID和已验证会话调用SEC-I01及SEC-I02。缺上下文沿现有503 AUTH_DEPENDENCY_UNAVAILABLE拒绝，身份或权限拒绝沿现有对应错误处理；不得以初始化上下文代替身份验证。该作用域仅覆盖固定核准/发布流程，不暴露公开set入口、通用callback网关或身份构造器。存在HTTP/工具上下文时拒绝嵌套，不覆盖他人上下文；自行建立的上下文及MDC关联在成功、拒绝和异常出口均finally清理，不写managementRevision、不进入管理写守卫、不跨线程传播。签名记录中的requestId取该服务端ID。

work2实施批新增目标TrustedAdminToolRequestContextContractTest：源码/类型负控制登记requestId建立点仅既有RequestMetadataFilter与上述适配器，工具/业务组件不得自行setRequestId；若存在其他生产建立点，逐个列出并先裁定，不用目录级放宽或删除旧安全断言。正向运行用例须覆盖有效Bearer经真实SEC-I01/I02到达核准操作、非法/过期Bearer零操作、停用/顶号/撤权拒绝、既存上下文拒绝且不被清理、异常后上下文清空及异步线程无上下文。门禁与适配器均未实现、未运行，来源合同由work2登记，不修改SEC-I01/I02 Port签名或原HTTP Filter行为；签名密钥与模板部署仍为独立前置。

#### 2026-10-11复审残余：JWT密钥、会话期限及失败判据

上文“签名/到期验证”按以下精确口径实施，不假称当前已有安全部署：现有TokenService.getLoginUser(String)经JwtUtils.getUserKey调用JwtUtils.parseToken，parseClaimsJws执行签名校验；但JwtUtils.secret当前初值来自TokenConstants.SECRET的公开硬编码默认值，配置样例中的注释不是覆盖生效证据。工具启用前由work2公共安全窗口把token.secret登记为部署必填秘密来源，签发端、网关及工具验签端使用同一受控配置合同；不能只给工具换密钥而签发端仍用默认值。沿现行HS512时使用密码学随机且满足算法强度的密钥（解码后至少64字节），禁止默认常量、样例值或空值回退；密钥只能经受控秘密配置注入，不入源码、交付文档或日志。检出缺失、默认值、非法强度或签发/验签配置未核齐，拒绝启用工具，零建立上下文、零签名、零发布。这是JWT认证密钥前置，独立于报告Ed25519发布签名密钥；密钥配置/轮换须协调既有登录会话和多实例，不能用旧默认密钥作工具兼容回退。本段仅冻结合同，尚未改JwtUtils、签发链或部署配置。

当前签发链不显式设置JWT exp，因此“过期Bearer”以有效Redis登录会话为主要期限事实，不凭空假设exp已存在。适配器严格验签并取可信会话关联后，要求login_tokens对应行存在、Redis剩余TTL为正且LoginUser.expireTime晚于服务端当前时刻；缺行/已过期为会话拒绝，无期限或期限事实不可判定为依赖故障，不自动刷新来使失效票据重新有效。若JWT实际含exp/nbf等时效声明，解析器还须拒绝已失效声明；不以缺exp单独否决现行合法会话。之后仍经SEC-I01/I02核验实时会话替换、停用和权限，签核及发布前复核期限，不把初始化时的一次认证永久缓存为资格。本段不改变普通登录链刷新政策，工具不得调用verifyToken刷新会话后再声称通过到期校验。

工具适配器不能仅调用会吞异常返回null的getLoginUser或只刷新期限的verifyToken作为完整失败判据；复用经受控密钥配置的JwtUtils.parseToken验签机制，并分开处理非法签名/格式/已过期声明、会话失效、Redis或密钥提供方故障。已确认无效身份沿SESSION_INVALID拒绝，认证依赖不可用沿503 AUTH_DEPENDENCY_UNAVAILABLE拒绝；不捕获依赖故障伪装成无会话，不输出Bearer、密钥或会话键。TrustedAdminToolRequestContextContractTest同批补缺/默认密钥拒绝、正确密钥有效签名、错误签名、Redis已过期/无期限/故障、对象期限已过及不调用刷新路径的运行用例，验签算法与密钥覆盖不能只用mock断言方法名。未满足此组条件阻断M05核准工具启用，不阻断独立的ResourceTransactionExecutor与M07消费者开发；不宣称已有认证安全改造或运行验收。

### 2026-10-11核准模板与拥有方

用户确认正式报告只使用已核准的固定模板版本。M05拥有TemplateProfile解析、核准状态及不可变版本，客户端只选择服务端登记的键，不提交font/hash/cellMappings伪造核准。模板版本核准须包含本节既有schema全部字段、真实模板来源及哈希、逐项检项/单位映射、可用字体与渲染器版本；核准身份、时间及依据可追溯。具体配置存储与管理入口由M05登记，不借M04六类工艺模板的template_kind塞入REPORT/PDF。

管理员上传/修改产生待核准的新版本；新版本不自动覆盖已有报告任务。未核准、关键映射缺失或真实资源不齐，不签发可创建正式报告的REPORT_JOB令牌。预览令牌绑定精确profileId/version、资源摘要、渲染版本及冻结结果集合；032只消费该合法冻结载荷，不自行猜模板或重建选择集合。

后端首批载体选择M05受控文件版本清单，而非凭空引用不存在的det_report_job表或必须新增核准表。既有det_print_export_log.template_profile（最长32字符）保存服务端分配的版本键，template_hash保持既有列语义，保存原模板文件SHA256的32字节原始摘要；完整规范化profile摘要作为profileHash存入root的content_manifest.template，不偷换列含义。完整TemplateProfile不塞进该字符串列。清单条目={versionKey,profile:本节完整TemplateProfile,status:DRAFT/APPROVED/RETIRED,approval:{approvedByUserId,approvedAt,evidenceRef,contentHash}或null}。versionKey是稳定唯一ASCII键、最长32字符，不截短哈希充当唯一键；profileId/version同样不能重复指向不同内容。

文件清单、模板和字体按不可变发布工件保存于部署配置指定的M05受控根目录，版本清单只登记相对资源引用及真实摘要；解析拒绝越界路径、软链接逃逸、未知schema、重复版本键、资源摘要不符或审批记录缺失。管理员提交新资源先DRAFT，核准流程生成与内容哈希绑定的真实审批/发布记录后才能APPROVED；受信发布流水线验证记录及目录访问控制，不能接受浏览器自报approved=true。首批以受控导入/核准发布交付后端，在线上传/核准页面后续单独实现；未交付流程/部署核准时不能声称可用于正式报告。

所有实例读取同一发布版本及完整摘要，激活以整版原子替换实现，保留旧版工件供job解析；停用状态可变，profile内容和核准事实不可覆盖。每次预览/创建重验当前核准资格；已建job按冻结版本渲染，下载重验权限与文件hash。若后续需要在线可编辑核准工作流，再单独批准M05表结构方案并同步模块字典、来源DDL、开发基线01/02/03及来源清单；本批不暗加表、不写虚构初始化模板。

已有job始终引用原核准版本，后续模板修改不重渲染覆盖原文件。停用模板禁止新任务，不删除旧版本及既有报告追溯；文件读取仍重验权限和摘要。没有合格模板不输出“通用正式报告”；真实模板、字体许可/文件、单位映射核准和部署阈值/HMAC密钥不得虚构。PRINT还需M02权威打印机事实；无打印机不阻断合法PDF/XLSX用途。

#### 2026-10-11第三轮：发布工件与配置合同

配置键固定为futurefab.m05.report.template-root（服务器只读绝对目录）、futurefab.m05.report.template-manifest-sha256（已核准整版清单64hex摘要）、futurefab.m05.report.template-approval-public-key（核准签名校验公钥；不得配置审批私钥到业务服务）。受控根下每个发布版是不可变子目录releases/<manifestSha256>/，清单名manifest.json；清单schemaVersion=1，包含releaseId、profiles（按versionKey排序的上述条目）、approvalEvidence相对引用。manifest摘要按现行规范化JSON计算，不包含自身摘要或签名，资源分别按原文件字节SHA256校验。配置缺失/非法或目录不受控，模板提供方不可用，不能签发REPORT_JOB；配置静态登记不是发布成功。

approvalEvidence是同版只读核准记录文件，结构固定为{schemaVersion:1,releaseId,manifestHash,submittedByUserId,approvedByUserId,approvedAt,profileHashes:[{versionKey,sourceSha256,profileHash}],evidenceRef,authorizationEvidence:下文第四轮资格证据,keyId,signature}。签名使用Ed25519，对除signature以外的规范化记录字节签名；受信核准工具先验证管理员当前核准资格、真实模板及字体/单位/渲染器证据，再生成记录。发布工具验证签名、公钥keyId、releaseId和全部摘要一致、核准者身份记录可追溯后原子发布；普通业务实例仅验签/读取，无审批私钥和目录写权限。evidenceRef指向保留的核准凭据，不假设sys_oper_log存在request_id列，也不伪造M06审批ID。核准工具与资格核验流程须真实交付；本文件不授予任何普通文件上传者核准权限。

多实例采用同一核准发布工件、同一公钥及同一manifest摘要；部署使用整组切换，不允许混合清单的实例同时接预览/创建流量。就绪检查验证整版资源与配置摘要，路由仅向本次核准发布组放量；切换期间旧组停止新预览/创建，已建job仍可按其冻结release摘要读取保留的旧工件。单机rename不能当作集群原子切换证据。上线记录必须包含实例清单、发布摘要、逐实例就绪、路由切换和回退结果；未完成为BLOCKED_DEPLOY，后端实现及隔离契约测试可先交付，不据此宣称正式报告可用。

2026-10-11第四轮核准资格：新增目标功能码detect:report:template:approve归M05报告核准，由M01权限体系判定；work2窗口登记功能码与来源合同，权限种子只进受控开发包并经实际授权，不写入02-基础数据初始化.sql。本轮仅冻结设计，不新增码位/菜单SQL或授权账号。受控核准工具必须有当前已验证的管理登录身份，通过SEC-I01 ActorContextPort解析真实会话，再通过SEC-I02 FunctionPermissionPort以该ActorContext检查此精确功能码及当前authzVersion；这两个Port不是任意userId授权查询，不得自己构造ActorContext或假造sessionKey。未登记功能码、会话无效、权限依赖不可用或明确拒绝均不得签核；未提供合法认证适配器时不能退化为“能启动工具就是管理员”。核准工具认证及调用接入由拥有方在实施批登记，不新增未编号HTTP核准入口。

## 4. 持久化、打印与失败恢复

复用det_print_export_log，每个冻结result一条，最小resultId对应root行，job_root_id为root.log_id。仅root存大manifest；每行保存同一actor/request，唯一(actor_user_id,request_id,result_id)。一个result仅一份根内引用，重复勾选先归一。root中job_state=PREPARING/RENDERING/READY/FAILED（文件）；物理打印在READY之后SUBMITTED/UNKNOWN，SUBMITTED只代表打印服务接受。本期不宣称纸张已印出，设备回执可作为证据附加但不回写签批。

job_version CAS与root行锁保证单个渲染/打印租约；job_evidence保存leaseOwner/token/expiresAt及尝试过程。渲染先写服务端私有临时文件，校验页数/文件类型/大小/hash后原子重命名并置READY，路径不含未经处理的样品号且不从客户端取值。进程崩溃产生的未发布临时文件由按job归属的清理任务移除，不扫描删除任意路径。同一次重试复用job与冻结manifest；失败渲染可重试，打印提交超时只查询原打印请求，不自动再打。文件存储保留期由既有平台档案策略管理；没有策略时不自动删除。日志保留文件摘要及失效事实。

下载/预览也记录M01访问审计，但不得把访问动作纳入生成中同一文件导致无限递归。manifest日志截止在生成动作前，当前生成动作在文件封面元数据标明。READY必须文件存在且hash一致；任务UNKNOWN不能作为成功统计。当前源码recordWorkbenchPrint仅写客户端提供文件信息、export以cultureId为空推模式，均属于开发要修改的现状，不是已实现能力。

- 同版内容寻址资源为 `releases/<manifestSha256>/resources/<sourceSha256>` 与 `resources/<fontSha256>`。引用仅由已签名 profile 的真实摘要构造，不增加浏览器路径字段；清单、核准记录、模板、字体均禁止软链接逃逸及不符摘要。目录访问控制及多实例发布切换仍须部署验收。
- 私有文件目录配置为 `futurefab.m05.report.report-root`，必须为部署提供的绝对目录；输出键为 `jobs/<jobId>/<fileSha256>.pdf|xlsx`，不是公开 URL。服务端校验字节、原子移动和完整性后才可置 READY；失败不以非原子复制降级，不自动删除历史文件。
- 首批可核准的代码渲染版本为 `M05-PDFBOX-2.0.32-V1` 与 `M05-POI-4.1.2-V1`。标识仅表示具体实现，不能代替对真实源附件、字体、映射、日志/更正页和视觉布局的核准。未核准工件不会因版本串合法就取得资格。
- PDF `templateKey` 作为核准映射行的稳定键，行顺序取 profile 固定顺序。旧Excel发布版的D—Y映射只用于原冻结作业；新版按本专题第3节A:AO布局生成派生模板并登记新的既有发布版本，指标分别映射D:J/O:W/AB:AC/AH:AK，四组签审从各自真实动作读取，不挤占指标映射。移除来源示例数据，保留原指标含义/单位及三行表头样式，培养模式A:B仍为SampleTime；不修改客户源文件。
- `unitPolicy` 可为原单位严格相等的字符串；转换形式为 `{sourceUnit,displayUnit,multiplier,version}`，必须全部显式核准。`displayUnit` 允许空字符串以保留附件空标签，不能从空标签推断源单位。未核准或不匹配时 MAPPING_UNVERIFIED，数值不能静默换标签。原始值和单位仍保留在来源附录。

受信核准工具及 M01 认证适配器仍为独立提供方实施项，缺少它们时不得用测试签名或配置自报 approved=true 充当正式发布。真实模板/字体/单位映射、公钥登记、HMAC/阈值及目录部署为运行输入。物理打印的 M02 权威事实/提交查询链独立验收，不阻断合法 PDF/XLSX 文件用途。


### 2026-10-16 报告任务接线增量

031 请求新增必填 `entryPoint`，固定枚举为 `WORKBENCH`、`SIGN_CONSOLE`、`RECORD`、`APPROVAL_RECORD`，并与用途及范围一同进入令牌和 `content_manifest.renderLayout.entryPoint`。SIGN_CONSOLE 只接 BATCH；WORKBENCH 只接 SINGLE_RESULT；RECORD/APPROVAL_RECORD 只接 SINGLE_RESULT PDF_EXPORT（记录页的打印沿 PDF 下载）；物理 PRINT 只接 WORKBENCH。导出权限为 detect:sign:export 加入口当前 query 功能码；PRINT 为工作台 edit 加 query。读状态和下载按冻结入口/用途重算当前功能权限并逐个复核所有冻结结果，非发起者另需对象/用途审计权，不把记录页用户默认当作签批控制台用户。

032 客户端正文仅有 confirmationToken 和可空 printerId；requestId、managementRevision 只由两个 Header 注入。031 不接受日期、人员、分页或卡片 ID 字段。严格 JSON 绑定拒绝重复键、未知字段和额外正文值。032 同 actor/requestId 的 root 持久化相同规范化请求摘要；超出短期守卫回执窗口仍先回读该 root，当前权限及摘要一致方可重放，不重新创建作业。新请求固定 SYSTEM → M02 全实验室升序 → 全设备升序 → sample/result 升序，在同事务冻结准确 revision 和操作截止快照，写入 root/children 与登记的 M05_032 审计/回执。报告预览不写 revision；创建只可补当前普通版本 BASELINE，不补历史 VERIFIED 事实。

root `content_manifest.schemaVersion=2` 的 `template.profileSnapshot` 保存完整核准 Profile，`renderLayout.signatureFacts[resultId]` 保存普通有效 signId/reviewId 经现有 M05 签名事实读取器校验后所得 `{userId,occurredAt}`，actionId 不得作为签名人显示；更正版本使用其自身已冻结的 submittedSignature/reviewedSignature。详情增加 `hasLaterCorrections:boolean`、`correctionNotice:string|null`、`laterCorrections:[{resultId,frozenObjectVersion,currentObjectVersion,correctionId}]`，提示经过当前对象权限复核的后续有效更正，旧文件与 manifest 保持不变。

`futurefab.m05.report.worker-enabled` 默认为 false，部署在模板、密钥、阈值、私有 report-root 均就绪后显式启用；未启用拒绝新预览/创建，已存在作业仍可重鉴权读取。调度仅处理 PREPARING 或租约过期 RENDERING，短事务认领后在事务外渲染、私有文件原子发布，再以 job_version、leaseToken、leaseExpiry 栅栏写 READY/FAILED。job_evidence.storage 固定 `{objectKey,sha256,sizeBytes,contentType,unitCount}`，同时与根行 file_path/file_sha256 对照；下载先验证全对象权限，再验证实际字节摘要、大小及受控路径。受控 report-root 不对公网提供静态 URL，原子移动不可用不得退化为非原子发布。

证据边界：代码与隔离契约/行为测试不表示真实库、HTTP、浏览器或部署已验收。M01 核准工件生产者（可信当前权限、受控签名私钥及发布）仍是独立缺失代码域，真实核准模板/字体许可/单位策略/公钥与部署根目录为外部输入；业务服务只验签，不生成审批证据。物理打印尚缺真实 submit/query/后台恢复适配器；当前 PRINT 不会假装排队成功或因仅配置地址而开放。


预览摘要增量：`scopeSummary.scopeNotice:string|null` 对批次告知所有日期及全部有权检测类型范围，明确列表人员/日期/分页/卡片不会缩小导出；`ambiguities:Issue[]` 仅针对已授权冻结集合中同 labId/cultureId/规范化 sampleNo/detectClass 出现多条结果给出 RESULT_PAIRING_UNVERIFIED，保持各结果独立，不作为 exclusions。私有存储 requireAvailable 在预览/新提交且 SYSTEM 锁前核验根目录与可写事实；实际原子移动能力必须由 publish 验证，不能以只读就绪门禁冒充发布成功。普通签名链未核验时显示 UNVERIFIED 并保留未知时间，不用动作ID冒充用户；已核验人/时间来自被冻结的真实签名事实。
