## 报告作业 stateReason 词表（非 HTTP 错误码）

M05-033（`GET /detect/report-jobs/{jobId}`）成功响应内的 `stateReason` 字段是"状态原因"，不是 HTTP 拒绝外壳，也不新增 HTTP 错误码：033 的运行拒绝仍只用 `FORBIDDEN_OR_NOT_FOUND`(404) 与 `DEPENDENCY_UNAVAILABLE`(503)。`stateReason` 由服务端按 INT-34 裁决从根行冻结的 `job_evidence.attempts[]` 读时派生（基线无原因列，`attempts[].errorCode` 只作映射输入、绝不原样透出），词表取值如下：

| job_state | stateReason | 含义 |
| --- | --- | --- |
| PREPARING / RENDERING / READY / SUBMITTED | `null` | 非失败或未知态，不返回原因 |
| FAILED 且关键必需映射缺失 | `MAPPING_UNVERIFIED` | 模板或映射未核准导致生成失败（对应 §原句"关键必需映射缺失时任务FAILED/MAPPING_UNVERIFIED"） |
| FAILED 且为其它渲染/生成失败 | `RENDER_FAILED` | 渲染或生成过程失败，外部 `errorCode` 不透出 |
| UNKNOWN | `PRINT_STATE_UNCONFIRMED` | 打印/外部回执未确认，只能查原请求 |
| FAILED / UNKNOWN 但无终态尝试证据或 `job_evidence` 不可解析 | `REASON_UNAVAILABLE` | 保留未知，不编造原因 |

权威尝试选择规则：仅在 `job_state` 为 `FAILED`/`UNKNOWN` 时取终态尝试——按 `endedAt` 最大、`endedAt` 为空回落 `startedAt`、仍并列取 `attemptId` 最大者为唯一权威；无可用尝试或证据不可解析即 `REASON_UNAVAILABLE`。

## 报告作业创建链路（M05-032）作业状态与阻塞口径（INT-35，非新增 HTTP 错误码）

M05-032（`POST /detect/report-jobs`，输入 `{confirmationToken, printerId?}`，头 `X-Request-Id`/`X-Management-Revision`，输出 `{jobId, state, manifestHash}`）本期**未落码**，仍按自身编号返回 501，不新增 HTTP 错误码。其运行拒绝的 lawful 口径与既有码位如下（供接线批直接复用，不重复设计）：

- 缺失、过期或与当前 `actor`/`managementRevision`/payload 不一致的 `confirmationToken`：`CONFIRMATION_EXPIRED_OR_CHANGED`(409)，不自动重试、须回 031 重新预览。
- 同用户 + 同 `X-Request-Id` 不同 payload：`MANAGEMENT_CONFLICT`(409)；同 payload 重放返回原任务回执，不重复生成审计（唯一 `(actor_user_id, request_id, result_id)`）。
- 功能码/对象读取范围不足：与其它无权统一失败关闭，不泄露存在性。

落码后 root 行**只能停在契约允许的等待态 `PREPARING`**（范围已冻结、尚未渲染）；`RENDERING`/`READY` 必须由 `ReportJobRules` 的真实渲染租约与已校验文件事实驱动，本批不得伪造 `READY` 或文件摘要。

不可落码的精确前置（三项，缺一即不可，均非"设计未定"泛称）：① `confirmationToken` 的 purpose `REPORT_JOB` 在 `src/main/java` 里零签发/校验方，唯一 lawful 签发入口 M05-031 预览仍 501，其令牌 payload 形状亦无已落地生产者冻结；② §2/§3 冻结顺序要求 root/child 同事务前按实验室→设备升序加行锁，而 `service/port/m02` Port 面无 `FOR UPDATE` 读出口（跨模块前置，M07 `PlanReplacementPort` 已证可加锁，缺的是 M02 侧一个加锁读方法）；③ 核准 TemplateProfile 载体（`rendererVersion`/`font_sha256` 等）与 PDF 渲染库尚未落地。证据由 `M05ReportJobCreateChainBlockedEvidenceContractTest` 钉住。连带口径：M05-033 因唯一生产者 032 无 root 行写链仍 `BLOCKED_DATA`；M05-034 仍 `BLOCKED_EXTERNAL`（渲染/存储）。

## 报告作业预览链路（M05-031）落码预评估与阻塞口径（INT-40，非新增 HTTP 错误码）

M05-031（`POST /detect/report-jobs/preview`，输入 `{purpose, scope, exportMode?, resultId?, expectedObjectVersion?, projectId?, batchId?, cultureId?, templateProfile}`，输出 `{scopeSummary, confirmationToken, expiresAt}`）本期**未落码**，仍按自身编号返回 501，台账 `wired=false`、`perm=null`，不新增 HTTP 错误码。其运行拒绝的 lawful 码位以骨架清单登记为准（`INVALID_REQUEST`、`FORBIDDEN_OR_NOT_FOUND`、`MANAGEMENT_REVISION_CONFLICT`、`DEPENDENCY_UNAVAILABLE`），确认令牌本身的失败关闭沿用既有 `CONFIRMATION_EXPIRED_OR_CHANGED`(409) 与密钥缺失 `DEPENDENCY_UNAVAILABLE`(503)，均由共享签发器 `M05ConfirmationTokens` 已实现并测试。

本批承接 INT-35 的决定性发现（032 缺 lawful `REPORT_JOB` 令牌生产者）评估上游 031。结论：**八层精确前置，缺一即不可落码**，且本批**未收窄** INT-35 的阻塞①（`Purpose.REPORT_JOB` 在 `src/main/java` 仍零引用，报告作业应用服务未接入签发器）：

2. **TemplateProfile 归属未登记**：现行设计树内 `TemplateProfile` 只出现在本模块的导出设计与本文件，无 M02/M04 侧登记表或接口认领。`BLOCKED_DESIGN`（载体归属待裁决）。
3. **预览阶段阈值配置键无载体**：§2 要求"数据量超部署配置阈值在预览阶段提示"，且"异步任务最大结果数/字节数/超时为技术部署参数，缺配置拒绝超大任务"；三个部署值在全仓配置源（`nacos-config/*.yml`、服务 `bootstrap.yml`、模块资源）零命中，键名亦未登记。依约不得编造默认值。`BLOCKED_INPUT`。
4. **必响应字段 `scopeSummary.versions` 语义未注册**：§2 只写"实际结果数/版本"未拆叶子，`M05完整目标字段字典.md` 与 `审阅收尾完整字段字典.md` 均无 `scopeSummary` 条目，契约类型自身留痕"设计文档未定义，待补充"。`BLOCKED_DESIGN`（单点字段）。

6. **`REPORT_JOB` 令牌 payload 字段清单无权威定义**：信封 7 键、5 分钟 TTL、`purpose`/`actorId`/`managementRevision` 绑定、payload 非空且必须服务端形成、摘要与密钥缺失失败关闭——这些基建已冻结并有测试；缺的只是 payload 业务快照字段清单，其唯一候选来源 `content_manifest` 的 `template:{profile,version,sha256,fontSha256,rendererVersion,mappingSnapshot}` 又依赖第 1 项。`BLOCKED_DESIGN`。

## 外壳与验收

HTTP失败的code与状态一致；字段定位只含当前有权对象。认证失败、管理请求失败和领域异步结果分别解析。400/409保留非敏感草稿，401清敏感身份，403/404隐藏无权对象。任何结果未知的写请求先查原身份，不自动生成新UUID。每个接口的错误集合由本表及其明确引用的生产方定义组成，不要求所有接口返回所有码。

样例构造：选择本表HTTP码，errorCode为精确码名，code为同一HTTP整数，requestId为原请求ID；其余外壳字段严格采用所属接口既有定义。运行事件使用其reasonCode/issues，不套HTTP外壳。测试须覆盖同键重放、同键异载荷、无权、旧版本和依赖故障。
