# HT 批量发送锁等待与 QA 残留排查修复

日期：2026-10-25。基线 HEAD：`558c4e2df`。本轮仅修改 M05 内部实现、相关测试与文档；未修改公共锁序、跨模块 Port、数据库结构、Nacos 或模拟服务。修改未提交、未推送。

## 1. 发送准备阶段的查询放大

既有调用链为 `DetWorkbenchController → M05SampleMutations → ManagementGuardExecutor → save → M05SendPreparation.persist → CommunicationUsageRegistrationPort → CommunicationUsageRegistry → M05CommunicationUsageFactsAdapter`。设备外部调用由提交后的 `M05PreparedDispatchProcessor → M05DispatchExecutor → adapter.submit` 执行，不在准备事务内。

已确认的放大点：M05 每追加一个通信使用关联，事实核验器先对所有历史登记分别 `selectSample/selectResult/selectDispatch`，再完整锁读设备三类原生集合。入口与 persist 又重复登记一次同一样品。15 条正常发送原来执行60轮登记与全量核验，已知 HT 设备目前有202个样品、606条 M05 关联，累计查库随历史增长显著放大；SYSTEM 管理锁在这些准备工作期间仍持有。运行库语句摘要也存在数万次该类点查，但摘要是累计值，不作为某一批请求的独立计数。

本轮改动：

- DETECTOR 身份已固定时，按原顺序完整锁读样品/结果/派发，建立种类+主键索引，核验所有登记身份、资源键和实验室；每次核验固定3次完整查询，保留未登记原生活动和 UNKNOWN 阻断。
- 缺行、异设备、异实验室、非法关联、重复原生身份均失败关闭。不跨事务缓存，不仅核验新增子集，不修改下游身份发现路径。
- 发送由 persist 同事务登记三类关联，入口不再重复登记样品；15条降为45次登记。暂存及容量不足保存为未发送草稿仍正常登记。登记与 CAS、审计、回执整体回滚语义不变。
- 保留 guardedMs 并补 guardEntryMs/guardCallbackMs，区分进入回调前与业务回调耗时。这些字段不等于 MySQL 行锁持有时间，未宣称已测得精确持锁时长。

真实库只读查询形态对照：使用相同606条关联、相同字段投影，旧核验609条 SQL，新核验3条 SQL，均无 SQL 错误。运行耗时4347ms/2881ms包含 JVM启动、连接和输出，且未执行 SYSTEM 写事务或真实15条受理；不把此微基准当作受理耗时/并发验收。证据 `.local-start-tools/ht-read-benchmark.json` 及同目录 old/new SQL与输出。

## 2. 新 QA 的 UNKNOWN/pending 与 timeout 原因

对 `QA-CDP-W-ZM1-9N25*`、`QA-CDP-W-ZN1-9N25*` 重读样品、派发、耐久事件和源任务。每列状态分布与模拟器后缀规则一致：

| 样品尾号/通道 | 原始证据与结果 | 处理 |
| --- | --- | --- |
| 7 | `send_orders|0100000000000007|CedexMissingDevice` | 保留UNKNOWN及原请求 |
| 8 | `send_orders|0100000000000008|CedexSubSystemOrdersError` | 同上 |
| 9 | `send_orders|0100000000000001|样品ID`，非空回执 | 不符合已核准空成功回执，保留UNKNOWN，不从文本猜测安全释放 |
| 0（ch10） | `send_orders|0100000000000007|CedexNotRunning` | 保留UNKNOWN |
| 4（ch4/ch14） | CDP夹具刻意不安排完成；源Status=5、EndTime=NULL | 保留超时和RUNNING/RECONCILING，不能伪造迟到完成 |

前四类对应耐久事件均为 `NATIVE_ACCEPTANCE_UNPROVEN`；查表 source_order_count=0，既有派发 UNKNOWN、样品 RESERVED、结果 pending/OPEN/NONE。没有源订单不等于能证明设备绝未受理。主系统正式接受/拒绝证据契约未改；没有把 UNKNOWN 自动改成 rejected、COMPLETED 或 RELEASED，也没有重发。

根因是本轮 QA 直接以01..15结尾，混入了模拟器故障/永不完成用例，并非物理通道7到10天然不能发送。后续正常15条场景应选择批准前缀内的唯一ID，把位置编号放中间，最后数字固定1；负向用例另行隔离。不得为了出双列截图清掉旧未知任务。
