## 九、发现、风险与建议

本轮未发现需要修改生产代码的确定缺陷。以下为需要主任务裁决或补证的事项：

1. **HT 隔离夹具缺失（`BLOCKED_EXTERNAL`）**：HT 冻结 120 秒、模拟器完成延迟 90 秒，无法自然构造超时后迟到。建议新增“HT 同型号、冻结阈值 < 90 秒”的隔离设备，或独立模拟器把延迟调到 > 120 秒；不要改共享阈值。复现：在 HT 上发送任一样品并读取最新 `collection_basis.detectionTimeoutSeconds=120` 与 `start-mock.ps1:35` 的 90 秒即可复核。
2. **同批多行运行时未复验（`NOT_VERIFIED`）**：本轮运行包只发送 1 条，批次合并、一次 CAS、整批回滚只在契约测试验证。建议在隔离实例上发送一批 2–3 条并核对使用行只加一次版本、链接数为 3×条数、全部成功或全部回滚。主任务上一轮两列各15条运行在同一修复jar（SHA-256与本轮复用包一致），其运行证据有效；仅不能作为本轮独立复验多行批次的证据。
3. **统计 SQL 的候选窗口（观察项）**：新流程行在 SQL 中不按时间窗过滤，只按 `LIMIT` 取候选；`ORDER BY r.testing_end_time` 会把旧列为 NULL 的新流程行排在前面。当前 481 行无影响，但长期增长到 `maxPoints+1`（默认 120 万）后，任意时间窗查询都会整体拒绝（`M05StatisticsSourceAdapter.java:32`），而不是返回窗口内数据。是否需要按 `timeEvidence` 持久化列或分页，属设计裁决。
4. **上限拒绝缺直接测试（覆盖缺口）**：`M05StatisticsSourceAdapter.java:32` 的“达到候选上限即拒绝”没有对应单测；现有测试覆盖类型/偏移/窗口/回退，不覆盖该分支。建议补一例“返回 limit 行即抛 INPUT_INVALID”。
5. **单条登记错误文案变化（低风险）**：`CommunicationUsageRegistry.java:242` 把 null 单条转成 null 批次后，空值错误从“通讯关联登记请求不能为空”变为“检测通讯关联批次不能为空或超过受控上限”，错误码仍为 `INPUT_INVALID`。若有外部断言依赖旧文案需同步。
6. **取证缺口**：发送请求的双版本头未留存；浏览器隐藏导致截图与检测中帧缺失；历史签名摘要未做数据库比对；重复观察不重复上传只到契约层。相应条目已按 `NOT_VERIFIED` 标注。
