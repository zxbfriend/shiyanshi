## 2. 实现与修复

1. 原 HTTP 2xx、code/msg 成功回包持久化为平台接收事件；回执展示“平台已接收，设备受理待确认”，不伪造设备已开始事实。
2. HTTP 查询在数据库事务外执行，保留原始字节。短事务收件，锁内重新核对原派发、M02 通信版本、样品/结果身份、占位代次和冻结检项；正式结果、版本与上传原子推进。
3. 仅映射已配置检项的源编号，名称和单位来自冻结配置；未配置 DO 不进正式项，也不显示设备原生结果。
4. 完成时间使用有批准时区的源 `resultTime`，写入可信 `time_evidence.completedAt`。不以采集时间替代，也不回填 `actual_started_at` 或旧 `testing_end_time`。
5. HTTP pending 的平台计时与一般设备待检测计时区分，必须核验本次原始平台接收事件；超时保留占位与代次，不发送新命令。迟到结果仍入原结果。
6. 真实回包带附加 `success` 属性曾导致提交解析失败：现允许附加响应字段，仍严格以 HTTP 状态和 code/msg 判断，不能仅凭 `success=true` 认定成功。由此产生的 QA UNKNOWN 保留原文，未自动恢复。
7. 模拟服务精确 QA 完成时间在订单接收时冻结，查询重放不再改变完成时间；默认样品行为不变。移除相关端点的密钥、token日志输出。
8. 复审补强：按冻结平台结果地址、设备编码及样品号跨内部设备查重，并对同内部设备的同名历史派发保守阻断，包含缺少冻结平台身份的旧记录；歧义/非法回包及时间冲突耐久隔离为 `UNMATCHED/AMBIGUOUS`，不写业务结果，相同原文去重。
