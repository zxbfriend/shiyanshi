## 2. 配置模型

型号维护规则模板，实例引用已核准的模板版本；第一版不增加实例任意覆盖。规则引擎输入不使用detectClass/detectType/modelName做行为分支。协议适配器仍可按既有协议键路由，且需声明支持的规则能力；配置不能凭空让设备支持排队或位置定位。

| 字段 | 类型/范围 | 精确语义 |
| --- | --- | --- |
| schemaVersion | 固定1 | 配置结构版本，不等同管理版本 |
| profileRevision | 服务端版本 | 配置发布修订，不由客户端指定生效 |
| layout.columnCount | 正整数 | 页面列数，HT为6；等于型号库`column_count`（需求“排数”），2026-09-29用户确认 |
| layout.rowsPerColumn | 正整数 | 每列填写位置数；等于型号库`channel_count`（需求“通道数”，即左侧填写区行数），2026-09-29用户确认；BGA的100是填写区，不推导100个物理检测工位 |
| layout.topology | LIST / MATRIX / RING | 位置布局与寻址，LIST不声称设备具有相应物理载具 |
| supportStored | boolean | 启用即同时显示行暂存和列批量暂存；false不显示两个主动暂存按钮 |
| sendMode | single / column | 行按钮提交1条，或列按钮提交同列候选集合 |
| singleSendLimit | 正整数 | 本次请求最多样品数；single请求仍严格为1，Cedex Bio配置24不变成批发或并发上限 |
| scheduling.queueEnabled | boolean | false：接受并开始后本次样品均testing；true：一个testing，其余pending。对应需求08首表“在设备上排队”列（2026-09-30用户定义该列语义） |
| scheduling.selectionOrder | NONE / PHYSICAL_CYCLE / ADAPTER_REPORTED | 不排队用NONE；圆盘按物理位置循环；设备主导且顺序未经确认时按真实反馈展示，不自行模拟FIFO |
| workCapacity.unit | SAMPLE / COLUMN | 工作占用量纲；独立于sendMode，不由column自动推导COLUMN |
| workSendLimit | 整数≥0 | 同量纲活动占用上限，0仅表示本项不限，不是累计按钮点击次数。需求08首表“工作状态下可发送次数”列即该设备可同时检测的数量，落到本配置由workCapacity.unit＋workSendLimit与queueEnabled共同表达，不是与该列一一对应（2026-09-30用户定义） |
| protection.lockScope | POSITION / COLUMN | 已发送位置保护，或该列本轮全部已发送样品完成前整列保护 |
| occlusion.enabled | boolean | 是否存在额外物理遮挡；与pending/testing状态保护叠加 |
| occlusion.initialBlockedPositions | 整数位置集合 | 已核准初始状态下不可使用的位置；不能在运行位置未知时当默认值 |
| occlusion.activeOffsets | 整数偏移集合 | 相对当前检测位置的遮挡；圆盘首尾环绕，例[-1,0,1] |

工作容量按全部活动请求统计，包括已预占待派发、设备已接受未完成及结果未知的请求；不按页面当天可见记录统计。COLUMN单位按不同占用列去重，向同一活动列合法追加时新增列数为0；SAMPLE单位按不同未完成样品身份计数。POSITION锁允许在其他合法位置追加，不需要另造“无限追加”开关。COLUMN锁的释放集合固定为本轮提交的样品，不包含未填写空位。2026-09-30需求方第八轮问答补充（Cedex Bio HT，需求方陈述层级）：该型号"没有整列说法，只看单条"，即设备不回报"整列测完"，因此本段的释放集合口径不变、不得据"等待时长到点"或"提交条数凑满"推定整列完成事实；列的整体状态与列锁释放时机只能由单条回话聚合得出，该聚合口径属M05消费侧、须由该模块负责人复核，本轮未改任何配置数值与判定规则，出处见[需求澄清决策记录](../../需求说明书V4.0-0904_md/需求澄清决策记录.md)同日第八轮问答第3项。**"只回了部分项目"能不能腾位已由2026-10-01第二十九轮问答裁决（需求方答复"同意，只要还有项目没回结果就不腾位"）**：需求按"拿到任一检测项结果"把页面状态置为"已检测"，但**该展示态不是可信终结事实**——一次送检里还有项目没回结果时，本段的工作名额统计、COLUMN 释放集合与位置占用**一律不变**，该样品仍算未完成、仍占名额，排队设备的队列**不因此前进**，左侧不可删；转 COMPLETED 只认设备整次完整结束的事实，或已按既有异常终结规则人工处理过的事实，**不得由"已检测"字样、回到的条数或等待时长推定**。落点见[检测工作台接口与位置生命周期](检测工作台接口与位置生命周期.md)第 5 节、[检测状态三向映射表](检测状态三向映射表.md)第 3 节，出处见[需求澄清决策记录](../../需求说明书V4.0-0904_md/需求澄清决策记录.md)同日第二十九轮问答。

2026-09-30需求方第四轮问答逐台确认混放口径：七型号（BGA、Cedex Bio、Cedex Bio HT、OSMO-1、OSMO-2、OSMO-3、Vi-CELL）均允许在同一列或同一队列内同时存在不同项目、不同批次的样品记录，HT明确为“一列内可混放”，不要求同列同项目或同批次。该口径与上段“POSITION锁允许在其他合法位置追加”“COLUMN锁释放集合固定为本轮提交的样品”一致，**不修改任何配置数值、不新增字段**；此前登记的“摆放口径在需求表与本文之间不明”至此消解，出处见[需求澄清决策记录](../../需求说明书V4.0-0904_md/需求澄清决策记录.md)2026-09-30第四轮问答第3项。

不开放脚本、任意表达式或管理员编辑状态白名单来绕过pending/testing保护。更换型号名称不改变行为，变更规则才改变行为。静态配置约束包括：单次上限不得超过每列行数；COLUMN锁须有可识别列与完成证据；PHYSICAL_CYCLE须RING且queueEnabled=true；遮挡位置必须在范围内且去重；偏移按环绕后去重；queueEnabled=false必须selectionOrder=NONE。当前设备例子满足这些约束，新增能力超出现有枚举需升级schema，不伪称任意设备零开发支持。

## 4. 运行事实与统一操作判断

配置描述能力，运行投影描述事实：DeviceQueueSnapshot={detectorId,profileRevision,queueRevision,communicationState,positionEvidence,activePosition,columns,positions,activeRequests}。位置身份为detectorId/columnNo/positionNo；每次装入新样品产生新的sampleId及位置占用代次，业务sampleNo可按已有规则复用，不能拿新1号覆盖旧1号请求。

positionEvidence区分INITIAL_CONFIRMED、ACTIVE_CONFIRMED、DERIVED_FROM_TASK（按任务表推算）与UNKNOWN。只有确认初始姿态才使用initialBlockedPositions；运行时按当前位置计算遮挡，公式为blocked=((activePosition-1+offset) mod N+N) mod N+1。检测从1号转2号时原1号即使检测完成仍被遮挡；转3号后1号解除遮挡，完成且其他规则允许时可删除并装入新1号。2026-09-30用户二次确认该两段口径：圆盘没有工作时被挡住的是10、11、12，工作状态下遮挡集合随当前读数位变化，与initialBlockedPositions＋activeOffsets模型一致，不新增字段、不改配置数值；该确认层级为用户陈述与实物照片，非设备手册或位置回报。

**不映射的两类**：**`occupancy_state='RELEASED'` 不映射任何标签**——该行退出"当前占位集合"（不进入引擎 `occupants`），但样品行、结果与签批历史一律保留，与第 4 节"完成不是左侧自动删行"、增量设计第 4 节"左侧移除完成样品／删除从未发送草稿"两行一致；**空位不生成虚构 DRAFT**——某位置没有未 RELEASED 行时该位置就是空位，请求里的新候选（`sampleId` 为空）不因此获得任何占用事实。

**四条硬规则（本表判定必须逐条满足，不得以枚举优先级替代）**：

- **① 只认当前占用代次**：发送记录必须与样品的 `sample_id`＋设备＋位置＋`occupancy_generation` 唯一关联才参与判定；`det_dispatch_log` 所指代次与样品行代次不一致时，该样品判 UNKNOWN。**旧代次不得推进新样品**——同位置腾位后再装的新样品是全新身份与代次，迟到回调只关联原身份（第 4 节既有口径）。
- **② 先校验一致性，再判断阶段**：占用态、`queue_status`、调用生命周期三者矛盾时**统一 UNKNOWN**，不得因为标签表从上往下匹配就挑一个"看起来最近"的阶段，不得用枚举顺序掩盖矛盾。

- **④ 标签只供规则引擎内部使用**：不新增页面状态名、不改第 2 节三向映射表的任何展示行、不覆盖第三十二轮"沿用『待检测』字样、不新增中文状态名"等既有展示裁决。

| POST /detect/workbench/sample/save-draft/batch | 新目标入口，列暂存，1..rowsPerColumn条显式候选，原子保存 |
| POST /detect/workbench/sample/send | 复用单发，严格1条且sendMode=single |
| POST /detect/workbench/sample/send/batch | 复用列发，同列候选，sendMode=column；POSITION配置支持活动期间追加 |
| DELETE /detect/workbench/sample/{sampleId} | 复用行删除，执行同一位置删除判断 |
| POST /detect/workbench/sample/delete/batch | 新目标入口，提交同列显式sampleId/objectVersion/occupancyGeneration集合，逐项处理并保存回执 |

action为SAVE_DRAFT/SEND/DELETE，行或列由入口和候选数共同限定；evaluate不授予正式写入权。所有写入口带Authorization、X-Request-Id和X-Management-Revision，提交profileRevision及对象版本；真实labId、sampleId归属、位置代次和动作权限由服务端取得，不信任客户端allowedActions。新建候选使用clientRowId，已有对象使用sampleId及objectVersion；业务字段沿现有样品白名单后续完整DTO，不允许提交queueStatus/resultStatus/操作者等服务端字段。

批量删除返回DeleteBatchResult={requestId,requestedCount,deletedCount,skippedCount,items:[{sampleId,outcome:DELETED/SKIPPED,reasonCode,message}]}。requestedCount为去重后的非空显式对象数，等于deletedCount+skippedCount；已删除、版本变化、待检测、检测中、列锁、遮挡、无权限等返回可安全展示的原因；无权对象不泄露培养或操作者信息。重复ID、跨列/跨设备、格式错误为整请求参数错误；整请求无功能权限直接403，不能伪装全跳过成功。

技术实现建议：取得公共管理/设备/列/位置/样品的稳定顺序锁，逐项检查状态并条件更新；业务不可删仅记SKIPPED，可删项与完整回执在一个本地事务提交。数据库/依赖系统故障则回滚本次全部写入并返回错误，不把故障伪装业务跳过。queueRevision变化触发重读逐项判断，不因任一行变化让整列批量删除失败；profileRevision或公共授权管理版本冲突则请求失败刷新，不能按旧配置判断。24小时内同请求ID及同载荷重试返回原回执，不重新删除原先跳过而后来变可删的样品；再次操作需新请求ID。同ID异载荷拒绝。此处“跳过”与主设计11节签批原子确认集合有意不同。

发送采用本地原子预占与设备派发分步：锁内校验并持久化本次集合/固定规则/请求身份；事务提交后派发；按可信接受/拒绝/未知反馈更新，不在数据库事务中等待设备。批量本地准入原子不等于设备批量执行原子；协议部分接受须逐样品保留事实，不能全体回滚后重发。未知先查原请求。设备幂等/查询能力需逐适配器验证，不宣称通用引擎可以保证外部exactly-once。
