# M05 受控更正、报告范围与审计保留确认

2026-09-11，用户已确认采用推荐方案。M05-Q09：历史身份不能核验、原签名人离职/停用时提供受控更正；Q10：批次报告不沿用列表人员/日期筛选；Q11：审计数据暂不自动删除，可受控归档。本文件只新增上述已确认范围，不恢复添加审批人入口、不改变暂存本人限制。原两轮审阅保留原文；此前“没有更正入口/没有本期未答问题”是本次确认前的范围描述。

## 1. 历史证据与更正边界

保留旧结果、原签名、旧用户名与时刻，禁止用当前用户冒充原签名人。证据不足的历史继续UNVERIFIED；更正通过只证明当前人员对新版本负责，不把旧签批链升级VERIFIED。原始测量、设备开始/完成事实仍须独立取证，不能因为人工审核通过而从UNKNOWN变COMPLETE。

准入覆盖历史链UNVERIFIED/CONFLICT且有更正需要，或原有效签名/审核人账号已停用、离职且不能正常撤销的结果；离场依据须来自账号/组织生命周期或受控附件，不能仅由客户端勾选。原记录应已形成检测结果，pending/testing或关联当前尚未核对的物理运行不得更正。仅历史缺设备结束时刻或历史完成依据，不单独阻止提交：以当前设备/样品关联证明没有仍在执行的本次运行，旧完成依据仍保留UNKNOWN；不能以更正解除占位或伪造终结事实。正常本人六动作继续使用原入口。

更正以同一resultId的新不可变版本承载，不复制样品、不产生新检测任务，不改设备任务ID/样品代次/培养/实验室归属。只允许对有原始记录或核准证据支撑的指标值、单位、项目映射、项有效性及说明提出更正；缺证据的指标保留原值与UNVERIFIED或明确排除，不能手工填0或凭签批制造测量。增加新的实际测量走正常新检测流程，不伪装为旧测量更正。

历史身份有充分证据时可在本次证据包说明账号映射及原动作关系，仍不直接修补旧活动指针。旧动作恢复功能继续要求唯一可核验原动作；本次交付是新增更正版本通道，不提供覆盖历史的回填工具。

## 2. 权限和页面

复用结果详情/签批详情，增加“发起更正”和更正历史入口；有权查看者能看到原版与当前更正版标识、差异、当前签名/审核和历史依据质量。提交前展示原/新内容、理由、附件、受影响报告及下游使用摘要并二次确认。无权对象不返回身份或使用明细。

新功能码detect:correction:submit与detect:correction:review独立授予，不自动给超级管理员或现有角色。提交还须detect:sign:sign和当前普通结果操作范围，排除仅历史分享；审核还须detect:sign:audit及M05-Q01/Q02当前资格。发起人即新版本签名人，审核人必须是另一个稳定userId；不得冒充已离场人员。审核时重验双方账号有效、提交者原操作范围及签名权限、审核者当前资格。角色变化/权限服务不可用按403/503拒绝，不沿用提交时权限快照放行。

更正历史读沿原结果用途权限；附件下载须同权限并重验，技术原件仍需技术审计权限。管理员不豁免双人约束。受控更正专用双人审核，不复用已删除的审批人名单、不由M06培养方案审批策略决定。

## 3. 状态和原子生效

SUBMITTED→APPROVED / REJECTED / WITHDRAWN / STALE。提交即冻结完整候选与新签名声明，无可编辑服务端草稿；页面未提交内容仅本地草稿。SUBMITTED内容不可改，退回后需新申请。REJECTED、WITHDRAWN、STALE及APPROVED均终态，保留证据不物理删除；一个结果同一时刻最多一个SUBMITTED申请。

提交记录baseObjectVersion和baseCorrectionId、原版精确快照及hash、候选完整ResultSnapshot和hash、规范差异、1—500字原因、不可变附件ID/version/SHA256、提交者稳定ID/当时显示名/签名声明时刻。提交不是生效，原有效结果继续使用；原值本已不可信时继续按原规则排除。需立即标识疑似错误时沿现有有权异常处理，不由提交更正自动停止设备。

审核APPROVE绑定精确candidateHash及基线；理由1—500字且重验当前身份、证据可读/摘要、字段与单位、来源事实及同一结果归属。候选不能由审核者就地改写。锁序SYSTEM→真实实验室→设备→样品→结果→更正申请；所有入口一致，网络/归档读取在事务外完成，锁内重验版本与凭证。提交/撤回/决定均使用M01管理版本、回执和本地事务。管理版本或结果基线冲突返回409，不静默接受最新版本。

审核发现结果object_version或current_correction_id已变，原子记录STALE及原因，返回409 CORRECTION_BASE_CHANGED；不生成结果版本，用户须重新提交。若另一个请求已作决定，重放原决定或返回终态冲突，不能覆盖。申请本人可以撤回；有审核权限且不同人的审核者可以拒绝。APPROVED不能改回SUBMITTED，后续错误另提新的关联更正。

批准同事务：插入det_result_revision完整新快照（object_version+1、event_kind=CORRECTION_APPLIED、source_kind=CORRECTION、source_id=correctionId）、更新det_result.object_version及current_correction_id、申请APPROVED/result_revision_id/审核签名、公共审计与回执。原det_result业务内容列、det_result_item、签批原动作和旧revision均保留，不原地改数字/原签名；仅新增技术指针与版本递增。不修改样品物理状态、占位或设备完成事实。事务回滚不留下半生效指针。

## 4. 唯一当前结果读取及后续操作

current_correction_id=NULL沿原结果投影；非NULL必须由统一resolveEffectiveResult(resultId,purpose)联查APPROVED申请及其result_revision_id，核对结果ID/objectVersion/contentHash，读取该不可变新版本。找不到或不一致返回RESULT_PROJECTION_UNAVAILABLE，不回退旧det_result数值作为当前。更正表是申请证据，不是另一套检测结果主表；权威结果版本复用det_result_revision。

新ResultSnapshot schemaVersion=2：保留schema1全部键，增加correction={correctionId,baseObjectVersion,baseCorrectionId,baseContentHash,candidateHash,reason,evidenceRefs,changedPaths,submittedSignature,reviewedSignature,legacyEvidenceQuality}。新当前resultStatus=reviewed，activeActions为原结构的空旧动作指针，当前签名/审核明确从correction两份新签名投影；不伪造det_result_sign_record原有效动作ID。候选规范hash域M05_CORRECTION_CANDIDATE_V1，包含基线身份/版本、待审内容、差异与证据，排除审核决定与生成时刻；最终contentHash域M05_RESULT_V2包含批准后全量内容及两份签名，排除自身hash，不改变历史schema1算法。提交签名绑定candidateHash，审核签名绑定同一candidateHash、提交签名及决定，不允许同人。

2026-10-13 B3 读取实现约定：schema2 的最终摘要输入固定为 `{"domain":"M05_RESULT_V2","content":<移除顶层 contentHash 后的完整快照>}`，复用 `NormalizedPayloadHasher.canonicalJson` 的对象键排序、数组保序和 JSON 转义，再对规范 UTF-8 字节计算 SHA-256（64 位小写十六进制；不是幂等回执的 HMAC）。两份签名至少具有文本 `userId`、`candidateHash`，完整 JSON 必须分别等于申请行的 `submission_signature`、`review_signature`，未知扩展字段也参与整体相等与最终摘要核验。读取同时核对 APPROVED 状态、结果 ID、精确 revision ID、baseObjectVersion+1、当前更正指针及双人身份。当前更正版缺失或任一关联不一致时失败关闭；精确旧版本不要求仍是当前指针，但必须保有自己的批准证据。该约定不改写历史签批 `snapshot.content` 摘要，也不为 schema1 历史快照重算新摘要。

内部 `M05EffectiveResultReader` 最多批量读取 500 个不同结果 ID，空集合不触库；批内缺失、重复返回或版本错配整批失败。无更正且无不可变版本时只返回明确 ORIGINAL 标识与当前版本事实，不合成历史快照、不代替原版内容核验。跨模块精确版本 Port 不接受 ORIGINAL 标识冒充不可变结果。该服务不承担用途授权，调用方必须先核验身份、功能权限及对象范围；授权边界不因内部读服务共用而放宽。schema1 内容摘要来源、047/记录/签批全部消费方的统一接线仍需后续 B3 完成。

候选查询的首次筛选与版本关联校验在同一个只读 REPEATABLE_READ 事务中执行。存在更正指针时，状态及项目条件读取当前不可变快照的 `resultStatus`、`items`，不能借旧结果状态或旧明细排除合格更正版；schema2 通过批准及完整双签名核验后，Port 的 `irreversible=true`，不依赖旧版有效签批动作指针。

列表、统计、详情、报告、导出、queryEligibleResults以及M07人工确认读取全部走统一当前投影，不能继续SQL直接过滤旧状态/数值后再装饰新内容。数据库分页实现可联查当前revision的固定JSON路径做投影与过滤，不能先对旧状态分页导致遗漏。源设备晚到包仍耐久保存，若试图改已更正当前结果则待核验，不自动覆盖。旧det_result、det_result_item当前直读旁路必须在开放入口前清理。

当前为更正版时普通六动作及结果改写入口返回USE_CONTROLLED_CORRECTION，页面引导新增更正；不在原版指针上撤销新签名。更正通道始终允许有新证据者对已更正版再次申请，不再要求原人员离场，审核仍双人。以此避免原表状态与新版本发生两套写入。历史版按getResultRevision精确可读，禁止普通接口直接更新revision内容。

ResultChanged外层schemaVersion=2用于CORRECTION_APPLIED，payload为完整schema2快照。消费者未支持schema2时明确拒绝/重试，不默默按旧版解析；M05、报告、M07消费者兼容后才开放更正写入口。发布沿现有事务发件箱至少一次机制、按(resultId,objectVersion)去重，不新增第二个发件箱。

新取数使用更正版且仍逐项核验来源、单位、完整性及调用方规则；更正签批资格与测量可信度是两个维度，整体evidenceQuality及各指标依据按证据如实保留；reviewed不自动使未知值可用于补液。M07取数与人工确认必须同步校验当前版本，旧已缓存候选被更正后失效；历史计算/确认保留精确旧版本和影响关联，不自动重算、不反向执行物理补液。更正通知用于提示已消费记录核对；无ACK不能宣称下游处理完毕。M08继续暂停，本次只定义兼容边界，不实施其设计。

## 5. 接口及持久幂等

目标HTTP统一前缀/detect/result-corrections。所有ID/版本十进制字符串。写请求带Authorization、X-Request-Id、X-Management-Revision；规范hash由服务端算，拒绝客户端actor/status/hash/resultId改绑字段。

| 方法/路径 | 请求 | 返回/约束 |
| --- | --- | --- |
| POST /preview | resultId,expectedObjectVersion,changes,evidenceRefs,reason | 完整差异、candidateHash、基线、影响摘要、5分钟确认令牌；只读 |
| POST 根路径 | confirmationToken | correctionId,state=SUBMITTED,version,managementRevision；令牌绑定本人、完整候选/证据及基线；提交是本人新签名确认 |
| POST /{id}/decision-preview | expectedVersion,candidateHash,decision=APPROVE或REJECT,reason | 当前证据与差异、影响摘要、5分钟决定令牌；只读 |
| POST /{id}/decisions | confirmationToken | 绑定本人、APPROVE/REJECT、理由、申请/结果/管理版本；返回state,resultRevisionId或STALE冲突 |
| POST /{id}/withdraw | expectedVersion,reason | 仅SUBMITTED申请人；记录WITHDRAWN |
| GET /{id} | 无写参数 | 原版/候选/决定/版本/权限内证据；无权与不存在统一响应 |
| GET 根路径 | resultId,pageNum,pageSize(10/20/50/100) | 当前有权结果的更正历史 |

changes仅为稳定itemId的显式白名单字段替换及说明；无测量证据、身份/时间改写、未知单位转换拒绝CORRECTION_EVIDENCE_INSUFFICIENT。基线未核验不等于可改任意值。reason首尾去空白，附件1—20个受控不可变引用，单个已通过平台大小/类型校验；预检把实际可读内容固定到保留策略，不存客户端路径或凭据。

持久唯一(submitted_by,submit_request_id)且提交正文hash固定；终结唯一(terminal_actor_id,terminal_request_id)。所有写在M01公共回执之外同时查更正表持久键，回执过期仍返回原结果；同UUID异正文409 REQUEST_CONFLICT。终结hash绑定申请ID、动作、版本、理由和候选hash；不同申请同终结键冲突。预检令牌过期只影响尚未处理请求，不阻止合法重放。普通403、503及版本409沿M05原错误语义，新增CORRECTION_ALREADY_PENDING、CORRECTION_BASE_CHANGED、CORRECTION_EVIDENCE_INSUFFICIENT、USE_CONTROLLED_CORRECTION、RESULT_PROJECTION_UNAVAILABLE；技术失败重试同键，不生成新UUID掩盖未知结果。

## 6. 报告与导出（Q10）

批次PDF、按培养/按日期Excel沿确认批次全部日期及原类型展开规则，只纳入有权对象；不沿用列表人员、日期、页码、勾选。人员筛选只影响列表。预览固定提示“报告按批次授权范围生成，不沿用列表人员及日期筛选”，展示实际范围、数量和更正版标识。后台preview拒绝隐藏人员/日期限制；requestedFilters只作来源页面审计，不进入选取谓词，增加ignoredListFilters说明。单份resultId报告保持单份范围。

新报告冻结当前有效版本，并保存更正ID/原版本/原因/新签名审核；原报告不覆盖、不换文件内容或hash。下载旧报告时页面显示“该报告部分结果已有更正”及有权查看的版本链接，文件本身仍是生成时刻历史。PDF在独立更正说明页披露差异和双人签名；Excel保留既有sheet及A:AC列布局，追加“更正说明”sheet，仅有更正时生成，避免把人员姓名无提示替换成新值。原打印日志不假记重打，更正版另建文件任务。

## 7. 审计保留与归档（Q11）

det_device_event原文、det_result_revision、签批/更正/编辑记录、关联证据和报告文件暂不自动删除；本期不设TTL/定期DROP/逻辑删除掩盖历史。HTTP幂等回执原24小时规则不变，长期领域记录用于回执到期后的防重。报告文件原平台档案策略如包含自动删除，对这些M05审计对象必须配置保留覆盖；部署不能只保留摘要却删去唯一原件。

允许归档：当前有效版本、活动签批引用、未决更正、尚未发布消息及未处理事件保持在线；已终结旧附件/原文可转受控归档，保存逻辑ID、精确版本、SHA256、位置、授权与恢复状态。通过copy→hash/数量验证→独立恢复演练→原子切换读取位置→核验至少一份持久副本可读的过程，才可释放在线重复字节；归档不是删除历史。当前SQL包不移除BLOB，也不交付清理脚本。归档读取失败返回ARCHIVE_UNAVAILABLE，不以最新版本补缺或生成空白报告。

容量按真实设备观测峰值×平均/95分位原件字节×天数，加结果变更数×版本字节、更正附件及报告字节，分别估算在线/归档/备份容量；部署采样填实数，不虚构设备吞吐。容量告警、配额及恢复时限纳入部署验收；容量不足阻断新的不可靠持久化并告警，不暗删旧证据。后续自动清理期限须另行确认，不能以本次归档授权推导删除授权。
