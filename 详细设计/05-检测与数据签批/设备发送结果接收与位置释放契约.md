# M05 设备发送、结果接收与位置释放契约

## HTTP 平台接收与结果关联补充（2026-10-27 用户确认）

HTTP 通道取得可确认的平台接收回包时，检测超时按平台确认接收时间起算；平台接收与设备实际开始检测仍是不同事实，不得伪造设备开始时间。通信异常、无回包或无法确认接收的调用仍为 UNKNOWN，保留占位且不自动重发。按设备编码与样品 ID 查询 HTTP 检测结果并关联原任务；必须校验冻结设备、样品、结果、派发和占位代次，保留原始响应，按冻结检测项编号映射并通过正式收件和版本事务入库。旧 UNKNOWN 不能仅凭本条规则批量解除。该补充为需求确认；实现与验证分层见本文下一节及[2026-10-27 HTTP 验证记录](history/review/2026-10-27-HTTP平台接收计时与正式结果采集入库-验证.md)，模拟验证不代替现场验收。

### HTTP 正式采集的实现与证据边界

- 原发送回执新增独立的 `PLATFORM_ACCEPTED`，页面显示“平台已接收，设备受理待确认”；不显示成设备已受理，原 `UNKNOWN` 不随版本升级解除。
- 非排队和排队 HTTP 样品均在原平台接收事件应用后开始业务超时计时。排队中的 `pending` 仅在 `businessStatus.basis=SDMS_PLATFORM_ACCEPTED` 且原 HTTP 回包、派发、样品、结果、代次全部可核验时参与；命名管道的待检测规则不变。超时保留占位及原起点，不重发。
- 正式结果启用由逐设备 `formal-result-enabled` 登记控制；冻结 `sdmsResultAdmission`、结果查询地址、设备编码、原样品编号、检测项/名称/单位、明确来源时区和核准引用。来源时区不取服务器默认值。历史派发缺少该冻结依据时不借当前配置回填。
- `M05SdmsObservationProcessor` 在事务外读取原通信修订并查询平台 `order/get`，使用原设备编码及样品编号，按原接收时刻和明确来源时区构造查询窗口。返回的多个同名样品、重复检项或未经核准的子样品拒绝自动关联；相同设备样品编号存在多个派发时拒绝任选当前任务。
- 原始响应字节持久化至既有 `det_device_event`，适配器为 `SDMS_HTTP_V1`，契约为 `SDMS-RESULT-1`，不伪造 CDP 任务主键或设备原生修订。同语义轮询复用原事件，已应用事件只读短路；未应用事件在重启后继续重试，不重新发送设备命令。
- 锁内复核通信版本、原接收事件、派发、样品/结果指针、占位代次和对象版本后，仅将本次冻结的检测项写入 `det_result_item`。数值保留设备字符串格式；单位不匹配、错误值、空值和未配置项不产生正式测量，不填零或覆盖既有项目。发生不同值或不同可信完成时间时保留冲突事件，不覆盖历史。
- 完成时间只取平台结果 `resultTime`，按冻结的已核准时区转换为 `time_evidence.completedAt`；缺失、非法或时区偏移不唯一时不伪造。`completion_observed_at` 是我方观测时间；`actual_started_at` 不填平台接收时间，旧 `testing_end_time` 不作为新流程的完成依据。**「2026-11-04 修订」：本条为最终口径，M05 新链不写 `testing_end_time`、不回填历史，页面改读 `time_evidence`；详见本节末“单设备单通道修订”。**
- 全项正常且完成时间可信时，原样品推进至 `COMPLETED`，历史占位仍经正式清空/跨日规则处理。培养关联样品自动生成一次 `SYSTEM/AUTO_UPLOAD` 动作和结果版本；非培养样品保留人工上传入口。`detect_mode=manual` 仍表示页面人工发送，与培养结果自动上传互相独立。整次收件应用、明细、状态、版本和系统上传在同一事务中回滚或提交。
- 页面“刷新结果”与后台调度复用该正式采集链；仅当未归属该正式范围时才判定其他通道，不将托管结果交回旧兼容轮询。模拟服务验证和现场设备验收分别报告，运行层结论以本轮验证记录为准。

### 2026-11-04 单设备单通道修订（用户裁决）

- **背景**：现场确认命名管道与 HTTP 两条通道都在用。**2026-11-04 用户裁决采用「一台设备只允许一种通道」**，通道中立唯一键方案已否决；约束落在 M02 既有设备通信配置 `lab_communication.communication_type`（`device_kind='DETECTOR'` + `device_id`，字典 `smp_communication_type`，检测设备只取 `HTTP`/`NAMED_PIPE`），为唯一来源，不得在派发快照或型号能力字段再配一遍。
- **落地**：保存时拒绝同设备双通道（现有 `LabCommunicationApplicationServiceImpl.java:486-489` 的设备唯一校验 + `01-完整建表.sql:964` 的 `uk_m02_business`；需补切换期在途校验与提示“一台设备只能选一种通信方式”）；启动巡检拒绝 0 行/多行/非法通道并阻断该设备调度；切换按“停旧通道→在途收尾→启新通道→记录切换时间与操作人”执行，期间不得双跑；切换前已入库结果不重算、不回改，只保证不新增重复。
- **调度分流**：按设备当前通信配置决定走“管道查表”还是“HTTP 取数”，不再硬编码 `adapterKey`（现状 `M05CdpObservationMapper.xml:159-168` 只认 `NAMED_PIPE_V1`、`M05SdmsObservationMapper.xml:4-13` 只认 `SDMS_HTTP_V1`）；配置缺失/非法/与冻结派发不一致时拒绝调度并告警，不静默跳过。
- **防重等价性**：单设备单通道把跨通道重复收敛为“同设备不可能双取”，通道内既有 `dedup_key`/`(result_id,item_code)` 唯一键与签批版本守卫负责“同通道重复轮询不新增、已签批不被覆盖”，两者组合即等价于跨通道防重。详见[接收事件持久化与结果字段设计](接收事件持久化与结果字段设计.md) 2026-11-04 增量条款第 2、4 节。
- **完成时间**：上文“旧 `testing_end_time` 不作为新流程的完成依据”**继续有效并升级为最终口径**——M05 新链只写 `time_evidence.completedAt`（源标记完成时刻，如 `resultTime`/`EndTime`），`completion_observed_at` 仅为我方观测时间，`det_sample.testing_end_time` 不写新值、不回填历史，页面改读 `time_evidence`。原文中“证据充分时可写 `testing_end_time`”的表述按「2026-11-04 修订」限定为历史兼容/其他模块，不再适用于 M05 新结果链。
- **同库**：命名管道通道读取 `cdp_testing_*` 的同库访问边界见[设备适配与结果采集核对清单](设备适配与结果采集核对清单.md) 2026-11-04 增补条款；本条不改变 HTTP 的接口取数方式。

## UNKNOWN 原证据受控恢复（2026-10-26 用户确认）

新增独立动作 `M05-DISPATCH-RECOVER`。`GET /detect/workbench/dispatches/{id}/recovery-preview` 只读返回证据摘要、当前样品/结果版本、原代次及可恢复类型，顶层带 SYSTEM managementRevision。`POST /detect/workbench/dispatches/{id}/recover` 要求查询与编辑权限、实验室操作范围、X-Request-Id、X-Management-Revision、X-M05-Contract-Version=2；Body 为预览的 evidenceHash、sampleVersion、resultVersion、generation 和必填 reason，不接收客户端状态、测量值或源地址。

入口默认关闭；必须在服务端按 dispatch 日志主键逐条登记 `futurefab.m05.unknown-recovery.dispatches.<id>.approval-reference`，且仅核准 QA-MOCK 原派发。本轮授权不是对真实设备错误码的通用放行。来源仍使用原派发冻结的精确 M02 CDP 登记；源定位和读取在写事务外完成，事务内重验来源登记、通信修订、原始派发、样品/结果指针、位置代次、双对象版本及证据摘要。零候选不证明未执行；多候选、已删除、不同设备/样品、不同来源均拒绝。

仅两种允许结果：① 已冻结 BGA 正式准入、唯一未删除且正常完成并有测量的源任务，可追加“源任务证明已接收”的受理证据，原调用转 RESOLVED/ACCEPTED，再由既有受理投影、正式采集和版本链推进。不能把源快照伪装成当年的命名管道 ACK；原回包和冻结 JSON 不变，缺历史 timeContext 不补造。② 原始完整 Cedex send_orders 回包精确为 CedexMissingDevice/CedexSubSystemOrdersError/CedexNotRunning、错误位匹配、源任务候选为空且逐派发已核准时，追加确定拒绝证据并释放该次 RESERVED 工作预占，原样品和结果不删除，保存未执行终态与原证据引用。BGASampleSended、重复样品提示、通信异常、空包和其他错误继续保护。

恢复在原管理守卫事务内追加事件、改变派发事实、记录审计及耐久回执；原事件原文/hash 不覆盖，同请求同载荷重放不新增事件或自动采集，异载荷冲突。该动作无设备发送客户端依赖，不发命令、不自动重发、不调用人工取消。BGA 后续投影可独立重试，恢复确认成功不冒称正式采集已完成；结果状态在检测记录中核对。

## 3. 发送接受与部分成功

发送分两层身份：HTTP requestId关联用户幂等回执；dispatchId/request_id关联一次真实设备调用。预占事务固定所有sampleId/resultId/位置代次、规则快照和本次项目集合后才允许网络调用。预占失败不发设备；网络调用在事务外执行，失败后不抹掉已提交意图。

| 事实 | 每样品接受状态 | 处理 |
| --- | --- | --- |
| 字段/容量/权限校验失败，尚未创建派发意图 | NOT_ATTEMPTED | 请求拒绝，不发送，不生成设备已拒绝事实 |
| 已有意图，但可证明尚未调用 | NOT_ATTEMPTED | 可以继续同一已授权意图；这不是自动发送普通暂存 |
| 设备明确接收该任务 | ACCEPTED | 保留工作占用；是否pending/testing另看排队与开始依据 |
| 设备明确拒绝且保证没有执行该任务 | REJECTED | 释放该样品的派发工作预占，保留失败历史，重新发送由用户发起 |
| 请求超时、连接断开、空响应、无法解释响应 | UNKNOWN | 保留占用，先查询原调用，不盲目重发 |
| 仅知道批量整体失败 | UNKNOWN或有证据的逐项结果 | 不能默认所有样品未执行 |

例：一列提交A/B/C，设备确认A接收、B拒绝、C未知。A保留运行占用；B保留可人工修正重试的记录；C等待核实。POSITION模式其他空位独立判断；COLUMN模式只要本轮还有A/C未终结，该列保持保护。明确拒绝的B保留在原提交集合但标“未执行终态”，不被当成永远待完成；也不伪造它检测成功。COLUMN正常/异常释放分别依据真实成员终态，不能删除失败成员来缩小历史集合。

单条调用展开批量时也记录每个调用独立结果；停止后续未调用项需标NOT_ATTEMPTED，不能因其中一条已成功而重发整批。没有协议级幂等支持时，不承诺外部恰好执行一次。

本形状是**映射前的设备侧收件事实**（信封层），落在 det_device_event 的观测载荷里；它**不是** `det_result_revision.content_snapshot` 的 `items[]` 键名，两者键名不同源（`sourceItemCode`/`subSampleRef`/`sourceRevision` 属源侧标识，快照明细按持久列命名）。快照明细元素的权威键名以[自动检测与跨模块结果契约](自动检测与跨模块结果契约.md)4.1（INT-11 冻结，2026-10-07）为准；本节的 `itemOutcome` 取值域与该清单一致，仍为 VALUE/ERROR/NO_MEASUREMENT/UNKNOWN。

关联优先级：

1. 已认证设备、固定的真实设备任务ID或调用ID，命中当次不可变item_bindings。
2. 经核准的中间表任务主键或设备原生run标识，建立到原dispatch/sample/result/位置代次的映射。
3. 旧协议仅有业务样品号时，只有在包含历史/别名的完整候选范围内，有可信设备、时间隔离或任务边界证据证明唯一，才允许兼容关联；“当前只有一条未完成”不是充分证据。

无法证明唯一时保存UNMATCHED/AMBIGUOUS事件，不改结果、不释放位置、不把旧值写入新样品。禁止仅按最新sampleNo、页面位置、采集时间最接近或数据库最新行匹配。已删除或已腾位样品的迟到事件仍首先关联原内部身份，其历史处理不能污染同位置新样品。

## 5. 幂等、乱序与更正

先持久化原始观测与接收回执，再做关联和领域状态应用。接收回执有RECEIVED/APPLIED/DUPLICATE/UNMATCHED/CONFLICT/RETRYABLE_ERROR，不把“已收到”说成“结果已更新”。只有事件已耐久保存才向可重投的适配器确认接收；存储故障返回可重试，不吞掉事件。解析无效或身份不可信的流量按接入错误处理，不执行领域更新。

事件去重命名空间由已核准的源实例/设备事件空间定义，不能因本应用重启或代码升级随意变化。优先nativeEventId＋明确nativeRevision；同一键同一语义载荷重放原处理结果；同一键不同语义载荷保留冲突证据并阻止自动覆盖。原生事件号会重用时，必须有可信源任务/运行周期隔离，不能无依据自造周期。

无原生事件ID的轮询观测，可在已唯一绑定任务且协议明确是同一份快照的前提下，由稳定任务身份、项目/子样品、源修订或源时间及语义摘要产生去重键；不得包含本次轮询时间。不能证明同一事件时只记录独立观测，禁止仅凭相同数值丢弃合法的新检测。JSON对象键顺序等表示差异不应变成结果更正；原始字节及标准化语义分别留痕。

乱序规则：有可信源序号/修订时只推进对应事实版本；没有序号时不按接收先后决定哪个数值“最新”。完成后迟到STARTED不回退为testing；先收到结果、后收到接受回执时合并一致证据，不降低已确认事实。位置证据单独按可信时间/序号核对；旧任务位置事件不能改变新任务当前检测头位置。

相同指标相同源修订重放不增加结果版本；明确新增指标或核准的新修订才增加版本。已签名/已审核/已作废结果收到不同值或新的更正包时，保存待核验更正事实，不直接覆盖签批快照、不自动撤销签批或恢复作废。当前确认范围没有手工改数值或更正审批入口；更正包保存待核验，不自动更改已签批内容，边界见[结果操作第2节](检测记录与结果操作设计.md)。

## 6. 完整性、采集终结与位置释放

结果完整性沿主设计13节expectedItems固定集合，按稳定项目/子样品映射比较集合，不能按返回行数凑齐。NONE/PARTIAL/COMPLETE/UNVERIFIED与设备NOT_FINISHED/FINISHED/UNKNOWN独立。

## 7. 轮询、超时与恢复

采集候选依据未闭合的调用/收集事实，而非只取result_status=testing：包括已接受待检测/检测中、tested但PARTIAL、timeout但仍可能回传、调用接受UNKNOWN及已腾位历史的待核验事件。扫描以调用/事件稳定主键游标分页，不能用UI日期筛选或删除标志切断历史恢复。

网络读取在数据库事务外；取得观测后进入单事件或一致原始包的短事务。按公共管理守卫→设备→样品→结果→明细/有效动作的既有锁序重读身份、版本和状态，应用结果、完整性、位置版本及事件APPLIED回执同事务提交；数据库故障全部回滚该次应用，持久化的RECEIVED仍可重试。解析版本固定，重新解析不得暗中覆盖旧应用事实。

对已确认业务冲突保存CONFLICT/UNMATCHED并退出自动重试；对暂时数据库失败有限退避重试原事件，不重新调用设备发送。原始结果包、事件与签批事实的保存周期需按项目审计要求核定，不能沿用HTTP回执24小时后删除全部证据。

超时值读取本次固定能力快照，区分接受等待、开始等待和实际检测耗时。当前仅已有检测timeout配置，不把同一数值偷偷套成所有阶段超时；新增阶段监控阈值需明确工程来源。设备无开始时刻时不能把提交时刻伪装成检测开始时间；上样时间按原08成功发送事实保留独立业务含义，精确时间字段对应需同步最终结果字段包。2026-09-30需求方第七、八轮问答确认（需求方陈述层级）：七台的接受等待时长一律以资源管理的检测设备型号配置里设置的"超时设置"按台判断，超时后仍保留占用并先查证原调用。**该口径的"系统与文档不预设固定值、不把设计侧建议值写成常量"部分已被同日第十三轮问答修订（统一默认600秒、配置页仍按台可改），第十四轮问答进一步确认七台一律使用该默认值、没有例外**；本段"不把同一数值偷偷套成所有阶段超时"的限制不变。出处见[需求澄清决策记录](../../需求说明书V4.0-0904_md/需求澄清决策记录.md)同日第七轮第1项、第八轮第2项（原口径）、第十三轮第4项与第十四轮（现行口径）。

**超时量的是哪个窗口（2026-09-30 第二十三轮问答，需求方裁决层级）**：需求方答复"**只数真正在测的时间**"，即超时计时对象是**该条样品停留在"检测中"业务状态的时长**，**排队等待（"待检测"）的时长一律不计**。需求 `08-检测分析.md` 第 180 行（"检测中"状态停留时间）与第 276 行后半句（"以发送检测需求的时间作为起点"）互斥，**本轮以第 180 行为准、第 276 行后半句作废**，两种口径不得同时实现。四条硬边界：

- **实际只改变排队的三台**：BGA、Cedex Bio、Cedex Bio HT、OSMO-1 不排队（`可配置发送暂存与删除规则设计.md` 第 4 节上表 `queueEnabled`＝否，需求第 175 行"发送后即为检测中"），两种算法等价；OSMO-2、OSMO-3、Vi-CELL 的队列中除首条外均为"待检测"（需求第 174 行），这些记录**不参与超时计时**。
- **计时起点是业务状态进入时刻，不是设备开始检测时刻**："检测中/待检测"由我方在发送成功后置位（需求第 128 行），机器不回报"这条我开始测"（第十、十一轮 F-10 的真实开始时刻记录两台均未取得；第十二轮 Vi-CELL 圆盘位置亦只能推算）。故排队三台的起表时刻属**推算值**，起点误差直接进入判定。**该推算时刻不得写入 `actual_started_at`、不得当作设备确认的开始时刻**，与本段上一段"不能把提交时刻伪装成检测开始时间"同向；页面若展示"检测中起始"须按第十三章口径标明是系统置位时刻。
- **由此产生的空档（已由同日第二十四轮问答处置）**：机器把样品收进队列却一直不开始测时，该记录停在"待检测"，按本条**永不报超时**；而第六至十二轮已确认七台都不给拒收回执，超时到点原本是唯一自动发现手段。需求方第二十四轮答复"**不设新时限，但显示排队时长**"：**不新增**"排队等待上限"数值、**不新增**配置字段，改为对"待检测"的样品在页面**展示它已等了多久**（例如"已排队 25 分钟"）。三条硬边界：①**展示不产生判定**——不得因该时长超数就报超时、不得据此释放位置或列锁、不得自动重发、不参与 `configurationReady`，措辞不得与"超时"混用；②**不得把同一个 600 秒套到待检测阶段**（承本段"不把同一数值偷偷套成所有阶段超时"，本轮再确认）；③**排队时长从"我方记录成功发送"的时刻起算**（需求 `08-检测分析.md` 第 903 行），属我方业务事实而非设备回报，层级与上一轮"起表时刻为推算值"相同，回报与推算不符以回报为准并记差异；不排队的四台无"待检测"档（需求第 175 行），**不得给它们造排队计时**。风险如实登记：系统侧仍**无任何自动告警**，长时间不动须人工发现，该风险由需求方知悉承担（同第五、十二轮的推算类风险），本轮不改动任何状态列。出处见[需求澄清决策记录](../../需求说明书V4.0-0904_md/需求澄清决策记录.md)同日第二十三、二十四轮问答。
- **数值与处置未改**：仍为 600 秒、七台无例外；超时后 UNKNOWN/RESERVED 保留占用、先查证原调用、不自动释放、不自动重发、迟到合法结果按原任务补齐。出处见[需求澄清决策记录](../../需求说明书V4.0-0904_md/需求澄清决策记录.md)同日第二十三轮问答与用例 M05-RX32。

时间字段交接：send_requested_at为本地发送请求时点；现testing_start_time按原页面“上样时间/成功发送”语义保留，不能又当作实际检测开始时点。真实检测开始需独立actual_started_at目标字段；设备结束时刻有证据才填testing_end_time，系统首次观测到结束另需completion_observed_at。这两项新时刻及旧历史时间质量标识尚未加入20列包，后续接收数据库包统一冻结；历史本地接收时刻不改名伪装设备时间。

## 8. 接收事实的存储交接

已交付20列仅覆盖规则、占位和发送意图，不足以承担耐久事件收件、每事件去重与冲突原文保留。det_result.raw_data是结果聚合原文；当前det_dispatch_log是调用事实；均不能在不扩展模型的情况下当作完整事件历史。不能用重复覆盖raw_data代替接收日志，也不能挪用业务签批审核日志作为设备收件表。

新增技术收件对象建议命名det_device_event，只保存观测、关联及处理回执，不创建平行检测结果主表。必需字段组为：eventId、可信设备/源命名空间、原生事件键/修订、原始字节及摘要、语义摘要、接收/源发生时间、关联dispatch/sample/result/位置代次、关联状态、应用状态/结果版本、重试次数/下次时点、错误码及冲突关联。无原生ID时去重键可空，不以NULL伪造唯一性。

同键不同载荷需要保存两份证据；物理唯一约束必须允许保留冲突，不能仅一个唯一键使第二份原文被插入失败后丢掉。接收状态与业务更新应共享本地事务；跨服务事件存储如果后续归并M08，需另给出同等耐久交接和幂等证据，当前不假设M08已经提供。

本轮冻结上述接收职责及不变量，技术收件表物理DDL、结果完整性/采集状态及源时刻的字段映射仍需并入后续接收数据库包；不修改已完成的20列包计数，也不声称现代码已具备事件持久化。未完成这项存储与身份映射之前，不应进入真实自动结果覆盖/位置释放验收。
