## 2026-10-13 B6 接线补充：M05-024

`PUT /detect/workbench/result/{resultId}/exception` 的 JSON 只接受三个字符串：`expectedObjectVersion`（正整数）、`exceptionType`（1—50 字）、`noteContent`（首尾去空后 1—500 字）。拒绝额外字段、重复键、数字型版本及正文中的身份/请求头字段；路径 resultId 与可信 `WriteMeta` 由 Controller 组装内部 `M05ExceptionWriteRequest`，该内部对象不接受 HTTP JSON 绑定。

请求须带 `X-M05-Contract-Version: 2`、`X-Request-Id`、`X-Management-Revision`。入口要求 `detect:workbench:query`；新写入在管理守卫中另要求 `detect:workbench:edit`、当前对象操作范围及真实 `sent_user_id` 本人。管理员无代办豁免。结果和样品均须 pending/testing，且当前结果、派发、占位代次和锁内版本与归属快照一致；更正中的结果拒绝此动作。

合法类型来自 M01 `FormCandidateFactsPort` 的 `m05_exception_type` 字典。只接受唯一已启用编码；不创建默认生产字典值。未提供核准值为 BLOCKED_DATA，依赖无法读取为 DEPENDENCY_UNAVAILABLE。`det_exception_note` 保留编码/说明，v2 `MARK_EXCEPTION` 动作快照固化字典名、字典项 ID、编码、显示标签、占位代次、请求摘要和首次回执；历史展示不得改用当前字典覆盖旧标签。

SYSTEM→实验室→设备→样品→结果锁序下，异常说明、动作快照、样品/结果状态及版本、队列 CAS、公共审计和幂等回执同事务提交。状态改为 exception，停止正常推进；原始数据、派发、占位状态及占位代次不改，不发送设备取消命令，不视为设备已停止或释放位置。

同键同内容成功重试先验证当前读取范围，再回放原业务回执与首次 `managementRevision`，不依赖字典仍启用或结果仍为 exception；异体为 REQUEST_CONFLICT，证据损坏为 RESULT_PROJECTION_UNAVAILABLE。骨架登记不代替数据库事务/部署 HTTP 验收。

全部人工写入校验功能权限、当前有效可操作对象范围、非删除结果、锁内版本和状态。历史分享只读。下表本人指固定送检人sent_user_id；身份未知拒绝依赖本人条件的动作。

| --- | --- | --- |
| 修改样品ID | tested/uploaded；有操作范围 | 仅sampleNo、关联解析和必填原因；记录所有旧新ID，不改检测值 |
| 手工上传 | tested；有操作范围 | uploaded；保留当前完整性和真实缺项，不因手工上传补值或释放位置 |
| 自动上传 | tested、固定期望项目正常结果全部取得、真实已关联培养 | uploaded；同接收事件事务写系统动作，不冒充送检人或网页用户 |
| 撤回上传 | uploaded且送检本人，无有效签名审核 | tested；撤销准确有效上传动作，原因沿现有接口必填 |

| 整结果作废/恢复 | 原合法状态及适用作废审批配置 | 需审批时通过后作废生效，免审批沿原合法流程；恢复保留原合法链，不增加单项操作或依赖任务暂停/恢复 |
| 单个检测项作废/恢复 | 不在需求范围 | 不提供本期业务入口；既有历史字段/旧接口存在不代表需求已授权 |

| 右侧结果删除 | pending/testing，二次确认 | 逻辑隐藏该结果，保留设备请求、原文、版本和占位；非取消命令 |

自动上传的“正常全部取得”按固定expectedItems映射逐项判断，ERROR/NO_MEASUREMENT不填成正常数值；保留异常/缺项并继续核对。全部失败按异常结果处理。手工上传保持原文tested可执行语义；PARTIAL必须在详情和后续快照明确显示，不能变成COMPLETE。签名并不把缺失/错误指标变为可计算值，M07逐指标执行消费准入。

标记异常的原文操作矩阵允许pending/testing，当前实现testing/tested需调整；不把tested开放异常作为目标规则。异常后迟到数据仍归原结果并保留，但不自动撤销人工异常或恢复上传；普通页面不增加“恢复异常/改原数值”操作。更正包按接收契约保存待核验事实，本期未提供更正审批入口，不把未来扩展列为本期遗漏。

单个检测项作废及恢复属于此前额外推导，已撤下。作废针对需求规定的整条结果/样品操作；不按“页面与整条一致”推导单指标审批，也不将作废审批与自动补液或校准任务联动。

## 3. 样品ID、上传事实和逻辑删除

2026-11-07原生澄清106：D0修正不触发本节改号，既有编号、历史别名、真实培养关联与检测时刻保持。用户确需改号仍走本节原手工入口及全部原条件；准备期新号D-1及无明确关联候选的识别见[工作台样品身份节](检测工作台接口与位置生命周期.md#v51样品身份与培养关联2026-11-07)。不增加所有状态可改或批量自动重命名分支。

结果列表返回objectVersion（结果版本）和sampleObjectVersion（关联样品版本）；修改ID请求分别将两者作为expectedObjectVersion、expectedSampleVersion提交，任一缺失时页面提示刷新并停止提交，不能互相替代。修改ID请求还需带expectedSampleVersion。服务端复用已确认的长度/编码校验（中试不套用可视化格式强校验），按新ID重新解析培养；确实无培养时执行既有二次确认。重新关联必须同时满足原/目标范围权限，不通过修改cultureId规避Q01审核资格。原发送绑定、当时参数和源任务ID不变。

占号按真实lab_id＋detect_class串行核验所有已发送未删除记录及其det_sample_id_history别名，不能仅锁一个设备排除同实验室另一设备的竞争；使用既有公共实验室守卫，在同一事务查号和写号。暂存内部重复另按原暂存规则。样品ID历史、结果动作、样品版本和结果版本同事务写入。新每次送检使用新sample_id；旧sample_id绑定多个结果且不能证明合法一致修改范围时拒绝自动重命名并列历史核验，不静默改动已签名兄弟记录。

active_upload_id指向当前有效UPLOAD/AUTO_UPLOAD动作。撤回只从uploaded恢复tested，不从旧日志任意beforeStatus恢复到其他状态。手工上传主体与固定送检人分开保存；自动主体为SYSTEM和触发事件ID。撤回设置source_progress中的manualUploadSuppressed=true，阻止下一次轮询把用户刚撤回的同一份完整结果立即自动上传；再次人工上传或新一次独立送检才能开启新的上传动作。重复事件不重复生成自动上传。

右侧删除复用det_result.del_flag=2，并记录DELETE_RESULT动作和不可变删除版本；sample保留作为设备跟踪对象。业务编号是否占用按“存在未删除有效送检结果”及原别名判定，删除后允许业务编号再用，但新发送必须新sample_id/dispatchId/代次且满足物理容量。运行中的旧位置不可重用。此处补齐原文右侧pending/testing可删除，与Q05左侧运行行不可删除不是同一个操作。

删除后的业务列表/报表不展示该结果；技术恢复继续按内部ID采集，不以del_flag停止，迟到结果不能写入新同名对象，也不能把旧删除记录自动重新显示。普通页面没有恢复删除入口；审计根据权限可追溯删除事实。若设备协议只支持复用样品号且无法区分旧新调用，编号的业务可重用不等于该设备可以安全再派发，拒绝该设备新调用并提示原请求身份待核验。

## 4. 左侧清空、自动腾位和复制

左侧清空针对填写内容/位置投影，右侧删除针对结果列表，两者均不发取消。批量清空先预览候选及SKIPPED原因，再对确认集合按设备版本重验；运行/未知/被遮挡位置保持占用标记，不能显示为可发送空位。清空本人未发送暂存按Q08，本人/状态不合格逐项跳过；已完成样品清空只腾位，右侧结果保留。

Vi-CELL/OSMO原“已检测自动清空”落实为本次完整结束且正常释放条件满足后自动清除填写内容；首项tested＋PARTIAL不腾位。COLUMN配置等待固定本轮全部成员确定终结，POSITION配置独立核验；遮挡仍按当前位置证据。HT原“检测完成不允许清空”与同章清空所有通道的文字冲突，以最新已确认完成后列可再次使用为准：允许符合释放条件的腾位，不允许通过清空绕过列锁。BGA/OSMO-1保留手工清空。

午夜仅执行Q37已确认的未发送暂存清理，不采用旧正文“所有通道一律空闲”清除活动设备事实。与派发共享锁，PREPARED/INVOKING/ACCEPTED/UNKNOWN、有结果、历史依据不一致均排除；系统定时清理是原Q37职责，不是负责人修改他人暂存的人工权限例外。

复制先按源位置之后向下找合法空闲填写位，找不到再向上；“+1”按各模板既有向下选择规则。小试递增样品ID、中试保留原字段；复制不携带sample_id/result_id/签名/上传/位置代次/已接受调用。仅复制允许输入字段，目标设备参数必须适用，不截断稀释/项目。前端填写成功不代表已占物理位，发送时仍执行统一版本和容量守卫。
