| 字段 | 类型、必填/null与范围 |
| --- | --- |
| deviceKind/deviceId | 必填string，固定设备种类白名单+正bigint十进制ID；组合解析真实labId，不接受客户端labId/route任意选表 |
| commId | PUT必填正ID，POST禁止客户端分配；不得改变原设备身份 |
| communicationType | 必填HTTP/NAMED_PIPE/NETWORK/FILE/SERIAL；型号与专属适配器允许集合交集 |
| interfaceUrl | HTTP必填string≤500，仅http/https；其他分支不接收 |
| interfaceAccount/deviceCode/subsystemDeviceNo/deviceModel | string/null≤100；必填性按源分支表，检测HTTP的deviceCode必须非空 |
| subsystemIp/deviceIp | string/null≤128；IP有效，主机名仅已核准适配器支持时允许；按源表区分子系统/物理设备 |
| portNo | integer/null，1—65535；地秤NETWORK只需deviceIp+portNo，下游SERIAL为子系统端口 |
| excelPath | string/null≤500，中转主机路径；FILE/NAMED_PIPE必填，不从浏览器读取该路径 |
| pipeName | string/null≤64，NAMED_PIPE必填，不允许路径跳转 |
| serialPort | string/null≤50；baudRate为正int/null，parity/dataBits/stopBits/flowControl各string/null≤20；有效值取已核准字典，不按示例猜生产默认 |
| interfacePasswordChange/deviceSecretChange | 正式写请求各显式提供SecretChange；action必填KEEP/REPLACE/CLEAR，value仅REPLACE必填非空。KEEP/CLEAR不接收value；沿现加密算法验证结果能完整存入255字符密文列，不能将密文列长度直接当明文最大长度或截断密文 |

普通更新同一分支时省略可选非敏感字段保留原值、显式null按可空规则清空；分支切换只提交目标分支并清除旧分支非适用字段，整个候选校验后原子写。敏感值仍按KEEP/REPLACE/CLEAR显式指令，不能通过字段省略/******隐式清除。目标分支不得将残留的、不适用凭据交给适配器，即使受控存储按KEEP保留；后续读取/导出永不暴露秘密。

## 3. HTTP逐接口

| 接口 | 请求/权限 | 成功输出与行为 |
| --- | --- | --- |
| GET /lab/communication/getByDevice | Query deviceKind/deviceId必填；lab:communication:query＋设备可见 | 完整CommView；已存在设备无配置时commId=null、desiredRevision="0"、appliedRevision=null、NOT_CONFIGURED、字段null；GET不初始化记录 |
| GET /lab/communication/{commId} | Path commId必填，无Query；同上 | 完整CommView；配置不存在/无权404，不同于“设备存在但无配置” |
| POST /lab/communication | 第1节Body；lab:communication:add＋目标实例操作 | {commId,managementRevision,desiredRevision,applyState:PENDING}；创建唯一设备配置及审计/版本，事务提交后才通知加载 |
| PUT /lab/communication | 第1节Body含commId；lab:communication:edit＋原实例操作 | 同POST回执；原设备身份不可变；新desiredRevision递增，保留原appliedRevision直到可信加载回报 |
| DELETE /lab/communication/{commIds} | 逗号分隔1—100个去重正ID、无Body、写Header；lab:communication:remove＋每设备操作 | {removedIds:ID[],managementRevision:string}；整批引用/活动使用重验，全成全败；不发送停机 |
| GET /lab/communication/list | Query labId/deviceKind/deviceId/communicationType可选，pageNum默认1≥1/pageSize默认10≤100；lab:communication:list＋逐设备可见 | 顶层rows:CommView[]、total/pageNum/pageSize；本批收敛白名单，不接受账号、密钥、任意route/SQL过滤 |

## 4. 内部getEffectiveCommunication

仅可信M05/M07服务上下文；不在浏览器新增解密接口。输入deviceKind:string、deviceId:ID、requiredRevision:非负十进制字符串>0（对原“所需revision”命名）、可信调用用途与主体由服务上下文提供。解析原设备及授权用途后，只取精确指定修订；无法取得该修订返回VERSION_CONFLICT/CONFIGURATION_INCOMPLETE领域失败，不退回最新配置替代执行快照。历史业务持有的固定配置由原业务快照/适配器保存规则负责，本方法不承诺当前表可以重建所有历史密文。

成功输出={deviceKind,deviceId,labId,revision,communicationType,configuration}。configuration仅含第1节当前分支业务字段，SecretChange替换为内部interfacePassword:string/null、deviceSecret:string/null，不含修改指令。无使用资格PERMISSION_DENIED、依赖故障DEPENDENCY_UNAVAILABLE；失败不回解密值。传输仅受信内部通道、使用后不写日志/HTTP缓存；此对象不是CommView。读配置为加载输入，不要求该版本已经applied，否则首次加载无法进行；实际新业务准入仍须desired/applied匹配及实时执行条件。

## 5. 内部reportAppliedConfiguration

输入沿原字段：deviceKind、deviceId、desiredRevision均必填；adapterInstanceId为当前注册适配器身份字符串；result:APPLIED/FAILED/UNKNOWN；errorCode:string/null≤64（失败/未知有已登记原因，成功null），observedAt:带offset的ISO8601时刻。适配器身份从认证上下文校验，不因Body自报可信。APPLIED只代表该配置加载成功，不代表设备在线或命令执行。

返回目标结构={accepted:boolean,duplicate:boolean,desiredRevision:string,appliedRevision:string/null,applyState:NOT_CONFIGURED/PENDING/APPLIED/FAILED/UNKNOWN,reasonCode:string/null}。accepted表示本回报在有效身份/修订上被处理；重复回报duplicate=true、不重复改变状态。以设备+修订+适配器+规范化回报内容识别相同证据；同修订先失败后重试成功是合法新证据，不能按设备+修订的粗粒度“重复”永久吞掉恢复成功。

事务锁定原配置：非当前注册适配器拒绝PERMISSION_DENIED；旧desiredRevision回报accepted=false、reasonCode=VERSION_CONFLICT，当前状态保持；当前修订APPLIED更新appliedRevision并标APPLIED；FAILED/UNKNOWN保留最后成功版本。已经接受APPLIED后，迟到FAILED/UNKNOWN不降级，返回accepted=false、reasonCode=VERSION_CONFLICT；进程重启/当前连接状态由适配器会话与实时心跳独立判断，不能借加载状态掩盖断线。观测时刻保留审计，不单靠设备时钟决定覆盖最新修订。

```json

  "adapterInstanceId": "SIM-ADAPTER-1",
  "result": "APPLIED",
  "errorCode": null,
  "observedAt": "2026-09-13T10:00:00+08:00"

```
```json
{
  "accepted": true,
  "duplicate": false,
  "desiredRevision": "2",
  "appliedRevision": "2",
  "applyState": "APPLIED",
  "reasonCode": null

```

内部成功回报只更新加载事实，不递增SYSTEM管理配置版本，不在事务中执行网络；改变期望配置的责任仍是HTTP配置保存。以上新增的内部输出叶子/拒绝语义须随T9对齐M05/M07适配器消费者，不能视为已联调。

## 6. 验收断言

逐分支只接收白名单，SERIAL缺现场必需参数不填默认；切换方式不留可执行旧字段；KEEP/REPLACE/CLEAR和旧星号分别测试；所有公开读取/list/export无明文/密文。设备同ID不同kind不可串读。回读APPLIED≠在线。旧修订迟到不覆盖，新修订失败保留原appliedRevision；同修订失败后成功可恢复，重复成功不重复写。HTTP写回执过期、故障恢复、现场能力及代码实测仍按各自验收，不以本文件模拟输出充当通过。

## 2026-10-13 B4 准备事务接线

COM-06/07 增加 `M02RegisteredCommunicationConfiguration` 生产提供方，由 `M02InternalCommunicationConfiguration` 注册名为 `m05SdmsCommunicationConfiguration` 的受信内部 Bean。调用能力绑定服务端注册 `m05-sdms`，不从 HTTP 或回报正文建立身份。当前只开放登记范围内的 DETECTOR/HTTP，其他设备类型或通道拒绝；不新增解密 HTTP 入口。

部署必须显式提供 `futurefab.m02.internal-adapters.m05-sdms.instance-id`、`device-refs`（逗号分隔，例如测试值 DETECTOR:12）、`lab-ids`（例如测试值 2）。这些示例不是生产授权。请求设备、当前真实实验室、请求修订及回报适配器身份必须匹配；空回报身份也拒绝。COM-06 仅解密当前 HTTP 分支；COM-07 在自己的短事务中取得 SYSTEM 锁、复核范围/配置并 CAS 回写，不递增管理版本，不执行外部 I/O。

新增 `lab_communication_apply_receipt` 保存规范化回报摘要、原始回报 JSON 和首次回执 JSON。相同证据在当前范围仍有效时返回 duplicate；旧修订迟到或 APPLIED 后的失败回报保存 accepted=false 的不可变回执，不覆盖当前成功事实。非成功 errorCode 当前仅登记 CONFIGURATION_LOAD_FAILED、CONFIGURATION_LOAD_UNKNOWN；APPLIED 不带 errorCode。配置已加载、通讯探活 ONLINE、configurationReady 为不同事实。

M05 在守卫准备事务之前加载精确配置、回报 APPLIED 并探活；事务内再次核对版本。该实现不提供 M07 自动取测订单，也不能证明设备已接受检测命令。新增 SQL 已同步目标 DDL、完整建库基线与来源清单，尚未在本批执行 MySQL。
