# M02 唯一性预检查与消耗旧入口兼容契约

版本DD-20260913-T8-R6。承接[四类资源](四类资源逐接口契约.md)、[消耗聚合](消耗配置聚合与解析契约.md)及[错误码登记](错误码全集.md)。本文件区分源码现状和目标要求；未执行HTTP、数据库或并发测试。

## 1. 已核实的生产与消费行为

- LiquidBagServiceImpl.checkLiquidBagUnique、FeedMediumServiceImpl.checkFeedMediumUnique：Mapper计数>0抛ServiceException，否则返回boolean true。不是返回false或字符串0/1。
- 对应Mapper的count查询限定del_flag='0'，按description/medium_name比较；传入bagId/mediumId时排除自身。名称比较沿数据库现有字符集/排序规则，不另造大小写规则。
- 两个Controller用success(checkUnique(...))，权限分别device:liquidBag:query、device:feedMedium:query。
- futurefab-ui/src/views/device/liquidBag/index.vue与device/feedMedium/index.vue的validateUnique均为then回调通过、catch回调失败；未依据data布尔分支。目标必须把重复作为失败，不可改200＋false而让旧页面放行。
- futurefab-ui/src/api/lab/consumptionRule.js当前封装bootstrap、config GET、consumable-options、config PUT四项。对应页面保存后await loadConfig()，不使用PUT返回的data。此结论只限这两个已读文件，不表示全项目没有旧API调用者。
- ConsumptionRuleServiceImpl旧insert/update已有validateSingleLegacy及实验室操作检查；delete已有共享源检查。仍缺目标管理版本/统一最终图证据，不能描述为“旧接口完全没有校验”。当前delete会跳过不存在对象，并逐行检查共享来源，不能视为已经实现目标整批最终图语义。

## 2. GET /lab/liquidBag/check-unique

功能权限device:liquidBag:query；全局主数据，无labId。Query严格description必填字符串trim后1—100字符，bagId可省略，提供时必须为正十进制字符串且指向当前有效对象；Body空。不接受其他实体字段，null/空串ID不能作为“排除全部”条件。对象失效404 NOT_FOUND。新增预检查省略bagId，修改传真实bagId排除自身。

示例Query：description=模拟液袋&bagId=7201（实际URL编码）。GET无WriteMeta，不锁定名称、不递增版本、不写幂等回执。目标HTTP 200完整响应：

```json
{"code":200,"msg":"操作成功","requestId":"00000000-0000-4000-8000-000000000006","data":true}
```

重复目标HTTP 409，使用现有NAME_CONFLICT，不返回冲突对象ID：

```json
{"code":409,"msg":"液袋描述已存在","requestId":"00000000-0000-4000-8000-000000000006","errorCode":"NAME_CONFLICT","data":null,"fieldErrors":[],"retryAfterSeconds":null}
```

## 3. GET /lab/feedMedium/check-unique

功能权限device:feedMedium:query。Query严格mediumName必填字符串trim后1—100字符，mediumId可省略/有效正十进制ID；Body空。其他结构、排除自身和失败规则同上一接口。示例Query：mediumName=模拟培养基&mediumId=7301。目标HTTP 200：

```json
{"code":200,"msg":"操作成功","requestId":"00000000-0000-4000-8000-000000000006","data":true}
```

目标重复HTTP 409：

```json
{"code":409,"msg":"补料培养基名称已存在","requestId":"00000000-0000-4000-8000-000000000006","errorCode":"NAME_CONFLICT","data":null,"fieldErrors":[],"retryAfterSeconds":null}
```

两接口还可能400 INPUT_INVALID、403 PERMISSION_DENIED、404 NOT_FOUND、503 DEPENDENCY_UNAVAILABLE，认证沿M01。数据读取故障不当作名称可用。源码ServiceException的实际HTTP映射尚未通过请求验证；409是统一目标，不冒充现有运行响应。

前端保留then/catch协议；异步校验结果必须与发起时字段/ID匹配，用户随后改值则丢弃旧结果。预检查与保存之间仍可能有人先提交；POST/PUT在SYSTEM事务内再次执行有效唯一校验，并由有效唯一约束兜底，映射NAME_CONFLICT。前端不得凭预检查通过跳过保存错误处理。

## 4. 消耗旧接口逐入口适配责任

下表路由/功能权限来自ConsumptionRuleController。目标不将旧行操作直接透传Mapper，统一适配到[聚合契约](消耗配置聚合与解析契约.md)的最终图验证。既有功能码保留，额外施加真实实验室读取等级0、写管理等级2；不得要求无关的另一功能码替代旧权限。

| 入口 | 既有功能权限 | 目标适配与尚待验收项 |
| --- | --- | --- |
| GET /lab/consumptionRule/list | lab:consumptionRule:list | 按可见实验室过滤后分页；精确筛选字段及旧返回列需继续审阅，不以实体任意绑定为正式白名单 |
| GET /lab/consumptionRule/{ruleId} | lab:consumptionRule:query | 先确认真实实验室可见；旧行返回需补同ConfigView行一致的字段映射，不暴露跨域共享源 |
| POST /lab/consumptionRule | lab:consumptionRule:add | 读取目标lab/tab完整页签，在对应卡片追加一行，再统一校验；新ID服务端生成；源必须已保存且有效 |
| PUT /lab/consumptionRule | lab:consumptionRule:edit | 按ruleId读取真实lab/tab/card，禁止移动身份；以提交可写行替换原行，再校验完整图；不能只校验输入行 |
| DELETE /lab/consumptionRule/{ruleIds} | lab:consumptionRule:remove | 先解析全部唯一ID及真实归属，不存在任一对象整批404；在最终图中移除全部目标行后检查保留共享引用；允许同批删除源及全部引用 |
| POST /lab/consumptionRule/export | lab:consumptionRule:export | 源码直接ExcelUtil文件流；不引入异步任务。精确筛选/列白名单未完成，不能算进R4已核实25项导出清单 |

旧写入口同样要求X-Request-Id和X-Management-Revision，版本属于SYSTEM；缺少安全版本协议的旧客户端409 CLIENT_UPGRADE_REQUIRED，不能替它读取最新版本后静默提交。适配不能把未提交卡片置空。PUT实际身份与Body身份不符400 INPUT_INVALID，仍被保留共享行引用409 REFERENCE_EXISTS；同键异体409 REQUEST_CONFLICT、旧版本409 MANAGEMENT_CONFLICT、依赖/锁失败503。所有变更、审计、版本、回执在同事务提交。

批量删除涉及多个lab/tab时，对所有真实对象先授权、建立每页签最终图，再在同一SYSTEM事务里一次提交；不能逐页签提交后忽略后续错误。若底层存储不能提供该原子范围，该入口不具备目标交付条件，不宣称分布式回滚已解决。

以上收口了旧入口必须遵守的行为；六入口的完整请求/响应样例、旧字段兼容映射及调用方全量盘点仍未结束，不计为T8六接口验收通过。前端现页面可继续聚合入口，写回读增量与保存后GET兼容，但新版本需从成功回执或重新读取取得，不能复用旧版本。

## 5. 占用并发协议的T9验收门槛

液瓶保存与M03/M07“连接槽位/开启培养”必须竞争同一真实资源身份（取样按控制器及三槽，补料按目标槽）。保存方与占用方都要在保护区内重查对方状态，不能仅保存方检查一次远程空闲。

T9逐生产者登记：资源键来源、锁/守卫实现位置、锁顺序、事务边界、失败回滚、重试身份、占用事实写入方。SYSTEM管理锁已在M02设计声明，但不能推断运行占用转换已获取同锁。此次未核验M03/M07全部实现，因此不指定未经证据支持的新分布式锁服务，也不关闭该项。

必须验证两个交错场景：保存先获得保护，占用方只能在新配置提交后读取并固定新修订；占用先获得保护，保存返回RESOURCE_IN_USE且不修改配置/观测。占用依赖故障返回DEPENDENCY_UNAVAILABLE；已知未知占用仍拒绝变更。锁等待超时回滚为MANAGEMENT_BUSY。物理命令不在管理事务内发出。

## 6. 静态验收与局限

本批已确认两个预检查返回语义、Mapper有效范围/排除自身、两个页面消费方式，以及消耗六旧入口的路由/部分防护。知识图谱Transport closed，采用源文件直读；不能据此作调用方穷尽声明。样例为目标协议，未执行真实接口/数据库/并发测试。

验收用例：可用名称返回true；重复走失败；编辑排除自身；伪造ID拒绝；软删名称按有效唯一规则处理；预检查通过后竞争保存仍409；前端迟到校验不覆盖新输入；旧客户端缺版本不得静默升级；同批删除源及共享行成功、保留一个共享行则整批回滚；跨实验室任一无权不部分删除。
