# M02 工作流执行配置与首次计量事实契约

## 目的

M02 负责保存可供 M07 读取的权威运行前事实：已核准的工作流执行配置，以及与该配置版本绑定的首次计量事实。M07 不直接读取 M02 内部表，也不自行推导配置、能力或计量设备来源。

## 存储边界

- `m02_workflow_execution_configuration`：每个控制器连接、泵和通道的当前有效配置事实，同时固定首次计量的设备类型、设备 ID、物理通道和指标编码。唯一有效槽位由连接、泵、通道和 `state=READY`、`valid_to IS NULL` 约束；同一 `profile_hash` 可以在不同资源上复用，因此仅建立普通索引。
- `m02_workflow_metering_fact`：不可变的首次计量事实。通过适配器实例、启动代次和来源事件 ID 保证来源幂等；读数必须带配置版本、质量、观测时间、来源实例和方向。

两张表只定义事实存储和读取边界。本次不伪造生产数据，也不把 M07 的运行分段写入 M02。

## Port

- `WorkflowExecutionConfigurationPort.resolve(WorkflowExecutionConfigurationQuery)`：读取唯一、有效且 profile 完整的执行配置；缺失、多义、版本不一致或 profile 不完整统一返回 `RESOURCE_FACTS_UNAVAILABLE`。
- `WorkflowMeteringFactPort.resolve(WorkflowMeteringFactQuery)`：读取配置版本匹配的最新 GOOD 计量事实；缺失或同一最新时间戳多义时统一返回 `RESOURCE_FACTS_UNAVAILABLE`。

读取适配器不承担事实写入。事实写入复用既有受信 `OBS-I01` 观测收件链：只有验签、设备与实验室身份、已应用通讯配置、核准映射均通过，且观测为 `VALID + GOOD` 时，才尝试投影工作流计量事实。投影必须按实验室、计量设备、通道、指标、配置版本及适配器实例精确命中生效中的 READY 工作流配置，方向取核准 `measurementPolicy.direction`；无匹配工作流配置时仍按普通观测归档，匹配配置的方向多义或投影写入失败时不得 ACK。来源实例、启动代次和事件 ID 在投影前锁读，重投只返回既有不可变事实，不追加第二条。

## 执行 profile 最小字段

`execution_profile_json` 至少包含 `scaleRefs`、`measurementPolicy`、`configurationRevisions`、`resourceKeys`、`materialResourceKey` 和正整数文本 `timeoutMilliseconds`。Port 返回原始 profile，同时返回配置版本、能力版本、适配器实例、profile hash 和 object version，供 M07 构建运行请求时做一致性校验。

## 2026-10-26 受控停止观测配置增补

原六字段 execution_profile_json 可显式增加 observationPolicy，由 M07 与完整执行规格一起冻结。其精确字段、两类真实观测角色、原件及覆盖规则统一见[数据库JSON契约](../07-补液运行与任务执行/数据库JSON与事务契约.md#2026-10-26-工作流-v1-受控停止覆盖)。角色来源必须匹配核准 M02 设备/指标/配置和首次不可变事实，不增加猜测映射。缺该配置的旧 profile 仍可读取原事实，但不能据此宣称受控停止覆盖已成立。

本增补不加表、列、索引，不更改事实投影或重算历史量账；目标DDL及建库基线不变。配置准备与代码接线不代表客户接口、设备和现场取值已经核准。验证结果以原开发计划本轮记录为准，本文早期“尚未执行脚本/停止未完成”保留为当时状态，不代表当前验证结论。

W07新预填充必须具备该核准策略方可准入；历史profile读取及原执行必要停止保留原能力。策略的泵/秤角色、单位及配置版本必须与完整冻结规格匹配，不能仅凭profile JSON存在或READY字段宣称具备完整停止能力。
