# 集成反应器型号与实例参数契约（M02）

状态：详细设计评审版，2026-09-09。本文聚焦型号能力、固定泵及消费者边界；完整页面见[实例设计](设备实例详细设计.md)，通讯见[公共契约](通讯与设备公共契约.md)，迁移见[数据库增量设计](数据库增量设计.md)。实机验证尚未执行。依据[实验室设置（V4.0 第 2 章）](../../需求说明书V5.1-1030_md/02-实验室设置.md)、[资源管理（V4.0 第 3 章）](../../需求说明书V5.1-1030_md/03-资源管理.md)、[工艺设置（V4.0 第 6 章）](../../需求说明书V5.1-1030_md/06-工艺设置.md)、[模块分工](../00-总纲与约定/00-业务模块划分与设计目录.md)及[型号设计](设备型号库设计.md)。本轮已目视新增原图image111。

2026-10-29 用户确认：实验室集成反应器的蠕动泵通道来自资源管理中的反应器型号；泵类型、外置泵型号和最大量程只读，实例量程即型号对应通道的最大量程，策略仍由实例配置。外置通道必须绑定本实验室对应型号的蠕动泵设备，新建时默认第一个可选设备；没有可选设备须阻止保存。本文旧的“实例量程可不同”和“外置泵是型号通道之外的独立列表”口径以本确认及下列修订为准。这里是目标契约，不代表数据库、接口或设备联调已完成。

## 1. 核对结论

| 范围 | 当前证据 | 设计处理 |
| --- | --- | --- |
| 型号容量/规格/压力单位 | 实例列表与详情Mapper联接dev_integrated_reactor读取；需求明确选型号后只显示 | 共享参数来自型号，实例编辑不允许覆盖；前端当前可编辑输入须收口 |
| 固定泵行数 | 需求每型号N个；页面MAX_PUMP_CHANNELS=8并slice截断；服务只要求非空 | 目标按型号pumpCount，禁止任意增删或静默截断；后端精确检查数量及编号 |
| 泵量程/策略 | lab_integrated_reactor_pump_config以(integrated_id,pump_no)为主键，量程decimal(18,2)、策略varchar(50) | 量程来自对应型号通道的最大量程且只读；策略按实例维护，不写回型号 |
| 固定泵保存 | 服务按数组顺序生成pumpNo=i+1，先删全部再插，重写关联时间 | 目标提交显式pumpNo并按稳定键差异更新，保留未变配置审计时间 |
| 外置泵 | lab_integrated_reactor_pump按(integrated_id,pump_id)关联 | 每个外置型号通道绑定一台同实验室、同外置泵型号的设备；通道号由pump_no显式保存，计入型号pumpCount，不以数组位置推断 |
| 型号新增能力 | 当前dev_integrated_reactor无pumpCount/MFC/达阈/控制能力列 | 延续型号设计增量，不从某台实例配置条数反推整个型号能力 |
| 运行/占用 | 现列表以culture_status=0派生使用中，删除引用查询排除1/2 | 仅为当前实现口径；M03统一当前业务引用和占用判定，不能借列表状态代替Q22 |
| 聚合事务 | create/update带事务，保存主记录、固定泵、外置泵 | 复用聚合入口，增加管理守卫/版本/精确数量校验，不拆成多个独立提交 |

当前前端将整个form展开提交，而保存DTO不含capacity、spec、pressureUnit；不能把前端可输入视为合法参数覆盖，也不能把未知字段被忽略当作成功保存。目标采用明确白名单并提示只读字段错误。

## 2. 参数来源和修改责任

| 参数 | 权威来源 | 实例页 | 下游使用规则 |
| --- | --- | --- | --- |
| modelName、spec、capacity(g)、pressureUnit | dev_integrated_reactor | 选型号后只读 | 显示当前型号；实际使用方案由M03固化来源和值 |
| pumpCount | 型号增量pump_count | 决定固定泵行数 | M04支持泵数、固定泵PUMP1…N；M03/M07验证通道存在 |
| mfcCount | 型号增量mfc_count | 能力只读 | M04按1…N生成MFC配置；不是MFC各气体量程 |
| temperatureControl、weightControl、pressureControl | 型号三个控制能力列 | 只读 | 决定可用控制回路；不直接启动控制功能 |
| thresholdWeightG | 型号达阈重量，整数g | 只读能力参数 | 与工艺方案达阈重量分开，不自动覆盖方案参数 |
| pumpNo、rangeValue、strategy | 型号通道最大量程、lab_integrated_reactor_pump_config策略 | 量程只读、策略选填 | 现行资源读取按型号最大量程投影；M03固化实际方案，M07执行使用已确认方案 |
| assetNo、deviceNo、reactorName、ownerUserId、labId等 | lab_integrated_reactor | 按实例权限维护 | Q24型号权限不赋予这些字段的修改权 |
| floorScaleLowLimit/HighLimit | 选地秤带出后形成实例配置 | 可按需求修改 | 保留实际配置，不因型号或地秤描述变更静默覆盖 |
| volume_ml | 既有实例工作体积列 | 非本次型号容量输入 | 不将重量g当体积mL，不使用固定密度自动换算 |
| 外置泵设备 | 同实验室蠕动泵实例，型号须与对应型号通道一致 | 外置通道选择设备编号 | 用明确pumpNo和pumpId绑定；量程来自对应型号通道，不按数组顺序推断 |

工艺设置原文中方案达阈/目标重量按规格使用g/kg并允许一位小数，型号达阈为整数g。DTO和快照均显式带单位和来源；同名不等于同一值。仅在业务明确需要质量单位换算时按g/kg转换，不能用字符串规格或重量推导体积。MFC气体量程按已有澄清手填，mfcCount只决定行数，不能为全部MFC复制一个虚构量程。

## 3. 固定泵配置保存规则

选择型号后，读取其PUMP通道及编号、类型、外置型号和最大量程；界面统一展示蠕动泵，不提供自由新增/删除通道或编辑这些型号字段的入口。策略选填；外置通道必须选择相应实例。原图展示8路只是示例，不能据此固定最大8路。保留现有pump_no unsigned smallint时型号pumpCount的存储兼容上限为65535，低于此上限也不代表真实设备支持，实际数量必须来自设备资料；更大数量需另行扩容设计，不能溢出或截断。

目标PumpConfigInput={pumpNo:integer必填1…N,rangeValue:decimal-string必填且等于对应型号最大量程,strategy:string/null可选≤50}。rangeValue单位g/min，精度复用decimal(18,2)，最多16位整数；服务端重查型号并验证，不能信任客户端篡改。外置绑定使用externalPumps[].pumpNo和pumpId，同一设备不能同时绑定同一反应器的多个通道。策略遵循现有实例接口口径；本轮不新增平行策略表。

pumpConfigs必须恰含N个不同编号，编号连续完整1…N；数组顺序不改变泵身份。缺号、重号、超号、空行或数量不一致拒绝整次保存。型号能力未知时可查看旧配置和修正不依赖该能力的资料，但禁止创建依赖未知能力的配置或投用；不能默认N=1或N=8让请求通过。

在SYSTEM守卫内重查型号与设备，按(integratedId,pumpNo)更新变更的通道配置，未变行保留create_time；不因数组排序改变泵身份。外置设备按显式通道与设备ID保存，保留同一关联原有的pumpUsage。主数据、泵通道、外置绑定、审计和管理版本同事务。失败保留非敏感草稿，不部分保存。

对现存同型号实例数量不一致，保留旧记录并标记配置待核验，不按最大/最小行数推定型号数量，也不静默删除超过N的行。型号结构变化与既有配置冲突按第8节M02-Q25处理，不自动删减或补造配置。

## 4. 当前接口的目标补充

控制器路径复用/lab/labintegratedreactor，实例写权限沿用相应lab:labintegratedreactor:add/edit及目标实验室操作准入；字段与来源限制不能由型号库维护权限绕过。本节不扩大现有实例操作等级为新规则。

2026-10-26 培养修改页只读编号补充：详情增加airPumpNo:string/null及feedScaleNo:string/null。前者按实例air_pump_id关联lab_air_pump.air_pump_id，后者按feed_scale_id关联lab_floor_scale.scale_id，均必须同实验室且关联设备未删除，返回真实device_no。补料地秤不能使用floor_scale_id对应的反应器地秤代替；未配置、悬空、跨实验室或已删除引用保留反应器详情并返回相应编号null。两字段在同一详情查询中取得，不逐项追加设备查询；仅扩展读取投影，不进入保存白名单，不改变权限、管理版本及既有设备ID字段。

| 编号 | 接口/内部契约 | 目标参数或返回 |
| --- | --- | --- |
| IR-01 | GET /lab/labintegratedreactor/{integratedId} | 保留详情主体，增加只读modelCapabilities、configurationReady、configurationIssues；泵配置显式返回pumpNo；只读airPumpNo、feedScaleNo取真实关联设备编号 |
| IR-02 | POST /lab/labintegratedreactor | 现有聚合DTO白名单，pumpConfigs采用显式编号；拒绝客户端型号只读参数及占用状态 |
| IR-03 | PUT /lab/labintegratedreactor/{integratedId} | 同上；结合管理版本重检modelId、型号能力和泵配置，不先清旧行再忽略非法项 |
| IR-04 | 内部resolveIntegratedCapabilities(actorUserId,labId,modelId,integratedId?) | 返回CapabilityView；调用者须有对应实例操作上下文/权限，仅返回选型必要参数，不泄露其他实验室实例 |
| IR-05 | 内部resolvePumpConfiguration(actorUserId,integratedId) | 返回modelId、managementRevision、固定泵集合及ready；M04/M03通过合法服务上下文调用 |

IR-01的每个`pumpConfigs`返回型号对应的只读`pumpType`；型号通道不可读时为null。每个`externalPumps`返回只读`pumpNo`和`deviceNo`：设备编号仅在蠕动泵未删除且与反应器同实验室时返回，否则为null；历史没有通道的关联`pumpNo=null`保留原样。`deviceNo`用于定位候选，不能替代按实验室、型号、状态重新核验设备ID。

CapabilityView={modelId:string,modelName:string,spec:string/null,capacityG:decimal-string/null,pressureUnit:string/null,pumpCount:integer/null,mfcCount:integer/null,thresholdWeightG:decimal-string/null,temperatureControl:boolean/null,weightControl:boolean/null,pressureControl:boolean/null,managementRevision:string,ready:boolean,issues:string[]}。null表示历史未知，不等于0/false；ready是完整性与一致性校验结果，不单独建立一个与数据脱节的可手动切换状态字段。

旧实例详情capacity仍按g兼容返回，新增能力对象命名capacityG消除单位歧义；禁止既有调用者误以为capacity改成了mL。既有固定泵DTO无pumpNo，正式前端与后端需同批升级；如短期兼容旧数组，只在型号N已确认且长度恰为N时按原顺序转换，标记旧契约，不能放宽正式校验。

configurationIssues只返回当前对象需核验的字段/原因，不暴露操作者无权查看的其他实例。缺失能力或数量不匹配按409 CONFIGURATION_INCOMPLETE处理，字段定位具体问题；未知引用查询结果不能当作ready。该错误为M02领域错误，复用公共错误外壳。M04调用不从浏览器传actorId决定身份，实际操作者来自可信会话或调用上下文。

## 5. 消费者和历史证据

M04的Config多型号选择按需求比较泵数、MFC数及控制能力；灌注方案还校验规格一致；补液模板按支持泵数与类型过滤型号，并要求规格一致。每项使用所需的兼容字段，不把所有模板一律按相同字段集合判断。

M04现行资源量程来源为实例所选型号的对应通道最大量程，返回带integratedId/pumpNo的结构化来源集合；不能保存“10/20”作为执行数值。没有有效型号通道时不得伪造0。型号最大量程的后续修改反映到当前资源读取，但不回写已固化的培养运行方案或历史快照；实际执行仍以合法生效方案为依据。

M03在培养初始化或批准的方案变更时固化使用的型号能力值、实例ID、泵编号、量程及策略标识/版本，与M04方案版本共同保存；快照具体表由M03设计，不由M02新增并行运行方案表。共享型号变更不重写已固化历史，M07以合法现行使用方案为执行依据并复核实时占用/资源可用性，不能每次直接读取最新型号来覆盖正在执行的方案。

M08归档保留事件时的值、单位、时间及来源，不用当前型号名称/单位替换历史证据。型号修改同Q22检查全部相关未结束业务，同Q24按共享型号功能权限判权；模板或实例结构引用按第8节Q25进一步阻断空闲期间的结构变更。

本轮图搜索未形成可依赖的完整M04/M07消费调用链，以上是按需求和已确认模块边界制定的目标契约，不标为当前消费者已经实现。

## 6. 旧数据与增量设计

1. 只读取当前型号/实例/固定泵/外置泵关系进行对照，按modelId聚合实际配置数量及差异，输出待核验清单；不得直接反推型号能力后批量写回。
2. 型号缺失的新能力列迁移先保留未知，依据设备资料补齐，再对依赖功能启用ready校验；新建型号仍须满足必填，不用历史nullable放宽新请求。
3. 核验同一实例泵编号连续、数量与型号一致、量程合法、策略引用可解析；修复需有明确依据。未涉及的关联ID、创建时间和外置泵配置保留。
4. 旧volume_ml、feed_range/feed_strategy与现固定泵表分别登记来源，不未经核对覆盖；模型g与实例mL不作隐式转换。
5. 固定泵结构仍复用lab_integrated_reactor_pump_config，不重建泵模型；模型新增列、引用校验和下游适配完成后统一编写迁移/核验/回退稿。本轮不执行SQL。

## 8. 已有配置引用时的结构保护（M02-Q25已确认）

M02-Q25已确认（2026-09-09）：型号已有设备实例或模板配置引用后，禁止直接修改泵数量、MFC数量及温度/重量/压力控制能力开关，即使设备空闲或相关业务已结束也不例外。需要不同结构时另建型号，再按合法流程调整设备和模板关联；保留原配置与历史。未被配置引用的型号仍须满足Q22及其他修改约束。


结构字段为pumpCount、mfcCount、temperatureControl、weightControl、pressureControl，比较数据库当前值与请求值，只在实际改变时检查本项。型号描述等非结构字段不因Q25被一律禁止；容量、单位等其他关键参数仍按Q22及各自兼容规则，不能把Q25解释为放宽它们的限制。

引用包括全部未删除的关联设备实例及M04当前模板配置；设备空闲/维护、模板禁用不解除引用。已归档历史快照保留但不等同于当前配置引用。引用检查在SYSTEM守卫内与型号修改、实例绑定及模板绑定共享一致性约束；查询失败不按零引用放行。功能权限允许全局维护（Q24），不豁免结构保护，超级管理员同样遵循。

正式修改命中返回409 REFERENCE_EXISTS，定位实际变化的结构字段，提示“该型号已有设备或模板配置引用，请新建所需结构的型号后调整关联”。混合修改结构字段与描述时整次拒绝，保留草稿，不先更新描述或删掉超出数量的PUMP/MFC。只提交原结构值可按其他约束保存。

另建型号须符合型号名称唯一及完整能力配置；设备换型号、模板重新选型仍由各自入口判权、检查业务状态和兼容性，不由型号新建接口批量迁移，也不自动重编号或复制不匹配的量程、策略、控制回路。原型号不能因新型号已建立而自动删除，删除仍检查现存引用，历史证据继续指向原来源。

历史未知能力的初次核验补齐须有真实设备资料并检查已有关联配置，不借“补齐”改变已知结构；新旧字段上线步骤仍在迁移设计中落实。本项不授权静默改造历史配置。
