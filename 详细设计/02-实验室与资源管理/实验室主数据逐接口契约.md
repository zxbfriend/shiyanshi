# M02 实验室主数据逐接口契约

版本DD-20260913-T8-R9，2026-10-26补充审批用途候选。覆盖LabLabController既有12个canonical HTTP入口及审批用途候选补充入口，承接[详细设计第8节](详细设计.md#8-实验室管理功能组)已确认规则。样例均为模拟数据；实现和运行验证分层登记，不以文档登记代替验证。

## 1. DTO、权限和公共事务

LabSave固定labName:string必填trim后1—20、labCode:string必填1—50且仅英文字母/数字/下划线、labType:string必填1/2/3/4（新增禁选2，旧2保持可编辑其他字段）、leaderUserIds:string[]必填可空、venueId/deptId正十进制字符串必填、ipAddress合法IPv4必填、port:integer|null必填、status:string必填0/1。POST不接受labId，PUT另含labId。address、remark、delFlag、审计、leaderNames、venueName/deptName、isDefaultLab、allowedActions、managementRevision为只读/不在本期表单，提交拒绝。

LabRow、LabDetail和PersonRef完全沿用主设计；列表行额外返回只读的venueId、deptId，供所属场地和所属部门列按当前授权名称树展示，不返回场地/部门名称或其他详情编辑字段。对象ID/版本用十进制字符串，时间为ISO8601/null。labTypeLabel来自字典当前显示；历史字典缺项返回原值并标配置问题，不篡改业务值。allowedActions由实时功能权限、实验室等级、状态和引用条件计算，只用于UI，提交仍重验。

写携X-Request-Id、X-Management-Revision。SYSTEM→实验室→关联对象固定顺序内处理幂等、版本、唯一、引用、主数据、负责人差异、审计与回执。同键同体且仍有权重放原回执，同键异体409 REQUEST_CONFLICT，新键旧版本409 MANAGEMENT_CONFLICT。事务中不调用设备或扫描Redis。创建者不会因创建自动获授权；仅显式列为负责人时取得负责人来源管理等级2。

## 3. GET /lab/lab/options

这是跨设备、培养、检测页面共用的精简候选，不强制lab:lab:list；要求已认证，并由服务端仅返回调用者有效VIEW范围。Query status可选0/1、labType可选1/2/3/4；Body空，其他字段拒绝。当前Controller没有@RequiresPermissions，目标安全依赖是统一认证过滤器＋VIEW范围，不能开放匿名或返回全表。调用页面自身功能权限仍由其页面API校验。

输出数组项固定labId、labName、labType、isDefaultLab:boolean；默认配置指向无权/删除/不匹配筛选对象时所有false，不把第一项伪造为默认。排序labName ASC、labId ASC（技术固定）。HTTP 200：
```json

    {
      "labId": "1001",
      "labName": "模拟实验室",
      "labType": "1",
      "isDefaultLab": true
    }
  ]
}
```

### 3.1 GET /lab/lab/approval-options（M02-LAB-APPROVAL-OPTIONS）

为通用M06审批操作页提供实验室候选。权限为`process:approval:list`，并按当前已认证用户的有效VIEW实验室范围裁剪；不要求`lab:lab:list/query`，不以登录用途列表或前端当前实验室替代审批用途授权。复用M02-229应用服务、既有实验室服务、LabAuthorizationService及同一Mapper，无第二套实验室来源。

Query为空，任何查询字段均以400 INPUT_INVALID拒绝，客户端不得提交角色、VIEW范围或状态。返回M02-229相同的`data: [{labId,labName,labType,isDefaultLab}]`精简字段；ID是十进制字符串。只查未软删且当前VIEW可见的实验室；不额外按启用状态过滤，防止停用实验室的历史审批入口消失。无VIEW范围返回空数组且不查询全表。默认实验室只作原有显示标记，不自动赋予审批资格。

候选可见不等于允许签审。M06列表、详情、预检和动作仍分别校验功能权限、当前实验室范围、成员资格、责任分离、原始冻结政策、对象版本及拥有方事实；最终写入在原管理守卫事务锁内重验，不改变审批政策或角色授权，不写业务表，不生成管理修订或审批单。

本补充入口不重编号既有M02-001～M02-241。控制器、用途权限及VIEW范围复用的定向HTTP测试单独记录；完整门户、真实部署和现场验收须另记证据。

## 7. GET /lab/lab/{labId}/authorized-users

权限lab:lab:query＋VIEW。Query pageNum/pageSize同list，Body空。AuthorizedUserRow固定userId、displayName、userName、deptName:null|string、roleNames:string[]、authorizationSources:(DIRECT/LAB_LEADER)[]固定顺序、directAuthType:0/1/2|null、effectiveAuthType:0/1/2、lastLoginTime:null|ISO、online:boolean、associatedAt:null|ISO。直接授权与负责人按userId合并；负责人贡献等级2，直接取自身等级，最终取最高。排序associatedAt DESC NULLS LAST、userId DESC，再分页。

## 10. PUT /lab/lab

## 12. PUT /lab/lab/{labId}/status

权限lab:lab:edit＋MANAGE。Query status必填严格0/1，Body空，WriteMeta必填。目标返回LabWriteResult；2026-11-03状态补正：当前状态入口已走WriteMeta与应用服务守卫，不是旧toAjax直写；专属目标回执与通用结果的字段一致性仍单列，不以入口接线代替验收。status=1事务内重做第8节全部检查，预检不锁定结果。status=0不恢复已撤销授权、不绕过其他业务状态。其他值400 INPUT_INVALID；当前状态入口已校验严格0/1；本轮未执行HTTP错误外壳验证。

## 13. DELETE /lab/lab/{labIds}

权限lab:lab:remove＋每个实验室MANAGE。Path 1—100个唯一ID；Body/Query空，WriteMeta必填。先全量存在/权限/引用检查，再同SYSTEM事务软删；任一失败全批回滚，不跳过不存在ID。不得自动删除授权、负责人、项目或运行历史。成功返回removedIds和版本。2026-11-03状态补正：当前批删应用回调先检查全部实验室存在/范围/引用后才软删；停用检查已含授权/负责人并集及M03未结束事实，不再称跳过不存在或遗漏负责人。事务并发、回滚及实际数据后果本轮未验证。

## 14. 错误及并发验收

读：400 INPUT_INVALID、403 PERMISSION_DENIED、404 NOT_FOUND、503 DEPENDENCY_UNAVAILABLE/RESOURCE_FACTS_UNAVAILABLE。写另有400 READ_ONLY_FIELD，409 NAME_CONFLICT/CODE_CONFLICT/REFERENCE_EXISTS/RESOURCE_IN_USE/REQUEST_CONFLICT/MANAGEMENT_CONFLICT，503 MANAGEMENT_BUSY。认证沿M01。失败外壳示例：
```json
{
  "code": 409,
  "msg": "实验室存在当前授权或负责人关系，不能停用",
  "requestId": "00000000-0000-4000-8000-000000000009",
  "errorCode": "REFERENCE_EXISTS",
  "data": null,
  "fieldErrors": [],
  "retryAfterSeconds": null
}
```

并发负责人变更、用户删除、实验室停用/删除、M03新建引用必须共用SYSTEM守卫和稳定锁序；不能先查空再无保护提交。管理事务不发送设备命令。已读Controller、实体、VO、Service、LabLabMapper、SysUserLabMapper和SmpPermissionQueryMapper；图谱Transport closed，以源文件直读补证，不作全调用方穷尽声明。
