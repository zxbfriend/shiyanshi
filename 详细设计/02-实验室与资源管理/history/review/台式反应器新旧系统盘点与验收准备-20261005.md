### 3.4 守卫写链路（源码盘点，非本轮改动）

- 前端：编辑器保存与列表删除均走 `writeMeta(await ensureRevision())`（`app-smp-settings/src/shared/use-guarded-write.ts`）；revision 取列表外壳顶层值；409 后标记 stale 并在下一次写前重取；`writeHeaders` 缺 revision 时不发该头、由后端 400 明确拒绝（前端不伪造版本）。
- 后端 `DevBenchReactorController`：list/getInfo 只读已接线 + `@CurrentManagementRevision`；add/edit/remove 均 `@ManagementGuardedWrite`；check-unique/check-delete/export 委托应用服务，`DevBenchReactorApplicationServiceImpl` 已全部实现（无 501 抛出，仅残留 import）。
- 守卫语义（公共组件，M01 同口径）：
  - 缺 `X-Management-Revision` → HTTP 400，`{code:400, msg:"管理写接口必须携带请求头 X-Management-Revision（十进制非负整数字符串）", errorCode:"INPUT_INVALID", requestId}`，日志 WARN「公共请求元数据非法」（`RequestMetaExceptionHandler`）。
  - 期望版本不一致 → HTTP 409 `MANAGEMENT_CONFLICT`；幂等键重复 → 409 `REQUEST_CONFLICT`；锁等待/死锁 → 503 `MANAGEMENT_BUSY`（`ManagementGuardExecutor`）。

### TC-06 缺 revision 短路

- 页面/步骤：浏览器 DevTools 或直连 HTTP（curl/直连 9201 带网关头）向守卫写口发送**仅带 X-Request-Id、不带 X-Management-Revision** 的 PUT。页面路径对应：本地拿不到 revision 时 `writeHeaders` 不发该头 → 后端拒绝，前端不伪造版本。
- HTTP：`PUT /device/benchreactor`（或 POST/DELETE 任一守卫写）
- 请求头：`X-Request-Id: <生成>`；**无 X-Management-Revision**。
- payload：合法 BenchSave。
- 预期：HTTP 400，`{code:400, msg:"管理写接口必须携带请求头 X-Management-Revision（十进制非负整数字符串）", errorCode:"INPUT_INVALID", requestId:"..."}`；数据不落库（列表 revision 不变，行未修改）；日志出现 WARN「公共请求元数据非法」（`RequestMetaInvalidException` 映射）。
- 记录预留：X-Request-Id、payload、response body、日志命中行、清理（无副作用，无需清理）。
- 状态：NOT_VERIFIED

### TC-07 revision 冲突提示

- 页面/步骤：①打开两个台式反应器页签 A/B；②A 保存一次使 revision 递增；③B 用旧 revision 保存 → 应得 409，页面提示冲突口径（"数据已被他人修改/刷新重试"类，`writeErrorMessage`），不报笼统失败；④B 重试（自动重取 revision 后）应成功。
- HTTP：`PUT /device/benchreactor`（③的请求带过期 `X-Management-Revision`）
- 预期：③ HTTP 409，`errorCode=MANAGEMENT_CONFLICT`，消息如"管理配置已被他人更新…"；日志可见版本冲突记录、无 GlobalExceptionHandler 堆栈异常；④重试 200。
- 记录预留：A/B 两头的 X-Request-Id、过期 revision 值、③④ response body、日志、清理（删除 B 新建/修改的行或还原描述）。
- 状态：NOT_VERIFIED
