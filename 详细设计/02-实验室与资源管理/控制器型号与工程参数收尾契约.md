# M02 控制器型号与工程参数收尾契约

2026-09-10。当前确认范围设计完成；新增内容属于M04提出的资源交接补齐，不创建另一套设备/型号主数据。最终40表672列，完整结构/字典及本次09—13 SQL见[收尾后完整字典](收尾后完整数据库字段字典.md)。01—08旧稿保留原基线用途；最终空库参考13，不把旧38表645列作为最终总数。真实厂商数据、历史核准与接口/设备验证仍未执行。

## 1. 控制器型号与核准入口

lab_bench_reactor_controller新增model_dict_code BIGINT NULL，关联sys_dict_data.dict_code，类型固定smp_bench_controller_model、一级parent_code=0、dict_level=1；新选必须status='0'/del_flag='0'，旧NULL原样保留。型号不是reactor_id、connection_id、罐体规格或显示名称。M01负责受控字典初始化，M02负责逐连接映射，M04读取，型号字典不放PID JSON。

初始化使用M01既有字典应用服务生成真实主键和审计；按dict_type幂等创建类型，没有经过核准的型号条目时保持空，不往SQL填猜测ID。逐连接核准输入固定为{connectionId,expectedManagementRevision,expectedModelDictCode:null或旧ID,newModelDictCode,evidence:{documentId,documentHash,section,verifiedByUserId,verifiedAt},requestId}。缺任一真实证据不能提交，不以“暂定型号”消除NULL。输入只从受控维护入口进入，不增加普通工艺页面的型号编辑权；普通连接保存省略该字段必须保留旧值。

保存/改映射在SYSTEM→实验室→连接顺序下重验身份、功能、实验室管理等级2、字典类型与当前设备/培养/模板引用。已占用、任务未结束或存在UNKNOWN物理命令时阻断结构性改映射。历史模板引用旧身份不改绑；已被引用型号的类型/键值/层级更改和删除按M01/M02/M04共同引用守卫拒绝，标签改名只改变当前显示。核准空映射/错误类型/孤儿ID清单由后核验输出，不自动清数据。

## 2. 工程资料的身份和版本

复用M02模型及实例身份，在lab_engineering_profile保存每个MODEL或INSTANCE范围的当前工程版本指针；lab_engineering_profile_version保存不可变内容/证据。profile.scope_key=SHA256(scopeKind,modelKind,modelId,deviceKind,deviceId)，MODEL必须只有型号对有效，INSTANCE必须只有设备对有效。名称/地址不参与身份。各实例不同不能取第一条/最大值/平均值推断型号统一能力。

保存草稿DRAFT可保留缺字段，但不能作为有效ModelFacts。核准动作要求完整profile及真实资料证据；在同一SYSTEM事务固定版本内容、核准人/时间、切current_version_id，status=VERIFIED。已有版本内容/hash永不UPDATE；修改生成新version_no，首版previous=NULL，此后同profile精确前版。核准人可以是有相应管理功能的同一维护人，不新增未经确认的双人业务审批。REVOKED表示该profile不再可用于新保存/生效/执行；历史仍可解码追溯，必要运行停止处置交M07，不由修改配置触发裸设备指令。

同一requestKey=actor+operation+scope+requestId，同hash返回原结果，异hash409；M01管理回执和版本行唯一键双重兜底。版本verified_*可在首次核准时从NULL一次填充；核准后不覆写，撤销状态作用于profile，证据沿M01审计保留。当前指针变化不回写旧M04/M03快照；执行依赖当下安全禁用事实，但不能偷偷改历史单位。

## 3. EngineeringProfile模式1（闭合字段）

所有内部ID/版本为十进制字符串；Decimal为规范十进制字符串，最多20位/6位小数；时刻UTC ISO8601毫秒，哈希为规范UTF-8 SHA256。未知字段拒绝，数值单位不靠字段名猜；以下叶子中未要求必需的null保留未知，核准完整性按使用类型判定。

| 对象 | 全部叶子与校验 |
| --- | --- |
| EngineeringProfile | schemaVersion:1,scope:{kind:MODEL/INSTANCE,modelKind?,modelId?,deviceKind?,deviceId?},vendor:{name,controllerFamily,protocolVersion,firmwareRange?},capabilities:Capabilities,specification:Specification,pidRules:[PidRule],channels:[ChannelRule],mediumMappings:[MediumMapping],feedingPolicy:FeedingPolicy|null,sources:[Evidence] |
| Capabilities | pumpCount:int≥0或null,mfcCount:int≥0或null,temperatureControl/weightControl/pressureControl:boolean或null,supportedStepCodes:[string],applicableInstanceIds:[ID]；MODEL通用能力须资料明确覆盖范围，不从用户可见实例推导 |
| Specification | originalText:string,value:正Decimal或null,unit:L/ML/null,volumeLitres:正Decimal或null,conversionRule:ML_DIV_1000/L_IDENTITY/null；单位不明或g规格不转体积 |
| PidRule | loopCode:string,algorithmCode:string,action:FORWARD/REVERSE/CONFIGURABLE,parameters:[PidParameter]；每个回路参数名称唯一，算法名称由来源真实给出，不初始化猜测的标准PID |
| PidParameter | name:GAIN/RESET/RATE,meaning:string,unit:string,min:Decimal,max:Decimal,minInclusive:boolean,maxInclusive:boolean,scale:int0..6,zeroMeaning:string,negativeMeaning:string,defaultValue:Decimal或null,deviceField:string,conversion:{expressionKind:IDENTITY/LINEAR,multiplier:Decimal,offset:Decimal,deviceUnit:string,deviceScale:int0..6},readback:{supported:boolean,tolerance:非负Decimal或null,unit:string或null} |
| ChannelRule | channelKey:string,kind:PUMP/MFC/CONTROL_LOOP,ordinal:int≥1,logicalUnit:string,min/max:Decimal,minInclusive/maxInclusive:boolean,scale:int0..6,supportedModes:[string],supportsCodeSpeed:boolean,codeSpeeds:[{code:SPEED1..SPEED10,value:Decimal,unit:string}],deviceField:string；未知CODE真实速度不能用代码序号计算流量 |
| MediumMapping | materialKind:FEED_MEDIUM/LIQUID_BAG/CONSUMABLE,materialId:ID,targetCategory:string,targetCode:string,unit:string；料桶类别按稳定源身份核准，不按名称模糊匹配 |
| FeedingPolicy | minSugarAmount:正Decimal或null,unit:G/ML/null,appliesWorkflowCodes:[string],sourceDocumentHash:64hex；NCS061所需最小量无资料则null，不默认0，相关执行阻断；ML到G须另外核准密度版本 |

limits需min≤max；相等只在双闭端点且有确切单值设备依据时合法；defaultValue若存在须范围/精度均合法。LINEAR的乘数、单位和反向读回规则须资料可证明，复杂非线性转换不能塞脚本，标不支持并由下一模式扩展评审。PID配齐对应算法必需参数，单纯Decimal存储通过不代表工程有效。没有真实PID资料就不能把默认0/1作为核准内容；该限制是实施数据准入，不是本轮字段或流程留白。

EngineeringSnapshot={schemaVersion:1,profileId,versionId,versionNo,profileHash,scope,profile:EngineeringProfile,verifiedAt,capturedAt}。读MODEL只能取得该MODEL核准版本；读INSTANCE先取得型号版本，再叠加该实例更严格的已核准边界，范围取交集、枚举取交集；单位/算法不一致阻断，禁止“实例覆盖”为更宽范围。双方原始快照均保留，effectiveHash覆盖交集结果；不能合成无来源型号能力。

## 4. 服务与页面契约

目标内部SVC-M02-E01 resolveEngineering(scope,expectedManagementRevision,purpose:TEMPLATE_SAVE/CULTURE_APPLY/RUN,requiredPaths:[string])→{state:COMPLETE/INCOMPLETE/REVOKED,modelSnapshot:EngineeringSnapshot|null,instanceSnapshot:EngineeringSnapshot|null,effectiveProfile:EngineeringProfile|null,issues:[{path,code,message}],managementRevision}。purpose为服务器调用白名单，读失败503 RESOURCE_FACTS_UNAVAILABLE，资料缺项正常返回INCOMPLETE，不伪装网络错误。M04原API13/14消费该结果，原ModelFacts字段全部保留，增加engineering引用与缺项。

目标受控维护API：GET /system/lab/engineering/profiles?scopeKind&modelKind&modelId&deviceKind&deviceId返回上述结果＋{profileId,version,status,allowedActions:[EDIT/VERIFY/REVOKE]}；POST /system/lab/engineering/profiles Body={requestId,expectedManagementRevision,expectedProfileVersion|null,profile:EngineeringProfile,evidence:[Evidence],action:SAVE_DRAFT/VERIFY/REVOKE,reason≤500}，输出{profileId,versionId,status,objectVersion,managementRevision,issues}。REVOKE仅需身份版本与原因，正文不得夹带修改值；新建草稿required不足只列issues，VERIFY不足整次失败。角色菜单按M01注册、实验室管理权和资源维护功能交集；不授予普通模板编辑人工程核准权。

受控控制器映射API POST /system/lab/controllers/{connectionId}/model-verification，Body为第1节核准对象，Path/Body ID必须一致，输出{connectionId,modelDictCode,managementRevision,requestId}。所有写入都受M01幂等、审计和实时撤权保护。

线框：身份/作用域只读→当前版本与证据→能力/规格/PID/通道/物料映射页签→逐项“未知”提示→保存草稿/核准/撤销。核准前展示差异和影响范围；保存中禁连点、403清敏感缓存、409保留输入并重读，退出未保存提示。协议地址/秘密不进入该资料表，仍归通讯配置。
