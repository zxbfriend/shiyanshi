## 2. 按方式区分字段

通讯方式采用现有字典值的明确映射，展示名可本地化。以下HTTP、NAMED_PIPE、NETWORK、FILE、SERIAL是目标稳定标识，旧字典值不按序号推断。型号可选方式与设备专属适配器共同决定允许集合。

| 方式 | 必填 | 可选 / 只读 | 验证和边界 |
| --- | --- | --- | --- |
| HTTP | interfaceUrl | interfaceAccount、密码更新、deviceCode、设备密钥更新；检测设备deviceCode/secret按既有规则必填 | URL仅http/https，≤500，不在保存时发出请求；检测设备不擅自增删已确认的回调/鉴权语义 |
| NAMED_PIPE（检测专属） | subsystemIp、pipeName、subsystemDeviceNo、excelPath | 型号许可的其余字段 | 主机有效IPv4或适配器明确支持的主机名；管道名≤64且不含路径跳转；结果目录是中转主机路径，不是浏览器本地路径；Vi-cell沿用仅命名管道 |
| NETWORK 网口 | subsystemDeviceNo、subsystemIp、deviceIp、portNo | subsystemMac只读 | IP每段0–255，端口1–65535；MAC未知显示未知，不设虚构MAC必填阻断 |
| FILE 文件 | subsystemDeviceNo、subsystemIp、excelPath | subsystemMac只读 | 路径≤500，由指定中转主机使用；保存不读文件、不删除结果文件；文件读取/去重归M05/M07适配器 |
| SERIAL 串口 | subsystemIp | deviceCode、deviceModel、subsystemDeviceNo、serialPort、baudRate、parity、dataBits、stopBits、flowControl | 通用表按原图串口参数可选；具体适配器缺必需项时不能投用，不填不会自动推断9600/8/N/1 |

下游设备专属串口表单按原文加强：子系统IP/端口、COM、波特率、校验位、数据位必填，停止位/流控选填；portNo存该子系统端口，deviceIp留空，绝不同时解释为物理设备网口。地秤专属IP+端口模式只要求deviceIp/portNo，不强制填写无来源的子系统编号。继电器仅 NETWORK，要求 deviceIp/portNo，拒绝子系统地址和编号；客户服务地址不作为设备 IP。台式控制器热更新配置由部署适配器提供，不把设备库的通讯选项视为协议实现。

声光报警器的配置界面沿用 HTTP、NETWORK、FILE、SERIAL 四个分支及上表相应字段校验，不接受检测专属 NAMED_PIPE。上述方式只描述可维护的配置；实际设备支持、网络服务地址、鉴权、动作和反馈协议均须现场核准，不能依据保存记录推断。通讯记录中的设备地址与客户报警 HTTP 服务部署地址属于不同配置，不从前者自动推导后者；保存或打开弹窗不触发声光动作、不视为在线或已应用。

打印机配置沿用 HTTP、NETWORK、FILE、SERIAL 四个分支及上表相应字段校验，不接受检测专属 NAMED_PIPE。打印设备支持方式、实际接入地址、命令和回执协议须现场核准；保存配置不发送打印任务，不表示已加载、在线或打印成功。`lab_printer` 兼容地址字段不作为自动覆盖或代替通讯记录的来源。

数值输入超范围/超精度返回400 VALIDATION_ERROR，字典字段验证当前有效值。切换通讯方式仅提交该分支字段；不适用字段在目标记录清空（旧值已留审计/受保护历史），避免后台仍用旧IP。敏感字段不得回显到草稿、日志或导出。

## 3. 凭据协议

### 9.1 签名与授权范围

- 用途固定为 `COMMUNICATION_USAGE`（关联登记）或 `OBSERVATION`（首次收件），不能跨用途重放签名。
- 签名算法为 HMAC-SHA256，签名值为 64 位小写十六进制；签名原文为下列五行 UTF-8 字节，末行后无换行。原始请求体按实际收到的字节计算 SHA-256，不先进行 JSON 重排。

```text
M02-INGRESS-V1
<adapterId>
<purpose>
<UTC timestamp>
<request body SHA-256 hex>
```

- 部署配置 `futurefab.m02.device-ingress.adapters.<adapterId>.hmac-key` 为独立密钥，至少 32 个 UTF-8 字节，无源码默认值，不写入日志或响应。
- 同前缀的 `lab-ids` 为明确的正十进制实验室 ID 逗号列表；`device-refs` 为明确的 `DETECTOR:<id>`、`FLOOR_SCALE:<id>`、`DOWNSTREAM_DEVICE:<id>` 逗号列表。不支持通配符，不能因配置部分合法就启用其合法子集。
- `futurefab.m02.device-ingress.max-clock-skew-seconds` 必须显式配置，取值 1—300 秒；缺失或格式错误拒绝接入，不采用隐式默认时间窗。
- 报文内 `labId`、`deviceKind`、`deviceId` 必须为字符串，并与部署授权范围一致。后续业务消费者仍须从服务端设备行复核真实实验室、通讯配置 ID 与版本，不能把验签后自报字段视为数据库事实。
- 实现输入上限为 1 MiB（包含原包编码后的整个请求体），为有界处理限额，不改变厂家协议或设备业务值域。

两个旧结果任务仍只处理 collection_basis IS NULL 的兼容记录，依据 M05-RX42 按到达时当前绑定配置选通道，不伪造发送时冻结快照。先从服务端样品复核 result/sample/device/lab 身份，再读取当前 APPLIED 且 desired==applied 的 COM-06 配置；刷新/HTTP 读取在事务外，写结果前在真实短事务中先取 SYSTEM 首锁并重验同一配置及样品归属。新 managed 记录仍隔离，不能借旧任务绕过位置代次和冻结版本。

SDMS 继续单平台：设备 interfaceUrl 是 valid-equ 完整健康地址，需与部署平台的协议、主机、有效端口和原始路径匹配，禁止 userinfo/query/fragment；结果查询仍用平台约定 ORDER_GET，不把健康地址猜改成结果地址。显式默认端口与省略默认端口按相同有效端口处理。HTTP 自动重试关闭及 UNKNOWN 不重发规则保持第二批约束。

### 2026-10-21 复审核验：当前读与失败语义

统一读口在真实写事务内先取得 SYSTEM 首锁，以配置→实验室→设备的当前锁定读重核版本、归属及应用状态；相关 MyBatis 查询关闭缓存并清除会话缓存，不能以同一 RR 快照的两次普通读代替当前事实。事务外加载用于外部 I/O，写前在独立短事务重新核验，持锁期间不执行外部 I/O。合法写方共用 SYSTEM 锁；此补强不表示已完成目标 MySQL 并发验收。

重复有效通讯行拒绝处理，不以 LIMIT 1 任取一行；内部配置缺失、部署范围无效或配置重核失败映射为明确的配置不可用。健康检查的两个入口仅对专用配置异常返回安全失败外壳（探活前 CONFIGURATION_UNAVAILABLE、探活后 CONFIGURATION_CHANGED），不保存验证结果；用户设备权限拒绝仍按原权限异常传播，不吞成普通探活失败。旧 LabCommunicationService 的四个直接写方法明确拒绝，正式管理写仍走原应用服务、在途保护、权限、版本和审计链。
