# M02 三类实验室设备适配契约

版本：INTEGRATION-20261010。与[共同边界](../00-三类实验室设备接入与执行边界.md)、[通讯公共契约](通讯与设备公共契约.md)、M07[命令契约](../07-补液运行与任务执行/设备命令契约.md)共同使用。本文补充适配职责，不声明生产驱动已实现。

## 1. 接入登记与核准

每个共享物理资源组登记实验室代际、来源系统实例和资源主键、型号/固件、泵位/秤/管路/料液绑定、实际服务版本、协议路由、配置版本、能力证据和当前控制方。代际与协议分开：不能以“小试二期”推导必用OPC，或以IP可达推导连接正确。

这些为逻辑登记项；复用现有模型或新增存储须先完成字段字典与基线评审，不在一期旧表加列。通用通讯设备白名单以[通讯公共契约](通讯与设备公共契约.md)第1节为准；控制器和泵使用其工程/专属契约，不借本补充扩名单。

核准顺序：来源和设备身份唯一 → 只读连通 → 实际读数与单位/质量/时间核对 → 泵位、秤和物料会话匹配 → 隔离环境动作与停泵验证 → 故障注入与资源组验收。保存配置、配置实际应用、通信在线、允许执行分别呈现；运行前须确认desired/applied一致且读数新鲜合格。

### 1.1 M07-033 执行器移交资格事实（2026-10-16）

M02 以 `lab_executor_resource_group`、`lab_executor_resource_group_member`、`lab_device_operation_grant` 与 `lab_executor_control_verification` 保存移交资格的唯一受控输入。M07 只调用 `ExecutorTransferEligibilityPort`，不得读取 M02 表或自行以页面输入、任务日志、存活探针推导物理隔离。

资格计算必须针对完整 ACTIVE 资源组：当前操作者须持有每个成员的未失效 `DEVICE_OPERATE` 授权；资源组、成员映射和核验证据的版本必须一致；核验必须为未过期 `VERIFIED`，且旧执行器物理隔离、命令对账并停机、新执行器绑定及旧 epoch 拒绝三项均为真。任一记录缺失、失效、版本漂移、适配器身份不受信或外部查询失败，均返回不可核验，不允许降级为可移交。

适配器通过 M02 内部受控接入写入核验事实，页面没有写入口，且不得将凭据或原始控制报文写入这些表。当前尚无现场受信适配器的生产接入实现，因此即使表结构和 Provider 完成，真实设备场景仍保持 `BLOCKED_EXTERNAL`；不得手工插入 VERIFIED 行制造放行。

原 M07 移交请求命中幂等重放时，M02 另由 `lab_device_read_grant` 和 `ExecutorTransferReceiptAccessPort` 对批次冻结的每个成员重验当前 `DEVICE_READ`。该读取授权与移交写的 `DEVICE_OPERATE`、提交人身份及当前归属相互独立；任一成员失权、过期、缺记录或事实源不可读，M07 一律返回不可披露，不重新提交移交，也不泄露原回执。

## 2. 适配路径

| 场景 | 适配责任 | 证据边界 |
| --- | --- | --- |
| 一期保留 | 映射原设备身份、观察连接与读数；经核准的业务桥接交原GUI/Core执行 | 不将一次旧补料动作拆成新系统直接调速；旧Core维持执行权 |
| 二期过渡 | 核对原/start-feeding服务版本及BatchTaskID关联；由明确的旧控制方执行 | 文档中的HTTP成功不能证明物理动作；服务端实现缺失时禁止新增派发 |
| 二期/中试目标 | 向M07提供统一设备能力、submitCommand/queryCommand和真实执行证据；复用已验证通信服务 | OPC、IoT、外泵与秤适配分别核准，不复用未经证实的点位/单位 |
| 中试旧调度过渡 | 识别真实DB扫描执行路径，采集旧任务与回执 | 已提供版本的/start-feeding为空入口，不能当作启动接口 |

Windows/OPC桥接、HTTP网关或串口服务的部署位置、服务身份、启动恢复、配置加载及失联行为由逐设备实施包落实。历史地址、端口和寄存器不是生产默认配置；凭据按M01/M02现行机制管理，不出现在文档、日志或响应中。

## 3. CMD-I01/I02 的提供方边界

M02提供`DeviceCommandPort.submitCommand(DeviceCommand)`与`queryCommand(DeviceCommandQuery)`，M07消费。字段、状态和证据复用[设备命令契约](../07-补液运行与任务执行/设备命令契约.md)，不另造设备控制HTTP入口。

1. M07持久化命令身份、参数、配置/能力版本、资源声明与fence后调用。
2. M02验证可信执行器、当前物理控制权、全部资源声明及实际配置；按登记适配器转换协议。无法在物理入口隔离旧写入方的设备不具备自动切换资格。
3. 网关按稳定命令身份去重，同键异载荷拒绝；记录传输和原始回执证据。网关记录用于传输查单，不成为第二套业务任务或结算账。
4. M02返回原命令的受理/运行/停止/失败或未知事实；M07更新唯一业务命令状态与事件。没有证据不能填executedAt或把空响应转成EXECUTED。
5. 查询严格查询原命令，不能暗中重发。旧设备无命令ID时须核准网关持久化关联和重启恢复能力；仅进程内缓存不满足未知动作对账要求。

调用与回执持久化失败可能导致物理动作未知，不能以本地事务失败推导设备未执行。绝对速度/停止的重传也必须使用原键及经核准幂等能力，禁止盲目重发定量投料动作。

## 4. 停止、断连与配置变更

执行读数归M07，通用非执行观测归M02。读数保存原值、单位、质量、序列和观察时间；失联不复用陈旧值冒充实时。零速指令受理不是实际停泵证据，需经型号核准的停止反馈、稳定重量及必要现场确认。

通信中断时保留UNKNOWN事实和资源隔离；是否可通过独立通道停止、现场watchdog如何动作必须实测。重连先恢复身份、原命令和配置核对，不自动恢复泵速。执行中的结构性绑定变更须受M07未决命令及M03占用屏障约束，不只检查设备列表的空闲标记。

## 5. 交付与验收

交付设备组映射、协议/版本清单、能力与单位核准、原命令查单证据、进程重启/断网/旧执行器复活测试和实际停止证据。对应共同验收INT-AC01/02/04/05/07/08/11/14/15。

缺现场Core/二期服务实现、真实点位或停止反馈时按共同边界登记BLOCKED_INPUT/BLOCKED_EXTERNAL；可继续开发模拟适配器和既有明确契约，未核准路径保持关闭。新增一期桥接签名、关联存储及物理DTO缺项须在实现前同步接口台账、字段字典和基线，本文不将其标为已接通。

## 6. 补料异常声光设备接入（2026-10-28）

M09基于核准规则和受控异常事实请求声光动作；M02核验可核验的事件时绑定与当前绑定一致、实验室归属、通道配置、控制资格、原命令身份及可用能力后，方可派发。事件时绑定缺失或变更时阻断，不用新绑定设备顶替历史目标。请求目标必须为声光报警器真实ID，不能以反应器ID冒充。人工关闭复用既有M09-016及M02关闭命令链，不因设备配置保存触发动作。多任务或多告警共用时的活动条件归并、关闭范围和重响规则尚未确认；聚合能力不可证明时按M09原契约BLOCKED，不推断独占或自动关闭。

客户《声光报警器 REST API 接口文档》列示 `GET /alarmService/api/open`、`/flash` 和 `/close`，均为有设备副作用的操作。响应需解析 `IsSuccess`，不能只凭HTTP 200或`ResultCode=1`判断；服务报告成功、命令受理与现场实际声光动作分开。客户文档未说明原命令ID、幂等查单及实际状态回读，不得臆造其能力；结果未知保留原身份，未具备核准查询或安全重试能力时不得盲目重发。调用地址、设备映射、身份鉴权、超时/错误及反馈语义须客户和现场核准；历史串口、服务地址和报文不作为默认值。

本节是接入约束，不表明生产控制、客户接口或现场验证已经完成。声光异常不得代替设备停料保障，声光失败不得延误STOP，关闭声光不清除补料停止原因或自动授权继续。正常任务闪烁和完成关闭待确认，保持未启用。

2026-10-28实现边界：M02自动OPEN和M09-016人工OFF均可委托明确核准的对应能力提供方；未装配或非唯一提供方时保持阻断。提供方须证明事件时与当前绑定、权限、共享聚合和原命令身份的持久幂等及未知结果恢复；目前没有生产提供方，地址目录或隔离替身不构成能力核准。客户 GET 传输不自动重试、不跟随重定向，接口受理不代表实物动作。现有设备HTTP入口只允许HTTPS或回环HTTP，客户远程明文HTTP不能绕过该限制，部署通道与凭据待核准。
M02自动声光调用前，须经M09内部只读口取得与当前有效 leaseToken、INVOKING尝试、规则、设备目标、UTC事实时刻和载荷摘要一致的权威投递上下文，再经M07内部只读口核对原运行事件/子事件与入站载荷；任一未知或不一致阻断，不进入设备提供方。返回的来源上下文不代替提供方核验历史设备绑定、当前映射、实际资格及多条件聚合。M02随后调用仍在读事务外；该检查仅是发送前门禁，不证明可以撤销已经进入设备写入口的在途命令。提供方必须继续按原设备/命令身份持久仲裁和处置未知结果。
