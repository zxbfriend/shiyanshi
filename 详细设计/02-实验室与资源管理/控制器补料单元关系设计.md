# 控制器与补料单元关系设计

状态：2026-10-28 控制器字段和后台读写接口已实现，定向测试通过；用户指定的开发库已执行结构变更，并经后台接口配置和回读 9 个 TEST 控制器。W03 新单元的流程登记、人工装量确认和无物理动作时取消已接入源码；5581 页面已验证登记、刷新恢复和安全取消，未提交虚构装量；真实泵操作和正式连接尚未接通。

## 已确认的业务规则

- 补料单元属于实验室，并对应同一实验室中的一个控制器。例如实验室中的控制器 `fx033` 对应补料单元 `f33`。
- 不新增维护界面，不要求通过液瓶配置维护控制器与补料单元关系。单元编码是实际配置数据，不能从控制器编号猜测或自动生成。
- 读取该控制器“泵的默认连接”的全部通道，不区分内置泵和外置泵；按泵号数字顺序排列后，依次生成 `f33.1` 至 `f33.n`。例如 `PUMP1`、`PUMP2`、`PUMP10` 按 1、2、10 排列，不使用字符串字典序。
- 瓶位按当前通道重新编号，不单独保存固定的通道与瓶位对应关系；用户确认暂不考虑流程快照和操作期间通道变化的处理。
- 当前培养的培养基、耗材和补料规则从该培养自己的生效补液设置读取，不能读取模板后续修改或借用其他控制器的数据。台式罐体按当前培养容量匹配，与补料单元归属分开。
- 2026-10-28 用户最新确认：人工填写的初始装量以 g 为单位，沿用原页面的正整数和不超过容量的要求；转换规则待确认期间，前端各瓶临时统一使用 1000 g 作为展示及输入上限，该数值不是实际核准容量。最终容量由耗材容积按待确认规则换算，不得自行假定换算系数。人工确认不代表真实设备连接或设备执行成功。

## 数据关系建议

建议在 M02 的控制器表 `lab_bench_reactor_controller` 增加可空的补料单元编码字段，例如 `feed_unit_code`。控制器行已有 `lab_id` 和 `connection_id`，由此表示实验室、控制器与单元的关系；未配置时保持空。建议同实验室的有效单元编码唯一，作为防止同一个单元被重复配置的技术约束；不同实验室是否允许相同编码仍需业务确认。

`feed_unit_code` 已纳入目标 DDL、字段字典和新库基线；已有开发库使用单独的定向结构升级，不通过罐体或旧控制器自动回填。无需保存 `f33.1` 等派生编号或新增页面。配置通过受控后台接口写入，遵守现有权限、审计与管理版本约束；`m02_active` 保持原名。

## 后台接口

- `GET /lab/pumpconnection/controller/{controllerId}/feed-unit`：需要 `lab:pumpconnection:query` 与实验室可见权限；响应 `data` 包含 `unitCode` 和按当前通道泵号数字顺序生成的 `slots`，每项包含真实 `channelId`、`channelNo`、`pumpNumber` 和展示用 `slotCode`。未配置单元时返回空编码和空槽位；管理版本位于响应顶层 `managementRevision`。
- `PUT /lab/pumpconnection/controller/{controllerId}/feed-unit`：需要 `lab:pumpconnection:edit`、该实验室操作权限及 `X-Request-Id`、`X-Management-Revision`；请求体为 `{ "feedUnitCode": "F33" }`。去除首尾空白后编码须为 1 至 50 个字符；同实验室有效控制器不得重复编码。写入、审计及管理版本经现有管理守卫处理。
- W03 候选的 `benchFeedUnit` 是只读投影，结合当前培养生效补液方案匹配真实泵号；名称优先取方案快照，缺失时按方案引用 ID 读取当前主数据并标记 `CURRENT_MASTER`。当前名称仅用于展示，不改变培养方案。

## 读取和展示建议

1. 根据当前培养读取其实验室、控制器和生效补液方案，核对控制器属于当前实验室。
2. 按实验室和控制器查对应的补料单元编码；读取该控制器默认连接的全部通道。
3. 将可核验的通道泵号按数字排序，按排序位置生成单元瓶位编码；保留通道本身的真实身份和泵号用于与培养方案匹配。瓶位序号与泵号是不同字段，不能因为二者数字相同便互相替代。
4. 按实际泵号读取当前培养方案中的培养基、耗材和规则，再用于连接补料单元流程。未配置补液的通道仍生成瓶位；是否需要录入装量需进一步确定，不能自动视为已配置。

默认连接通道编号当前为文本，也可能为空，既有查询按文本排序；不能以 SQL 的字典序当作数字顺序。通道泵号缺失、重复或无法与当前培养方案核对时，应明确提示数据不可用，不按其他控制器、旧 `reactor_id`、旧 `CTRL-F12` 或数组位置猜测泵身份。

## 与现有流程的差异

旧 W03 液瓶路径继续使用 `bottle_config`、数字瓶 ID、泵资源键和核准克重容量。新单元流程用实时通道身份与派生瓶位登记并确认人工装量，确认记录保留当时的通道、瓶位和装量作为操作事实；不新增通道与瓶位的固定映射或流程快照。逻辑标识不能冒充旧数字瓶 ID、真实设备连接或实测重量。正式设备动作仍需真实泵设备、适配器及计量依据。

培养补液设置中耗材容量使用 mL/L 时，不得直接当作 g 的重量上限。用户确认本次暂不需要模拟；真实计量与设备验证仍需有效数据。

## 验证建议

- 同实验室读取正确控制器及补料单元，跨实验室或缺少配置时明确提示。
- 零通道、单通道、多通道、泵号 2 与 10、通道增删后实时重排，以及泵号缺失和重复。
- 当前培养方案覆盖默认配置；不同培养和控制器之间不串数据，不读取 `CTRL-F12` 的旧关联。
- 按当前培养生效快照读取泵配置；未配置泵与缺失耗材分别验证，mL 与 g 不混用。
- 分别验证模拟接口、浏览器操作和真实设备；各层结果独立报告。
