# 控制器与取样单元关系设计

## 已确认边界

- 小试控制器对应一个独立取样单元；取样单元自带一台取样泵。取样单元与补料单元独立，不关联设备配置中的独立蠕动泵。按 2026-11-02 用户确认，取样单元液瓶槽位可直接关联控制器，详见[液瓶接口与观测边界](液瓶配置逐接口与观测边界.md)；不因此推测物理泵或占用事实。
- 取样单元编码保存在 `lab_bench_reactor_controller.sampling_unit_code`，与补料单元编码同表、不同字段；可空表示未配置，同一实验室未删除控制器的非空编码唯一。编码是人工配置的事实，不能按控制器编号或 S/F 前缀猜测。
- 该字段仅表明控制器与取样单元的配置关系，不代表真实泵通信、物理连接或设备就绪。内置泵不生成虚构的独立泵 ID 或通道。

## 配置与使用

- `GET /lab/pumpconnection/controller/{controllerId}/sampling-unit`：要求 `lab:pumpconnection:query` 和实验室查看范围；返回 `data.unitCode`（未配置为 null）和顶层 `managementRevision`。
- `PUT /lab/pumpconnection/controller/{controllerId}/sampling-unit`：要求 `lab:pumpconnection:edit` 和实验室操作范围；携带 `X-Request-Id` 与本模块读取得到的 `X-Management-Revision`，请求体为 `{ "samplingUnitCode": "S01" }`。编码去除首尾空格后为 1 至 50 字符；守卫事务内重验权限、唯一性并记录前后审计。
- 小试开始培养候选根据当前实验室及培养的控制器读取该编码，并在第三步显示；没有配置时不生成默认单元。中试及补料单元流程不使用此字段。会话恢复与安全关闭不依赖该配置读取。
- 按用户当前测试要求，小试开始培养暂直接使用模拟设备交互，不需要启动参数；服务端保留 `SIMULATED` 来源，完成流程仍写入培养业务状态。该测试实现不得当作真实设备联调，投产前须移除模拟并接入已确认的设备协议；中试不受影响。

## 数据库与验证边界

新空库定义和核验随开发基线同步；已有库使用单独的定向结构升级脚本，执行前须确认目标、停写、备份并另行授权，不回填历史单元。未执行 SQL 不能声明环境已升级；部署新后端前须先核验目标库已包含新字段和约束。HTTP、浏览器及真实设备分别验收，不以模拟替代设备联调。
