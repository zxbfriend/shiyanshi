# M02 默认连接与打印排版接口契约

## 2026-11-05 培养固定泵与空闲外置泵补充规则

本节为用户最新确认的目标行为。反应器详情的“默认连接”弹窗在控制器空闲时始终读取和保存实验室初始化默认连接，不论是否关联草稿或草稿是否已有固定泵；有有效占用时继续按该占用培养及现行审批规则处理。实验室泵默认连接入口维护实验室初始化配置，有有效占用时按既有规则拒绝保存。草稿关联不构成有效占用。单独培养管理入口的培养配置不由本规则隐式改写。

### 空闲控制器默认连接保存（2026-11-05 最终确认）

空闲时直接保存实验室默认连接，不同步、不覆盖任何关联草稿的固定泵、补液方案或计算规则。controllerId 为控制器的 connection_id；控制器和反应器兼容入口解析至同一配置后按同一规则处理。保存无需原因、不走实验室审批策略；在 SYSTEM 守卫事务内复核控制器身份、实验室操作权限及不存在有效占用，预约、运行或待核验释放均按既有规则拒绝保存。读取、权限或占用事实不可得时失败关闭。

空闲弹窗中外置泵字段置灰且不可更改。现有通道 pump_id 是实验室蠕动泵实例的配置关联，不作为培养外置泵身份，也不证明设备物理连接；保存保留该关联原值。详情只读 pumpDeviceNo 根据已关联泵的 ID 批量读取当前实验室未删除实例的设备编号，失效或未绑定时为 null。培养基、耗材及泵速策略选择沿现有真实主数据、权限、完整通道集合、审计和版本规则处理；不能根据历史文本猜测主数据 ID。

保存使用原读口管理版本和请求标识，重试沿用原请求及载荷；完整通道、并发校验、审计和幂等遵循 M02-110 现行契约。此规则描述目标行为，源码接线及 HTTP、浏览器验收须分别核验，不因文档更新宣称通过。

培养的固定泵配置与补料任务、补糖规则是不同内容；固定泵首次保存不能虚构计算规则，后续修改须保留已有规则。“已设置”还须同时满足培养固定泵保存和补液计算规则配置两项条件。培养状态及审批策略的适用范围以相关现行契约和用户确认核验，不凭是否存在快照推断已设置。

## 2026-11-05 补料容器主数据

按用户确认，台式控制器默认连接的新选培养基与补料容器分别使用培养基及 Bucket 耗材主数据，`materialName` 和 `feedContainer` 分别保存主数据 ID 字符串；服务端校验培养基有效，耗材未删除、CITEM、名称含 Bucket、容量为正且单位为 mL 或 L。清空允许；既有占用守卫、权限、双头及通道全量保存规则不变。历史数据尚未转换，本段不表示数据库迁移或浏览器验收已完成。

### 既有默认连接的数据转换准备

2026-11-05 对目标开发库只读核查：93 个通道均归属有效控制器，无孤儿通道；其中 74 个非空培养基值、74 个非空容器值。七个通道属于有效运行占用，其中六个有上述两项配置。上述数量只反映核查时刻，执行时不得当作固定条件使用。

旧培养基字典代码 `1` 指向用户确认的 `Na2CO3`；`2`、`3`、`4`、`5`、`6` 分别对应 `FM020a`、`FM020b`、`Glucose`、`Basal`、`Harvest`。按核查时的有效主数据，每一项均可唯一找到对应 ID。旧容器代码 `1`、`2`、`3` 的字典标签分别是 1000、2000、5000 mL Bucket；核查时各有唯一有效 Bucket 主数据。其他已保存培养基名称在核查时也有唯一有效主数据。名称匹配结论仅用于形成待审核映射，不能推定之后的数据仍相同。

处理前以稳定通道 ID 导出原值及所属控制器、实验室、占用和管理版本，分别重查每项映射唯一性及目标 ID 的有效性。无法唯一核实的项必须停止处理并列明，不自动猜测、清空或覆盖。每台控制器按完整通道集合处理，使用当前管理版本及既有守卫写入口；事务内重查有效占用，`RESERVED`、`RUNNING`、`RELEASE_PENDING` 均禁止修改实验室默认配置，待释放后重新核验。不得通过数据库批量更新绕过权限、占用、审计和并发守卫。

处理后按通道 ID 对照前后值、目标主数据、控制器归属、通道数量和占用状态，并通过培养管理带入及反应器详情回读核对；记录实际 HTTP 与浏览器验证结果。此节是处理方案，不是 SQL 执行记录，亦不授权修改目标数据库。

反应器详情中，控制器无有效占用时，始终编辑并保存实验室默认连接的培养基、Bucket 耗材和泵速策略；无需填写原因，也不走实验室审批策略。保存保持物理通道、泵绑定、速度及称重设备原值，不同步关联草稿；外置泵字段置灰且不可更改。提交须保留原读口的管理版本与本次请求标识，未确认结果按原请求重试；当前页面会话中的未决请求按用户、实验室和控制器隔离，浏览器重载后的恢复仍需验证和补齐。占用时不可使用该入口修改实验室默认配置。

## CB-20261024：独立台式控制器与罐体绑定（最新确认）

台式控制器为独立实验室实例，主键沿用 `lab_bench_reactor_controller.connection_id`，对外命名 `controllerId`。允许控制器尚未绑定罐体；一个控制器可绑定多个罐体，一个罐体最多绑定一个控制器。规范关联改为 `lab_bench_reactor.controller_id → lab_bench_reactor_controller.connection_id`，可空且索引不唯一，不新增表。关联必须同实验室、目标有效；变更仍须实验室操作权限、SYSTEM管理守卫、真实设备使用/引用检查及审计，不以型号、编号或名称猜测关系。

控制器 `reactor_id` 仅保留迁移兼容事实，允许NULL，停止新增业务依赖或双写；旧字段不得限制新控制器的独立生命周期或一控多罐关系。反应器旧 `controller_no` 亦为兼容列，真实编号只读自控制器 `controller_no`。型号采用统一 `dev_reactor_model` 的有效 `BENCH_CONTROLLER`，型号无实验室归属；`model_name` 为型号名称，`spec` 为规格，均不代替实例编号或资产号。小试上游按 `lab_lab.lab_type='1'` 与授权实验室集合过滤实例 `lab_id`，不按型号归属筛选。

默认连接新主接口为 `GET /lab/pumpconnection/controller/{controllerId}`、`PUT /lab/pumpconnection/controller/{controllerId}`。沿原查询/编辑功能权限和实验室准入，PUT沿Header/WriteMeta双头，读响应顶层返回SYSTEM `managementRevision`；`controllerId` 解析为 `connection_id`，响应同时保留 `connectionId`。`controllerNo` 取该控制器真实编号，通道按稳定 `channelId` 读写，不要求先绑定罐体。响应 `reactorId` 为旧兼容字段，可空且不得解释为完整罐体集合。

旧 `GET/PUT /lab/pumpconnection/reactor/{reactorId}` 保留兼容：由该罐体的 `controller_id` 解析控制器并复用同一配置链，禁止按控制器旧 `reactor_id`、编号或“最后一条”解析；未绑定返回配置未就绪，不创建控制器或自动绑定。旧调用不能通过控制器配置修改罐体绑定。一个控制器的默认连接及通道由多个罐体共用，配置前必须检查该控制器及全部已绑定罐体的使用状态，任一阻断或事实未知即整次拒绝，不以当前入口罐体空闲代替全量检查。

空库仍只执行开发基线01/02/03；既有库单独使用 [RM-04升级来源](RM-04-现有开发库控制器罐体绑定升级.sql)，明确确认目标、停写和备份后执行。仅依据唯一、同实验室且无冲突的旧 `reactor_id` 回填；已有不同绑定、失效目标或多连接歧义拒绝，不猜测、不覆盖。脚本支持修正冲突后重跑；MySQL DDL隐式提交，不能承诺整个DDL与回填原子回滚。没有执行SQL或运行验收的证据时仅标静态设计同步，不能宣称数据库/HTTP/浏览器通过。

## 1. 共同约束

Authorization必填；读取无Body/写版本头；保存Content-Type:application/json、X-Request-Id(UUID)、X-Management-Revision（非负十进制字符串）必填。ID均正bigint十进制字符串，时间/小数遵循M01/M02已有约定。响应成功外壳code/msg/requestId/managementRevision，data为各接口明确对象；写回显提交后的版本，GET无管理版本增长。本文新写响应采用原聚合视图，避免前端自行猜测保存后的行和主键。

写入遵守SYSTEM→管理版本→真实对象及实验室→权限/引用/业务使用守卫→聚合修改/审计/回执/版本→提交；任何失败全部回滚。用户+requestId相同载荷回放原结果，异载荷REQUEST_CONFLICT；结果未知使用原键核实，不生成新键绕过。设备网络、实际打印、文件清理不在配置事务内触发。

公共错误：INPUT_INVALID（400字段/数量/精度）、READ_ONLY_FIELD（400只读字段）、NOT_FOUND（404不存在或不可见）、PERMISSION_DENIED（403无功能或操作资格）、MANAGEMENT_CONFLICT（409旧管理版本）、REQUEST_CONFLICT（409同键异载荷）、REFERENCE_EXISTS/RESOURCE_IN_USE（409引用/活动或未知使用阻断）、CONFIGURATION_INCOMPLETE（409缺少配置依据）、DEPENDENCY_UNAVAILABLE/MANAGEMENT_BUSY（503依赖或锁竞争）。GET不套写冲突；详情读取的旧配置缺项可在视图返回未知，依赖失败不得伪造完整配置。完整外壳见第6节。

## 2. GET /lab/pumpconnection/reactor/{reactorId}

Path reactorId必填，无Query/Body。功能lab:pumpconnection:query＋实验室可见；从真实台式反应器解析其有效连接，不能用reactorId当connectionId。无对象/不可见404；多条有效连接属于配置冲突，409 CONFIGURATION_INCOMPLETE，禁止任取最后一条。

完整data字段：connectionId/controllerId/labId:string，reactorId:string/null，modelId:string/null（只读控制器型号ID），controllerNo:string/null（只读），balanceId:string/null、balanceKind:FLOOR_SCALE/BALANCE/null（未知不推断）、balanceNo:string/null（只读设备编号），remark:string/null（≤500沿当前控制器物理列），channels:Channel[]，managementRevision:string。Channel全部字段：channelId:string、channelNo:string（已初始化物理编号，只读），pumpType:string/null、pumpId:string/null，defaultSpeed/maxSpeed:integer/null（历史未知允许null），materialName/feedContainer/speedStrategy:string/null。读取保留已初始化顺序与真实身份，不能按数组索引重新生成channelId或channelNo。

按控制器及按罐体的详情均返回 `data.modelId`：取所解析控制器的 `lab_bench_reactor_controller.model_id`，十进制字符串，可空；为空表示该控制器未登记型号。该字段是控制器型号 ID，并非罐体的 `lab_bench_reactor.model_id`，不得从罐体型号推断或回填；只用于读取，不属于默认连接写入字段。

2026-10-26 培养修改页只读编号补充：按反应器及按控制器的详情均增加balanceNo。服务端在同一主行查询中按已保存balanceKind分别关联lab_balance.balance_id或lab_floor_scale.scale_id，只返回同实验室、未删除设备的真实device_no；未配置、未知类型、跨实验室或已删除引用均返回null，不因数值ID相同切换设备表，不把历史FLOOR_SCALE称为天平。字段仅为只读投影，不进入保存白名单，不改变现有权限、身份校验及管理版本来源。

## 3. PUT /lab/pumpconnection/reactor/{reactorId}

2026-11-05 用户确认：小试泵速选择与培养补液方案保持一致。`speedStrategy` 可保存 `Speed1` 至 `Speed10` 中一个代码、M04 策略 ID，或 `VERSION|模板ID|版本ID`；代码与策略或模板选择互斥。模板版本必须属于启用且未删除的泵速模板，并适用于小试；读取时返回对应名称，继承到培养方案时保留所选版本。不改变现有管理版本、权限和完整通道校验。

`GET /lab/pumpconnection/controller/{controllerId}/speed-template-candidates` 按控制器可见范围和 `lab:pumpconnection:query` 权限分页读取可用于小试的当前泵速模板版本；`data.rows` 每项包含 `templateId`、`versionId`、`name`，并返回 `total`、`pageNum`、`pageSize`。候选复用 M04 已启用、未删除、适用于 COMMON/SMALL 的版本筛选，不读取或修改设备配置。

## 6. 完整失败样例与验收

两个写接口X-Management-Revision过期均HTTP 409：

```json
{
  "code": 409,
  "msg": "配置已变更，请重新核对后保存",
  "requestId": "00000000-0000-4000-8000-000000000003",
  "errorCode": "MANAGEMENT_CONFLICT",
  "data": null,
  "fieldErrors": [],
  "retryAfterSeconds": null
}
```

重复channelId或rowNo、缺初始化通道或缺四行中的任一行，HTTP 400：

```json
{
  "code": 400,
  "msg": "配置行重复或不完整",
  "requestId": "00000000-0000-4000-8000-000000000003",
  "errorCode": "INPUT_INVALID",
  "data": null,
  "fieldErrors": [],
  "retryAfterSeconds": null
}
```

打印机无合法尺寸模板仍请求保存，HTTP 409：

```json
{
  "code": 409,
  "msg": "缺少有效排版模板，无法保存",
  "requestId": "00000000-0000-4000-8000-000000000003",
  "errorCode": "CONFIGURATION_INCOMPLETE",
  "data": null,
  "fieldErrors": [],
  "retryAfterSeconds": null
}
```

| 接口 | 验收断言 |
| --- | --- |
| 默认连接GET | reactorId/connectionId不混用，物理通道ID稳定；历史BALANCE/FLOOR_SCALE不靠ID碰撞猜测 |
| 默认连接PUT | 重排仍按channelId更新；缺/重复/跨连接整次拒绝；失败不改原连接、不清通道、不改变能力 |
| 排版GET | 固定4槽，缺值null且未就绪；GET不建排版记录、不造尺寸 |
| 排版POST | 4行原子写、宽高完全保留、只接受整数新字体；未核准模板拒绝；无打印副作用 |
| 两个写接口 | 同键同体原回执；异体409；审计或回执写失败整体回滚；撤权后不能以旧候选绕过 |

以上为设计契约与模拟夹具，未调用真实HTTP、未执行SQL或打印/设备验证。物理模板单位、泵协议值及现场能力仍沿已有资料核准，不由本文样例确定。
