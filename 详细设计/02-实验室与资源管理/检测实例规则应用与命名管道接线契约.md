## 实例规则应用

- M02-256：GET `/lab/labdetector/{detectorId}/runtime-profile`，`lab:labdetector:query`与实验室可见范围，顶层managementRevision。返回detectorId/modelId/modelProfileRevision/appliedProfileRevision/queueRevision、型号就绪结论及问题；读取不应用规则。
- M02-257：POST `/lab/labdetector/{detectorId}/runtime-profile/apply`，沿用Header/WriteMeta，载荷仅expectedProfileRevision、expectedAppliedRuleRevision（首次null）、expectedQueueRevision。功能权限`lab:labdetector:edit`且目标实验室MANAGE；服务端固定动作码M02-257。逐台显式确认，不支持静默批量应用。
- SYSTEM→实验室→设备锁内重读型号、实例及版本；调用M05拥有的使用事实出口，任何未释放草稿、活动检测、未完整回收结果、未决/UNKNOWN派发均阻断。未知旧事实拒绝，不按空闲处理。存在草稿时先按现行权限处理草稿，避免规则变化后草稿位置/字段失效。
- 型号配置完整且协议已注册方可应用。本接口仅提交工作台服务器规则，不修改物理设备参数，不假造设备ACK。通信配置应用和探活仍独立。
- 原子写入applied_rule_revision、applied_rule_snapshot并推进queue_revision；以当前applied版本及queue版本CAS。同原键重放返回原回执；载荷变化、版本冲突沿既有守卫错误处理。审计字段为model_id、applied_rule_revision、queue_revision和快照SHA-256，原始大JSON不写入普通审计。

## 完整实例快照

存储信封：`{schemaVersion:1,modelId:string,profileRevision:string,legacyScalars:{detectType,communicationTypes,supportStored,sendMode,singleSendLimit,workSendLimit,columnCount,channelCount},ruleProfile:object}`。

legacyScalars冻结同一持锁型号版本的旧标量；ruleProfile逐叶复制型号受控rule_profile（schemaVersion、layout、scheduling、workCapacity、protection、occlusion、inputProfile），不添加凭据、运行位置或客户端自报能力。modelId和profileRevision必须与实例列匹配。M02对内Facts.profileJson返回由该信封解析的DetectorRuntimeProfile投影；M05不能读取型号最新规则替代实例快照。旧非信封结构、缺叶或身份不一致失败关闭，不自动改写。

新发送使用不重试的sendOnce，保存读取到的原始字节（包括无法解析的帧）；旧进程内send保留调用签名，但也不得在通信结果未知时自动重发。APPLIED只证明配置已加载，ONLINE只证明探活，两者都不是检测受理、开始或完成事实。

### 2026-10-21 第二批：超时、并发与失败原始证据

- 命名管道读写采用可取消的底层异步 I/O；超时后取消并等候本次操作收束，再释放原生缓冲区、事件及管道句柄，不能仅让上层 Future 超时而遗留阻塞读取。相同实际管道路径的调用串行，路径大小写归一；不同管道不共用客户端全局锁。该保护是本 JVM 的调用互斥，不代表多部署节点或设备侧的全局控制权。
- `named-pipe.client.read-timeout-millis` 在管道打开后，为本次写入与完整响应读取设置共用期限，不因收到一块数据就重置期限；它不限制 Windows/SMB 的管道打开耗时。超时、断开或传输失败时保留已经读取的原始字节；不把可能恰好长得像成功回执的部分帧当作完整 ACK。异常后的自动恢复只查询原调用；协议不支持查询时保持 UNKNOWN。
- SDMS 连接超时使用 `sdms.client.http.connect-timeout-millis`，读超时独立使用 `sdms.client.http.read-timeout-millis`（既有缺省值为 300000 毫秒）；非正值拒绝客户端配置，不能变成无限等待。RestTemplate 创建时应用这些值，配置修改后须重启服务。读超时表示底层等待数据的超时，不冒充整个 HTTP 调用总期限。
- SDMS 继续连接已核准的一套平台，沿现有认证链提交一次订单；显式关闭底层 HTTP 客户端自动重试，包括 429/503 响应后的重试，不因生产类路径变化而重新启用。响应头已收到时保留 HTTP 状态；响应体读取中断时保留已收字节，返回 UNKNOWN，不重发订单，也不根据 HTTP 200 或部分内容推断设备受理。
- M05 对实际收到的原始字节或 HTTP 响应沿既有 Evidence 独立耐久保存，再投影 UNKNOWN；完全未收到响应时不伪造设备事件，在现有 det_dispatch_log.error_message 中以独立事务保存 NATIVE_TRANSPORT_UNKNOWN 或 TRANSPORT_UNKNOWN 原因码，保留首个非空原因，随后投影 UNKNOWN。恢复仅有泛化未知结论时使用 DISPATCH_INVOCATION_UNKNOWN，不覆盖既有原因。原因或原包写入失败应向调用方报错；耐久调用已进入 INVOKING，之后恢复也不能再发送物理命令。不新增平行证据存储或修改本批数据库结构。

本批实现、自动测试与真实设备验收分别记录；本机隔离测试管道或 HTTP 服务不代表客户设备或 SDMS 联调。

复用现有M05耐久预占/派发执行器、原调用UUID和逐样品绑定；新适配器必须在事务外调用已注册NamedPipe协议服务。严格区分协议成功、逐样品接受、实际开始、检测结果和整次完成；缺少某类原始事实则保持对应未知，不按固定等待时间推断。

结果以原发送时固定身份、项目集合、列/行及占用代次关联，原始证据先耐久保存再投影。结果文件/设备响应不能仅凭可复用sampleNo覆盖历史对象；重复与冲突、迟到及UNKNOWN查询按M05接收契约处理，不盲目重发。模拟器可扩展受控测试事实，但不能把模拟核准或夹具当真实设备/现场验收。

M02 对内 `DetectionCollectionFactsPort` 仅向服务端采集消费者提供锁与队列 CAS：调用者已持 SYSTEM 锁，以冻结的 adapterKey 和 communicationRevision 选择已注册的 m05-namedpipe/m05-sdms 能力，重新核验部署设备/实验室范围及当前通信版本，再按实验室→设备顺序加锁。锁后再核验归属、通道和版本；不读取 M05 业务表，不依赖发送人的当前登录，不接受浏览器自报适配器身份，不返回通信凭据。此内口不新增公开 HTTP 动作。
