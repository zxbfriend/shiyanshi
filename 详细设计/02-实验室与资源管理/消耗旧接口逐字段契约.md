# M02 消耗旧接口逐字段契约

DD-20260913-T8-R7。六个保留入口沿用ConsumptionRuleController路由，补齐目标DTO；与[旧入口适配责任](唯一性预检查与消耗旧入口兼容契约.md)、[聚合配置规则](消耗配置聚合与解析契约.md)、[错误码登记](错误码全集.md)共同使用。以下为目标技术协议，非现有实现验收结论。

## 1. 公共字段、范围与版本

所有ID为正十进制字符串，managementRevision为非负十进制字符串；quantity/seqNumber为JSON整数1—2147483647，quantity允许null表示NA。读写都核验真实实验室范围，GET可见等级0，写管理等级2；功能权限逐节列出。聚合卡片枚举固定tabType=feeding_batch/column_after/sample，detectClass=BGA/ViCell/OSMO/Cedex/留样，dilutionType仅ViCell为diluted/undiluted，其他为null，组合必须在bootstrap定义中。

写头X-Request-Id=UUID、X-Management-Revision必填，不进入Body；缺旧客户端安全协议409 CLIENT_UPGRADE_REQUIRED。SYSTEM守卫事务内先处理幂等回执/版本，再读完整页签构造最终图，保存配置、审计、版本、回执一起提交。同键同体且仍有权重放原结果，同键异体409 REQUEST_CONFLICT；新键旧版本409 MANAGEMENT_CONFLICT。网络超时以原键原体核对，不能新键绕过。以下模拟写分别从30成功到31，不连续执行相同样例ID。

旧实体到目标映射：rowName取固定cardName，只读；sharedSource仅保留历史来源显示字符串/null，不作为共享身份，真实引用只看sharedRuleId；consumableCode/consumableDescription为当前有效耗材展示，失效时null，configurationIssue标问题。delFlag、remark、params、审计字段不开放写；rowName、seqNumber、sharedSource、展示字段、resolvedQuantity、configurationIssue同为只读。不能用旧字段名称承载任意新指令。

RowView平铺：ruleId、labId、tabType、detectClass、dilutionType、rowName:string、seqNumber:int、itemType:'1'/'2'、consumableId:string|null、sharedRuleId:string|null、sharedSource:string|null、quantity:int|null、consumableCode/consumableDescription:string|null、resolvedQuantity:int|null、configurationIssue:string|null、createBy/updateBy:string|null、createTime/updateTime:ISO8601|null、managementRevision。直接行resolvedQuantity=quantity，共享行由稳定源解析；失效源为SOURCE_UNAVAILABLE，失效耗材为CONSUMABLE_UNAVAILABLE，正常null，NA本身不报错。只回读有效行，不输出delFlag或BaseEntity.params。

## 2. GET /lab/consumptionRule/list

权限lab:consumptionRule:list。Query可选labId、tabType、detectClass、rowName、dilutionType、seqNumber、itemType、consumableId、quantity，另pageNum默认1且≥1、pageSize默认10且1—100；Body空。labId/consumableId为ID，整数及枚举按上节，rowName字符串trim后≤100，空串相当不筛选，模糊搜索按字面处理%/_。未提供labId时仅当前可见集合，显式不可见labId为404，不把未授权实验室混进total。无权集合返回rows=[]、total=0。

筛选联合AND，quantity未提供表示不过滤而非只查NA；不新增NA查询编码。dilutionType未提供不过滤，不能用字符串null查空；提供时必须合法值，若同时指定非ViCell则400。其他组合非法400。拒绝客户端params.viewLabIds、delFlag、排序SQL和未登记键。先授权过滤后统计/分页。

目标排序labId ASC、tabType ASC、detectClass ASC、dilutionType ASC、seqNumber ASC、ruleId ASC，字符比较沿数据库排序规则；不是聚合页面的卡片显示顺序。末尾真实ID保证相同序号分页稳定。示例Query：labId=1001&tabType=feeding_batch&pageNum=1&pageSize=10。HTTP 200：

## 4. POST /lab/consumptionRule

权限lab:consumptionRule:add＋实验室管理等级2。Body严格labId、tabType、detectClass、dilutionType、itemType、consumableId、sharedRuleId、quantity，全部键必出现（允许null的字段按下述规则），不接受ruleId。类型1有效耗材必填，sharedRuleId必须null，quantity正整数或null；类型2只填已保存的同lab/tab其他卡片直接源sharedRuleId，consumableId/quantity必须null。不能共享未保存新行、共享行或同卡片源。示例追加一个直接行：

```json
{
  "labId": "1001",
  "tabType": "feeding_batch",
  "detectClass": "BGA",
  "dilutionType": null,
  "itemType": "1",
  "consumableId": "7401",
  "sharedRuleId": null,
  "quantity": 1
}
```

读取完整目标页签，将新行追加在目标卡片末尾，seqNumber由服务端重排，分配新ruleId。重验最终图后提交，不覆盖其他卡片，不扣库存。目标成功回执为{ruleId,labId,tabType,managementRevision}，HTTP 200：

```json
{
  "code": 200,
  "msg": "操作成功",
  "requestId": "00000000-0000-4000-8000-000000000007",
  "managementRevision": "31",
  "data": {
    "ruleId": "8103",
    "labId": "1001",
    "tabType": "feeding_batch",
    "managementRevision": "31"
  }
}
```

## 5. PUT /lab/consumptionRule

权限lab:consumptionRule:edit＋真实实验室管理等级2。Body为POST完整白名单＋ruleId必填。提交labId/tabType/detectClass/dilutionType必须与真实行身份完全相同，拒绝移动行或伪造归属。保持原序号，不能用seqNumber重排；排列调整走聚合入口。既有共享行不能直接改直接耗材行，先删后新增。直接行改共享行必须验证最终图，包括是否有保留引用依赖原直接源。示例调整直接源数量（所有共享引用随后按该源解析）：

```json
{
  "ruleId": "8101",
  "labId": "1001",
  "tabType": "feeding_batch",
  "detectClass": "BGA",
  "dilutionType": null,
  "itemType": "1",
  "consumableId": "7401",
  "sharedRuleId": null,
  "quantity": 2
}
```

同页签统一校验及事务；已固化任务用量不重算。HTTP 200成功：

```json
{
  "code": 200,
  "msg": "操作成功",
  "requestId": "00000000-0000-4000-8000-000000000007",
  "managementRevision": "31",
  "data": {
    "ruleId": "8101",
    "labId": "1001",
    "tabType": "feeding_batch",

  }
}
```

## 6. DELETE /lab/consumptionRule/{ruleIds}

权限lab:consumptionRule:remove＋全部真实实验室管理等级2。Path为非空逗号分隔唯一ID集合，Query/Body空，WriteMeta必填。重复ID400，任一不存在404；先全量授权，再建立每lab/tab删除后的最终图，保留共享行仍指删除源409 REFERENCE_EXISTS。删除源和全部共享行可一起成功。多个页签/实验室也必须同SYSTEM事务原子提交；不逐行成功后跳过失败。例8101为源、8102为其唯一共享行：DELETE /lab/consumptionRule/8101,8102。

removedIds按请求顺序返回（幂等请求摘要保留该顺序），成功HTTP 200：

```json
{
  "code": 200,
  "msg": "操作成功",
  "requestId": "00000000-0000-4000-8000-000000000007",
  "managementRevision": "31",
  "data": {
    "removedIds": [
      "8101",
      "8102"
    ],
    "managementRevision": "31"
  }
}
```

重排受影响卡片展示序号，不改保留行稳定ruleId。新请求再删已删除对象404，原成功请求ID同体重放首次回执。

## 7. POST /lab/consumptionRule/export

权限lab:consumptionRule:export＋列表相同可见范围。Query采用list全部业务筛选，去掉pageNum/pageSize，Body空；不需要WriteMeta，不递增版本，不配置写。示例?labId=1001&tabType=feeding_batch。ExcelUtil直接返回XLSX；此项是R4表外新增核验入口，不能悄悄把原25项计数改为全项目覆盖。

HTTP 200文件字节，Content-Type为application/vnd.openxmlformats-officedocument.spreadsheetml.sheet；目标Content-Disposition附件名consumption-rules.xlsx。无JSON data、taskId或轮询地址。文件传输/失败原则复用[既有导出契约](既有导出接口与文件响应契约.md)。响应提交前失败返回标准JSON；文件流已开始后中断只能判下载失败，不能追加JSON冒充成功。重新导出重新鉴权读取当前配置。

目标列顺序固定：ruleId、labId、tabType、detectClass、rowName、dilutionType、seqNumber、itemType、consumableId、consumableCode、consumableDescription、sharedRuleId、sharedSource、quantity、resolvedQuantity、configurationIssue。来源同RowView；名称按既有中文展示，ID按文本，数量null留空而不是0，字符串按文本不得触发Excel公式。不直接沿实体未经审阅的readConverterExp；不导出审计账号、任意params或文件路径。当前Excel注解存在说明文字形式的转换表达式，目标列映射须显式实施并实际打开工作簿验收。

## 8. 逐接口错误集合及完整失败

list/export：400 INPUT_INVALID、403 PERMISSION_DENIED、指定lab无效404 NOT_FOUND、503 DEPENDENCY_UNAVAILABLE。detail：同上；有坏引用但可展示时用configurationIssue，不把整行伪造为空。

POST/PUT：400 INPUT_INVALID/READ_ONLY_FIELD，403 PERMISSION_DENIED，404 NOT_FOUND，409 CLIENT_UPGRADE_REQUIRED/REQUEST_CONFLICT/MANAGEMENT_CONFLICT/REFERENCE_EXISTS，503 DEPENDENCY_UNAVAILABLE/MANAGEMENT_BUSY。DELETE同集合但不接收Body；源被保留引用才用REFERENCE_EXISTS。所有认证错误沿M01，失败不产生部分配置/版本/成功审计。完整409示例：

```json
{
  "code": 409,
  "msg": "仍有保留共享行引用该源，删除未执行",
  "requestId": "00000000-0000-4000-8000-000000000007",
  "errorCode": "REFERENCE_EXISTS",
  "data": null,
  "fieldErrors": [],
  "retryAfterSeconds": null
}
```

## 9. 源码差异和交付证据

已读ConsumptionRule实体、ConsumptionRuleMapper.xml列表/联表/排序，结合R6已读Controller和Service。列表Mapper排序仍使用c.detect_type，selectByLabAndCard亦引用c.detect_type/#{detectType}；当前目标consumption_rule字段字典为detect_class。登记为实现修正项，不能认定数据库运行已经报错或该方法实际有调用；本轮未改SQL/Java。

旧实体Long数量/序号目标收敛为int存储范围，旧共享显示文本不能当稳定引用。当前旧写回toAjax而非本文件ID/revision回执，属于明确实现差异。图谱连接仍不可用，采用源读，不作所有调用方已覆盖声明。

本批六入口字段/样例已补齐；实际旧客户端字段适配、统一事务实现、工作簿、跨模块占用保护仍待T9/实现验证。验收需覆盖空列表、越权过滤后total、并列序号稳定分页、共享源失效、同键重放、批量删除全部引用/残留引用、旧字段注入拒绝、NA导出空单元格和中途断流。
