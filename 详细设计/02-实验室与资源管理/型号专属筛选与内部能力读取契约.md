# M02 型号专属筛选与内部能力读取契约

版本DD-20260913-T8-R10。覆盖8个型号列表的实际页面筛选和M02拥有的3个内部能力读取方法。样例为模拟数据。本文件是目标设计；未声明当前Java、Vue、SQL已完成适配。

## 1. 列表公共规则

8个GET list均沿原功能权限，Body空。pageNum默认1且≥1，pageSize仅10/20/50/100且默认10；beginDate/endDate各自可空、格式YYYY-MM-DD，按Asia/Shanghai的updateTime形成开始日含、结束日次日00:00排除条件。数组去空、去重，单数组最多50项。未知Query、实体审计字段、delFlag、iconPath、description等未列字段返回400 INPUT_INVALID。排序统一createTime DESC、业务主键DESC；空集合200。响应只使用对应Row，字段见[型号查询响应与契约样例](型号查询响应与契约样例.md)。

当前8个Controller直接接收领域实体；Mapper允许多项未审阅字段，日期只有双端齐全才生效，除分析仪外未见ORDER BY。目标实现须使用独立Query DTO并固定SQL白名单，不能把“实体能绑定”当公开契约。

## 3. 内部调用公共规则

内部调用身份来自可信会话或服务上下文，浏览器不得提交actorUserId。DeviceRef={kind:BENCH_REACTOR/INTEGRATED_REACTOR/CONTAINER/FLOOR_SCALE/DETECTOR/PERISTALTIC_PUMP/AIR_PUMP/ANALYZER/BENCH_CONTROLLER,id:string,labId:string}。requiredFields为拥有方登记的字段路径白名单，1—100项、去重；未知路径400，不允许任意反射读取实体。

只读方法不创建占用、不发送命令、不修改配置。对象不存在或对调用上下文不可见统一404 NOT_FOUND；权限不足403 PERMISSION_DENIED；事实源异常503 RESOURCE_FACTS_UNAVAILABLE。能力缺失是领域结果ready=false/issues，只有调用目的要求立即可执行时由调用方转为409 CONFIGURATION_INCOMPLETE。

## 4. resolveDeviceConfiguration

`resolveDeviceConfiguration(context, deviceRef, requiredFields, expectedManagementRevision?) -> DeviceConfigurationView`。context含可信actor、purpose:TEMPLATE_EDIT/CULTURE_PREPARE/RUN/MONITOR_POLICY、businessId可空；RUN必须有合法业务ID。expectedManagementRevision可空用于浏览，执行准备必填；版本不符409 MANAGEMENT_CONFLICT。

purpose值域按INT-10/W3补齐MONITOR_POLICY（M09-015告警监控策略保存的设备归属判决），businessId为该作用域业务键；purpose与businessId一律由服务端可信调用上下文构造，浏览器不得提交，新增消费方只扩purpose登记、不改Port物理签名与DTO。归属判决语境的调用形状（INT-10默认裁决）：requiredFields仍须1—100项且只认拥有方登记路径，消费方携带该deviceKind任一已登记最小字段路径，判决只取200/404两种结果，不得以400或响应内容表达归属差异，也不得由消费方自行登记kind到字段路径的第二套清单。

归属判决（INT-06/W2为resolveDeviceConfiguration补充）：deviceRef.labId是必验归属断言，实例必须属于labId，由提供方按M02权威实例表lab_id逐候选判决，与§5 CAP-I02同类条款口径对齐；"实例不存在"与"实例存在但不属于声明labId"统一404 NOT_FOUND且同文案，不得泄露"存在但不归属"的差异，不得改以403、400或任何其他码表达归属失败。失败码口径与INT-03 provider `M02DeviceConfigurationAdapter` 已落地行为一致：404仅归属判决、503仅事实源异常、400 INPUT_INVALID仅入参形状与未知字段路径且不得用于表达归属失败、ready/issues只表达能力缺失。归属判决不替代权限判定：调用上下文无权时仍按§3给403 PERMISSION_DENIED。

DeviceConfigurationView按PKG-00 §6.2冻结为items:[{path,value,unit|null,source:MODEL/INSTANCE/ENGINEERING}]、ready:boolean、issues:[{path,code,message}]、managementRevision:string；不固定deviceRef或modelRef回显字段（deviceRef是入参，建立来源所需ID只在items.source表达）。INT-10/W3更正：本文原表述“View固定deviceRef、modelRef”与冻结DTO不符，已按实现口径修正，归属判决不得依赖响应回显，只以200/404为判决结果。只返回requiredFields及建立来源所需ID，不返回密码、通讯秘密、其他实验室对象或占用租约。

```json
{"deviceRef":{"kind":"FLOOR_SCALE","id":"3001","labId":"2001"},"modelRef":{"kind":"FLOOR_SCALE","id":"4001"},"managementRevision":"63","values":{"range.min":"0","range.max":"200"},"units":{"range.min":"kg","range.max":"kg"},"sources":{"range.min":"MODEL","range.max":"MODEL"},"ready":true,"issues":[]}
```

上例是§4早期的目标语义样例，仅说明字段来源与单位语义；实际登记响应形状以上一段与PKG-00 §6.2的冻结DTO为准，deviceRef/modelRef不作为响应字段。

## 5. resolveIntegratedCapabilities

`resolveIntegratedCapabilities(context, labId, modelId, integratedId?, expectedManagementRevision?) -> CapabilityView`。未传integratedId只返回型号能力；传入时实例必须属于labId且引用modelId。本句是原契约中唯一的"必须属于labId"归属判决条款；INT-06已把同类归属判决推广补齐到§4 CAP-I01，两处统一404 NOT_FOUND不泄露归属差异的口径一致，签名与DTO不变。CapabilityView沿[集成反应器契约](集成反应器型号与实例参数契约.md#4-当前接口的目标补充)：modelId/modelName/spec/capacityG/pressureUnit/pumpCount/mfcCount/thresholdWeightG/temperatureControl/weightControl/pressureControl/managementRevision/ready/issues。未知历史值保持null，不能变成0/false。

```json
{"modelId":"5001","modelName":"模拟集成型号","spec":"10L","capacityG":"10000","pressureUnit":"kPa","pumpCount":4,"mfcCount":3,"thresholdWeightG":"8000","temperatureControl":true,"weightControl":true,"pressureControl":true,"managementRevision":"63","ready":true,"issues":[]}
```

## 6. resolvePumpConfiguration

`resolvePumpConfiguration(context, integratedId, expectedManagementRevision) -> PumpConfigurationView`。调用方须具备该实例对应业务上下文；服务锁定同一管理修订读取型号pumpCount与实例固定泵。返回integratedId、modelId、managementRevision、pumps:[{pumpNo:int,rangeValue:decimal-string|null,unit:"g/min",strategyId:string|null,source:"INSTANCE"}]、ready、issues。pumps按pumpNo升序，恰覆盖1..pumpCount才ready；缺号、重号、数量不符或策略不可解析进入issues，绝不补造默认泵。

```json
{"integratedId":"6001","modelId":"5001","managementRevision":"63","pumps":[{"pumpNo":1,"rangeValue":"12.50","unit":"g/min","strategyId":"PULSE","source":"INSTANCE"}],"ready":false,"issues":[{"path":"pumps","code":"COUNT_MISMATCH","message":"型号要求4路，当前仅1路"}]}
```

## 7. 一致性与验收

三个方法在一次读取中使用同一managementRevision；读到版本切换须重试快照或返回冲突，不能拼接新型号与旧实例。缓存键必须含对象、字段集合/方法和版本，权限在命中缓存前重验。M04消费能力和量程，M03在批准边界固化，M07使用固化方案并复核实时准入，M09按CAP-I01以purpose=MONITOR_POLICY做DEVICE作用域保存的归属判决（INT-10/W3：只用200/404，不消费归属回显，失败按本模块NOT_FOUND同文案透出）；M02不返回执行成功或占用状态。

验收覆盖：8类仅允许白名单Query、单边日期、稳定翻页、空数组、非法层级检测类型、未知字段；3方法的无权/不存在、版本切换、null未知、字段最小化、泵缺号/重号、依赖故障。当前源码未发现这3个目标方法；它们属于待开发契约。图谱Transport closed，本批以8个Mapper、对应页面和现有设计精确核对，不作全调用图穷尽声明。


## 8. 小试控制器运行前置读取

`resolveBenchControllerRuntime(context, labId, connectionId, expectedManagementRevision) -> BenchControllerRuntimeView` 是 M02 向 M07 的只读 Port。它从 `lab_bench_reactor_controller` 与其通道表返回控制器能力、称重设备身份及固定泵的通道、泵身份、默认/最大速度和策略；实验室归属、软删及管理修订不符失败关闭，通道缺失、泵绑定不完整或速度边界无效通过 `ready=false/issues` 表达。该Port不读取PLC当前量、不下发命令；PLC执行读数仍由M07的设备适配与执行事实负责。

展示字段 `controllerNo` 返回同一已核验控制器实例的真实编码，空白或未知为 null。它与内部身份 `connectionId` 严格区分，不能用连接主键填补编码，也不以编码判定设备执行资格。M07 小试候选的 deviceCode 消费该编码；W07 启动将其冻结到 selection_snapshot.controllerNo，并由实例详情 controllerNo 返回。旧实例无此冻结字段时返回 null，不回查当前编码覆盖历史。

W07 展示补充使用独立只读 `BenchReactorDisplayPort.read(labId, reactorId)`，仅供已通过工作流 VIEW 范围校验的受信调用方。M02 读取同实验室有效反应器及其真实设备库型号，输出 specText/iconPath/issue；品牌和类别按既有字典解析，未知数字字典键不冒充规格，缺失不推算容量或单位。该展示读取与控制器运行配置、首次计量和命令准入隔离，展示依赖失败不得阻断已有安全停止。

W07 换瓶槽位快照可含 iconUrl，来自该槽位配置的耗材图标。M02 使用已有 selectBottleSlotView 的耗材关联读取，不猜测瓶型；M07 将其冻结在 before.consumable.iconUrl，详情按原快照返回，未知为 null。当前布局图片沿既有 Slot.iconUrl 提供。

## 培养预设的当前设备型号窄读（2026-11-07）

原`CultureChangeDevicePort.readConfigModel(long labId,String deviceKind,long deviceId)`返回同Port的`ConfigModel(long labId,String deviceKind,long deviceId,String modelKind,long modelId)`，只给真实设备/型号身份，不重复完整能力、参数或执行资格。M03源应用/P02先按各自当前培养及lab资格构造服务器设备引用；M02核同lab、实际实例主键、启用/未删除及正型号。当前资格或原件不可核验不能补默认，依赖故障沿DEPENDENCY_UNAVAILABLE，不返回空型号冒成功。

BENCH_CONTROLLER只读取`lab_bench_reactor_controller.connection_id/model_id`，对应BENCH_CONTROLLER_MODEL；INTEGRATED_REACTOR读取本实例integrated_id/model_id，对应INTEGRATED_MODEL。不得用控制器所连罐体的modelId、任意同类别第一罐或数字相同的另一表身份替代。该窄读可为已纳入的CONFIG/PERFUSION培养预设提供相同基础事实，但不授权这些业务动作；完整型号存在、类型、通道和能力仍由原TemplateModelResourcePort核验。

GET不为该读构造写Guard或伪HTTP会话；P01/P02在原M03事务和SYSTEM版本下重验当前绑定，绑定与固定正文型号不符不能仅凭“旧型号仍存在”生效。历史固定包读取与当前保存资格分开：设备后来停用或改型号不删除/重建旧包，不以当前模板覆盖历史。原模式变更requireReactor用途及构造依赖保留，不将此窄读扩为通用设备授权框架。


2026-10-18 Vi-CELL字典键去重接入修正：设备型号筛选使用真实 dev_detector_model.model_id。M02-141 新增可选 modelId（正bigint十进制字符串，精确匹配），旧 detectType 协议筛选继续兼容；不把二级字典值翻译或写入 detect_type。已有 /device/devdetector/select-options 返回 id=型号主键、name=型号显示名（缺失才回落协议键）、code=检测类型，并支持 keyword 的受限远程查询。型号库筛选与实验室设备绑定筛选按 modelId 提交；二级字典仅提供业务分类/名称建议，不是协议路由标识。
