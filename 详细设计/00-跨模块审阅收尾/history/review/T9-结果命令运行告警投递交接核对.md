# T9 结果、命令、运行事实与告警投递交接核对

版本DD-20260913-T9-R3。本文冻结M05→M07、M07↔设备适配器、M07→M03/M09及M09投递四组剩余交接，并据此关闭T9静态设计核对。关闭仅表示文档中的生产与消费约束可逐字段对照，不表示Java/Vue、消息总线、数据库、设备或第三方通道已经实现和验证。

## 1. M05结果与受控更正 → M07

普通结果使用ResultSnapshot schemaVersion=1，稳定身份至少包括resultId、objectVersion、sampleId、dispatchId、occupancyGeneration、cultureId、labId、detectClass、detectType、resultStatus、resultCompleteness、deviceCompletion、collectionState、timeEvidence、collectionBasis、items、contentHash和createdAt。ResultChanged schemaVersion=1以eventId=revisionId、eventType=M05_RESULT_CHANGED、resultId、objectVersion、eventKind、sourceKind/sourceId、occurredAt及完整ResultSnapshot为载荷；消费者以(resultId,objectVersion)去重，只把更大版本推进为当前投影，审计事件全部保留。

受控更正后的有效结果必须通过resolveEffectiveResult(resultId,purpose)取得。更正应用事件外层schemaVersion=2，payload为ResultSnapshot schemaVersion=2，并在schema1叶子外增加correction={correctionId,baseObjectVersion,baseCorrectionId,baseContentHash,candidateHash,reason,evidenceRefs,changedPaths,submittedSignature,reviewedSignature,legacyEvidenceQuality}。消费方不兼容schema2时拒绝并重试，不能把更正包按schema1截断；result/objectVersion/contentHash不一致返回RESULT_PROJECTION_UNAVAILABLE，也不能回退读取旧det_result。

M07选值必须固定resultId、objectVersion、itemId、value、unit、algorithmVersion及时间/质量证据。资格判断同时校验培养身份、用途所需结果状态、未删除/未作废、item=NORMAL、数值和单位已核准、测量时间及新鲜度；PARTIAL仅在规则明确允许时使用。UNKNOWN/UNVERIFIED不得驱动物理补液。更正使缓存候选失效并按新版本重算后续决策，已经执行的物理命令、历史计算和证据不得用最新结果反向改写。

## 2. M07命令 ↔ 设备适配器

命令请求固定commandId、requestId、fence、deviceRef、operation、configRevision和CommandParameters。parameters固定schemaVersion=1、deviceRef/operation、targetGrams、speed、desiredMode、executionRef、capabilityRevision和完整resourceClaims；configRevision在回执中逐值映射为evidence.configurationRevision，不形成第二个配置版本来源。

命令生命周期仅为PREPARED、INVOKING、ACCEPTED、EXECUTED、FAILED、UNKNOWN；设备查询事实另为NOT_SENT、ACCEPTED、RUNNING、STOPPED、FAILED、UNKNOWN、NOT_FOUND。INVOKING须在网络调用前持久化并提交；ACCEPTED只表示网关受理，executedAt仍为空；NOT_FOUND只表示网关查无记录，不能证明从未物理执行。业务状态、命令状态、queryResult和结算状态分别存储，HTTP 202/错误外壳不能替代其中任何一项。

统一回执={commandId,state,evidence}；CommandEvidence schemaVersion=1固定resultCode、deviceCommandId、acceptedAt、executedAt、readings、queryResult、adapterInstanceId、configurationRevision、fence和payloadHash。commandId、deviceCommandId、配置版本、fence或hash不符的迟到证据只可隔离或补原历史，不得更新新执行。

StopEvidence不是submitCommand可写参数，而由可信适配器读数和固定MeasurementPolicy验证后生成，字段为schemaVersion、profile、stopCommandIds、actualStopReading、stableReadings、stoppedAt、postMonitorUntil、verifiedByAdapter、issues。STOP受理不等于停止执行；已确认停止也须等待稳定读数、唯一结算和停止后监控完成。UNKNOWN/NOT_FOUND先以原commandId查询并保留资源；仅经核准的幂等绝对速度/STOP可按原键重传，一次性开始或体积脉冲不得在结果未知时重发。

## 3. M07运行事实与释放证明 → M03/M09

CultureRuntimeFact schemaVersion=1完整携sourceModule、sourceEventId、sourceEventKey、streamId、streamSequence、previousEventKey、cultureId、eventType、sourceObject、expectedCultureVersion、expectedPlanVersion、occupancyId、occurredAt、对应workflow/terminal/release/deadline/resolution联合体和payloadHash。sourceEventKey由接收方按模块与源事件ID复算；同键同hash重放原结果，同键异内容冲突；序列缺口保持BLOCKED，不能按接收时间越过。

M03的接收ACK仅表示RuntimeFact已持久化为RECEIVED。只有完成来源、版本、序列、状态转换及占用校验后，才可在同事务推进培养态和应用回执。FIRST_WORKFLOW_STARTED只允许NOT_STARTED→RUNNING；TERMINAL_CONFIRMED不自动证明资源释放；RESOURCES_RELEASED必须指向当前精确occupancyId。

ReleaseProof schemaVersion=1携cultureId、occupancyId、runtimeVersion、connectionGeneration、complete、resourceSetHash、resources、unresolvedTaskIds、unresolvedCommandIds和proofHash。每项资源保留owner/fence、physicalState、leaseState、commandRefs及releaseEvidenceHash。只有资源集合完整、每项STOPPED或可信NEVER_STARTED、无未决任务/命令且owner/fence仍匹配时complete=true；租约EXPIRED、人工关闭告警、培养终态、暂停请求或STOP的ACCEPTED均不能作为释放证据。

M09只消费已经由源模块确定的事实。M07设备命令映射到M09 CommandEvidence时只导出commandId、ACCEPTED/EXECUTED/FAILED/UNKNOWN、occurredAt、source及可选measuredValue/unit；PREPARED/INVOKING属于执行器内部阶段，不伪装成告警证据。只有EXECUTED物理证据可以渲染“已停止/已断电”，UNKNOWN必须显示“结果待核实”。

## 4. 源事件 → M09告警与投递

M09 Event schemaVersion=1、canonicalVersion=1固定sourceModule、sourceEventId、sourceObject、sourceVersion、ruleKey、eventKind、conditionKey、sourceSequence、labId、cultureId、occurredAt、fact和payloadHash，sourceEventKey由服务端计算。Fact使用受控白名单，QuantityRef保留source、decimal字符串value、unit、observedAt、quality和normalizationProfile；源模块判定业务事实，M09只负责规则匹配、收件人快照和投递，未知schema或状态阻断，通知失败不回滚源业务。

DeliveryRow状态只取PENDING、SENDING、SUCCEEDED、FAILED、UNKNOWN、SKIPPED、CANCELLED，并携delivery/event/alarm身份、roundNo、channel、目标快照、内容摘要、reasonCode、attemptCount、时刻、providerRef、successMeaning、version和allowedActions。FAILED才允许以expectedVersion执行RESEND；UNKNOWN只允许RECONCILE/QUERY，不能通过新建投递绕过原身份。AttemptRow按attemptId/attemptNo保留每次开始、完成、状态和提供方摘要，不输出密钥或原协议报文。

站内消息与delivery成功在同一事务，唯一deliveryId避免重复消息。外部投递先把attempt置INVOKING并提交，事务外调用提供方，再以租约/token写结果；崩溃转UNKNOWN并查单，不持数据库事务等待网络。查单/回调证据固定schemaVersion、method=RESPONSE/CALLBACK/QUERY、provider、reference、receivedAt、signatureVerified、responseHash和source；迟到回调只能按原delivery/attempt与签名、版本匹配后单向终结，不覆盖历史失败摘要或其他尝试。

## 5. 兼容、错误与验收夹具

生产方拥有字段、枚举、错误码和schema升级；消费方不得复制同名不同语义。破坏性变化须升级schemaVersion并提供双读期，文档批次版本不等于线上schema。ID/版本按十进制字符串，小数按decimal字符串，时间按UTC ISO8601，hash按规范化载荷验证；缺键、未知枚举、单位不兼容、版本倒退和同键异hash都必须阻断或进入明确补偿态。

契约夹具至少覆盖：ResultChanged重复/倒序/异hash、schema2更正遇旧消费者、更正后旧候选、PARTIAL未授权、ACCEPTED误作EXECUTED、UNKNOWN与NOT_FOUND误重发、旧fence迟到回执、StopEvidence缺稳定读数、ReleaseProof占用已换主、RuntimeFact乱序、收件ACK误作应用、M09未知schema、UNKNOWN误开放重发、外部调用崩溃后查单、迟到回调匹配错误尝试。
