- **口径**：M06/M09 的脚本化前置**只应对 `M06*`、`M09*` 测试集断言**，不得把 `FullSystemSkeletonGateTest` 全绿列为本两模块的前置条件；门禁红项另按 m05 归属单独成批。
- **建议回填位置**：清单 §15.1 表格末补一行前置说明；统一清单 §4 P0 段补"门禁红项归属排除"一句。

### N-3 M06-007 并非"主数据零缺口"：授权面仍需 `lab_lab` + `sys_user_lab` 或超管
- **事实**：清单 §6.2 记 M06-007 "主数据零缺口（但需 §7 权限）"。本批核对清单 §6.5 与统一清单 §2.1：`purpose=POLICY` 需 **MANAGE(2)**、`purpose=FILTER` 需 **VIEW(0)**，判权经 `SmpPermissionQueryMapper.xml:29-41` 的 `sys_user_lab`（`cast(auth_type as unsigned) >= minAuthType`）**UNION** `lab_lab_leader` 全行；`SecurityUtils.isAdmin` 旁路。

### N-4 Redis 键路径缺陷是 M06/M09 HTTP 的实际前置，不是可选项
- **事实**：统一清单 §1.1 E-7 实测 `nacos-config/application-dev.yml:9-19` 为顶层 `redis:` 块，而 Java 侧 `redis.host` / `redis.port` / `@Value("${redis.*}")` / `prefix="redis"` **零消费者**，全仓 yml **无 `spring.data.redis.*`**，`RedisConfig` 直接注入自动配置的 `RedisConnectionFactory` ⇒ 连接实际落到 Boot 默认 `localhost:6379`/db0/无密码。
- **影响**：M06/M09 所有 HTTP 用例都要先取 token（统一清单 E-8：`futurefab-auth` 与 `futurefab-system` 须同时在线），而登录令牌写入依赖 Redis。**Redis 不在默认位置时，M06/M09 会在"取 token"这一步失败，失败现象与 M06/M09 本身无任何关系。**
- **口径**：把 E-7 从"待修配置"提升为 M06/M09 HTTP 的**显式前置项**（环境即本机默认，或先迁 `spring.data.redis.*` 并重启——后者属代码/配置批，本批不做）。
- **建议回填位置**：清单 §1 的 P0 闸门表增列 G-5（Redis 可达性）；或在 §16 步骤 1 显式并入。
