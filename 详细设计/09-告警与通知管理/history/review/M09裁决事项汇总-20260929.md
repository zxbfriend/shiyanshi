## 二、各事项前置缺口归纳

### 2.1 M09-019 批量已读（详见《阻塞核查》§二）

| 缺口 | 内容 | 出处 |
| --- | --- | --- |
| expectedVersion 口径 | 逐条 CAS 的 `row_version IS NULL` 是视作 0 还是视作拒绝，只存在于 JavaDoc；闭环矩阵 expectedVersion 列仍为「待登记—MISSING」，字段字典未登记空值语义。不得由实现方自行选定。 | 《阻塞核查》§2.2 |
| 命令收据落库链路 | 站内批量已读复用 `alarm_event` 做 COMMAND 收据，但 `AlarmEventMapper` 接口与 XML 均不存在；`selectNotificationsForUpdate`/`batchMarkReadByVersion` 无 statement；COMMAND 类 `payload_json` v1 模式未定义。不是"补三条 SQL"的工作量。 | 《阻塞核查》§2.3 |
| operation_code / AuditPolicy | `operation_code` 封闭枚举只含 M01 号；`ManagementOperation` 无 M09 动作、`AuditPolicyRegistry` 无 M09 策略。守卫链（`@ManagementGuardedWrite`＋`X-Management-Revision`）在扩号前无法挂载；Controller 现状符合基线、非漏写注解。 | 《阻塞核查》§2.4、§3.7 |
| INT01 身份防线 | 命令收据要求"只允许内部命令处理器创建，不可经 INT01 外部伪造 M09 身份"，而 `EventIngestionPort` 只有接口无实现，防线无处落地。 | 《阻塞核查》§2.5 |
| SELF 鉴权表达 | `SELF=AUTHENTICATED` 应表达为"已认证即可、不挂字面权限码"，避免重复 M09-018 曾把 `AUTHENTICATED` 写成字面权限码的事故。需实现前与契约负责人确认。 | 《阻塞核查》§2.6 |

### 2.2 M09-021 通知重发（详见《阻塞核查》§三）

| 缺口 | 内容 | 出处 |
| --- | --- | --- |
| 无 sender / 无投递执行器 | 全仓无邮件/短信 sender、无租约领取执行器、futurefab-job 无 alarm/delivery 类；INT03 `reconcileDelivery` 未实现；`alarm_mail_default` 邮件与 SMS 网关参数缺客户输入（BLOCKED_INPUT）。 | 《阻塞核查》§3.2 |
| attempt/lease 归属冲突 | "执行器领取时建 attempt"与"重发命令直接 `insertResendAttempt`"两套登记互不相容；人工重发时刻无 worker 租约，而 attempt `lease_token NOT NULL`。至少三种可能解，语义与审计后果不同，不得自行拼接。 | 《阻塞核查》§3.3 |
| 站内信不可重发 | 契约明确站内 delivery_id 唯一、重试不生成第二封站内信（`uk_m09_notification_delivery` 物理层落地）；"缩窄为站内信重发"方案已被排除。 | 《阻塞核查》§3.4 |
| 权限无种子 | `alarm:delivery:resend` 全仓 SQL 零命中，权限只能来自 `sys_menu` 行，除超管外恒 403 → BLOCKED_MENU。 | 《阻塞核查》§3.5；《种子核查》§三、§四 |
| FAILED 主数据缺失 | M09-CASE30 前置需"提供商明确未受理且 FAILED"的可信回执；无 sender 则不存在可信 FAILED 记录，本轮未连库核验。 | 《阻塞核查》§3.6 |
| 守卫链缺口 | 与 M09-019 同源：operation_code 未扩号前不能挂 `@ManagementGuardedWrite`。 | 《阻塞核查》§3.7 |

**关键判定（《阻塞核查》§3.2）**：在无 sender、无执行器的情况下写入 `attempt_state=INVOKING`，等于落库"调用已开始"的虚假证据，违反 `AGENTS.md` §10 与 §13.6。**不得伪造 INVOKING attempt 或发送成功结果。**

### 2.3 M09 权限种子 / 菜单安装机制（详见《种子核查》）

| 事实 | 内容 | 出处 |
| --- | --- | --- |
| 新基线要求 `sys_menu` 为空 | `03-初始化结果核验.sql:86` 把任意 `sys_menu` 行判定为 `unexpected_initial_data`；植入菜单行即官方核验报异常。 | 《种子核查》§二、§六 |
