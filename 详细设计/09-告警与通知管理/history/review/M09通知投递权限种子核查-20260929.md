## 三、结构性事实链：为什么"缺菜单行"就是硬阻断

权限串不是配置项，只能来自 `sys_menu` 行，链路全部为真实实现（非 501 骨架）：

1. `SysMenuMapper.xml:106-112` `selectMenuPermsByUserId`：`select distinct m.perms from sys_menu m left join sys_role_menu rm … left join sys_user_role ur … where m.status='0' and r.status='0'`
2. `SysPermissionServiceImpl.java:92`：`perms.addAll(menuService.selectMenuPermsByUserId(user.getUserId()))`（经 `SysMenuServiceImpl.java:105-107` 转调）
3. 导航链：`SysMenuController.java:214-218` `GET /getRouters` → `SecurityContextApplicationServiceImpl.java:61-63` `currentRoutes` → `buildMenus(selectMenuTreeByUserId(...))` → `SysMenuMapper.xml:77-79`（同样读 `sys_menu` 并 join `sys_role_menu`）
4. 前端 `sdk-smp-api/src/index.ts:90` 调 `/system/menu/getRouters`，`sdk-smp-stores/src/index.ts:74,81` `buildEntries(...)`
5. 门禁两处落点（都只认 `sys_menu` 来源的权限集合）：
   - 注解式：`AlarmDeliveryV2Controller.java:44` `@RequiresPermissions("alarm:delivery:resend")`
   - 服务内式：`AlarmNotificationApplicationApplicationServiceImpl.java:126` `AuthUtil.hasPermi(PERMISSION_NOTIFICATION_LIST)`（M09-017 ADMIN 支）、`:148` `AuthUtil.hasPermi(PERMISSION_NOTIFICATION_EDIT)`（行内 READ 动作）
   - 注意：V2 通知控制器**没有** `@RequiresPermissions` 注解，`SELF/ADMIN` 语义以注释登记（`AlarmNotificationV2Controller.java:33,48`）并在服务内判定；旧入口 `SysNotificationController.java:45,57,70,80` 才用注解式

**推论**：`alarm:delivery:resend` 若没有 `sys_menu` 行，就没有任何角色能获得它，接口在任何环境下恒为 403；`smp:notification:list/edit` 同理——即使只作服务内判定，`AuthUtil.hasPermi` 读的仍是同一份来自 `sys_menu` 的权限集合。页面若没有 C 型菜单行就不进 `entries`，用户看不到入口。这正是 `BLOCKED_MENU` 的准确含义，与 M09-021 的其余阻塞相互独立。

## 六、为什么本轮不写 SQL

1. **与官方核验直接冲突**：`03-初始化结果核验.sql:86` 把"存在任意 `sys_menu` 行"判定为 `unexpected_initial_data`。在新基线语义下菜单**不是初始化数据**（`来源清单.json:752-756` 的 `seedTables` 不含 `sys_menu`）。要让种子合法，必须同时改 02、03 与来源清单三处并重新核准基线——这超出本任务授权（用户约束"不修改正式基线 SQL"）。
2. **主键不可猜**：设计两处明令（`详细设计.md:1271`、`:1285`）。可执行 INSERT 必须给 `menu_id`，而雪花 ID 由 M01 创建流程赋值。写死 ID 即违反权威设计；用占位变量则不可执行，等于没交付。
3. **父链不存在，挂点无处可引**：M09 页面所需的 C 型父菜单在新空库里一行都没有；`README.md:28` 又禁止"整批导入旧菜单"作为替代。种子只能是**一组有序依赖**（根目录 → 页面 → 按钮），必须先有部署核准的菜单树。
4. **被指定的核准入口尚未产出**：`页面与接口契约.md:150` 要求"其他目标动作权限以**M01菜单登记表**核准"，而全仓检索该表不存在。绕过它自行定权限归属，正是 §150 与 `详细设计.md:1285` 所禁止的"依赖前端按钮或角色名称"式做法。

因此本轮交付严格止于差异表＋裁决问题清单。
