# M09 物理接口与骨架字段设计

版本：DD-20260918-PHY-01。本文是 M09 目标 HTTP 接口的物理类名、方法名、DTO/VO、功能权限和 Mapper 适用性权威。业务字段、状态、事务与错误仍分别以《页面与接口契约》《Controller请求调用时序设计》《数据库JSON与事务契约》《错误码全集》为准；本文不表示代码已实现。

## 1. 包与兼容边界

- canonical `/alarm/v2/**` Controller 使用下表 `*V2Controller`，避免与现有旧路径 Controller 的类级 `@RequestMapping` 冲突。
- 旧 Controller 仅作 COMPAT 协议适配，必须调用同一个 `I*ApplicationService`；不得继续持有第二套业务事务或直接复用 Entity 作为 canonical 入参。
- 应用端口位于 `com.futurefab.system.service`，实现位于 `com.futurefab.system.service.impl`；DTO/VO分别位于 `com.futurefab.system.domain.dto.alarm`、`com.futurefab.system.domain.vo.alarm`。
- Controller 只完成协议、ActorContext、校验注解和 DTO 映射，不直连 Mapper、跨模块 Service 或设备适配器。
- `AUTHENTICATED`表示只要求有效会话并继续执行对象范围校验，不生成虚构的菜单权限码；复合权限按请求中的 `context` 和通道在服务端再次判定。

## 3. DTO/VO 组合约束

2026-11-07 G07设计修正：API08的`AlarmStatusConfigQuery`目标字段为labId/tab/unitCode/必要rowNo/liquidType；unitCode沿M02原≤50部署编号，rowNo沿原正整数布局行。旧unitId如保留在Query中仅用于明确拒绝非空输入，不再参与业务查询，按既有INPUT_INVALID提示刷新；不能通过删除DTO字段使未知参数被静默忽略。`UnitOption`目标为unitCode/rowNo/label，`StatusRow`单元投影为unitCode/rowNo，原真实bottleId保留，unitId不再作为单元响应字段。Controller/原应用/Mapper/原SDK和真实lab-statusalarm页同批迁移；此处只改设计，未据此修改源码或宣称验收。

- Path、Query、Body在Controller层组合成上表单一 Request DTO；所有写Command包含公共`requestId`，版本字段按页面契约必填，不接受Entity、Map或Object。
- `AlarmHandleResult={mutation:MutationResult,current:AlarmRow}`；`BatchMutationResult={requestId,results:[MutationResult]}`。
- `AlarmStatusConfigView`、`AlarmOnlineConfigView`、`AlarmOfflineConfigView`分别包装契约中的`ConfigSet(StatusRow|OnlineRow|OfflineRow)`，状态配置额外包含`filterOptions`。
- `NotificationPageView`固定包含`context`、`channel`、分页元数据以及二选一的`notificationRows`或`deliveryRows`；禁止Java联合类型或混装两类行。
- `AlarmDeliveryDetailView={delivery:DeliveryRow,attempts:[AttemptRow],content?}`；`AlarmDeliveryResendResult={mutation:MutationResult,delivery:DeliveryRow}`。
- API18 的`NotificationUnreadCountView={count:int,display:string}`；API19 的`NotificationBatchReadResult={requestId,results:[NotificationReadResult]}`。

## 5. 生成门禁

1. 21个canonical接口各生成一个Controller方法和一个应用端口方法；旧COMPAT方法不生成第二应用端口。
2. 新增权限码必须进入M01菜单/权限初始化开发包及首管理员安全初始化，不写入基础DDL固定种子。
3. 所有Mapper statement ID与接口方法同名；骨架阶段可抛统一开发态`NOT_IMPLEMENTED`，但XML不得用假SQL返回空成功。
4. API16不得生成Mapper；其他20个接口缺任一登记Mapper方法时，M09骨架检查失败。
5. 禁止保留`TBD-MISSING`、未解释`null`、Entity/Map/Object入参或旧畸形权限字符串。
