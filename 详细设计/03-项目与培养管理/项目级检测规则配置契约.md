# 项目级检测规则配置

2026-10-23 用户确认：原型 `①③④⑤批次管理.html` u2090 的中试下游检测规则本次补齐项目级配置；小试专用反应器容量暂缓。本文件落实原型中“带出当前实验室检测规则、按项目修改、保存项目”，不重算历史检测结果。

## 范围和权限

配置按 `(projectId, labId)` 隔离；lab 必须是项目参与的真实中试下游实验室（labType=4）。未创建项目不能写配置，不为表单草稿分配虚拟项目身份。未保存项目覆盖时只读 M02 当前真实六项默认，不插入、不生成阈值；已保存覆盖始终读取项目值，不随实验室默认变化自动覆盖。

读要求 `resource:project:query`、项目普通可见范围、实验室查看权限。写要求 `resource:project:edit`、Q05 项目可信创建人或当前项目负责人、实验室操作权限及项目参与实验室关系；SHARE 不取得该写权。所有校验在写事务内重判。不存在、删除或读范围外统一404；不合格实验室及关系同样拒绝。

## 接口

| 编号 | 方法与地址 | 输入 | 输出 |
| --- | --- | --- | --- |
| M03-046 | GET `/resource/project/{projectId}/detection-rule` | Query `labId` | `data={projectId,labId,projectVersion,source:LAB_DEFAULT/PROJECT,items:[{ruleItem,operator,value}]}`；顶层 `managementRevision` 来自本读口 |
| M03-047 | PUT 同地址 | Query `labId`；Body `{expectedProjectVersion,items}`；Header `X-Request-Id`、`X-Management-Revision` | `MutationResult`，objectId=projectId，objectVersion=保存后的项目版本；管理版本沿统一外壳 |

规则项固定为 M02 已有六项：`density-difference`、`photometer-time`、`photometer-rds`、`photometer-blank-concentration`、`solovpe-rds`、`solovpe-r2`。运算符和数值符号、精度、上限完全复用 M02 已有规则策略。请求须精确包含六项各一次，服务端按固定顺序归一化。未配置项允许 `(operator=null,value=null)` 成对保留；不允许只填一半。值按 decimal-string 传输，不截断、不四舍五入，不生成缺省阈值。

首次保存与后续覆盖均同一 SYSTEM 守卫事务：重读并锁定项目 → 权限/参与关系/lab 类型 → expectedProjectVersion → 验证六项 → 项目 object_version CAS+1 → upsert项目覆盖 → 同事务前后审计及幂等回执。保存与项目基础编辑共享项目版本，任一冲突整次拒绝；读取不顶版本。未知结果必须沿用原次身份、requestId、管理版本及完整载荷确认；明确冲突刷新后让用户核对，不自动换键重发。

## 持久化与审计

表定义见 [PD-01](PD-01-项目检测规则表结构.sql)，字段见 [数据库表结构与字段字典](数据库表结构与字段字典.md)。唯一写拥有方 M03，M02仅经新增Port提供真实默认及无写入的规则校验；不向实验室规则写口提交项目编辑。

审计操作 `M03-047`，对象为项目，前后字段为 `project_id`、`lab_id`、`items_json`、`updated_project_version`。首次覆盖前像 items_json=null；后像是本次实际落库内容及更新后项目版本。配置JSON不接受客户端审计列或其他业务字段。

默认与覆盖是配置来源，不代表已对检测结果应用；本次不修改 M05 既有结果、设备型号规则或历史签批事实。新表只创建结构，不从实验室批量回填、不引入默认项目配置。现有开发库仅执行 PD-01 中这一张新表的 CREATE，经确认目标后由主代理执行；禁止重跑空库安装链。
