## 3. work4 复核新增的三条硬证据

### 3.1 M03-044 与 M03-029 在 `/resource/project/*` 上无常规可行解

- 两条路由：`ResProjectController` 类级 `@RequestMapping("/resource/project")`(:52) + `@PostMapping("/{projectId}/exit")`(:187)；
  `ResGrantController` 类级 `@RequestMapping("/resource")`(:29) + `@PostMapping("/{type}/{id}/exit")`(:73)。
  `type=project` 时匹配同一 URL，字面段更多者优先命中 **044**。
- 两种"常规处置"各自失败：
  1. **保留 044 映射并置 `disabled`（返回 400）**：canonical 退出写口在 `type=project` 上被永久遮蔽，
     前端切 `/resource/project/{id}/exit` 拿到的是 400，M03-029 对该类型不可达。
  2. **摘除 044 映射、条目保留 `disabled`**：`SkeletonEngine.checkHttp501`(:511-517) 会向 `/resource/project/1/exit`
     发 POST 并断言 400 外壳；摘映射后该 URL 由已 wired 的 029 命中并返回 canonical 结果 → 断言必红。
- 因此 044 的翻面**必须前置一条路径裁决**（真翻面保映射 vs 摘映射并连带条目/计数联动），
  不能按"照 039~043 同样处理"直接推进。此为 P0 项，见 §5 R1/R2。

### 3.2 M05 已预演 Guard 翻面后的"501 抛出数 0 != 方法数"门禁后果

- `checkImplThrows501`(`SkeletonEngine.java:337-408`) 只豁免 `wired`，对 `disabled` 条目仍逐方法
  `assertThrows(SkeletonNotImplementedException.class)`。
- 取证：`LegacyDetectionEndpointGuardImpl.java`（M05）**12 个 `DisabledEndpointResult` 方法、编号 501 抛出点 0 个**；
  `LegacyResourceEndpointGuardImpl.java`（M03）6 方法 / 6 抛出点。
- 含义：M05 若把这些守卫条目由 `wired=true` 迁为 `disabled=true`，门禁会当场对 12 个方法全部报"501 抛出数 0 != 方法数"。
  这正是 M05 至今仍把停用形状登记为 `wired=true`+Guard 的原因，也是 M03 包5 **不能沿用该形状**的原因：
  翻面必须先给 `disabled` 一条合法的 Impl 判定分支，否则首个翻面即拖红，并把 M05 的登记口径矛盾暴露成门禁红。

### 3.3 Controller 注入字段与冻结 `svcFq` 不匹配会导致反射注入失败/NPE

- `checkHttp501` 的注入逻辑（:455-484）只把 Impl 塞进**字段类型全名等于 `e.svcFq`** 的 Controller 字段；
  `checkWiring`(:292-306) 对非 `wired`/非 `legacy`（即 `disabled`）条目仍强制要求 Controller 持有 `svcFq` 类型字段。
- 取证：`ResProjectController`/`ResBatchController`/`ResCultureController` 中
  `LegacyResourceEndpointGuard` 注入命中数均为 **0**。
- 含义：翻面提交若只改方法体去调守卫、或改 `svcFq` 而不补注入字段，standalone MockMvc 里该字段为 null，
  请求触发 NPE → 被泛化 500 吞掉，disabled 分支的 400 断言直接失败，且失败表象会被误读为"错误码配错"。
  **补守卫字段注入是翻面的硬前置，不是可选清理。**

## 4. 对方案原文的更正项

- **更正**：`SkeletonEngine.checkHttp501` 的 D3 停用态断言**已经完整覆盖** `HTTP 400` +
  `$.errorCode=PROTOCOL_UPGRADE_REQUIRED` + `$.contractId=<编号>`（`SkeletonEngine.java:511-517`）。
  方案原文把"判定器侧需要新增断言"列为缺口的表述**作废**。
- **真实缺口在生产侧**：全仓 `src/main` 不存在任何产出"400 + errorCode + contractId"停用外壳的路径——
  `GlobalExceptionHandler:177-186` 只为 `SkeletonNotImplementedException` 挂 `contractId`；
  `ManagementGuardExceptionHandler` 有 `errorCode` 但**不挂 `contractId`**，且 M05 侧走的是 409 语义。
- **判定器侧仍需要补的只有一处**（非断言，而是豁免分支）：`checkImplThrows501` 缺 `disabled` 分支（见 §3.2），
  否则翻面即红。
- **落地时须复核的一条实现细节**（不改变上述结论）：`checkHttp501` 的 standalone advice 集合当前只注册
  `GlobalExceptionHandler`（:486-488）。新停用异常若由该 handler 承接则测试侧零改动；
  若另起 `@RestControllerAdvice`，则需同步纳入该 advice，属 R2 实现细节，须以实际跑绿为证据，不得先宣称通过。
