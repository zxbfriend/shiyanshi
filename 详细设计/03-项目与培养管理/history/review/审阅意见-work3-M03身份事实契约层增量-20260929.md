## 5. 未来 DB 接线字段缺口（焦点 10）

依据 `docs/开发基线/01-完整建表.sql`：

1. **身份事实核准标志缺失**：`res_project` / `res_batch` / `res_culture` 均有 `facts_status`（READY/REVIEW，CHECK 约束），三张成员/分享表均有 `grant_type IN (MEMBER,SHARE,LEGACY)` 且默认 LEGACY。设计 §1 要求"REVIEW/LEGACY/未知身份不能被当成普通成员或负责人；未知来源导致必要事实不可得时返回 UNAVAILABLE"。
   Snapshot 只有 `bindingVerified`，**没有 `identityFactsApproved` / `legacyGrantPresent`** → 实现期只能静默忽略或误判 DENY。
2. **受保护全局实验室来源无承载**：设计 §4.1 明文"受保护全局实验室来源必须显式表达，不能复用 null 哨兵"，`MatchedSourceKind.PROTECTED_LAB_ADMIN` 已定义但 Snapshot 无对应字段、Policy 从不产出。
3. **view / operable / manage 包含不变量未定义**：`evaluateHistoryRecord` 只认 `viewLabIds`，`resolveReviewIdentityFacts` 认 `view ∪ operable ∪ manage`；DB 加载若不保证 `operable/manage ⊆ view`，Q02 用户可审核却读不到。需在 Snapshot javadoc 写死不变量并补测试。
4. **实验室启用态**：§3.2 `LabAccess.labExists/labEnabled` 无承载字段（禁用实验室不得靠过滤假装无历史授权）。
5. **绑定解析链**：`det_result` 无 lab_id / project_id / batch_id / culture_id 列（仅 `sample_id`、`detector_id`），M05 须经 sample/dispatch 链解析 `HistoryBinding`；建议补 `bindingSource` 字段或写明"解析不可得 → UNAVAILABLE"。

## 6. 已核验通过项（正面结论）

- 未越权写 M05 放行逻辑：Port / `ReviewIdentityFacts` / `ReviewIdentityBasis` / `MatchedSourceKind` 四处 javadoc 均声明"M03 只给身份因子，最终 ALLOW 由 M05 合并 M01 功能码 ∧ 状态机 ∧ 签审分离"；`collectApprovalSources` 排除 SHARE / ROLE_VIEW_SCOPE / APPROVAL_ASSIGNEE。
- 身份只认稳定 userId：`projectCreatorUserId(Long).equals(actorUserId)`，全链路无 username 字段或字符串比较。
- 失败关闭主干成立：`FACTS_UNAVAILABLE`（q/s/labId/binding 缺失或未核验）与 `LAB_AUTHORIZATION_UNAVAILABLE`（实验室来源不可得）齐全，且与 `FutureFabErrorCode` 的 503/404 名称对齐。
- 伪造父 ID：`mismatch()` 对四个 claimed*Id 校验，一律以 `HistoryBinding` 为权威。
- 期限含当日（C07）：`isUnexpired` 正确，且有"截止当日仍有效 / 次日失效"边界用例。
- 历史只读 = 覆盖来源 ∧ 最终记录实验室 VIEW（`evaluateHistoryRecord`）：有权源但记录实验室不可见 → DENY 且 `matchedSources` 非空，未回退全放行、未返空冒充无数据。
- 新增 Port 为 interface-only：全仓无 `implements MemberIdentityFactsPort`，未改动既有 `SmpPermissionService` / visible / history SQL 语义。
- 枚举 parity 单向对齐：`ProjectSelectorPurpose` 三个取值在 `IdentityPurpose` 均有同名取值。
- 15 个用例实测全通过（`Tests run: 15, Failures: 0, Errors: 0`）。
