# 观测时培养关联与历史修订契约
版本 DD-20260917-OBS；2026-10-14 普通关联源码切片见下文，不代表全部历史核准与事件生产者已实现。M03是培养关系唯一权威，M02仅保存解析结果证据；统计延期不影响该服务。新增2表23列见[增量DDL](OBS-02-业务观测增量建表.sql)，实际新系统安装只用开发基线入口，不重复执行设计来源DDL。

## 1. 为什么不直接复用占用表
res_culture_occupancy保留acquired_at/released_at、设备身份、占用版本和释放证据，应继续复用为占用依据。但预约取得时间不是测点实际绑定时刻，且不能表达一个控制器多个通道的物理容器历史。现有lab_bench_reactor_controller_channel是泵连接通道，也不能直接充当全部在线指标通道映射。

新增res_observation_binding_revision按(deviceKind,deviceId,channelCode,revisionNo)保存完整关系修订；res_observation_binding_interval结构化保存该修订的全部可信区间。它们不是第二个预约锁，不改变占用/释放规则。revision行本身为不可变修订证据及幂等回执，不额外复用仅面向N标记/延期的notice_outbox发送未知事件。

区间[startAt,endAt)。MATCHED须有culture/project/batch/lab、准确occupancyId及核准配置版本；UNASSOCIATED须有当时空闲证据，不是“查不到培养”的别名。没有可信区间表示UNKNOWN。公共测点没有培养范围时不能复制到所有培养；只能在已核准DEVICE级测量范围内读取，不虚构匹配。

## 2. 发布及并发事务

### 2026-10-14 普通关联自动发布

用户确认：普通设备关联、换设备与解除关联随真实业务维护，不增加普通用户的证据登记操作；人工历史纠正仍须受控核准。发布来源不能仅凭 RESERVED 推断任意测点。

本次源码支持有明确连接与已核准通道的普通业务切片：M03-011 随批创建培养、019/020 基础修改、022 删除、023 撤回、024 重约在原守卫事务内同步发布。M02 拥有配置只读口 BIND-C01，当前从集成反应器 floor_scale_id（罐重秤，不是 feed_scale_id）与同实验室地秤及已核准 lab_observation_mapping 取得通道；共享秤、多义核准、缺项或提供方故障失败关闭。其他种类没有冻结的明确测点连接，保留 UNKNOWN，不按设备名/全部控制器通道猜测，不代表设备空闲。

新 MATCHED 只来自本次业务实际创建的占用及明确测点配置，起点不早于占用取得与配置核准生效时刻；不能在后来编辑中反填此前未知区间。解除以持久 released_at 关闭旧区间，未核准的空档不补 UNASSOCIATED。旧修订完整复制到新修订，历史实验室等叶子保留原值，不用当前培养归属重写。运行变更审批回投、结束培养的后续事件生产者以及其他种类测点仍需独立接入，不能把本次切片声称为所有事件已覆盖。

内部请求键为 UTF-8 SHA-256(`BIND-BUSINESS-V1\n`＋守卫操作者ID＋`\n`＋原业务 requestId＋`\n`＋测点规范流键) 的64位小写hex；同操作者/原业务/测点唯一，不跨通道或跨操作者复用。request_hash 为 canonicalVersion=1 的完整发布请求规范 JSON UTF-8 SHA-256 原始32字节；键序使用已有 canonicalJson，ID十进制字符串、时刻UTC且最多微秒、空终点显式null、区间顺序不可变，不使用HMAC代替固定内容摘要。M02绑定配置指纹为 M02BIND1:＋罐重秤及完整核准映射ID/版本集合的SHA-256，不冒充设备报文 configurationRevision。

发布只接受所属 M03 守卫真实业务生成的命令，不开放任意客户端区间写入；自动领域事务 approved_by 按现行DDL为NULL，操作者由原业务审计记录。人工历史纠正不得借此分支免核准，本次没有新增核准表或普通用户历史编辑接口。所有区间写入与原业务同生共死；首版本、修订版本和请求键继续依赖已有唯一键兜底，旧修订不更新。

普通自动发布的开放区间在读取时重新核验当前培养占用与 M02 核准配置指纹。连接移走、占用释放或配置版本改变而没有可信后续事件时返回 UNKNOWN，不沿用旧 MATCHED；已关闭区间仍按原历史依据解析迟到报文。该校验不能代替配置变更事件生产者，也不补造失效期间的历史区间。

以上是实现范围与判据，不代表已有主数据、目标库SQL执行、HTTP、设备或部署验收证据。真实 MySQL 一致性读视图、跨模块配置变更并发与锁范围尚未验证；不能从替身事务测试推导这些运行期保证。

### 发布契约
内部BIND-I01 publishBindingRevision输入：
{requestId≤64,expectedRevisionNo:string(首次0),deviceKind≤40,deviceId,channelCode≤64,reason≤500,evidenceRef≤500,intervals:[{validFrom,validTo:null|ISO,state:MATCHED/UNASSOCIATED,cultureId?,projectId?,batchId?,labId,occupancyId?,configurationRevision≤100,evidenceRef≤500}]}。
操作者、来源M03业务事务、核准时刻由服务端取得；核准用户不能来自请求体。输出{revisionId,revisionNo,duplicate,intervalIds[]}。限制最多10000区间/请求，超限改为受控批次同事务发布；分批中间结果不能作为最新修订可见。

事务先按requestId查幂等：同hash原回执，异hash409 REQUEST_ID_CONFLICT；检查expectedRevisionNo等于当前最大已提交版本。锁当前修订行，追加revisionNo+1及完整区间，唯一版本键兜底并发；首版本也靠唯一键竞争，败者回409 VERSION_CONFLICT。提交前验证：
- 原培养/批次/项目/实验室关系、占用凭据、M02通道/配置版本均可核验；服务不可用返回503，不默认为空闲。
- 每段起点<终点，按起点排序，任何重叠拒绝409 BINDING_OVERLAP；同边界A结束=B开始合法。开放尾段只能最后一段；缺口保留未知，不补空闲。
- 包含当前修订所有需保留的可信历史；历史纠正须明确reason/evidence及具有受控核准资格，不能按现绑定覆盖旧关系。
- 在培养绑定/更换设备的所属M03事务内发布新的关系快照；同库同事务提交业务绑定与本修订。跨服务M02的设备配置先完成可信核准，失败不开放映射；不能在M02表上跨模块直接写入。
- 禁止把所有RESERVED直接当作物理测点绑定。按已确认业务绑定事件生效时间建立区间，外部实物关系未知先不发布MATCHED。

新修订不是修改旧行：关闭原开放区间在新修订副本内完成，旧修订保持当时依据。历史纠正不自动触发培养状态/任务重算，不得通过该内部服务重绑实际设备。普通用户没有任意历史关系编辑HTTP；运行绑定由原业务变更流程调用，历史核准由受控迁移/维护程序调用并审计。

## 3. 按时刻解析与查询
BIND-I02 resolveAt({deviceKind,deviceId,channelCode,observedAt,requiredRevisionId?})：
{state:MATCHED/UNASSOCIATED/UNKNOWN/AMBIGUOUS,revisionId?,revisionNo?,intervalId?,cultureId?,projectId?,batchId?,labId?,occupancyId?,configurationRevision?,reasonCode?,candidateIntervalIds:[]}。
无requiredRevisionId时读取同一一致快照里的最新已提交完整修订，再取命中区间；不得跨修订混合匹配。指定修订必须属于同设备通道，否则400。零命中UNKNOWN；一条UNASSOCIATED才为空闲；异常多命中返回AMBIGUOUS并告警，不LIMIT 1掩盖坏数据。RPC不可用由调用方保存UNKNOWN并补偿，不能因关联不可用丢弃原始观测。

BIND-I03 listRevisions({deviceRef,channelCode,afterRevisionNo,limit≤500}) → {rows:[{revisionId,revisionNo,createdAt,reason}],nextRevisionNo,hasMore}。M02按每个设备通道的已消费修订号持续拉取，初始没有关联的观测也周期重试；不以全库最大雪花ID作为提交高水位，不依赖M08消息消费者。修订后的关联扫描需覆盖旧、新区间并比较来源修订，不能仅扫描今天。

三个内部接口只对M02/M07等指定可信服务开放，凭据约束设备范围、调用用途。服务间解析结果不是浏览器读权限。历史展示可复用原培养详情历史组件，增加目标 BIND-Q01 GET /resource/culture/{cultureId}/observation-bindings：
请求 from/to、cursor、limit≤500；响应{rows:[{deviceKind,deviceId,channelCode,revisionId,revisionNo,validFrom,validTo,state,labId,configurationRevision}],nextCursor}。使用M03现有resource:culture:query及当前/历史数据权限；跨培养记录不得泄露，raw evidenceRef不输出。内部源ID由服务复核，不允许客户端传labId覆盖。

## 4. 典型边界及验收
10:00 A→B，09:59:59观测即使10:05收到仍归A，10:00整归B。10:00以前关系缺证据，不能用B填满历史；设备搬到另一实验室后，旧区间labId不变。培养改名或逻辑删除不删除历史，不用当前名称覆盖来源身份。

必须验证：同版本并发只成功一次；同requestId重放；同键异hash；区间交界；重叠拒绝；空档UNKNOWN；显式空闲；多通道不串；RPC断线补偿；历史修正保留原依据；新实验室/新项目权限不能继承旧历史；M08全停依旧可解析。DDL及运行验证状态见[联合交付核对](../history/review/00-业务观测独立交付与迁移核对.md)。

接口索引见[模块目录](接口目录与契约定位.md)，错误及重试见[错误码全集](错误码全集.md)。内部BIND凭据不会转化为浏览器查询资格。
