## 候选与接口

新增 res_culture_change_candidate。持久化申请人、原请求键/摘要、cultureId、expectedTargetVersion、场景、before/after、candidateHash、政策证据、原因、审批关联和最终回执。同培养一个 PREPARED/PENDING/UNKNOWN 候选；冲突不覆盖旧候选。

| 拥有方内部方法 | 输入 | 结果与校验 |
| --- | --- | --- |
| prepareCultureChange | actorUserId、requestId、cultureId、expectedTargetVersion、sceneCode、changes、reason | candidateId、candidateHash、before/after、ownerReadiness；读取真实所属，拒绝越权与未知字段 |
| attachApproval | candidateId、candidateHash、approvalId、固定 policyEvidence | 原子绑定；重复相同返回已有，不可换审批单 |
| applyCultureChange | candidateId、candidateHash、approvalId、decisionVersion、decisionKey、decisionHash | APPLIED/CONFLICT/UNKNOWN 或持久封禁回执；重试先查原回执 |
| queryCultureChange | 原候选与原决定身份 | 原回执或可验证 NOT_APPLIED/UNKNOWN；查询不写业务字段 |
| sealCultureChange | 原身份、reconciliationId、双人核准摘要 | 同拥有方事务检查并永久封禁；已经 APPLIED 时仅返回原 APPLIED |

所有 JSON schemaVersion=1、ID/版本为字符串、时间 UTC 毫秒 Z；hash 沿公共规范化规则。before/after 只含 cultureId、cultureCode、start/end 计划日期、cultureMode、deviceKind/deviceId 及有关对象版本；changes 为场景白名单，禁止接收完整培养对象覆盖。

SC027 只改编号并复用现行编号声明/可复用规则；SC028 只改已有契约允许的计划日期，校验起止关系与培养状态，不改历史实际发生时刻；SC029 只允许已确认的普通培养转反应器模式，复用设备可用性与占用规则，不增加反向转换。M03_DEVICE_CHANGE 是内部已有更换操作的交接类型，不凭空加入 M06 第48场景，其审批政策仍取该原业务操作的已确认映射。

## 原子生效与设备交接

沿 M01 SYSTEM→实验室→M03 培养/编号/占用/方案守卫→M07 培养运行守卫→相关设备资源（稳定键排序）→候选/审批交付的既有顺序；不得 RPC 持锁。拥有方与 M07 当前同库集成必须加入同一事务。拆服务后必须先实现带版本的 prepare/commit 屏障，未实现不得启用设备更换入口。

先核验原决定与永久封禁，再重验期望版本、状态、权限、目标编号/设备。设备更换发现 EXECUTING、PAUSED、已发送但未知命令、未结算物理事实时阻断；不能取消数据库任务来证明设备停止。锁住相关运行状态后，原子更新培养/占用、使旧未执行计划候选失效、更新未来生成依据并写可靠事件，保留旧任务历史与已占用规则日额度。本轮D0修正按[运行变更契约](培养运行变更页面与接口契约.md)第3节保留方案参数、取消方案来源未执行任务并新生成，人工日历任务保留；旧原任务改时间路径已由Q-3-02替代；历史真实执行不改；模式变更不能绕过 M02 生效配置。

M09 收到带 eventId、cultureId、旧/新设备及版本、changedFields、occurredAt 的事件后停止旧设备绑定配置的后续评价，保留旧告警、原收件人和历史配置；新配置仍须独立就绪。M06 已提交候选按固定基础版本判 CONFLICT，不能迁移到新设备自动生效。事件乱序按版本水位拒绝回退。

DIRECT/DIRECT_REASON 与审批使用同一候选及生效方法，前者固定政策版本，后者非空原因；两者不创建虚假 apr_request。APPLIED/永久封禁的回执必须与业务变更同事务持久化。永久封禁后迟到 apply 一律返回已封禁，不能重新进入待审；归档后同样生效。

## 2026-10-24 补液方案签审的拥有方预检

M06 签审通过前消费 `ApprovalOwnerPrecheckPort` 的 M03 实现 `M03ApprovalOwnerPrecheckAdapter`。输入是审批单冻结的原审批、场景、目标、候选版本/摘要、培养祖先、原请求及变更快照；不是直接传递 M06 私有表行。预检不生效参数包、不生成任务、不改审批单，也不授予物理执行资格。

- `precheck(Query)` 仅查询；`lockAndPrecheck(Query)` 必须加入已有真实签审事务，调用方先持有 SYSTEM、M02 实验室、M06 政策根，再由 M03 锁培养及参数槽，最后才锁审批单。锁后审批单身份必须仍与原 Query 一致。
- 核对当前培养未删除及允许生命周期、实验室/项目/批次、对象及日期计划版本、设备身份；日期计划版本 0 保留其正式“尚无计划”语义，不擅自改成 1。
- FEEDING 候选重验不可变信封、候选 hash、原请求、固定培养版本、原计划版本、当前槽候选/审批指针、槽版本与旧生效快照。槽位保留的历史 `decision_key/application_receipt` 不冒充当前候选已处理，也不因为存在历史记录拒绝合法新候选。
- `M06_SC019` 仅 INIT，原候选及当前槽均不得已有生效快照。`M06_SC048` 仅 MODIFY，必须有原生效快照，冻结影响必须为 `REPLACE_PLAN_CANCEL_UNSTARTED`，精确锚定原快照并同时列出 FEEDING/SUGAR。其他参数页面不因该端口存在而开放。
- SC027—SC030 沿既有培养变更候选核原审批绑定、场景、版本、hash、当前状态和原请求；最终动作仍交原拥有方生效服务完整复验，不直接调用数据库更新绕过业务条件。

`ApprovalCultureSourcePort` 是 M03 仅供上述预检核当前祖先的窄读/锁读口：M07 通过它获取当前培养来源，不注入 M03 Mapper。它不判审批人资格；真实成员、账号启用、阶段权限、OPERATE 和职责分离仍由 M06 正式资格链处理。任何拥有方事实缺失或冲突均阻断签审；不可用不得当成通过。

实现验证：拥有方行为测试及精确 Mapper 边界门禁分开记录；它们不是 M06 HTTP、浏览器或真实设备验收。
