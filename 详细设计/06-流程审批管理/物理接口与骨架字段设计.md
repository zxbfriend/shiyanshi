# M06 物理接口与骨架字段设计

版本：DD-20260918-PHY-01。本文先冻结M06物理字段的收口规则，不表示15个HTTP接口已逐项完成。

- 审批、政策、对账和审计Controller按现有冻结类名分文件；每个入口唯一对应ApplicationService及实现方法。
- 原契约中带字段说明的`TARGET:`类型收敛为纯Java类型名，字段说明继续由详细设计、时序和notes约束。
- 访问M06政策、审批、决定投递或对账表的接口为`REQUIRED`；纯跨模块查询才可`NOT_APPLICABLE`。Mapper写不越过M06表拥有权。
- 所有Request/Response、Mapper适用性及XML statement必须显式登记；未实现代码只能返回统一`NOT_IMPLEMENTED`，不得返回空成功。
- 逐接口最终物理值以开发任务清单M06段及JSON为机器权威。

## 2. Mapper补充

15条均访问M06本地`apr_*`事实，Mapper适用性全部为`REQUIRED`。原表中单Mapper原名保持不变，以下三条多表写冻结为：

- M06-006：`AprLabPolicyMapper#updateActivationState`与`AprPolicyRevisionMapper#insertActivationRevision`；
- M06-009：`AprLabPolicyMapper#savePolicyWithRevision`与`AprPolicyRevisionMapper#insertPolicyRevision`；
- M06-014：`AprRequestMapper#updateDecisionState`、`AprActionMapper#insertAction`、`AprDeliveryMapper#insertDelivery`。

每个方法在`mapper/system/<Mapper>.xml`有同名statement。多Mapper写由对应ApplicationService在同一本地事务中编排；事务外拥有方调用不进入Mapper。

### 2026-10-24 签审依赖接线（不新增 HTTP 路由）

`ProcessApprovalQueryApplicationServiceImpl` 与 `ProcessApprovalCommandApplicationServiceImpl` 共享 `M06ApprovalReadiness`。它消费 `M06ApprovalMemberEligibility` 和精确 owner 的 `ApprovalOwnerPrecheckPort`；readiness 不直接访问 M03/M07 Mapper。成员来源由 M03 `ApprovalMemberCandidatesPort` 提供，账号及功能码由 M01 `DeferredActorPermissionPort` 提供，实验室范围由现有 `LabAuthorizationService` 提供。原 API07/API08 的请求/返回字段和动作词表不变。

写消费者增加 M02 `CultureChangeDevicePort.lockLab` 和 M06 自有 `AprLabPolicyMapper.selectPolicyIdForUpdate`，按正式锁序在 owner 锁前执行。该政策根只作串行屏障，不重算在途单冻结政策；缺根仍失败关闭。`apr_delivery.insertDelivery` 明确写入 created_at 与 updated_at，不依赖数据库默认时间。

`MemberIdentityFactsMapper` 新增的三个只读查询仍归 M03；M06 不持有该 Mapper。当前真实成员枚举与 owner 检查不是“已有类即完成”，以生产消费者及独占 SQL/HTTP 的分层记录为证据。
