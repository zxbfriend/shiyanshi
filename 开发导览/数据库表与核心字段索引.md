# 数据库表与核心字段索引

这是学习用的静态索引，不是安装脚本，也不是当前运行数据库的 SHOW CREATE TABLE 结果。依据 2026-10-16 工作树中的 `docs/开发基线/01-完整建表.sql` 和 `04-表结构与模块拥有方清单.md` 提取。表用途优先保留 DDL 原注释，不按表名前缀擅自决定拥有方。

当前基线 172 张表：M01 22、M01公共框架 7、M02 51、M03 21、M04 9、M05 19、M06 7、M07 21、M09 15。M08 没有持久化业务拥有表。桌面旧 SQL 导出中识别到 174 张 CREATE TABLE，不能把它直接当成当前新系统基线，也不据此判断哪张应该删除。此前 169 张表的统计文档属于较早快照，本索引按当前源码重新核对。

关联 ID 字段不必然有物理外键；字段备注与 CHECK、唯一键、SQL 过滤和应用服务共同决定完整语义。没有注释的字段不猜测含义。逻辑删除、对象版本和状态约束不能省略。

## 三 用一条记录练习

在已授权个人开发库只读核对：先取得一个 `res_culture.culture_id`，记录其 project_id、batch_id、lab_id、culture_code、start_completed_at。再查该培养的 det_sample，记下 sample_id、sample_no、second_id、current_result_id；最后对照 det_result 与相同 object_version 的 det_result_revision。在线侧从观测 association 的 culture_id 反查，不能要求它一定具有 det_sample。

状态字段以对应模块契约及当前枚举／CHECK 为准，不能把所有名为 status 的列统一理解为启用／停用。比如设备 status、结果 result_status、培养 lifecycle_state、快照 evidenceQuality 表示不同维度。

表的“拥有方”表示谁负责写事实，不等于其他模块可以任意直连读表。你的统计应通过现有 M02/M03/M05 Port 消费；主键和业务编号、测量设备和培养容器、样品天数和真实 D0 都要分开。
