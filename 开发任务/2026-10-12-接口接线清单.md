## 0. 并行工作区纪律（长期有效）

⚠️ 本工作区常态有 **5 个以上 work 并行**，且远端高频前移。三类已实证风险：
1. **共享 `target/` 被并发重建** ⇒ `NoClassDefFoundError`（观察到 445 / 376 条的炸法）。**工作区静默约 5 分钟后重跑即收敛。**
2. **`.worktrees/` 下 3 份** `ManagementGuardExecutor.java` 副本 ⇒ `GuardCallbackContextContractTest` 恒红（环境噪音）。
3. **远端与本地可能做同一件事的不同实现**（本次 M05-029/030 即是）⇒ 拉取前**必须算三方交集**，不能直接 `git pull`。

**更新代码库的标准序列**（本次已验证可行）：
```
git fetch origin
git diff --name-only HEAD origin/cloud > /tmp/remote.txt   # 远端改动集
git diff --name-only > /tmp/local_unstaged.txt              # 本地未暂存
git diff --cached --name-only > /tmp/local_staged.txt      # 本地已暂存
comm -12 <(sort /tmp/remote.txt) <(sort /tmp/local_*.txt) # 算交集
# 备份 → stash push --include-untracked → merge --ff-only → stash pop → 解冲突
```

**禁止**：在有未提交改动时直接 `git pull`（会被拒绝或覆盖他人成果）；**禁止**用 `git checkout --` / `reset --hard` 丢弃他人未提交改动。

**每批开工前必做三查**：`git status --short`（目标文件是否已脏）／`git diff --name-only`（变化集是否只落本模块）／共享台账 `skeleton-mXX.json` 是否被他人占用。

**改在他人未提交改动之上时的纪律**：先 `git diff -- <目标文件>` 读懂他人在同一文件里已写好的代码，**增量开发、不覆盖、不重写他的逻辑**。
