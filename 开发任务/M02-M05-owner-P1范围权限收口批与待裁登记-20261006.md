## 4. 任务4｜`ResultCorrectionTokenSupport` 与 M05-001/048 令牌形状（结论：0L 不是技术阻塞，M05-048 维持 BLOCKED_DESIGN）

五维度覆盖现状（`M05CorrectionWiredContractTest` 12/12、`M05CorrectionP1ContractTest`、`M05ConfirmationTokensTest`）：

| 维度 | 是否已证 | 出处 |
|---|---|---|
| 过期 | 是 | `tokenRejectsExpired` + TTL 边界（`TTL_SECONDS=300`，`+300` 秒即失效） |
| 篡改（签名错配 / 载荷重写） | 是 | `tokenRejectsTampered`、本批新增 `tokenRejectsPayloadRewrittenWithForeignSignature` |
| 换人 | 是 | `tokenRejectsDifferentActor` |
| 换内容 | 是 | `tokenRejectsChangedCandidateHash`、`previewTokenStaysBoundEvenWithoutCorrectionId` |
| 换版本 | 是 | `tokenRejectsChangedVersion`；本批新增 `tokenRejectsDifferentCorrectionBinding`（换申请主键） |
| 换申请主键（001 预览态） | 是（本批补测） | 同上 |

判定：

- 预览阶段 `correctionId=0L` 哨兵**不构成绕过**：令牌安全来自（候选内容哈希 + 动作人 + 基线版本）三要素，已用反证测试钉住
  （换内容/换人/换版本任一即失效）。因此"0L 阻塞提交闭环"不成立。
- 但 `M05-048`（提交）**不接线**，原因属设计口径而非技术缺失：令牌把 `correctionId` 作为一等绑定段
  （payload `correctionId|actorId|candidateHash|expectedVersion|expiresAt`，`verify` 要求 5 段全等），
  提交前尚无主键 ⇒ 只能签 `0L`，令牌即不满足"一次性、绑定到具体申请、跨申请不可复用"的语义；
  若改为提交阶段重签令牌或换载荷形状，会同时触及 001/002/003 的签发/校验式与既有契约测试。
- 附带登记：令牌为**无状态 HMAC**，不存在真正的一次性消费登记（重放在 5 分钟 TTL 内可行，仅被基线版本 CAS 兜住）；
  `ResultCorrectionTokenSupport` 与 `M05ConfirmationTokensTest` 对 TTL 边界的口径不同（一为 `>` 一为 `>=`），属测试口径差而非实现缺陷。
- 结论：M05-048 维持 **BLOCKED_DESIGN**，台账 `wired` 不翻转，本批未改令牌载荷形状与冻结契约。
