## 4. 本批新取证的两条事实（未在 INT-21 登记过）

### 4.1 静态壳是进程级全局槽，测试里"调一次"就会污染后续测试

`SnowflakeIdUtils:14` 的 `private static volatile SnowflakeId snowflakeId` 只由构造器写入（Spring 装配），`:46` 的 `nextId()` 是静态方法。⇒ 任何"用 legacy 回填来证明主键已选定"的契约测试要么无处注入替身，要么真的调用它并把**同 JVM 内其它测试**的行为改掉。本类因此**不调用**该方法，只反射其静态性与槽字段可见性（`:155`）。INT-21 §2.4(1) 的"不可测"据此可复现。

### 4.2 AUTH-I01 准备侧在创建场景**禁止**携带 targetUserId

`M02LabAuthorizationAdapter`：

- `:207`（`replaceUserLabs`＝AUTH-I02）`Long targetUserId = requireDecimalId(command.getTargetUserId(), "目标用户ID")` ⇒ 替换侧要求真实 ID；
- `:496—:505`（`requireSceneConsistency`，AUTH-I01 准备侧）`:498` `if (operation == UserLabOperation.USER_CREATE && targetUserId != null) throw invalid(...)` ⇒ 准备侧在创建场景**必须**为空。

两条同时成立 ⇒ 创建期那个 ID 只能由应用服务自己持有，不可能从准备侧拿。这既支撑 §2 第 4 行的次序约束，也再次说明**创建期版本摘要从哪来仍是 86 号 §7.2 的 Q-a／Q-c（INT-21 §6 R-1）**：本批只钉形状边界，不裁该问题，也不得被读成 R-1 已解。
