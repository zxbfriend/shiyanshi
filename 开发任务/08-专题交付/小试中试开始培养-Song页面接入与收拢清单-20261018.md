## 2. 目标页面链路

建议统一到Song页面体系中的一个开始培养承载位置：`run-workflows` 内的 `StartCultureWorkspace`。`reactor-overview → feeding-workspace → feeding-reactor-detail` 保持为反应器浏览链路。

```text
Song反应器总览 → 反应器详情 → 生产过程 → 开始培养
                                           ↓ 携带设备及当前培养
Song工作流首页 → 开始培养 ──────────────→ 同一个开始培养工作区
                                           ├ 未完成：按规则进入/从第1步重开
                                           └ 已完成：仅显示目标培养完成记录
旧工作台/旧书签 ── 校验授权与参数后兼容转入 ────┘
```

采用单一承载位置，避免在反应器工作台和工作流首页各自复制一套开始培养状态。具体URL必须通过现有授权菜单及`pagePath`解析，不能硬编码实验室路径、绕过菜单或按钮权限。

## 7. 入口上下文与状态规则

以下为目标契约建议，不是已实现的新路由/API字段。

- 单台入口传递：实验室ID、设备类别、设备ID、目标培养ID、来源页面和页签。小试设备类型使用现行`BENCH_CONTROLLER`，中试使用`INTEGRATED_REACTOR`。不按名称、卡片序号或设备ID单独猜测。
- 实验室级入口不传目标培养，小试由用户选择多台，中试选择一台。单台入口校验失败不得静默切换成实验室级入口。
- URL参数仅用于定位。进入时重新核验当前实验室、设备关联、可见权限和服务端候选/完成结果；每次写入的权限、占用、设备状态、当天期限仍由后端验证。
- 缺活动培养：说明需先创建/关联培养；多活动培养：说明关联异常并阻断开始；只有历史培养：不得当作当前培养开始。历史查询需明确培养身份。
- 已完成：直接渲染只读完成页。从单台入口进入已完成批量时，只显示对应成员。
- 未完成：正常首次进入第1步；刷新或取消后的再次进入，先按既有服务端恢复/关闭规则处理旧尝试，再从第1步开始，不能恢复旧表单。
- 单台入口遇到本培养属于未完成小试批量：不得拆出单成员单独续做或取消，仍遵循原整组核对及安全关闭规则，并明确提示关联批量。只有已完成记录展示才按目标成员过滤。
- 次日：不允许新开/续做/补完成前一天尝试；保留查询及必要安全收尾。
- 返回：返回来源总览或详情/生产过程页签，恢复设备定位；返回动作须经过现有未完成离开保护。来源失效时回到已授权的Song工作流首页。
- 路由及组件实例：切换实验室、设备或培养时重置页面实例，不能只按实验室作为组件key复用上台设备的草稿。

## 8. 建议实施顺序和验收清单

1. **先统一定位和入口（P0）**：当前培养解析、空闲卡片入口纠正、统一路由上下文、旧链接兼容。此阶段不改变四步表单和提交接口。
2. **再将开始培养嵌入Song页面（P1）**：统一页头/侧栏/返回行为，保留四步内容和完成组件。
3. **迁移原工作台详情能力（P1）**：核对运行信息修改、结束培养、连接提示和授权后，再收起重复的列表/详情区域。
4. **最后抽取通用展示（P2）**：设备摘要、步骤条、结果布局。避免在入口尚未稳定时一起改状态机。

| 验收编号 | 场景 | 预期 |
| --- | --- | --- |
| A01 | 小试总览 → 某台详情 → 开始培养 | 只定位本台当前培养，能返回原详情生产过程页签 |
| A02 | 中试总览 → 某台详情 → 开始培养 | 仅单台，进入中试四步，不能落到小试模板 |
| A03 | 工作流首页小试/中试入口 | 小试允许批选；中试只能单选；不会继承上次单台目标 |
| A04 | 小试批量完成后分别进入两台详情 | 每台只显示自己的完成记录；再次进入和刷新仍只读 |
| A05 | 中试完成及次日查询 | 显示服务端完成记录、操作人、时间、模拟来源，无重复提交按钮 |
| A06 | 未完成刷新、取消、返回、跨天 | 按原关闭/恢复规则处理；重新从第1步；不恢复表单；跨天不能续做 |
| A07 | 空闲设备“创建培养” | 不调用开始培养写接口；走真实M03入口或显示明确不可用原因 |
| A08 | 同数字ID不同设备类别/实验室、多活动关联、历史培养 | 不串台、不猜测、不把历史培养作为当前培养开始 |
| A09 | 仅查询权限、缺开始权限、菜单未授权、会话失效 | 只读记录与写动作分开授权；不能借旧链接或返回参数绕过权限 |
| A10 | 从手工补料/液体补充切到开始培养 | 清理互斥参数，渲染正确流程；不沿用其他流程版本或草稿 |
| A11 | Mock与后端受控模拟 | Mock不写真实业务；受控模拟保留白名单、审计和模拟来源 |
| A12 | 收拢后原运行信息修改、结束培养等功能 | 仍可从Song详情进入，原权限、预检与守卫保留 |
| A13 | 新旧链接、浏览器后退、切换实验室、窄屏 | 跳转与返回可用、上下文不串用、无重复页头或导航 |

将来实施后需分别记录类型/契约测试、真实HTTP和浏览器结果。本文没有执行上述验收，不以源码可见入口替代实际验证。
