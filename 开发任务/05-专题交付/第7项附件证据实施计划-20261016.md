# 第7项受控更正附件证据实施计划

2026-10-16：用户已确认采用 M05 私有表保存不可变 BLOB 原件；本入口只接收普通更正证据，不接收设备技术原文。未提交附件仅上传者且仍有当前结果操作范围可读；提交后沿结果当前读取用途权限。所有原件暂不自动删除，不提供覆盖、删除或 TTL。

## 实施范围

1. 先补行为测试：真实摘要核验、跨结果/版本/摘要拒绝、草稿与已提交授权、锁内仅元数据、上传长期回执和下载完整性。
2. 新增 M05-067 POST `/detect/result-corrections/evidence` 守卫上传，M05-068 GET `/detect/result-corrections/evidence/{attachmentId}/versions/{version}/file` 精确下载；不扩公开 URL 文件服务。
3. 原件读取、字节限额和摘要计算在守卫事务外；锁内重验当前身份、对象版本和不可变元数据。更正预览和决定预览核验原件，提交/决定仅重验冻结的 ID/version/SHA256；本地不可变精确引用作为凭据，不扩预览 JSON。
4. 新建 `det_correction_evidence`，原件、元数据、上传长期请求键与首次管理版本原子保存。同步 M05 目标 DDL、字段字典与新系统开发基线。仅保存脚本，不执行数据库。
5. 页面改为上传并选择服务端返回的证据，提供有鉴权的下载；未知结果重试保留原文件和请求键，不自动换键。
6. 主代理负责共享更正服务接线、审计/操作注册表和接口门禁；本任务负责附件专属代码、DDL/基线和页面。不得混入其他逾期项。

## 配置和验收

`futurefab.m05.correction-evidence.max-bytes` 必须显式配置为正数；未配置时仅附件上传失败关闭，不猜生产限额。部署须协调 HTTP multipart、MySQL max_allowed_packet、容量及备份恢复。既有平台类型白名单不等于可上传设备技术原文；入口用途固定普通人工证据。

验证分层记录：单元/契约、编译、目标 MySQL、HTTP、浏览器、部署分别报告。当前数据库/HTTP/浏览器未运行，不能以静态脚本或 Mock 代替运行验收。
