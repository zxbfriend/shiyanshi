# 第7项 M07 检测来源确认与显式恢复实施计划

> 执行方式：按已授权并行分工在当前共享工作区实施；本车道原地执行，不创建子代理。先写行为测试，由主代理统一执行 Maven 并确认 RED，再实现并复验。未经授权不提交、不操作数据库、不接设备或网络。

**Goal:** 将当前合法 M05 精确版本接入残糖确认，并允许人工对未开始的受影响原任务重新确认、计算和提交新候选。

**Architecture:** M05 继续拥有精确结果事实；M03/M04 提供不可变指标映射包。M07 固定来源、同日确认槽、不可变新计算和新候选，沿原审批政策生效；原生成键及历史证据保留。影响查询以公开 Port 返回当前有权聚合计数，不能读取 M07 私有表。

**Tech Stack:** Java 17 / Spring / MyBatis / JUnit 5 / Mockito；现有 Vue 页面和 SDK。

**Spec:** 用户已确认 evidenceQuality=VERIFIED、无 activeSign 强制门；恢复流程为重选→60秒确认→新计算→同一未执行任务新候选审批。现行依据为 M07《计量确认与补液计算契约》《数据库JSON与事务契约》《任务页面与接口契约》和 M05《自动检测与跨模块结果契约》。

## 全局约束

- 接口只消费实际冻结 M05 schema1/2，保留 exact result/version/item/hash；禁止用最新值代替旧版本。
- VERIFIED 不等于 GOOD；旧位置无依据为 null，quality=UNKNOWN；旧 UNVERIFIED 更正后仍不升级。
- 实际完成时刻必须可信、属于上海当日且不晚于服务器；60秒结束重验当前版本、权限和冻结映射。
- 仅接受已核准 g/L 数值；不自造未知单位换算。
- 无物理开始、无已发/未知 START 命令、非 PAUSED/UNKNOWN 才可恢复。
- 恢复不新建任务、不清 generationKey、不返还自动每日额度、不修改旧计算/账本/候选。
- 共享 operation、注册表、接口目录机器台账由主代理协调；本车道先提出明确接口再接线。

## 审阅焦点

1. M05 完成时刻不能采用今日可变父行补历史；未知或未来时刻拒绝。
2. M04 简称需精确 itemId 绑定及包来源，不能把 itemCode 猜成 GLC/LAC。
3. 原 generation 引用旧确认必须保持历史，但仅经验证的新生效恢复事实可替代当前启动来源。
4. 失效 pending CREATE 的 objectVersion 已大于1，恢复必须按当前 expectedVersion CAS；旧审批拒绝。
5. 无权或依赖故障的影响查询返回未知计数，不以0掩盖失败。
