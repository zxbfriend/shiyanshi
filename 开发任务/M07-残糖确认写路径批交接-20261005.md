## 3. 如实登记的实现边界与口径决策（复核重点）

1. **M07-018 恒 503 失败关闭**：契约冻结"手工候选全局样品号在 M01 SYSTEM 守卫内与 M05 样品号校验并原子登记""接口/共同守卫未接入时不允许手工候选登记"。M07→M05 样品号校验 Port 未声明（DET-I01 为 M05 侧检测候选预检、DET-I06/07 为结果读取，均不承载样品号占用校验），`requireM05SampleNoCleared` 在守卫事务内、任何数据库写入之前 503。本地输入校验、守卫链、样品号占用检查（RESOURCE_IN_USE，含 M05 保留值）与占号写代码已就绪，待 M05 校验 Port 冻结后生效。**BLOCKED_M05**（跨模块 Port 缺口）。
2. **M07-019 的 M05 源恒 503**：Port 缺失 503；Port 接线后 DET-I06 视图仅含 resultId/revision/schemaVersion/value/observedAt/irreversible，不足以冻结完整 `confirmation.source_snapshot`（缺 itemId/shortName/unit/sampleNo 等），亦 503 并登记为跨模块契约缺口（需 M05 扩展 DET-I06 或另立候选详情读口）。MANUAL 源为真实实现（锁行复核培养归属/版本/指标行，数值非负，单位仅接受 g/L 原值，其他单位换算未核准 503）。
3. **019/020 与 PHY Mapper 清单的取舍**：PHY §3 API19 行列有 `updateConfirmedGlucoseByVersion`，但《数据库JSON与事务契约》§3"60s完成"事务（confirmation+runtime 确认指针+审计事件）明确优先于 PHY 的 Mapper 适用性清单；故 runtime 确认指针 CAS 实现在 **020 到期完成分支**（锁 runtime 行 + object_version CAS），019 仅追加 COUNTDOWN 事实行。已在类注释登记该取舍依据。
4. **020 分支语义**：取消须原确认人本人（403）+ expectedVersion 匹配（409）；now<deadline 撤销为 CANCELLED（invalid_reason 固定 `OPERATOR_CANCELLED`，词表未冻结在此登记）；now≥deadline 按"同一行锁按服务器时刻尝试完成"执行 60s 完成事务，完成前复核源有效性，任一变化置 INVALIDATED（保留已发生时刻）；CONFIRMED 不可再取消/编辑（409）。到期完成的兜底触发（021 查询懒完成或 job 扫描）**不在本批**，用户确认后离开页面则确认保持 COUNTDOWN 直至后续交互——属后续批次缺口。
5. **017 双分支**：onlyConfirmed=true 从本日 CONFIRMED 行真实装配（不依赖 Port，`completedAt` 等从 source_snapshot 解析）；onlyConfirmed=false 时候选主体由 M05 DET-I07 提供，Port 缺失 503（不把本地已确认值静默降级为候选）。DET-I07 行为结果版本级（resultId+revision），无 analyteKind/itemId/value 单位等字段，相应叶子置 null 不猜 GLC/LAC 归类、不做单位换算；观测时刻按上海日归日过滤。**BLOCKED_M05**（候选浏览分支）。
6. **事件码词表未冻结**：本批选码 `CONFIRMATION_SELECTED/CANCELLED/CONFIRMED/INVALIDATED`、`MANUAL_RESULT_REGISTERED`，全部 `publish_state=LOCAL`（仅内部审计，不承诺外部发布），source_event_key=`M07:<事件>:<requestId>` 承载幂等；payload 按 event.payload 模式 schemaVersion=1，Actor.managementRevision 在守卫事务内无 committed 值如实为 null。选码待总控复核或后续词表冻结。
7. **M07-020 权限登记**：skeleton 的 020 perm 由 null 更新为 `run:glucose:confirm`（功能码部分；复合表达式"且本人"由应用服务核验原确认人，契约原文保留在 Controller 注释）。
