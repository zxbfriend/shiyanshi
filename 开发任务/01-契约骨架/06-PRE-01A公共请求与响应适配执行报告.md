## 3. requestId 生命周期

1. `RequestMetadataFilter`（order = HIGHEST+100）读取 `X-Request-Id`。
2. 缺失 → 服务端生成 UUID；合法 8-4-4-4-12 UUID → 原值复用；非法 → 服务端另生成权威值，先写入上下文与 MDC，再记 WARN 日志并输出 HTTP 400 `{code:400,msg,errorCode:"INPUT_INVALID",requestId:<同一生成值>}` —— 错误响应与日志上下文使用同一个 requestId，非法客户端值不回显、不入日志；随后 finally 清理。
3. 合法/生成值经上下文与 MDC（键 `requestId`）贯穿日志、参数解析、异常处理与响应适配；成功响应与错误响应顶层 requestId 一致（§9 用例 1/2/4/14 验证）。
4. finally 清理 MDC 与 ThreadLocal（下游抛异常、前置 501 拒绝均覆盖）。
5. 上下文为普通 ThreadLocal（R1）：不向异步线程池传播；异步任务如需 requestId 必须显式捕获并在自己的 try/finally 中设置与清理。
6. requestId 不是业务键；幂等回执（sys_management_request）不实现（PRE-01B）。
7. 选型：Filter + HandlerInterceptor（前置）+ ControllerAdvice（复制），杜绝逐 Controller 复制逻辑；网关（webflux）不在本机制范围。

## 4. WriteMeta 解析规则（公共解析能力，不做逐业务 Command 合并）

- 端点声明 `WriteMeta` 形参即触发解析器；GET 查询与普通端点不感知。
- requestId：取上下文（Filter 已校验/生成/拒绝）；上下文未初始化时回退 Header 校验，仍不可得则生成。
- managementRevision：只读 `X-Management-Revision` Header；缺失 → 400（"管理写接口必须携带"）；格式非法由 `WriteMeta` 构造器统一抛 RequestMetaInvalidException → 400 INPUT_INVALID（同一校验入口，无双套规则；超 long 值域按非法）。
- Body 不可覆盖 Header；Path 覆盖 Body 同名的 Command 组装属后续逐接口改造（PRE-01B/PKG-01 实现步）。
- 非管理写端点与 GET 不要求 `X-Management-Revision`（§9 用例 17 验证）。

## 5. AjaxResult / R / TableDataInfo 适配方式

- 统一在 `RequestMetadataResponseAdvice.beforeBodyWrite` 完成；第一步即 instanceof 判定，非三种外壳立即原样返回——不读 Source、不抛异常。
- `AjaxResult`：Map 顶层 `put`（覆盖）requestId/managementRevision，code/msg/data 不动。
- `R` / `TableDataInfo`：上下文有值即 setter 覆盖预填值；上下文无值保持原样。
- 上下文为权威：Controller 预填的不一致 requestId/managementRevision 一律被覆盖（§9 用例 8/9）。
- `TableDataInfo` rows/total 保持顶层；不新建并行外壳、不双重包装（用例 7/13 断言顶层键集恰好为 code/msg/data/requestId）。

## 6. managementRevision 边界（R1 重构后）

- QUERY_CURRENT（查询）：`ManagementRevisionPreResolver` 在 Controller 执行前读取 → `putCurrentManagementRevision` 入上下文。Source 缺失、抛错或返回非法值（空、空白、负数、非数字、long 溢出）→ Controller 执行前 HTTP 501 + NOT_IMPLEMENTED（contractId=PRE-01A#ManagementRevisionSource），此时不可能已有业务写入。
- MUTATION_COMMITTED（写）：ApplicationService 在管理写事务成功提交后调用 `putCommittedManagementRevision` 回填新版本；显式值优先于任何当前值读取。写接口禁止用 QUERY_CURRENT 读取的版本冒充提交后版本（注解 javadoc 与实现双向排除）。
- Advice：只做"上下文已有值 → 外壳顶层"的无失败复制；无 Source 字段、无注解判定、无校验、无抛错路径（结构反射测试锁定无参构造 + 零字段）。
- 全链路不存在"业务事务已提交后在响应序列化阶段抛 501"的代码路径：501 只可能来自 Filter（业务未开始）、PreResolver.preHandle（Controller 未执行）或既有 GlobalExceptionHandler 对业务/服务层主动抛出的 SkeletonNotImplementedException 的映射（该异常由业务侧自行决定抛出时机，不属于响应阶段注入）。

## 7. 被排除的响应类型（不读取 Source、不被外壳适配改动）

- `String`（StringHttpMessageConverter）→ 原样文本；`byte[]`/`Resource`（文件下载、导出流）→ 原样字节；SSE（`ResponseBodyEmitter`/`SseEmitter`）→ 不经外壳路径，输出不含 JSON 外壳字段；任意非外壳 Map/DTO → instanceof 不命中原样返回。
- 标注 @CurrentManagementRevision 的非外壳端点同样被前置解析器跳过（返回类型门槛），避免"查询一个二进制流却因缺 Source 被 501"的歧义。
- 网关透传响应、feign 内部调用 DTO（R 的 requestId 为 null 不出字段）不变化。

## 8. 异常状态保持方式

- 未改动 `GlobalExceptionHandler`；`SkeletonNotImplementedException` 仍 HTTP 501 + errorCode=NOT_IMPLEMENTED + contractId，Advice 仅追加 requestId，不改状态（用例 14）。
- `NotPermissionException` 403 的 HTTP 状态与体 code 与"无 PRE-01A 组件"基线逐项相等（用例 14b 对比断言）。
- 新增 400 只来自本任务新语义（X-Request-Id 非法、X-Management-Revision 缺失/非法），不吞、不改写任何原 errorCode/msg。
- 401（未认证）仍由网关统一处理，servlet 侧状态映射零改动（§11 局限）。
- Advice 不可能把失败变成功或把成功变失败：其唯一行为是复制上下文字段。

## 11. 已知限制

1. 仅覆盖 servlet 侧服务（依赖 common-security 的 system/auth 等）；网关（webflux）的 requestId 策略不在本步。
2. `X-Management-Revision` 只解析不复核——版本一致性校验、幂等回执、SYSTEM 守卫事务全部属 PRE-01B；58 个 ADJUST Controller 尚未接入 WriteMeta/注解（本任务禁止改动）。
3. `ManagementRevisionSource` 尚无生产 bean：M01 适配器（读 sys_management_revision）由 PRE-01B 注册；当前标注 @CurrentManagementRevision 的端点在任何业务执行前得到 501（显式未实现，非伪造）。
4. 前置解析器对返回类型的门槛为三种外壳（含 ResponseEntity<外壳>）；其他包装类型（如自定义 wrapper）需 PRE-01B 按需扩展。
5. 超 long 值域的 managementRevision 按非法处理（合同未定义任意精度语义，取保守边界）。
6. 401 未认证路径在网关，本层未动也未在 servlet 测试中复现。
7. 普通 ThreadLocal 意味着使用 `@Async`、手动线程池或虚拟线程的端点不会自动携带 requestId/revision 上下文；如业务需要，异步任务须显式传值（该要求是有意的安全默认，防止可变 Holder 泄漏到池线程）。
8. 未启动真实服务做 HTTP 联调；结论层级为单元/契约测试通过。MDC 键 `requestId` 已在代码侧写入，logback pattern 是否展示属运维配置，未改。

## 12. PRE-01B 进入条件

- 公共机制已冻结可用：Controller 以 `WriteMeta` 形参取 requestId+revision；查询型管理端点标 `@CurrentManagementRevision` 即自动获得顶层 managementRevision；写接口由 ApplicationService 调 `putCommittedManagementRevision` 回填——三类装配均无需逐 Controller 逻辑。
- PRE-01B 范围（05 审计 blockers 已登记）：sys_management_request 幂等回执（24h HMAC 指纹）；sys_management_revision SYSTEM 行守卫事务（同事务锁行、复核、审计、+1、写回执）；M01 `ManagementRevisionSource` 生产适配器（注册为 bean 后前置解析路径自动生效）；随后按 58 接口清单逐 Controller 接入。
- 需客户/设计确认项：BLK-02/03/04b/04c 仍开放，不阻塞 PRE-01B 基础设施编码，但阻塞对应端点完成验收。
