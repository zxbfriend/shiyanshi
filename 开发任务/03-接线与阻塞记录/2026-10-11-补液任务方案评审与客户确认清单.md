# 补液任务生成与执行方案评审及客户确认清单

版本：2026-10-11 草稿。性质：SUPPORTING，供与药明方评审会使用，会后结论回写对应模块现行契约。本文描述的是**当前设计方案**，不代表功能已开发完成、设备已联通或现场已验收。

## 0. 本次会议目的

1. 向药明方说明新 SMP 中补料/补糖任务“怎么生成、怎么审批、怎么下发、怎么执行、出了问题怎么处理”，请确认方案方向。
2. 请药明方核对我们根据附录2资料对旧系统的理解是否正确（第 7 节）。
3. 逐项确认或约定提供第 8 节所列事项，明确责任人和时间。

## 1. 三类实验室的执行路径

| 实验室 | 补料由谁执行 | 新 SMP 的角色 |
| --- | --- | --- |
| 小试一期 | **保留原系统**：原网站落库、原 Core 驱动泵并回写，表结构不变 | 建立与原任务/批次/设备的对应关系，只读展示任务与结果并对账；不另起一套调度去执行同一动作 |
| 小试二期 | 目标由新 SMP 执行；切换前由原控制方继续执行 | 统一生成、审批、调度、执行、异常处理与计量 |
| 中试 | 目标由新 SMP 执行；切换前由原调度程序继续执行 | 同上 |

切换按“设备组”逐组进行：先停原系统对该组的新任务 → 处理完执行中/暂停/状态不明的任务 → 确认旧控制通道已断开 → 再由新系统接管。**任何时刻同一台设备只有一个系统在控制**，不做新旧双控。

## 2. 任务从哪里来

| 来源 | 说明 | 防重复规则 |
| --- | --- | --- |
| 固定补料 | 补液方案“补料任务”页按泵逐行配置（第几天＋计划时间＋数值/百分比＋体积）；**连接补料单元完成时一次性生成整个培养周期的全部任务** | 同一培养、方案、规则行、日期只生成一次 |
| 补糖·按数值 | 补糖规则“按数值”（日区间＋每日执行时间＋固定克数）；与固定补料同时一次性生成 | 同上 |
| 补糖·按规则 | **动态生成**：按检查周期（默认 10 秒）判断；当天有补料任务时须等补料全部完成，无补料任务视为已完成；残糖低于下限（< 或 ≤）时按“糖补料至”计算，补糖量 ≥ 最小阈值才生成（需求澄清 2026-09-07） | **每条规则每天最多生成一次**；一旦生成，即使被取消/驳回当天也不再重建 |
| 方案修改后重生成 | 已连接补料单元时修改补液方案：取消旧方案未执行任务，按新方案重新生成；未连接时待连接完成再生成 | 旧任务保留为“已取消” |
| 人工新增/复制 | 任务队列或反应器详情页新增：选择反应器和泵（只能选固定泵中已配置的泵），立即执行或定时执行；多反应器多泵时**按泵拆成单独任务、各自审批**；未填写的泵行不生成任务。手工补糖只能按数值，不支持百分比（原型）。复制任务须重新选择执行时间 | 默认防重复：同培养、同泵、同时间再次提交会提示已存在；确需再加一次时用户明确选择“新增一次”。另按原型：同一反应器同一天已有同一泵的补料任务时给出提醒（不阻断） |
| 异常补充 | 执行异常处理时选择“自动补充”生成的子任务 | 与原任务挂钩，一次异常只能处理一次 |

补充规则：

- 已生成的任务**固定创建时的方案版本**。之后修改方案或模板，不会悄悄改动已有任务；如需替换方案，系统取消旧方案中尚未开始的任务并按新方案重新生成。
- 动态补糖低于“最小允许补糖量”时不生成任务，只发通知（NCS061）。该最小值需药明方提供（第 8 节 C-01）。

### 2.1 补液量怎么算

依据 V5.1 25-字段说明与计算公式（V4.0 第 21 章）及需求澄清（2026-09-07）。公式中的“体积/罐重”统一指罐内培养液净重（g，密度按 1）。

| 任务 | 目标补液量 |
| --- | --- |
| 补料·数值 | 直接取输入的克数 |
| 补料·百分比 | 初始培养重量 × 百分比（初始培养重量＝初始培养体积＋接种体积，由实验人员合计后一次录入） |
| 补糖·按数值 | 直接取输入的克数 |
| 补糖·按规则（残糖） | （目标糖浓度 − 补糖前糖浓度）× 计算依据重量 ÷ 糖补料浓度 |
| 补糖·按规则（残糖＋乳酸） | （目标糖浓度 − 补糖前糖浓度 − 乳酸浓度）× 计算依据重量 ÷ 糖补料浓度 |

- **计算依据重量**按培养设置“补料计算依据”取：初始重量，或执行前当前重量。当前重量：中试读反应器秤；小试按“初始培养重量＋累计实际补液量－累计取测量”计算（小试无反应器秤，实际补液量取补料天平前后读数差）。
- **补糖前糖浓度**：当天最近一次补液后计算的糖浓度；当天还没补过则取当天确认的残糖值。是否把补料带来的糖浓度变化计入，由培养设置“补糖时计算补料引起的糖浓度变化”决定。
- **按规则补糖分两次计算**：生成任务时算一次，用于判断是否需要补、是否达到最小补糖量；**真正开始执行前，用当时最新的合格数据再算一次并固定为本次目标**，暂停后继续不再重算（见 A-10）。
- 结果按补料秤精度四舍五入一次；缺少任何输入时不计算、不按 0 处理。

## 3. 审批与生效

- 新任务、修改、取消按实验室审批政策走审核/批准；审批未通过前任务不会被执行。
- 审批通过只代表“同意”，系统在生效时会再次检查任务是否仍可执行（未开始、未过期、方案未变）。
- 只有“待执行”或“已安全暂停”的任务可以修改或取消；取消理由必填。

## 4. 排队与启动前检查

**排队**：同一培养的补料和补糖放在同一队列，按计划时间先后执行；前面有未结束的任务（待审、暂停、出错、状态不明）时，后面的任务等待。不同培养互不影响，除非共用同一台泵、秤或控制器。

**时间窗**：计划时间到达后当天内执行；**过了当天仍未开始则记为“跨天取消”，不自动顺延到第二天。**

**启动前逐项检查**（任一项不满足就不启动，并在页面显示原因）：

- 审批已生效，培养状态正常、设备占用正确，队列中前序任务已结束
- 设备处于自动模式且无错误码，泵、秤、控制器通信正常
- 补料秤读数新鲜且稳定（旧系统做法：连续稳定超过 10 次才开始，30 次仍不稳定报 NCS035）
- 残糖按培养设置的“补液前残糖确认”方式满足：必须人工确认 / 不需要 / 综合策略（Cedex 当天有且仅有 1 个糖结果时自动确认，多个时等人工确认）
- 补料袋余量足够（不足报 NCS012）
- 目标量、速度在泵的量程内

**没有读数一律视为“未知”而不是 0**，不会因为缺数据而放行。

## 5. 下发与执行

### 5.1 下发方式

- **每台设备固定由一个执行程序控制**。页面、审批等服务可以多台部署，但只有这一个执行程序能向该设备发命令。执行程序出故障时**不会自动切换**到另一台，需人工确认旧程序已断开、设备已停泵后再移交。
- 每条设备命令**先记入数据库，再发给设备**。即使程序在发送过程中崩溃，重启后也能查到“发过什么、发到哪一步”。
- 设备回复“收到”只表示命令已受理，**不等于已经执行完成**。

### 5.2 泵速策略（沿用旧系统算法）

- **二段式**：先高速补到目标量的 A%，再低速补到终止百分比 E% 后停泵。
- **三段式**：先校准段，按实际补入量反推流量系数修正后续高、低速，再高速、低速。
- 理论时长按“限幅后的实际速度”计算，再加宽限时间作为超时上限。
- 外置泵：系统按 g/min 计算速度，再按每台泵的换算系数转换为泵的转速后下发（旧系统同样做法，系数需药明方提供，见 C-03）。

### 5.3 运行中监控

| 监控 | 触发条件（概述） | 处理 |
| --- | --- | --- |
| 超量 NCS009 | 实际量超过目标量的允许超量百分比 | 立即安全停泵 |
| 超时 NCS008 | 实际运行时长超过理论时长＋宽限 | 安全停泵 |
| 抖动 NCS030 | 秤读数异常跳动 | 先降为 0 观察，观察期后恢复正常则继续，仍异常则停泵报错 |
| 返水 NCS032 | 补料秤读数反向增加超过阈值 | 安全停泵 |
| 堵塞 NCS031 | 实际补入量远低于理论量 | 安全停泵 |
| 泵速为 0 NCS007 | 运行阶段实际泵速持续为 0 | 停泵报错 |
| 通讯异常 NCS023/026/013 | 秤、外置泵或实时数据连续读取失败 | 请求安全停泵，状态记为“未知” |
| 泵错误 / 下发失败 NCS018/037 | 泵报错误码或速度下发失败 | 停泵并保留原始错误 |

## 6. 停止、结算与异常处理

- **停止**：达到终止百分比后下发停泵；确认**泵速归零且秤读数稳定**后才结算。旧系统判据为“泵速 < 0.001、至少观察 5 秒、最近 5 条读数差不超过秤精度、结束后继续监秤 120 秒”，新系统拟沿用（待确认，见 A-03）。
- **结算**：最终量低于下限记“少加”（NCS033），高于上限记“超量”；**实际量不明时不记为 0**。
- **暂停与继续**：暂停须等泵速确认归零才显示“已暂停”；继续时只补**剩余量**，不重新补满整个目标。
- **异常处理**：先安全停泵，再由人工录入实际补入量。误差大于 5% 时可选“自动补充”（生成子任务，重新走审批）或“手工补充”（登记人工补加量）；误差不大于 5% 只登记实际量。
- **断网/状态不明**：命令状态记为“未知”，设备保持占用，只按原命令查询，**不会重新下发一次补料**，需人工核对现场后处理。
- **旧任务接续**：本期不接管旧系统中尚未完成的任务；旧数据保留可查。
