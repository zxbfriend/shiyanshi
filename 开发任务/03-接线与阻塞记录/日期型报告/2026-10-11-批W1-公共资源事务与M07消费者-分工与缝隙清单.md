## 4. work1 需要 work2 到货的确切项（缺任一项三个 worker 不能编译或不能鉴权）

1. **能力句柄类型全名**及其对消费者可见的调用面：`M07ResourceClaimWorker` 需要的抢占 Port 方法、`M07CommandReceiptApplyWorker` 需要的回执应用方法、`M07ResourceReleaseWorker` 需要的核准释放方法。合同只固定用途三类，未固定方法签名。
2. **固定用途枚举/常量的确切值与类型**（`requirePurpose(expectedPurpose)` 的入参形态）：资源抢占 / 命令回执应用 / 证据核准释放。
3. **`ResourceTransactionContext` 只读查询面**：调用方取"当前任务或事件ID、已核验执行器归属、完整锁集合、SYSTEM 锁已取得事实"的确切 getter 名。
4. **装配注入形态**：三个 worker 的 `private final` 字段类型、构造器还是字段注入、以及"工厂返回实例＝最终 Bean 引用全等"约束下 work1 可写的构造签名（消费者不得有公开 getter 暴露句柄）。
5. **锁序与预解析责任边界**：work1 提供按字典序加锁的 DAO 语句；`ResourceTransactionExecutor` 是否在调用前统一取得 SYSTEM 行并按 §5.5 总序重验，work1 不重复取 SYSTEM 锁。
6. **PKG-00 逐方法来源登记**：本批新增/改动的资源锁读与占用转换方法属 `BACKGROUND_ONLY` 或 `BOTH`，须由 work2 登记，work1 不自行写入登记表。
7. **等待预算落地方式**：`futurefab.resource-transaction.lock-wait-seconds` 由公共拥有方以连接级方案实现；work1 的 DAO 语句不内嵌 `WAIT n`/`NOWAIT`，避免改动共享连接后遗漏恢复。
