## 3. 两步法怎么实现的

### 3.1 分组键

真实 `labId` + 真实 `cultureId`（无培养显式 `NULL`）+ 规范化当前 `sampleNo` 三元组。

按已裁决 **B-01/A**（同实验室同培养内编号完全一致才合并，不忽略大小写/标点/前导零），分组与
组键比较一律走 `cast(s.sample_no as binary)`：

```sql
group by s.lab_id, s.culture_id, cast(s.sample_no as binary)
```

⚠️ 关键点：库内 `sample_no` 列排序规则是 `utf8mb4_0900_ai_ci`（**大小写不敏感**）。若直接
`group by s.sample_no`，`ABC001` 与 `abc001` 会被合并，直接违反 B-01/A。测试
`groupKeyComparesSampleNumberAsBinarySoCaseIsNotIgnored` 钉住这一点。

`cultureId` 用 `(s.culture_id <=> #{g.cultureId})` 参与回捞比较——NULL 安全相等，保证"无培养"是
独立组身份而不是通配（Q02：不能清空 `cultureId` 降级）。

`groupKey` 是**服务端不透明投影键**：长度前缀编码后取 SHA-256（复用既有
`SignActionRules.sha256`），避免 null 与分隔符碰撞。SQL **不**再另算一套 group_key——
早期版本 SQL 用 `lpad` 拼串、Java 又用另一种格式，同一组会出现两个 key，已删除 SQL 侧那份。

### 3.2 先过滤再分页（不是全表捞回 Java 过滤）

- `countSignConsoleGroups` 与 `selectSignConsoleGroupsPage` **共用** `<sql id="signConsoleGroupFrom">`
  → 共用同一 `<sql id="signConsoleResultFilter">`，杜绝 count 与 page 两套口径。
- `count` 无 `limit`（否则 `total` 退化为当页组数）；`page` 才有 `limit/offset`，单位是**组**。
- 分组键由 SQL `GROUP BY` 产生，Java 只做装配，不做筛选。

### 3.3 展开阶段不重复套筛选

`selectSignConsoleGroupResults` 按**本页组键**（`@Param("groups")`）回捞，**刻意不引用**
`signConsoleResultFilter`。这样同组其它检测类型即使不符合本次状态/日期/人员筛选也照常成卡
（M05-QUERY04/05），只靠 `matchedFilter` 标记解释原因。

`matchedFilter` 在 **Java 侧**按同一份 `SignConsoleQueryCriteria` 判定。我最初在 SQL 里复制了
第二份筛选条件做 `case when ... then matched`，但两处条件必然漂移，已删除该片段。

范围条件（`signConsoleGroupScope`：项目/批次父级收窄 + `del_flag` + `SmpPermissionScope`）
两步始终生效——§12.3 明确"项目/批次/真实培养/实验室范围和删除/历史许可约束两步始终生效"。

### 3.4 一次一致性快照

`querySamples` 整体在 `TransactionTemplate(readOnly=true, ISOLATION_REPEATABLE_READ)` 内完成
count → page → expand → items。避免"组按旧快照翻页、结果按新快照展开"造成组与结果错位。

### 3.5 上样时间列 —— 已查证，真实存在

需求要求"不得用 `r.create_time` 顶替，查不到就报阻塞"。**查证结果：列真实存在，未阻塞。**

`docs/开发基线/01-完整建表.sql:2614`：

```
`testing_start_time` datetime NULL DEFAULT NULL COMMENT '上样时间',   -- det_sample
```

`det_result` 同名列在 `:2431`。测试
`loadedTimeColumnReallyExistsInBaseline` 直接断言基线里这一行文本，
`dateWindowUsesTrustedLoadedTimeColumnNotResultCreateOrEndTime` 断言读口 SQL 里
**不出现** `r.create_time`、筛选片段里**不出现** `r.testing_end_time`。

日期边界按 `Asia/Shanghai` 的 `[startDate 00:00, endDate 次日 00:00)` 换算为**本地壁钟**
`Timestamp` 传给 JDBC，不使用 `date_add(#{endDate}, interval 1 day)`，因此不受数据库服务器
本地时区影响。跨日含首尾已由测试 `boundaryDatesAreBothIncluded` 覆盖。

⚠️ **遗留（非阻塞）**：§12.2 原文要求"当前列 `testing_start_time` 是否在所有适配器中保持此义
需逐路径核对"。本次只核对了基线列存在性与列注释，**未逐个设备适配器核对**该列写入值是否
一律等于"需求发送成功时间"。该核对属设备联调范畴，需现场数据，标 `NOT_VERIFIED`。

未知上样时间保持 `NULL`：不参与命中、排序置后、不用完成时间顶替，并附 `LOADED_AT_UNVERIFIED`
issue（`unknownLoadedAtNeitherMatchesNorFallsBackToCompletedAt`）。

### 3.6 当前有效签名/审核动作

按 `det_result.active_sign_id` / `active_review_id` **指针精确命中** `det_result_sign_record`
动作行，不从全体历史取最大时间猜测（签批记录与报告导出设计 §1 明文禁止）。

链未核验（`sign_chain_state <> 'VERIFIED'`）时**不下结论**：`signature`/`review` 返回 `null`，
改附 `ACTOR_IDENTITY_UNVERIFIED` issue。旧人/旧时间留在历史动作记录里，不由查询侧拼凑。

上传人另取 `active_upload_id` 指针（与 `sent_user_id` 送检人是两个不同事实，不能混用）。

### 3.7 单位快照

`det_result_item.unit`（结果接收时保存的事实），**不 join** `dev_detector_item`。缺失保持 `null`
并附 `UNIT_UNVERIFIED` issue——不用今日字典单位改写既有结果的量纲（§12.4）。
`numericValue` 只在有明确解析依据（`numeric_value` 非空）时给出，原始精度经
`cast(i.numeric_value as char)` 保留；`valueText` 原样保留 `<0.01` 这类表达，不转 0。

### 3.8 权限下推

照抄同模块 `DetSignConsoleMapper` 的 `SmpPermissionScope` 范式（`<sql id="signConsolePermissionScope">`），
复用 `SmpPermissionService#resolveScope`，**未发明平行机制**。`allAccess` 不下推；非 allAccess
且集合为空生成 `and 1 = 0`，不退化为放开全库。权限服务返回 `null` 时按"零可见"处理。
m05 DTO **不含** `scope` 字段，客户端无法注入范围。

### 3.9 LIKE 转义

应用服务把 `% _ \` 转义后再拼两侧 `%`：

```java
"%" + keyword.replace("\\", "\\\\").replace("%", "\\%").replace("_", "\\_") + "%"
```

配合 SQL `like #{...}`，用户输入的 `%`/`_` 只当普通检索文字，不开放 SQL 通配表达式。

### 3.10 `operatorFilter` 三态 / `status` 四态

| 模式 | 实现 |
| --- | --- |
| `SELF_UPLOADER`（默认） | `s.sent_user_id = #{actorUserId}`，按**稳定 ID** 过滤，账号改名后仍可命中（M05-QUERY12） |
| `ANY_PERSON` | 送检人 / 当前有效签名人 / 当前有效审核人 三方 `user_name`/`nick_name` OR 模糊 |
| `ALL` | 不加人员条件，`keyword` 必须为 `null`（否则 400） |

`status` 四态 `UPLOADED/SIGNED/REVIEWED/VOIDED` 映射小写存储值；`ALL` 不加状态条件（已含作废记录）。
拒绝未知枚举与任意 SQL 值（`SignConsoleQueryInput.normalize` 统一 400）。

### 3.11 `allowedActions`（双人制实时计算）

| 状态 | 动作 |
| --- | --- |
| `uploaded` | `SIGN` |
| `signed` | 本人是当前签名人 → `REVOKE_SIGN`；否则 → `REVIEW`（审核人不得是签名人） |
| `reviewed` | 本人是当前审核人 → `REVOKE_REVIEW`；否则空 |
| `voided` | `RESTORE_VOID` |
| 其余（检测中等） | 空集合 |
| 链未核验 | 空集合（不下当前有效动作结论） |

不预判功能权限——预检 M05-038 与正式提交会再判一次，此处只按已核验指针与实际状态推导。

## 4. 响应装配

- 全部 ID 以 `String` 外泄（前端精度安全）。
- `dayNumber` 未知保持 `null`，**不补 D0**。
- `cultureId` 无培养显式 `null`，不补 0。
- 组内排序：检测大类 BGA→VICELL→OSMO→CEDEX → 上样时间 → resultId；未知型号排末尾，不冒充其中一类。
- 组排序：`MIN(上样时间) ASC`，`NULL` 置后，再以 `lab_id / culture_id / 二进制编号` 稳定打破并列。
- 结果身份或 `object_version` 证据不完整 → 抛 `RESULT_PROJECTION_UNAVAILABLE` 失败关闭，
  不返回半张卡片让前端按缺字段猜测。
