## 3. 两个"优先实现 provider"的取证与口径更正（本批关键发现）

任务书要求优先实现 `ExecutionSamplePort`、`RunEventPublisherPort` 的"本地落账部分"。87 号 §3.2 曾把它们归入 **A 组**，结论是"零跨模块前置 ⇒ 唯一缺的是**实现授权**"。**该口径经取证收紧：即使拿到授权，本批也落不了码——缺的是冻结模型的载体位。**

### 3.1 `RunEventPublisherPort`（M07-INT-07）

| 项 | 实测 |
|---|---|
| 冻结模型 `service/port/m07/model/RunEvent` | **4 个字段**：`eventId`(String)、`occurredAt`、`eventType`、`payload` |
| 目标表 `run_event` NOT NULL 列 | **13 列**（`01-完整建表.sql` run_event 段） |
| 模型未承载 | **9 列**：`lab_id`、`culture_id`、`object_kind`、`object_id`、`object_version`、`source_event_key`、`payload_hash`、`publish_state`、`publish_attempts` |
| 其中服务端可派生 | `payload_hash`＝规范化 payload 的 SHA256；`publish_state`/`publish_attempts`＝`LOCAL`/`0` 常量（`mapper/system/RunEventMapper.xml` 已把这两个值写死在语句里） |
| 其中不可派生 | **6 列**：`lab_id`、`culture_id`、`object_kind`、`object_id`、`object_version`、`source_event_key` |
| 类型错配 | `RunEvent.eventId` 是 `String`，`run_event.event_id` 是 `BIGINT` |
| 现行 `source_event_key` 口径 | `RunMeasurementApplicationApplicationServiceImpl:854` 已实现该语义：`"M07:" + eventType + ":" + requestId`。**键的构成依赖 `requestId`，而 `requestId` 不在冻结模型里** |
| 设计侧派生规则（均为模式特定） | `数据库JSON与事务契约.md:74`（消费外部事件＝owner+eventId）、`业务观测采样与告警交接.md:20`（SAMPLE_CONFLICT＝冲突身份+hash 的 SHA256）、`审阅收尾执行器与接续契约.md:21`（接管／交接＝内部命名空间＋userId/requestId 摘要） |

**结论**：M07 的本地落账能力**已经存在**，但它存在于已接线写口内部（`RunEventMapper#insertEvent`，唯一调用方 `RunMeasurementApplicationApplicationServiceImpl:853`，事实来自业务流的调用点局部变量）。要把这套语义泛化成 Port provider，必须给 `RunEvent` 补 `labId/cultureId/objectKind/objectId/objectVersion/actorUserId/requestId` 载体位（至少 `object` 三件套 + `requestId`）——这是 **PKG-00 §6.7 冻结签名载体变更**，属本批禁区；替代路径是自造一套 `source_event_key` 派生规则，会与上述四条已核准规则冲突（AGENTS.md §10 禁止编造、§8 状态变更必须校验幂等键）。
