## 1. 四项 P2 的处置

### 1.1 P2-1｜例外作用域从"无上限跳过"改为"带命中上界"

**批 86 写法**（G-4 引入）：`if (m04OwnedScope || registeredException) continue;` ⇒ `mapper/resource/`、`mapper/detect/` 两个目录的 XML **完全不检**。今天没命中不等于将来不能在这里静默吸收跨模块直读——白名单没有上界。

**上界取值前置实测**（本批，与判据同一套抽取口径 FROM/JOIN/INTO/UPDATE）：

| 目录 | XML 份数 | 对 M04 私表（`prc_` 前缀族 + 4 张 workflow 表）命中 |
|---|---|---|
| `mapper/resource/`（M03 面） | 23 | **0 文件 / 0 命中** |
| `mapper/detect/`（M05 面） | 20 | **0 文件 / 0 命中** |

**修法**：新增 `REGISTERED_EXCEPTION_CEILINGS`（`作用域 → 命中上界`，当前均钉 **0**）。例外目录不再 `continue` 跳过，而是**照旧逐份扫描并计数**，循环后对每个登记作用域做：

1. `assertTrue(该目录实际扫到的 XML 数 >= 1)`——否则上界断言会因目录改名/移动而空转（消息里同时打印份数，如"该目录扫描 23 份"）；
2. `assertEquals(上界, 实际命中数)`——命中即红，消息点名"抬高需裁决并同步登记"。

**语义收窄**：登记例外的含义从"该目录可以读 M04 私表"改为"该目录的归属不由本类裁定"。要抬高上界必须先出跨模块裁决并同步本表，不能靠白名单吸收。

### 1.2 P2-2｜扫描量下限贴近实际规模 + `mapper/lab/` 不再整目录放行

**下限**：`scanned >= 40` → `MIN_SCANNED_MAPPER_XMLS = 150`。实测全仓 Mapper XML **160** 份（system 54 / lab 32 / resource 23 / detect 20 / alarm 12 / device 9 / process 7 / smp 3）。40 只能证明"没空跑"，漏掉一整个中等目录（如 lab 32 份）仍会通过；150 使"漏扫任一个 ≥10 份的目录"即变红，且新增 XML 只增不减、不会误报。

**`mapper/lab/` 的真实问题**：批 86 把整个 `/mapper/lab/` 目录当作"M04 自有作用域"放行（**32 份 XML**），实测只有 **1 份**（`LabWorkflowNodeMapper.xml`：4 处 `from lab_workflow_node` + 1 处 `into lab_workflow_node`）命中，其余 31 份因此完全不受检——白名单把"归属待裁"这件事掩盖成了"M04 自有"。

**修法**：

|---|---|---|
| M04 自有作用域 | `/mapper/process/` **或** `/mapper/lab/` | 仅 `M04_OWNED_XML_SCOPE = /mapper/process/`（7 份） |
