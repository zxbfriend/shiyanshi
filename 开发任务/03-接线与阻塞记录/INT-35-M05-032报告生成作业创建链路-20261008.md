## 2. 最小可落码子集判定

派发希望"优先只创建 root 行并返回作业 ID/状态，且 root 行能被 INT-34 的 M05-033 读到"。经第一性复核，该最小子集**不能在不伪造冻结集合的前提下落地**，理由分三层，逐层可机械核验：

### 阻塞①（决定性，本批新发现）：032 唯一输入 `confirmationToken` 无 lawful 生产者
- `M05ConfirmationTokens.Purpose.REPORT_JOB` 在 `src/main/java` 里**零引用**（`grep "Purpose.REPORT_JOB"` = 0 命中；审计枚举的 `DET_REPORT_JOB` 是无关命名）。既无 `issue` 也无 `verify` 调用方。
- 唯一 lawful 签发入口是 **M05-031 预览**，而 031 仍抛自身编号 501。
- 结论：032 是 031 的**纯下游消费方**。root 行的 `content_manifest`（purpose/results[]/template/versions）、`selection_snapshot`、幂等 `request_payload_hash` 只能来自令牌；客户端不提交、032 也无 lawful 来源自行重建。任何"只落 root 行"的实现若要填充这些列，等价于伪造冻结集合——踩红线，禁止。

### 阻塞②（跨模块，本批禁改 M02）：同事务冻结锁需要 M02 加锁读出口，Port 面没有
- 设计 §2 冻结顺序"M01管理守卫→实验室升序→设备升序→样品升序→结果升序"，§3 要求"每次任务和其结果索引**同事务**写完后才返回 jobId"。
- `service/port/m02` 下**无任何 `FOR UPDATE` 读出口**（M05 依约不得注入他模块 Mapper/内部表）。
- 这不是"跨模块不能加锁"——M07 `PlanReplacementPort` 已承载 `FOR UPDATE`（INT-23 已纠正该误判）；缺的是给 M02 Port 增一个同事务加锁读方法，属 M02 批次 + 总控裁决，不在本派发允许面内。

### 阻塞③（外部依赖，仅影响 RENDERING→READY 与 034）
- 核准 TemplateProfile 载体（`rendererVersion`/`font_sha256`/`cell_mapping`/`source_sha256`）与 PDF 渲染库均未落地。
- 关键界定：渲染器**不阻断** `PREPARING` root 行本身（渲染在设计里就是事务外后置阶段）；因此本条不否定"最小子集"的形态，但与①②叠加后，032 连"停在 PREPARING"所需的 lawful 输入都不具备。M05-034 的 `READY`/下载仍因本条 `BLOCKED_EXTERNAL`。
