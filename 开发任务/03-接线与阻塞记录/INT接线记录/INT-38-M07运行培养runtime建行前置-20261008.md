### 2.5 对 INT-22 §8.1 项 1 的实质更正

INT-22 写："归属干净：该表是 M07 自有……**不改 Port 签名、不动 `PortSignatureSnapshotTest`、不需要跨 owner 授权**。"

- `subflow_id` / `subflow_code` / `definition_hash` / `definition_snapshot` 四列 `NOT NULL`，注释逐列写"M04二级流程""固定流程定义，SHA256""M04定义/步骤/图片版本"，`数据库JSON与事务契约.md:27` 更明写"M04导出固定内容"⇒ **M04 模板包事实**；

### 3.2 阻塞②｜"同一事务边界"在原则层面无宿主（缺的是事务边界宿主）

任务书要求 3 要"建行与对应运行动作处于同一事务边界"。该"对应运行动作"= 写 workflow/step 完成事实，而：

- `RunWorkflowInstanceMapper.xml` 全文只有 1 条 `<select>`（`:25`），零 `<insert>`；
- `RunWorkflowStepMapper.xml` 零 `<insert>`；
- 全仓 Mapper XML（实测 163 份）里指向 `run_*` 表的 `INSERT INTO` 恰为 3 处：`RunConfirmationMapper.xml:125`→`run_confirmation`、`RunEventMapper.xml:11`→`run_event`、`RunManualResultMapper.xml:47`→`run_manual_result`。

⇒ 完成事务连自己的事实都无处写。要么 runtime 行先于它所守卫的工作流实例存在（与 `数据库JSON与事务契约.md §3` 的事务定义冲突，且 `connection_workflow_id` 无值可写），要么本批造一个没有对应运行动作的孤立 `INSERT`。两种都不满足要求 2/3（详见 §4）。

### 3.3 阻塞③｜无上游写路径可挂靠（方向性冲突）

今天唯一带真实写事务的 M07 口是 018/019/020，三者都**以 runtime 行为前置**、缺行即 `CONFIGURATION_INCOMPLETE` 失败关闭（§2 表），且全类对 `run_culture_runtime` 只有一次 `updateConfirmedGlucoseByVersion`（UPDATE），零插入调用。

同时 `RunCultureRuntimeMapper` 是 M07 自有 Mapper 中唯一被 `M04M07CrossBoundaryContractTest:142-143` 的 `M07_OWNED_MAPPERS` 白名单认可的运行守卫 Mapper——写通道形态是设计明确冻结过的。

⇒ 让确认路径顺手建行，等价于用"我需要一个前置守卫行"去证明该守卫行合法存在，直接抵触 Mapper 面三处声明与 AGENTS.md §8"状态变更必须校验当前状态……不允许无条件覆盖"。

## 4. 为什么"只加一个 insert 原语"不能算部分交付

按 INT-22 §7 的三条件（逐列直读零推导 / 缺行 fail-closed / 判定性缺值传 null）逐条对照：

1. **无消费者**：六条阻塞里没有任何一条能被一个无人调用的 Mapper 方法解除。M07-019/020 仍会读到 null 行并抛 `CONFIGURATION_INCOMPLETE`——任务书要求 3 里"M07-019/020 可见缺行阻塞被收窄"这一验收点**客观不成立**。
2. **它不是最小切口，是最大绕路**：孤立 insert 要么被某个已接线口调用（破坏 §3.3 的方向性口径），要么不被调用（死代码）。AGENTS.md 明确"不做半成品实现"，多代理纪律亦禁止造无归属的在途件。
3. **它必须改写三处职责声明**：而那三处声明正是"建行职责归哪个组件、在哪个事务里发生"这一未裁事项的唯一载体；改了声明等于用代码替 owner 做裁决。
4. **门禁联动**：`M04M07UnwiredPrerequisiteContractTest:200-201` 的 `M07_XML_WRITE_TARGETS` 与 `:811-814` 的 015/022 阻塞标签会与实际写面漂移，制造新的注释债（本批不引入）。

⇒ 走任务书要求 4：钉桩，不落码。
