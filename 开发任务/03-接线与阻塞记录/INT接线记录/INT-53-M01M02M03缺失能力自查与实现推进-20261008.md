## 2. 本批实际推进的子项与选择理由

优先级按任务要求：先做「小而可独立闭合」「owner 前置且能解锁其它模块」「契约+表+错误码齐备、不依赖共享注册表/SQL/前端」的条目。

### 5.1 M02-212 `data` 载荷形状偏差 —— BLOCKED_DESIGN

`docs/详细设计/02-实验室与资源管理/检测项目开关与规则接口契约.md` §1/§2 冻结 `data` 为**对象**：`detectorId`、`detectClass`（现有效分类）、`items[]`、`data.managementRevision`（样例中外壳与 data 各带一份 `"managementRevision": "13"`）。当前实现返回 `data` 为 `DetectorItemOptionView[]` 数组，`detectClass` 与逐项版本无 HTTP 出口。

### 5.2 M01→M03 事实源 Port 裁决包 —— BLOCKED_PORT

M03-003/004/005/011/025/026/027/030 的自建阻塞口径（`GrantApplicationServiceImpl.java:67-70`）：A01 完整授权列表与 A02/A05 候选/快照需要 **M01 部门树、用户候选、字典 provider** 与 **M02 实验室/工程候选 provider**，跨模块 Port 尚无实现。

这是 M01 侧 owner 前置，但落码需要总控开两个窗口，非本批可自取：

- (a) **契约登记窗口**：`PortSignatureSnapshotTest` 按硬编码 `FROZEN_PORTS` 登记表逐个 `Class.forName`（HEAD 冻结为 44 接口 / 72 方法，见同文件 `:217`），不做 `service/port/mXX` 文件系统扫描，因此新增未登记的 Port **不会**让快照变红——但正因为这样，绕过登记就等于制造「代码里有、冻结快照里没有」的第三类漂移。是否把新 Port 写入 PKG-00 冻结登记表与 `FROZEN_PORTS`，属总控裁决。
- (b) **共享注册表窗口**：provider 适配器自有的 Mapper 必须进 `FullSystemSkeletonGateTest.PORT_ADAPTER_ALLOWED_MAPPERS`（该表按 `mXX` 白名单校验，见同文件 `:425/:500`），改动即触碰共享注册表。

建议签名沿用既有单方法先例 `RoleCandidateFactsPort` 范式：`M01DepartmentTreeFactsPort#departmentOptions(query)`、`M01UserCandidateFactsPort#userCandidates(query)`、`M01DictOptionFactsPort#options(dictType)`，均"单 Request 模型入参 + 单 Response 模型出参"（满足快照的 `portMethodsUseSingleModelRequestAndResponse`），返回 M03 只读视图、不暴露 M01 Mapper 类型。裁决包已在本节成型，等总控开窗。
