## 4. M03-003 / 004 / 005 / 006 / 007 / 039 逐条阻塞原因

骨架现状（快照 HEAD）：M03-003/005/006/007 为无标志的普通 501 条目（`ProjectApplicationServiceImpl` 三方法全部 `throw SkeletonNotImplementedException`）；M03-004/039/044 为 `legacy: true`。

### M03-003（`GET /resource/project/options`，P03）— BLOCKED_INPUT / BLOCKED_DESIGN

- 冻结契约要求候选集按 `field ∈ {DEPT, LEADER, LAB, TAG}` 与 `purpose ∈ {PROJECT_CREATE, PROJECT_EDIT}` 返回 `items/total/defaultLabIds`，其中 DEPT/LEADER/TAG 属 M01、LAB 属 M02。
- 现状：`service/port/m01` 仅登记 ActorContext / FunctionPermission / ManagementRevision 三个身份 Port；`service/port/m02/LabAuthorizationPort` 只有 `prepareUserEdit`、`replaceUserLabs`、`removeUserLabs`，**没有实验室候选读方法，也没有 adapter**。37 为本包登记的「需接入 Port」面同样只有 `M03→M01: ActorContext / Permission / managementRevision`。
- 结果：不提供跨模块 Provider Port 就无法在服务端取候选与资格，而 AGENTS.md §8 与本包 `forbidden_actions` 禁止直查 M01/M02 Mapper 或内部表，也禁止发明平行机制。
- 附加：详细设计 §7.4 P03 冻结「`defaultLabIds` 仅 LAB 提供」「Q30 只读权不授予完整编辑候选」，资格判定口径需与 M01/M02 Provider 一同裁决。

### M03-004（`POST /resource/project`，新增）— BLOCKED_DESIGN

- 骨架冻结为 `legacy: true` + `dialect: LEGACY_FLAT` + `replacedBy: M03-004`（自指），实现在 `ResProjectApplicationServiceImpl#insertResProject → IResProjectService#insertResProject`。
- D1 使 `legacy` 与 `wired` 互斥：在本包内把它翻成 `wired` 会直接违反冻结断言（`M03SkeletonContractTest.LEGACY_IDS` 含 M03-004）。
- 正确出口是把该旧口的规范化/停口并入「停旧口」批次，由总控分配窗口；本包不得单方面改断言迁就实现（39§2.5）。

### M03-005（`PUT /resource/project/{projectId}`，P05）— BLOCKED_INPUT / BLOCKED_DESIGN

- 除 M03-003 同一批候选/资格 Port 缺项外，写链路的 operationCode 未登记：`service/guard/ManagementOperation` 当前只有 `M03_014/019/020/022/023/024`，**无 `M03_005`**；`AuditObjectType` 亦无 `RES_PROJECT`；`AuditPolicyRegistry` 的 M03 行仅覆盖上述 6 条，且 `require(operation)` fail-closed——未登记即在写库前被拒。
- 39§3.8 要求 operationCode/审计策略走「登记小批次先行合入，禁止多包并行改注册表」。`AuditPolicyRegistry`、`ManagementOperation`、`AuditObjectType` 都是多包共享串行文件，须由总控分配。
- P05 还冻结「不允许移除仍有未删除批次的实验室；任何一项失败全回滚」（Q05），依赖 M02 实验室引用保护口径与批次可读面。

### M03-006（`POST /resource/project/{projectId}/delete-preview`，P06）— BLOCKED_INPUT

- 详细设计 §7.4 L950 冻结：允许删除时 `snapshotToken` **必有**、`expiresAt` 有值；阻断时 `token` 与 `expiresAt` 为 `null`；token 由服务端签名或服务端存储，绑定 actor、动作、目标版本、全局版本、排序后的批次 ID/版本及 10 分钟技术有效期，不可由客户端自报哈希。
- 全局版本侧可达（`ManagementRevisionSource` 已有 `M01ManagementRevisionSourceAdapter`），缺的是**签名密钥**：`nacos-config/` 目前只有注释态 `# proof-hmac-key: <运维注入，≥32 字节随机串>`，M05 同类组件依赖的 `futurefab.m05.confirmation-hmac-key` 也未在任何配置中落地；`M05ConfirmationTokens.requireKey()` 在密钥不足 32 字节时抛 `DEPENDENCY_UNAVAILABLE`。
- `DEPENDENCY_UNAVAILABLE` **不在** M03《错误码全集》登记码名族内（M03 为 INPUT_INVALID / READ_ONLY_FIELD / PROTOCOL_UPGRADE_REQUIRED / CODE_CONFLICT / REFERENCE_EXISTS / VERSION_CONFLICT / REQUEST_CONFLICT / DELETE_SCOPE_CHANGED / PREVIEW_EXPIRED / STATE_CONFLICT / MANAGEMENT_CONFLICT / NOT_FOUND / PERMISSION_DENIED / ASSIGNMENT_DENIED / FACTS_UNAVAILABLE / POLICY_NOT_READY / RETRY_LATER / LAB_AUTHORIZATION_UNAVAILABLE）。密钥来源与错误码归属须由总控裁决。
- 并发冲突：同一包 `service/impl/application/m03` 内，TP-M03-05 正在落 `BatchSnapshotToken.java`（batch 专用 HMAC 令牌，形态 `batchId.version.expiryEpochSec.hmacHex`，快照中为未跟踪）。项目侧令牌应复用/扩展同一机制而非再造第二套，这本身需要跨包协调。
- 顺序问题：token 唯一消费方是 P07（M03-007），而 M03-007 当前被停口窗口阻塞。只签一个无人校验的 token 属半截实现。
- 37 另标注 M03-006 需复核脱敏，属未裁决项。

### M03-007（`POST /resource/project/{projectId}/delete`，P07）— BLOCKED_DESIGN（需总控停口窗口）

- `SkeletonEngine.checkDialect` 的 D6 判定：`e.legacy && rep.wired && e.stopPending == null` ⇒ 违例。M03-039 的 `replacedBy` 正是 M03-007；因此一旦把 M03-007 置 `wired`，就必须**同批**把 legacy M03-039 置 `disabled`。
- 而置 `disabled` 要改 `LegacyResourceEndpointGuard` / `LegacyResourceEndpointGuardImpl` / `ResProjectController#remove`，并同步 `M03SkeletonContractTest` 中冻结为空的 `disabledRegistry` 断言。`stopPending` 豁免集在测试里冻结为 `{M03-041}`，没有本条出口。
- 按本轮任务要求第 4 条：一旦必须改 `LegacyResourceEndpointGuard` 即停止并回报，由总控分配窗口。该文件在 37 的并行冲突标注中同时属于 TP-M03-05/06/07。
- P07 自身语义还依赖 M03-006：锁后复核 Q20、重比快照、比对 PROJECT/DELETE 与全部 BATCH/DELETE 结果，且不能扩大已确认清单（L948 冻结：检查完整项目范围，不按当前用户可见培养计数，存在则 `REFERENCE_EXISTS`）。

### M03-039（`DELETE /resource/project/{projectIds}`，legacy 旧口）— BLOCKED_DESIGN
