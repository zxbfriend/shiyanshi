## 5. 登记项（不自行放宽，交总控/work2 判）

- **U-1 管理集合观察项**：读取资格取"当前 ∨ 历史"两条集合，`manageCultureIds` 不参与（与 BIND-Q01 一致）。
  现行 SQL 来源下管理身份同时命中读取集合，`manage-only` 是防御性形态而非现网路径；
  本批把它固化为 **DENY**（失败关闭方向），若未来出现 manage-only 事实源须另行裁决，不由本端口放宽。
- **U-2 调用成本**：端口按单条 `cultureId` 判定，而每次判定都要重跑一次 `resolveScope`（十余条范围 SQL）。
  消费方在同一响应内应**按去重后的 cultureId 逐条判定**，不得对每条观测原样重复调用；
  若 M02 需要"同一 EvaluationStamp 批量 1—100 条"形态（跨模块契约 §3 的 `evaluateActions` 方向），
  属新增契约面，须先报总控再开，本批不预设。
- **U-3 与共享 SQL 的关系**：本端口不改 `SmpPermissionQueryMapper.xml` 的可见/历史语义（含旧 `permission_type` 集合与
  `det_approval_assignee` 审批人来源）。收紧旧 SQL 是独立变更评审（`MemberIdentityFactsPort` Javadoc 同口径声明），
  本批只在其结果之上判读，因此**不宣称**已消除旧来源与 `grant_type` 新模型的差异。
- **U-4 绑定两表仍无生产写入方**：读侧就绪不等于已有真实绑定历史（62 号 §1 同判），M02 不得据此假定现网可命中关联。

## 7. M02 接线约定（给 work2 的交付件，本批不代做）

1. **调用点**：M02-001 `GET /lab/observations/current`、M02-002 `GET /lab/observations`、M02-003 详情
   权限三元组的第三因子（"关联培养读取资格"）改调本端口；前两因子仍分别由 M01 功能码
   （`lab:observation:query`）与 M02 `LabAuthorizationService`（设备/发生时实验室范围）判定，**不得由本端口代答**。
2. **入参构造**：`ActorContext` 只能由 M01 服务端会话适配器解析得到（M02 现有 m01 入向链路即可用），
   `cultureId` 取绑定解析出的真实关联值；浏览器自报的 cultureId/角色/范围不参与判定。
3. **状态到响应的映射（错误映射登记）**：
   | 端口返回 | M02 应做 | 对外表达 |
   |---|---|---|
   | `ALLOW` | 允许把该关联的 `cultureId`（及其有权可见的祖先投影）渲染进响应；仍须自行判对象存在/状态 | 正常输出 |
   | `DENY` | **不输出该关联的对象 ID**（观测契约 §4 字面）；行本身按契约以"无权关联"形态脱敏或按 404 语义处理，不得据原因码区分存在与否 | 403/404 或脱敏行，由 M02 契约选一并登记 |
   | `UNAVAILABLE` | 整次请求失败关闭，**不得**当作"无权限"过滤掉、不得返回空集合、不得降级缓存 | 503 `DEPENDENCY_UNAVAILABLE` |
   | 抛 `ManagementGuardRejectException(INPUT_INVALID)` | 视为调用方构造错误（缺可信上下文或畸形 ID），修正调用点 | 400 |
4. **current/lastGood 分别判定**：观测契约 §4 要求 `current` 与 `lastGood` 分别鉴权，
   二者关联不同培养时必须各调一次，不得用其一的结论覆盖另一。
5. **翻页与失效**：每页重新调用（本端口不缓存），不引入长期票据；`evaluatedAt` 只用于链路核对。
6. **解除范围**：只解除 59-M02 台账 §3 的 **BLOCKED_PORT(G-1)** 半边；
   ②绑定修订时效载体、③`obs:query` 部署参数（TTL/最大 ID 数）、④上游接收引擎、⑤`deviceKind` 词表交集（G-2/G-2a）
   四项前置**原样不动**，M02-001/002 在此之前仍应保持诚实 501、不翻 `wired`。
