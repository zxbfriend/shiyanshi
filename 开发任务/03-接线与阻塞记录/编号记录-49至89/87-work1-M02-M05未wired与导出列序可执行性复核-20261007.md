## 4. 本批新发现的系统性阻塞（对既有登记的加重，只登记不修）

上一批把菜单阻塞写成"`detect:correction:*` 无种子"。本批全量实测后需**加重口径**：

```
grep -c "INSERT INTO sys_menu" docs/开发基线/02-基础数据初始化.sql   = 0
grep -c "lab:"                docs/开发基线/02-基础数据初始化.sql     = 0
grep -c "detect:"             docs/开发基线/02-基础数据初始化.sql     = 0
01-完整建表.sql 里 sys_menu 出现 1 次（仅 CREATE TABLE）
03-初始化结果核验.sql 出现 25 次（核验查询）
05-开发调试测试数据.sql 出现 3 次（仅一条无 perms 的占位菜单 9202，且不在安装链）
```

**结论**：新系统授权安装链（01→02→03）**不含任何业务菜单/权限种子**。因此 M02/M05 的**全部** `@RequiresPermissions`
接口在 HTTP/浏览器层都是 `BLOCKED_MENU`，不是仅更正族；这直接约束"printer 试点先做"的可达上限——
**即使总控冻结列序并落码头/删列，也到不了 HTTP_VERIFIED/BROWSER_VERIFIED，除非先补菜单种子。**
`docs/开发基线/**` 属只读基线且不在本批文件范围 ⇒ 只登记，请总控裁决种子批次的归属与顺序。
