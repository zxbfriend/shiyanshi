### 2.1 M03-API01 未结束业务事实（技术上可写，前置未清）

口径（现行权威，`docs/详细设计/03-项目与培养管理/详细设计.md:1102`）：

但**本端口要读的判别列没有写入方**——见下面 P-2。这一区别是它与 §2.3（整表零覆盖）的差别，
不是"可以直接交付"的差别。

三项前置未清（任一未决即不落码）：

1. **P-1 不是开放问题：契约已把权威判给 M03，M02-234 现状属"自创终态"缺陷（上报协调，不自行改）。**
   权威原文 `docs/详细设计/02-实验室与资源管理/详细设计.md:164`：
   "项目/批次/培养未结束定义**由 M03 提供统一查询，M02 不自创终态**"，同句还要求
   "依赖计数不可用应报错，不能用 0 假装可停用"。现状是 M02-234（`LabLabApplicationServiceImpl.java:555-605`）
   用 `mapper/lab/LabLabMapper.xml:132-150` 直查 M03 私表自算三类计数，其中培养按**旧列**
   `culture_status != '1'` 统计（`:1709`，char(1) "0进行中 1已完成 2已终止"），与新 `lifecycle_state` 七态
   不同源不同义：不区分 DRAFT/NOT_STARTED/EXPIRED/DELAYED、不按项目/批次去重，
   且旧列为 NULL 的行会被 SQL 三值逻辑直接排除（等价于"用 0 假装可停用"）。批次计数同样不同源：
   `countActiveBatches` 用 `res_batch.batch_status != '1'`（`:1572`，char(1) "0进行中 1已完成 2已暂停"，同样可空），
   而 API01 的"未结束批次"定义是**由未结束培养按批次主键去重**，与批次自身状态列无关。另登记两处次生偏差：

   M02 自身两份文档字段名不一致（`02-详细设计.md:164` 用 `unfinished*Count`，
   `实验室主数据逐接口契约.md:177,190` 用 `projectCount/activeBatchCount/activeCultureCount`）。
   ⇒ 对 M03 的含义：provider **就是**契约指定的唯一权威，交付它不算另建平行计数；
   但在 M02 改消费之前，两处结论并存且可能互相矛盾（M02 判"可停用"而 M03 判"有未结束业务"）。
   故本轮不自称"就绪即交付"，而是把缺陷上报总控协调切换批次；**M02 文件不属本包，M03 不改**，
   并要求 provider 与 M02 消费切换同批验收，不留"两个权威"窗口期。
2. **P-2 "未知状态"落地口径未裁决，且按字面执行会让预检 100% 不可用。** 全仓唯一的 `res_culture` INSERT 是
   `mapper/resource/ResCultureMapper.xml:129 insertResCulture`，其列集合
   （`:132-152` 列清单＋`:154-173` 值清单）**不含 `lifecycle_state`、也不含 `facts_status`**；XML 中 `lifecycle_state` 的写入者只有两条
   迁移语句（`:331` withdraw→'DRAFT'、`:349` rebook→'NOT_STARTED'），都要求行已存在。调用方是旧口
   （`ResCultureController.java:214`、`ResBatchServiceImpl.java:477,524`）。因此**今天任何新建培养行都是
   `lifecycle_state=NULL` 且 `facts_status='REVIEW'`**（`:1737` DEFAULT 'REVIEW'；`:1800` `ck_m03_culture_facts`
   仅 READY/REVIEW；`:1820` `ck_m03_culture_ready` 已把"READY⇒状态非空"写死，即库本身承认这类行是"未核验"）。
   两条候选口径：
   - A（契约字面）：NULL 状态/`facts_status<>'READY'` ⇒ 整次调用 503 `DEPENDENCY_UNAVAILABLE`。
     后果：只要实验室里存在任一旧路径创建的培养，M02 停用/删除预检永久 503，直到数据被核准或写侧接管。
   - B（保守计入）：NULL/REVIEW 行计入"未结束"从而阻断。可用性好，但**违反"不猜 0"以外的另一侧**——
     它把"未知"当成已知事实参与业务结论，且无法与真实未结束区分。
     注意同表生成列 `m03_live_code`（`:1781`）的注释已就同类问题做过一次选择："取消或删除释放，
     **未知状态保守占号**"——即基线在"占号"这件事上把 NULL 状态按保守值处理，而不是报错。
     该先例可支持 B，但占号与"未结束业务计数"是两个不同决策对象，不能直接搬用，仍需显式裁决。
   M03 倾向 A（契约字面＋与 `:1795`"来源无法核准则 503 阻断，不用猜测名称或零计数通过"一致），
   但 A 会立即影响 M02 可用性，**属改变既定契约可观察行为的决定，须先报告后动**（用户指令原文）。
