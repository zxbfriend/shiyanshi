## 2. 复审 P1-1 修复（本批唯一阻断项）

**缺陷**：第 6 次旧密码失败锁定路径在事务内已 `revokeCurrentSession` 并携带 `revokedSessionKey`，
但出口先 `throw pendingRejection`，Redis `login_tokens:` 清理永不执行；而 TokenService 校验只读 Redis
（不校验 DB `session_version`），锁定后旧 token 仍可用。

**修复**（`PasswordManagementApplicationServiceImpl`）：

1. 出口顺序改为**提交后 → 清 Redis（凡有 revokedSessionKey，含拒绝路径）→ 再抛拒绝 / 返回回执**；
   DB 失败计数与锁定仍先提交（事务边界不变）。
2. 新增 `clearRevokedSessionCache`：拒绝路径 Redis 清理抛错时只记 warn 日志（不带口令/摘要/会话键原文），
   **原拒绝照常抛出**；成功路径维持 USR04 同口径（清理失败不回滚已提交事实，回执失败照常抛出）。
3. 测试同批翻正（`M01SelfPasswordChangeWiredWriteContractTest`）：
   - `sixthWrongOldPassword…`：`redisDeletes.isEmpty` 翻正为
     `redisDeletes == ["login_tokens:" + SESSION_KEY]`，并钉 `revoke < redis-delete` 顺序；
   - `wrongOldPassword…BelowThreshold…`：非锁定普通失败**不清 Redis** 按实现语义重新钉住
     （无撤销即无 revokedKey，只有成功与第 6 次锁定携带）；
   - 新增 `lockPathRedisCleanupFailureNeverMasksCommittedRejection`：Redis 抛错时锁定截止与撤销
     已提交、清理已尝试、异常仍为 `OLD_PASSWORD_INVALID`。
