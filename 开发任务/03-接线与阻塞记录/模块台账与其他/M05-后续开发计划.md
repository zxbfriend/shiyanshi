## 3. 早期阶段任务分解（历史参考，现按 B0—B10 执行）

### P0：冻结基线与接口清点

1. 以 `docs/开发任务/00-全接口契约骨架清单.json` 的 M05 编号为清单，核对 Controller → ApplicationService → Mapper／Port → 前端 API／页面，标记 `IMPLEMENTED`、`CONTRACT_TESTED`、`HTTP_VERIFIED`、`BROWSER_VERIFIED` 或阻塞状态。
2. 对照 `docs/开发基线/README.md` 的三份空库安装文件、来源清单与当前目标字段字典，列出 M05 表和约束缺口。这里只做静态核对；库结构变更另立经授权的数据库任务，不执行 `history/sql`。
3. 审计结果、样品、签批记录旧通用 CRUD 旁路；确定兼容入口如何转新应用服务、如何拒绝不安全直改。前端以实际 `futurefab-frontend/packages/app-smp-data` 和 `sdk-smp-api` 为准。

完成条件：每个接口有唯一拥有者、前后端入口、依赖、数据库字段和验证层级；DEP-01—07 的可用性有证据或明确阻塞状态。

### P1：送检与采集链

1. 先完成队列真实位置投影、规则读取和只读预检（M05-006／007）。位置由 M02 核准配置生成，区分 DRAFT、RESERVED、RUNNING、UNKNOWN、COMPLETED、RELEASED；跨日活动占位不得从当天列表消失。
2. 实现暂存、单发、列发、本人删除与批量删除（M05-008—013）及操作回执查询（M05-014）。输入白名单、稳定 userId、对象版本、位置代次和管理版本同时校验；部分接受逐项呈现，UNKNOWN 只查原请求，不盲目重发或释放。
3. 建立持久派发意图、设备调用与接收事件流水；按设备任务身份＋样品代次去重，保存原包、项目终态、完整性和可信时间。接收迟到旧任务不能覆盖当前结果或当前位置；位置只凭终结证据释放。
4. 同步改工作台 UI／SDK：本地未提交输入与服务端队列按位置／代次合并；展示逐项状态、冲突及恢复入口；不把设备接受当检测完成。七型号按真实能力矩阵逐个接入，不以单一模拟器代表全部。

硬依赖：DEP-01—04、DEP-06；培养关联不可用时不能开放真实发送。验收：正常／拒绝／部分接受／响应丢失／重启恢复／重复请求／旧事件迟到／跨日占位／本人限制，至少完成契约、HTTP、浏览器与逐型号实机分层记录。

### P2：结果操作与签批

1. 基于可信采集结果完善记录列表、详情、签名台查询及当前有效结果投影（M05-015—020、045—047）。保留 M05-015 的 `BLOCKED_DATA`，待自然形成或另行授权准备符合契约的数据后补正向验收。
2. 实现改样品号、人工／自动上传与精确撤回、异常、单项作废／恢复、结果删除预检、左侧清空（M05-021—030）。右侧结果删除与左侧腾位分开；所有动作写版本、精确动作记录和审计，阻止通用 CRUD 旁路。
3. 实现签名台动作预检及六动作（M05-038—044）。签名／审核绑定完整不可变内容快照和 hash；审核人与有效签名人不同；撤销仅当前动作本人；一次确认集合全量重验后原子提交，冲突整批回滚。
4. 同步改结果页、签名台、签批记录页和 SDK：按服务端 `allowedActions` 展示、预检确认、管理 revision、409 冲突刷新、历史版本与证据质量提示。

硬依赖：DEP-01／02／03／05／06／07；实际结果来源还依赖 P1。可在 P1 实机联调期间，用隔离库中有来源证据的样例实现状态机与签批契约测试，但不能据此宣称采集链已验。验收重点：跨实验室隔离、仅历史分享不可写、审核资格、重复提交、并发版本冲突、签后结果不得改写、失败事务无半条签批记录。

### P3：受控更正

1. 建立唯一当前有效结果解析器：无更正读原版，有更正只读已批准的完整新 revision；版本或 hash 不一致返回 `RESULT_PROJECTION_UNAVAILABLE`，不能退回旧值。
2. 实现预览、提交、决定预览、双人批准／拒绝、撤回、详情和分页（M05-001—005、048—049）。预览固定候选 hash、基线、证据和影响范围；批准同事务写新 revision、当前指针、双人签名、审计及回执。旧结果、旧签名、旧文件保持不可变。
3. 列表、统计、详情、签批、报告、M05 对外结果 Port 全部改用同一有效版本；已更正版普通改写返回 `USE_CONTROLLED_CORRECTION`。与 M07 交接 schemaVersion=2、旧候选失效和精确版本消费，消费者未兼容前不开放批准写入口。
4. 前端增加更正差异、原因、不可变证据、双人审核和历史链；针对 403／409／STALE 给出准确提示。

硬依赖：P2 不可变版本与签审事实，DEP-01／02／06／07，以及 M07 消费兼容门槛。验收重点：同人自审拒绝、基线变更转 STALE、同键回放、证据不足拒绝、批准后旧报告不变、失权和归档不可读时失败关闭。

### P4：报告任务与导出

1. 实现预览、提交、任务查询、受控下载（M05-031—034），并让旧打印／导出入口 M05-035—037 转同一任务服务。预览按有权批次全日期选择并显示范围、数量、排除原因；SINGLE_RESULT 保持单份范围。
2. 提交时冻结结果 ID、当前有效版本、签批与更正证据、模板／映射版本及 manifest hash；事务外异步渲染 PDF、按培养 Excel、按日期 Excel。任务按 PREPARING→RENDERING→READY／FAILED 处理，真实物理打印另记录 SUBMITTED／UNKNOWN，不把“打印服务接受”写成纸张已打印。
3. 文件写服务端受控存储，校验类型、大小、页数／sheet、hash 后发布；查询和下载按原用途与全部冻结对象重新鉴权。更正后新报告另建任务，旧文件不覆盖；PDF／Excel 附更正说明。
4. 前端显示批次全日期提示、实际范围、任务进度、失败重试、版本和历史文件提示；文件内容按原 PDF 8 页和两种 Excel 模板逐页／逐 sheet 回归。

硬依赖：DEP-01／02／05／06／07，P2 结果和签批投影；若包含更正结果则依赖 P3。文件存储、打印服务与模板是另需核准的外部依赖。报告任务实现可与 P3 并行，但开放更正报告前须接入统一有效版本。

### P5：联调与交付门槛

1. 对每包运行相应编译、单元／契约、SQL 映射及并发测试；再按 HTTP、浏览器、设备／文件服务实测分层验收。写接口浏览器记录 method、URL、`X-Request-Id`、`X-Management-Revision`、payload、响应和日志。
2. 对 M01／M02／M03 的 Port 做失效注入、失权、版本漂移和数据范围对照；外部依赖不可用时不得变为空成功。M07 用旧／新结果版本及乱序事件做消费验证。
3. 每个型号单独形成现场能力证据；缺设备标 `BLOCKED_EXTERNAL`，缺授权数据标 `BLOCKED_DATA`，未发布运行服务标 `BLOCKED_DEPLOY`，仅静态或契约测试不得写“浏览器／现场通过”。

## 4. 推荐切片顺序与协作界面

建议按 **P0 → P1 核心派发／接收 → P2 结果动作／签批 → P3 当前有效版本／更正 → P4 报告 → P5 总联调**推进；P2 的纯状态机与 UI、P4 的模板渲染器可在前序联调等待期并行，但真实业务写入口必须守各自硬门槛。每个切片同时交付前端 API／页面、后端 Controller／应用服务／存储、必要字段、测试与验收记录。M01／M02／M03 的能力由各自模块提供，M05 只消费契约；发现缺口先明确缺少的 Port、返回状态和阻塞的 M05 接口，再与对应负责人确认归属。
