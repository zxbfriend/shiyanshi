# M05 对 M01、M02、M03 的协作交接清单

日期：2026-09-29。用途：供协作开发人员认领跨模块能力。本文是执行清单，不替代 `docs/02-详细设计.md`、各模块现行契约和 `M05-后续开发计划.md`；下述状态为当前 `cloud` 分支静态代码核对，不代表 HTTP／设备验收。M05 自有结果状态机、签批、采集、报告实现不转交给其他模块。

## 共同交付口径

每个能力请交付：明确的提供方接口／Port、请求与返回 DTO、失败／不可用语义、生产实现、最少一条允许与拒绝测试、跨模块契约测试及当前运行环境的联调记录。无权、真实无关联和依赖不可用必须可区分；不得返回 `null`、空集合或 `false` 冒充依赖故障。所有 ID／版本在 HTTP JSON 中为十进制字符串；跨模块不访问对方 Mapper 或内部表。

状态请分开标注 `IMPLEMENTED`、`CONTRACT_TESTED`、`HTTP_VERIFIED`、`BROWSER_VERIFIED`、`BLOCKED_DATA`、`BLOCKED_DEPLOY`、`BLOCKED_EXTERNAL` 或 `NOT_VERIFIED`，并提供对应证据。完成代码不等于真实运行服务已更新。

**边界**：M03 提供真实关联和身份／范围事实；M05 决定检测结果是否可上传、签名、审核、作废或更正。M03 不应把培养维护 `evaluateAction` 的 ALLOW 直接等同 M05 审核 ALLOW。真实无培养 Q02 使用记录所属实验室至少 OPERATE 加 M01 审核功能码，并由 M05 排除签名人自审；不要在 M03 伪造项目成员。

## 建议交付顺序及最小联调包

1. **先交 P0 只读 Port 与错误语义**：M01 功能权限、M02 实验室／设备运行快照、M03 用途范围／真实关联／成员事实。给 M05 各提供一条允许、拒绝、依赖不可用样例。
2. **再交公共写支撑及配置**：M01 与 M05 注册业务动作和审计策略；M02 完成 runtime-profile 读写及版本；M03 完成历史分享与签审用途资格。M05 在这些能力上实现自己的守卫写事务。
3. **最后联调真实对象与设备**：当前成员与仅历史分享账号各一名、真实有培养与无培养结果各一条、不同实验室对照数据、至少一个已核准检测器实例；依次做 HTTP、浏览器和逐型号设备验收。缺样例记 `BLOCKED_DATA`，缺协议记 `BLOCKED_EXTERNAL`，不造成功证据。
