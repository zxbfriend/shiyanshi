## 3. 六类不一致逐项核对

**(a) skeleton wired=true 但实现仍抛 501（＝隐性假绿，最危险方向）**
**结论：0 例。** 逐模块验证：所有 501 抛点（108 处）均落在 skeleton **未接线**条目上，无一落在 wired=true 条目的 canonical 实现里。特别核对 M02-175：skeleton 记 `wired=true`、canonical 实现为 `CalibrationObjectApplicationServiceImpl`（controller 活路径，真实接线）；同编号的 501 抛点位于 **legacy** `CalibrationObjectServiceImpl`，且 `M02CalibrationDeleteGuardContractTest` 明确将其定性为**故意 fail-closed 安全背压**（"方法体必须在触库前抛编号 501…任何误接都不会物理删除"），并有 `legacyServiceDeleteMethodsFailClosedBeforeTouchingDb` 用例固化。**故 M02-175 非漂移，M02 无假绿。**

**(b) skeleton wired=false/缺失 但实现已接线（＝漏翻 wired，测试会假红）**
**结论：M04（P1，唯一）。** skeleton-m04.json 全部 16 条无 wired=true，但 `ProcessTemplateApplicationApplicationServiceImpl` 已实现 15/16（读路径真实返回、写路径经管理守卫），仅 `resolveSamplingResourceFacts`（M04-016）仍抛 501。门禁对"未接线期望 501"的断言与实现"已返 200/守卫拒绝"相冲突→ `M04SkeletonContractTest:46/:58` 红。详见 §5。

**(c) skeleton 条目缺失（impl 有接口方法但 skeleton 未登记）**
**结论：无孤儿。** 各模块条目数与冻结期望一致（M02=253、M03=44、M04=16、M05=58、M06=15、M07=33、M09=21），`MxxSkeletonContractTest` 均以 `EXPECTED_ENTRIES` 硬断言锚定（M02 `=253`、M04 `=16` 实测）。未发现"实现存在接口方法但 skeleton 未登记"的遗漏。M01 因无 JSON 不适用本条（见 §7）。

**(d) 测试 expected count ≠ skeleton 条目数**
**结论：无漂移。** 实测 M02 `EXPECTED_ENTRIES=253`（skeleton 253）、M04 `EXPECTED_ENTRIES=16`（skeleton 16），均相等。M03/M05/M06/M07/M09 同型（`SkeletonEngine.load` 条数 == 期望）。`FullSystemSkeletonGateTest.contractIdsAndRoutesGloballyUnique` 以 `port-closure-anchor.json` 的 `gateEntriesExpected` 作全局锚点（00 清单非 M01 总数 − spec blocked），机制在位。

**(e) FullSystemSkeletonGateTest 红项归属是否与当前文档一致**
**结论：一致。** 当前基线为 `FullSystemSkeletonGateTest` **9 例 2 失败**：
- `:166`＝`applicationServicesAreZeroFieldNumbered501Only` 末尾断言"应用服务违例"——违例清单落在 **m04**（`content/*` Normalizer/Content 类 + `ProcessTemplateApplicationApplicationServiceImpl`）＋ **m05**（`WorkbenchConfiguration*`/`M05AccessSupport`/`M05ResultIdentity*`/`ResultRevision*`/`SignActionConfirmation`/`LegacyDetectionEndpointGuardImpl`）；
- `:261`＝`generatedCodeImportsStayInOwnModule` 末尾断言"跨模块引用违例"——**m05** `WorkbenchConfiguration*` 直引 m02（**模块隔离**问题）。
`docs/59`（批次三～批次十五多轮）逐字登记"四条红＝`FullSystemSkeletonGateTest:166/:261`＋`M04SkeletonContractTest:58/:46`"，归属＝**M04 应用服务违例 ＋ M05 跨模块直引 m02**，与本任务独立静态推演**完全吻合**。需注意 `docs/59` 的简写":166=M04、:261=M05"是概括——实际 `:166` 清单**同时含 m04 与 m05 面文件**，本报告按违例文件精确归属。

## 5. M04 深入剖析（头号 P1）

**事实面（两独立来源印证：源码静态读取 ＋ `docs/59` 红项明细）**：
- 规格：`skeleton-m04.json` 16 条，**无 wired=true**（0/16）。
- 实现：`ProcessTemplateApplicationApplicationServiceImpl` 16 公开方法，仅 1 处 `new SkeletonNotImplementedException("M04-016")`（`resolveSamplingResourceFacts`）；其余 15 条读路径真实返回、写路径经管理守卫（`ManagementGuardRejectException`）。该类含 `@Autowired`/`Mapper`/`ManagementGuardExecutor`（wired 应用服务特征，非零字段骨架）。
- Javadoc：声称 M04-005/008/012~016 七条"保持骨架 501"，与实现面（仅 1 条抛 501）不符。
- 门禁红机理：`M04SkeletonContractTest` 对"未接线"条目断言 HTTP 501，实测**实得 200 或 `ManagementGuardRejectException`**→ `:46`（`implThrowsNumbered501Only`）/`:58`（`http501EnvelopeForEveryEntry`）红；`FullSystemSkeletonGateTest:166` 的 `detectImplViolations`（wired==0 分支要求"501 抛出数 == 方法数"且禁含 banned token）因 M04 面违例而红。

**判定**：这是"skeleton 漏翻 wired"（类别 b）而非"实现缺 501"。**实现进度领先于骨架登记**，导致骨架/测试按"全 501"预期与实现"已接线"现实冲突而假红。风险方向为**假红**（gate 正确地报警，暴露登记滞后），**不是假绿**——因此归 P1 而非 P0。
