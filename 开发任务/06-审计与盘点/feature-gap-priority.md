## 0. 审计方法与已验证事实

### 0.1 方法
1. 老系统功能以**后端菜单种子 `sql/sys_menu.sql`**（权威）为准，并登录线上系统实测菜单渲染与数据。
2. 新系统功能以**后端菜单种子 `sql/ymsw.sql` + `futurefab-system` Controller 清单 + `futurefab-ui` view 清单**为准做代码层核对。
3. 运行时逐页 Network 状态（200/404/403/501）因新系统登录含**验证码**无法在本轮自动登录实测，统一移交给 `qoder-frontend-api-auditor` / `qoder-backend-api-auditor`。

### 0.2 已验证事实
| 项 | 结论 | 证据 |
|---|---|---|
| 老系统登录 | ✅ 成功（admin/admin123，无验证码） | 线上实测进入 `/portal` |
| 老系统菜单结构 | 6 大模块 + 工作空间门户 | `sql/sys_menu.sql`（约 120 个菜单项）|
| 新系统菜单结构 | 与老系统 **1:1 平移**（菜单 ID、组件路径完全一致） | `sql/ymsw.sql` 第 3688/3689 行：`101 场地管理 smp/venue/index`、`102 实验组管理 smp/labgroup/index`，与老系统完全相同 |
| 新系统后端 | 覆盖老系统全部模块（Sys/Lab/Dev/Res/Det/Alarm/Process/Venue/Group 全系列 Controller） | `futurefab-system/.../controller/*.java` 全量列举 |
| 新系统前端 | 老系统各业务 view 均存在对应组件 | `futurefab-ui/src/views/**` 列举 |
| 老系统运行态 | 三工作空间 + 检测分析页 + 系统设置页均可渲染且**有数据** | 线上实测 |
| 老系统设备通信 | BGA 检测页报"NamedPipe 客户端未启用，派发中止" | 线上实测（设备联动依赖外部） |
| 新系统登录 | ⚠️ **被验证码拦截**，本轮无法自动登录实测 | 本地 `127.0.0.1:5581` 登录页含"验证码"必填项，AAD 按钮禁用 |

### 0.3 关键结论
**新系统是对老系统的微服务重实现，功能菜单基本已平移，不是"缺功能"而是"需联调/补齐集成层"。**
主要风险集中在：① 登录验证码（老系统无，新系统有，阻塞进入）；② 运行时接口 200/404/403 尚未实测；③ 老系统特有的"工作空间门户"呈现层、NamedPipe 设备联动、AAD 等集成；④ 少量交互/状态展示差异。

## 5. 应先补 options 的接口（跨页复用下拉/选择器）

## 6. 需等 qoder-frontend-api-auditor / qoder-backend-api-auditor 的页面

**原因**：新系统登录含验证码，本轮无法自动登录，故所有新系统页面的运行时 Network 状态（200/404/403/501）**均未实测**，必须移交前后端 API auditor 用可登录环境（关闭验证码或注入会话）逐页验证。

需优先复核的页面（按批次）：
- **批次1**：登录 `/login`、验证码 `/captchaImage`、菜单 `/system/menu/getRouters`、当前用户 `/getInfo`、个人中心；场地/实验组/用户/角色/菜单/字典 列表与各自 options。
- **批次2**：实验室（lab/*）、设备（device/*）、项目/批次/培养（resource/*）、工作流（process/workflow）、检测记录（detect/record）、系统监控（monitor/*）的全部列表 GET 与 options；字典/参数/公告/通知/日志。
- **批次3**：检测分析工作台（detect/bga、vicell、osmo、cedex、workbench）、数据签名（detect/sign-workbench）、各增删改/导出/导入 POST·PUT·DELETE；NamedPipe 下发（设备联动）、AAD（`/aad/*`）、子系统接口测试页（subsystem/*、sdms/order）。

API auditor 应输出：每页 进入性（200/403/404）、列表数据条数、查询/列/下拉/字典展示是否与老系统一致、写操作是否 200/501（未实现）。
