### 3.1 M01 部门删除（配合后端 M01-030 ORG18）

页面路径：系统设置 → 部门管理。点击路径：任意非根部门行 →「删除」。

| 场景 | 操作 | HTTP | 期望 |
|---|---|---|---|
| 正常删除 | 选无引用子部门 → 确认 | `DELETE /system/dept/{id}`，头 `X-Request-Id`+`X-Management-Revision`（来自列表外壳顶层 `managementRevision`） | 200 外壳，`data.removedIds` 含根+子树；提示「删除成功」或「已删除部门“X”及其 N 个下级部门」；树刷新；Network 中响应外壳 `managementRevision` 已前移 |
| 引用阻塞 | 选有在册用户/实验组/实验室/项目引用的部门 | 同上 | 409，`errorCode=REFERENCE_EXISTS`；提示后端明细（「部门或其子树存在N条…引用，无法删除」）；确认框保持打开；列表刷新 |
| 过期 revision | 删除前让另一账号先做一次任意管理写 | 同上 | 409，提示「数据已被他人修改」类文案；列表自动刷新；重试可用 |
| 缺 revision 短路 | （开发态）接口不可用时点删除 | — | 前端不发写请求（Network 无 DELETE），有明确提示 |
| 权限 | B 账号 | — | 无删除按钮（`system:dept:remove`） |
| 确认文案 | 打开确认框 | — | 文案警示「删除将同时移除其全部下级部门；…存在…引用，删除将被拒绝」，不承诺必定成功 |

测试要点（每页同构）：
1. 请求 method=POST、Content-Type `application/json`、payload 只含页面筛选对应字段（无筛选时为空对象 `{}`）。
2. 响应应为 xlsx 二进制流；前端触发浏览器下载。若后端返回 JSON（导出未接线/未部署），前端提示「未返回可下载文件」——此时记 `BLOCKED_DEPLOY`，不要反复重试。
3. 带筛选导出的行数/实验室范围应与筛选一致；范围授权由服务端执行，前端不拼接任何 labIds（Network 里确认 payload 无 `viewLabIds` 之类字段）。
4. 无权限账号（B）看不到导出按钮。

### 3.3 M05 签批台六动作（配合后端 M05-039~044）

页面路径：数据管理 → 数据签名。点击路径：筛选 → 勾选结果 → 动作按钮（签发/审核/撤销签发/撤销审核/作废，撤销作废在「更多」菜单）→ 弹窗。

流程为两段式：**预检**（弹窗 OK 按钮，POST preview）→ **确认执行**（预检通过后 OK 按钮变为「确认执行」）。

| 场景 | 操作 | HTTP | 期望 |
|---|---|---|---|
| 预检 | 勾选可操作行 → 动作 → 填原因（撤销/作废必填） | `POST /detect/sign-console/preview-action`，body `{action, items:[{resultId, expectedObjectVersion}], reason}` | 200；弹窗列出可执行/不可执行清单；OK 变「确认执行」；响应外壳与体内 `managementRevision` 一致 |
| 正常执行 | 预检通过 → 确认执行 | `POST /detect/sign-console/{sign\|audit\|revoke-sign\|revoke-audit\|void\|revoke-void}`，头 `X-Request-Id`+`X-Management-Revision`（**只取预检回执里的 revision**），body `{items, reason, confirmationToken}` | 200；成功提示「{action}成功，共 N 条」；弹窗关闭、选择清空、列表刷新 |
| 重复点击 | 执行中快速双击/回车 | — | 只发一次请求（busy 守卫 + 请求去重），无双提交 |
| 重放/重复提交 | 同一令牌执行两次（抓包重放） | 同上 | 第二次 409（守卫四元组拒绝）；前端提示后端明细并刷新列表 |
| 过期 revision | 预检后另一账号做管理写，再确认执行 | 同上 | 409 `MANAGEMENT_CONFLICT`；提示冲突；列表刷新；需重新预检 |
| 令牌过期 | 预检后等待过期（expiresAt）再确认 | — | 前端本地短路提示「预检已过期，请重新预检」，不发请求 |
| 终态不可操作 | 选已签发/已审核/已作废行 | — | 不匹配的动作按钮禁用（`selectionAllowsAction`）；后端 ineligible 列表兜底 |
| 缺权限 | B 账号（无 `detect:sign:sign`/`detect:sign:audit`/`detect:sign:edit`） | — | 对应按钮不渲染 |

### 3.4 M05 受控更正（新页面，配合后端 M05-001~005）

页面路径：数据管理 → 受控更正（直连 URL `/#/detect-result-correction`；菜单项待配置，见 §5）。双人制：预览需 `detect:correction:submit AND detect:sign:sign`，决策需 `detect:correction:review AND detect:sign:audit`。

| 场景 | 操作 | HTTP | 期望 |
|---|---|---|---|
| preview | 上半区填检测结果ID+期望版本+变更项+证据+原因 → 更正预览 | `POST /detect/result-corrections/preview` | 200；展示变更路径、影响面（报告数/下游使用数）、候选哈希、令牌过期时间 |
| submit | 预览通过 → 提交更正申请 | `POST /detect/result-corrections` | **后端 M05-048 当前显式 501**：透出后端错误提示，记 `BLOCKED_BACKEND`；不得伪造成功 |
| detail | 下半区填更正申请ID → 加载详情 | `GET /detect/result-corrections/{id}` | 展示 correction 行（状态/提交人/时间/原因/变更路径）、diffs 表、证据表、签名、issues 告警 |
| decision preview | 决策区选 APPROVE/REJECT + 理由 → 决策预览 | `POST /detect/result-corrections/{id}/decision-preview` | 200；返回决策令牌与摘要 |
| decide | 决策预览通过 → 确认决策 | `POST /detect/result-corrections/{id}/decisions`，头 `X-Request-Id`+`X-Management-Revision`，body 只有 `{confirmationToken}` | 见下方「已知后端缺口」；成功则状态刷新 |
| withdraw | 本人 + SUBMITTED 状态 → 填撤回原因 → 撤回 | `POST /detect/result-corrections/{id}/withdraw`，头同上，body `{expectedVersion, reason}` | 成功则状态变 WITHDRAWN；非本人账号按钮禁用 |
| 提交人自审拦截 | 提交人本人打开决策区 | — | 决策表单禁用并提示「提交人不能审核本人的更正申请」（后端双人制为准） |
| 令牌过期/内容变化 | 决策预览后等待过期或修改内容再决策 | — | 409 `CONFIRMATION_EXPIRED_OR_CHANGED` 类提示；要求重新预览 |
| 缺权限 | B 账号 | — | 上/下半区分别显示权限警示，按钮禁用 |

**已知后端缺口（本批前端已按契约短路，登记给后端 owner）**：
`DetResultCorrectionController` 的读口（decision-preview / detail 等）未标注 `@CurrentManagementRevision`，响应外壳没有顶层 `managementRevision`，前端因此**没有合法的 revision 来源**。前端处理：decide/withdraw 调用时若拿不到 revision，本地拦截不发请求，提示「读口未返回顶层 managementRevision（后端缺口），已拦截本次守卫写请求」。修复路径：后端在 decision-preview（及 detail）加 `@CurrentManagementRevision` 并补契约测试；前端无需再改（已按外壳顶层字段取值）。

### 3.5 守卫写请求头统一核查结论（任务 2 汇总）

| 写口 | X-Request-Id | X-Management-Revision 来源 | 缺 revision 短路 | 409 处理 |
|---|---|---|---|---|
| M01 部门删除 | ✓（requestId() 生成） | ✓ 列表外壳顶层 `managementRevision`（`ensureRevision`，409 后强制重取） | ✓（writeHeaders 不发头 + 后端 400 兜底；本地 revision 缺失时 reloadRevision 兜底） | ✓ 本批补齐：分流提示 + 刷新 + 回执回填 |
| M05 签批台六动作 | ✓ | ✓ 预检响应外壳+体内双校验（`readSignConfirmation`） | ✓ API 层校验 revision 格式，非法直接 409 不发请求 | ✓ 本批补齐执行步 409 处理 |
| M05 更正 decide/withdraw | ✓ | ○ 读口当前不返回（后端缺口，见 §3.4） | ✓ API 层短路（MANAGEMENT_REVISION_MISSING） | ✓ 冲突后丢弃令牌要求重预 |

不允许硬编码 revision：全仓 revision 均来自读口外壳或写回执（`rg "revision:"` 无字面量版本）。
