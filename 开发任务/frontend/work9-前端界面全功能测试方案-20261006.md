## 0. 执行规则（cloud code 必读）

1. **判定口径**：每个用例只允许三种结果——`PASS` / `FAIL` / `BLOCKED(原因)`。禁止把 BLOCKED 记成 PASS。
2. **证据要求**：每条用例记录：操作步骤描述、HTTP method+URL、请求头（重点 `X-Request-Id`、`X-Management-Revision`、`Authorization`）、请求体、响应状态码与响应体摘要（脱敏）、页面截图或 DOM 摘要、后端日志关键行（如出现 `RequestMetaInvalidException`、`MANAGEMENT_CONFLICT`）。
3. **抓包**：全程开启 DevTools Network。凡本方案标注【守卫写】的请求，必须验证两个头都存在；缺任何一个即 FAIL。
4. **禁止事项**：不修改前端源码来"让用例通过"；不跳过清理步骤；不使用 Mock 数据替代真实后端响应；发现 UI 与本方案不符时如实记 FAIL 并附证据。
5. **前端启动**：按仓库实际脚本启动（`futurefab-frontend` 下 `npm run dev:portal` 或等价方式），登录地址以部署配置为准；若环境不可用，全部用例记 `BLOCKED(环境)`。
6. **结果落盘**：按 §10 模板输出 `docs/开发任务/frontend/work9-前端测试执行记录-<日期>.md`，显式路径提交（不 push）。

## 3. M01 部门管理（页面：系统设置 → 部门管理）

通用前置：以账号 A 登录；打开 DevTools Network。

### TC-M01-DEL-001 正常删除（级联提示）
- 步骤：选择一个**无任何引用**的、带 ≥1 个子部门的测试部门 → 行内「删除」。
- HTTP：`DELETE /system/dept/{deptId}`【守卫写】。
- 请求头：`X-Request-Id`（任意 UUID）、`X-Management-Revision`（取自页面列表接口 `GET /system/dept/pageList` 响应顶层 `managementRevision`）。
- 期望响应：200，外壳顶层 `managementRevision` 较请求值 +≥1，`data.removedIds` 数组含根与子树 id、升序。
- 期望 UI：确认框标题「删除部门"X"？」，内容含「删除将同时移除其全部下级部门；…引用，删除将被拒绝」；成功后提示「已删除部门"X"及其 N 个下级部门」（N=removedIds.length−1；若只删单节点则提示「删除成功」）；树刷新且被删节点消失。
- PASS 条件：两个头都在、级联提示与 removedIds 数量一致、树刷新。
- 清理：无需（软删除）。

### TC-M01-DEL-002 引用阻塞（REFERENCE_EXISTS）
- 步骤：对**含在册用户/实验组/实验室/项目引用**的部门执行删除并确认。
- 期望响应：409，`errorCode=REFERENCE_EXISTS`，msg 点名引用对象与数量。
- 期望 UI：提示**后端原文**（如「部门或其子树存在N条…引用，无法删除」）；确认框保持打开；列表自动刷新；不出现"删除成功"。
- PASS 条件：文案含后端明细、无成功提示、确认框未销毁。

### TC-M01-DEL-003 版本冲突（过期 revision）
- 步骤：打开删除确认框后（不点确认），用另一会话/账号 A2 对任意部门做一次新增或修改（使全局 revision+1），再回来点「确认」。
- 期望响应：409，`errorCode=MANAGEMENT_CONFLICT`。
- 期望 UI：提示「数据已被他人修改」类冲突文案（不是后端原文也可，但必须含"冲突/刷新/重试"语义）；随后列表自动刷新（Network 可见重新拉取 pageList）；再次删除可用且成功。
- PASS 条件：409 后自动刷新 + 重试可成功。

### TC-M01-DEL-004 缺 revision 短路（正交验证）
- 方法（二选一，cloud code 任选可行者）：a) 断网/改后端返回使 pageList 无 `managementRevision` 字段；b) 用 DevTools 把本地缓存 revision 清空后直接调 `deptApi.remove`（仅限能驱动页面代码的执行器）。
- 期望：**不发出 DELETE 请求**（Network 无记录）或后端 400 拒绝；页面有明确提示；不出现"删除成功"。
- 若两种注入都不可行：记 `BLOCKED(注入手段)`，不判 FAIL。

### TC-M01-DEL-005 权限（账号 B）
- 步骤：账号 B 打开部门管理。
- 期望：无「删除」按钮；直接调 DELETE 接口返回 403。

### TC-M01-DEL-006 确认文案合规
- 步骤：打开删除确认框（不确认）。
- 期望：文案**不承诺必定成功**，包含「删除将同时移除其全部下级部门」与「引用…将被拒绝」两段语义；有「删除/取消」按钮，okType 为危险色。

## 6. M05 签批台（页面：数据管理 → 数据签名，路由 `data-signing-workbench`）

通用前置：账号 A；测试项目下存在已上传（uploaded）状态的检测结果；DevTools 开启。

### TC-M05-SIGN-001 查询与选择
- 步骤：选项目+时间范围 → 查询；勾选单列、全选、取消。
- 期望：矩阵渲染；选择计数「已选 N」实时更新；未查询时提示「请先进行筛选」。

### TC-M05-SIGN-002 预检（六动作通用）
- 步骤：勾选可签发结果 → 「签发」→ 弹窗填原因（预检阶段可留空）→ 点 OK（文案「预检」）。
- HTTP：`POST /detect/sign-console/preview-action`，body `{action:"SIGN", items:[{resultId, expectedObjectVersion}], reason}`。
- 期望响应：200；外壳顶层 `managementRevision` 与 body `managementRevision` 一致；`eligible`/`ineligible` 清单与所选一致；`confirmationToken` 非空、`expiresAt` 为未来时间。
- 期望 UI：弹窗信息条变为「预检已通过：「签发」将应用于 N 条结果…」；OK 按钮文案变「确认执行」。
- PASS 条件：两处 revision 交叉一致（不一致前端会抛「签批预检响应不完整」——若出现记 FAIL 并附响应）。

### TC-M05-SIGN-003 确认执行（签发）【守卫写】
- 步骤：预检通过 → 点「确认执行」。
- HTTP：`POST /detect/sign-console/sign`，头 `X-Request-Id` + `X-Management-Revision`（**等于预检响应里的 revision**），body `{items, reason, confirmationToken}`。
- 期望响应：200，`data.items` 每条含 previousStatus/currentStatus。
- 期望 UI：成功提示「签发成功，共 N 条」；弹窗关闭；选择清空；列表刷新且状态变为 signed。

### TC-M05-SIGN-004 审核及撤销族
- 步骤：对 signed 结果执行「审核」（action=REVIEW，接口 `/detect/sign-console/audit`）；对已签发执行「撤销签发」（`/revoke-sign`，**必填原因**）；对已审核执行「撤销审核」（`/revoke-audit`，必填原因）；`/void` 与 `/revoke-void`（必填原因，撤销作废在「更多」菜单）。
- 期望：各自 200 且状态机按 signed→reviewed、signed→uploaded、reviewed→signed、voided→uploaded 流转；原因未填时前端拦截提示，不发请求。

### TC-M05-SIGN-005 防抖/双击
- 步骤：确认执行请求进行中快速连点。
- 期望：仅一次 POST（Network 计数=1）。

### TC-M05-SIGN-006 令牌过期
- 方法：预检后等待 `expiresAt` 过期（或用 DevTools 改本地时间不可行时，改用拦截响应把 expiresAt 改小）→ 点「确认执行」。
- 期望：本地提示「预检已过期，请重新预检」，**不发正式写请求**。

### TC-M05-SIGN-007 过期 revision 冲突
- 步骤：预检通过后，另一会话做一次任意管理写（revision+1）→ 确认执行。
- 期望：409（MANAGEMENT_CONFLICT 或状态冲突）；提示冲突文案；列表自动刷新（保留选择）；需重新预检。

### TC-M05-SIGN-008 重放
- 步骤：用抓包工具原样重放上一步成功的执行请求。
- 期望：409（守卫幂等/冲突拒绝）；前端展示后端明细。

### TC-M05-SIGN-009 权限与状态匹配
- 账号 B：六个动作按钮全部不渲染（无 sign/audit/edit 权限）。
- 账号 C 或状态不匹配时：不满足条件的动作按钮禁用；预检响应 `ineligible` 在弹窗「不可执行」表格中逐条展示原因。

### TC-M05-SIGN-010 打印/导出入口
- 期望：「更多」菜单中打印/导出为**禁用态**（文案「（报告任务待开放）」）；不可点出成功提示。

## 7. M05 受控更正（路由直连 `/#/detect-result-correction`；菜单 `detect/result-correction/index`）

通用前置：账号 A（双权限齐全）；测试结果的主键 resultId 与其 objectVersion 从签批台/检测结果页获取。

### TC-M05-CORR-001 预览成功
- HTTP：`POST /detect/result-corrections/preview`，body `{resultId, expectedObjectVersion, changes:[{itemId, field:"VALUE", newValue, unit}], evidenceRefs:[{attachmentId, version, sha256}], reason}`。
- 权限：`detect:correction:submit` AND `detect:sign:sign`。
- 期望响应：200；`data` 含 candidateHash、changedPaths、impactSummary、confirmationToken、expiresAt。
- 期望 UI：预览结果区展示候选哈希/过期时间/变更路径/影响面（报告数+下游使用数）；提示「预览通过…」。
- PASS 条件：不发任何"提交"请求；页面无「直接生效/应用」类按钮（这是硬性检查项）。

### TC-M05-CORR-002 表单校验短路
- 步骤：分别缺 resultId / objectVersion / changes / reason 点「更正预览」。
- 期望：对应警告文案，不发请求。

### TC-M05-CORR-003 提交（预期后端 501）
- 步骤：预览通过 → 「提交更正申请」。
- HTTP：`POST /detect/result-corrections`，body `{confirmationToken}`。
- 期望响应：**501 或 ACTION_NOT_SUPPORTED**（M05-048 未接线）。
- 期望 UI：透出后端错误提示；**绝不出现「已提交/已生效」**。记 `PASS`（该用例验收的就是"不可用且如实提示"）；若出现成功提示记 FAIL。

### TC-M05-CORR-004 详情
- 前置：库中存在一条更正申请（由后端造数；前端无法创建，见 003）。
- HTTP：`GET /detect/result-corrections/{id}`。
- 期望 UI：correction 行（状态标签色、提交人/时间、原因、变更路径）、diffs 表（path/before/after/unit）、证据表（displayName/attachmentId/version/sha256）、签名区、issues 告警逐条显示。
- 数据缺失时记 `BLOCKED_DATA`。

### TC-M05-CORR-005 决策预览 + 决策
- HTTP：`POST /detect/result-corrections/{id}/decision-preview`，body `{expectedVersion, candidateHash, decision:"APPROVE"|"REJECT", reason}`（值取自详情接口，不硬编码）。
- 决策：`POST /detect/result-corrections/{id}/decisions`【守卫写】，body 只含 `{confirmationToken}`，头 `X-Request-Id`+`X-Management-Revision`。
- **已知后端缺口（预期行为）**：更正读口未返回顶层 `managementRevision` → 前端**短路不发请求**，提示「读口未返回顶层 managementRevision（后端缺口），已拦截本次守卫写请求」。出现该提示记 `PASS`（验收点即"缺 revision 短路"）；同时记 `BLOCKED_BACKEND`（决策功能正路径待后端补注解后复测）。

### TC-M05-CORR-006 撤回
- 步骤：以**提交人本人**账号打开 SUBMITTED 状态申请 → 填撤回原因 → 「撤回申请」。
- 期望：与 005 同样的 revision 短路口径（后端缺口期间）；非本人账号按钮禁用。

### TC-M05-CORR-007 提交人自审拦截
- 步骤：提交人本人打开审核区。
- 期望：决策表单禁用 + 警示「提交人不能审核本人的更正申请」。

### TC-M05-CORR-008 组合权限
- 账号 C-1（有 sign:sign 无 correction:submit）：发起区禁用 + 权限警示。
- 账号 C-2（有 sign:audit 无 correction:review）：审核区禁用 + 权限警示。
- 账号 B（全无）：两区均禁用。

### TC-M05-CORR-009 403 提示
- 方法：用无权限账号直接驱动请求（或后端撤权后操作）。
- 期望：提示「权限或菜单种子未配置（detect:correction:\* / detect:sign:\*），请联系管理员开通后再操作」；不出现成功提示。

### TC-M05-CORR-010 令牌过期/内容变化
- 方法：决策预览后等待过期再决策，或修改详情内容后用旧 token 决策（需后端造数）。
- 期望：409 CONFIRMATION_EXPIRED_OR_CHANGED 类提示「请重新预览」；决策预览结果区清空。环境不可造数时记 `BLOCKED_DATA`。
