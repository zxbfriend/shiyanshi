## 4 公共开发契约（FE00）

### 4.1 类型、外壳、列表和空值

- URL 相对工程配置的 apiBaseUrl；不自行重复拼 `/system`。部署代理须支持 `/resource`。
- 分页读取顶层 `rows/total/pageNum/pageSize`，详情及业务结果读取 `data`；保留顶层 `managementRevision/requestId/errorCode/fieldErrors/retryAfterSeconds`。不同返回类型按附录核对，不统一假设 `data.rows`。
- 正整数 ID 与非负版本保留十进制字符串，不经 JavaScript Number 中转。`expectedVersion`、`planVersion`、`runtimeVersion`、重量版本各自独立，不能互换。
- `null`、未知和空集合分别表达；界面可显示“—/暂不可用”，请求不能发送字符串 `NA`。计数未知显示“—”，不能显示 0。
- `pageNum >= 1`，pageSize 使用 10/20/50/100；keyword 最长 100。筛选改变回到第一页，详情返回保留筛选；切换上下文时清除过时选择并取消过时响应。
- 列表 `timeType=CREATE/UPDATE`，`fromDate/toDate` 必须成对提供；日期格式 `YYYY-MM-DD`。项目按创建时间倒序，批次/培养按修改时间倒序，次排序 ID；客户端不重排当前页伪装全局排序。
- 业务日期按 Asia/Shanghai，允许范围 1000-01-01—9999-12-31；观测历史的 from/to 则是带时区的 ISO 时刻，两种字段不可混用。
- 视图使用 `NamedRef{id,name}` 和 `audit{creator,createdAt,modifier,modifiedAt}`；不再依赖 `leaderNames/deptName/createTime` 等旧扁平字段。

### 4.2 请求元数据与恢复

| 入口类别 | 发送方式 | 当前处理 |
| --- | --- | --- |
| 已接守卫写：004、007、014、019、020、022、023、024 | Header `X-Request-Id`、`X-Management-Revision`；Body 业务白名单及对象 expectedVersion | Controller 以 Header 为权威并覆盖 DTO 元数据；复用公共 helper，单次提交固定 UUID |
| 部分写：012、016、029 | 当前 DTO Body 含 requestId、managementRevision、expectedVersion | 独立 SDK 适配；后端补齐前不宣称可靠重放，不用 Header-only 请求代替现有 Body |
| 尚未正式接线的写 | 以 DTO/专题契约准备类型 | 真实元数据入口及回执行为纳入 BE01/02/06/07 联调，不预设已具备守卫 |
| 列表/详情、删除与退出预览、授权查询 | 只读请求 | 不因是 POST 就套管理写；预览 Body 无业务字段时发 `{}` |

- 从本次有权读取的响应获取 managementRevision；001/002、008/009、017/018、031 已有当前版本注入，006 项目预览也有。以实际顶层/预览响应核对返回值，不从其他模块旧缓存借版本，不填 0。
- 新建项目可先取有权项目列表取得版本；只有新增权限但无法读取任何版本来源时，需后端提供合法读取来源，不在前端绕过读权限。
- 015/021 的预览版本输出及 012/016/029 的版本更新要在联调中专门核对。拿不到可信版本时保留表单并阻止提交。
- 双击、网络超时后的同次重放沿用原 UUID 和原载荷；改了业务内容应作为用户确认后的新请求。结果未知先查已提供的查询/回执接口；不能给所有写虚构通用 request lookup URL。
- 运行变更的原请求查询只使用 036。其余部分写缺少可验证回执时停止自动重试，刷新并人工核对；不能用新 UUID 反复尝试。
- 写成功后刷新对象、列表和管理版本；对象更新与占用/运行事实重新读取，不把本地表单值当最终生效值。

### 4.3 动作权限与事实状态

按钮同时考虑功能权限、对象可见性、服务端动作集、业务状态和接口可用性。前端隐藏按钮不能替代后端逐对象授权。

当前读投影的动作集主要由功能权限生成：项目 VIEW/CREATE_BATCH/EDIT/DELETE，批次 VIEW/CREATE_CULTURE/EDIT/DELETE，培养 VIEW/EDIT/DELETE。它不是全部业务身份、状态、执行屏障都已核验的证明；也尚未完整输出撤回、重约、N 标记等动作能力。新增动作的可用性和拒绝原因需要 BE09 对齐，不自行扩造后端已授予的 allowedActions。

`factsStatus != READY` 或设备 availability=UNKNOWN 时显示事实不可用及可理解原因，不能推断可删除、可预约、可运行。当前设备读投影 availability 为 UNKNOWN，列表中的设备名称只证明关联，不证明空闲。

### 4.4 错误交互

| 错误 | 界面动作 |
| --- | --- |
| INPUT_INVALID、READ_ONLY_FIELD、PLAN_INCONSISTENT | 定位字段，保留草稿；仅发白名单，不自动截断或替用户改日期 |
| CODE_CONFLICT | 当前编号提示重复；不展示无权对象名称或负责人 |
| VERSION_CONFLICT、MANAGEMENT_CONFLICT | 提示资料已变化，重新读取并由用户核对；不静默覆盖 |
| PREVIEW_EXPIRED、DELETE_SCOPE_CHANGED | 重新预览完整删除清单并重新确认 |
| STATE_CONFLICT、DEVICE_OCCUPIED、DEVICE_INVALID、PLAN_DEADLINE_PASSED | 刷新状态/设备事实，要求重新选择；不释放他人占用 |
| ACTIVE_CHANGE_EXISTS | 打开已有候选，不用新请求绕过 |
| GRANT_CONFLICT、MEMBER_ALREADY_CONFIGURED、SELECTION_EXPIRED | 重读来源/首次配置资格或重新选人，不部分提交 |
| PERMISSION_DENIED、ASSIGNMENT_DENIED、NOT_FOUND | 收回相关入口并提示无权/不可用，不泄露范围外信息 |
| DEPENDENCY_UNAVAILABLE、FACTS_UNAVAILABLE、POLICY_NOT_READY、RETRY_LATER | 显示暂不可操作；按原请求身份核对结果，遵守服务端重试时间 |
| PROTOCOL_UPGRADE_REQUIRED | 提示页面需更新，停止旧请求；不降级重试 |
| 501 未实现 | 显示能力暂未开放，不能作为业务校验成功或“已保存” |

错误码完整定义见附录来源。401 走统一登录恢复，不记录身份秘密；产品提示使用业务语言，contractId/Port 名称仅保留在开发诊断中。

003 按 purpose/field/deptId/projectId 加载候选；可选值不是任意用户/实验室全集。修改受创建者/负责人身份及功能权限约束。004 可按真实接口开发，005 真实提交待 BE01，不能用旧 PUT 顶替。

**删除（006 → 007）**：点击删除先请求预览，显示目标、阻塞原因、全部级联空批次和数量。存在培养、引用、隐藏范围或不可枚举级联时按 canDelete/blockers 阻止。用户确认后携带目标 expectedVersion、snapshotToken 和管理元数据。令牌技术有效期 10 分钟；范围漂移/过期重新预览。项目下允许删除的空批次必须完整告知，不能只显示当前页、截断清单或分批悄悄删除。

**验收**：新增成功后重读；编辑未接时不出现假成功；跨部门候选清理；重复编号不泄露其他范围；计数未知不能删除；预览过期/级联增加/对象版本变化均重新确认。

**培养行输入**：

| 字段 | 输入方式/规则 |
| --- | --- |
| cultureCode | 必填 1—50，最终全局唯一校验；删除/取消记录不按活动编号继续占用 |

### 5.3 FE07：培养列表、详情、基础修改与批量修改

**列表/详情（017/018）**：复用 culture-management。展示项目、批次、实验室、培养编号/别名、模式、N 标记、设备和房间、计划日期/周期、状态、延迟原因、成员配置状态、审计。内部版本保存于状态容器，用于对应动作，不直接作为普通用户业务列。

| 状态 | 界面说明 | 占用/动作要点 |
| --- | --- | --- |
| DRAFT | 草稿，计划不完整 | 不占用设备；当前完整预约入口仍有缺口 |
| NOT_STARTED | 已预约，尚未开始 | 完整计划保存即预约，不等到计划开始日；可按准入修改/撤回 |
| RUNNING | 已有工作流开始 | 基础运行变更走候选流程，不普通 CRUD 改状态 |
| EXPIRED | 开始截止已过且无工作流开始 | 已释放预约，设备/日期调整走重约 |
| DELAYED | 已开始但相关流程超时未完成 | 保留占用，不能当空闲设备 |
| CANCELLED | 已取消 | 终态标签不能代替资源释放事实 |
| FINISHED | 已完成 | 同上，历史仍按稳定 cultureId 关联 |

开始/结束截止按对应计划日次日 00:00、Asia/Shanghai。状态由服务端事实确定，不由客户端定时器直接写回。培养日序号是 D0—D(duration-1)，与“计划周期=结束日−开始日+1”的含首尾天数口径同时成立。

**单条修改（019）**：读 018 后维护 originalVersion，Body 为 `{expectedVersion,changes}`，路径传 cultureId，Header 传管理元数据。changes 只带用户明确修改的 CPatch 字段；基础状态准入 DRAFT/NOT_STARTED/EXPIRED，运行/延迟改编号或日期改走 FE13。EXPIRED 改设备/日期走 024。

当前 PATCH 将 null 当作未提供，不能承诺“清空别名/日期”。日期后像要求三项齐全或全空；NOT_STARTED 不允许清空日期，须用 023 撤回；DRAFT 补齐三项会被拒绝，而 024 只接 EXPIRED，这一缺口登记 BE05。表单不要通过改 lifecycleState 或伪造 EXPIRED 绕过。

**批量修改（020）**：2—100 条、同批次、同允许状态、逐条 expectedVersion/changes、整批事务。跨页选择必须显示总数和对象范围；超限提示拆分由用户决定，不能静默截断或自动拆成部分成功；任一行版本/身份/设备失败整批失败。过期重约不能混入基础批量修改。

**培养删除（021 → 022）**：基础可删状态为 DRAFT/NOT_STARTED/EXPIRED，但仍需状态、引用和资源释放事实。明确展示预览 blockers、snapshotToken 及有效期；成功后重读，不因“草稿”标签直接 DELETE。

**验收**：未知状态/事实/设备不显示成正常；批量全部回滚；旧版本提示重读；null 清空暂不误报成功；删除范围或占用漂移阻止提交；历史关联不因编号修改丢失。

### 5.4 FE08：撤回草稿与重新预约

- 023 撤回：仅 NOT_STARTED 且没有工作流启动；确认文案说明将清空计划日期/周期并释放自身预约，保留培养编号与设备关联。成功重读状态和 planVersion，禁止只在表格中改成 DRAFT。
- 024 重约：仅 EXPIRED。输入完整日期三元组和合法 device；复核开始截止、设备所属实验室与占用。不得抢占他人设备；延迟培养不可按空闲处理。
- 当前 BENCH_CONTROLLER 归属事实适配器尚未落地，设备核验会拒绝 DEPENDENCY_UNAVAILABLE；台式培养真实重约待后端适配及联调。中试/容器等分支也须以对应事实为准。
- DRAFT 首次预约和撤回后再预约没有可直接闭环的正式入口，独立列为 BE05；前端不能将 024 自动套给草稿。
- 本节是业务预约/关联，不是物理启动/停止命令。设备状态与 M07 实机联动另列“待后续联调”。

**验收**：截止边界、已开始流程、设备被占、归属未知、版本冲突均阻止错误预约；撤回不清除设备关联；仅重约成功才显示新的预约结果。

### 5.5 FE09：成员和分享

复用 shared/member-dialog 的外形，数据模型替换为正式授权契约。

**查询（025）**：`targetType=PROJECT/BATCH/CULTURE`、targetIds、`grantType=MEMBER/SHARE`、`purpose=SELF/MANAGE`。项目/批次单对象，培养 1—100 个。SELF 单对象仅查看本人来源且 canSubmit=false；MANAGE 需逐对象管理资格。

每行展示用户、授权类型、来源对象、是否继承、有效期、ACTIVE/EXPIRED/INVALID、覆盖目标和可编辑性。CREATOR/LEADER/上级继承来源不能通过本级成员弹窗删除。`memberSetup=NEVER/CONFIGURED/UNKNOWN` 分开显示，未知不能当作首次配置资格。

**差量保存（027，待 BE06）**：targets 带对应对象版本，changes 为 adds/updates/removes 三数组，数组必传、无变更可空；不使用全量替换。有效期 null 为长期，过去日期不能新设，未修改的历史过期来源保留原样。share 是历史查看/打印/导出范围，不授予实时操作、成员维护或设备控制。

**验收**：继承只读、到期边界、多人多目标覆盖范围、无权人员不可见、首次资格冲突、快照过期和全部回滚。当前可先完成正式来源查询，写入不得继续走旧 members 接口伪装完成。

### 5.6 FE10：退出

028 先预览本人能退出的关系和退出后剩余访问；029 带原对象版本及元数据确认。只移除当前层级本人直接 MEMBER，不移除继承、分享、创建者或负责人关系。

同一用户可能退出直接成员后仍通过上级或其他来源可见，按 remainingAccess 展示结果；不能统一提示“已失去全部访问权限”或无条件把项目从列表删除。029 当前缺少完整管理守卫/幂等，按 BE04 处理结果未知，不自动重试。

**验收**：仅分享或继承成员时不可退出；退出直接成员后剩余访问正确；旧空请求和 PUT 裸 ID 全部移除；预览到提交期间身份或版本变化重新读取。

### 5.7 FE11：N 标记和模式

- N 标记（014）：提交 `{expectedVersion,marked}` 和管理 Header，成功后重读。它是外部标记，不改变培养算法或代替模式切换。
- 模式（013）：独立确认弹窗，目标 NORMAL → REACTOR；仅适用中试相应设备/政策准入，不开放逆向切换或小试切换。保留 reason，接收 RuntimeChangeView 后按候选状态展示，不将 HTTP 成功等同模式已生效。
- 模式原因按政策：DIRECT 可为 null，DIRECT_REASON/APPROVAL 必填去空白 1—500 字；不能把重量变更的“始终必填”规则套给模式所有分支。
- 当前 013 未实现，旧 `cultureApi.updateMode` 不可继续使用；模式准入的设备事实及 M07 执行屏障待联调。

**验收**：N 标记失败回滚展示；模式受限状态、活动执行或审批条件不满足时不变更；读取返回不再依据旧数字枚举猜 NORMAL/REACTOR。

### 5.8 FE12：初始重量

031 读取初始重量及版本/可用动作；032 变更独立表单，当前未实现。

- `initialWeightG` 用规范正整数字符串，范围 1—99999999999999 g；不经浮点数存储、不允许科学计数法或小数静默取整。
- 初始重量由人员确认合并接种与培养基等输入，前端不能拿设备瞬时读数直接填成业务基准。
- 显示单位：规格小于 15L 使用 g，达到 15L 使用 kg，规格未知用 g；提交始终为整数 g。使用十进制字符串换算并校验，不把重量自动当体积，不将未知显示为 0。
- 请求含 expectedVersion、expectedWeightRevision、initialWeightG、reason（1—500）；对象版本和重量版本不可混用。
- 准入需 RUNNING/DELAYED 且至少一个已完成工作流的可信事实；接续基线和活动执行等屏障另行复核。前端不能只凭状态标签放行。
- 保存结果进入候选/生效面板，审批通过不直接覆盖初始重量；重新读取 031 取得实际值。

**验收**：大数无损、单位往返、边界值、未知规格/重量、版本冲突、无完成流程/基线保护均覆盖；032 开放前真实保存不可用。

### 5.9 FE13：运行变更和候选状态

**入口**：培养详情及 M07 CultureOperations 内的“变更编号/计划”与“变更进度”。033 只支持 CODE/DATES；模式和重量分别用 013/032，不混入 changes。运行态 RUNNING/DELAYED 不走 019。

**提交流程目标**：读 018 + 034，确认无活动候选后录入变化及原因；033 使用原对象版本与固定请求身份；按 RuntimeChangeView 展示影响和执行结果。当前 033 未实现，可先完成表单、只读候选和 Mock，正式提交等待 BE07。

**已可对接的只读链**：034 当前候选 `{active:对象或null}`；035 指定候选；036 按当前用户的原 requestId 查询 `{lookup:FOUND/NOT_FOUND,change}`。NOT_FOUND 只说明该查询未命中，不能据此生成新键重新发起；结果未知保留原键及原载荷。

| 返回字段 | 界面用途 |
| --- | --- |
| operation、before、after、reason | 展示这次实际变更，不显示为已生效现值 |
| candidateId/candidateVersion | 候选身份与刷新版本 |
| policyRoute | DIRECT / DIRECT_REASON / APPROVAL；只解释服务端选择 |
| approvalId/approvalState | 跳 M06 审批详情，显示审批阶段 |
| candidateState/applyState | 分开显示候选和生效阶段 |
| resultingTargetVersion/effectiveAt | 确认生效后的对象版本与时间 |
| impact/issues/allowedActions | 影响提示、失败原因、刷新/撤回等操作 |

applyState 包括 PREPARED/PENDING/APPLIED/DISCARDED/CONFLICT/FAILED/UNKNOWN。PREPARED/PENDING/UNKNOWN 不能当作无活动变更；UNKNOWN 应保持占位和查询恢复，不出现“再次发起”绕过按钮。只有 APPLIED 并重读业务事实后展示生效结果。

日期变更影响由后端生成：周期改变会清除当前补料/补糖方案关联并取消未开始任务；周期不变保留方案但仍取消受影响的未开始任务。执行中/暂停/未知任务受保护，不由前端批量取消。

审批撤回属于 M06 `POST /process/approval/requests/{approvalId}/actions`，action=WITHDRAW，携带 M06 的 expectedObjectVersion、reason 及元数据；需按 M06 契约和 allowedActions 接入。M03-023 是培养撤回草稿，不能代替审批撤回。

**验收**：直接生效/待审批/审批通过但生效冲突/依赖失败/UNKNOWN/原键恢复；不同身份查请求不泄露；进入页面先恢复既有候选，离开页面停止轮询，页面再次聚焦可刷新；不无间隔轮询。

### 5.10 FE14：跨模块入口与观测绑定历史

- 培养列表的运行操作入口携带稳定 cultureId 跳转 M07 CultureOperations；路由及返回路径与 M07 对齐，不能仅传可修改的 cultureCode。当前 dashboard 不是已验证替代入口。

**验收**：同名/改名培养仍定位正确；设备种类+ID 不串设备；历史分页无重复遗漏；跨权限范围不显示隐藏培养或原始证据；外部模块不可用时本页可读资料仍有清楚状态。

### 5.11 FE15：方案和参数快照

**验收**：没有无依据的保存/提交审批按钮，没有模拟成功状态；既有资料读取正常；后端未开放能力清晰列为依赖。
