## 4 公共开发契约

### 4.1 路径与响应

- SDK 路径相对部署配置的 `apiBaseUrl`，不硬编码主机、端口或凭据。
- 场地、实验组沿用现有 SDK 的 `/smp/venue`、`/smp/labgroup`。正式目录的 `/system/smp/...` 经系统前缀路由也可定位；本次统一采用 SDK 现用路径。部署前验证代理确实覆盖 `/smp/**`。
- 普通管理接口为 `/system/...`，认证为 `/auth/...`。
- 分页一般返回顶层 `rows`、`total`；详情、树和写回执一般在 `data`。密码有效期另有顶层政策字段，不返回 `data`。
- 不把所有接口统一解包成 `data.rows`。保留外壳 `managementRevision`、`requestId`。
- ID 使用十进制字符串，根节点 `parentId="0"`。不得将 bigint ID 转 Number。
- Query 公共 Q：`pageNum` 默认 1、最小 1；`pageSize` 默认 10，只允许 10/20/50/100。
- 仅声明 F 的接口接受通用搜索：`keyword` 最长 100，`beginDate/endDate` 为日期，按上海时区起日 0 时至结束次日 0 时左闭右开。用户及日志接口使用自身时间条件，不混用 F。
- 日期显示 `YYYY-MM-DD`；时间请求带明确时区。空值显示“—”，不补造日期或用 0 替代未知。

### 4.2 写请求和重试

管理写头：`Authorization: Bearer ...`、`Content-Type: application/json`、`X-Request-Id: UUID`、`X-Management-Revision: 当前版本`。Body 只含业务白名单，不用 Body 版本替代 Header。

一次逻辑操作维护一个请求标识与提交快照。同一操作因响应丢失而恢复时，不自动换 UUID。用户改动输入后属于新操作；但旧请求结果未知时应先核对结果，不能用新请求绕过未知状态。

| 状态 | 页面行为 |
| --- | --- |
| 准备提交 | 固定业务载荷、版本和 requestId，校验后禁重复点击 |
| 已成功 | 读取实际回执，更新版本，刷新数据，再提示成功 |
| 明确输入/业务拒绝 | 保留非敏感草稿，定位错误，按原因修正 |
| 版本冲突 | 本次停止；重新读取业务详情、候选及版本，用户核对草稿后重新提交 |
| 超时或网络中断 | 显示“操作结果尚未确认”，核对当前数据；有明确回执能力时才调用，不假设存在通用查询接口 |
| 原操作无法确认 | 保留跟踪 requestId，交后端排查；创建、授权和密码动作不盲目重发 |

修改密码是特殊流程：成功可能已撤销会话；响应丢失后提示使用新密码登录确认，不承诺旧 token 还能查询回执。前端不持久化密码或挑战票据到日志、URL、持久缓存。

### 4.3 版本来源表

| 写功能 | 读取来源 | 使用字段 |
| --- | --- | --- |
| 场地 | `GET /smp/venue/pageList` | 顶层 managementRevision |
| 部门 | `GET /system/dept/pageList` | 顶层 managementRevision |
| 实验组 | `GET /smp/labgroup/list` | 顶层 managementRevision |
| 菜单 | `GET /system/menu/pageList` | 顶层 managementRevision |
| 角色 | `GET /system/role/list` | 顶层 managementRevision |
| 用户编辑/启停/删除/强制下线 | `GET /system/user/list` | 顶层 managementRevision |
| 个人资料 | `GET /system/user/profile` | 顶层 managementRevision |
| 字典类型/项 | 对应 type/list、data/list | 顶层 managementRevision |
| 系统参数 | `GET /system/config/list` | 顶层 managementRevision |
| 本人改密 | `GET /system/user/profile/passwordState` | data.credentialVersion → Body.expectedCredentialVersion |
| 实验室授权 | `GET /system/user/editor-options` | data.labAuthorizationVersion → Body.labAuthorizationVersion |
| 强制下线附加版本 | 用户列表目标行 | sessionVersion → Body.expectedSessionVersion |
| 密码政策 | `GET /system/user/passwordValidity` | policyVersion → expectedPolicyVersion；管理写版本来源仍待后端收口 |

管理版本、凭据版本、授权版本、会话版本和政策版本不得互相替代。管理页共用 SYSTEM 版本，无关页面修改也可能造成冲突。不能通过借另一个页面的新版本来强行保存旧草稿。

打开编辑上下文时获取最新业务数据与有效版本。拿不到当前版本时停止写入；刷新版本失败不得返回缓存旧版本。多个读请求不是天然同一快照，发生冲突后必须重新核对。

### 4.4 权限与错误

页面与顶层动作按功能权限控制；契约返回行级 `allowedActions` 的列表，行按钮再按该字段判断。缺字段或空数组按不允许，不回退放开。批量操作所有选中行都必须允许，后端仍最终判权。

| 错误 | 处理 |
| --- | --- |
| INPUT_INVALID / READ_ONLY_FIELD | 保留草稿；指出字段；只提交白名单 |
| OLD_PASSWORD_INVALID / PASSWORD_POLICY_VIOLATION / PASSWORD_REUSED | 定位口令字段；不当成全局会话失效 |
| ACCOUNT_LOCKED | 使用服务端 retryAfterSeconds 提示；客户端计时不构成解锁许可 |
| SESSION_INVALID / SESSION_REPLACED | 清敏感会话，回登录；不能仅保留旧页面 |
| CHALLENGE_EXPIRED | 清挑战及密码，保留账号，重新验证身份 |
| PERMISSION_DENIED / ASSIGNMENT_DENIED | 不重试写入，更新权限及可操作范围 |
| NOT_FOUND | 提示对象不存在或不可访问，不泄露其真实状态 |
| NAME_CONFLICT / CODE_CONFLICT | 定位名称/编码；不提示成版本冲突 |
| REFERENCE_EXISTS | 显示允许公开的引用类别和数量，不提供强制删除绕过 |
| MANAGEMENT_CONFLICT / VERSION_CONFLICT / SESSION_VERSION_CONFLICT | 刷新对应业务与版本，重新确认，不能自动覆盖 |
| REQUEST_CONFLICT | 提示请求内容冲突，核对原操作，不换新键绕过 |
| LAB_AUTHORIZATION_UNAVAILABLE / MANAGEMENT_BUSY | 保留草稿，提示依赖不可用/稍后核对；不当作空候选或成功 |
| 501 / NOT_IMPLEMENTED | 标记功能尚未开放；不使用旧接口绕过 |

精确错误集合按附录接口及生产方实现，不要求每个接口返回表内所有错误。业务失败分别按 errorCode 处理，不能把全部 409 都描述为“数据被别人修改”。

### 4.5 共用页面交互

- 查询提交后回第一页；重置清筛选；快速查询时取消或忽略旧响应。
- 详情返回保留筛选、页码与树展开；新增成功按设计定位首屏，编辑保留当前页，删除末条回退合法页。
- 首次加载、刷新中、加载失败、无匹配数据、无权限分别展示。刷新失败可保留旧结果但标明未刷新。
- 保存中禁重复；关闭有修改的表单需确认。非敏感草稿在失败后保留；密码关闭即清理。
- 删除预检只提供提示，不保证随后删除成功；确认对象集合固定，选择变化不改变已确认请求。
- 候选失败不替换成空数组后保存。搜索、分页、切换部门不得误删未展示的已有关系。
- 复用现有中英文语言资源、错误提示和表格风格；未知 PC/MAC、历史审计姓名等显示“—”，不得补造。

### FE02 个人资料与本人改密

**接口：**M01-055/056 为个人资料，M01-006/005 为密码状态/修改密码。本人有效会话可用，不能强加管理员权限。

**资料：**昵称、账号、部门、角色只读；可编辑 email、phonenumber、通知偏好、默认头像选择。notifyInsite 固定 "1"；avatarPreset 仅 DEFAULT/CUSTOM，CUSTOM 仅保留已有图，不能新增性别预设。若现有弹窗不开放偏好控件，保存必须保留其原值；按本次资料范围补齐偏好与默认头像交互。

**密码字段与顺序：**打开页签 GET passwordState → 保存 data.credentialVersion、展示 rules → 输入 oldPassword/newPassword/confirmPassword → PUT updatePwd → 成功清会话回登录。

```json

  "oldPassword": "<用户输入，不记录日志>",
  "newPassword": "<用户输入，不记录日志>",
  "confirmPassword": "<与新密码一致>",
  "expectedCredentialVersion": 3,
  "requestId": "6df7b02b-58c5-42cb-99c7-13913bfdf21c"
}
```

示例版本只是形状示例，运行时必须来自读口。此接口不提交 userId，不取管理版本，requestId 在 Body。

### 6.1 角色修改

```http
PUT /system/role
Content-Type: application/json
Authorization: Bearer <当前令牌>
X-Request-Id: 50489c5d-16e9-481f-a86a-ab98905e8409
X-Management-Revision: 42
```

```json
{"roleId":"200","roleName":"实验人员","status":"0","remark":"","dataScopes":["2"],"deptIds":["100"],"menuIds":["300","301"]}
```

版本取 role/list 顶层；完整数据取 role/{roleId}。按钮树半选节点如何合并沿现有 tree-selection 与菜单契约，不能将未知父节点权限自动加入可授予范围。

### 6.2 删除预检

```json
{"code":200,"msg":"操作成功","data":{"canDelete":false,"targetIds":["100"],"descendantCount":2,"references":[{"kind":"<后端返回的引用类别>","count":1}]}}
```

预检 canDelete=false 时不提供继续删除；true 后确认也可能被最终写拒绝。引用标签有语言资源则翻译，无匹配时保留服务端含义，不猜未授权对象名称。

### 6.3 冲突响应

```json
{"code":409,"msg":"数据已变化，请刷新后重新核对","errorCode":"MANAGEMENT_CONFLICT","requestId":"50489c5d-16e9-481f-a86a-ab98905e8409","data":null}
```

前端保留非敏感草稿，重新加载服务端数据供比较；用户核对后才发新操作。REFERENCE_EXISTS 虽也为 409，必须展示引用阻塞，不能套这条提示。

### 身份与路由装配

CurrentIdentity 目标位于 data，包含 user（Profile）、roles（角色 key 数组）、permissions（功能码数组）、permissionRevision、password（密码状态）、allowedModules。不要把旧顶层 user/roles/permissions 结构继续当新契约。RouteNode 包含 name/path/component/redirect/hidden/alwaysShow/query/meta/children；meta 包含 title/icon/noCache/link。身份与菜单读取的版本不一致时重取，避免不同版本的权限和菜单混装。具体序列化以当前 VO 和实际 HTTP 响应核对，字段缺失不得默认获得权限。
