### 2.1 业务与跨模块边界

- 四类页面承载七型号：BGA、Vi-CELL、OSMO-1/2/3、Cedex Bio、Cedex Bio HT。型号/实验室/设备/检测项目配置归 M02；本模块消费其真实配置。

- 当前普通工作台不提供人工录入/修改设备测量数值。受控更正走独立证据、预览和审核流程，不能用通用明细编辑替代。

- M03 历史分享范围用于读、打印和导出，不等于允许上传、签名、审核、作废或派发设备。
- 自动检测的触发、设备回调、结果采集和自动上传在服务端进行；浏览器不调用内部 Port、不自行补回调或计算下游控制值。

## 4 公共契约与交互规则（FE00）

### 4.1 ID、响应、时间与页面状态

- ID及版本保存为十进制字符串，禁止 `Number()`/`parseInt()` 后再传回；金额/测量十进制值按契约用字符串，不用JS浮点重算。
- 区分 `sampleId`（不可变身份）、`sampleNo`（业务编号）、`resultId`、`resultItemId`、`dispatchId`、`occupancyGeneration`。按真实ID定位，不按同名样品合并或匹配迟到结果。
- 正式响应保留外壳 `code/msg/data/requestId/managementRevision` 等实际元数据；分页分别适配 `data.rows/total` 与旧 `TableDataInfo.rows/total`。不要用一个泛型猜两种结构。
- Asia/Shanghai自然日筛选使用 `[startDate 00:00,endDate+1 00:00)`，不是浏览器时区截断UTC；页面时间显示按服务端时区证据。缺失时间显示“未提供/未核验”，不填当前时间。
- 页面至少有：初始选择、加载、空数据、成功、权限不足、依赖未就绪、读取失败。501/503不是空数据；失败保留用户输入但失效原预检及写资格。
- 设备/实验室/项目切换、查询条件变更、组件卸载时取消旧读请求并丢弃迟到响应。未保存输入切换需提示；写请求取消不代表服务端撤销。
- 所有状态同时有文字，不能只用颜色。未知码显示“未知状态/待核验”及安全诊断信息，不当作成功、空闲、未作废或无告警。

### 4.2 版本、令牌及幂等

| 元数据 | 来源/用途 | 禁止做法 |
| --- | --- | --- |
| managementRevision | 当前业务读/预检的正式外壳；受控写 `X-Management-Revision` | 从M02、其他页面、旧缓存借值；缺失补0/1 |
| requestId | 用户一次明确提交生成UUID；`X-Request-Id` | 超时立即换键重发；在按钮每次重试中无条件生成新键 |
| objectVersion | 当前结果/样品读响应；分别传 expectedObjectVersion/expectedSampleVersion | 用管理版本代替对象版本；客户端+1假装成功 |
| profileRevision/queueRevision | 当前设备配置/完整队列投影 | 用runtimeProfile版本冒充队列版本 |
| occupancyGeneration | 当前样品占位代次 | 仅按通道号操作，误删新一代样品 |
| confirmationToken | 当前用户、动作、对象版本、理由对应预检；通常5分钟 | 修改选择/理由后沿用；存日志或localStorage |

现有带 `@ManagementGuardedWrite`：003/004、021—023、025—027、039—044。Header是权威来源；DTO中同名字段不能由Body覆盖。目标样品V2链还要求 `X-M05-Contract-Version: 2`；尚为骨架的接口不能仅补头就认为已接线。

当前明确带 `@CurrentManagementRevision` 的M05预检是038（使用全限定注解）。028和更正读口未标注；结果读口也未提供对应闭环来源。**只允许签批页使用自身038预检回执；其他写动作等待BE04/07，不调用038去借管理版本。**

超时或断网：保留原请求ID和原载荷，显示“结果待核实”；已发送设备命令不能自动重发。014目标查询只查本人且当前仍可读的原操作；它目前501，不能伪装成已有恢复通道。重新编辑后属于新意图，须刷新/重新预检并用新键提交。

### 4.3 权限与状态分层

- 功能权限、对象范围、当前身份、状态和版本均需服务端逐次验证。按钮依据权限和 `allowedActions` 展示；allowedActions缺失/空不能按管理员身份自行补齐。
- 本人身份区分：暂存管理为创建人（Q08）；撤回上传、异常、取消登记为固定送检人；撤销签名/审核为当前有效动作本人。使用稳定userId，不能比较姓名、昵称或工号。
- 下列维度独立展示，不共用一个状态字段推算：

| 维度 | 编码/意义 |
| --- | --- |
| resultStatus/queueStatus | idle/stored/pending/testing/tested/uploaded/signed/reviewed/voided/timeout/exception/cancelled |
| occupancyState | DRAFT/RESERVED/RUNNING/UNKNOWN/COMPLETED/RELEASED；表示位置证据 |
| resultCompleteness | NONE/PARTIAL/COMPLETE/UNVERIFIED |
| deviceCompletion | NOT_FINISHED/FINISHED/UNKNOWN |
| collectionState | UNVERIFIED/OPEN/RECONCILING/CLOSED/CLOSED_EXCEPTION |
| itemOutcome | VALUE/ERROR/NO_MEASUREMENT/UNKNOWN |

空白输入行不产生一条idle样品；已有idle记录也不是空位。首项返回可显示“已检测”，但只要还有应回项目未返回，位置不得释放。手工上传不补足结果、不自动释放位置；不能由uploaded/signed文字反推物理位置已空。

### 4.4 错误处理

| 错误/情况 | 页面行为 |
| --- | --- |
| INPUT_INVALID、逐字段校验 | 定位字段，保留草稿；同一行多项问题完整展示 |
| NON_CULTURE_CONFIRM_REQUIRED | 仅对对应clientRowKey显式确认；无法访问已关联培养时不能借确认绕过权限 |
| CLIENT_UPGRADE_REQUIRED | 提示功能需使用新流程；禁止退回旧URL或去掉版本头重试 |
| RESULT_VERSION_CONFLICT、管理版本冲突、CONFIRMATION_EXPIRED_OR_CHANGED | 清除预检，刷新后重新确认；不自动覆盖 |
| RESULT_STATE_CONFLICT、SIGNER_CANNOT_REVIEW、ONLY_CURRENT_ACTOR_CAN_REVOKE | 展示具体原因，刷新当前状态/有效操作人 |
| FORBIDDEN_OR_NOT_FOUND | 统一无权或不存在文案，不泄露隐藏对象的样品号、项目或人员 |
| RESULT_PROJECTION_UNAVAILABLE、ACTOR_IDENTITY_UNVERIFIED、DEPENDENCY_UNAVAILABLE | 明确待核验/依赖不可用；阻止相关写入，不能当作“无记录” |
| CORRECTION_ALREADY_PENDING、CORRECTION_BASE_CHANGED、USE_CONTROLLED_CORRECTION | 指向已有更正/刷新基线；不重写原结果 |
| 501 | 功能待后端接入；生产按钮关闭，开发环境保留可见诊断 |
| 网络超时/UNKNOWN | 原请求结果待核实，保留占位和原请求键，不自动补发 |

完整业务码以现行错误码登记和后端结构化错误为准。`issues`在不同接口可能为字符串数组或对象数组，按各自类型适配，不统一硬读`.message`。

## 5 页面开发说明

### 5.1 FE01 设备入口、配置与通讯校验

1. 进入BGA/Vi-CELL/OSMO/Cedex页面，读取授权实验室、真实设备；实验室改变清空设备和旧规则快照，型号来自设备配置。
2. 复用 GET `/detect/workbench/options`、`/labs`、`/detectors`；项目选择来自当前范围，检测项来自 `/detector/{detectorId}/available-items`，不从所有检测项中客户端筛。
3. `runtimeProfile={profileRevision,configurationReady,issues:[{path,code,message}]}`。就绪须同时满足true、合法版本、无问题；缺失/刷新失败立即清旧就绪状态并阻止新写。失去设备可见性清空所选设备。
4. 按最新澄清，每次进入该台操作界面需通讯探活，通过才开放新增填写/发送；发送时仍再次检查在线。接入配置校验、进页面探活、发送校验三者不可合并。
5. 探活失败不删除已有未发送记录、不改变在测状态/占位。已有留存的人工重发按其专门规则处理，不因探活失败清空；实际派发仍需发送当刻校验。
6. “通讯未验证”提示仅在通讯配置页和该台检测操作界面；不加到设备清单/详情/发送记录。不要求“我知道了”，不记录谁已读，不以未确认提示增加门禁。探活成功摘标也不等于设备接线或能力核准。

| Excel导出 | XLSX_EXPORT且显式CULTURE或DATE；项目/批次必选，cultureId可选且属于批次；不能以cultureId为空猜模式 |

批次报告取批次内全日期；样品任一类型满足uploaded/signed/reviewed后，扩展读取其全部授权检测类型及日志。与签名台当前页、日期筛选、所选卡片不同，确认弹窗必须解释实际范围。两种Excel模式改变分组，不偷偷截断数据；非培养样品不伪造培养sheet。

预览显示用途、范围、版本、扩展类型、排除原因、数量和模板；超过上限明确拒绝，不静默截断。缺打印机不阻塞PDF/XLSX。创建后冻结清单/版本/日志截止点；随后撤销签批不改写原文件。下载时重新验证当前权限，失去任一必要范围应拒绝，而不是缓存下载URL继续放行。

状态PREPARING/RENDERING/READY/FAILED/SUBMITTED/UNKNOWN按实际返回展示；SUBMITTED只是打印任务已提交，UNKNOWN不能显示完成。stateReason为服务端受控原因，不能把外部错误文本/文件路径直接展示。轮询卸载即停、失败退避；具体间隔作为前端配置，不伪称已冻结接口要求。

### 5.11 FE11 人工取消登记（接口待登记）

只做“我已在设备上取消”的受控登记：原固定送检人本人、当前功能权限及对象范围同时成立；原因1—500字，操作者与时刻由服务器写入；占位代次+版本+幂等确保只生效一次。

不由创建人替代发送人，不允许管理员/设备负责人代登记、转交或委托；本人不可用而长期占位是已确认边界。只需本人单人登记，无M06/第二人审核。登记产生“人工报告”的异常终结证据，不伪造设备取消回执，不接收浏览器finished=true。

成功后也保留原样品/结果和迟到原文；迟到数据不能重新激活已终结代次、自动上传/签批或供M07正常消费。当前URL、方法、请求/回执、权限及菜单未登记；仅保留交互设计与禁用状态，BE10完成前不实现猜测接口。

### 5.12 FE12 旧入口治理

050—060分别关闭结果/明细直接写、签名记录改删、审批人增改删/邀请。旧异常和旧打印导出同样关闭。旧只读列表可按范围保留，但不能从详情页漏出通用form保存、快捷删除或复制修改测量数值。
