# M09 前端开发交接文档

本文面向前端开发、后端联调和测试人员，覆盖 M09 告警与通知管理。沿用前序模块文档结构，提供页面任务、字段、接口、交互规则、源码差异、依赖与验收条件。

- 编写日期：2026-10-09；代码基准：本地 `cloud@a1a54bcb`。
- 依据：当前需求/详细设计、M09 专题契约、Controller → ApplicationService → Mapper/Port，以及前端 `src` 源码。
- 本次为静态核对；未运行构建、单元测试、数据库、HTTP、浏览器或真实设备/短信/邮件。旧批次记录中的测试结果不作为本次执行证据。
- 接口已接线只说明存在业务代码，不代表需求全部完成或环境已验收。目标规则、现有实现和交付阻断分别标注。

## 1 阅读顺序与交付方式

1. 前端负责人按第2节分派任务，第3节确定现有页面的迁移范围。
2. 第4节统一 SDK、响应外壳、版本和状态；第5节按页面实现。
3. 第6节 BE 编号是后端/联调依赖；第7节是验收用例。
4. 附录A映射全部21项正式HTTP接口；附录B/C给出实际Java请求、响应及嵌套模型；附录D列枚举；附录E提供源码证据。

文中001等短编号均指 M09-xxx。字段附录登记的是当前Java形状；第3—6节登记字段未填充、业务未闭环和设计差异。不得仅按附录出现某字段就认定服务器会返回有效值。

### 2.2 责任边界

- M09拥有告警事实、接收人快照、通知规则、配置修订、人工处理、通知与投递记录。规则保存不等于来源事件已产生，也不等于通知已发出。
- M01提供身份、角色候选、授权、个人通知偏好和管理修订。本人通知不应被管理员通知菜单权限挡住。
- M02提供设备/实验室归属、能力、可信数量与可靠声光控制；M03提供培养生命周期、成员与设备关联；M05提供精确检测结果版本。
- M06提供培养配置变更政策与审批；审批通过后仍须M09应用决定。M07的 CultureOperations 页面承载培养告警与监控组件，M02 DeviceOperations 承载空设备配置。
- M08统计页面不作为告警业务入口或状态事实源。旧独立离线配置页不代替“当前培养”的正式入口。
- INT01事件接收、INT02配置决定、INT03投递对账、INT04截止评估、INT05监控ACK是内部能力；本批21项HTTP没有对应通用入口，不自行拼接URL。
- 声光控制、监控执行应用、在线采集触发、离线检测事件均标“待后续联调”；邮件/短信标“待通道联调”。数据库保存成功不能解除这些标记。

## 4 公共协议、状态、权限与错误

### 4.1 请求与外壳

复用现有网关baseURL、会话与请求器，不自行添加 `/system`。当前21项Controller均 `success(serviceResult)`，读取成功业务体在 `AjaxResult.data`；001是 `data={total,rows}`，017是 `data={context,channel,pageNum,pageSize,total,notificationRows,deliveryRows}`。不能套旧列表的顶层rows。

`client.ts`保留完整外壳；SDK也必须保留顶层 `managementRevision`。身份来自会话，路径alarmId/deliveryId/deviceId由Controller绑定；Body不复制矛盾ID。

| 写接口 | 对应读基线 | 当前写协议 |
| --- | --- | --- |
| 003 | 001或002顶层managementRevision + AlarmRow.version | X-Request-Id、X-Management-Revision；Body action/remark/expectedVersion |
| 005 | 004顶层managementRevision + rules[].version | 逐行expectedVersion；新增行不带ruleId/expectedVersion；rules整组 |
| 007 | 006顶层managementRevision + version/revisionId | expectedVersion与baseRevisionId独立；首次配置按无对象分支，不造版本 |
| 009 | 008顶层managementRevision + rows[].version | labId/tab、显式rows、每行expectedVersion；baseRevisionId仅用真实可得值 |
| 015 | 014顶层managementRevision + revisionId | Body scope/baseRevisionId/mode/remark；没有expectedVersion字段，不加自造字段 |
| 019 | 017顶层managementRevision + notificationRows[].version | context=SELF、items[{notifyId,expectedVersion}]，1..100 |
| 021 | 020顶层managementRevision + delivery.version | 路径deliveryId、Body expectedVersion |
| 011/013/016 | 目标使用对应作用域/对象的真实版本 | 当前骨架未接ManagementGuardedWrite；解除BE06/07/10时同步补读写契约，DTO有字段不等于头已生效 |

以上七个已实现写口由守卫及Controller从头权威回填元数据。管理修订、配置revisionId、对象version是三个不同概念；缺失不能写死1、取当前时间或借其他模块的revision。历史空版本只有服务明确投影为字符串`"0"`时原样提交，不把任意缺失版本补0。

一次明确意图一个requestId；双击锁按钮；超时保留原ID及非敏感载荷，先回读当前事实。没有统一公开“按requestId查询M09收据”的HTTP，恢复入口需BE01明确，不能自动换键重发。修改载荷后先重新读版本，再由用户确认新意图。

### 4.2 写结果的当前真实形状

当前公共 `MutationResult` 是 `applied/requestId/managementRevision/objectId/objectVersion/credentialVersion/policyVersion/nextAction/warnings`，**没有**旧页面设计里的通用outcome/revisionId/approvalId/commandId字段。专用响应见附录。

- 003：`data.mutation`与`data.current`；刷新详情和当前列表行。
- 005：`data.results`当前固定一条台账级MutationResult；不得与rules逐项zip，也不能把objectId当ruleId。BE03补齐或冻结统一响应后验收。
- 007/009/015：`data`为公共MutationResult；009/015 objectId取台账修订，objectVersion当前写为`"1"`，不是每行/策略的最新版本。保存后重新读取。
- 019：`data={requestId,results:[{notifyId,outcome,readTime,version}]}`；outcome为READ/ALREADY_READ。它不是公共MutationResult，不读取不存在的applied。
- 021：`data={mutation,delivery}`；`mutation.nextAction=RESENT_ENQUEUED`表示已入队，保持PENDING状态。
- applied=true只能提示“配置已保存”“已标记处理”“重发已入队”等与动作对应的事实，不能提示“通知已送达”或“监控已关闭”。

### 4.3 类型和时间

- ID与版本使用string，禁止Number/parseInt转换；Java Long经公共Jackson输出字符串，包括total/count/attemptNo等计数。分页计算仅在确认安全整数范围后转换，不影响ID。
- Integer状态仍按整数处理；旧页`"0"/"1"`应在SDK边界规范，页面不要散落弱比较。
- BigDecimal当前没有统一字符串序列化，不能因设计写“十进制字符串”就假设线上一定是string。输入保留十进制文本，避免JS浮点计算阈值；与BE01固定真实响应夹具及精度后接入。
- 日期筛选为`YYYY-MM-DD`，成对且start≤end，业务日Asia/Shanghai半开区间；默认每页10，可选10/20/50/100。配置整组不分页。
- 公共Jackson对Date/OffsetDateTime输出`yyyy-MM-dd HH:mm:ss`，OffsetDateTime不带偏移且保留原墙上时间。M09部分读服务转Shanghai，Attempt映射转UTC，不能一律在浏览器追加Z或假定同一时区。BE01统一传输口径后验收跨日/边界查询。

### 4.4 状态显示

| 维度 | 值及文案 | 交互约束 |
| --- | --- | --- |
| 异常条件 | ACTIVE异常中、RESOLVED已恢复、LEGACY_UNKNOWN历史未知 | 与人工处理独立，已处理仍可能异常中 |
| 人工处理 | handleStatus 0未处理/1已处理；handleAction 1处理/2忽略 | 已处理只读；不由conditionState推算 |
| 接收人 | RESOLVED已解析、KNOWN_EMPTY确认无人、UNKNOWN待核实 | UNKNOWN不能当空集合扩大处理权限 |
| 投递 | PENDING待发送、SENDING发送中、SUCCEEDED已确认成功、FAILED失败、UNKNOWN结果待核实、SKIPPED已跳过、CANCELLED已取消 | 只有FAILED可申请重发；UNKNOWN不重发 |
| 已读 | isRead 0未读/1已读 | 仅site；email/sms的SUCCEEDED不代表已读 |
| 配置来源 | OWN当前配置、DEVICE_PREVIEW设备配置预览、EMPTY未配置 | 空自有配置也应OWN，当前在线读存在差异 |
| 配置应用 | NONE/PENDING/APPLIED/CONFLICT | 审批/配置修订状态；不当设备ACK |
| 监控 | ON开启、TEMP_OFF临时关闭、LONG_OFF长期关闭、UNKNOWN未知 | UNKNOWN仅读，不能保存为模式 |
| 执行确认 | APPLIED已应用、PENDING待应用、UNKNOWN未知 | 当前014恒UNKNOWN；不能根据mode反推 |
| 通道就绪 | READY配置就绪/BLOCKED受阻；缺失值显示未知 | READY不等于已做真实发送验证 |

建议成功绿色、待办/部分橙色、失败红色、未知灰色，状态同时保留文字及说明，不只靠颜色。未知枚举显示“未知状态（原值）”，关闭危险动作；不将任意非FAILED值归为成功。

### 4.5 权限与失败处理

接口功能权限见附录A。按钮至少同时满足功能权限、服务端allowedActions、对象状态及本文件记录的实现门禁；当前010/012、017 ADMIN的动作投影有差异，应额外关掉未开放的保存/标读。前端隐藏按钮不能替代服务端授权。

- 017 SELF、018、019 SELF均使用本人身份；不提交userId。017 ADMIN需要`smp:notification:list`；019 ADMIN当前拒绝。
- 020 USER目标本人可读，非本人需`smp:notification:query`；SOUND/EXTERNAL目标需要`alarm:delivery:operate`。管理员查询权限不自动授予声光/外部运维权限。
- 021需`alarm:delivery:resend`，同时核实目标读取资格。列表看得到不代表详情/重发有权。

| 失败类别 | 页面处理 |
| --- | --- |
| 400 INPUT_INVALID/VALIDATION_FAILED/INVALID_ARGUMENT/ROW_SCOPE_MISMATCH | 定位field/rowId；无issues时表单顶部显示原因；保留非敏感草稿；整组不宣称部分成功 |
| 401 UNAUTHENTICATED | 会话恢复流程；清秘密、本人数据和缓存 |
| 403 FORBIDDEN | 关闭当前操作；不切换SELF/ADMIN或调用旧接口绕过 |
| 404 NOT_FOUND | 对象不存在或无权；隐藏旧详情与路径敏感参数，不探测真实存在性 |
| 409 VERSION_CONFLICT/STATE_CONFLICT/ALREADY_HANDLED/DELIVERY_NOT_FAILED | 回读真实状态，保留非敏感差异供重新确认，不自动覆盖 |
| 409 IDEMPOTENCY_CONFLICT/EVENT_CONFLICT | 停止原键修改，展示原请求身份，核实后再形成新意图 |
| 409 ADDRESS_CHANGED | 不修改旧投递目标；来源新事件须先核实旧UNKNOWN |
| 503 DEPENDENCY_UNAVAILABLE/FACTS_UNAVAILABLE/RESOURCE_FACTS_UNAVAILABLE/POLICY_UNVERIFIED/RECIPIENT_UNKNOWN | 展示依赖不可用，关闭提交；不能当空列表/免审批/无人接收 |
| 501 骨架未实现 | 明确“功能待接入”；不调用旧写口、不伪造成功 |
| 网络超时/未知结果 | 保留原requestId/对象ID；可刷新事实，不自动生成新投递 |

外部reasonCode与HTTP errorCode分开。CHANNEL_UNCONFIGURED、SMS_TEMPLATE_TOO_LONG、MISSING_ADDRESS、SKIPPED_PREFERENCE等是投递原因；按明确证据映射提示，未知原因原样保留安全摘要，不按文案子串猜成功。

### 5.11 页面公共完成条件

- 加载、空数据、无权、依赖故障、未知结果分别渲染；网络失败不显示“暂无记录”。
- 详情/筛选请求带取消或epoch保护；保存期间锁同一意图；路由切换清理计时器、秘密与上个作用域的状态。
- 表格稳定ID作key，表单错误定位行/字段；键盘可操作，弹窗关闭后焦点返回入口；状态文字可被读屏读取。
- 通知正文默认转义；富文本若开放必须经核准白名单清洗；不使用原始v-html执行消息内容。
- 不记录完整联系方式、秘密、正文或原始响应到日志；排查信息只保留requestId、对象ID、版本、原因码。
- 没有正式接口的导出、测试发送、未知结果核实、批量全部已读等动作不制造按钮背后的虚假成功。告警旧导出仅可在筛选/权限适配核实后复用。

### A.2 字段使用约束

- GET模型中没有分页字段的配置读取不发送pageNum/pageSize；拒绝未知分页参数是目标要求，DTO没有字段不等于服务器已经显式拒绝。

- Scope、RuleInput、OnlineInput、StatusConfigRowInput、OfflineConfigRowInput、NotificationReadItem虽在vo包，也被请求DTO使用，详见附录C。
- AlarmDetail继承AlarmRow，已展开；PageResult<T>用于001时T=AlarmRow。枚举大小写保持不变。
