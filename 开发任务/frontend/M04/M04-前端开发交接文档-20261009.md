### 3.3 前端现状及改造点

- `processTemplate.ts` 已给 create/update/copy/status/delete 加 writeHeaders，列表使用 pageRowsWithRevision；补液编辑器已接收 managementRevision 并在缺失时阻止提交。保留这些修复，不回退到仅 Body 元数据。
- 该 SDK 的 content、columns 主要按 FEEDING 建模，不能直接把同一 FeedingContent 类型套给其他五类；改为按 templateKind 区分的联合类型，各类有独立输入白名单。
- 补液编辑器从详情装配的绑定，普通修改为 RETAIN，复制为 SELECT；后端尚拒绝 RETAIN，且复制不能未经确认重选当前子版本。需按 FE08/BE04 收口。
- 现有补液 SDK 将 specificationSnapshot、resourceSnapshot 带 null；目标可写投影要求移除服务端只读快照字段。当前规范化器要求这些键存在并忽略值，存在契约差异，见 BE05，不原样回传真实快照。
- 补液规范化输出的 specificationSnapshot 和各泵 resourceSnapshot 当前仍为 null，版本写使用该规范化 content。015 能读取资源事实不等于这些事实已固定进版本本体；工程段的独立固定也不能替代培养基/耗材等内容快照，列 BE05。
- 泵速页面仍调用 `/lab/pumpSpeed/...`、strategyId 与旧平面字段，正式模板使用 templateId/versionId/content。不能把旧 strategyId 当作新模板身份，或把旧 CRUD 成功标为正式版本链完成。
- workflow.ts 仍允许无 ID 的二级流程/步骤，查询缺 labTypeList，写请求没有守卫元数据；目标工作流只编辑固定结构，须按 FE09 修正。

## 4 公共前端契约（FE00）

### 4.1 路由、响应与管理版本

- 正式文档浏览器路径含 `/system/process/...`、`/system/lab/...`，Controller 服务内去掉 `/system`。当前模板 SDK 使用 `/system/process/templates`，工作流 SDK 使用 `/process/workflow`；复用 client/apiBaseUrl/网关约定，联调记录实际 URL，不能全局随意增删一次前缀。
- 当前 011 是顶层 rows/total/managementRevision；003、012、013 的 Controller 仍 success(PageResult)，实际分页在 data 内。SDK 按接口适配并登记 BE08，不能对所有列表统一读 data.rows 或顶层 rows。
- 006—010 必发 `X-Request-Id`（本次固定 UUID）与 `X-Management-Revision`；后者来自本页面的 011 响应。001 创建上下文和 002 详情当前不能作为已验证版本来源。仅有 add/query 而无 list 权限时，需要后端补合法读版本出口，不借别的模块 revision。
- templateId、versionId、currentVersionId、objectVersion、versionNo、managementRevision 全程字符串。schemaVersion 是整数；对象版本、内容版本与管理版本含义不同，不能互换。
- 修改同时带 expectedObjectVersion、expectedCurrentVersionId；复制带 copySourceVersionId、expectedSourceObjectVersion；启停/删除带 expectedObjectVersion。禁止用 updateTime 当版本。
- 同次重试保留原 UUID 和载荷，双击合并；结果未知不生成新 UUID。当前没有公开通用写回执查询 URL，不虚构接口。按已守卫端点的原请求重放核对结果；发生冲突后刷新、比较并由用户重新确认。
- 同键异载荷拒绝是目标验收要求，当前 BE11 未满足完整摘要覆盖：例如修改仅将 templateId 传给守卫，复制仅包含来源身份/版本。重试必须使用提交时封存的请求，不能拿用户随后编辑的表单重建相同 UUID 请求；后端补齐摘要及回执响应前，不把此约束视为已由服务器完全保证。
- 成功后重读对象及列表。编辑/复制构造明确字段白名单，不将 Detail 原样回传；修改不附 status，状态走独立 009。

### 4.2 名称、枚举、日期、数字与空值

- 除泵速名称 1—19 字外，模板名称 trim 后 2—50 字；同类型未删除身份占名，禁用仍占名。删除后可复用名称，但新身份不能顶替旧版本引用。
- status=`"0"` 启用、`"1"` 禁用；禁用也须完整内容校验，不是保存半成品的方式。
- 模板实验室类型 PILOT/SMALL/COMMON 与工作流 smp_lab_type 的 `"1"—"4"` 分开映射；不得混用大小写或字典值。
- DEC(p,s) 使用普通十进制字符串；拒绝科学计数法、NaN、单位文本、超精度，不静默舍入。I32 字段用整数，技术容量不是设备能力上限。
- 未选分支按 schema 显式 null，集合按指定空数组；缺字段、null、0、空串不能互换。未知资源/量程不填 0，DEFAULT 温度也不是 0℃。
- 日序号为 D0，0≤dayIndex/arrivalDay/startDay/endDay<cultureDays，区间含两端；HH:mm:ss 长度 8，按上海业务日解释。规则 ruleId 为稳定 UUID，排序用 displayOrder，不以数组下标关联绑定。
- 列表 beginDate/endDate 允许单端，与 M03 的成对日期要求不同；结束日按次日 00:00 不含。前五类 timeField=CREATED/UPDATED；泵速不传 timeField，以创建或修改时间命中。
- pageNum≥1，pageSize=10/20/50/100，keyword≤100。筛选变更回首页；空页仍可新增；删除末条后回退有效页。请求取消或序列号隔离过期响应。

### 4.3 权限与可用状态

类型权限前缀分别为 process:config、process:perfusion、process:sampling、process:autoControl、process:feeding、process:pumpSpeed；动作 list/query/add/edit/changeStatus/remove。复制用来源 query + 目标 add，没有另造 copy 功能码。当前服务已有动态 requireFunction 判权，不能仅因 Controller 没有静态权限注解就判断无权限校验。

列表/详情按对象可见，限定实验室模板读需可见；维护原范围及修改后范围至少实验室等级 1。工作流实验室配置维护要求等级 2，不能套模板等级。菜单种子与角色绑定须在目标环境验证，超管测试不代表普通角色可用。

allowedActions 用于当前对象按钮：VIEW/EDIT/COPY/ENABLE/DISABLE/DELETE/HISTORY；新建 Context 可为 CREATE。同时检查接口实际支持程度和依赖状态；不能因按钮在动作集里就忽略四类规范化器缺失或 RETAIN 未接。

资源 COMPLETE、INCOMPLETE、REVOKED、依赖故障区分展示：已知缺项/撤销提示具体资料问题，读取故障提示暂不可核验。模板保存成功不等于实例应用通过，也不等于设备已执行。

### 4.4 共用错误交互

| 错误 | 前端处理 |
| --- | --- |
| INPUT_INVALID/CONTENT_INVALID/READ_ONLY_FIELD | 定位 fieldErrors 的字段、ruleId、slotKey；跨页错误可跳转，保留输入 |
| NAME_CONFLICT/NO_CHANGE | 提示重名或无变化，不创建假版本 |
| VERSION_CONFLICT/MANAGEMENT_CONFLICT | 刷新版本，展示需要重新核对的字段，不静默覆盖 |
| SOURCE_VERSION_CONFLICT/SOURCE_UNAVAILABLE | 新选/重载重新确认；不能自动升级已固定来源 |
| BINDING_INVALID/APPLICABILITY_CONFLICT | 定位槽位和实验室范围交集，不自动删规则缩范围 |
| SCHEMA_UNSUPPORTED/ACTION_NOT_SUPPORTED | 不降级成空表单；保留可读身份信息并阻止该动作 |
| ENGINEERING_REVOKED/工程缺项 | 引导核对 M02 工程资料，不伪造核准版本或单位 |
| RESOURCE_FACTS_UNAVAILABLE/RESOURCE_MAPPING_UNRESOLVED/WORKFLOW_REFERENCE_UNAVAILABLE | 明确依赖不可用，不当空候选/无引用，不自动重试新请求 |
| REFERENCE_EXISTS/STATE_CONFLICT | 刷新当前配置和引用；不得强制清空或连带修改培养 |
| 401/403/404 | 统一会话恢复或无权/不存在说明，不泄露对象名称、实验室和引用数量 |

旧链路可能仍返回 ServiceException 和其他旧错误码；适配时保留未知错误，不把所有失败转换为“参数错误”。完整来源见附录。

## 5 页面与功能开发说明

### 5.1 FE01：六类模板列表、详情、历史与动作

共用列表骨架，按类型独立配置列/筛选；每行读取 `{template,columns}`。

| 类型 | 专属筛选（公共 keyword/日期/分页之外） | 专属列 |
| --- | --- | --- |
| CONFIG | reactorType、controlPlatform=DELTAV | 平台、反应器类型、工艺类型 |
| PERFUSION | reactorType、status | 反应器类型、型号 |
| SAMPLING | applicableLabId | 固定实验室、检测方式 |
| AUTO_CONTROL | reactorType、cultureDays 精确且>1 | 周期、规格引用、监控间隔 |
| FEEDING | reactorType、modelKind/modelId 成对、cultureDaysKeyword | 型号、固定规格、周期；周期关键词为1—10位数字文本包含匹配 |
| PUMP_SPEED | labType 精确、strategyType 二段/三段 | 理论分钟、各阶段速度/占比；keyword 同时匹配名称或时长展示串 |

### D.1 数字编码与 Config/灌注公共对象

[字段权威来源](../../../../docs/详细设计/04-工艺与方案管理/模板内容存储契约.md)。

#### 1.1 数值与空值编码

| 记号 | JSON编码及技术容量 | 约束 |
| --- | --- | --- |
| ID | 非空十进制字符串，对应正bigint | 无正号/指数/小数；由服务端校验身份，不使用名称匹配 |
| I32 | JSON整数，−2147483648至2147483647 | 所有字段再施加业务范围；无明确业务上限的正整数使用此技术容量，不能将其误报为设备支持上限 |
| DEC(p,s) | 普通十进制字符串，总精度p、最多s位小数 | 不允许NaN/Infinity/科学计数法/单位文本；输入超精度报错，不自动四舍五入后保存 |
| STRING(n) | JSON字符串，最多n个Unicode字符 | 是否允许空/NULL按各字段定义；快照忠实保留合法资源显示值 |
| NULL | JSON null | 与属性缺失不同：下文要求存在的键缺失时报告必填错误 |

数值存储/内容hash使用规范字符串：去多余整数前导0和小数末尾0，零统一为"0"。例如"99.00"规范为"99"，但不因规范化接受超出原允许小数位的输入。页面格式化两位小数只是展示，不能改变存储精度。计算用十进制/精确整数，不用二进制浮点累积。

I32容量是本次存储类型决定，跨字段乘法使用至少64位或任意精度中间量并先检查容量，不以各输入均合法推断结果不溢出。特别是Vi-CELL派生检测量的容量与原样品量1—9998范围分开；不得把派生量强制压回样品量范围。

#### 7. Config与灌注共用结构

以下为第二批字段树草案，字段位置已展开，Q11量程校验时点已确认，PID工程约束及型号精确来源尚未闭合，不能据此发布运行算法。CONFIG/PERFUSION的content_schema_version目标为1，calculation_profile=M04_CALC_V1；未完成的工程约束不以schema编号冒充已验证。

本节延续ID、I32及十进制字符串编码。未明确输入精度的工程数暂以DEC(20,6)作为存储容量，明确一位/两位小数的字段仍执行原精度；六位不是设备允许精度，也不表示可自动舍入未知设备参数。单位、符号、物理上下限和量程对应未核准时保持依赖未就绪，不能给未知值补0。所有新增存储路径是设计字段，不是现有接口。

#### 7.1 型号引用与稳定通道

| 路径/结构 | 类型与完整叶子 | 规则 |
| --- | --- | --- |
| reactorType | INTEGRATED_REACTOR/BENCH_REACTOR | 与既有类型逻辑一致，不用实例ID替代型号 |
| models[] | 非空有序数组，每项仅modelKind、modelId | modelKind=INTEGRATED_MODEL/BENCH_CONTROLLER_MODEL；modelId为ID；同类型且去重，依reactorType选择来源 |
| models[].modelKind | STRING(32)，固定判别码 | 集成关联dev_integrated_reactor.model_id；台式须控制器类型库，不能误用台式容器型号dev_bench_reactor |
| models[].modelId | ID | 台式控制器类型精确表/列仍待M02契约核对；不虚构表或按名称寻找ID |
| MFC通道身份 | channelNo:I32，1…M | 本版本型号兼容通道集合内稳定编号；MFC1等显示码由编号派生，不以数组位置关联 |

型号集合投影到prc_template_version_model，display_order取明确数组次序；保存前重新核验泵数、MFC数及温度/重量/压力能力一致，灌注还要求规格一致。Config不增加规格一致条件。集合变化使通道/回路失效时保留编辑输入并阻止提交，不静默删行或重挂。

#### 7.2 两输出映射MAP2

MAP2为恰好两条输出，按outputNo=1、2排序。用于Config的loops.do/loops.ph，以及灌注parameters.loops.do/parameters.loops.ph已配置分支；不是JSON中可提交任意回路名的开放映射。

| 每项叶子 | 类型 | 校验 |
| --- | --- | --- |
| outputNo | I32 | 1或2，集合恰为{1,2} |
| source.kind | MFC/PUMP | DO只能MFC，pH允许MFC或PUMP |
| source.channelNo | I32 | source.kind=MFC取channelNo，PUMP取pumpNo；按判别码校验对应集合，不跨表碰数字 |
| inputStart、inputEnd | DEC(20,6) | 两者不同，保留方向；0→−100合法结构，不强制升序 |
| outputStart、outputEnd | DEC(20,6) | 两者不同，保留方向；两个端点都要满足有证据的输出量程 |

source对象仅kind/channelNo两键，无设备命令、名称或通路可写字段。DO选择完整Air/O2通道；pH选择完整CO2通道或完整泵；两输出不能同源，同气体同通路的重复按主设计规则拒绝。显示通路从同版本MFC行派生，不独立存第二份。两个输入区间将端点取min/max后比较，允许端点相接，不允许正长度交集。

例：输入区间[−100,0]和[0,100]可相接；[−100,0]与[−1,100]重叠1个单位，拒绝。输出量程0—100时0→80可通过范围项，0→101不能通过；灌注应用时按已确认Q11对照培养固定的有效Config及目标设备能力，不擅自新增量程输入框。

#### 7.3 PID_SET

PID_SET固定五键do、ph、vesselTemp、jacketTemp、vesselPressure。每个非null对象只含gain、reset、rate三项DEC(20,6)，全部必填；不存自由表达式或函数。do/ph/vesselTemp必有对象，jacketTemp/vesselPressure可为null；设备无对应能力时可选项必须null。不存在agitator PID行，不能凭控制回路有Agitator就新增一组PID。

三个数值的工程单位、符号、物理范围和实际允许精度仍待资源PID契约；有限数和存储容量检查不等于PID合法性完整验证。当前不能宣称负增益或负时间常数有效。初次带入需全部所选型号有相同合法来源，否则由允许的页面输入供校验；保存后读取本模板版本，不从当前资源重新覆盖。后续明确工程规则必须同步到本节和版本兼容策略，不能悄悄把已存旧值按新单位解释。

| backflowFactor、backflowCheckFactor | monitor.backflow.factor；检查系数由monitor.jitter.checkFactor生成 |
| clogCheckFactor、clogFactor | monitor.clog.checkFactor/factor |
| calibrationRatePctPerMin、highDurationMin、lowDurationMin、theoreticalDurationMin | 固定公式版本只读计算，不写可变内容值；总时长展示投影写version.duration_display_min |

理论时长比较保留精确分数或等价精确计算，不把两位小数展示值用于超时判定。比如calibration占比10%、运行180秒，其理论速度是10/3%/min，不能先截成3.33再倒算校准时间。所有求和完成后才对展示分钟HALF_UP两位；无法整除的中间结果不逐步舍入。

Q09正常抖动计算固定为同窗口：Δj=intervalSeconds×jitter.checkFactor，threshold=max(精度×jitter.scaleFactor，窗口开始理论每秒流量×Δj×jitter.factor)。它在运行时还需要目标量、同单位精度及可信窗口读数，模板仅保存参数。下发0泵速后的观察恢复、跨阶段窗口和命令执行结果仍待M07，不凭本模式新增默认算法。

正常停泵和超量比较沿已确认的≥终点、>超量边界；三段100%占比理论总时长与endpointPct<100的提前停泵独立，不能按二段式公式改写三段低速输入占比。

### D.6 自动控制/补液公共规则

[字段权威来源](../../../../docs/详细设计/04-工艺与方案管理/模板内容存储契约.md)。

#### 11. 自动控制与补液的规则公共结构

第三批补齐AUTO_CONTROL/FEEDING字段树草案，schema目标均为1、calculation_profile=M04_CALC_V1；继承第1节数值编码与第7节型号判别规则。页面显示字段全部有存储或只读生成落点，但规格/型号映射、资源证据接口和运行恢复仍有明确依赖，不能据此宣称整个模块已具备编码/执行条件。

#### 11.1 行身份、日期与时间

每个规则对象必含ruleId（规范小写UUID字符串，36字符）与displayOrder（I32≥0）。同模板全部规则ruleId唯一，displayOrder在所属规则数组内唯一、用于展示排序；数组规范化按displayOrder，执行时间另算，不能用排序号当执行时间。修改保留原ruleId，新增生成新ID；复制模板为所有行重建ID并重新映射取样槽位，来源版本和合法有效参数沿Q01/Q02固定。客户端不能借沿用不存在的规则ID获取旧绑定资格。

dayIndex/arrivalDay/startDay/endDay都是I32日序号，0≤日序号<cultureDays；起止区间含两端且startDay≤endDay。HH:mm:ss是长度8的24小时字符串，00:00:00—23:59:59，无时区后缀；解释时采用Asia/Shanghai业务日，不能将D1理解为保存后经过24小时。时间缺失不得填00:00:00默认掩盖。

#### 11.2 自动控制DetectionSpec

| 对象叶子 | 类型/空值 | 规则 |
| --- | --- | --- |
| configured | boolean | 定时取样必须true，其余可false |
| waitMinutes | I32或null | true时≥0，表单默认0；false时null |
| baseType | RULE_TIME/TASK_COMPLETED_AT/PREDICTED_AT或null | true时由槽位类型固定，不能自由替换；false时null |
| slotKey | STRING(128)或null | true时服务端按ruleId和用途生成；false时null且无绑定行 |

定时取样slotKey=rule/{ruleId}/scheduled，baseType=RULE_TIME；完成检测=rule/{ruleId}/completion、TASK_COMPLETED_AT；温度预测检测=rule/{ruleId}/predicted、PREDICTED_AT。每个true槽位与一条SAMPLING绑定一一对应，parent_rule_id=ruleId、effective_schema_version=1，完整有效内容采用第2节七键SAMPLING结构。false却提交非空等待/基准/槽位或遗留绑定行，整体拒绝，不默默生成隐藏检测。

AUTO_CONTROL原文允许修改带入检测字段，因此可编辑已允许的类型、样品量、温度/稳定模式、倍数、项目与方式，并按同实验室可用资源和SAMPLING叶子规则重验；不套灌注“只读参数/来源类型子集”的限制。不能修改来源固定实验室来跨实验室使用，不能回写来源版本。全部生效取样绑定的实验室约束与父本体求交，无交集拒绝。

等待基准只保存语义枚举，不提前存任务完成时间或预测时间。定时取样可静态计算业务相对时刻=dayIndex×86400+timeSeconds+waitMinutes×60；使用宽整数计算防溢出，保留跨日结果。同培养检测类型相交且时间差<3600秒冲突，恰好3600秒允许。运行再按M05合格任务集合重验。按用户要求，后续代码常量/核心判定必须注释60分钟业务原因及边界，不能仅在文档说明。

#### 11.3 有边界数值区间WINDOW

WINDOW固定lower、upper两对象，每侧仅operator、value。operator为LT/LE/NA；NA时value=null，其他情况下必填十进制字符串。lower表达value < 或≤ 观测值，upper表达观测值 < 或≤ value；双侧非NA还要求lower.value<upper.value。至少一侧非NA，禁止双NA充当有效条件。各规则具体单位、数值范围见后表。

与灌注pCO2不同，本处lower是“下值与观测值”的方向，不能复用灌注比较方向相反的表达式。日期交集与触发数值集合交集同时存在才按对应规则判冲突；端点开闭参与集合运算，不能只比较阈值文本或只检查是否完全重复。

#### 12.2 六类规则完整业务叶子

下表各数组行均先含第11.1节ruleId/displayOrder，然后仅包含本行列出的属性。DetectionSpec为第11.2节完整四键，WINDOW为第11.3节完整四叶子，不是任意JSON。

| 数组路径 | 本行其他字段（完整） | 数值、单位与关联 |
| --- | --- | --- |
| rules.sampling[] | startDay、endDay、sampleTime、detection | 日序号/时间按第11.1节；detection必须true且RULE_TIME |
| rules.phAdjustment[] | arrivalDay、logicalJoin、temperatureCondition、targetPh、deadbandPlus、deadbandMinus、actionMode、completionDetection | logicalJoin=AND/OR；temperatureCondition仅operator=GE/GT/LE/LT、valueC=DEC(20,6)；targetPh=DEC(20,6)有限数，死区各DEC(20,6)非负幅值；实际物理范围另核准；actionMode=AUTO/MANUAL；完成检测可选 |
| rules.aeration[] | startDay、endDay、window、targetGas、targetRoute、targetFlowLpm、actionMode、completionDetection、maxAdjustments | window两侧value=DEC(20,6)，单位mmHg；targetGas=AIR/O2/CO2，页面默认AIR；targetRoute=SPARGER_1/2，默认2；flow=DEC(20,1)>0 L/min；maxAdjustments=I32>0；actionMode=AUTO/MANUAL |
| rules.agitation[] | startDay、endDay、window、triggerGas、triggerRoute、targetRpm、actionMode、completionDetection | window有效侧=DEC(4,1)，0<值<1000 L/min；triggerGas固定O2，route=SPARGER_1/2默认1且本数组所有行相同；targetRpm=DEC(5,1)，0<值≤9999；actionMode=AUTO/MANUAL |

| rules.temperature[] | arrivalDay、logicalJoin、vcdCondition、targetTemperatureC、actionMode、executionOrder、predictedDetection、completionDetection | logicalJoin=AND/OR；vcdCondition仅operator固定GE、value=DEC(20,6)≥0（×10^6 cells/mL）；targetTemperatureC=DEC(4,1)<100℃，物理下限另核验；actionMode=AUTO/MANUAL；executionOrder=FEED_THEN_COOL/COOL_THEN_FEED；两个检测均可选且基准不同 |

规则关联与冲突条件：PH调整同arrivalDay不得两行；温度调整仅禁止arrivalDay与VCD阈值组合完全重复，不把PH限制套来。通气/搅拌按日期和WINDOW交集检查；微泡日期区间不重叠，连续监测时长不跨低于阈值片段累计。规则涉及的气体/通路必须能映射到合法已配MFC；同气体同通路多通道时精确选择/聚合口径仍需资源与M07契约，不取第一条当作事实。

microbubble的“≥触发流量并持续”的比较符由schema固定，不能替换为仅瞬时满足。aeration的maxAdjustments是配置上限，实际次数/链条ID/重试计数不进入content_json；达到上限只告警的执行逻辑另由M07维护。温度FEED_THEN_COOL沿原文最后一条补液计划时刻+1分钟，不能自动替换成补糖的“等实际补料全部完成”。无补料、迟延、预测算法和事件顺序仍需运行契约。

#### 13. FEEDING schema 1字段树草案

根对象固定八键reactorType、models、supportedPumpCount、specificationSnapshot、cultureDays、remark、pumps、rules。reactorType/models用第7节；型号规格一致且泵数匹配supportedPumpCount，规格与能力未知时不能任选一个型号生成固定泵。

#### 13.1 基本字段、资源快照及固定泵

| 路径 | 类型/完整叶子 | 约束 |
| --- | --- | --- |
| supportedPumpCount | I32>0 | 候选来自资源实际支持集合，不允许手填任意数 |
| specificationSnapshot | STRING(50)，服务端必有快照 | 从已核准的共同规格取得，不靠前端显示文本推导容量 |
| cultureDays | I32≥1 | 允许1天 |
| remark | STRING(500)或null | 选填；空白规范为null |
| pumps[] | 恰N项 | 每项仅pumpNo、mediumId、consumable、speedSelection、resourceSnapshot |
| pumps[].pumpNo | I32 | 1…N完整集合，按编号升序；泵码只读派生 |
| pumps[].mediumId | ID或null | 对应feed_medium.medium_id；Nothing为null，不是0或字符串Nothing |
| pumps[].consumable | 对象/null | 对象仅kind=LIQUID_BAG/BUCKET、id=ID；集成关联liquid_bag.bag_id，台式关联consumable_master.consumable_id并核验CITEM/Bucket类别 |
| pumps[].speedSelection | 固定三键kind、code、slotKey | kind=UNUSED/CODE/TEMPLATE，分支见下文 |
| pumps[].resourceSnapshot | 服务端对象/null | 未使用泵为null；已用泵保存下文完整结构，不能把只读量程/浓度当成用户指定值 |

UNUSED要求mediumId/consumable/resourceSnapshot/code/slotKey全部null，行仍保留pumpNo；已用行培养基与速度选择必须完整，耗材可为null（Nothing=不耗耗材）。CODE仅台式，code为Speed1…Speed10、slotKey=null，无泵速绑定；TEMPLATE时code=null、slotKey=pump/{pumpNo}/speed，对应一条PUMP_SPEED绑定，parent_rule_id=null、effective_schema_version=1，完整参数按第3节固定。策略适配集成=PILOT/COMMON、台式=SMALL/COMMON；速度代码不是rpm也不是同名策略。

本期补液页未明确开放修改带入泵速阶段/监控参数，因此泵速绑定按只读带入完整来源内容，改变策略参数通过维护策略新版本后明确重新载入；不能从核心绑定支持effective_parameters_json推导出所有页面都有任意局部编辑权。已保存父方案可沿Q02保留禁用/删除的来源；新选/重新载入仍需可选资格。

#### 13.2 resourceSnapshot完整结构与来源

resourceSnapshot仅medium、consumable、flowSources、capturedAt四键，capturedAt为服务端采集来源事实时ISO 8601 UTC时间。快照描述模板保存时看到的来源，不保证设备当前可执行；使用阶段仍按实际设备、合法使用方案及必要实时事实核验。

| 完整叶子/集合 | 类型 | 来源与未知处理 |
| --- | --- | --- |
| medium.name | STRING(100)或null | feed_medium当时名称，不按名称识别糖属性 |
| medium.isSugarFeed | boolean或null | 读取来源糖标志；未知不能当false放入普通补料候选，须核准角色归属 |
| medium.concentrationGl | DEC(20,2)或null | g/L；来源允许0不改成虚构正数，按浓度补糖执行必须>0 |
| medium.sourceRevision | 非负十进制字符串或null | 来源管理修订/证据版本；未知保持null，不伪装为当前版本0 |
| consumable.description | STRING(100)或null | 由kind/id对应资源固定 |
| consumable.minimumValue | DEC(20,6)或null | 对应来源下限；当前liquid_bag.lower_limit_vol单位是g，不能因列名vol当作mL |
| consumable.minimumUnit | STRING(20)或null | 跟随有依据的来源计量单位；未知不默认g/mL |
| consumable.sourceRevision | 非负十进制字符串或null | 版本依据同上 |
| flowSources[] | 数组，可空 | 每项仅modelKind、modelId、deviceKind、deviceId、pumpNo、value、unit、sourceRevision；按稳定资源键规范化排序，不存斜杠拼接值 |
| flowSources[].modelKind、modelId | 第7节型号引用 | 记录该量程属于哪个合法来源型号 |
| flowSources[].deviceKind、deviceId | INTEGRATED_REACTOR/BENCH_CONTROLLER及ID，均可null | 同时有或同时null；实例量程必须保留实例身份，不能冒充型号统一值 |
| flowSources[].pumpNo | I32 | 对应固定泵编号，不能与当前pumps[].pumpNo错挂 |
| flowSources[].value | DEC(20,6)或null | 原量程证据，缺失为null；不得取第一个/平均值作为实际执行速度 |
| flowSources[].unit | STRING(20)或null | M02固定泵目标契约已明确g/min；纳入该契约且旧单位已核准者输出g/min，未核准旧range_value保持null，不凭列名批量赋单位 |
| flowSources[].sourceRevision | 非负十进制字符串或null | 来源版本，未知仍保留证据缺口 |

当前[SQL基线](../../../../sql/ymsw.sql)的lab_integrated_reactor_pump_config主键为(integrated_id,pump_no)，range_value为decimal(18,2)，并非每型号唯一量程；来源适配必须保留实例差异。耗材基础表没有下限列时minimumValue/Unit不能由capacity猜出。主设计第10节已定义资源读取投影及sourceRevision语义：同一次一致性捕获的SYSTEM管理修订，非源表更新时间或独立行版本；相关写入口与读取尚未纳入守卫时保持null。台式型号/实例身份映射仍待闭合；暂不能返回可验证来源的值保持未知，不伪造记录。

全方案最多一个isSugarFeed=true的泵；未知糖属性阻止依赖其糖/非糖身份的规则保存。允许非糖培养基重复并提示。已有补糖规则时移动糖泵必须先处理原规则，不将rule.pumpNo静默改到新泵。全量保存应对照旧版本确认这项前置，不能只检查最终恰好一个糖泵而漏掉迁移规则。

#### 13.3 普通补料与补糖规则

rules仅feeding、sugar两个数组键，未配置为[]。每行都有ruleId/displayOrder，其余字段如下；业务日内唯一性不依赖displayOrder。

| 数组/路径 | 完整其他字段 | 规则 |
| --- | --- | --- |
| rules.feeding[] | pumpNo、dayIndex、plannedTime、calculationType、amountGrams、percentValue | pumpNo是完整非糖泵；日序号/时间按第11.1节；calculationType=AMOUNT/PERCENT |
| rules.feeding[].amountGrams | I32或null | AMOUNT时>0整数g，PERCENT时null |
| rules.feeding[].percentValue | DEC(5,3)或null | PERCENT时0<值<100%，AMOUNT时null；保存百分数本身 |
| rules.sugar[] | pumpNo、startDay、endDay、planMode、fixedAmount、concentrationRule | pumpNo须是唯一完整糖泵，不能由任意泵编号绕过归属 |
| rules.sugar[].planMode | FIXED_AMOUNT/CONCENTRATION_RULE | 前者按数值，后者按规则，分支互斥 |
| rules.sugar[].fixedAmount | 对象/null | FIXED_AMOUNT时仅dailyTime=HH:mm:ss、amountGrams=I32>0；其他分支为null |
| rules.sugar[].concentrationRule | 对象/null | CONCENTRATION_RULE时仅operator=LT/LE、lowerGl、targetGl、calculationMode；其他分支为null |
| rules.sugar[].concentrationRule.lowerGl、targetGl | DEC(20,2) | 均>0 g/L且target>lower |
| rules.sugar[].concentrationRule.calculationMode | GLUCOSE/GLUCOSE_LACTATE | 残糖/残糖和乳酸，明确映射旧数值前不直接拷贝旧枚举 |

同一非糖泵dayIndex+plannedTime唯一，即使AMOUNT/PERCENT不同也冲突；同泵不足一小时（跨日按完整相对秒数）仅提示，允许保存。此处代码注释必须说明“前任务可能未执行完，仅提醒”，不得共用Q08取测硬拒绝函数/异常。不同泵同时刻不被该唯一规则拦截，设备共享资源另由运行准入处理。

补糖所有规则共同检查D0闭区间不重叠，两个分支不能各自单独校验而漏掉交叉冲突。CONCENTRATION_RULE不含dailyTime；系统检查周期复用系统设置默认10秒，不在规则中再存monitoringIntervalSeconds。有补料先等全部相关补料实际完成，无补料视为前提满足；所涉任务状态、每日去重、失败/取消重建和NCS061最小量仍由M07细化。模板不存今日已生成、实际重量、检测结果或当前糖量。
