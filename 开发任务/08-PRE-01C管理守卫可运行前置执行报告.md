## 2. ActorContextPort 生产适配器与真实调用链

`com.futurefab.system.service.impl.port.m01.M01ActorContextAdapter`（@Component，唯一生产 Bean）。解析链（全部服务端事实，浏览器 Body 无入口）：

```
网关 AuthFilter(JWT+Redis 校验, 重写 user_key/user_id/user_name 头)
  → HeaderInterceptor(order -10) → SecurityContextHolder(线程上下文)
  → ManagementGuardExecutor.resolveTrustedActor: sessionKey=SecurityUtils.getUserKey(), requestId=WriteMeta
  → M01ActorContextAdapter.resolveActorContext:
      ①sessionKey 与线程 user_key 一致（不等→SESSION_REPLACED）
      ②当前请求 Authorization JWT（JwtUtils 同密钥解析）user_key claim 与 sessionKey 一致
      ③TokenService.getLoginUser 读 Redis login_tokens:{uuid}（缺失/登出/强退→SESSION_INVALID；记录 uuid 不符→SESSION_REPLACED）
      ④线程 user_id 与会话 userid 一致（不一致→ACTOR_IDENTITY_UNVERIFIED，不串号）
      ⑤SysUserMapper.selectUserById 实时复核存在/未删除/未停用（否则 ACCOUNT_UNAVAILABLE）
      ⑥authzVersion 与 labScopes 权威读取（见 §3/§4）
  → ActorContext{actorUserId, actorName, sessionKey, authzVersion, requestId, labScopes} 全字段填充
```

拒绝浏览器自报 `actorUserId/userId/authzVersion/laboratoryIds/roleIds/permissionCodes`：适配器签名只收 `ActorContextQuery(requestId, sessionKey)`，测试 `browserSuppliedActorFieldsStructurallyCannotInfluenceResolution` 断言结果只反映服务端事实。未建立第二套身份模型/会话解析逻辑（复用 `LoginUser`/`TokenService`/`SecurityContextHolder` 既有链路）。

## 3. authzVersion 来源与遗留裁决项

- 来源：`sys_management_revision` 固定 SYSTEM 行当前管理版本（详细设计 §22 `permissionRevision="当前管理版本"，每次鉴权读取管理版本` 口径），每次解析实时读取；DataAccessException/缺行/负值 → AUTH_DEPENDENCY_UNAVAILABLE(503) 失败关闭。
- 登记裁决项 **ADJ-01**：冻结 `LoginUser`（PKG-00 公共模型，本任务禁改）无版本载体，PKGBASE 会话缓存侧"会话签发后权限变更即失效"的一致性校验（§三"会话 authzVersion==权威版本"）无落点；当前实现为"实时权威读取"语义，会话内权限变更在下次守卫写即生效，但**登出外**的"版本变更吊销既有会话"需设计侧补充会话版本字段（`SysUserAuthStateMapper.session_version` 写路径为 PKG-01 骨架 M01-006/057 未实现）。未擅自扩展 LoginUser 或表结构。

## 6. 同事务与失败关闭证明

- 钩子在 `ManagementGuardExecutor` 的单一 `TransactionTemplate` 事务内、CAS/回执之前调用；适配器自身无任何 `@Transactional/@Async` 声明（测试反射断言无 REQUIRES_NEW 传播级别；线程名断言与调用线程一致）。
- 任一失败路径抛异常 → 业务写、revision 递增、回执、审计全部回滚：`auditHookFailureRollsBackEverything`（执行器）断言 revision 回退+回执为空+txRollback；`changeLogAffectedRowsNotOneFailsClosedAfterOperLog` 证明 insert 影响行数≠1 或 operId 未回填即失败关闭。
- 未写入前拦截：敏感键扫描先于任何 insert（测试断言零写入）；"版本冲突 / REQUEST_CONFLICT / 重放 / applied=false 不写审计"在执行器测试断言 `auditSeen.isEmpty()`。
- 重放路径只读回执，不触审计。

## 11. HMAC 密钥部署说明（§七）

- 配置键：`futurefab.management.receipt-hmac-key`（`NormalizedPayloadHasher` 注入；缺失/空白 → 启动失败 BLOCKED_INPUT，无默认值、不回落）。
- 注入方式：Nacos 加密配置 / 环境变量 / 密钥管理服务注入运行时属性；**任何情况下不得**把真实密钥写入 `application*.yml`、Dockerfile、Git 或测试日志（当前仓库符合：源码仅含键名）。
- 各环境使用互不相同的独立密钥；本地/CI 仅需显式提供独立测试密钥（测试均经 `MapPropertySource`/直接构造注入，如 `wiring-test-only-hmac-key`、`unit-test-hmac-key`）。
- 轮换影响：回执指纹摘要以密钥 HMAC 计算，**轮换后 24h 有效期内既有回执的指纹不可再验证**——同 requestId 重传将因摘要不符走 REQUEST_CONFLICT，需按"新 requestId + 刷新版本"恢复；轮换步骤（双密钥窗口/回执清空窗口期）须纳入上线运维轮换计划，密钥轮换机制本身不在本任务范围。
