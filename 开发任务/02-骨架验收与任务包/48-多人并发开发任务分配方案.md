# 多人并发开发任务分配方案

日期：2026-09-26。

本文用于把既有 `37-第9步业务开发任务包总览.md`、`38-业务开发任务包-按人员分配建议.md`、`40-V4业务开发六周计划-0921至1030.md`、`44-M01系统管理批量迁移作战图.md` 中的任务分配重新整理为适合“多人各自在自己电脑开发”的执行方案。

本文不修改业务代码，不替代需求和详细设计正文；它只规定任务包归属、并发边界、共享文件冲突消解和合并顺序。

## 1. 结论

旧分配已经把 48 个任务包分到 `DEV-A` 到 `DEV-D`，但 38 号文档也检出了大量共享文件冲突。多人各自在电脑上并发开发时，不能只按旧表同时开工，否则会在合并阶段集中冲突。

新版方案采用：

1. 每个开发者一个独立分支和独立电脑；
2. 每个任务包只允许一个负责人；
3. 命中共享文件冲突的任务包，改为“同一冲突域单 owner 串行提交”；
4. 跨模块可以并发，跨共享文件不能并发合并；
5. 守卫、审计、登录会话、契约测试登记等共享基础设施由开发人员统一维护。

## 2. 角色映射

`DEV-A` 到 `DEV-D` 仍是编码，不是真实姓名。项目经理需要把真实人员填入下表。

| 编码 | 建议真实角色 | 主要责任 | 是否可远程 |
| --- | --- | --- | --- |
| DEV-A | 开发人员 | 集成、PKG-01 底座、复杂状态机、冲突域评审 | 可远程 |
| DEV-B | 开发人员 | M02/M03/M07 中等复杂包、现场联调包 | 现场优先 |
| DEV-C | 开发人员 | M02/M05/M06/M09、外部系统相关包 | 现场优先 |
| DEV-D | 开发人员 | M01 只读与回归、小包、前端/接口核验辅助 | 现场优先 |
| DEV-I | 开发人员 | 分支合并、共享文件、门禁测试、冲突仲裁 | 可远程 |

如果只有 4 个人，`DEV-I` 由 `DEV-A` 兼任；如果有 5 个人，建议单独设 `DEV-I`。

## 3. 分支规则

每个开发者在自己电脑上独立开发，但分支必须按任务包命名：

| 类型 | 分支命名 |
| --- | --- |
| 单任务包 | `codex/TP-M02-14-observation` |
| 模块冲突域串行包 | `codex/M03-culture-series` |
| PKG-01 底座 | `codex/PKG-01-auth-guard` |
| 集成修复 | `codex/integration-YYYYMMDD` |

禁止多人共用同一分支。禁止在任务包分支中顺手修改无关模块、客户原始资料、开发基线 SQL 或他人临时文件。

## 4. 第一批立即开工

第一批按“最低冲突、最高解锁价值”安排。

| 包 | 负责人 | 可并发 | 目标 | 备注 |
| --- | --- | --- | --- | --- |
| PKG-01-auth-guard | DEV-A | 不与 M01 写包并发合并 | 登录 I01/I02、ActorContext、AuditHook、守卫从 401 推进到版本校验 | 当前关键路径；44 号文档批次 C |
| M01-read-pack | DEV-D | 可与 PKG-01 并发开发 | M01-013/017/021/022/023/029/035/043/047/054/008 只读接口 | 不依赖 PKG-01；44 号文档批次 A |
| TP-M02-14 在线业务观测 | DEV-B | 可并发 | M02 观测接入小包 | 38 号建议为低共享/低依赖上手包 |
| TP-M02-13 消耗配置 | DEV-B | 可并发 | M02 消耗配置 | 和 M02-14 同人，避免现场资源上下文切换 |
| TP-M09-01 告警规则与监控策略 | DEV-C | 可并发 | M09 告警规则基础包 | 37 标注无共享文件 |
| TP-M09-03 通知策略配置 | DEV-C | 可并发 | M09 通知策略配置 | 37 标注无共享文件 |

第一批不建议同时开 M03、M05、M07 的共享冲突域大包，除非已经指定单一 owner 并接受串行合并。

## 5. 冲突消解后的总分配

### 5.1 DEV-A

DEV-A 负责高级冲突域和关键底座，不再只按旧 38 号表承接业务复杂包。

| 分组 | 任务包 | 调整原因 |
| --- | --- | --- |
| PKG-01 底座 | `PKG-01-auth-guard`，覆盖 43/46 号文档中的 I01/I02、ActorContext、AuditHook、登录重接 | 原 38 号把 M01 登录会话放 DEV-D，但该包涉及 auth/system/common、安全密钥和守卫，调整为高级 owner |
| M03 培养冲突域 | `TP-M03-01`、`TP-M03-02`、`TP-M03-03`、`TP-M03-06`、`TP-M03-07` | 这些包共享 `ResCultureController`、`ResCultureMapper`、`Culture*Service`，必须同 owner 串行 |
| M04 工艺模板 | `TP-M04-01` | 复杂但共享冲突少，可远程实现 |
| M05 高复杂域 | `TP-M05-01`、`TP-M05-02`、`TP-M05-06` | 共享 `DetResultMapper`、`DetResultRevisionMapper`，由高级 owner 统筹 |
| M07 核心运行域 | `TP-M07-01`、`TP-M07-02`、`TP-M07-04` | 共享 `RunEventMapper` 等运行核心文件，必须串行 |

DEV-A 不承接需要现场真实设备、邮件短信、Named Pipe、SDMS 立即联调的包；只做代码、设计裁决和远程评审。

### 5.2 DEV-B

DEV-B 负责 M02 资源和 M03/M07 中现场相关但不触碰 DEV-A 冲突域核心的包。

| 分组 | 任务包 | 并发要求 |
| --- | --- | --- |
| M02 工程与观测 | `TP-M02-01`、`TP-M02-13`、`TP-M02-14` | 可先做 `M02-13/14`，`M02-01` 与 `TP-M02-12` 有共享文件，合并前协调 |
| M02 设备通讯/型号 | `TP-M02-07`、`TP-M02-08`、`TP-M02-10` | 可与 DEV-C 的不同设备包并行，但不能同改同一 Controller/Mapper |
| M02 设备实例 | `TP-M02-04`、`TP-M02-06` | `TP-M02-06` 与 `TP-M02-12` 共享打印相关文件，需串行合并 |
| M03 项目/批次基础 | `TP-M03-04`、`TP-M03-05` | 不得修改 DEV-A 的培养变更/状态动作共享文件；如需改 `LegacyResourceEndpointGuard`，先由 DEV-I 分配窗口 |
| M07 现场运行入口 | `TP-M07-03`、`TP-M07-05` | 与 DEV-A 的 M07 核心包共享 `RunEventMapper`、`RunCommandMapper`，只能在 DEV-A 合并后的窗口接入 |

### 5.3 DEV-C

DEV-C 负责 M06/M09 和 M05 现场/外部系统包，以及部分 M02 包。

| 分组 | 任务包 | 并发要求 |
| --- | --- | --- |
| M09 无冲突基础包 | `TP-M09-01`、`TP-M09-03` | 第一批可直接开工 |
| M09 投递/消音 | `TP-M09-02`、`TP-M09-04` | 两者共享 `AlarmDeliveryMapper`，必须同人串行或先合并 `TP-M09-02` 再做 `TP-M09-04` |
| M06 审批 | `TP-M06-01`、`TP-M06-02`、`TP-M06-03` | `M06-01/02` 共享 `AprDeliveryMapper`，串行；`M06-03` 可先做 |
| M05 现场检测包 | `TP-M05-03`、`TP-M05-04`、`TP-M05-05`、`TP-M05-07` | `M05-03/07` 共享 `DetSample*`，`M05-04` 与 DEV-A 的 `M05-01/02/06` 共享守卫/版本文件，合并需排队 |
| M02 设备实例/检测项目 | `TP-M02-02`、`TP-M02-03`、`TP-M02-05`、`TP-M02-09`、`TP-M02-11` | 与 DEV-B 只按 Controller 聚类并行；碰到同一设备 Mapper 时由 DEV-I 指定 owner |

### 5.4 DEV-D

DEV-D 不再独立承接 M01 登录会话底座。M01 登录/守卫由 DEV-A 负责，DEV-D 负责只读、回归、页面核验和低风险写包。

| 分组 | 任务包 | 调整原因 |
| --- | --- | --- |
| M01 只读接口 | `M01-read-pack`，即 44 号文档推荐 10 个只读接口 | 可立即并发，不受 PKG-01 阻塞 |
| M01 回归核验 | `TP-M01-01`、`TP-M01-03`、`TP-M01-04`、`TP-M01-05`、`TP-M01-06` 的已实现读接口与页面核验 | 不直接改登录/会话核心 |
| M01 写接口辅助 | 在 DEV-A PKG-01 合入后，按 DEV-I 指派处理参数、字典、场地等低风险写接口 | 写接口 HTTP 验收依赖 PKG-01 |
| M02 小包 | `TP-M02-12`、`TP-M02-15` | 与 DEV-B 的 M02 共享文件需先协调；不可自行改共享 Controller |

## 7. 合并顺序

多人可以同时编码，但合并按以下顺序：

1. `PKG-01-auth-guard`：解除登录/会话/守卫关键阻塞；
2. `M01-read-pack`：只读接口，无 PKG-01 依赖；
3. M02 低冲突包：`TP-M02-13`、`TP-M02-14`、`TP-M02-02`、`TP-M02-11`；
4. M09 低冲突包：`TP-M09-01`、`TP-M09-03`；
5. M06 策略配置：`TP-M06-03`；
6. M01 写接口包：按 `参数/字典 -> 场地部门实验组 -> 角色菜单 -> 用户` 的顺序；
7. M03 培养冲突域：DEV-A 串行；
8. M02 设备实例和型号大包：DEV-B/DEV-C 分批；
9. M05 工作台/签批/报告：先 DEV-A 核心，再 DEV-C 现场包；
10. M07 运行核心：先 DEV-A，后 DEV-B；
11. M09 投递包：`TP-M09-02` 后 `TP-M09-04`；
12. 跨模块 Port 联调和浏览器/HTTP 验收。

## 8. 每个任务包交付物

每个开发者提交任务包时必须给出：

| 项 | 要求 |
| --- | --- |
| 任务包号 | 例如 `TP-M02-14` |
| 接口范围 | 列出 interface_id |
| 修改文件 | 列出实际修改文件，不得超出包范围 |
| 依赖说明 | 标明依赖的 Port/provider 是否已实现 |
| 验证层级 | 文档/静态/编译/单元/契约/HTTP/浏览器/设备，按真实结果填写 |
| 未完成项 | BLOCKED_INPUT、外部系统、数据库、浏览器或现场验收未跑必须写明 |

## 9. 合并门禁

合并前至少满足：

1. `git status --short` 中只包含本任务包文件；
2. 无客户原始材料改动；
3. 无开发基线 SQL 改动，除非任务明确要求且已同步来源清单；
4. 不含 `node_modules/`、`dist/`、本地配置、临时脚本输出；
5. 对应模块最小测试通过；
6. 写接口若受 PKG-01 阻塞，只能标记 `BLOCKED_BY_PKG01`，不得宣称 HTTP 写验收通过；
7. 外部设备、邮件、短信、SDMS、Named Pipe 未真实联调时，只能报告未运行或 BLOCKED_INPUT。
