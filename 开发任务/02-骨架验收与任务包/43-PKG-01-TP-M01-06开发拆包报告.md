> 性质：**只读分析 + 拆包**，不改代码、不提交。

## 1. I01–I05 接口逐项清单

> 通用 Header：`from-source`（内部调用凭据，`SecurityConstants.FROM_SOURCE`）对所有 5 个方法必填。
> 通用返回外壳：`R<T>`（`code/msg/data`）。
> Provider 落点：`futurefab-system` 新增一个受限 `@RestController`（建议 `InternalAuthController`，路由基 `/internal/auth`，网关须拒绝外部 `/system/internal/auth/**`）。

### I01 — 凭据校验（登录/解锁）
- **contract id**：I01（`RemoteAuthContractService#verifyCredential`，冻结于 PKG-00 §6.1）
- **URL**：`POST /internal/auth/verify`
- **method**：POST
- **header**：`from-source`（必填）；`X-Auth-Proof` **不适用**
- **request DTO**：`AuthCredentialVerifyRequest` — `username`(必填), `password`(必填,明文内部通道), `mode`(必填, `AuthVerifyMode.LOGIN|UNLOCK`), `sessionKey`(UNLOCK 必填), `requestId`(必填,幂等;LOGIN 时作为 authProof 内 `originLoginRequestId`)
- **response DTO**：`AuthCredentialVerifyResponse` — `userId`, `userName`, `password`(D1 `PasswordStateView`: passwordState/effectiveDate/expiresDate/remainingDays/validDays/remindDays/policyVersion/credentialVersion), `authProof`(LOGIN 成功必填 1–2048 字符；UNLOCK 时 null)
- **errorCode**：`CREDENTIALS_INVALID`(400)、`ACCOUNT_LOCKED`(423)、`ACCOUNT_UNAVAILABLE`(403)、`AUTH_DEPENDENCY_UNAVAILABLE`(503)
- **当前位置 / 是否 501 / 是否缺 Provider**：
  - 契约=`RemoteAuthContractService.verifyCredential` ✅ 已冻结；反射测试 ✅。
  - **Provider 缺失**（system 无实现控制器）。
  - Consumer 侧 `AuthenticationApplicationServiceImpl.login` 未调用 → 登录链路绕过了 I01。

### I02 — 会话激活
- **contract id**：I02（`RemoteAuthContractService#activateSession`）
- **URL**：`POST /internal/auth/activate`
- **method**：POST
- **header**：`from-source`(必填) + **`X-Auth-Proof`(必填，I01 签发)**
- **request DTO**：`AuthSessionActivateRequest` — `userId`(必填,须与 proof 内 userId 一致), `verifiedCredentialVersion`(必填), `verifiedPolicyVersion`(必填), `sessionKey`(必填 1–64), `requestId`(必填), `ipaddr`(必填 ≤128), `browser`/`os`(可空 ≤50), `skipWarning`(必填 boolean)
- **response DTO**：`AuthSessionActivateResponse` — `userId`, `userName`, `sessionVersion`(原值+1), `credentialVersion`, `password`(D1)
- **errorCode**：`SESSION_INVALID`(401)、`INPUT_INVALID`(400)、`AUTH_DEPENDENCY_UNAVAILABLE`(503)、`PROOF` 类（签名/有效期/准入失败 → 401，需按设计补错误码或复用 `UNAUTHENTICATED`/`CHALLENGE_EXPIRED`）
- **当前位置 / 是否 501 / 是否缺 Provider**：
  - 契约已冻结 ✅；**Provider 缺失**。
  - 这是把 `sessionKey`/`sessionVersion` 写入 `sys_user_auth_state` 的**唯一正确入口**；当前登录链路未调用 → 守卫无激活行。

### I03 — 会话校验（每请求）
- **contract id**：I03（`RemoteAuthContractService#validateSession`）
- **URL**：`POST /internal/auth/session/validate`
- **method**：POST
- **header**：`from-source`(必填)；`X-Auth-Proof` 不适用
- **request DTO**：`AuthSessionValidateRequest` — `userId`, `sessionKey`, `credentialVersion`, `sessionVersion`, `requestId`(全必填)
- **response DTO**：`AuthSessionValidateResponse` — `valid`(boolean), `passwordState`(`PasswordState`), `permissionRevision`(String)
- **errorCode**：`SESSION_INVALID`(401)、`SESSION_REPLACED`(401)、`AUTH_DEPENDENCY_UNAVAILABLE`(503)
- **当前位置 / 是否 501 / 是否缺 Provider**：
  - 契约已冻结 ✅；**Provider 缺失**。
  - **Consumer 侧读路径已存在并工作**：`M01ActorContextAdapter.verifySessionStillActive` 已调用 `selectAuthSessionStateByUserId`（XML 有 SQL），只是因无写入而恒失败。I03 Provider 实现（DB `sessionKey`/`session_version` 比对 + Redis 会话存在性 + 输出 `permissionRevision`）待补。

### I04 — 挑战改密完成
- **contract id**：I04（`RemoteAuthContractService#completePassword`）
- **URL**：`POST /internal/auth/password/complete`
- **method**：POST
- **header**：`from-source`(必填) + **`X-Auth-Proof`(必填)**
- **request DTO**：`AuthPasswordCompleteRequest` — `userId`(须与 proof 一致), `verifiedCredentialVersion`(必填), `newPassword`(必填), `confirmPassword`(必填), `requestId`(必填)
- **response DTO**：`AuthPasswordCompleteResponse` — `applied`(boolean), `credentialVersion`(新), `nextAction`(`PasswordNextAction.LOGIN_REQUIRED`)
- **errorCode**：`PASSWORD_POLICY_VIOLATION`(400)、`PASSWORD_REUSED`(400)、`OLD_PASSWORD_INVALID`(400)、`INPUT_INVALID`(400)、`AUTH_DEPENDENCY_UNAVAILABLE`(503)
- **当前位置 / 是否 501 / 是否缺 Provider**：
  - 契约已冻结 ✅；**Provider 缺失**。
  - Consumer 侧 `AuthChallengeApplicationServiceImpl.completePasswordChange`(M01-003) = 501 桩；`M01-006` 密码状态读 mapper = 501 桩。

### I05 — 会话撤销（登出/强制下线/改密吊销）
- **contract id**：I05（`RemoteAuthContractService#revokeSession`）
- **URL**：`POST /internal/auth/session/revoke`
- **method**：POST
- **header**：`from-source`(必填)；`X-Auth-Proof` 不适用
- **request DTO**：`AuthSessionRevokeRequest` — `userId`, `sessionKey`(须与 DB 当前一致), `requestId`(必填), `reason`(必填, `SessionRevokeReason.LOGOUT|LOCK|RESET|DISABLE|REPLACED`)
- **response DTO**：`AuthSessionRevokeResponse` — `revoked`(boolean), `sessionVersion`(判定后代次)
- **errorCode**：`ONLY_CURRENT_ACTOR_CAN_REVOKE`(403)、`INPUT_INVALID`(400)、`AUTH_DEPENDENCY_UNAVAILABLE`(503)
- **当前位置 / 是否 501 / 是否缺 Provider**：
  - 契约已冻结 ✅；**Provider 缺失**。
  - Consumer 侧 `SessionApplicationServiceImpl.logout`(M01-010) = 501 桩；`SysUserAuthStateMapper.revokeUserSessions`(M01-057) = 501 桩；账号级批量撤销（禁用/删除用户时）由 system 本地事务处理，亦未实现。

> 注：I01/I02/I04 的契约方法名与 `AuthContractReflectionTest` 断言的方法名、路由、Body 类型、Header 完全一致，Provider 实现时**必须保持方法签名与注解不变**，否则该反射测试会红。

## 2. 每个接口的最小实现任务

- **I01 verify（最小实现）**
  1. system 新增 `InternalAuthController#verifyCredential`，调 `AuthenticationApplicationService.verifyCredential`。
  2. 应用服务：规范化 username → 查 `sys_user`；bcrypt 校验密码（事务外用快照预计算，事务内确认版本未变）；查 `sys_user_auth_state` 计算锁定窗口/失败计数（`login_failures` JSON，第 7 次锁定）；查 D1 `PasswordStateView`（政策版本/凭据版本/有效期）。
  3. `mode=LOGIN` 成功：**签发 authProof**（HMAC，见 §5 外部输入），返回 `authProof`；`mode=UNLOCK` 成功返回 `authProof=null`。
  4. 失败提交失败计数/锁定（写 `sys_user_auth_state.login_failures` / `locked_until`），返回 `CREDENTIALS_INVALID`/`ACCOUNT_LOCKED`/`ACCOUNT_UNAVAILABLE`（不返回摘要）。
  5. 校验失败关闭：`AUTH_DEPENDENCY_UNAVAILABLE`(503) 当 MySQL 不可用（**不得把验证失败当成功**）。

- **I02 activate（最小实现）**
  1. system `InternalAuthController#activateSession`，先**验 `X-Auth-Proof`**（签名、5 分钟有效期、userId 与请求一致、动作准入）。
  2. 锁行（`sys_user_auth_state` 按 `user_id` 悲观锁/乐观 `version`）验证当前状态：替换 `current_session_key`、原子 `session_version+1`、`login_count+1`、写 `last_login_request_id`、写登录日志（`sys_logininfor`，禁记明文密码/proof/JWT）。
  3. 返回新 `sessionVersion`/`credentialVersion`/D1；调 auth 侧在 I02 成功后再写 Redis 会话、签 JWT（**Redis 写入失败不放行**，见 §3）。
  4. **不可作为"指定 userId 免密登录"入口**（仅接受 I01 验证后由 auth 保管的上下文）。

- **I03 validate（最小实现）**
  1. system `InternalAuthController#validateSession`：校验 DB 当前 `sessionKey` 与代次、`credentialVersion` 与请求一致；校验 Redis 会话存在性；输出 `valid` + `passwordState` + `permissionRevision`。
  2. 不通过返回明确错误（不返回静默 false）。本接口供网关/公共安全每请求调用。

- **I04 password/complete（最小实现，属于该包）**
  1. system `InternalAuthController#completePassword`，验 `X-Auth-Proof` 与动作准入；用户来源以 proof/票据为准，**不采信 Body 外层 userId**。
  2. 更新口令摘要/时间/初始标记/凭据版本（`credentialVersion+1`）、追加口令历史（`sys_user_password_history`）、**撤销既有会话**（调 I05 逻辑）、写 `sys_user_auth_state`。
  3. 返回 `applied=true` + 新 `credentialVersion` + 固定 `LOGIN_REQUIRED`。

- **I05 revoke（最小实现）**
  1. system `InternalAuthController#revokeSession`：按 `reason` 撤销与 `sessionKey` 匹配的当前会话——清 `current_session_key`、递增 `session_version`、删 Redis 会话；旧 key 与当前不符返回 `revoked=false` 且不撤新会话。
  2. 账号级批量撤销（禁用/删除用户场景）在 system 本地事务内处理。

## 3. 第 1 批必须完成（才能解除字典 guarded write 401）

按"先让登录真正写入激活行"的最小闭环：

1. **system 侧 I01**（Provider + 应用服务 + 密码/锁定/失败计数写路径 + authProof 签发）。
2. **system 侧 I02**（Provider + 锁行替换 `current_session_key` / `session_version+1` / 登录计数 / 日志）。
3. **auth 登录链路接 I01/I02**：改造 `AuthenticationApplicationServiceImpl.login`，由 `sysLoginService.login`（legacy 仅做用户存在/状态预检）+ **调用 I01** 拿 `authProof`/`D1` → **调用 I02** 激活会话写 `sys_user_auth_state` →（I02 成功后）`tokenService.createToken` 写 Redis 会话、签 JWT。**Redis 写入失败不放行**（I02 已写 DB 行，但 Redis 会话缺失时不得签发 JWT，避免"有激活行却无可用会话"的半状态）。
4. **`current_session_key` / `session_version` 维护**：I02 负责 `current_session_key` 替换与 `session_version` 自增；`M01ActorContextAdapter` 已能读取并比对（读路径已就绪），登录激活后即可通过守卫会话复核。
5. **`sys_user_auth_state` 初始为空保持**：第 1 批只保证"登录后写入该行"，不要求预置数据；未登录用户本就无激活行，守卫按现状返回 401 是正确语义。

> 第 1 批完成后，guarded write 应从「恒 401 SESSION_INVALID（无激活行）」推进到「通过会话复核后进入管理写版本校验（`MANAGEMENT_REVISION_CONFLICT`/权限判定）」。

## 5. 必需外部输入（BLOCKED_INPUT，实现前须由客户/设计裁决）

1. **`X-Auth-Proof` 签名密钥**：HMAC 使用的服务器密钥存放位置/来源（Nacos 配置？KMS？）。契约只说"服务器密钥 HMAC"，未给具体 key 名/源。
2. **HMAC 算法 / 轮换口径**：契约与详细设计均未冻结具体算法（HMAC-SHA256？SHA512？）与密钥轮换/版本机制。须裁决并在 `FutureFabErrorCode`/配置中登记。
3. **proof 有效期**：已冻结为 **5 分钟**（`RemoteAuthContractService` 注释 + 详细设计 §8.1）；但"到期时刻"是否允许时钟漂移容差、过期后挑战上下文（Redis 5 分钟）是否同源，需确认。
4. **dev 环境是否允许生成临时密钥**：是否允许在 dev/test 用固定/自签名临时密钥（避免本地无法跑通登录链路）；prod 必须走受控密钥。建议 dev 允许、prod 禁止明文。
5. **口令历史表 / 密码政策参数来源**：I04 依赖 `sys_user_password_history` 与全局口令有效期/提醒天数（D1 `validDays`/`remindDays` 取全局政策），该政策参数表/默认值须确认已存在或须初始化。

## 6. 数据库改动判断

- **是否需要改表**：**不需要改 `sys_user_auth_state` 结构**。DDL 已含全部所需列（`current_session_key varchar(64) ascii`、`session_version bigint NOT NULL DEFAULT 0`、`locked_until`、`login_failures`/`change_failures` JSON、`last_login_request_id`、`version` 乐观锁、`update_time`）。第 1 批直接复用。
- **是否只需要补 Mapper/XML**：是的，且分两类：
  - 读路径**已存在**：`selectAuthSessionStateByUserId`（XML 有 SQL）。
  - 写路径**待补**：I02 的 upsert/更新 `current_session_key`/`session_version`/`login_count`/`last_login_request_id`；I01 的失败计数/锁定更新；I05 的清键/递增代次；I04 的改密 + 历史追加。需在 `SysUserAuthStateMapper.xml` 补 insert/update 语句（含 `INSERT ... ON DUPLICATE KEY UPDATE`，因用户首登时该行可能不存在）。
- **`sys_user_auth_state` 初始为空是否保持**：**保持**。设计基线允许为空（无激活会话）；禁止预置/回填行作为小修。登录链路负责"登录后写入"，未登录用户无行是正确语义。

## 7. 必补测试

1. **I01 成功/失败/锁定**
   - 成功：`mode=LOGIN` 返回 `userId/userName/D1/authProof(非空)`；`mode=UNLOCK` 返回 `authProof=null`。
   - 失败：错误口令 → `CREDENTIALS_INVALID`(400)，不返回摘要。
   - 锁定：连续失败达阈值 → `ACCOUNT_LOCKED`(423)，且锁定窗口内再验仍 423。
2. **I02 激活**
   - 合法 proof → `session_version` = 原值+1、`current_session_key` 被替换为请求值、登录计数+1、登录日志落库；非法/过期 proof → 401。
3. **再次登录旧 token → `SESSION_REPLACED`**
   - 同一用户先后两次登录（两次 I02），用第一次的 Redis/JWT 会话访问守卫 → `M01ActorContextAdapter` 判定 `currentSessionKey` 不一致 → `SESSION_REPLACED`(401)。
4. **Redis 失败不发 JWT**
   - `AuthenticationApplicationServiceImpl.login` 在 I02 成功后、Redis 会话写入失败时，**不签发 JWT**，登录整体失败（避免半状态会话）。
5. **guarded write 从 401 推进到版本校验**
   - 端到端：登录（I01→I02）→ 调用字典 guarded write（如 `SysDictDataController` 写）→ 不再 401，而是进入管理写版本校验（`MANAGEMENT_REVISION_CONFLICT` 或权限判定）；旧 token 场景仍 401 `SESSION_REPLACED`。
   - 复用/扩展现有：`M01WiredWriteContractTest`、`M01WiredWriteDictTypeContractTest`、`GuardedWriteFixtures`、`M01ActorContextAdapterTest`（已存在，需从"恒失败"补充"激活后通过"分支）。

## 8. 风险与不可绕过项

1. **不可绕过契约直接写表**：禁止在 `SysLoginService`/`TokenService` 内联写 `sys_user_auth_state` 作为小修——这会让"会话状态"脱离 I02 的锁行/版本/审计闭环，与"登录链路统一经 I01/I02"的设计相悖，且会造成 Redis 与会话行状态不一致。
2. **读写非同一事务**：DB（会话/凭据版本）与 Redis 会话不在一个事务；网关/守卫以 I03 + DB 当前行为准，**不得只凭 Redis TTL 判断撤销**。I02 写 DB 后，Redis 会话写入失败必须回滚放行 JWT（见 §3/§7.4）。
3. **authProof 安全边界**：`X-Auth-Proof` 与 proof 内容禁止写日志、禁止回浏览器、禁止当业务 JWT；I02/I04 验签失败必须 fail-closed（401），不降级。
4. **锁顺序与并发**：统一锁顺序 = 政策版本（需时）→ 用户 → `auth_state` → 历史写入；同用户两次改密串行；失败计数"锁行后计算提交，不读 Redis 再写"避免计数丢失；bcrypt 在事务外预计算、事务内确认版本未变。
5. **脱敏硬约束**：初始化/改密禁止把 `password/newPassword/confirmPassword`、Authorization、`X-Login-Challenge`、`X-Auth-Proof`、JWT、摘要交给通用 `@Log` 自动保存（详细设计 §8.1 + §17）。
6. **Redis/MySQL 不可用语义**：Redis 不可用 = 不登录/不续会话；MySQL 不可用 = 验证不成功（503）。缓存清空后旧会话无法继续，DB 锁定截止仍存在，重启不自动解锁。
7. **外部输入未决即开工会留坑**：§5 的 HMAC 算法/密钥/轮换口径若未裁决，I01/I02 的 proof 签发与验签无法落地或会被事后返工——属 BLOCKED_INPUT，须先裁决。
8. **反射/架构门禁**：`AuthContractReflectionTest` 与 `ManagementGuardedWriteArchTest` 会校验契约方法与控制器接线；Provider 实现须保持方法签名/注解不变，且 guarded write 控制器须带 `@ManagementGuardedWrite` 标记。

## 9. 推荐开发顺序

```
批次 1（解除 guarded write 401 的硬前置，须一次性闭环）
  ① 裁决 §5 外部输入（HMAC 算法/密钥/轮换/dev 临时密钥）—— 设计/客户侧，先于编码
  ② system：I01 Provider + 应用服务（密码校验/锁定/失败计数/失败关闭） + authProof 签发
  ③ system：I02 Provider + 锁行替换会话 + 登录计数/日志 + proof 验签
  ④ system：补 SysUserAuthStateMapper/XML 写语句（upsert current_session_key/session_version 等）
  ⑤ auth：改写 AuthenticationApplicationServiceImpl.login —— 接 I01→I02→(Redis 写成功才)签 JWT
  ⑥ 测试：§7.1/7.2/7.4/7.5（I01 成功失败锁定、I02 激活、Redis 失败不发 JWT、guarded write 推进）
  ⑦ 端到端验收：字典 guarded write 从 401 → 版本校验

批次 2（会话生命周期完善，不阻塞 guarded write）
  ⑧ system：I03 Provider（每请求校验 + permissionRevision）
  ⑨ system：I05 Provider + SysUserAuthStateMapper.revokeUserSessions + 账号级批量撤销
  ⑩ auth：M01-010 logout 接 I05；M01-011 refresh 接 I03
  ⑪ system：I04 Provider；auth：M01-003 改密完成接 I04（改密后自动吊销旧会话）
  ⑫ 失败计数/锁定策略化与压测（§4 末项）
```

**最小可验收门禁**：批次 1 完成 + §7.5 端到端通过后，字典 guarded write 不再恒 401，`M01ActorContextAdapter` 读取到激活行并通过会话复核，守卫进入管理写版本校验层。批次 2 只影响"登出/强制下线/改密吊销/续期"等会话生命周期行为，不决定 guarded write 能否解开。
