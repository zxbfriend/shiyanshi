# 39-业务实现验收门禁与替换501规则

- 时间：2026-09-20
- 依据：`33-第9步任务包生成基线规则.md`（12 条基线）＋ `31-第8步全量骨架验收复核审计报告.md`（分层验证上界）＋ `37/38` 任务包 ＋ AGENTS.md §11/§12
- 用途：第9步业务开发任务包（37/38）执行期间的**强制验收门禁**。任何包合入主干前须逐条满足本文；违反任一即门禁失败，不得放行。
- 编号说明：任务书口径 36/37/38 顺延为 37/38/39（36 已被《骨架包名语义化影响评估》占用）。

## 1. 适用范围与总原则

1. 适用对象：37 总览中 48 个业务开发任务包（515 条 `SKELETON_IN_SOURCE`；M01 6 包为存量回归链，不涉 501 替换）。
2. 不适用范围：17 条 `BLOCKED_REGISTERED`（只走 32 清单设计裁决）、M08（完全排除）、TASK-ROUTE 待裁决项（只进 35 清单）。
3. 全局唯一键 = `interface_id`；契约测试命名、门禁条目、审计记录一律带 `interface_id`（形如 `M05-035`），禁止以裸 `contract_id` 作全局锚（33§4—6）。

## 2. 501 替换规则（逐条、同步、可回退）

1. **逐条替换**：每条骨架接口的实现提交必须同时完成三件事——真实契约行为落地、该条契约测试从「501 信封断言」改写为「真实响应形状/错误语义断言」、`contract/skeleton-m0x.json` 门禁条目经再生链更新。三者缺一即门禁失败。
2. **禁止批量放开**：不得删除/注释 `checkHttp501` 条目、不得整体放宽 `SkeletonContractTest` 套件、不得以“先全量绿后补测试”方式提交。一次提交只允许替换其声明覆盖的 `interface_ids`。
3. **再生链固定**：改 spec（`_tmp_skelgen/spec/<group>.json`）→ `node _tmp_skelgen/gen/testgen.js M0X`（或 regen 脚本）→ `node _tmp_skelgen/gen/gen26.js` → `node _tmp_skelgen/gen/gen32.js` → `node _tmp_skelgen/gen/genAnchor.js` → `node _tmp_skelgen/gen/genTaskPkg.js`（计数与包划分程序派生，禁止手改清单/锚点）。
4. **锚点联动**：骨架门禁条目数（439）、blocked 数（17）、515/532/456 总口径随实现进度程序化变化；任何计数只能由上述脚本产生，命中不一致即停止合入。
5. **回退口径**：真实实现引发门禁红时，回退该条实现或继续保留 501，不得改断言迁就实现。

## 3. 每条接口最低测试集（acceptance_tests 的执行细则）

**查询接口（最低 4 组）**：
1. ApplicationService 单元/契约测试：正常路径＋关键失败路径＋入参校验失败（错误码/消息按模块《错误码全集》）。
2. Controller standalone MockMvc 契约测试：路由、`permission` 标识、响应外壳与冻结 View 形状一致；`NoBody` 接口（M09-004/006/018）按 PKG-00 冻结语义测空体路径，不得生成空 DTO 或登记「DTO 缺失」。
3. Mapper/XML：SQL 静态审查（字段映射、别名、分页方言、`del_flag`/租户条件）为最低层；如改 SQL 须同步实体/DTO/View/契约（AGENTS §8）。
4. 安全断言：未授权 401/403、数据范围（`LabAuthorizationPort` 口径，G3 裁决）、分页/排序参数边界、脱敏字段（密码/电话/邮箱等按 `AuditValueCodec` 既有规则）、响应不得泄漏 Entity/裸 Map 字段。

**管理写接口（在上述基础上追加 3 组）**：
5. 守卫链接线：`ManagementGuardExecutor.execute` 于应用服务内实调；`@ManagementGuardedWrite` 仅标 Controller 方法（ArchTest 位置门禁，25 报告 R2）；配套 `@Log(recordSuccess=false, isSaveRequestData=false, isSaveResponseData=false)` 三属性去重（33§7）。
6. 审计断言：`AuditIntent`＋before/afterSnapshot 装配、`sys_oper_log`/`sys_data_change_log` 落库内容与规范化 ID 断言（24 报告链）；守卫链失败必须整体回滚（含 revision/回执）。
7. 幂等与并发：重复提交、幂等键、`managementRevision`/版本冲突 409 语义、批量操作全量校验后执行（不得只验第一条或静默跳过）。
8. **operationCode 前置登记**：非 M01 写接口的 `operationCode` 须先入 `AuditPolicyRegistry`（当前仅 29 项 M01）并通过评审；登记小批次先行合入，禁止多包并行改注册表（38§5）。

## 4. 验证分层与措辞红线（继承 31/30，AGENTS §11）

| 层级 | 本阶段判据 | 措辞约束 |
|---|---|---|
| 静态/同源互证 | 清单↔源码互证 problems=0；gen 脚本断言全过 | 可宣称「静态检查通过」 |
| 编译 | `mvn -pl futurefab-modules/futurefab-system -am test-compile` BUILD SUCCESS | 可宣称「编译通过」 |
| 单元/契约＋MockMvc | 各包 §3 测试集全绿；全量套件绿（当前基线 463/463＋auth 14/14，随实现再生） | 仅可宣称「单元/契约层通过」 |
| SQL 真实执行 | 在目标 MySQL 实际执行 | 未执行不得称「建库/数据层通过」 |
| 真实 HTTP/网关/Redis | 部署联调 | 骨架与 MockMvc 绿**不得**外推为本层通过 |
| 外部系统（AAD/SDMS/管道/设备/邮件/短信/存储） | 现场联调 | 缺客户参数保持 `BLOCKED_INPUT`，禁止编造默认值；未联调不得标「通过」 |

- 禁止以 37/38 引用的 463/463 骨架绿数作为业务可用或真实环境验证证据（33§12）。
- 门禁测试修正必须配反例 fixture 证明可检出违规；命中 0 的判据只能表述为「预锁机制」，不得称「已验证真实链路」。

## 5. Port provider 逐步解除规则

1. `FullSystemSkeletonGateTest#portAdaptersStayUnwiredExceptM01Actor` 维持「provider 未接线」口径：某模块 Port 实现接线时，仅解除**该 Port** 的门禁条目，逐 Port 提交，禁止一次性全量解除（33§11）。
2. 接线前核对 `PortSignatureSnapshotTest`（71 签名快照）：签名变更=契约变更，须设计裁决＋快照再生，不得私改签名适配实现。
3. 消费方包不得等待提供方而猜形状：以 Port 接口＋快照为唯一契约面；跨模块只经 `service.port.m0x`，直查他模块 Mapper/表/实现类即门禁失败（33§9）。
4. provider 包与 consumer 包的合入顺序见 38§6 分层；并行冲突文件（含注册表、快照、门禁资源）以 38§4/§5 清单为准串行。

## 6. 每包合入统一门禁（串行执行）

1. 本包 `interface_ids` 覆盖的契约测试全绿；对应模块 wrapper（M0X…SkeletonContractTest）全绿。
2. `FullSystemSkeletonGateTest`＋`PortSignatureSnapshotTest`＋反例 fixture 全绿。
3. `mvn -pl futurefab-modules/futurefab-system -am test` 与 `futurefab-auth` 套件全绿（计数以再生后为准）。
4. `git diff --check` 干净；`git status` 未触碰禁改面（§7）。
5. 34 报告提交分组建议沿用：不整仓 `git add -A`；本阶段未获用户指示不执行任何 git 动作。

## 7. 禁改边界（全程有效）

- 开发基线 SQL、`futurefab-ui/`、客户只读材料（接口文档/附录2/需求附件/DOCX）。
- 并行会话资产 `_tmp_p010_*`/`_tmp_tc_*` 等（34§3 登记清单）。
- 未获用户明确指示不执行 git commit/push/reset/checkout/restore/clean；不删除临时文件。
- 不为 M08 引入编译依赖、目录或 Port（`m08IsFullyExcluded` 门禁；冻结取值表枚举豁免见 29§3）。
- blocked 17 条在 32 清单裁决闭环前不落码、不发明字段/枚举/路由/映射表。

## 8. 完成口径

一条接口记为「业务实现验收通过」当且仅当：§2 三件事齐 ＋ §3 对应测试集全绿 ＋ §6 统一门禁绿，且声明层级不高于 §4 实际执行层级。包内全部接口达标后，该任务包方可标记完成；blocked/M08/ROUTE 待裁决项不计入任何包的完成度。
