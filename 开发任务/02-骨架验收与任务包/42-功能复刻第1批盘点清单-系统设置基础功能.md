# 第 1 批功能复刻盘点：系统设置基础功能（新 vs 老）

- 盘点时间：2026-09-24 23:00 ~ 09-25 00:20
- 老系统：https://ymsw-smp.pub.futurefab.cn（`/prod-api/**`，若依前后端分离外壳）
- 新系统：http://127.0.0.1:5581（`/dev-api/**` → 网关 :9090 → auth :9200 / system :9201）
- 盘点方式：浏览器逐页打开 + 页内 fetch 探针 + 后端源码 501 抛出点比对 + `00-全接口契约骨架清单.json` 路由映射
- 页面结构对照：新老前端同为 `@futurefab/ui-app-smp-settings` 同源包，页面布局/查询条件/表格列/按钮天然一致，差异全部在后端接口层

## 一、结论摘要

1. 第一批 13 个页面的**列表类接口全部已通**（真实数据、无 501、无空壳伪造）：
   场地/部门/实验组/菜单/角色/用户/公告/通知/操作日志/登录日志/字典类型/参数/岗位。
2. 老系统全部功能可用；新系统缺口集中在**详情、编辑器装配、写操作（增/改/删/状态）与少量读接口**，共 **58 条 M01 契约接口仍为 501 骨架**。
3. 分页白名单（10/20/50/100）已在新后端生效；老系统无此约束。复刻时前端须按新契约分页取数。
4. 新系统登录链路已验证可用；验证码按用户授权暂未强校验（任意 code/uuid 可登录，仅限本地开发，上线前必须恢复校验）。

## 四、其他发现（登记，不在第一批擅自处理）

1. **响应壳并存两套**：`/system/notice/list`、`/smp/notification/list`、`/system/post/list` 返回旧式顶层 `rows/total`；`user/role/dict/config/labgroup/operlog/logininfor` 返回冻结 `AjaxResult.data=PageResult`。前端同源 SDK 已兼容两种壳，但需 TASK-ROUTE 裁决统一处置。
2. **字典 `smp_notify_type` 数据为空**（新老一致，因共库）：系统通知页的类型列会显示原值。属基础数据初始化缺失，非接口缺陷。
3. **验证码未强校验**：/auth/login 接受任意 code/uuid（用户授权用于本地测试）。上线前须恢复。
4. **老系统兼容路径** `/system/dict/data/type/{t}`（扁平列表）在新系统同样 200 可用，字段为原始字典行；新冻结 tree 接口节点为 `{id,label,value,level,parentCode,children}`，结构不同属契约设计，前端已适配。
5. **登录日志行含 `eventType:"LEGACY"`**：新旧共库导致日志混流，复刻验收时以功能可用为准，不比对数据条数。
