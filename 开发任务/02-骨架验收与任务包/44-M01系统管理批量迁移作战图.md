## 2. PKG-01 底座是什么（"是否受 PKG-01 阻塞"的判断依据）

"PKG-01 底座"= **管理写与登录会话得以通过 HTTP 验收的共用基础设施**，由两层组成，任一层未接线都会导致写/会话接口 fail-closed 或恒 401：

**A. 守卫写基座（`ManagementGuardExecutor`，PRE-01B-R1 已落代码但 fail-closed）**
- 已实现：`service/guard/ManagementGuardExecutor`、`NormalizedPayloadHasher`（HMAC-SHA256 启动 fail-fast）、`ManagementOperation`（29 项白名单枚举）、`ManagementGuardConfig`（固定 Asia/Shanghai 时钟）。
- 未接线（阻塞点）：
  1. `ActorContextPort`（SEC-I01 适配器）= `null` → 执行器显式 `IllegalStateException` 拒绝（PRE-01C 越界实现已撤回，见 09 报告）。**无可信操作者即所有守卫写无法进入 CAS/审计/回执。**
  2. `ManagementAuditHook` 真实实现缺失 → 执行入口 fail-closed（审计为必需能力，见 07 报告 §6）。
  3. `futurefab.management.receipt-hmac-key` 配置缺失即启动失败（BLOCKED_INPUT）。
- 受影响：全部 29 个 guarded write（含已接线的 059/060/063/064 4 条字典写，代码可跑但 HTTP 验收仍 401/拒绝）。

**B. 会话激活 Provider（I01–I05，43 报告）**
- 现状：`RemoteAuthContractService`（Feign）契约已冻结，但 `futurefab-system` 侧 `/internal/auth/**` **Provider 整体缺失**；登录链路（M01-001）仍走 legacy 未写 `sys_user_auth_state` 激活行。
- 后果：守卫读路径 `M01ActorContextAdapter` 永远读不到激活行 → 每个 guarded write 恒 `401 SESSION_INVALID`。
- 最小闭环（批次 C 必做）：I01 verify（密码/锁定/失败计数 + authProof 签发）、I02 activate（写 `current_session_key`/`session_version+1`）、auth 登录重接 I01→I02→签 JWT（Redis 失败不发 JWT）、补 `SysUserAuthStateMapper` 写语句、I03 validate、I05 revoke。
- 外部未决（BLOCKED_INPUT）：`X-Auth-Proof` HMAC 算法/密钥/轮换口径、proof 有效期容差、dev 临时密钥策略、口令历史表/政策参数来源。

> 判定规则：接口若属于 29 个 guarded write（无论是否已接线），或依赖 I01–I05（登录/会话/密码状态/强制下线），或密码链写（005/007/009 待登记 operationCode）→ **受 PKG-01 阻塞**。纯只读且不依赖会话 Provider 的接口（如 venue/dept 的 pageList、options、delete-check、users、editor-options、passwordValidity GET）→ **不受 PKG-01 阻塞**，可独立推进。

### 批次 C：PKG-01 底座（解锁批次 B 的 HTTP 验收 + 登录/会话）
- 范围：
  1. `ActorContextPort` SEC-I01 真实适配器落地（替换 PRE-01C 撤回缺口）→ 守卫执行器不再 fail-closed。

- 文件高度集中：`futurefab-common-security`（适配器）、`futurefab-system`（InternalAuthController/Mapper）、`futurefab-auth`（login 重接）——单 owner，避免并发。
- 外部输入裁决（BLOCKED_INPUT，先于编码）：HMAC 算法/密钥/轮换、proof 有效期容差、dev 临时密钥、口令政策参数表。

### 批次 D：浏览器验收（无代码，纯联调）
- 前置：批次 C 完成 + 批次 B 接口经网关真实调用。
- 验收：登录→守卫写（字典/参数/用户等）从 401 推进到版本校验/成功；旧 token → `SESSION_REPLACED`(401)；Redis 失败不发 JWT；在线用户/强退/日志清理等 legacy 路由功能可用。
- 工具：建议 kimi-webbridge + 已登录 Chrome 真实浏览器（用户既有工作流），而非 Playwright 自动化。

## 7. 风险与待裁决（登记，不在本计划擅自处理）

4. **BLOCKED_INPUT（PKG-01 会话基座）**：HMAC 算法/密钥/轮换、proof 有效期容差、dev 临时密钥、口令政策参数表——未裁决前 I01–I05 落地会留坑（43 §5）。

6. **字典唯一性预检端点未登记**：`checkValueUnique`/`checkLabelUnique` 为旧风格 legacy，需补 canonical 或裁决。
7. **验证码未强校验**：`/auth/login` 接受任意 code/uuid（用户授权本地测试），上线前须恢复（42 §四-3）。
