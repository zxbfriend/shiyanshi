## 2. 能否共用一个统一口令写服务（问题 2）

**结论：能共用「凭据写内核」，不能共用「一个方法」。**

三者**共享**的部分（可提取为统一内核）：

- 同一张 `sys_user` 的 `password` 列写入
- 同一张 `sys_user_password_history` 的历史追加
- `credential_version` 递增（**当前无任何 SQL 支持，见下**）
- bcrypt 加密

三者**不可共用**的部分：

| 维度 | M01-005 | M01-007 | M01-009 |
| --- | --- | --- | --- |
| 权限 | AUTHENTICATED_SELF 本人会话 | `system:user:edit` ＋目标用户可管理 | `system:user:edit` ＋ 仅超管（Q06） |
| CAS 位 | `expectedCredentialVersion` | `expectedCredentialVersion` | `expectedPolicyVersion` |
| 写目标 | 本人 `sys_user` | 目标用户 `sys_user` | `sys_config` 政策两键 |
| 副作用 | 撤销**本人**当前会话，返回 LOGIN_REQUIRED | 撤销**目标用户**会话，置 `is_initial_password=1` | 递增 `policyVersion`，按新值重算全体用户到期日 |
| 口令来源 | 用户输入 | **服务端生成 123456** | 不涉及口令 |
| 审计对象 | 本人 USER | 目标 USER | CONFIG（政策键） |

**关键阻塞（统一内核当前不存在）**：`M01PasswordChainBlockedEvidenceContractTest` §① 已钉——
能写 `password` 列的 update **恰好两条 legacy 语句**（`updateUser`、`resetUserPwd`），
两者**都不递增 `credential_version`、都不置 `is_initial_password`**；
且全仓 Mapper XML 的 update/insert 里 `credential_version` **出现 0 次**（只有读侧投影）。

⇒ 即：**既没有带 CAS 的口令写语句，也没有同事务递增凭据版本的语句。**
统一口令服务不是"复用现有 SQL"，而是**必须新建写侧 SQL**，属真实实现工作量。

## 3. 是否必须纳入管理守卫写（问题 3）

**结论：必须分三态处理，一刀切会写错。**

### 3.1 M01-005 —— 明确**不纳入**（设计已冻结，非本批裁决）

`docs/详细设计/01-系统管理/详细设计.md:1084`（§23 模块事务、审计与状态联动）明文：

> 「登录/改密仅需用户/认证状态锁，**不反向获取管理守卫**；管理员用户编辑不能写 password 字段，
> 因此不会覆盖同时改密结果。」

这句是**针对本问题的直接设计裁决**，且给出了配套的并发生效论证（管理员编辑不碰 password 列）。
因此 M01-005 挂 `@ManagementGuardedWrite` **会与设计冲突**，不是"保守起见先加上"。

§17.1 的"写接口另有 X-Request-Id 及 X-Management-Revision（必填）"是通用写接口口径，
被 §23 的口令专项条款**例外覆盖**（同文档专项优先于通用）。

### 3.2 M01-007 / M01-009 —— 属管理写，但**卡在编码冻结**

两者权限均为 `system:user:edit`、写全局/他人资源、需幂等回执 ⇒ 形态上是管理写。
但**真正卡点不是注解，也不是版本来源，而是 operationCode 无处可挂**：

| 冻结位置 | 实际内容 | 口令族编码 |
| --- | --- | --- |
| `数据库表结构与字段字典.md` §3.22（:578） | `ORG02/03/06/07/08/13/14/16/18，ACL02/03/04/06/07/08/10，USR03/04/05/06/09/10，DIC02/03/06/07，CFG02/03/05` | **无** |
| `01-完整建表.sql` `sys_management_request.operation_code` 列注释 | 原文口径：`本设计接口动作编码ORG/ACL/USR/DIC/CFG及序号`（`01-完整建表.sql:400`） | **无** |
| `ManagementOperation` 枚举 | 同上五族 | **无** |
| `AuditObjectType` 枚举 | 无任何 PWD/PASSWORD 族 | **无** |

新增 `USR11` 或口令族编码属**设计裁决 ＋ 基线批**（要同时改字段字典、建表脚本、枚举、审计注册表四处），
**不是 M01 自主可落的实现项** ⇒ 007/009 守卫化在本批为 `BLOCKED_DESIGN`。

### 3.3 M01-009 与 CFG 族的互斥性（额外约束）

`详细设计.md:1045`（§21）冻结：

> 「密码四个政策键调用 API09 等**专用路径**；」

代码侧已落地：`ConfigApplicationServiceImpl` 的 `PROTECTED_CONFIG_KEYS` 已含
`passwordValidateDays` / `passwordRemindDays` / `passwordPolicyVersion` / `initPasswordModify`，
通用参数口对这些键一律 `READ_ONLY_FIELD` 拒绝。

⇒ **009 不能借 CFG03（参数修改）闭合**，两条路互斥。§⑨④ 已钉此互斥事实。

## 5. 初始口令配置键权威（问题 5）

**结论：三个候选都不是权威源。权威源是设计常量 123456（服务端生成），落码不得新增配置读点。**

| 候选 | 实测 | 判定 |
| --- | --- | --- |
| `sys.user.initPassword` | `02-基础数据初始化.sql` **未播种**（`grep -c` = 0）；全仓唯一读点是 legacy 导入 `SysUserServiceImpl:771`，读后直接 `encryptPassword`，无空值校验；旧库 `sql/ymsw_20260417.sql:555` 有该键值 123456 | **不可用**：基线未播种 + 缺键返回空串 + 旧库脚本按 AGENTS.md §7 不得作种子源 |
| `sys.account.initPasswordModify` | `02` 第 57 行**已播种**，值 `'1'` | **不是口令值**：字段字典 §4 明确"固定1强制；旧0不再允许｜统一转1，不能通用配置关闭"，是**布尔开关** |
| 设计默认 123456 | `详细设计.md` :33/:57/:71 三处明文："由服务端生成初始 123456 的 bcrypt 摘要、`is_initial_password=1`，豁免强度/历史限制；**客户端不选择初始化密码**" | **权威源** |

**关键区分**：`initPasswordModify`（是否强制改密）与初始口令**值**是两个概念，
当前形态下被误当作同一件事的风险很高——若把它当初始口令值，会把"开关"与"值"混进一个键，
且违反"客户端不选择初始化密码"的设计冻结。

**落码要求**：
1. 007 的初始口令**用常量 123456**，不读 `sys_config`；
2. **不得**新增对上述任一键的读点；
3. legacy 导入路径的空串口令缺陷（§⑤ 已钉）**不在本批修复范围**，但 007 **不得复用该路径**——
   否则重置出的口令是空串摘要。

> 附带风险：`sys.user.initPassword` 未播种目前被 `system:user:import` 权限种子缺失（0 行）遮蔽。
> 一旦现场放行该权限，导入用户即落空串口令 ⇒ 建议总控登记为独立缺陷，不与本批混批。

  或总控明确裁决"007 不纳入管理守卫写"（此时 CAS 走 `expectedCredentialVersion` 行内版本）。
