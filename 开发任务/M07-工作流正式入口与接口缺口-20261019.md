## 3. 需安排的接口能力

### G01：W03 固定液瓶事实与连接提交闭环（优先）

- 对应现有 M07-024 GET `/run/workflows/{id}`、M07-025 POST `/run/workflows/{id}/steps/{stepId}`。
- 证据：`createW03Workflow` 将各步 `rows` 初始化为空，启动虽冻结 `channels`，详情只投影 `pumpRefs`。W03 步骤写目前把输入 rows 写入快照，不能据此认为已实现固定液瓶逐行校验、当前量应用和容量约束。
- 已找到的替代能力：M02 液瓶布局和 W07 槽位解析有真实资源信息，但实验室布局不能替代当前 W03 实例冻结的培养—控制器—泵—液瓶对应关系。前端不能按数组下标、显示名或猜测的资源键拼接。
- 建议补齐：CONNECT 步骤返回固定资源键、液瓶/介质、核准容量及单位、可信当前重量及质量/时间、配置版本；人工补填规则明确，提交时重验冻结映射与版本并应用当前量。优先补现有 024/025。
- 当前页面：候选、启动、详情和进入步骤已接线；缺少固定液瓶行时显示提示并阻止完成 CONNECT，不填演示容量或 0。因此 W03 仍不构成完整业务闭环。
- 建议责任：M07 编排/提交，M02 提供资源与可信读数。

### G02：AUTO 模式切换缺非计量命令契约

- 对应 M07-026 POST `/run/workflows/{id}/operations`。
- 证据：`allowedWorkflowOperations` 在 CONNECT 返回 `SET_AUTO`，但 `operateWorkflow` 对该操作明确抛 `CONFIGURATION_INCOMPLETE`：“SET_AUTO非计量执行规格尚缺核准契约，不能伪造正目标量”。
- 建议补齐：核准非计量执行规格、设备适配与回读判定，接通派发和恢复；同步使 `allowedOperations` 与可用能力一致。不能借预填充正目标重量伪造 AUTO 命令。
- 当前页面：不提供可执行 AUTO 按钮；调用层同样阻止发送，显示暂未开放。
- 建议责任：M07 与 M02；设备协议、HTTP、实机回读分别验收。

### G03：缺少工作流到真实执行 ID 的关联返回

- 已有能力：GET `/run/executions/{id}`、`/{id}/commands`、`/{id}/samples` 已有真实查询服务及范围校验。`RunWorkflowExecutionMapper` 也写入同一 `run_execution` 表；不必重做执行详情、命令和样本查询。
- 缺口证据：`WorkflowInstanceView` 只有步骤、`allowedOperations`、`pumpRefs`，没有执行关联；`operateWorkflow` 返回的 `objectId` 和 `relatedIds` 都是命令 ID，不能直接当 executionId。刷新后只有 workflowId/stepInstanceId，现有页面接口没有提供所属执行 ID。
- 建议补齐：M07-024 按步骤和固定通道返回 executionId/commandId 关联，或提供有权执行列表。之后前端直接复用已有执行查询显示实际量、状态和停止证据。
- 当前页面：只呈现服务端实例和命令受理信息，不以本地 `running/primed` 模拟设备状态。
- 建议责任：M07 查询投影与范围校验。

### G04：中试 W01 连接／W02 更换料液缺可用运行分支

- 检索了运行 Controller、M07 应用服务和前端 SDK。`feeding/model.ts` 的 `PILOT_CONNECT/REPLACE` 是前端类别，不代表接口已实现。
- 证据：`resolveLabWorkflowContext` 明确仅允许小试上游；候选接受 W03/W05/W07；`startWorkflows` 分派 W03/W05/W06/W07/W08。未找到 W01/W02 相匹配的可用运行分支。M04 定义管理不是 M07 运行口。
- 建议补齐：中试候选及模式事实、连接/换料启动、逐泵冻结袋体与容量、皮重/净重确认、设备命令和安全恢复。先明确中试字段和设备契约，尽量复用现有框架。
- 当前页面：中试保留既有开始培养；补料连接/换料显示未开放，不把中试 ID 送进小试 W03。
- 建议责任：M07 主责，M02/M03/M04 提供事实；属于后续中试范围，不阻塞本次小试入口迁移。

### G05：W06 换瓶步骤缺少 PENDING → IN_PROGRESS 转换（本轮发现，优先）

- 现有 M07-025 POST `/run/workflows/{id}/steps/{stepId}`，不是缺少新 URL，而是已有服务缺少动作分支。
- `RunWorkflowStepMapper.xml#insertWorkflowStep` 将所有新步骤写为 PENDING；`updateWorkflowStepByVersion` 仅更新当前步骤，没有自动开启下一步骤。
- `RunWorkflowApplicationApplicationServiceImpl#updateW06Step` 只在非 step_2 分支接受 NEXT。step_2 分支只接受 COMPLETE 且当前状态为 IN_PROGRESS，导致正常新建的换瓶步骤无法进入。未找到其他自动开启该步骤的实现。
- 影响：已可选择真实 Water/Alcohol 液瓶并启动、读取实例；正常新建流程无法完成换瓶。页面显示明确提示并阻止继续，不本地伪造 IN_PROGRESS，也不跳过现场确认。
- 建议补齐：M07 在原接口实现带前序步骤、范围、版本、幂等校验的进入动作，保留冻结槽位快照；验证从新建到换瓶完成的真实 HTTP 全链。前端在该能力交付后移除临时阻断。
- 建议责任：M07 服务端；无需重新开发 M02 布局口。
