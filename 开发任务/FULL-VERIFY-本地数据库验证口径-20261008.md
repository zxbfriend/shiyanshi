## 2. 数据库口径裁决

### 2.1 Nacos 公网库 = 共享开发测试库

- `Nacos futurefab-dev` 的 `application-dev.yml` 实际指向 **`MySQL 101.200.152.223:6033/ymsw_v2`（账号 ymsc）+ `Redis 192.168.1.98`**。
- 经总控裁决：该库为**多人共享开发测试库**，**非生产库，不按生产安全红线处理**；配置漂移相关问题不升为 P0 安全项。
- 但「非生产」不等于「可写」：多人共享意味着自动化写入会污染他人工作区、破坏他人数据与排障现场。

### 2.2 不作为自动化写入验证目标

| 用途 | 是否允许指向 `101.200.152.223:6033/ymsw_v2` |
|---|---|
| 只读盘点 / 事实取证（表结构、配置值、条数统计） | 允许（需在报告中注明为只读） |
| SQL 安装链执行（建表 / 初始化 / 核验） | **禁止** |
| 事务写测试、幂等 / CAS / 回滚测试 | **禁止** |
| HTTP 写口联调（含数据写入） | **禁止** |
| 服务启动时未覆盖数据源、随 Nacos 默认落到该库 | **禁止**（必须显式覆盖指向本地库） |

未按上表执行时的状态标注：`BLOCKED_DEPLOY` / `BLOCKED_INPUT`，不得宣称 SQL、HTTP 或事务层已验证。

### 2.3 本地 Docker 临时库 = SQL_VERIFIED 推荐目标

- **推荐目标**：本机 Docker MySQL 实例中**新建的一次性临时库**（命名建议 `ff_verify_<yyyyMMdd>`），验证结束即删除。
- **备选**：明确的、已确认归属单人的本地开发库（当前本机 Docker 实例的 `ymsw2`，root/root，既有 297 表）。使用前必须确认该库**缺基线种子**（已知缺 `sys_management_revision`、`apr_scene` 等），需要基线的验证不得直接在其上执行安装链。
- **连接方式**：允许命令行参数覆盖数据源（`--spring.datasource.dynamic.datasource.master.url/username/password`、`--redis.host=127.0.0.1`）指向本地库；**不为此修改仓库任何配置文件**。

## 3. 后续验证规则（强制）

1. **SQL 安装链只跑本地一次性库**
   `01-完整建表.sql` → `02-基础数据初始化.sql` → `03-初始化结果核验.sql` 只能在本地新建临时库执行；顺序不得颠倒、不得只跑其中一段宣称「安装链通过」；不得执行 `history/sql/` 下任何文件。

2. **事务写测试只跑本地库**
   事务边界、回滚、幂等键、`expectedVersion` CAS、唯一约束冲突等**会写库的测试**，一律指向本地库；禁止在共享开发库上制造或清理测试数据。

3. **HTTP 写口联调也必须写向本地库或明确测试库**
   启动服务时必须显式覆盖数据源指向本地库；若某个未覆盖的依赖（如 Redis、Nacos 下发的次级数据源）会把写入引向共享库，则该项判 `BLOCKED_DEPLOY`。守卫写口验证（`X-Request-Id` / `X-Management-Revision`）同样遵守本条。

4. **库属性未确认一律 BLOCKED_INPUT**
   无法确认目标库是「本地一次性库」「本人独占开发库」还是「共享 / 生产 / 客户环境」时，**禁止执行任何写操作**，标 `BLOCKED_INPUT`，并在报告中写明待确认项（归属人、是否共享、是否可清理）。

5. **只读事实取证可以连共享库**，但报告必须显式标注「只读，未写入」。

6. **验证后清理**：临时库用后即删；备选本地库上产生的测试数据必须清理并在报告中给出清理结果。清理范围不得超出本次自建 / 本次自插的数据。

7. **口径漂移的处置纪律保持不变**：Nacos 与仓库 `nacos-config/` 不一致时，只读核查 + 出裁决草案，改仓库配置需另行授权，回写 Nacos 需总控单独授权；**不得为了让验证跑通而擅自回写 Nacos 或改配置**。

8. **分层报告不可越级**：`SQL_VERIFIED` 只代表 SQL 在目标数据库执行通过，不等于 HTTP、浏览器、外部系统或现场验收通过。
