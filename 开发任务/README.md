# 开发任务目录说明

本目录存放契约骨架、任务包、接线与阻塞记录、验收准备、实施计划与前端交付等 2026-09 至 2026-11 的工作/过程材料；现行设计以 `docs/详细设计/` 为准，本目录不是日常阅读入口。路径中的 `docs/` 一律相对 docs 目录解析。

## 1. 根目录的 json + md 文件对不能移动

根目录现有 11 个 `.json` 与 11 个 `.md`，其中 10 个编号文件为 json+md 同名对（00、05、10、26、31、32、36、37、38 号；26、31 号各有两个 json）；`26-SC-20261017-开始培养接口增补.json` 无同名 md，`S04执行方案.md` 无同名 json。

这些文件对不能移动，因为工具与主仓库测试按固定路径读取：

- `tools/gen-skeleton-anchors.mjs` 把 `docs/开发任务/00-全接口契约骨架清单.json` 与 `docs/开发任务/26-全系统接口契约骨架清单.json` 作为冻结条目与收口报告的权威源；
- `tools/verify-start-culture-registration.py` 以 `docs/开发任务` 为根，读取 `26-SC-20261017-开始培养接口增补.json` 与 26 号清单并校验摘要哈希；
- 主仓库测试（含 `SkeletonAnchorRecomputeContractTest`）按 `docs/开发任务/<名>.json` 定位这些清单。

移动任一编号文件对都会使上述脚本与测试失配；2026-11-10 大迁移已明确排除它们，新增同编号文件同样留在根目录。

## 3. 新文件放哪个子目录

判断顺序（编号只是辅助，先按内容归类）：

1. 编号 `.json` 及其同名 `.md` → 留在根目录，不进子目录（见第 1 节）。
2. 契约骨架清单、冻结/复核/阶段门裁决 → `01-契约骨架/`；骨架验收、任务包拆分、排期与分配 → `02-骨架验收与任务包/`。
3. 接线窗口、阻塞与解锁记录 → `03-接线与阻塞记录/`，再按文件名形状分：`INT-` → `INT接线记录/`；两位数字编号 → `编号记录-49至89/`；`YYYY-MM-DD-` 日期开头 → `日期型报告/`；其余模块台账 → `模块台账与其他/`。
4. 验收证据与准备 → `04-运行验收准备/`；跨模块审计与接口盘点 → `06-审计与盘点/`。
5. 日期型 slug 的实施计划 → `07-实施计划/`；单专题或批次交付 → `08-专题交付/`；前端交付与测试方案 → `frontend/<模块>/`。
6. 环境准备脚本与数据 → `测试数据/`；过程执行记录 → `history/review/`；校验工具 → `tools/`。

编号不是唯一依据：`04-运行验收准备/` 中也有 50、68 号文件，`07-实施计划/` 用日期命名，`08-专题交付/` 多为无编号专题名；按内容归类优先于编号。
