## 4. 契约测试覆盖（M05ReportJobReadMapperContractTest，13 例）

真实解析走 `XMLMapperBuilder` + `Configuration` + `getMappedStatement().getBoundSql()`，不是纯字符串猜测：

1. 接口与 XML 落点同时存在。
2. XML 只含 `<select>`；出现 `<insert>/<update>/<delete>`、`FOR UPDATE`、`LOCK IN SHARE MODE` 即红；`<select>` 恰为 2 条。
3. 接口方法与 XML 语句 id 1:1 对等，namespace 正确。
4. 投影的每个下划线列名都在 DDL 块中存在（集合差为空）。
5. 最小事实覆盖：作业主键、状态、版本、清单、文件摘要、证据、状态时间、发起者、请求号、请求摘要、文件路径、result/sample、创建时间。
6. 三个 BINARY(32) 摘要经 `LOWER(HEX(...))` 归一。
7. 只读表集合恰为 `{det_print_export_log}`，不跨模块读 M02/M07/M09 表。
8. BoundSql：`jobId` 以绑定参数下推（出现 `?`、不出现字面量主键、参数映射恰 1 个）。
9. 无 `${...}` 直接替换（注入面）。
10. 根行语句必须含 `job_root_id = log_id`。
11. 零生产消费者：`src/main` 除接口/XML 自身外无人引用；`DetReportJobApplicationServiceImpl` 仍对 031/032/033/034 抛 501 且无 `@Autowired`。
12. 台账仍记四条未 wired。
13. 033/034 归因翻正钉：旧"窄口不存在"措辞不得复现；034 仍 BLOCKED_EXTERNAL（`ReportJobRules` 生产零引用、DDL `file_sha256 BINARY(32)`、设计"READY 必须文件存在且 hash 一致"）；五个 perm=null 口径不回退。

变异校验（证明测试有牙）：把 `#{jobId}` 改成 `${jobId}` 并加一条 `<update>`，实测 **EXIT=1**，失败恰为预测的 2 例（`${}` 注入钉、只读钉），其余全绿；从备份还原后 13/13 复绿，无残留。
