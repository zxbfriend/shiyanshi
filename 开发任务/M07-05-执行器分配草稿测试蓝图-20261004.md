## 一、为什么不把草稿类放进 `src/test/java`

1. **它是蓝图不是断言集**：草稿类当前只有两条"骨架阶段合法"的 501 断言，其余 IDEM/STM/LEASE/UNK/OLDW/EXT 全部是注释形态的落地要点。进入正式测试树后，Surefire 只会执行到那两条 501 断言，容易被误读为"M07-05 已有契约测试"。
2. **它依赖尚未接线的骨架实现**：`RunExecutorAssignmentApplicationApplicationServiceImpl` 两方法仍抛 `SkeletonNotImplementedException`，未注入 `ManagementGuardExecutor`、未消费 `expectedVersion`。真实用例一旦启用就会引用不存在的仓储与表行为。
3. **骨架门禁另有归属**：`FullSystemSkeletonGateTest` 与 `src/test/resources/contract/skeleton-m07.json` 已经承担"骨架期必须显式 501"的门禁职责；`wired` 位翻转属总控/需求方裁决事项，不由辅助代理或本批改动。
4. **避免与 work9 的在途工作冲突**：本草稿不占用正式测试类命名空间，work9 实现时可自行决定最终类名、包位置与用例切分。

结论：本批只提交文档形态的蓝图。草稿 Java 副本不删除、不提交，留在 work8 本机作为原始出处。

## 三、蓝图用例组与落地要点

标注格式：**用例｜要点**。"断言列"为 `docs/详细设计/07-补液运行与任务执行/10-审阅收尾完整目标表结构.sql` 中已定义列，实现时应真正消费这些列而不是用替代字段。

### IDEM｜幂等与重放

- **IDEM-01｜同一 `requestId` 重放移交**：两次 `transferExecutorAssignment(同 requestId)` 后比较 `TransferResult.assignmentEpoch` 与 `TransferResult.objectVersion`，必须与首次一致，`assignment_epoch` **不得二次增长**；幂等证据 `run_event.source_event_key = 内部命名空间 + userId/requestId 摘要`，禁止客户端伪造领域事件。同 key 异载荷应冲突拒绝（CLOSE-M07 同 key 异 hash 冲突）。
- **IDEM-02｜应答丢失 / 发布前宕机 / 归档后重传**（CLOSE-M07-09）：`run_event.eventId` 全局唯一供消费者去重；`run_event` 兼审计与发件箱，已落账业务不因发布失败回滚；重传同一 eventId 时 `run_ledger` 不重记。
- 断言列：`run_executor_assignment.assignment_epoch`、`object_version`、`run_event.source_event_key`、`publish_state`。

### STM｜状态机

- **STM-01｜`run_executor_assignment` 四态跃迁**：`DISABLED/ENABLED/ISOLATED/TRANSFERRING`（SQL 默认 `DISABLED`）；路径 `ENABLED→ISOLATED→TRANSFERRING→ENABLED`；任一证据为 `UNKNOWN` 时**保持 ISOLATED**，不得跳到 ENABLED；`assignment_epoch` 仅在 `TRANSFERRING→ENABLED` 成功时 +1。
- **STM-02｜`run_command` 生命周期**：`PREPARED→INVOKING→ACCEPTED/EXECUTED/FAILED/UNKNOWN`；`INVOKING` 必须在网络调用**之前**于事务内提交；崩溃恢复一律先查原 `commandId`，`UNKNOWN` 只查不重发。
- **STM-03｜`run_resource_guard` 物理态与 owner 一致性**：受 `ck_m07_guard_owner` 约束——`(FREE ∧ owner_id IS NULL ∧ owner_kind IS NULL) ∨ (非 FREE ∧ owner_id 非 NULL ∧ owner_kind 非 NULL)`；`physical_state = FREE/HELD/STOPPING/UNKNOWN`；租约过期只打协调者失联标记，**不得直接把 `physical_state` 置为 FREE**。

### LEASE｜租约与接管

- **LEASE-01｜隔离 + 停泵对账后接管，重放同 requestId**（CLOSE-M07-03）：`assignment_epoch` 只 +1 一次（E1→E2）、旧入口失效、原未决命令不重发、结果 `state=ENABLED`。
- **LEASE-02｜租约到期但设备可能仍在动**（CLOSE-M07-02）：**不自动接管**；旧 `worker_id` 恢复后不得与新进程并发发送（旧 fence 拒绝）；首期只允许单协调者持有发送入口。
- **LEASE-03｜伪造第二执行器直连**（CLOSE-M07-01）：合法副本共用同一意图 + 1 个固定执行器；第二控制通道（网络 ACL / 唯一串口 / 网关权限）实际拒绝伪造执行器。
- 断言列：`run_executor_assignment.assignment_epoch`、`run_resource_guard.worker_id`、`lease_until`、`physical_state`、`object_version`。

### UNK｜UNKNOWN 原键查单

- **UNK-01｜`INVOKING` 后崩溃 / 超时**（CASE070）：按原 `commandId` 查单，不新发 `START`；有回执则更新，无回执保持 `INVOKING/UNKNOWN` 并进入重试或隔离。
- **UNK-02｜租约过期但泵状态未知**（CASE071）：保留 owner 记录，旧 fence 拒绝控制命令，新进程只做核对不接管。
- **UNK-03｜M06 决定重复 / 响应丢失**（CASE053）：按原决定生效结果（原键）查询，任务、账目、事件不重复产生。
- 断言列：`run_command.state`、`run_resource_guard.fence`、`worker_id`。

### OLDW｜旧 worker 回写失败

- **OLDW-01｜失去 fence 的旧 worker 回写 `run_execution`**：`worker_id`(NOT NULL) + `fence`（执行域仲裁 epoch）+ `object_version`(CAS) 不匹配即拒绝，不得污染新 worker 的段或结算；返回冲突而非静默覆盖。
- **OLDW-02｜旧协调者回写 `run_resource_guard`**：`worker_id`(当前协调者，可 NULL) + `lease_until` + `object_version`，owner/epoch/version 不匹配应被数据库 CHECK 或 CAS 拒绝，guard 不回退到旧 worker。

### EXT｜事务外设备调用（CTRL-EXT）

- **EXT-01｜pause / resume / workflow operations / restart**（`Controller请求调用时序设计.md` 定位 008/009/026/028）：① 意图在本地事务内先提交（如 `phase=PAUSE_REQUESTED`）→ ② 事务提交后再发起设备调用 → ③ 无回执按原键查单恢复。设备调用**不得位于本地写事务内**；本地状态变更与设备副作用解耦。
- 现状：上述 4 个端点 Impl 仍抛 `SkeletonNotImplementedException("M07-008/009/026/028")`，EXT 模式未实现。

### CAS｜通用乐观锁

所有写路径携带 `expectedVersion` / `object_version`；失配返回冲突，不静默覆盖。注意：设计里**没有独立的 `lease_token` 字符串列**，fencing 由 `assignment_epoch`（归属代次）、`lease_until`（guard 租约截止）、`fence`（执行域仲裁）三列承载，断言应围绕这三列写。

以下前置全部满足后，work9 才应把本蓝图落成 `src/test/java` 正式契约测试；任一未满足时不得以"测试先行"名义把 501 期望写进正式树：
