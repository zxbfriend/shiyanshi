# 药明云当前开发文档入口

> **统一入口（2026-11-08 整理）**：本页是开发人员、Codex 和多 Agent 的统一文档入口。本轮只调整导航与定位，不改变业务裁决、不移动受保护材料。下文“变更与决策记录”保留原文，按时间倒序登记范围确认与实施结果，用于追溯；当前实现依据以模块现行契约为准。

## 0. 统一阅读顺序

新人或 AI 的最小阅读顺序：

1. 仓库根 [AGENTS.md](../AGENTS.md)：硬红线、任务边界、验证与交付纪律。
2. 本页：确定模块、任务类型和权威文档。
3. [需求文档](01-需求文档.md)：本期范围、明确不做、业务主线与已确认规则。
4. [合并详细设计](02-详细设计.md)：分层、事务、模块职责、验证分层。
5. 目标模块现行契约：模块 `详细设计.md` → `接口目录与契约定位.md` → `Controller请求调用时序设计.md` → `错误码全集.md` → 字段字典/状态机/专题契约。
6. 涉及数据库时加读 [开发基线](开发基线/README.md)：只按其中三份脚本安装，历史 SQL 不进入执行链。

只改前端页面时，可先读第 1、2、3、4 项和目标模块的页面/接口契约；跨模块调用必须加读[Controller与模块接口调用总设计](详细设计/00-总纲与约定/00-Controller与模块接口调用总设计.md)与[开发实现结构与事务编排约定](详细设计/00-总纲与约定/00-开发实现结构与事务编排约定.md)。

## 3. 权威状态约定

| 状态 | 含义 | 使用方式 |
| --- | --- | --- |
| CURRENT | 当前权威入口或现行模块契约 | 可作为实现与验收依据 |
| REFERENCE | 阅读导航、设计索引、来源说明 | 辅助定位，不单独作为业务裁决 |
| HISTORICAL | 历史审阅、阶段报告、迁移记录、旧版材料 | 只解释演进；与现行契约冲突时以 CURRENT 为准 |
| PROTECTED | 客户原始材料或阅读副本 | 原位置、原文件名、原内容，禁止改写/移动/删除 |
| UNKNOWN | 证据不足、权威性未定 | 不擅自当作历史或废弃，改动前先核实 |

冲突处理顺序：用户最新明确确认与澄清记录 → 本页指定权威入口 → 模块现行契约 → 模块详细设计 → 总体设计 → 早期基线/阶段记录/历史材料。
