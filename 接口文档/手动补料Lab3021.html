三、Core Service 接口明细（Lab=1）

1. pumping_getinfo — 查询反应器补料状态

GET {CoreServiceAddress}manual/operation/bioreactor?action=pumping_getinfo&deviceno={deviceNo}

封装方法：GetPumpingInfoFromCoreServiceByDeviceNo(string deviceNo, int labId)

被谁调用：StartPumping、AbortPumping（发送指令前先查设备状态）

入参（Query String）

参数来源说明
action固定pumping_getinfo
deviceno_pumpingService.GetLabDeviceNoByID(labDeviceID)反应器设备编号

出参

BaseCoreServiceResponse<PumingResponseData>

业务逻辑

  • StartPumping：若 Data.WorkStage == "Pumping"，认为该设备正在补料，直接返回错误 SE500204，不再发 start_pumping。
  • AbortPumping：若 Data.WorkStage == "Done"，认为补料已结束，本地更新 ManualOPRec 为取消状态，返回 SE5004816，不再发 abort_pumping。

2. start_pumping — 开始手动补料

GET {CoreServiceAddress}manual/operation/bioreactor?action=start_pumping&deviceno=...&sourceid=...&type=...&speed=...&locationcode=...&itemcode=...[&volume=...]

被谁调用：POST api/pumping/start-pumping（request.LabId == 1 时走 Client1）

Controller 入参 — PumpingRequestParam

字段类型说明
LabIdint传 1 时路由到 CoreServiceHttpClient1
LabDeviceIDint反应器设备 ID → 转 deviceno
BatchIDint批次 ID
PumpingTypeint?11=FM1 / 13=FM2 / 15=Glucose / 17=FM3
Volumedecimal?补料体积（>0 时传给 Core）
Speeddecimal?泵速（转 int 传给 Core）
LocationCodestring库位编码
ItemCodestring物料编码
PreFillVolumedecimal?预填充体积（仅本地校验，不传 Core）

传给 Core Service 的 Query 参数

参数来源说明
action固定start_pumping
devicenoLabDeviceID → deviceNo反应器编号
sourceid新建 ManualOPRec 的 ManualOPRecID手动操作记录主键，供回调关联
typePumpingType补料类型 11/13/15/17
volumeVolume（可选）仅当 Volume>0 时追加
speedSpeed泵速（int）
locationcodeLocationCode库位
itemcodeItemCode物料

出参

BaseCoreServiceResponse（无 Data 泛型）

Controller 对外返回：BaseResponse<PumingResponseData>，成功时 Data.ManualOPRecID 为新建记录 ID。

业务逻辑

权限校验 → 库存/反应器容量校验 → pumping_getinfo（防重复补料）→ 写 ManualOPRec(Status=Start) → start_pumping
  • ResultCode == 0（失败）：更新 ManualOPRec 的 ErrorCode/EndTime，写 Event 日志（Error），返回 SE500050 或 SE500051（缺液）。
  • ResultCode == 1（成功）：记录操作日志；补料结果由 Core Service 回调 POST api/pumping/get-pumping-result 异步回写。

3. abort_pumping — 中止手动补料

GET {CoreServiceAddress}manual/operation/bioreactor?action=abort_pumping&deviceno=...&sourceid=...&type=...&locationcode=...&itemcode=...

被谁调用：GET api/pumping/abort-pumping（labId == 1 时走 Client1）

Controller 入参（Query / Route）

参数类型说明
labIdint传 1 时路由到 CoreServiceHttpClient1
labDeviceIDint反应器设备 ID
batchIDint批次 ID（仅日志）
pumpingTypeint补料类型 11/13/15/17
locationCodestring库位编码
itemCodestring物料编码
manualOPRecIdint?手动记录 ID；未传时由服务按设备+类型查询

传给 Core Service 的 Query 参数

参数来源说明
action固定abort_pumping
devicenolabDeviceID → deviceNo反应器编号
sourceidmanualOPRecId手动操作记录 ID
typepumpingType补料类型
locationcodelocationCode库位
itemcodeitemCode物料

出参

BaseCoreServiceResponse

Controller 对外返回：BaseResponse<List<PumingResponseData>>

业务逻辑

权限校验 → pumping_getinfo（若已 Done 则本地取消记录）→ abort_pumping → 更新 ManualOPRec Status=Canceled
  • 无论 Core 返回成功或失败（ResultCode==0），多数分支都会把 ManualOPRec 更新为取消(99)。
  • 成功时记录「Abort Pumping」操作日志。

五、相关但非 CoreServiceHttpClient 出向调用

以下接口与补料流程相关，但方向是 Core Service → WebAPI 回调，或 不走 CoreServiceHttpClient：

接口方向说明
POST api/pumping/get-pumping-result Core → WebAPI 手动补料完成回调；入参 SamplingFeedingResult（sourceid、errorCode、weight、LabId）；更新 ManualOPRec、写 Event、保存 BatchOP
POST api/pumping/get-pumped-weight Core → WebAPI 补料过程重量回调；保存补料明细重量
POST api/pumping/auto-pumping-result Core → WebAPI 自动补料结果；SaveBatchOPExec
POST start-pumpingV2 / GET abort-pumpingV2 Lab2 流程 通过 PumpingService.StartFeeding / AbortPump，走 OPC/IOT，不调用 CoreServiceHttpClient
GET get-dose / POST set-dose 外部 OPC 调用 SystemConstant.PumpingDose 的 OPC 服务，非 Core Service

六、Lab=1 完整调用时序

开始补料
前端 POST start-pumping (LabId=1) → pumping_getinfo → 写 DB ManualOPRec → start_pumping → Core 执行补料 → 回调 get-pumping-result / get-pumped-weight
中止补料
前端 GET abort-pumping (labId=1) → pumping_getinfo → abort_pumping → 更新 ManualOPRec 为 Canceled
