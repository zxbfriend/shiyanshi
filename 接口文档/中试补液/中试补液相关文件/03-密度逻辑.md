# 密度逻辑

## 1. 入口与数据来源

页面位置：`dashboard.html` 的 Density 区域。

前端控制器：`dashboardController.js`。

设备加载：

```js
$scope.DensityEqus = await getEquipmentListByType(3);
```

前端操作入口：

```js
captureCurrentData(item, 'Density')
captureCancel(item, 'Density')
viewDetailDensity(item)
```

接口定义：

| 前端资源 | URL |
| --- | --- |
| `captureDensity` | `api/dashboard/DensityCapture` |
| `cancelCaptureDensity` | `api/dashboard/DensityCaptureCancel` |
| `viewCaptureDensity` | `api/dashboard/DensityView` |

后端入口：

```csharp
DashboardService.DensityCapture(DensityCaptureModel densityCaptureModel)
DashboardService.DensityCaptureCancel(int equipmentId, int preBatchTestingId, int userId, string cancelResult)
DashboardService.DensityView(int preBatchTestingId)
```

## 2. 页面校验与展示

采集前必须选择 `DensityDeviceID`。

页面展示字段：

- `DensityDeviceID`
- `Density`
- `DensityIsValid`
- `Density_Testing_By`
- `Density_Testing_time`

如果后端返回 `IsValid = false`，前端不会刷新整页，而是临时显示：

```js
item.Density = data.Data.ValueStr;
item.DensityIsValid = data.Data.IsValid;
item.DensityWrong = !data.Data.IsValid;
```

如果 `DensityIsValid == false && Density != null`，输入框标红。

## 3. 普通密度计计算逻辑

普通密度计指设备 Model 不是 `MT-D4`。

后端取数：

```text
从 CDP_Testing_Density 读取当前设备最近有效期内的未绑定记录
条件：
- Status != false
- EquID = 当前设备
- Value != null
- Creation_time >= now - DensityExpireMin
按 TestingTime 倒序取 3 条
```

失败条件：

- 最近 3 条中已有记录被绑定到样本，即 `PreBatchTestingID != null`。
- 有效记录不足 3 条。

密度值计算：

```text
Density = round((d1 + d2 + d3) / 3, 3)
```

## 4. 密度有效性判断

规则来源：

```text
CDP_RuleSetting.RuleType = 1
```

对应枚举：

```text
RuleType.Difference = 1
```

后端对三条密度数据做两两差值：

```text
abs(d1 - d2)
abs(d1 - d3)
abs(d2 - d3)
```

每个差值都必须满足规则：

```text
CheckDensityValue(Symbol, Value, diff) == true
```

全部满足时：

```text
Density_IsValid = true
```

任一不满足时：

```text
Density_IsValid = false
```

`CheckDensityValue` 支持 `<`、`<=`、`>`、`>=`、`=`、`!=`、`≤`、`≥`。

## 5. MT-D4 密度计特殊逻辑

如果设备 Model 是 `MT-D4`：

1. 不读取 `CDP_Testing_Density` 的最近 3 条。
2. 从 `CDP_Testing_D4Task` 读取当前设备最新任务。
3. 取 `Dens` 作为密度值。
4. `Density_IsValid = true`。
5. 原始记录使用 `EquRecordId` 绑定。

页面也有针对 D4 的处理：

```js
item.isDeviceView = !(findDevice && findDevice.DeviceModelType === 'MT-D4');
```

D4 设备不显示普通密度记录查看按钮。

## 6. 落库逻辑

采集成功后，后端会：

1. 把普通密度计的 3 条 `CDP_Testing_Density` 标记为已使用：
   - `Status = false`
   - `PreBatchTestingID = 当前样本`
2. 写入 `CDP_PreBatch_TestingRecord`：

| 字段 | 值 |
| --- | --- |
| `TestItem` | 21 |
| `TestItemName` | Density |
| `EquID` | 密度计设备 ID |
| `EquName` | 设备编号 |
| `Value` | 平均密度或 D4 Dens |
| `OperationType` | 1 |

3. 更新 `CDP_Equipment_Record`：
   - `DataType = 3`
   - `StepID`
   - `StepName`
   - `PreBatchID`
   - `PreBatchTestingID`
   - `Created_by`
4. 更新 `CDP_PreBatch_Testing`：
   - `DensityDeviceID`
   - `DensityDeviceName`
   - `Density`
   - `Density_Testing_time`
   - `Density_Testing_By`
   - `Density_Testing_Byname`
   - `Density_IsValid`

## 7. 撤销逻辑

撤销入口：

```csharp
DashboardService.DensityCaptureCancel(...)
```

撤销时：

1. 写入 `CDP_PreBatch_TestingRecord`，`OperationType = 5`，记录撤销原因。
2. 清空当前样本密度字段：
   - `Density`
   - `DensityDeviceID`
   - `DensityDeviceName`
   - `Density_TestingSourceType`
   - `Density_Testing_By`
   - `Density_Testing_Byname`
   - `Density_Testing_time`
3. 普通密度计如果能找到原先绑定的 3 条记录，则恢复：
   - `Status = true`

## 8. 注意点

- 普通密度计必须要有 3 条有效未绑定数据，不能只取 1 条。
- 有效期由配置 `DensityExpireMin` 控制。
- `Density_IsValid = false` 时，数据仍会返回给前端展示，但页面会标红并允许重新采集。
- D4 与普通密度计逻辑差异较大，排查问题时先确认设备 Model。
