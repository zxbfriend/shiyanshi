# 完整性测试仪逻辑

## 1. 入口与数据来源

页面位置：`dashboard.html` 的 Filter Integrity Test 区域。

前端控制器：`dashboardController.js`。

设备加载：

```js
$scope.FilterEqus = await getEquipmentListByType(9);
$scope.FilterDescOptions = await geDescriptionListFilterByType(3);
```

完整性测试数据列表字段：

```text
item.FilterIntegrityTestList
```

后端查询 Dashboard 时，从 `CDP_PreBatch_TestingFilterIntegrityTest` 子表加载。

## 2. 页面操作入口

| 页面操作 | 前端方法 | 后端入口 |
| --- | --- | --- |
| 保存描述 | `saveDescFilterIntegrityTest` | `Sartocheck4plusDescSave` |
| 取消描述 | `cancelDescFilterIntgrityTest` | `CancelDescription` |
| 新增一行 | `addFilterIntegrityTest` | 前端临时新增，保存/采集时落库 |
| 选择已有结果 | `selectCurrentFilterIntegrityTest` | `DataBindingSartocheck4plusResult` |
| 发送采集命令 | `captureCurrentFilterIntegrityTest` | `Sartocheck4plusOrderSend` |
| 轮询结果 | `loopFilterIntegrityTest` | `RefreshSartocheck4plusResult` |
| 撤销采集 | `cancelFilterIntegrityTest` | `Sartocheck4plusOrderCancel` |
| 查看 PDF | `viewFilterIntegrityTest` | 直接打开 `FilterIntegrityTestPath` |

## 3. 描述保存逻辑

页面要求先选择 `DescriptionID`。

保存入口：

```csharp
DashboardService.Sartocheck4plusDescSave(PreBatchTestingFilterIntegrityTestModel requestModel)
```

如果已有 `PreBatchTestingFilterTestID`：

- 更新 `DescriptionID`
- 更新修改人和修改时间

如果是新行：

- 新建 `CDP_PreBatch_TestingFilterIntegrityTest`
- 写入 `PreBatchTestingID`
- 写入 `DescriptionID`
- 默认 `Status = true`、`IsDelete = false`

页面通过 `DescriptionFlag = Boolean(DescriptionID)` 控制描述是否可改。

## 4. 发送 Sartocheck4plus 测试命令

前端入口：

```js
captureCurrentFilterIntegrityTest(item, parentItem)
```

发送前必须选择：

```text
FilterIntegrityTestDeviceID
```

请求参数：

- `EquipmentId`
- `PreBatchId`
- `StepName`
- `PreBatchTestingId`
- `PreBatchTestingFilterTestID`

后端入口：

```csharp
DashboardService.Sartocheck4plusOrderSend(DensityCaptureModel requestModel)
```

后端流程：

1. 查询操作人显示名。
2. 查询完整性测试仪设备。
3. 如果已有 `PreBatchTestingFilterTestID`，更新当前行的设备、测试人、测试时间和来源类型。
4. 如果没有 `PreBatchTestingFilterTestID`，新增 `CDP_PreBatch_TestingFilterIntegrityTest`。
5. 新建一条 `CDP_Testing_FilterIntegrity`：
   - `EquId = EquipmentId`
   - `PreBatchTestingID = PreBatchTestingFilterTestID`
   - `Status = Waiting`
   - `SendTime = now`

注意：这里 `CDP_Testing_FilterIntegrity.PreBatchTestingID` 存的是完整性测试子表 ID，即 `PreBatchTestingFilterTestID`，不是主样本的 `PreBatchTestingID`。

## 5. 轮询结果逻辑

页面在 Dashboard 列表加载后，如果发现：

```text
FilterIntegrityTest_Testing_By 有值
且 FilterIntegrityTestResult 为空
```

就启动轮询：

```js
loopFilterIntegrityTest(item, index)
```

轮询间隔：

```text
100000 ms
```

同时会立即执行一次 `_fn()`。

后端入口：

```csharp
DashboardService.RefreshSartocheck4plusResult(int preBatchTestingId, int userId)
```

后端查询当前样本下所有完整性测试行，并对每行查找完成结果：

```text
CDP_Testing_FilterIntegrity.PreBatchTestingID == 当前行.PreBatchTestingFilterTestID
Status == 3
ReportName != null
按 Creation_time 倒序取最新一条
```

如果找到完成结果，且当前行还没有结果，则回填：

- `FilterIntegrityTestType = tfi.Type`
- `FilterIntegrityTestResult = tfi.Evaluation`
- `FilterIntegrityTestEval = tfi.Result`
- `FilterIntegrityTestPath = tfi.FilePath`

并写入操作记录：

| 字段 | 值 |
| --- | --- |
| `TestItem` | 23 |
| `TestItemName` | FilterIntegrityTest |
| `EquID` | 完整性测试仪设备 ID |
| `EquName` | 设备编号 |
| `Value` | `FilterIntegrityTestResult` |
| `OperationType` | 1 |

同时写入设备归档：

- `CDP_Equipment_Record.DataType = 3`
- `PreBatchID`
- `PreBatchTestingID`
- `StepID`
- `StepName`
- `Value = FilterIntegrityTestResult`

## 6. 选择已有测试结果绑定

页面入口：

```js
selectCurrentFilterIntegrityTest(item, parentItem)
```

弹窗：`selectFilterIntegrityTest`。

后端入口：

```csharp
DashboardService.DataBindingSartocheck4plusResult(PreBatchTestingFilterIntegrityTestModel requestModel)
```

后端从 `CDP_Testing_FilterIntegrity` 查找：

```text
TestingFilterIntegrityId = requestModel.TestingFilterIntegrityId
Status in (3, 5)
ReportName != null
```

绑定时回填：

- `FilterIntegrityTestType`
- `FilterIntegrityTestResult`
- `FilterIntegrityTestEval`
- `TestingFilterIntegrityId`
- `FilterIntegrityTestDeviceID`
- `FilterIntegrityTestDeviceName`
- `FilterIntegrityTestPath`
- `FilterIntegrityTest_Testing_By`
- `FilterIntegrityTest_Testing_Byname`
- `FilterIntegrityTest_Testing_time`

已有行绑定时：

```text
FilterIntegrityTest_TestingSourceType = 9
```

新建行绑定时：

```text
FilterIntegrityTest_TestingSourceType = 1
```

绑定成功后，原始 `CDP_Testing_FilterIntegrity.Status` 会被置为 `5`。

## 7. 撤销逻辑

页面入口：

```js
cancelFilterIntegrityTest(item)
```

后端入口：

```csharp
DashboardService.Sartocheck4plusOrderCancel(int equipmentId, int preBatchTestingFilterTestID, string cancelResult, int userId)
```

撤销时：

1. 写入 `CDP_PreBatch_TestingRecord`：
   - `TestItem = 23`
   - `OperationType = 5`
   - `Value = 原 FilterIntegrityTestResult`
   - `CancelResult = 撤销原因`
2. 清空当前完整性测试行：
   - `FilterIntegrityTestDeviceID`
   - `FilterIntegrityTestDeviceName`
   - `FilterIntegrityTestResult`
   - `FilterIntegrityTestEval`
   - `FilterIntegrityTest_Testing_By`
   - `FilterIntegrityTest_Testing_Byname`
   - `FilterIntegrityTest_Testing_time`
   - `FilterIntegrityTestType`
   - `FilterIntegrityTestPath`
3. 设置：
   - `FilterIntegrityTest_TestingSourceType = Cancel`
4. 如果有关联的 `CDP_Testing_FilterIntegrity`，把其 `Status` 恢复为 `3`。

## 8. 查看结果

页面通过：

```js
viewFilterIntegrityTest(item)
```

直接打开：

```text
location.origin + item.FilterIntegrityTestPath
```

通常用于查看完整性测试仪生成的 PDF 或报告文件。

## 9. 注意点

- 完整性测试仪的结果不是页面计算出来的，而是设备/外部数据表 `CDP_Testing_FilterIntegrity` 产生后由后端回填。
- 发送命令后，页面靠轮询刷新结果；轮询间隔较长，但会立即执行一次。
- `CDP_Testing_FilterIntegrity.PreBatchTestingID` 在这里指向完整性测试子表 ID，不是主样本 ID，排查 SQL 时容易混淆。
- 选择已有结果绑定和发送命令采集都会写入操作记录，但来源类型不同。
