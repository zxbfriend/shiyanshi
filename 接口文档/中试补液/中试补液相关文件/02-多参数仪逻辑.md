# 多参数仪 pH / Cond. 逻辑

## 1. 入口与数据来源

页面位置：`dashboard.html` 的 `pH_Conductivity` 区域。

前端控制器：`dashboardController.js`。

设备加载：

```js
$scope.PHEqus = await getEquipmentListByType(5);
$scope.CONDEqus = await getEquipmentListByType(5);
```

前端操作入口：

```js
captureCurrentPHData(item, type)
cancelCurrentPHData(item, type)
```

| type | 含义 |
| ---: | --- |
| 1 | 只采集 pH |
| 2 | 只采集 Cond. |
| 3 | pH 和 Cond. 一起采集 |

接口定义在 `NPPGUI/res/app-res.js`：

| 前端资源 | URL |
| --- | --- |
| `capturePHOrCond` | `api/calibration/PhOrCondTest` |
| `cancelCapturePHOrCond` | `api/calibration/PhOrCondCancel` |

后端服务不在 `DashboardService` 中，实际由：

```csharp
MultiParamterService.PhOrCondTest(PhOrCondTestModel request)
MultiParamterService.PhOrCondCancel(PhOrCondTestModel request)
```

处理。

## 2. 页面校验与展示

采集前校验：

| 操作 | 校验 |
| --- | --- |
| type = 1 | 必须选择 `PHDeviceID` |
| type = 2 | 必须选择 `CondDeviceID` |
| type = 3 | `PHDeviceID` 或 `CondDeviceID` 至少一个存在 |

页面规则：

- pH 和 Cond. 如果选择不同设备，页面提示 `dashboard_PH_Cond_Difference`。
- 如果同一台多参数仪同时支持 pH 和 Cond.，页面允许一次 Capture All。
- 温度超出 `24.5 ~ 25.4` 时，前端提示 `dashboard_PH_Cond_Temp_Wrong`。

温度提示是页面级提示，后端另有校准上下限规则用于判断 pH / Cond. 数值是否合格。

## 3. 后端取数逻辑

`PhOrCondTest` 从 `CDP_Testing_Multiparameter` 中找当前设备未绑定到样本的读数。

### 3.1 只采集 pH

取数条件等价于：

```text
EquID = request.EquipmentId
PreBatchTestingID is null
DataType in (PH, PHAndCond)
Creation_time > 有效时间下限
按 TestingTime 倒序取最新一条
```

写入：

- `PH`
- `PHTemp`
- `PHDeviceID`
- `PHDeviceName`
- `PH_Testing_By`
- `PH_Testing_Byname`
- `PH_Testing_time`
- `PH_TestingSourceType = 1`

同时写入 `CDP_PreBatch_TestingRecord`：

| 字段 | 值 |
| --- | --- |
| `TestItem` | 11 |
| `TestItemName` | pH |
| `Value` | `PHStr` |
| `OperationType` | 1 |

### 3.2 只采集 Cond.

取数条件等价于：

```text
EquID = request.EquipmentId
PreBatchTestingID is null
DataType in (Cond, PHAndCond)
Creation_time > 有效时间下限
按 TestingTime 倒序取最新一条
```

写入：

- `Cond`
- `CondTemp`
- `CondDeviceID`
- `CondDeviceName`
- `Cond_Testing_By`
- `Cond_Testing_Byname`
- `Cond_Testing_time`
- `Cond_TestingSourceType = 1`

同时写入 `CDP_PreBatch_TestingRecord`：

| 字段 | 值 |
| --- | --- |
| `TestItem` | 13 |
| `TestItemName` | Cond. |
| `Value` | `CondStr` |
| `OperationType` | 1 |

### 3.3 pH + Cond. 一起采集

后端会在有效期内取：

- 最新 DataType = 1 的 pH 记录。
- 最新 DataType = 2 的 Cond. 记录。

如果两种记录都存在，则同时写入 pH 和 Cond. 字段；如果只存在其中一种，则只写入存在的那一种。

## 4. 合格性判断

后端使用设备校准设置判断 pH 和 Cond. 是否在范围内。

### 4.1 pH

```text
PHVerificationMin <= PH <= PHVerificationMax
```

满足则：

```text
PHStatus = true
```

### 4.2 Cond.

```text
ConductivityCalibrationMin <= Cond <= ConductivityCalibrationMax
```

满足则：

```text
CondStatus = true
```

### 4.3 一起采集时的状态

| 结果 | `Status` | `PHStatus` | `CondStatus` |
| --- | --- | --- | --- |
| pH 和 Cond. 均合格 | true | true | true |
| 只有 pH 合格 | false | true | false |
| 只有 Cond. 合格 | false | false | true |
| 都不合格 | false | false | false |

## 5. 设备原始记录绑定

采集成功后，后端会把关联的 `CDP_Equipment_Record` 更新为当前样本上下文：

- `DataType = 3`
- `PreBatchID`
- `PreBatchTestingID`
- `StepID`
- `StepName`
- `Created_by`

对应的 `CDP_Testing_Multiparameter.PreBatchTestingID` 也会绑定当前样本，表示该读数已被使用。

## 6. 撤销逻辑

撤销入口：

```csharp
MultiParamterService.PhOrCondCancel(PhOrCondTestModel request)
```

撤销 pH：

- 查找当前设备、当前样本、当前 `PH_Testing_time` 对应的多参数原始记录。
- 清空 `PH`、`PHTemp`、设备、测试人、测试时间、来源类型等字段。
- 写入撤销操作记录，`OperationType = 5`，`TestItem = 11`。
- 将原始 `CDP_Testing_Multiparameter.PreBatchTestingID` 置空。

撤销 Cond.：

- 查找当前设备、当前样本、当前 `Cond_Testing_time` 对应的多参数原始记录。
- 清空 `Cond`、`CondTemp`、设备、测试人、测试时间、来源类型等字段。
- 写入撤销操作记录，`OperationType = 5`，`TestItem = 13`。
- 将原始 `CDP_Testing_Multiparameter.PreBatchTestingID` 置空。

## 7. 注意点

- 页面温度异常提示使用固定范围 `24.5 ~ 25.4`，后端 pH / Cond. 合格性使用校准设置上下限，两者不是同一条规则。
- pH 和 Cond. 使用相同设备类型 `5`，页面分别维护 `PHEqus` 和 `CONDEqus`，但来源列表相同。
- DashboardService 只负责查询展示这些字段，不负责 pH / Cond. 采集计算。
