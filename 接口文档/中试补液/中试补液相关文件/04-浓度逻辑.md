# 浓度逻辑

## 1. 入口与设备类型

页面位置：`dashboard.html` 的 Protein Concentration 区域。

前端控制器：`dashboardController.js`。

设备加载：

```js
let list7 = await getEquipmentListByType(7);
let list1 = await getEquipmentListByType(11);
$scope.CONCEqus = list1.concat(list7);
```

设备类型：

| type | 含义 | 页面处理 |
| ---: | --- | --- |
| 7 | ND2000 / 光度计类浓度设备 | 打开 concentrationTesting 弹窗 |
| 11 | SoloVPE | 发送 SoloVPE 任务并轮询 |

前端入口：

```js
changeEqu(item)
goConc(item)
cancelCaptureConc(item)
viewDetailConc(item)
```

## 2. 分流逻辑

`goConc(item)` 根据设备类型分流：

```text
如果 EquType == 11:
    走 SoloVPE 任务发送 + 轮询
否则:
    打开 concentrationTesting 弹窗，走 ND2000 / 光度计流程
```

页面展示格式：

```js
if (item.ConcDeviceType === 11) {
  if (item.Conc && ['AC', 'BE', 'FT', 'VINF', 'VF'].includes(item.Step)) {
    item.Conc = Number(item.Conc).toFixed(3);
  } else {
    item.Conc = Number(item.Conc).toFixed(1);
  }
}
```

即 SoloVPE 浓度：

| Step | 显示精度 |
| --- | ---: |
| `AC`、`BE`、`FT`、`VINF`、`VF` | 3 位小数 |
| 其他 | 1 位小数 |

## 3. ND2000 / 光度计流程

弹窗控制器：`NPPGUI/views/downBio/dashboard/concentrationTesting/concentrationTestingController.js`。

主要接口：

| 前端资源 | 后端入口 |
| --- | --- |
| `getConcQueryList` | `DashboardService.QuerryConc` |
| `sendConcOrder` | `DashboardService.SendND2000Task` |
| `cancelConcOrder` | `DashboardService.CancelConc` |
| `doneConcOrder` | `DashboardService.SaveConcResult` |
| `deleteConcData` | `DashboardService.DeleteND2000` |

弹窗初始化后每 5 秒轮询：

```js
$scope.getCurrentStatus(true)
```

轮询返回：

- 测试明细 `ND200QuerryModel`
- 当前 `Avg`
- 当前 `RSD`
- `RSDStatus`
- `LastBlankStatus`
- `CanSend`
- 页面操作颜色 `OperColor`

## 4. ND2000 查询与计算

后端入口：

```csharp
DashboardService.QuerryConc(int preBatchTestingID)
```

规则来源：

| RuleType | 枚举 | 用途 |
| ---: | --- | --- |
| 3 | RSD | 样本 RSD 判定 |
| 5 | BlankConc | Blank 浓度判定 |

明细来源：

```text
CDP_Testing_ConcentrationTask
join CDP_Testing_ConcentrationOrder
join Auth_User
```

### 4.1 RSD 规则

后端取最后一次有 RSD 的任务：

```text
当前 RSD = 最新任务.RSD
当前 Avg = 最新任务.Avg
```

如果 `RSD < 0`：

```text
RSDStatus = false
```

否则：

```text
RSDStatus = CheckDensityValue(RSD规则符号, RSD规则值, 当前RSD)
```

但是 RSD 是否有效还有额外条件：

```text
非 Blank 样本数必须 >= 3
最后 3 条测试不能包含 Blank
```

不满足时：

```text
RSDStatus = null
```

### 4.2 Blank 规则

对 Blank 记录：

```text
BlankStatus = !CheckDensityValue(Blank规则符号, Blank规则值, abs(ProteinConc))
```

最新 Blank 是否允许继续发样本：

```text
CanSend = CheckDensityValue(Blank规则符号, Blank规则值, abs(最新Blank.ProteinConc))
```

页面在发送样本前会检查：

```js
if (!$scope.canSend) {
  utility.message(T.T('dashboard_Conc_Send_Error'));
  return false;
}
```

### 4.3 保存浓度

弹窗点击 Done 时：

```text
如果 current.RSDStatus 为 true:
    保存当前 Avg 为 Conc
否则:
    关闭弹窗，不保存
```

保存入口：

```csharp
DashboardService.SaveConcResult(SaveConcModel saveConcModel)
```

保存字段：

- `ConcDeviceID`
- `ConcDeviceName`
- `Conc`
- `Conc_Testing_By`
- `Conc_Testing_Byname`
- `Conc_Testing_time`
- `Conc_TestingSourceType = 1`
- `Conc_RSD`

同时写入：

- `CDP_PreBatch_TestingRecord`，`TestItem = 15`，`OperationType = 3`
- `CDP_Equipment_Record`，`DataType = 3`

## 5. SoloVPE 流程

前端入口：

```js
getSolovpeEqu(item)
setQuerry(item)
```

发送参数：

- `SampleID`
- `StepName`
- `EquId`
- `preBatchTestingID`

发送成功后每 3 秒轮询一次：

```js
getSolovpeQuerry({ preBatchTestingID, view: false })
```

最多等待 60 秒。超过 60 秒提示 `public_SoloVpe_NoData`。

后端入口：

```csharp
DashboardService.SoloVPEQuerry(int preBatchTestingID, int useID, bool view = true)
```

规则来源：

| RuleType | 枚举 | 用途 |
| ---: | --- | --- |
| 9 | UltravioletRSD | SoloVPE RSD 判定 |
| 11 | SoloVPEConc | SoloVPE 明细 RSqr 判定 |

## 6. SoloVPE 计算与判定

后端查询最新 `CDP_Testing_ConcentrationSoloVPETask`，并加载明细 `CDP_Testing_ConcentrationSoloVPETask_Dtl`。

明细规则：

```text
每条明细 RSqr 都必须满足 RuleType = 11 规则
```

如果明细规则都通过，则判断 RSD：

```text
RSDStatus = CheckDensityValue(RuleType=9 的符号, RuleType=9 的值, RSD)
```

如果存在 `Avg`，则写入当前样本：

- `Conc = Avg`
- `Conc_SoloVPE_ID`
- `ConcDeviceID`
- `ConcDeviceName`
- `Conc_Testing_By`
- `Conc_Testing_Byname`
- `Conc_Testing_time`
- `Conc_RSD`

当 `view = false` 时，还会写入：

- `CDP_PreBatch_TestingRecord`
- `TestItem = 15`
- `OperationType = 1`

## 7. 撤销逻辑

页面撤销入口：

```js
cancelCaptureConc(item)
```

前端弹出撤销原因，然后调用：

```js
downDashboardRes.cancelConc({
  PreBatchTestingId: item.PreBatchTestingID,
  CancelResult: value
})
```

后端另有：

```csharp
DashboardService.CancelSpectrophotometer(CancelDescriptionModel cancelDescriptionModel)
```

用于清空浓度字段并记录撤销。ND2000 设备任务取消则走：

```csharp
DashboardService.CancelConc(int deviceId)
```

该方法主要向设备服务发送 cancelTask。

## 8. 注意点

- ND2000 的 Done 保存依赖 `RSDStatus == true`，而 `RSDStatus` 只有在最近 3 条非 Blank 样本满足条件时才有明确值。
- Blank 判断同时影响是否允许继续发送样本。
- SoloVPE 会直接把 `Avg` 写入 `Conc`，并额外保存 SoloVPE 任务 ID 和 RSD。
- 页面端对 SoloVPE 浓度做显示精度处理，实际数据库中保存的是后端返回的 `Avg.ToString()`。
