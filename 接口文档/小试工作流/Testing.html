1. 手动取测（BGA / Cedex / OSMO / OSMO6060 / Vicell）

1.1 共性链路

sequenceDiagram participant UI as SystemControl页面 participant API as TestingTaskController participant Svc as TestingService participant Pipe as Named Pipe participant Sub as 设备子系统 participant DB as CDP_Testing UI->>API: 录入 SampleID 并 Send API->>Svc: 校验重复/LoadSample占用/已上传 Note over API: Mode = Manual(1) API->>Pipe: sendOrder / order / send_orders / log_in_manual Pipe->>Sub: 下发订单 Sub->>DB: 写 Order / Task / Result UI->>API: 轮询 task-list UI->>API: Upload / Sign / Verify
  1. Angular 页通过 taskRes（app/res/app-res.js）调用 api/task/*。
  2. 控制器：WuXiBioLogics.WebAPI/Testing/TestingTaskController.cs。
  3. API 设置 Mode = EnumDeviceMode.Manual (1)，并校验：
    • SampleID 在 Order/Task 中是否重复；
    • ILoadSampleService.CheckSampleIdRepetition（与手动取样冲突）；
    • ITestService.CheckSampleStatusIsUpload（状态约 10–14 已上传则拦截）。
  4. 通过 Named Pipe 发往设备 Windows 子系统；子系统负责创建/更新 Order、Task、Result。
  5. UI 轮询任务列表；检测完成（Tested）后人工 Upload → Signed → Verified。
  6. 若实验室机器为 Auto 模式且当前设备为指定自动设备，前端会拦截手动发送。

2. 自动取测（Task Queue）

2.1 含义

自动取测对应 Task Queue 中 OPID = 1 / Code = SAMPLINGTEST，权限为 Auto Sampling / Auto Testing。

  • 本仓库：创建队列、校验、编辑删除、终止/重置调用。
  • 外部 Core Service：真正执行取样与检测，回写 CDP_Batch_OP 状态。
  • 检测结果仍落在各 CDP_Testing_* 表（与手动取测共用结果表结构）。

同页还支持 OPID=2 FEEDING（自动补料），逻辑类似但不在本文展开。

2.6 业务逻辑

sequenceDiagram participant UI as TaskQueue UI participant API as TaskQueueController participant Svc as TaskQueueService participant DB as SQL participant Core as Core Service participant Test as CDP_Testing UI->>API: add-taskqueue OPID=1 API->>Svc: 接种/权限校验 + Rule展开 API->>Svc: 耗材计算 Svc->>DB: Insert TaskQueue+Batch_OP Mode=Auto Status=Pending Core->>DB: Pending to Executing to Executed Core->>Test: 驱动取样与仪器检测 Test->>DB: 写入检测结果 UI->>API: terminate/reset to Core HTTP

创建

  1. 选择反应器 + OPID=1（SAMPLINGTEST）。
  2. 勾选子项：TestingRule（常开）+ BGA / VICELL / OSMO / CEDEX / RESERVEDSAMPLE 等；自动检测至少勾选一个 assay。
  3. 设置时间策略：Now / Timing / Rule（日期范围内每日）/ Interval（间隔分钟）。
  4. Cedex 打开检测项对话框配置分析项与限值。
  5. check-taskqueue：当日同反应器/同 SampleID 是否已测预警。
  6. add-taskqueue：Rule/Interval 展开为多条 Timing；解析批次；插入 TaskQueue → Batch_OP（Mode=Auto, Pending）→ Sub + Parameter；耗材预估。

排队与执行：Pending 直至 Core Service 拾取；驱动硬件并更新状态；UI 可 Terminate/Reset；结果写入 CDP_Testing_*。

编辑/删除：仅 Pending 可编辑；Executing 不可删。

3. 手动取样自动检测（loadSampleNew）

3.5 业务逻辑

flowchart TD A[人工放管到 ROW6_EPTUBE3] --> B[Draft 保存] B --> C[写 LoadSampleDtl Status=0] B --> D[写 Item_Serials Status=2 + ExtraData] C --> E[Confirm Status=1] E --> F{机器模式 Auto?} F -->|是| G[切 Manual] F -->|否| H[Start] G --> H H --> I[Status=3] H --> J{含 BGA或Vicell?} J -->|是| K[ItemStatus=17] J -->|否| L[ItemStatus=16] H --> M[切 Auto] K --> N[机器人按 ExtraData 检测] L --> N N --> O[IoT回写或 SyncLoadSample] O --> P{全部 IsComplete 且物料 Discard?} P -->|是| Q[Status=5 Completed]
  1. 加载：GET update-load-sample 合并 ROW6_EPTUBE3 孔位与未完成明细（Status < 5）。
  2. Draft：POST save-manual-sample-auto-test — 校验后写 Dtl(Status=0) + Item_Serials(Status=2, ExtraData)。
  3. Confirm：Status 0→1；若为 Auto 模式先切 Manual。
  4. Start：Status 1→3；ItemStatus→17（有 BGA/Vicell）或 16；切 Auto。
  5. 机器人/IoT：读 ItemStatus 与 ExtraData 执行检测；可经 update-load-sample-status（DeviceType 1/3/5/7）置完成。
  6. 同步：SyncLoadSample / Job 轮询 Testing 表更新 *IsComplete；全部完成且 ItemStatus=28 → Status=5。
  7. Cancel（Status<3）：Status=9，ItemStatus=28，位置置空。

4.3 结果表与三种流程的关系

三种流程最终检测数据都汇聚到同一套仪器结果表：

  • BGA：CDP_Testing_BGATask + BGATaskResult
  • Cedex：CDP_Testing_CedexTaskDtl + CedexTaskResult
  • OSMO：CDP_Testing_OSMOTaskDtl（字段 OSMO）
  • Vicell：CDP_Testing_VicellTaskDtl（VCD / Viability / AvgDiam）
区别在于如何产生订单：手动取测靠 Pipe；自动取测靠 TaskQueue + Core Service；手动取样自动检测靠 LoadSample 物料状态交接后再由机器人写入上述表。
