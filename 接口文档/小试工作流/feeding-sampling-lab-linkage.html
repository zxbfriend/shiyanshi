一期 / 二期 · 自动补料与手动补料取样

说明一期、二期自动补料与手动补料/取样的入口、用到的表、字段含义，以及表与表之间的关系。

1. 产品分工

一期二期
自动补料 在「任务队列」中创建 在「补料任务队列」中创建
手动补料 「手动补料」页面（两端同一入口，执行链路不同）
手动取样 「手动取样」页面（冲洗 / 取样 / 消毒等）

一期

  • 自动补料 → 任务队列 → CDP_TaskQueue + CDP_Batch_OP（FEEDING，Mode=3）
  • 手动补料 → 手动操作记录表 → 下层设备服务
  • 泵速主数据 → 速度设置（非默认连接页）

二期

  • 自动补料 → 补料任务队列 → CDP_Batch_FixedFeedingTask
  • 任务队列里不再作为自动补料入口（自动 FEEDING 选项隐藏）
  • 手动补料 → 同样写入固定补料任务表（Mode=手动）并驱动地秤状态
  • 地秤 / 泵默认 → 「地秤」「默认连接」页配置

2. 一期：自动补料（任务队列）

一期 自动补料只在「任务队列」创建。本节只讲自动补料，不涉及取测。

做什么

  • 选择培养批次 / 反应器，选择操作类型为自动补料（FEEDING）
  • 勾选泵位子操作、填写计划时间、体积、速度等参数后保存
  • 系统按自动模式调度执行，并可查看补料实测曲线

表与表的关系

CDP_OP_Definition (OP 主数据, Code=FEEDING) ↑ OPID CDP_Batch ←—— BatchID —— CDP_Batch_OP (Mode=3 自动, LabId=1) │ │ │ LocCombinationID ├── 1:N CDP_Batch_OP_Sub (泵位子操作) ↓ │ │ CDP_Location_Combinations │ └── 1:N CDP_Batch_OP_ParameterValue │ LabDeviceID │ (计划时间、体积、速度等) ↓ ├── 1:N CDP_Batch_OP_Exec (实测 ActualValue) CDP_LabDevice │ └── 1:1 CDP_TaskQueue (队列头, BatchOPID)

如何限定到一期实验室

列表经 CDP_Batch_OP.BatchID → CDP_Batch.LocCombinationID → CDP_Location_Combinations.LabID = 1（或 Batch_OP.LabId）过滤。

创建到执行逻辑

  1. 任务队列保存 → 插入 Batch_OP（Mode=3，OP=FEEDING）+ Sub + ParameterValue + TaskQueue
  2. 调度按计划时间执行各泵位子项，更新 Status / 时间
  3. 执行结果写入 Batch_OP_Exec.ActualValue，供曲线查看

3. 一期：手动补料 / 手动取样

3.1 手动补料

在「手动补料」页选择补料单元与泵位，填写体积、速度后启动或中止。一期走手动操作记录，再下发给设备侧。

表关系

CDP_Batch ← BatchID — CDP_ManualOP_Rec — LabDeviceID → CDP_LabDevice (补料单元) │ ├── LocCombinationID → CDP_Location_Combinations │ ├── LabDeviceSubID → CDP_LabDeviceSub (泵) │ └── LocationControls → 料液/瓶 ItemDefID │ └── 1:N CDP_ManualOP_Detail_Rec (过程重量等) CDP_ManualOP_Parmeter (按 LabDeviceID + OperationType 存默认体积/速度)

CDP_ManualOP_Rec

字段含义关联
ManualOPRecID主键← Detail_Rec.ManualOPRecID
LabDeviceID补料设备→ LabDevice
BatchID当前培养→ Batch
OperationType操作类型（不同泵位/料液对应不同编号，如 11/13/15/17）—
ExecParametersJSON：体积、速度、位号、物料等—
StartTime / EndTime起止—
Status1 执行中等；结束/中止更新；异常可带 ErrorCode—
Weight汇总重量（如有）—
LocCombinationID工位组合→ Location_Combinations

CDP_ManualOP_Parmeter / Detail_Rec

表关键字段作用
CDP_ManualOP_Parmeter LabDeviceID, OperationType, PumpingType, DefaultParameters 该设备某类操作的默认参数
CDP_ManualOP_Detail_Rec ManualOPRecID, Weight, PumpedTime, Speed, CurrentScaleValue 执行过程采样点

3.2 手动取样

在「手动取样」页做冲洗、取样、消毒。一期同样写 CDP_ManualOP_Rec（OperationType：1 冲洗 / 3 取样 / 5 消毒），下发设备后回写结束状态；成功取样可回写批次操作上的取样体积类参数。

与「取样单元换液」工作流不同：本页是设备侧手动冲洗/取样/消毒；换液走工作流另一套表（见第 7 节）。

4. 二期：自动补料（补料任务队列）

二期 自动 / 计划补料在「补料任务队列」创建与管理。中心表是 CDP_Batch_FixedFeedingTask。

表与表的关系

CDP_Batch ← BatchID — CDP_Batch_FixedFeedingTask │ ├── FeedingMediumID → CDP_Item_Def (补料介质) ├── FeedingPumpNo / 速度 对应同舱补料单元上的泵位 │ (经 LabDevice Type=5 → LabDeviceSub / Location_Combinations) ├── ScaleId 链路：LabDevice(Type=5).ScaleId → CDP_EqumentScale │ 执行时写 DeviceStatus；Batch.IsFeeding 同步 └── 可选 TaskQueueID / OP 参数回写 ParameterID=49 存 BatchTaskID ParameterID=41 存实际体积

CDP_Batch_FixedFeedingTask 字段

字段含义说明
BatchTaskID主键—
TaskNo任务编号—
BatchID培养批次→ CDP_Batch
SoureType来源1 协议 / 3 人工创建 / 5 子系统等
Mode模式1 自动（本队列计划）；3 手动（手动补料页也会插）
FeedingPumpNo泵位号对应位置组合上的泵
PumpSpeed泵速g/min 等
FeedingMediumID介质→ Item_Def
FeedingTime计划执行时间—
FeedingType计量方式1 按初始体积% / 3 固定体积 / 5 规则
FeedingVolumePercent / FeedingVolume计划量—
IsFeedingGlucose是否糖补料—
Confirm* / Review* / Approve*确认、复核、批准人与时间审批链
StartUserID / StartTime / EndTime实际执行—
Abort* / AbortReview*中止及审核—
TotalFeedingRealVolume 等 Before/After 重量体积执行实测—
Status任务状态见下方状态链

TaskQueueID可选关联队列→ TaskQueue（若有）
CedexSampleID关联检测样糖补料审核场景

Status 状态链

3 待批准 → 5 待执行 → 7 执行中 → 19 已执行 ↘ 9 异常 → 11 异常已处理 ↘ 17 跳过 / 99 取消

逻辑简述

  1. 在补料任务队列新建计划（Mode=1）→ 写入 FixedFeedingTask
  2. 确认 / 审核通过后进入待执行
  3. 到点执行：驱动泵；补料单元绑定的地秤 DeviceStatus=2，批次 IsFeeding=true
  4. 结束或中止：回写实测字段与 Status；地秤恢复空闲
  5. 异常处理：补量、清 ErrorCode、释放地秤，并可回写 OP 参数（如实际体积）

5. 二期：补料任务队列中的取样项

补料任务队列编辑时可勾选取样类项（如 Sampling Test）。保存时若介质类型为取样类，可带出取样体积，并旁路触发取样相关工作流，最终仍可能落到批次操作 / 任务队列记录上，但计划入口在补料任务队列，而不是一期那种在任务队列里建自动补料。

环节涉及
页面勾选取样体积等字段随任务明细提交
保存旁路可走取样手动类工作流（写工作流子表 / 再 Finish）
落库FixedFeedingTask 侧任务 + 可能的 Batch_OP / TaskQueue 审计记录

6. 二期：手动补料 / 手动取样

6.1 手动补料（与一期同页，链路不同）

一期二期
主执行表 CDP_ManualOP_Rec CDP_Batch_FixedFeedingTask（Mode=3 手动，Status 进入待执行/执行）
地秤 弱依赖 LabDevice.ScaleId → EqumentScale.DeviceStatus 2↔1；Batch.IsFeeding
详情来源 ManualOP 历史 固定补料任务执行信息；灌注场景另有剂量记录表
预灌 工作流侧启动补料指令（一期路径） 工作流侧二期路径（与补料单元供液等共用）

二期手动补料关系

手动补料页 Start → INSERT CDP_Batch_FixedFeedingTask (Mode=手动) → LabDevice(Type=5).ScaleId → CDP_EqumentScale.DeviceStatus=2 → CDP_Batch.IsFeeding=true Abort / 结束 → 任务 Status 更新；DeviceStatus=1；IsFeeding=false

6.2 手动取样

表结构与一期相同，仍为 CDP_ManualOP_Rec。二期界面多冲洗/消毒速度、灌注时多 ATF 冲洗/取样（OperationType 2 / 4）；请求会带上实验室与速度参数。

7. 二期主数据：地秤与默认连接

二期仓库菜单可见「地秤」「默认连接」。一期对应泵速走「速度设置」，不配置这两页。

表关系

CDP_EqumentScale (地秤主数据 + DeviceStatus) ↑ ScaleId CDP_LabDevice Type=5 (补料单元) ←同舱 LabCabinID→ CDP_LabDevice Type=1 (反应器) │ └── CDP_Location_Combinations (每个泵位一条) ├── LabDeviceSubID → CDP_LabDeviceSub │ DefaultSpeed / MaxSpeed / Status / StorageType=2(泵) └── CDP_Location_Controls ControlType=3 → 料液 ItemDefID ControlType=1 → 瓶 ItemDefID

CDP_EqumentScale

字段含义谁写
ScaleId主键地秤页新建
LabId / EquipmentNo / AssetNo / Model / Specification归属与铭牌信息地秤页
IP / Port通讯地秤页
Status是否启用（维护勾选）地秤页
DeviceStatus1 空闲 / 2 补料中手动补料启动中止、补料任务异常处理

表字段含义
CDP_LabDeviceScaleId, Remake补料单元绑哪台秤、备注

这些默认会被「补料单元连接」工作流读取；连接过程中的 Next 步骤也可能按扫描结果覆盖料液、瓶与速度。培养完成（二期）会重置控件 Status、瓶默认物料，但一般保留 DefaultSpeed / MaxSpeed。

8. 与工作流的衔接

工作流影响
补料单元连接 建立反应器与补料单元关系，写/改 Location_Controls、LabDeviceSub；批次写 SupplementaryUser。之后手动补料列表才有完整泵位与料液。
补料单元供液 换液；预灌与手动补料页共用二期补料启动路径。
取样单元供液 换液（CDP_Workflow_LiquidImport_SamplingUnit），不是手动取样页。
工作流内手动补料 / 取样 Finish 向任务队列体系插入 Mode=5 的批次操作记录（审计），不等于在任务队列里「建一期自动补料」。
完成培养（二期） 重置补料侧位置/控件 Status；瓶控件默认 ItemDefID；速度字段通常保留。
