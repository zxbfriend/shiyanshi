# 串口奥豪斯设备开发操控文档

## 1. 证据与适用范围

资料来源：`feed softwae/ohaus/OhausSerialPortTool.exe`、`OhausSerialPortTool.exe.config`、反编译代码和 `总结.txt` 串口样例。历史程序证明的是串口采集和本地 HTTP 查询，不证明设备型号、写入能力或现场连通性。

## 2. 部署参数

| 项目 | 历史值 |
|---|---|
| 程序 | `OhausSerialPortTool.exe` |
| 串口 | `COM1` |
| 波特率 | `9600` |
| 数据位 | `8` |
| 停止位 | `1` |
| 校验位 | `None` |
| 握手 | `Software` / `XOnXOff` |
| DTR、RTS | 程序均设置为 `true` |
| 读取超时 | `2000 ms` |
| 分帧 | `0D 0A`（CR LF） |
| 单位 | `g` |
| 对外地址 | `http://localhost:8088` |
| 缓存键 | `OHAUSCacheKey` |
| 数据新鲜度 | API 读取时按 `DelayTime=5` 秒判断 |

## 3. 实际输入与解析

样例原始帧：

```text
1B 65 6E 74 65 72 2E 32 31 37 34 33 2E 37 20 67 0D 0A
```

ASCII 近似为：

```text
<ESC>enter.21743.7 g<CR><LF>
```

历史解析流程：

1. `DataReceived` 读取当前可用字节。
2. 转成大写十六进制并追加到接收缓存。
3. 按 `0D 0A` 拆分，保留不完整尾部。
4. 只处理包含 `67`（ASCII `g`）的分段。
5. 十六进制转文本，用 `[-]?\d+[.]?\d+` 提取第一个数字。
6. 使用本机接收时间写入缓存，单位固定为配置值 `g`。

风险：程序未在解析层验证稳定标志、净重/毛重字段或设备状态；应在重开发时保留原始帧并增加状态校验。

## 4. 查询接口

```http
GET http://localhost:8088/messageService/api/getOhausScaleData
GET http://localhost:8088/messageService/api/getOhausScaleDataList
```

单值成功结果等价于：

```json
{
  "RespondCode": 200,
  "GatherTime": "yyyy-MM-dd HH:mm:ss fff",
  "Weight": "21743.7",
  "WeightUnit": "g"
}
```

历史程序还包含设备数据查询、用户登录和 MQTT 发布路由；这些路由不应在没有业务授权和接口验证时直接开放。
