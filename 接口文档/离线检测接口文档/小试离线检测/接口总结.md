# 药明生物 SMP 系统 · 接口文档总结

> 来源目录：`docs/接口文档/`
> 整理日期：2026-08-08
> 范围：覆盖本地设备通信、SDMS 平台、Inno 反应器 IoT、上游 INNOVEL 厂商 API、LDMS 设备数据、AAD 身份认证共 6 大类接口。

---

## 0. 接口全景图

| 类别 | 传输方式 | 来源文档 | 服务对象 | 用途 |
|------|----------|----------|----------|------|
| 本地设备通信 | Windows 命名管道 | `SubSystem-NamedPipe接口文档.md` / `TestingTaskController-PipeSend-API.html` | BGA / Cedex / OSMO / ViCell 本地子系统 | 向工控机上的检测子系统下发订单、查询状态 |
| SDMS 平台 | HTTP/REST (JSON) | `发送订单到SDMS-接口文档.md` + `参数示例.txt` | SDMS 调度平台 | 下发 BGA/OSMO/Cedex 检测订单、回查结果 |
| Inno 反应器在线参数 | HTTP/REST (JSON) | `npp/InnoCaptureDataApi.md` | Inno IoT 平台 | 采集反应器在线参数（pH/DO/温度/MFC 等） |
| 上游 INNOVEL 厂商 API | HTTP/REST (JSON) | `npp/NPP API接口文档20240305.pdf`、`npp/IV-NPP-自动检测接口文档_V1.0.2.pdf`、`ccpd/(CCPD)IV-CDP-16 Innovel-IoT API接口文档.pdf` | INNOVEL 信息系统 | 本地命名管道接口的"上游源"——设备结果/检测下发的厂商标准 API |
| LDMS 设备数据 | HTTP/REST (JSON) | `npp/LDMS查询IoT平台数据API-2023-04-25.xlsx` | LDMS IoT 平台 | 按设备/时间范围拉取已接入设备实验数据 |
| 身份认证 (AAD) | SAML 2.0 + 本地 JWT | `CMCAAD调用原理.html` | Azure AD / 本地账号 | 系统登录与 Token 签发 |

**关系链**：本地 `SubSystem-NamedPipe` 的 5 个子系统，本质上是**上游 INNOVEL API（NPP / IV-NPP / CCPD）在工控机侧的本地客户端封装**——请求/响应同构（command\|payload、LabKey、ResultCode/ResultData 概念一致）。SDMS、Inno、LDMS 则是并行对接的三个外部平台，分别负责订单调度、反应器参数、设备数据采集。

## 1. 本地设备通信：Windows 命名管道（Named Pipe）

### 1.1 协议
- **写入**：`{command}|{payload}`（无参数时 payload 为空字符串，但**必须保留 `|`**）
- **读取**：`{CommandName}|{ErrorCode}|{ResultDataJSON}`
- **ErrorCode（8 位十六进制）** = `ErrorCodeLevel(2位)` + `ErrorType(2位)` + `SubsystemErrorNumber(4位)` + `00000000`
- 不符合两段格式 → 返回 `SubsystemParamsError`

### 1.2 子系统与管道名（默认 IP 来自 `TestingTaskController-PipeSend-API`）

| 子系统 | 服务类 | Pipe 名称 | 默认 IP（环境值） |
|--------|--------|-----------|-------------------|
| BGA 血气 | `BGAService` | `BGAService` | 192.168.1.145 |
| Cedex 设备配置 | `CedexService` | `CedexPipe` | 设备 SubSystemIP |
| Cedex 订单 | `CedexOrderService` | `CedexOrderPipe` | 192.168.1.226 |
| OSMO 6060 | `OsmoSixService` | `OsmoSixPipe` / `OSMOSixPipe` | 192.168.1.227（注意大小写不一致） |
| ViCell XR | `ViCellService` | `VicellPipe` | 192.168.1.145 |

### 1.3 命令一览（共 5 子系统 / 35+ 命令）

| 子系统 | 命令（节选） | 功能 |
|--------|--------------|------|
| **BGA** (9) | `log_in_check` / `log_in` / `sendOrder` / `cancel` / `cancel_sample` / `result` / `refreshResult` / `queryPortName` / `saveDevice` | 登录前检查、自动/手动下单、取消、状态查询、刷新结果、串口/配置 |
| **Cedex 配置** (2) | `get_port_names` / `save_subsystem_device` | 串口列表、保存配置 |
| **Cedex 订单** (5) | `log_in_check` / `log_in` / `send_orders` / `result` / `empty_racks` | 自动/批量下单、按 Rack 查状态、查空闲 Rack（J/K/L/M/N） |
| **OSMO 6060** (9) | `log_in_check` / `log_in` / `order` / `cancel` / `start` / `result` / `del_order` / `queryPortName` / `saveDevice` | 登录/下单/启动/取消/删除/状态/配置 |
| **ViCell XR** (10) | `save_subsysytem_setting` / `log_in_check` / `log_in` / `log_in_manual` / `clear` / `cancel` / `result` / `refresh` / `del_order` / `reset` | 配置保存、自动/手动登录（1~12 位）、清空、取消、状态、刷新、删除、重置队列 |

### 1.4 WebAPI 封装层（`TestingTaskController-PipeSend-API`）
- 封装类：`PipeConnectionHelper.PipeSend(ClientPipeConnection, method, data)` → `BaseResponse<string>`
- **返回字段**：`IsSuccess`(bool)、`ResultCode`(1=成功 / 0=业务失败 / -1=连接或解析异常)、`ResultMessageCode`(成功=`0x0000000000000000`，失败=16 位 hex)、`Data`(JSON 字符串，需二次反序列化)
- 全控制器共 **27 处 PipeSend 调用 / 22 种唯一管道方法**
- 文档中每个方法均给出：HTTP 标签（如 `POST bga-order-send`）、C# 调用片段、入参对象、成功判定（`IsSuccess && ResultCode==1`）

### 1.5 通用任务状态码（`result` 命令）
`0`=无记录 · `1`=已创建 · `3`=检测中 · `5`=进行中/等待 · `7`=已完成 · `99`=已取消（各子系统有额外映射逻辑）

## 2. SDMS 平台接口（HTTP/REST，订单下发与结果回查）

- **Base URL**：`{SDMSPlatformAddress}` + `sdms-app/`，示例 `http://10.248.161.66:9080/`
- **Content-Type**：`application/json`；**超时**：300 秒（5 分钟）

### 2.1 接口清单
| 常量 | 相对路径 | 用途 |
|------|----------|------|
| `SDMSOAUTHLOGIN` | `sdms-app/oauth/login` | 应用登录，获取 `appToken` |
| `SDMSVALIDEQU` | `sdms-app/valid-equ` | 校验设备序列号 + 私钥 |
| `SDMSSENDORDER` | `sdms-app/order/set` | **下发检测订单**（BGA/OSMO/CedexBio 通用） |
| `SDMSORDERRESULT` | `sdms-app/order/get` | 按时间范围查询检测结果 |
| `SDMSREMOTECONTROL` | `sdms-app/remote-control` | 远程控制（已配置，文档未含调用日志） |

### 2.2 认证
- `POST sdms-app/oauth/login`，入参 `{appKey, appSecret}`，返回 `data.appToken` + `data.tokenTimeOut`(示例 120s)
- Token 由 `TokenJob` 定时刷新（`TokenJobIntervalEnable=Y`）
- 业务请求经 `CustomMessageHandler` 注入 `appToken`（Header 名需对照源码，文档 cURL 示例用 `Authorization: Bearer`）

### 2.3 `order/set` 请求体（通用结构）
```json
{ "serialNumber": "...", "privateKey": "...",
  "testingOrder": {
    "sampleId": "...",
    "DeviceModel"/"DeviceNo"/"Temp": "...",   // BGA（DeviceModel/DeviceNo 已标注"无用"）
    "positionNo": "...",                       // OSMO
    "PositionNo": "...", "cedexCheckBioModel": [...]  // CedexBio
  } }
```

### 2.4 `order/get` 响应（结果回查）
`{code, msg, msgEn, data:[{ sampleId, resultTime, itemList:[{ testingNo, name, value, unit, errorMsg }] }]}`

### 2.5 ⚠️ 成功判定陷阱
同时满足才算成功：`IsSuccess==true` **且** `code=="200"` **且** `msg=="SUCCESS"`。
> 实际日志中 `code` 是**数字** `200`，若反序列化为 `int`，与字符串 `"200"` 比较会失败——需统一类型或兼容两种格式。

### 2.6 定时任务轮询
`BGAJob` / `OSMOJob` / `VicellJob` / `CedexBioJob`（默认开关 `Y`，间隔 `30s`）+ `AsyncResultTime=700`，配合 `order/get` 拉结果回填。

## 3. Inno 反应器在线参数接口（HTTP/REST, IoT 平台）

- **Base URL**：`https://slms-nppwgq.wuxibiologics.com`
- **鉴权**：请求体内 `Request.Token` 传递（非标准 Authorization Header）

### 3.1 接口
| 接口 | Path | 说明 |
|------|------|------|
| 通用在线参数 | `POST /api/inno-app/capture-data` | 反应器在线参数 |
| STR 在线参数 | `POST /api/inno-app/capture-data-str` | 同通用，但 `MFC1HSTOT~6HSTOT`、`MFC1SP1TOT~6SP2TOT` 强制为 `null` |
| XDR 在线参数 | `POST /api/inno-app/capture-data-xdr` | 同通用 |
| G3Lab 在线参数 | `POST /api/inno-app/capture-data-g3lab` | 同通用 |

### 3.2 公共请求模型
- `ID`：请求 GUID（uuid）
- `Request`：`ApiVer`(如 `1.0.1`) + `Token`
- `Params`：`LabKey`(实验室标识) + `ReactorNo`(反应器编号) + `DetalvType`(int：`0`=Actual 实际值 / `1`=Set 设定值 / `2`=Mode 模式值)

### 3.3 公共响应
`{ ResultData: EnvReactorOnlineModel, ID, ResultCode, ResultMessage, CurrentPage, PagesCount, RecordsCount }`
- 成功 `ResultCode=200 / ResultMessage="Success"`；失败 `ResultCode=-1 / "ReactorNo not exist"`
- `EnvReactorOnlineModel` 字段：`PH`、`DO`、`Temp`、`Agitation`、`WorkingWeight`(内部 `/1000` 保留 2 位)、`Weight`、`Pressure`、`MFC1~6`/`MFC1SET~6SET`、`PUMP1~4`、`Scale1/2WorkingWeight`、`OxygenFlowRate`、`CO2FlowRate`、`Mode`、`*modeactual`/`*modeset` 等几十个过程参数。

## 4. 上游 INNOVEL 厂商 API（vendor reference）

三份 PDF 同属 INNOVEL 信息系统标准 API，是本地命名管道接口的"上游源"。

**公共约定（三份一致）**
- RESTful + JSON，**所有方法均为 POST**
- 按**实验室维度**认证：携带 `LabKey` + `LabSecret` 申请 Token（默认失效 30 分钟，失效前可刷新）
- 公共请求：`ID` + `Request`(ApiVer/Token) + `Params`
- 公共响应：`ID` / `ResultCode`(200 成功) / `ResultMessage`(Success) / `ResultData` + 分页字段
- 公共错误码：`200` 成功；`100001/100002/100003` Access Token 过期/失效/非法；`400/401/403/404/429/500/503`；`-2000` 参数无效；`-5001` LabKey 不存在

| 文档 | 页数/版本 | 核心接口 |
|------|-----------|----------|
| `NPP API接口文档20240305.pdf` | 43 页 / V1.0.1 | 基础服务：`get-token` / `refresh-token`；反应器/控制器 API（FX001~FX032）；查询 OSMO/Cedex **历史检测结果**；检测目录（BGA/Vicell/OSMO/Cedex） |
| `IV-NPP-自动检测接口文档_V1.0.2.pdf` | 39 页 / V1.0.2 | 查询样本 ID、查询温度、**下发+查询** BGA / OSMO / CEDEX 检测 |
| `(CCPD)IV-CDP-16 Innovel-IoT API接口文档.pdf` | 127 页 / V1.0.7 | IV-CDP-16（CCPD）IoT API；含 `BatchNo`、项目编号；`4.1~4.17` 系列接口（2022-03 调整） |

## 5. LDMS IoT 平台设备数据接口（HTTP/REST）

- **地址**：`POST /messageService/api/getDeviceData` 与 `/getDeviceListData`
- **PROD**：`https://ldmsapi.wuxibiologics.com:8082`；UAT：`https://10.248.5.144:8082`
- **Headers**：`appId`（当前不校验）

### 5.1 两个接口
| 接口 | 地址 | 说明 |
|------|------|------|
| 实验室设备数据接口 | `/messageService/api/getDeviceData` | 单设备实验数据 |
| 批量实验室设备数据接口 | `/messageService/api/getDeviceListData` | 多设备（`devIdList=a&devIdList=b`） |

### 5.2 参数
`devId`(设备编号,必填) · `lotNo`(批号,选填) · `mTimeBegin`/`mTimeEnd`(**UNIX 时间戳秒,必填,间隔 ≤ 7 天**) · `wbp`(项目号) · `operator` · `viewName` · `filterLatestStatus`(1=只取最新且非删除/非终态) · `fieldLike`(SQL Like 过滤 map)

### 5.3 响应
`{ value: { respondCode:200, responseContent:{ baseDeviceData:{devId,devModel}, data:[...] }, dataType:1 } }`
- 返回按时间**倒序，最多 100 条**。

## 6. 身份认证：AAD（SAML 2.0）+ 本地登录

- **两种登录**：① 域账号 AAD/SAML（默认）② 本地账号 `api/auth/login`
- **AAD 流程（SAML 2.0，后端用 `AspNetSaml` 组件）**：
  1. 前端 `loginController.aad()` → `GET api/auth/aad-url` → 后端返回 Azure AD SAML 登录 URL
  2. 浏览器跳转 Azure AD（`ida:Authority` = `https://login.microsoftonline.com/{tenantId}/saml2`）→ 用户输入域账号/MFA
  3. Azure AD `POST SAMLResponse` → `api/auth/callbacksaml`（`RedirectUri` ACS）
  4. 后端 `ADDCallback()` 用证书 `wxlogicscer` 校验签名、提取 **Email**
  5. Email 匹配本地 `Auth_User` 表 → 生成**本系统 JWT** → 302 到 `WebIndex?code={加密email}`
  6. 前端 `/loading?code=xxx` → `GET api/auth/user-login?code=xxx` → 写入 `localStorage`（loginUser / authorizationData / ModuleSetting）

### ⚠️ 配置坑
`AuthController` 读取的是 `ida:RedirectUri`，但 `Web.config` 当前写的是 `RedirectUri`（无 `ida:` 前缀）——若 `redirectUri` 为空，`AssertionConsumerServiceURL` 可能不正确，建议统一 Key 名。

## 7. 跨接口关键注意事项（踩坑汇总）

1. **Windows 命名管道会话隔离（最核心）**：管道是本机会话命名空间，`\\.\pipe\X` 跨 Windows 会话/跨进程不可达。本地联调必须**主应用与 mock/子系统同机同 Windows 会话**，否则发送侧通、结果回执卡"检测中"。
2. **`code` 类型兼容**：SDMS `order/set`/`order/get` 返回的 `code` 在日志中是数字 `200`，代码常按字符串 `"200"` 比较——联调前统一反序列化类型。
3. **Token 生命周期**：SDMS `appToken` 有效期约 120s（由 `TokenJob` 刷新）；INNOVEL Token 默认 30 分钟、按实验室维度、失效前需 `refresh-token`。
4. **JSON 命名不一致**：SDMS `serialNumber`/`privateKey`/`sampleId` 为小驼峰，`DeviceModel`/`DeviceNo`/`Temp` 为 PascalCase——以实际抓包为准。
5. **管道名大小写**：OSMO 子系统同时存在 `OsmoSixPipe` 与 `OSMOSixPipe`（大小写不一致），对接时注意来源。
6. **全局任务状态码** `0/1/3/5/7/99` 在命名管道 `result`、SDMS `order/get`、各子系统间通用，回写检测记录状态时应统一映射。
7. **INNOVEL 与本地接口同构**：本地 5 个命名管道子系统 ≈ INNOVEL NPP/IV-NPP/CCPD 的本地客户端实现；上游文档中的 `LabKey`/`ResultCode`/`ResultData` 概念可直接映射到本地响应模型。
