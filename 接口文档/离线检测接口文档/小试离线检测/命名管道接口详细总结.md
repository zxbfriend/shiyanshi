## 一、通信协议总览

### 1.1 管道地址（Pipe Name）

| 子系统 | 服务类 | Pipe 名称 | WebAPI 默认 IP | 实际 IP 来源 |
|--------|--------|-----------|----------------|--------------|
| BGA 血气分析 | `BGAService` | `BGAService` | 192.168.1.145 | 参数 ip 或设备 SubSystemIP |
| Cedex 设备配置 | `CedexService` | `CedexPipe` | — | 设备 SubSystemIP |
| Cedex 订单 | `CedexOrderService` | `CedexOrderPipe` / `CedexOrderPipeTwo` | 192.168.1.226 | 设备 DeviceIP，按设备号切换 |
| OSMO 6060 | `OsmoSixService` | `OsmoSixPipe` / `OSMOSixPipe` | 192.168.1.227 | 设备 SubSystemIP（**大小写不一致**） |
| OSMO（非 Six） | — | `OSMOPipe` | 192.168.1.1 | 设备 SubSystemIP |
| ViCell XR | `ViCellService` | `VicellPipe` | 192.168.1.145 | 设备 SubSystemIP |

客户端使用 **Windows Named Pipe**，管道名即上表 Pipe 名称（本地连接，写 `\\.\pipe\X`）。

### 1.2 请求报文格式

```
{command}|{payload}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| command | string | 命令名，与各 Service `AddProcessor` 注册名一致 |
| payload | string | 业务参数；无参数时传空字符串，但**必须保留分隔符 `|`**（即 `command|`） |

> 若请求不符合 `command|payload` 两段格式，返回 `SubsystemParamsError`。

### 1.3 响应报文格式

```
{CommandName}|{ErrorCode}|{ResultDataJSON}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| CommandName | string | 回显请求命令名 |
| ErrorCode | long（十六进制字符串） | 由 `ErrorCodeLevel` + `ErrorType` + `SubsystemErrorNumber` 拼接后转 16 进制 |
| ResultDataJSON | string | 成功或失败时的附加数据 JSON；无数据时为空字符串 |

**ErrorCode 组成：**

| 组成部分 | 格式 | 说明 |
|----------|------|------|
| ErrorCodeLevel | 2 位十六进制 | `SuccessLevel`=成功；`ErrorLevel`=失败 |
| ErrorType | 2 位十六进制 | 通常 `SubsystemErrorType` |
| SubsystemErrorNumber | 4 位十六进制 | 具体业务错误码枚举值 |
| 后缀 | `00000000` | 固定填充 |

### 1.4 公共响应对象 `NamePipeResult`

| 属性 | 类型 | 说明 |
|------|------|------|
| CommandName | string | 命令名称（响应时回显） |
| ErrorLevel | ErrorCodeLevel | 错误级别（只读） |
| _errorCodeLevel / _errorType / _subsystemErrorNumber | 对应枚举 | 各级错误信息 |
| _resultData | object | 附加返回数据，序列化为 JSON 写入响应第三段 |

构造函数：`NamePipeResult(SubsystemErrorNumber, object resultData = null)` 根据 errorNumber 是否为 0 自动判定 Success/Error。

## 二、WebAPI 调用层（`PipeSend` 封装）

### 2.1 `PipeConnectionHelper.PipeSend` 参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `clientConnection` | ClientPipeConnection | 第一个参数=**服务命名（管道服务名）**，第二个参数=**服务所在 IP** |
| `method` | string | **管道名称/方法名**，子系统据此路由 |
| `data` | string | **入参**，JSON 序列化字符串；无参时传 `""` |

源码逻辑：连接 → `Write($"{method}|{data}")` → 读取 → `ConvertBaseResponse` → 关闭；异常时 `ResultCode = -1`、`ResultMessageCode = SE500145`。

### 2.2 `BaseResponse<string>` 通用返回字段

| 字段 | 类型 | 说明 |
|------|------|------|
| IsSuccess | bool | 通信是否成功（业务失败时也可能为 true） |
| ResultCode | int | **1=成功，0=业务失败，-1=异常/连接失败** |
| ResultMessageCode | string | 成功=`0x0000000000000000`；失败=16 位 hex 错误码 |
| ResultMessage | string | 可读消息（部分接口填充） |
| Data | string | 业务数据，JSON 字符串，**需二次反序列化** |

**状态码转换规则（ConvertBaseResponse）：**

| 管道返回状态码 | ResultCode | ResultMessageCode |
|---------------|-----------|-------------------|
| `"0"` | 1 | `0x0000000000000000` |
| 非 `"0"` 数字 | 0 | `0x{16位hex}` |
| 解析/连接异常 | -1 | `SE500145` |

### 2.3 调用总量

共 **27 处有效 `PipeSend` 调用**，覆盖 **22 种唯一管道方法**。已废弃/改用 HTTP 的有 4 处（CedexBio 相关，改为 `cedex_bio_url` HTTP API）。

### 2.4 关键命名不一致（务必对照代码）

| 问题 | 详情 |
|------|------|
| `OsmoSixPipe` vs `OSMOSixPipe` | `saveDevice`/`order`/`cancel`/`queryPortName` 用 `OsmoSixPipe`；`del_order` 用 `OSMOSixPipe` |
| `save_subsysytem_setting` | ViCell 管道名拼写为 **ytem**（代码原始拼写，非 subsystem） |
| `CedexOrderPipe` vs `CedexOrderPipeTwo` | 按 `SubSystemDeviceNo` 切换：`FXCCPD-CDX-002`→CedexOrderPipe，`FXCCPD-CDX-003`→CedexOrderPipeTwo；IP 均为 DeviceIP |
| `CedexPipe`（配置）vs `CedexOrderPipe`（订单） | 两个不同 Pipe，配置合并计划见第四节 |

## 三、五大子系统逐命令详解

### 3.1 BGA 子系统（Pipe: `BGAService`）

| 命令 | 入参 payload | 出参 | 功能 |
|------|--------------|------|------|
| `log_in_check` | 无 | 无/错误码 | 登录前可用性检查（校准、测样间隔等） |
| `log_in` | `RequestOrderModel` JSON | 无 | Core 自动下单（Mode=3） |
| `sendOrder` | `RequestOrderModel` JSON | 无 | UI 手动下单 |
| `cancel` | 无 | 无 | 取消当前待处理订单（Status 1→99） |
| `cancel_sample` | sampleId 字符串 | 无 | 按 SampleID 取消样品 |
| `result` | 无 | int 状态码 | 查询最近一次检测任务状态 |
| `refreshResult` | `"{sampleId}"`（JSON 字符串） | 无 | 刷新指定样品检测结果 |
| `queryPortName` | 无 | `List<string>` | 查询可用 COM 口 |
| `saveDevice` | `TestingBGADevice` JSON | 无/SubSystemIP | 保存/更新 BGA 串口配置 |

**核心数据模型：**
- `RequestOrderModel`：SampleID(必填)、TEMP(默认33℃)、Position、BGADeviceID、BatchID、BatchOPID、Mode(log_in 强制3)、Status 等。
- `TestingBGADevice`：BGADeviceID、SubSystemMAC/IP/DeviceNo/DeviceModel、TestingEquipmentID、SerialPortName/BaudRate/DataBits/StopBits/Parity/FlowType 等。

**常见失败错误码（log_in_check）：** BGANotRunning、BGADeviceException、BGAOtherSampleTesting、BGATwoPointCheckDoing/Missing、BGAOnePointCheckMissing/Doing、BGAFiveMintusTip、BGASampleSended、BGAJsonException、BGASubSystemError。

> 实测：BGA `sendOrder` 正常，`result` 出参 `data:7` 表示已完成；`saveDevice` 实测报 **53**（接口报错，需自行配置）；`logIn` 调度用、前端用不了。

### 3.2 Cedex 设备配置子系统（Pipe: `CedexPipe`）

| 命令 | 入参 | 出参 | 功能 |
|------|------|------|------|
| `get_port_names` | 无 | `List<string>` | 获取可用串口列表 |
| `save_subsystem_device` | `CedexPortModel` JSON | 无/SubSystemIP | 保存/更新 Cedex 设备配置 |

- `CedexPortModel`：CedexDeviceID、SubSystemIP、DeviceIP、SubSystemMAC、SubSystemDeviceNo、TestingEquipmentID、SerialPort* 等。
- 失败码：CedexSubSystemDeviceRepeat、CedexSubSystemDeviceMacAddressRepeat、CedexSubSystemComportError、CedexSubSystemError。

### 3.3 Cedex 订单子系统（Pipe: `CedexOrderPipe` / `CedexOrderPipeTwo`）

| 命令 | 入参 | 出参 | 功能 |
|------|------|------|------|
| `log_in_check` | 无 | 无 | 检查 Cedex 运行中且未在处理订单（**调度系统用，我方不调**） |
| `log_in` | `List<CoreTestingModel>` JSON | 无 | Core 自动下单（调度用） |
| `send_orders` | `List<TestingOrder>` JSON | 无 | **UI 手动批量下单（主用）** |
| `result` | rack 字符串 | int | 查询指定 Rack 最近任务状态（调度用） |
| `empty_racks` | 无 | 逗号分隔 Rack 字母 | 查询空闲 Rack（暂调不了） |

- `CoreTestingModel`：SampleID(必)、RackNo(J/K/L/M/N)、TubeNo、BatchId、BatchOPId、Code。
- `TestingOrder`：DeviceId、SampleID、BatchID、BatchOPID、RackPostionNo(枚举)、TubePostionNo、SampleRemake、ManualDilutionFactor、UpdateBy、testingOrderItems。
- `TestingOrderItem`：TestingNo、SpecticFactor(默认1)。

> 实测：RackPostionNo 含义 `1=I, 2=J, ...`；`sendOrders` 的 `TestingNo` 是检测项编号（如 "938"/"933"）。Cedex 先调 `10.248.150.25`，再由它下发到机器，**链路慢、需等待**。`getPortNames` 实测返回 COM8/COM6/COM1/COM2/COM3/COM4。

### 3.4 OSMO 6060 子系统（Pipe: `OsmoSixPipe` / `OSMOSixPipe`）

| 命令 | 入参 | 出参 | 功能 |
|------|------|------|------|
| `log_in_check` | 无 | 无 | 登录前检查（调度用） |
| `log_in` | `List<OsmoPROResult>` JSON | 无 | Core 自动登录（Mode=3） |
| `order` | `List<OsmoPROResult>` JSON | 无 | **UI 手动下单并启动检测（主用）** |
| `cancel` | 无 | 无 | 取消当前任务 |
| `start` | 无 | 无 | 启动检测（DB 状态更新） |
| `result` | 无 | int | 查询最近任务状态 |
| `del_order` | sampleID 字符串 | 无 | 删除指定样品订单 |
| `queryPortName` | 无 | `List<string>` | 查询可用串口 |
| `saveDevice` | `OSMODevice` JSON | 无/SubSystemIP | 保存设备配置 |

- `OsmoPROResult`：**字段名 `TestingOSMOOrderID`**（注意不是 OSMOOrderID）、OSMODeviceID(必)、SampleID(必)、PositionNo(必)、Mode、ItemID 等。
- `OSMODevice`：OSMODeviceID、SubSystemDeviceNo/MAC/IP、TestingEquipmentID、OSMOIP、OSMOPort、OSMOType(固定3)、SerialPort*。

> 实测：OsmoSixPipe 在 `10.248.150.25`，下发只需传 7 个字段（TestingOSMOOrderID/OSMODeviceID/IsDelete/SampleID/PositionNo/Status/Created_by/Mode/DeviceNo）。**OSMOPipe（非 Six，`10.248.161.125`）参数名同样为 `TestingOSMOOrderID`**，已踩坑。

### 3.5 ViCell XR 子系统（Pipe: `VicellPipe`）

| 命令 | 入参 | 出参 | 功能 |
|------|------|------|------|
| `save_subsysytem_setting` | `ViCellDevice` JSON | int(1) | 保存设备配置（上线时测） |
| `log_in_check` | 无 | ResutData | 登录前检查（调度用，永不调） |
| `log_in` | `List<SampleInfo>` JSON | 无 | 自动登录（调度用，永不调） |
| `log_in_manual` | `List<SampleInfo>` JSON | 无/List\<int\> | **手动送检（主用）** |
| `clear` | deviceId 字符串 | 无 | 清空未完成订单 |
| `cancel` | 无 | 无 | 取消当前检测任务 |
| `result` | 无 | int | 查询最近任务状态（调度用，永不调） |
| `refresh` | `SampleInfo` JSON | 无 | 刷新单个样品（覆盖 unknown→正式 SampleID） |
| `del_order` | sampleID 字符串 | 无 | 删除订单 |
| `reset` | 无 | 无 | 重置队列（调度用，永不调） |

- `SampleInfo`：PositionNo(1~12,必)、SampleID(必)、CellType(必)、DilutionFactor(>0,必)、Mode、BatchID/BatchOPID、VCD/Viability/AvgDiam、ExcelFileLocation 等。
- `ViCellDevice`：VicellDeviceID、TestingEquipmentID、SubSystemMAC/IP、ExcelPath(目录必须存在)、WasteUpperLimit、CurrentWasteCount、EquipmentModel。
- `ResutData`：dataType（SampleID/DeviceIP/InitialTime）、message。

> 实测（10.248.150.50）：
> - **主用 `logInManual`**（测 4/6/8/9/10；永不调用 2/3/5/7）。
> - `refresh` 场景：软件异常时 SampleID 变 `Unknow00x`，用其他检测 SampleID 把 unknown 数据覆盖过去（`UnknowSampleId`→`SampleID`）。
> - `clear` 传 deviceId、`delOrder` 传 SampleID、`cancel` 取消全部队列。

## 四、实测记录与实战经验（来自 `NamedPipe接口测试结果/`）

### 4.1 哪些接口"永不调用 / 调度用"

| 子系统 | 永不调用（给客户调度系统用） | 我方主用 |
|--------|------------------------------|----------|
| BGA | `logIn`（调度用，前端用不了） | `sendOrder`、`result`、`refreshResult`、`cancel`/`cancel_sample` |
| Cedex 订单 | `logInCheck`、`logIn`、`result`、`emptyRacks` | `sendOrders` |
| OSMO | `start`、`logInCheck`、`logIn`、`result` | `order`、`delOrder`、`cancel` |
| ViCell | `result`、`reset`、`logIn`、`logInCheck` | `logInManual`、`refresh`、`clear`、`delOrder`、`cancel` |

### 4.2 关键实战结论

1. **`logInCheck` 调用策略**：周卿建议——初始化页面调用一次看设备通不通即可，**下发无需每次调用 logInCheck**（非每次发送必需）。
2. **Cedex 链路慢**：先调 `10.248.150.25`，再由它下发到机器，测试需等待很长时间。
3. **CedexPipe 合并计划**：药明后续要把 `CedexPipe`（配置）合并进 `CedexOrderPipe` / `CedexOrderPipeTwo`（订单），Pipe 名称不变。
4. **OSMO 参数名坑**：OsmoSixPipe 与 OSMOPipe 的下发实体字段名均为 **`TestingOSMOOrderID`**（`OSMO测试参数记录.txt` 明确标注）。
5. **BGA `saveDevice` 报错**：实测返回 **53**，接口报错需自行配置（暂未跑通）。
6. **`delOrder` 语义**：OSMO 的 `delOrder` 删除的是机器左侧数据，与系统右侧数据无关。
7. **Cedex `emptyRacks` 暂调不了**；Cedex `/detect/cedex` 页面后端在 `namedPipeClient.send` 前曾全写假数据（早期联调阶段）。

### 4.3 命名管道会话隔离（重要环境约束）

- 小试设备走 `\\.\pipe\X`，**发送侧（写管道→生成"检测中"）已实测全通**；
- **结果回执读管道受 Windows 会话命名空间隔离阻断**——后台进程创建的管道与验证进程不在同一 Windows 会话时 `\\.\pipe\X` 不可达（报 `last_err=3`）；
- 闭环需在**同机同 Windows 会话**启动主应用 + mock 后复测。

## 五、关键踩坑与最佳实践

| 类别 | 坑点 | 规避/建议 |
|------|------|-----------|
| 报文格式 | 无参命令也必须写 `|`，否则 `SubsystemParamsError` | 统一 `method + "\|"`，空 payload 传 `""` |
| 成功判定 | 业务失败时 `IsSuccess` 仍可能为 true，须看 `ResultCode` | 成功判据：`IsSuccess && ResultCode == 1`（OSMO 个别用 `> 0`） |
| 错误码类型 | 管道回的 ErrorCode 是**字符串数字** `"0"`，非整型 | `ConvertBaseResponse` 已处理；自写解析勿用整型比较 |
| 大小写 | `OsmoSixPipe` vs `OSMOSixPipe` 混用 | `del_order` 必须用 `OSMOSixPipe` |
| 拼写 | `save_subsysytem_setting`（ytem） | 照抄原拼写，不要"纠正" |
| 设备选择 | `CedexOrderPipeTwo` 按 `SubSystemDeviceNo` 切 | FXCCPD-CDX-003 走 Two，其余默认 |
| 参数名 | OSMO 字段 `TestingOSMOOrderID`（不是 OSMOOrderID） | 严格照实体类 |
| Rack 映射 | `RackPostionNo` `1=I,2=J,...` | 与协议文档字母枚举区分清楚 |
| 会话隔离 | 跨 Windows 会话管道不可达 | 主应用与验证同机同会话 |
| `logInCheck` | 非每次发送必需 | 仅初始化页面探活一次 |
| `Data` 反序列化 | 多为 JSON 字符串需二次解析 | `JsonConvert.DeserializeObject` 对应类型 |
