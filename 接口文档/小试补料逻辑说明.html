补料逻辑说明

本文按当前代码说明五套程序怎么配合完成一次补料：地秤服务、OPC 服务、补料调度、补料监控、服务控制。调度负责开泵、读重量、改速度、写任务；监控负责在调度卡住或补多了的时候把泵速打成 0。两边都写同一套 MySQL 库，不互相调用。

总关系

五套程序里，只有调度和监控连数据库。地秤和 OPC 只提供 HTTP 接口，数据放在本机内存。服务控制不参与补料计算，只告诉监控“这台调度盒子还活着”。

调度和监控看的是同一批表：CDP_Batch_FixedFeedingTask、CDP_FixedFeedingTask_ExecDetail、CDP_Batch、CDP_OperateUnit_Events。调度往执行明细里插入行；监控只读最新一行的 Exenumber 和 CheckTime。

1. 地秤 SmallScaleService1

这是补料地秤上位机。程序集名 FeedSubSystems1。它打开串口或解析秤的报文，把重量放进本机缓存，再通过 WCF REST 给出去。调度来取重量时打的就是这个服务。

对外接口

方法路径返回
GETmessageService/api/getScaleData当前缓存重量。有数 RespondCode=200，缓存空 300，异常 400
GETmessageService/api/getScaleDataList缓存里的重量列表，字段 GatherTime、Weight、WeightUnit
POSTmessageService/api/getDeviceData给调度 LDMS 侧读设备数据，调度配置项 ldms_api_get_device_data

缓存键来自本程序 App.config 的 CacheKey。串口读到一帧就解析出重量、单位和时间，写入 LocalCachedProvider。HTTP 请求不直接读串口。缓存空时调度会把这次读数当成失败并累计错误次数。

地秤服务自己不写补料任务表。哪台秤对应哪口、型号是几，记在库表 CDP_EqumentScale，由调度去查：IP、Port、Model、ScalePrecision。调度里 Model=5 表示串口秤，走 getScaleData。

2. OPC 控制 SmallOPCDAService

这台程序连 DeltaV 的 OPC DA 服务器，做两件事：按罐循环读点，把结果放在内存；收到写泵速请求时再连一次 OPC 把设定值写下去。

读

外部或界面调用高低频采集后，程序按配置找到罐的 IP 和 OPC 服务名（OPC.DeltaV.1），建订阅，按周期 Read。高频点进 _bioHighRead，低频点进 _bioLowRead。读到的泵、泵设定、重量等字段包括 pump1 到 pump4、pump1set 到 pump4set、workingWeight，以及 pH、温度、溶氧等。

每读完一轮会查库，决定要不要停采集。SQL 是：批次 CDP_Batch.Status < 11、IsDelete=0，位置组合 CDP_Location_Combinations.Status=1 且未删除，设备 CDP_LabDevice.LabDeviceNo 在本服务配置的罐列表里。查不到这台罐，日志写 is finish Cultrue，高低频线程退出，之后 getSchdulerDeviceData 对该罐返回 ResultCode=300（缓存里没有这台）。

给调度和监控的接口

方法路径用途

写泵速时，按罐配置把 SetName 换成 OPC 点名（例如 FX093P1402/PID1/SP.CV），每次写都会重新枚举 OPC 服务器并 CoCreateInstanceEx。写完等约 1.6 秒再读回，最多对三次。设定为 0 时，读回也是 0 才返回 Code=200。RPC 不可用时写失败，调度和监控都会看到失败。

OPC 服务不插入补料执行明细。它用到的库表只有培养是否还在进行：CDP_Batch、CDP_Location_Combinations、CDP_LabDevice。

3. 补料调度 SmallSchdulerService

调度是补料的主程序。主循环按 coreservice_interval_time（秒）扫一批“可以补”的批次，满足条件就拉起该任务的补料线程。补料线程里读 OPC、读地秤、算速度、下发、写明细，直到完成、超量、堵塞或通讯失败。

3.1 哪些批次会进循环

GetBatchList 的条件：

  • CDP_Batch.Status 大于等于 9 且小于 11（收获前、生产未完成）
  • CDP_Batch.ErrorCode 为空或 0
  • 经 Auth_Culture 找到反应器 CDP_LabDevice
  • 同一 LabCabinID 上还有一台 LabDeviceType=5 且未删除的设备，它的 ScaleId 当作补料地秤 EquFeedingScaleId

取出的字段：BatchID、EquReactorId、EquFeedingScaleId、CurrentVolume、InoculationTime、MediumVolume、CellsVolume、CurrentGlucoseWeight、CultureCode。

同一轮里如果这台秤 CDP_EqumentScale.DeviceStatus 表示忙，或 LastUsed_DeviceId 不是本罐且 LastUsed_Time 仍在 Scale_Lock_Time 秒内，本批次跳过。秤上已有未处理 ErrorCode 也跳过。

3.2 哪些任务会真正开补

任务表 CDP_Batch_FixedFeedingTask，条件：

  • FeedingTime <= 现在，Mode=1
  • Status 为 5（待执行）或 2（待取消）
  • 批次 ErrorCode 为空或 0
  • 当天 Cedex 结果要能用：没有结果、多条未指定、一条未指定，非葡萄糖类型任务会等待（日志里的 cedex 错误）
  • 批次上还有未结束任务（状态 7、5、9 且补料时间在今天）则本批次先不往下

状态含义：1 待审，2 待取消，3 待批准，5 待执行，7 执行中，9 执行异常，11 异常已处理，17 跳过，19 已执行，99 取消。

开跑前还要补上泵的最大速度。最大速度不在任务表上，而在地秤侧泵位：

  • CDP_LabDeviceSub.MaxSpeed、LabDeviceSubNo（要和任务 FeedingPumpNo 字符串相等，4 对不上 04）
  • CDP_Item_Serials：本批次、ItemStatus<28 的袋子，ItemID、Quantity
  • CDP_Location_Controls.ControlType=3 且未删除，连到 CDP_Item_Def.GlucoseConc

MaxSpeed 对不上或为 0，本批次本轮停止，日志 MaxSpeed Not Set，任务状态不变，下一轮还会再报。FeedingTime 仍晚于现在则等待。同一批次已有线程在跑则不再启动。

3.3 计划补料量

FeedingType=3 时计划量就是任务上的 FeedingVolume。其他类型：

(MediumVolume + CellsVolume) × FeedingVolumePercent / 100 / 1000

葡萄糖规则类型还会按当前糖浓度和 FeedingTo、LowerLimit 另算一版 RealFeedVolume，并回写任务上的补料量。

3.4 开补时读写的外部数据

先读 OPC。opcda_reactors 列表里的罐走 getSchdulerDeviceData。连续失败达到 error_count_limit，任务记 1013（补料阶段 DeltaV 通讯异常），并尝试把该泵写成 0。读成功后取罐重 workingWeight 和对应泵的当前速度 pump1…pump4。

再读地秤。CDP_EqumentScale 的 IP、Port、Model、ScalePrecision（秤上没填精度就用配置 scale_precision）。Model=5 调地秤服务 getScaleData。读失败或重量小于等于 0，记 1024（自检地秤通讯异常），任务结束，不往下发泵速。地秤读数连续 feeding_scale_freeze_seconds 秒不变，记 1036。

秤被占用时更新 CDP_EqumentScale.DeviceStatus=1、LastUsed_Time、LastUsed_DeviceId，批次 CDP_Batch.IsFeeding=0 表示秤锁占用中的写法以代码为准：开始补料时把秤 DeviceStatus 置 1，结束或异常时置 2，并把批次 IsFeeding 置回。

3.5 泵速怎么算、怎么发

先取 min(任务 PumpSpeed, 泵 MaxSpeed)，再和 计划量 × 70% 取更小，这是启动速度。降速档默认是 计划量 × 15%，再和启动速度取更小。然后乘配置 Speed_Val（单位换算，默认 1），通过 OPC pumpSpeedSet 发出去。泵号 1 到 4 对应 pump1set 到 pump4set。

若罐号在 feed_speed_ignore_volume_cap_reactors 里：

  • 启动速度低于 feed_speed_volume_cap_floor 时抬到该保底。泵 MaxSpeed 已配置且比保底还小，则不超过 MaxSpeed。
  • 降速档改用 feed_slow_set_speed，不再用计划量的 15%。同样不超过 MaxSpeed，也不高于已经保底后的启动速度。

不在名单里的罐仍用 70% 和 15%。每次下发无论成败都插入 CDP_FixedFeedingTask_SpeedSet：TaskID、TaskNo、SetTime、PumpNo、Step、Speed、IsSuccess、DBTime（库的 now()）。

下发成功后任务改为状态 7，写 StartTime、CurrentVolumeBefore、GlucoseWeightBefore。

3.6 补料过程中写什么

循环里反复读地秤，已补量 = 开补时秤重量 − 当前秤重量。每次采样插入 CDP_FixedFeedingTask_ExecDetail：

字段含义
TaskID / TaskNo对应 BatchTaskID、任务号
CheckTime调度这台电脑的 DateTime.Now，不是数据库时间
DBTime插入时数据库 now()
Exenumber已补量
ExecTime从本段开始起的秒数
Step当前步骤，如加速、恒速
CurrentSpeed / SetSpeed读回的泵速、本段设定
ReactorWeight / FeedingScaleWeight罐重、地秤重量
IsFeeding是否仍在补

过程中的判断用表 CDP_FeedingConfig（IsDelete=0 的第一条）：IntervalTime、JamCoefficient、JamIntervalCoefficient、DitherCoefficient、DitherIntervalCoefficient、RebateCoefficient、RebateIntervalCoefficient。堵塞：一段时间内已补增量 < 设定速度/60 × 秒数 × JamCoefficient，记 1031。地秤短时间猛增，记 1032。这些系数是全局的，不按罐分开。

补完：任务状态 19，写 EndTime、ReactorWeightFeedingAfter。回写 CDP_Batch.CurrentVolume、CurrentGlucoseWeight（代码里按 ×1000 存），CDP_Item_Serials.Quantity 扣袋子余量。异常：任务状态 9，CDP_Batch.ErrorCode 写成该错误码，IsFeeding=0，秤 ErrorCode 同样写上，并插入 CDP_OperateUnit_Events（LabId=2，OperateType 8 或 10，ErrorCode，EventMessage）。

4. 补料监控 FeedingMonitor

监控不负责开补，也不读地秤。它盯着库里“正在补”的任务，发现明细停更或补多了，就向 OPC 发 0 泵速，并把任务打成异常。另一条线盯服务控制的健康检查，调度盒子不健康时也对相关罐停泵。

4.1 两条循环

循环间隔做什么
超标 / 停滞feedingMonitorRateValue 秒，默认随 rateValue查状态 7 和 9 的今日任务，逐个看执行明细
健康每台 serviceControlHealthIntervalSeconds 秒，默认 3请求 {baseUrl}/controlService/api/healthcheck。失败则按该 URL 映射的设备停泵

在补任务 SQL：CDP_Batch_FixedFeedingTask.Status IN (7,9)，FeedingTime 从今天 0 点起，IsDelete=0，连 CDP_Batch、CDP_Location_Combinations、CDP_LabDevice，取出 BatchTaskID、BatchID、LabDeviceNo、FeedingPumpNo、FeedingVolume、Status、PumpSpeed。数据库查询失败时用上一轮缓存，缓存超过 cacheMaxAgeMinutes 仍会用来停泵，并打警告。

4.2 停滞停泵

读 CDP_FixedFeedingTask_ExecDetail 中该 TaskID 按 DBTime 最新的一行，取 Exenumber 和 TIMESTAMPDIFF(SECOND, CheckTime, NOW())。

  • 没有明细：认为还没开始写，不停泵。
  • Exenumber <= 0：还没开补，不做停滞判断，仍做超标判断。
  • Exenumber > 0 且滞后秒数 > execDetailStallSeconds：立刻对该泵下发 0。滞后用的是数据库 NOW() 和调度写入的 CheckTime。调度电脑和数据库差几分钟时，会误停或该停不停。监控自己的电脑时钟不参与这个比较。

4.3 超标停泵

阈值 = FeedingVolume × (1 + overFeedingExcessRatio)。已补量 Exenumber 大于该阈值则停泵。配置 0.02 表示允许超过计划量 2%。

4.4 停泵之后写库

0 泵速发到监控配置的 opcda_url + opcdaReadService/api/pumpSpeedSet。只有返回码 200 才算停泵成功。成功后：

  • 状态仍为 7 的任务：CDP_Batch_FixedFeedingTask.Status=9，CDP_Batch.IsFeeding=0
  • 插入 CDP_OperateUnit_Events，ErrorCode 固定 2097，EventMessage 为罐号加原因（明细停滞、超标、健康检查失败等），LabId 来自 operateUnitEventLabId

停泵失败不把任务放进“已处置”，下一轮再试。成功后同一 BatchTaskID 本进程内不再重复停。

健康检查为 false，或调用异常：按 ServiceControlHealthList 里该 URL 对应的罐号，对状态 7 和 9 的在补任务停泵。监控循环自己连续异常达到 loopErrorCountLimit，对缓存中的在补任务紧急停泵。

5. 服务控制 ServiceControl

服务控制跑在调度那台电脑上，给监控一个健康结果。它不读补料表，也不下发泵速。

方法路径作用
GETcontrolService/api/healthcheck监控实际使用的接口
GETcontrolService/api/getservicestatus查某个 Windows 服务状态
GETcontrolService/api/getbatchservicestatus批量查服务状态
GETcontrolService/api/stopservice、resumeservice停、恢复 Windows 服务。补料监控的健康循环不调用这两条

healthcheck 做两步：GET 本机调度的 schedulerAlivePath（默认 version），JSON 里 Database 非空算调度通；再按 pingIp、pingTimeoutMs 做 ICMP Ping。两步都成功 IsSuccess=true。任一步失败，监控会按该 URL 映射的设备列表去停泵。

映射写在监控的 ServiceControlHealthList，格式 http://主机:端口^罐号,罐号;下一台...。健康失败时只停这一串罐号里、状态为 7 或 9 的任务，不是全厂所有泵。

一次补料按时间怎么走

  1. OPC 服务已在采这台罐（库里批次未结束）。地秤服务串口缓存里已有重量。服务控制在调度电脑上能打开。
  2. 调度扫到批次状态 9 至 10、无错误码、秤空闲。任务状态 5，补料时间已到，泵 MaxSpeed 大于 0，袋子 ItemStatus<28。
  3. 调度读 OPC 在线数据，读地秤 getScaleData。自检通过后按第 3.5 节算出速度，pumpSpeedSet 写到 DeltaV。
  4. 任务改为 7。之后每个采样周期插入一行执行明细。CheckTime 用调度电脑时间，DBTime 用数据库时间。
  5. 监控每几秒看到状态 7。明细在刷新、已补量未过阈值，则不动作。
  6. 调度正常结束：任务 19，回写批次体积、糖重和袋子余量，秤释放。监控之后不再把该任务当在补任务。
  7. 调度中途不再写明细，且已补量大于 0：监控发现 CheckTime 相对数据库时间超过 execDetailStallSeconds，向 OPC 写 0，任务改为 9，事件码 2097。
  8. 服务控制健康失败：监控只停该 URL 名下正在补的泵，同样写 0 和事件。

用到的接口

下面只列补料这条链路上真正会打出去的 HTTP。主机和端口都在各自 App.config 或库表里，路径是代码写死的。仓库里的示例地址：调度 OPC http://192.168.128.124:8085，监控 OPC http://192.168.2.2:8085，调度自身 http://127.0.0.1:8082，服务控制 http://localhost:5297，界面通知 http://localhost:7017。地秤地址不在配置文件里，用 CDP_EqumentScale.IP 和 Port。

调度调用 OPC（SmallOPCDAService）

基址：调度配置 opcda_url，或任务上的 OPC IP、端口拼出来。超时 api_timeout 毫秒。

项目内容
地址GET {opcda_url}/opcdaReadService/api/getSchdulerDeviceData?deviceId={罐号}

调度调用地秤（SmallScaleService1）

基址：http://{CDP_EqumentScale.IP}:{Port}。Model=5 的串口秤走下面这一条，调度按 EmersonDataModel 解析，只用 RespondCode 和 Weight。

项目内容
地址GET http://{秤IP}:{秤端口}/messageService/api/getScaleData
入参无。
出参RespondCode、GatherTime、Weight、WeightUnit。200 为缓存里时间最新的一条。300 缓存空。400 异常。调度把 200 且 Weight 能转成大于 0 的数当成有效重量。

罐号同时在 mettler_reactors 里时，调度改打同一路径，但按另一套模型解析：IsSuccess、ResultCode、ResultMessage、Data.Time、Data.Weight、Data.WeightUnit。单位是 KG 时乘 1000。地秤服务实际返回的是上面的 RespondCode/Weight，和这套 IsSuccess/Data 不是同一形状，现场梅特勒名单要和秤程序返回对得上才读得到数。

调度调用界面通知

任务记错误时额外通知界面，失败只打日志，不改变已经写好的任务状态。

项目内容
地址GET {gui_api_url}/api/notification/send?code={错误码}&msg={说明}&batchId={批次}&pumpId={泵号}。仓库里 gui_api_url 是 http://localhost:7017。
入参Query 四个：code、msg、batchId、pumpId。
出参按 ResultCode 判断，小于 0 记一条发送失败日志。

基址是监控自己的 opcda_url，和调度可以不是同一台。只在要停泵时调用，速度固定写 0。

项目内容
地址POST http://{opcda_url}/opcdaReadService/api/pumpSpeedSet
入参ReactorNo=CDP_LabDevice.LabDeviceNo，SetName=pump{FeedingPumpNo}set（泵 1～4），Speed=0。

监控调用服务控制（ServiceControl）

每台电脑一条循环。地址来自监控 ServiceControlHealthList，格式 http://主机:端口^罐号,罐号。仓库示例：http://10.248.161.146:5297^FX221,...,FX228。间隔 serviceControlHealthIntervalSeconds，默认 3 秒。isCCPDFeedingMonitor 不是 Y 时整段循环空转。

项目内容
地址GET {baseUrl}/controlService/api/healthcheck。相对路径配置项 serviceControlHealthApi。
入参无。
出参IsSuccess、ResultMessage、ResultCode。两项都通时 IsSuccess=true、ResultCode=200、ResultMessage=OK。否则 ResultCode=500，ResultMessage 拼上失败原因，例如调度 Database 为空、调度心跳失败、Ping 失败、未配置 pingIp。
监控怎么认HTTP 能解析且 IsSuccess=true 算这台电脑健康。HTTP 失败，或 IsSuccess=false，对该 URL 名下、状态 7 或 9 的在补任务停泵。

服务控制调用调度（SmallSchdulerService）

健康检查内部再打本机调度。地址由服务控制配置拼出：http://{schedulerAliveHost}:{schedulerAlivePort}/{schedulerAlivePath}，默认 http://127.0.0.1:8082/version。超时 5 秒。另外对 pingIp 做 ICMP，超时 pingTimeoutMs，默认 3000 毫秒。Ping 不是 HTTP。

项目内容
地址GET http://127.0.0.1:8082/version
入参无。
出参Version 程序集版本，ReleaseTime 文件时间，DataBaseServer 连接串里的服务器，Database 库名。服务控制只看 Database 是否非空。

补料监控每一项怎么判

监控启动后并行两条循环，开关都是 isCCPDFeedingMonitor=Y。一条是超标和停滞，间隔 feedingMonitorRateValue 秒（仓库里 5）。一条是每台服务控制的健康检查。两条都不读地秤，也不读 OPC 的在线数据。停泵时才打 OPC。

监控项数据从哪来怎么判成立后做什么
有没有正在补的任务 数据库，不调接口。
表：CDP_Batch_FixedFeedingTask 连 CDP_Batch、CDP_Location_Combinations、CDP_LabDevice。
字段：Status、FeedingTime、IsDelete、BatchTaskID、BatchID、FeedingPumpNo、FeedingVolume、PumpSpeed、LabDeviceNo。		 FeedingTime 从今天 0 点起，Status 为 7 或 9，IsDelete=0，罐号不为空。查失败时用内存里上一轮结果；缓存超过 cacheMaxAgeMinutes（默认 60 分钟）仍用来停泵，并打警告。 查库失败：对缓存里的在补任务紧急停泵，原因「数据库连接失败」。查成功：交给下面两项。
执行明细停滞 数据库。
表：CDP_FixedFeedingTask_ExecDetail。
SQL：WHERE TaskID=BatchTaskID ORDER BY DBTime DESC LIMIT 1，取 Exenumber、CheckTime，以及 TIMESTAMPDIFF(SECOND, CheckTime, NOW())。		 没有行：还没开写，不停。Exenumber<=0：还没开补，不做停滞判断。Exenumber>0 且滞后秒数 > execDetailStallSeconds（仓库默认 3，现场配置可能是 8）：停滞。比较用的是数据库 NOW() 和调度写入的 CheckTime。 调 OPC pumpSpeedSet，速度 0。成功后任务 Status 从 7 改为 9，批次 IsFeeding=0，事件 ErrorCode=2097，说明「补料执行明细停滞」。同一 BatchTaskID 本进程内不再重复。失败下轮再试。
补料超标 同一条执行明细的 Exenumber，加上任务表 FeedingVolume。不调接口。 阈值 = FeedingVolume × (1 + overFeedingExcessRatio)。仓库比例 0.02，计划 10 则阈值为 10.2。已补量大于阈值就停。FeedingVolume 为空则跳过超标判断。没有明细行时不做这项。 同样向 OPC 写 0，事件说明「补料量超了 2% 以上」。写库规则和停滞相同。
调度盒子是否健康 接口，不是库。子系统是跑在调度电脑上的 ServiceControl。
地址：GET {ServiceControlHealthList 里的 baseUrl}/controlService/api/healthcheck。
入参无。出参看 IsSuccess、ResultMessage、ResultCode。		 服务控制内部再 GET http://127.0.0.1:8082/version，Database 非空，并且 Ping pingIp 成功，才返回 IsSuccess=true。监控侧：调用异常，或 IsSuccess=false，算不健康。恢复为 true 后清掉这台 URL 的“已处置”标记，下次再失败还会停。 只停该 URL 后面列出的罐，且任务状态为 7 或 9。停泵仍是 OPC pumpSpeedSet 速度 0。事件说明带健康检查失败原因。
监控循环自己连续异常 不查库、不调健康接口。看超标循环自己抛异常的次数，上限 loopErrorCountLimit，缺省跟 errorCountLimit。 连续异常达到上限。 对内存里上一轮在补任务紧急停泵，原因「监控循环连续异常」。OPC 地址和入参与上面停泵相同。
读执行明细失败 上面那条 CDP_FixedFeedingTask_ExecDetail 查询抛异常。 查询失败，不是“没有行”。 对全部缓存在补任务紧急停泵，原因「无法读取补料执行明细」，本轮不再继续看后面的泵。

停泵这一下的接口固定是 OPC 服务，不是地秤，也不是调度。监控配置示例：POST http://192.168.2.2:8085/opcdaReadService/api/pumpSpeedSet，Body {"ReactorNo":"FX218","SetName":"pump4set","Speed":0}，返回 {"Code":200} 才写库。写库是监控自己做的：CDP_Batch_FixedFeedingTask.Status=9（仅当当前仍是 7）、CDP_Batch.IsFeeding=0、CDP_OperateUnit_Events 插入 ErrorCode=2097、OperateType=8、OperateMode=AUTO、SourceID=BatchTaskID、LabId 取配置 operateUnitEventLabId。

旧的 CheckIsTimeOutError 用 MAX(DBTime) 和 execDetailTimeoutSeconds 比较，当前超标循环没有调用它。停滞只看 CheckTime。

调度和监控常用错误码

码谁记含义
1013调度读 OPC 或下发泵速失败，文案里写 DeltaV 通讯异常或泵速下发失败
1024调度开补前地秤读失败或重量无效
1031调度地秤增量低于按泵速估算的量，按堵塞停泵
1032调度地秤短时间异常变大
1036调度地秤读数连续不变
2097监控监控侧停泵：明细停滞、补料超标，或健康检查失败后的停泵

1013 只说明调度没从 OPC 接口拿到成功结果。OPC 进程刚重启、缓存还没有这台罐，或者写点时 RPC 不可用，都会走到这个码。1024 只说明地秤 HTTP 没返回可用重量。
