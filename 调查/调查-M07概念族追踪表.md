## 7. 口径限制与无法确定项

### 7.1 口径限制（结论的适用边界）

1. **需求命中是关键词行级统计，不是语义匹配**。同一行含多个关键词只计一次；摘录的 3 条按“每关键词优先取 160 字以内的首条”，不保证是该族最贴切条款。因此“命中 100+”可能来自通用词（如“补料”“任务”“恢复”），不代表该族有同等密度的专项条款。
2. **调用链仅在这 4 个范围目录内做反向 BFS**（最多 3 层）。Controller、`futurefab-api` 契约与跨模块调用不参与建图，故“无 application service 入口”只表示“本目录内无直接/间接引用”，不等于无调用方。
3. **数据表由 Mapper XML 正则推断**，按 `run_/lab_/sys_/res_/det_/prj_/cfg_/dict_` 前缀过滤列名；注解 SQL、动态表名、跨库表可能遗漏，未做运行期核对。
4. **孤儿判定基于类名与 implements 接口名的文本引用**，未做 Spring 容器装配核查；`@Component/@Service` 类可能由扫描装配，`@Configuration` 类可能只在容器内生效。
5. **cron 只读取注解内联默认值**，未核对 Nacos 服务端配置，未启动任何服务。
6. **需求语料按版本参数选择**：默认 `V5.1` ＝ `docs/需求说明书V5.1-1030_md/` 正文（`18-反应器.md` 的三个章节区间 + `25/26/27`）+ V4.0 `需求澄清决策记录.md`；`V4.0` ＝ `docs/需求说明书V4.0-0904_md/` 的 6 份正文 + 同一澄清记录。V5.1 没有独立澄清记录，故澄清仍取 V4.0。V4.0 / V5.1 / V5.1+澄清 的差异见 §2b，原 V4.0 结论未被删除。
