## 1. 共用改造项

### C-01 对外 ID 改造（承载 2.4，联动 14.2）

- **统一改法**：新增 `publicId`（UUID v7 或雪花字符串）列，对外接口一律用 `publicId` 定位，内部仍用自增主键；入站解析后映射主键。禁止把主键直接暴露到 URL/JSON。
- **影响范围**：M01 用户/角色/部门，M02 工程资料，M03–M07 业务单据，M09 告警配置等所有对外路径参数与响应 ID 字段；涉及 `*Controller` 路径变量、`*VO` 字段、`*Mapper.xml` 查询条件。
- **存量兼容**：`publicId` 列可空 → 回填任务生成 → 加唯一索引 → 代码切读 → 保留主键列。分三期：①加列回填（不停机）；②双读双写（新老都能查）；③只认 `publicId`。切换期保留“数字 ID 入参 → 410 提示升级”兼容层，默认关闭。
- **验收**：见 2.4 / 14.2。

### C-02 字段加密升级与密钥管理（承载 3.2/6.2/7.1/7.5）

- **统一改法**：`FieldEncryptUtils` 改 `AES/GCM/NoPadding`，256 位密钥（`SHA-256(key)` 全 32 字节，不再截断）；密文格式升级为带版本前缀 `ENC2:` + `base64(iv|ciphertext|tag)`，保留 `ENC:` 旧格式只读兼容。密钥仅从 `futurefab.field.crypto.key` 系统属性或 `FUTUREFAB_FIELD_CRYPTO_KEY` 环境变量注入，**删除 `DEFAULT_KEY` 回退，缺密钥直接启动失败**。
- **存量密文重加密**：新增一次性迁移任务（`futurefab-job` 或独立 CLI），按 `ENC:` 前缀扫描 → 解密 → 用新密钥/新算法重加密 → 写回 → 校验抽样。方案：双写期（读兼容两种前缀）→ 迁移 → 关闭旧格式。条数校验：迁移前后 `count(*)` 相等、按 1% 抽样比对明文哈希。
- **密钥轮换**：配置支持 `current` + `previous` 两个密钥，`previous` 只用于解密；轮换后再跑一次迁移任务。
- **脱敏组件**（3.2 与 7.5 共用）：新增 `SensitiveMaskUtils`（手机号 `138****1234`、身份证、邮箱），VO 序列化统一走 `@Sensitive` 注解 + Jackson `ContextualSerializer`。
- **验收**：见 3.2 / 6.2 / 7.1 / 7.5。

### C-03 统一参数校验（承载 8.3，联动 14.5）

- **统一改法**：Controller 类级 `@Validated`；请求 DTO 用 Jakarta 约束注解（`@NotNull`/`@Size`/`@Pattern`/`@Min`/`@Max`），路径变量与查询参数用 `@Validated` + `@Min` 等；统一由 `GlobalExceptionHandler` 把 `MethodArgumentNotValidException`/`ConstraintViolationException` 转成同一错误码（400 + 字段级 message）。
- **约定**：新接口必须 DTO，不接受裸 `Map`；字符串长度上限统一（名称 64、备注 500、文本 2000）；禁止在 Service 层重复做格式校验。
- **验收**：见 8.3 / 14.5。

### C-04 统一错误码与“不存在/无权同码”（承载 14.8，联动 2.4/15.1）

- **统一改法**：`GlobalExceptionHandler`（`futurefab-common-security/.../handler/GlobalExceptionHandler.java`）与 `GatewayExceptionHandler` 统一外壳：`code` + 固定文案 + 追踪号；对“资源不存在”和“无权访问”统一返回 `404`（或统一 `403` 同一码），禁止“该 ID 不存在”这类可探测文案。
- **注意**：不得用 `500` 掩盖业务拒绝；不得把内部异常类型名、SQL 片段写进响应。
- **验收**：见 14.8。

### C-05 数据范围过滤与归属断言（承载 15.1，联动 14.2）

- **统一改法**：`DataScopeAspect`（`futurefab-common-datascope/.../aspect/DataScopeAspect.java`）覆盖全部列表查询；在 Mapper 层强制拼 `${params.dataScope}`。对按 `publicId` 取单条的接口，Service 层增加 `assertOwnership(entity, currentUser)`，越权抛统一错误码。
- **漏加检测**：新增单测基线，扫描所有 `select*List` 方法是否带 `dataScope` 参数；CI 静态检查（可用 ArchUnit 或自定义注解）。
- **验收**：见 15.1。

### C-06 管理端与业务端拆分（承载 1.12，联动 C-07）

- **统一改法**：后端新增 `/admin/**` 独立前缀（或独立 `futurefab-admin` 应用），网关按路径前缀路由到不同过滤器链；管理端仅允许指定网段 + 独立角色。前端在 `futurefab-frontend` 新增独立管理应用入口（复用 `app-smp-settings` 改造或新建 `app-smp-admin`），业务端不再暴露管理菜单。
- **兼容**：旧路径保留 301/308 到新前缀一个版本周期，响应头 `Deprecation` 标注。
- **验收**：见 1.12。

### C-07 内部服务凭证与命名管道共享密钥（承载 1.4/2.2）

- **统一改法**：服务间调用统一走 `InnerAuth` 注解 + 网关签发的内部令牌（短时效、按调用方标识），`AuthFilter` 继续清洗外部伪造的内部头；DB 连接改专用账号 + `useSSL=true`（或按客户要求的内网 TLS）；Named Pipe（`NamedPipeTransport.java`/`WindowsOverlappedNamedPipeTransport.java`）握手加共享密钥（HMAC + 时间戳，防重放）。
- **配置**：新增 `futurefab.inner.secret`、`futurefab.namedpipe.secret`，仅从环境变量/密钥管理注入，无默认值；缺失启动失败。
- **验收**：见 1.4 / 2.2。

### C-08 审计补齐与日志外送（承载 5.1/5.2/5.3/5.6）

- **统一改法**：定义审计事件字典（登录、授权失败、导出、敏感读取、批量变更、配置变更），新增 `@AuditEvent(type, resource, sizeField)` 或复用 `@Log`；导出端点必须记录条数与筛选条件摘要；`LogAspect` 扩展排除字段清单；新增 `MaskingPatternLayout`（logback encoder）对手机号/身份证/邮箱/口令做兜底脱敏；新增 `SyslogAppender`（TLS）配置项，地址留空即不启用。
- **留存**：`logback.xml` 的 `maxHistory` 改为 `${FUTUREFAB_LOG_MAX_HISTORY:-60}`，交付配置置 180。
- **验收**：见 5.1 / 5.2 / 5.3 / 5.6。

### C-09 生产配置开关基线（承载 14.10，联动 18.1）

- **统一改法**：`futurefab-system-dev.yml` 增 `springdoc.api-docs.enabled=false`、`springdoc.swagger-ui.enabled=false`；网关对 `/v3/api-docs/**`、`/swagger-ui/**`、`/doc.html` 返回 404；生产 profile 强制。新增启动自检，检测到生产环境开启时打 ERROR 并拒绝启动（可配置 `fail-fast`）。
- **验收**：见 14.10 / 18.1。

## 2. 逐条整改

### 1.1 员工还不能用公司账号（AD/ADFS）直接登录

1. **一句话问题**：员工目前只能用本地账号登录，还不能用公司域账号单点登录。
2. **现状**：`futurefab-auth/.../config/properties/AadProperties.java` 的 `enabled` 默认关闭；`AadSecurityConfig.java`、`AadLoginService.java`、`AadController.java` 已有 SAML 过滤器与登录链路，但依赖云端 AAD 元数据。
3. **目标状态**：内网 IdP 可达时，未登录访问首页跳转公司 IdP；非公司设备被 IdP 拒绝；本地口令登录保留为降级入口（可配置关闭）。
4. **整改步骤**：
   1) `AadProperties` 增加 `metadataUrl`/`entityId`/`assertionConsumerUrl`，支持内网 ADFS 地址；
   2) `AadSecurityConfig` 按配置注册 `SAMLProcessingFilter`，未配置时整体不注册；
   3) `AadLoginService` 把属性映射（工号/邮箱/部门）写入本地用户，首次登录自动建号并 `initPasswordModify` 失效；
   4) `nacos-config/futurefab-auth-dev.yml` 增加占位配置（不含真实地址）；
   5) 前端登录页增加“域账号登录”入口（`packages/app-smp-*` 共用登录组件）。
5. **影响面**：认证服务、Nacos 配置、前端登录页；不改表结构（用户表已有来源字段则复用，没有则加 `source` 列）；不发通知。
6. **工作量**：5–8 人日。
7. **风险与回退**：最坏是 IdP 协议不兼容导致全员无法登录 → 保留本地口令入口，配置 `smp.aad.enabled=false` 即回退；SAML 过滤器注册用 `@ConditionalOnProperty`。
8. **验收方式**：
   - 未登录浏览器访问首页 → 302 到内网 IdP 登录页；
   - 用非公司设备（不在允许组）登录 → IdP 拒绝且系统无 token 下发；
   - `smp.aad.enabled=false` 时本地口令登录仍可用。
9. **依赖与前置**：客户提供内网 IdP 元数据地址、证书、属性映射规则（见 §4 第 1 条）。

### 1.3 外部账号没有独立口令档位，锁定阈值也不符

1. **一句话问题**：外部人员账号和内部账号用同一套口令规则，且锁定阈值比公司标准宽。
2. **现状**：`InitialPasswordPolicy.java` 统一 10–18 位四类字符；`CacheConstants.java` 中 `PASSWORD_MAX_RETRY_COUNT=5`、`PASSWORD_LOCK_TIME=10`，与 URS 的“6 次/15 分钟”不一致；无外部用户体系。
3. **目标状态**：按用户来源分档（普通 ≥8、服务/特权 ≥16、内部 ≥10）；连续 6 次失败锁定 15 分钟；外部用户独立管理。
4. **整改步骤**：
   1) `InitialPasswordPolicy` 增加 `userType` 维度与档位表；
   2) `CacheConstants` 改为读配置 `security.password.maxRetryCount=6`、`lockMinutes=15`；
   3) 认证服务按 `userType` 取档位校验；
   4) `sys_config` 增加 `sys.account.externalPolicy` 开关与档位默认值；
   5) 单测覆盖三档边界。
5. **影响面**：认证服务、系统模块账号策略、`sys_config` 数据；不改表结构；对现有用户是收紧，需提前通知。
6. **工作量**：3–5 人日。
7. **风险与回退**：锁定阈值收紧可能造成误锁 → 配置项可调回 5/10；回退改配置即可。
8. **验收方式**：
   - 连续输错 6 次 → 第 7 次返回“账号已锁定”，15 分钟后可登录；
   - 特权账号设 12 位口令 → 保存被拒（不足 16 位）。
9. **依赖与前置**：需确认“服务/特权账号”在本系统的定义（无则按角色映射）。

### 1.4 数据库和管道通信没有各自的身份凭证

1. **一句话问题**：应用连数据库用超级用户、走明文，设备管道也没有共享密钥。
2. **现状**：`nacos-config/application-dev.yml:47-49`（`useSSL=false`，数据库账号为高权限账号、口令为明文默认值，具体值见该文件第 47—49 行，不在本文重复）；`futurefab-namedpipe-client/.../transport/NamedPipeTransport.java` 与 `WindowsOverlappedNamedPipeTransport.java` 无握手令牌；`InnerAuth.java` 存在但未全线启用。
3. **目标状态**：DB 用专用最小权限账号且链路加密；命名管道缺密钥的调用被拒；服务间调用必须带内部令牌。
4. **整改步骤**（引用 C-07）：
   1) DBA 建专用账号并授权（DDL 见 §4）；
   2) 配置改 `useSSL=true` + 专用账号，口令走环境变量；
   3) `NamedPipeTransport` 握手增加 HMAC-SHA256(challenge + secret + timestamp)，服务端校验并拒绝 30s 外重放；
   4) `InnerAuth` 覆盖 `futurefab-api` 全部 Feign/HTTP 内口；
   5) 启动自检：缺 secret 直接失败。
5. **影响面**：数据源配置、`futurefab-namedpipe-client`、`futurefab-api` 内口；不改表结构；需通知设备联调方。
6. **工作量**：4–6 人日。
7. **风险与回退**：TLS 开启失败导致全站不可用 → 配置 `useSSL` 开关回退；HSM/密钥缺失 → 环境变量注入，回退需同时回退客户端。
8. **验收方式**：
   - `mysql -u futurefab_app` 可连、`DROP TABLE` 被拒；
   - 不带密钥调用管道 → 返回拒绝码；带旧时间戳 → 拒绝；
   - 直连服务端口未带内部令牌 → 401。
9. **依赖与前置**：客户 DBA 建账号、提供 DB 证书或确认内网豁免（§4 第 2 条）。

### 1.12 管理功能和业务功能混在同一个入口

1. **一句话问题**：业务用户和管理员用的是同一个门户、同一个后端前缀，分不清边界。
2. **现状**：`futurefab-frontend/packages/app-smp-data|lab|settings` 共用网关与同一后端；`nacos-config/futurefab-gateway-dev.yml` 无独立管理前缀；无管理网段限制。
3. **目标状态**：管理端独立入口、独立前缀；业务账号访问管理端返回 403；管理端仅指定网段可达。
4. **整改步骤**（引用 C-06）：
   1) 网关新增 `/admin/**` 路由与独立过滤器链；
   2) 后端 Controller 按 `@RequestMapping("/admin/...")` 或新模块迁移；
   3) 前端新建 `app-smp-admin` 或改造 `app-smp-settings`，业务端移除管理菜单；
   4) Nacos 增加管理端网段白名单；
   5) 旧路径保留一个版本的 308 跳转。
5. **影响面**：网关、系统模块全部管理 Controller、前端三应用、Nacos；不改表结构；需通知前端与集成方。
6. **工作量**：8–12 人日。
7. **风险与回退**：路径迁移遗漏导致管理功能不可用 → 保留旧前缀一个版本；回退为网关开关 `futurefab.admin.separate=false`。
8. **验收方式**：
   - 业务角色账号访问 `/admin/user/list` → 403；
   - 管理网段外访问管理端 → 网络层不可达/403；
   - 管理端全部菜单功能回归通过。
9. **依赖与前置**：需先确认管理端目标域名/网段（客户网络侧，§4 第 3 条）。

### 2.2 内部服务可绕过网关直接调用

1. **一句话问题**：知道服务端口的人可以不走网关直接调内部接口。
2. **现状**：`AuthFilter` 只在网关生效；服务端口在内网可达；`InnerAuth.java` 未全线启用。
3. **目标状态**：未带内部令牌的直连请求一律 401/403；内部调用方有独立标识可审计。
4. **整改步骤**（引用 C-07）：`InnerAuth` 拦截器覆盖全部内口；内部令牌由网关签发、有效期 ≤5 分钟；服务端口在部署层只监听应用网段（由客户网络侧落地，写入交付说明）。
5. **影响面**：`futurefab-api`、各服务 Controller 内口、网关；不改表结构。
6. **工作量**：2–3 人日。
7. **风险与回退**：令牌校验遗漏导致内部调用 401 → 灰度按服务开启，开关 `futurefab.inner.auth.enforce`。
8. **验收方式**：
   - `curl` 直连服务端口不带令牌 → 401；
   - 网关转发带内部令牌 → 200；
   - 伪造 `FROM_SOURCE` 头 → 被 `AuthFilter` 清洗。
9. **依赖与前置**：1.4 的密钥先行（C-07）。

### 2.4 对外用连续数字编号，可被逐个试出

1. **一句话问题**：URL 里的编号是 1、2、3，别人可以逐个试出没权限的数据。
2. **现状**：`SysUserController.java` 等以自增主键作路径变量；`SysUserMapper.xml` 以数字主键关联；无 `publicId`。
3. **目标状态**：对外只见不可预测 ID；枚举相邻 ID 全部 404/403。
4. **整改步骤**（引用 C-01）：
   1) 目标表加 `public_id` 列 + 唯一索引（DDL 见下）；
   2) 回填任务按批生成；
   3) `*VO` 增加 `publicId`，`*Controller` 路径变量改 `publicId`，Service 解析；
   4) Mapper 增加 `selectByPublicId`；
   5) 旧数字 ID 入参返回 410（开关控制一个版本）。
   DDL：`ALTER TABLE sys_user ADD COLUMN public_id VARCHAR(40) NULL; UPDATE ...; CREATE UNIQUE INDEX uk_sys_user_public_id ON sys_user(public_id);` 回滚：`DROP INDEX` + `DROP COLUMN`（需评估已切流量的接口）。
5. **影响面**：全部对外接口与前端；改表结构；需数据迁移；破坏兼容（旧 ID 失效）；需通知集成方。
6. **工作量**：8–12 人日。
7. **风险与回退**：主键迁移不可逆、外部集成断链 → 分三期上线；回退保留数字 ID 兼容层开关。
8. **验收方式**：
   - 取一条记录的新 `publicId` 请求详情 → 200；把末位改一位 → 404；
   - `SELECT count(*) FROM sys_user WHERE public_id IS NULL` = 0；
   - 旧数字 ID 请求 → 410（兼容期）。
9. **依赖与前置**：C-01 方案评审；14.2/15.1 共用同一映射层。

### 3.2 配置里有明文口令，字段加密强度不足

1. **一句话问题**：配置文件能直接看到数据库口令，字段加密用的算法和密钥也不够硬。
2. **现状**：`FieldEncryptUtils.java:22,24,80-84`（`AES/ECB/PKCS5Padding`、SHA-256 截 16 字节、默认密钥回退）；`nacos-config/application-dev.yml` 明文口令。
3. **目标状态**：配置中无明文口令；字段密文为 AES-256-GCM；缺密钥启动失败。
4. **整改步骤**（引用 C-02）：改加解密实现与密文前缀；配置项改 `${DB_PASSWORD}` 占位；Nacos 生产配置由客户运维注入；迁移任务重加密存量；启动自检缺密钥失败。
5. **影响面**：`futurefab-common-core`、Nacos 全部数据源配置、迁移任务；改密文格式（不改表结构）；需迁移存量；不破坏读取（双格式兼容）。
6. **工作量**：6–9 人日。
7. **风险与回退**：存量迁移失败导致手机号等字段不可读 → 先备份表、保留旧密钥 `previous` 解密；回退恢复备份 + 回退版本。
8. **验收方式**：
   - `grep -r "password:" nacos-config` 无明文；
   - 未设置 `FUTUREFAB_FIELD_CRYPTO_KEY` 启动 → 失败并给出明确提示；
   - 迁移后抽样 100 条，明文哈希与迁移前一致。
9. **依赖与前置**：客户提供密钥注入方式（环境变量/密钥管理），§4 第 4 条。

### 5.1 导出、敏感读取这类操作没进审计

1. **一句话问题**：谁导出了什么、谁看了敏感数据，系统没留痕。
2. **现状**：`LogAspect.java` 只记录带 `@Log` 的方法；导出端点（`AlarmMailConfigController`、`DetResultController` 等）与敏感读取未标注。
3. **目标状态**：每次导出/敏感读取都有审计记录，含操作人、条数、筛选条件摘要。
4. **整改步骤**（引用 C-08）：定义事件字典；导出端点加 `@AuditEvent`；`AsyncLogService` 落 `sys_oper_log`；补充查询页。
5. **影响面**：系统模块、公共日志；不改表结构（复用 `sys_oper_log`）。
6. **工作量**：2–3 人日。
7. **风险与回退**：审计写入失败阻塞业务 → 异步落库 + 失败降级到文件；开关 `futurefab.audit.async=true`。
8. **验收方式**：
   - 导出一次 → `sys_oper_log` 出现 `business_type=EXPORT` 且 `oper_param` 含条数；
   - 敏感读取一次 → 出现对应事件。
9. **依赖与前置**：无。

### 5.2 数据导出既没审计也没二次验证

1. **一句话问题**：批量导出这类高风险动作，谁都能点，且不留痕。
2. **现状**：导出端点无 `X-Operation-Proof` 校验、无审计；`SensitiveOperationService` 已有二次验证能力但未接入导出。
3. **目标状态**：批量导出需二次验证；导出行为留痕且含条数。
4. **整改步骤**（引用 C-08）：导出端点接 `SensitiveOperationService`（挑战 + proof）；审计记录条数；前端导出弹二次验证。
5. **影响面**：导出端点、`SensitiveOperationService`、前端；不改表结构；需通知常用导出用户。
6. **工作量**：3–5 人日。
7. **风险与回退**：二次验证误挡定时导出 → 服务账号白名单 + 开关 `futurefab.export.stepup.enabled`。
8. **验收方式**：
   - 缺 `X-Operation-Proof` 调导出 → 403；
   - 通过验证后导出 → 200 且审计有条数；
   - 重放旧 proof → 失败。
9. **依赖与前置**：5.1 的事件字典先行。

### 5.3 日志里仍可能出现手机号和口令

1. **一句话问题**：排障日志可能把手机号、口令原样打出来。

8. **验收方式**：
   - 触发登录失败日志 → 日志中无完整手机号/口令；
   - 抽样 1000 行日志正则扫描 → 0 命中。
9. **依赖与前置**：无。

### 5.6 日志没有送给 SIEM/日志平台

1. **一句话问题**：日志只落在本机文件，安全平台拿不到。

9. **依赖与前置**：客户提供日志平台地址/协议/证书（§4 第 5 条）。

### 6.2 对称加密用的是 AES-128/ECB

1. **一句话问题**：字段加密强度不达标，ECB 模式还会暴露数据规律。
2. **现状**：`FieldEncryptUtils.java:24` `AES/ECB/PKCS5Padding`；`Arrays.copyOf(keyBytes,16)`。
3. **目标状态**：AES-256-GCM + 随机 IV；密钥 32 字节。
4. **整改步骤**（引用 C-02）：替换 transformation；改用完整 32 字节密钥；密文格式带版本；单测断言算法与密钥长度。
5. **影响面**：`futurefab-common-core`；改密文格式；需与 3.2 同批迁移。
6. **工作量**：2–3 人日（与 3.2 合并实施时更少）。
7. **风险与回退**：与 3.2 相同，保留 `previous` 密钥解密旧数据。
8. **验收方式**：
   - 单测 `FieldEncryptUtilsTest` 断言 `AES/GCM/NoPadding` 与 32 字节密钥；
   - 同一明文两次加密结果不同（随机 IV）。
9. **依赖与前置**：3.2 的密钥注入先行。

### 7.1 传输、存储、字段加密没有形成闭环

### 7.3 个人数据只能软删，不能匿名化

### 7.4 含个人数据的响应没有禁用缓存

8. **验收方式**：
   - 用户详情响应头含 `Cache-Control: no-store`；

9. **依赖与前置**：无。

### 7.5 列表默认把手机号原样返回

### 8.1 XSS、路径穿越、重复提交没有统一防护

1. **一句话问题**：跨站脚本、路径穿越、重复提交靠各接口自觉，没有统一拦。
2. **现状**：无全局 XSS 过滤器/路径规范化；幂等仅 `@ManagementGuardedWrite` 覆盖部分写接口。

### 8.2 响应里没有 CSP、nosniff 等安全头

1. **一句话问题**：浏览器没有收到防 XSS/点击劫持的安全头。

   - `curl -I` 首页 → 四个头齐全；
   - 浏览器控制台无 CSP 违规报告（Report-Only 阶段）。
9. **依赖与前置**：前端资源改造需与前端排期对齐。

### 9.1 没有第三方组件漏洞扫描与台账

5. **影响面**：构建与 CI；不改表结构。
6. **工作量**：3–5 人日。
7. **风险与回退**：离线漏洞库过期导致误报 → 固定基线版本并记录日期；不阻塞构建，只出报告。
8. **验收方式**：
   - `mvn dependency-check:check` 产出报告且高危清单为空或已挂账；
   - 台账覆盖全部直接/传递依赖。
9. **依赖与前置**：客户提供离线漏洞库或许可（§4 第 6 条）。

### 10.1 没有备份与恢复工具

1. **一句话问题**：系统没给运维提供能直接执行的备份/恢复手段。
2. **现状**：`deploy/` 仅 `nginx.conf.example`；无备份脚本、无恢复流程文档。
3. **目标状态**：一条命令完成全量备份，一条命令还原到测试库并校验一致。
4. **整改步骤**：
   1) 新增 `deploy/backup/`：`backup-db.ps1`/`backup-db.sh`、`restore-db.*`；
   2) 备份内容：MySQL 全量 + 附件目录；
   3) 校验：条数、校验和、抽样表哈希；
   4) 恢复演练手册；
   5) 与客户介质保管流程衔接。
5. **影响面**：部署脚本与文档；不改表结构；不影响运行。
6. **工作量**：3–5 人日。
7. **风险与回退**：备份锁表影响生产 → 用 `--single-transaction` + 低峰窗口；脚本只读，不修改业务数据。
8. **验收方式**：
   - 执行备份后生成文件，大小与条数记录一致；
   - 在测试库恢复后 `count(*)` 与源库一致、抽样哈希一致；
   - 恢复耗时记录在手册。
9. **依赖与前置**：客户提供备份介质与异地存放点（§4 第 6 条）。

### 14.2 参数可遍历，越权可探测

1. **一句话问题**：改一个参数就能试探别人数据，且能区分“没有”和“无权”。
2. **现状**：同 2.4；`DataScopeAspect` 未覆盖全部查询。
3. **目标状态**：遍历 ID 全部 403/404，不泄露存在性。
4. **整改步骤**（引用 C-01 + C-05）：切 `publicId`；单条查询加归属断言；错误码统一（C-04）。
5. **影响面**：全部对外接口；与 2.4 同一批。
6. **工作量**：2–3 人日（含在 2.4 之后）。
7. **风险与回退**：同 2.4。
8. **验收方式**：
   - 用 A 账号取 B 的 `publicId` → 404；
   - 随机 `publicId` → 404 且与无权响应一致。
9. **依赖与前置**：2.4 与 15.1 先行。

### 14.5 输入校验不成体系

1. **一句话问题**：同一类参数在不同接口校验口径不同。
2. **现状**：同 8.3。
3. **目标状态**：全部接口非法输入 400。
4. **整改步骤**（引用 C-03）：统一注解与异常映射；补齐查询参数校验。
5. **影响面**：全部 Controller；不改表结构。
6. **工作量**：1–2 人日（叠加在 8.3）。
7. **风险与回退**：同 8.3。
8. **验收方式**：
   - 分页参数 `pageSize=99999` → 400；
   - 非法枚举值 → 400。
9. **依赖与前置**：8.3 先行。

### 14.8 “不存在”和“无权限”返回不同，可被探测

1. **一句话问题**：返回文案能区分“这条不存在”和“你没权限”，等于告诉攻击者哪条存在。
2. **现状**：`GlobalExceptionHandler.java`（`futurefab-common-security/.../handler/`）与 `GatewayExceptionHandler`；部分旧 Controller 直接抛“该记录不存在”。
3. **目标状态**：两类情况返回同一码同一文案，仅追踪号不同。
4. **整改步骤**（引用 C-04）：统一异常映射表；旧 Controller 改抛统一异常；补充回归用例。
5. **影响面**：公共异常处理、旧 Controller；不改表结构；可能影响依赖错误文案的前端。
6. **工作量**：3–5 人日。
7. **风险与回退**：前端按文案判断的地方失效 → 改按 `code`；回退恢复映射表版本。
8. **验收方式**：
   - 不存在 ID 与无权 ID → 响应 `code`/文案一致；
   - 响应不含类名/SQL。
9. **依赖与前置**：C-04 与 2.4 的 ID 方案并行。

### 14.10 生产默认暴露 Swagger 文档

1. **一句话问题**：生产环境默认就能打开接口文档，等于给攻击者一张接口地图。
2. **现状**：`SpringDocAutoConfiguration.java:23` `matchIfMissing = true`；Nacos 未配置关闭。
3. **目标状态**：生产访问 `/v3/api-docs`、`/swagger-ui` 返回 404。
4. **整改步骤**（引用 C-09）：生产配置关闭；网关加路径黑名单；启动自检。
5. **影响面**：网关、系统模块配置；不改表结构。
6. **工作量**：1–2 人日。
7. **风险与回退**：联调环境误关 → 按 profile 区分；回退改配置并重启。
8. **验收方式**：
   - 生产 profile 访问 `/v3/api-docs` → 404；
   - 测试 profile 仍可访问（或同样关闭但保留本地开关）。
9. **依赖与前置**：无。

### 15.1 部分列表没按数据范围过滤

1. **一句话问题**：有些列表能把别人/别的项目的数据一起查出来。
2. **现状**：`DataScopeAspect.java`（`futurefab-common-datascope/.../aspect/`）与 `${params.dataScope}` 已存在，但未覆盖全部 `select*List`。
3. **目标状态**：跨项目读取返回 403/404，列表只含授权范围。
4. **整改步骤**（引用 C-05）：
   1) 盘点全部 `select*List`；
   2) 补 `dataScope` 参数与 XML 片段；
   3) 单条查询加归属断言；
   4) 新增静态检查防止回退。
5. **影响面**：M01–M07、M09 全部列表查询；不改表结构。
6. **工作量**：5–8 人日。
7. **风险与回退**：漏加导致越权或过度收紧导致看不到数据 → 单元测试覆盖每类角色；回退按 Mapper 版本。
8. **验收方式**：
   - A 项目账号查列表 → 不含 B 项目数据；
   - 按 B 项目 ID 查详情 → 404；
   - 静态检查报告 0 个未注入方法。
9. **依赖与前置**：C-01 的 `publicId` 映射先行（归属断言依赖它）。

### 18.1 后台地址与路径可被枚举

1. **一句话问题**：默认端口 + 文档页 + 可猜路径，让后台很容易被找到。
2. **现状**：同 14.10；端口与路径均为默认值。
3. **目标状态**：外部扫描不可见文档页与后台路径。
4. **整改步骤**（引用 C-09）：关闭文档；端口改非默认；网关路径加不可预测前缀；入口收敛。
5. **影响面**：部署配置、网关；不改表结构；需通知集成方改地址。
6. **工作量**：2–3 人日。
7. **风险与回退**：改端口影响现有集成 → 保留旧端口一个版本并 301。
8. **验收方式**：
   - 外部端口扫描 → 仅 443；
   - 访问默认 `/swagger-ui/index.html` → 404。
9. **依赖与前置**：14.10 先行。

### 18.2 旧接口把整行实体直接返回

1. **一句话问题**：老接口把数据库整行返回，带出多余字段甚至密文。
2. **现状**：部分旧 Controller 直接返回实体（如 `SysUserController` 返回 `SysUser`），无 VO 投影。
3. **目标状态**：响应字段清单只含必要字段，不含大字段与密文。
4. **整改步骤**：为旧接口建 VO；Controller 改投影；Mapper 查询列裁剪；前端字段核对。
5. **影响面**：系统模块旧接口、前端；不改表结构；破坏兼容（字段减少）。
6. **工作量**：5–8 人日。
7. **风险与回退**：前端依赖被删字段 → 逐接口灰度 + 前端联调；回退旧 DTO。
8. **验收方式**：
   - 调用旧详情接口 → 响应无 `password`/`remark` 等多余字段；
   - 响应字段与 VO 定义一致（快照测试）。
9. **依赖与前置**：前端排期对齐。
