# 生产构建与部署

## 构建命令和发布目录

使用项目规定的 pnpm 8.6.2 和 Node.js `^20.19.0 || >=22.12.0`，在 `futurefab-frontend` 根目录执行：

```powershell
pnpm install --frozen-lockfile
pnpm run build:prod
```

将 **`packages/portal/dist` 的全部内容** 发布到站点根目录，包含 `assets/`、`unpkg/`、`index.html` 和 `deployment-config.json`。不要仅复制 `assets` 或单独发布子应用的 `dist`。`pnpm start` 是本地开发入口，会构建后启动 Vite，生产服务器不运行它。

`build:prod` 执行完整构建及类型检查，最后检查生产产物；普通 `build` / `build-only` 的门户构建也会检查产物。检查失败必须停止发布。门户代理约定已纳入源码和 Nx 输入，构建可正常复用缓存。

## 固定代理约定

项目不使用 `.env` 保存门户地址，开发和生产约定集中在 `scripts/portal-environment.ts`：

| 场景 | 前端请求前缀 | 转发目标 |
| --- | --- | --- |
| 本地开发 | `/dev-api` | Vite 转发到 `http://127.0.0.1:8080` |
| 生产部署 | `/prod-api` | 线上 Nginx 转发到实际后端 upstream |

Vite 固定监听 `127.0.0.1:5581`。开发代理会去掉 `/dev-api` 前缀，例如 `/dev-api/captchaImage` 转发为后端 `/captchaImage`。生产包不包含开发后端地址，也不接受 CI 环境变量覆盖 API 前缀。

开发代理只匹配完整 API 路径段，不会拦截 `/dev-api-other`。查询参数、上传请求体、鉴权头和后端 HTTP 错误状态原样透传；代理等待后端响应的超时为 300 秒，与 Nginx 示例一致。浏览器客户端自己的请求超时仍独立生效。

旧系统入口仅在开发模式指向 `http://127.0.0.1:5173`；生产默认关闭旧系统跳转和 AAD 登录。若未来需要启用这些生产集成，应修改统一配置并补充相应部署验证，不要重新引入零散环境文件。

`deployment-config.json` 是构建结果的可读清单。构建检查和部署探测都会验证它是否符合上述固定约定；单独修改该文件不会改变浏览器脚本中的行为。

## Nginx

参考 `deploy/nginx.conf.example`，将其中的 location 规则合并到现有站点，保留实际域名、TLS、后端 upstream 和上传大小配置。示例按根路径 `/` 部署；子路径部署需另行配置前端资源 base 和路由，不能直接套用。

关键代理配置如下，其中后端地址须与实际环境一致：

```nginx
location = /prod-api {
    return 308 /prod-api/$is_args$args;
}

location ^~ /prod-api/ {
    proxy_pass http://127.0.0.1:8080/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_intercept_errors off;
}
```

`proxy_pass` 末尾 `/` 会把 `/prod-api/captchaImage` 转成后端 `/captchaImage`。API 错误应保留为 API 响应，不能回退为 `index.html`；静态资源不存在应返回 404。只有前端路由使用 History 回退。[Nginx proxy_pass 文档](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_pass)

## 发布检查

构建完成后可独立检查：

```powershell
pnpm run check:production
```

部署后，在开发机执行只读探测（换成真实站点域名）：

```powershell
pnpm run check:deployment https://smp.example.com
```

脚本检查公开配置清单与同源验证码接口，不登录、不修改业务数据。正常结果是 `/prod-api/captchaImage` 返回 JSON；`captchaEnabled: false` 也是正常响应。HTTP 200 + `text/html` 不代表接口正常，这是 SPA 回退的典型表现，脚本会报错。

最后人工确认登录、业务列表、上传下载及页面刷新。若出现旧地址，检查部署文件是否完整替换以及浏览器是否缓存了旧 HTML。本次代码验证不代替实际服务器的 Nginx 配置核验。
